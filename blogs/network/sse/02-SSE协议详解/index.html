    SSE 教程（二）：协议详解¶

    参考： W3C Event Stream Format

    一、事件流格式总览¶

    SSE 协议一共定义了 4 个字段：

    字段 作用 是否必须
    data 事件数据内容 ✅ 必须（每个事件至少一个 data）
    event 事件类型名称 ❌ 可选
    id 事件 ID（用于断线重连） ❌ 可选
    retry 重连等待时间（毫秒） ❌ 可选

    完整示例¶

    id: 1
event: user-login
retry: 5000
data: {"username": "alice", "time": "2024-01-01T00:00:00Z"}

id: 2
event: notification
data: 第一行
data: 第二行

    二、字段详解¶

    2.1 data — 事件数据¶

    data: 简单文本消息

    多行数据：用多个 data: 行，客户端收到时用 \n 拼接：

    data: {
data:   "message": "hello",
data:   "count": 42
data: }

    客户端收到的 event.data 为：

    {
  "message": "hello",
  "count": 42
}

    ⚠️ 注意：最后一个 data: 行后面的换行也会被拼进去（即末尾有一个 \n）。 实际上规范是：多个 data 行之间用 \n 连接，最后会去掉末尾的 \n。

    2.2 event — 事件类型¶

    event: message
data: 普通消息

event: error-alert
data: 出错了！

    客户端可以按事件类型分别监听：

    source.addEventListener("message", (e) => {
    console.log("普通消息:", e.data);
});

source.addEventListener("error-alert", (e) => {
    console.log("错误告警:", e.data);
});

    如果不指定 event，默认触发 message 事件。

    2.3 id — 事件 ID¶

    id: 42
data: 第 42 条消息

    作用： - 客户端收到后，会记住这个 ID - 断线重连时，浏览器自动在请求头带上 Last-Event-ID: 42 - 服务器可以据此从断点继续推送

    GET /events HTTP/1.1
Last-Event-ID: 42      ← 自动携带

    ⚠️ ID 必须是字符串，不能包含 \n 或 \r

    2.4 retry — 重连间隔¶

    retry: 3000
data: 请 3 秒后重连

    告诉客户端：如果断开连接，等 3000 毫秒 后再尝试重连。

    默认重连时间由浏览器决定（通常约 3 秒）。

    三、事件的分隔规则¶

    SSE 用空行来分隔事件。具体规则：

    data: 事件 A

data: 事件 B
    • 一个或多个空行 = 事件边界
    • 空行 = 连续两个 \n（即 \n\n）
    • 同一个事件内的多行 data 之间不能有空行

    注释行¶

    以 : 开头的行是注释，会被忽略：

    : 这是一条注释
: 通常用作心跳
data: 实际数据

    四、重连机制¶

    4.1 自动重连¶

    当连接断开时（网络波动、服务器超时等），EventSource 会自动重连：

    const source = new EventSource("/events");

source.onopen = () => console.log("连接已建立");
source.onerror = (err) => console.log("连接断开，等待重连...");
source.onmessage = (e) => console.log(e.data);

    重连流程：

    1. 连接断开
2. 等待 retry 毫秒（或默认时间）
3. 重新发起 GET /events 请求
4. 请求头带上 Last-Event-ID: <上次收到的 ID>
5. 服务器从该 ID 之后继续推送

    4.2 服务端实现断点续传¶

    from fastapi import Request

@app.get("/events")
async def events(request: Request):
    # 获取客户端上次收到的事件 ID
    last_id = request.headers.get("last-event-id")

    if last_id:
        # 从断点继续推送
        start_from = int(last_id) + 1
    else:
        start_from = 0

    async def generate():
        for i in range(start_from, 100):
            yield f"id: {i}\ndata: 消息 {i}\n\n"
            await asyncio.sleep(1)

    return StreamingResponse(generate(), media_type="text/event-stream")

    4.3 手动关闭连接¶

    source.close();  // 关闭后不再自动重连

    五、心跳保活¶

    为什么需要心跳？¶

    SSE 连接可能被中间设备（Nginx、代理、防火墙）因为空闲超时而断开。

    解决方案：定期发送注释行作为心跳：

    : heartbeat

    服务端心跳实现¶

    async def event_generator():
    while True:
        # 发送业务数据
        yield f"data: {get_latest_data()}\n\n"

        # 每 15 秒发送心跳注释
        await asyncio.sleep(15)
        yield ": heartbeat\n\n"

    Nginx 配置配合¶

    location /events {
    proxy_buffering off;       # 关键：禁用缓冲
    proxy_cache off;
    proxy_read_timeout 300s;   # 空闲超时设长
    proxy_send_timeout 300s;
}

    客户端                                    服务器
  |                                        |
  |--- GET /events ----------------------->|
  |    Accept: text/event-stream           |
  |                                        |
  |<-- 200 OK -----------------------------|
  |    Content-Type: text/event-stream     |
  |                                        |
  |<-- retry: 5000\n\n --------------------|
  |                                        |
  |<-- id: 1\n ----------------------------|
  |<-- event: init\n ----------------------|
  |<-- data: {"status":"connected"}\n\n ---|
  |                                        |
  |<-- id: 2\n ----------------------------|
  |<-- data: 第一条推送\n\n ---------------|
  |                                        |
  |<-- : heartbeat\n\n --------------------|
  |                                        |
  |    [网络断开]                           |
  |                                        |
  |--- GET /events ----------------------->|
  |    Last-Event-ID: 2                    |
  |                                        |
  |<-- id: 3\n ----------------------------|
  |<-- data: 从断点继续\n\n ---------------|
  |                                        |

    七、常见问题¶

    Q: SSE 能发二进制数据吗？¶

    不能。SSE 只支持 UTF-8 文本。如果需要发二进制，可以先 Base64 编码：

    import base64
data = base64.b64encode(image_bytes).decode()
yield f"data: {data}\n\n"

    Q: SSE 连接数有限制吗？¶

    浏览器对每个域名的 SSE 连接数有限制（通常 6 个）。如果需要更多连接，考虑： - 使用不同子域名 - 改用 WebSocket - 合并事件流（用一个连接推送多种事件）

    Q: SSE 安全吗？¶

    SSE 基于 HTTP，安全性取决于： - 使用 HTTPS 加密传输 - 服务端做认证/鉴权（Token、Cookie 等） - 注意 CORS 配置

    八、小结¶

    要点 内容
    4 个字段 data（必须）、event、id、retry
    事件分隔 空行 \n\n
    多行数据 多个 data: 行，客户端用 \n 拼接
    注释/心跳 : 开头的行
    自动重连 浏览器原生支持，带 Last-Event-ID
    重连间隔 retry: 字段控制（毫秒）
