    SSE 教程（一）：协议基础¶

    参考： W3C Server-Sent Events

    一、什么是 SSE？¶

    Server-Sent Events（SSE） 是一种基于 HTTP 的服务器向客户端单向推送技术。

    核心思想：客户端建立一次 HTTP 连接后，服务器可以持续不断地向客户端推送数据，直到连接关闭。

    客户端                          服务器
  |---- HTTP GET /events -------->|
  |<--- 200 OK (Connection: keep-alive) ---|
  |<--- data: hello\n\n -----------|
  |<--- data: world\n\n -----------|
  |<--- data: goodbye\n\n ---------|
  |          ...连接保持...         |

    二、SSE 的特点¶

    特性 说明
    方向 单向：服务器 → 客户端
    协议 基于标准 HTTP，无需额外协议
    数据格式 纯文本（UTF-8）
    自动重连 浏览器原生支持断线自动重连
    内容类型 text/event-stream
    编码 仅支持 UTF-8

    三、SSE vs WebSocket vs 长轮询¶

    这是面试高频题，务必掌握：

    对比维度 SSE WebSocket 长轮询 (Long Polling)
    通信方向 单向（服务器→客户端） 全双工 单向（客户端请求，服务器响应）
    底层协议 HTTP WebSocket (ws/wss) HTTP
    数据格式 纯文本 文本 / 二进制 任意
    自动重连 ✅ 浏览器原生支持 ❌ 需手动实现 ✅ 天然支持
    代理/防火墙穿透 ✅ 好（标准 HTTP） ⚠️ 可能被拦截 ✅ 好
    复杂度 低 中 中
    适用场景 通知、Feed、AI 流式输出 聊天、游戏、协作编辑 兼容性要求高的场景

    什么时候选 SSE？¶

    ✅ 选 SSE： - AI 大模型流式输出（ChatGPT 的 "打字机" 效果） - 实时通知 / 消息推送 - 股票行情、比赛比分等单向数据流 - 构建状态监控

    ❌ 不选 SSE： - 需要客户端频繁向服务器发数据 → WebSocket - 需要传输二进制数据（图片、音频） → WebSocket - 需要双向低延迟通信 → WebSocket

    四、一个最简单的 SSE 示例¶

    服务端（Python FastAPI）¶

    from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import asyncio

app = FastAPI()

async def event_generator():
    for i in range(5):
        yield f"data: 第 {i} 条消息\n\n"
        await asyncio.sleep(1)

@app.get("/events")
async def events():
    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream"
    )

    客户端（浏览器）¶

    const source = new EventSource("/events");

source.onmessage = (event) => {
    console.log("收到消息:", event.data);
};

source.onerror = (err) => {
    console.error("连接错误:", err);
};

    就这么简单！浏览器原生 EventSource API 自动处理连接、解析、重连。

    五、SSE 的 HTTP 请求长什么样？¶

    客户端请求¶

    GET /events HTTP/1.1
Host: example.com
Accept: text/event-stream
Cache-Control: no-cache
Last-Event-ID: 42        ← 断线重连时带上上次收到的事件 ID

    服务器响应¶

    HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
Transfer-Encoding: chunked

    关键点： - Content-Type: text/event-stream — 告诉浏览器这是 SSE 流 - Cache-Control: no-cache — 禁止缓存 - Connection: keep-alive — 保持连接 - Transfer-Encoding: chunked — 分块传输（数据边生成边发送）

    六、SSE 的数据流格式¶

    SSE 的数据格式非常简单直观：

    data: 第一条消息

data: 第二条消息

data: {
data:   "name": "JSON",
data:   "value": 42
data: }

    规则： - 每个事件以 data: 开头 - 多行数据用多个 data: 行 - 空行（\n\n）表示一个事件结束 - 文本必须是 UTF-8 编码

    下一章会详细讲解所有字段（data、event、id、retry）。

    七、SSE 在 AI 领域的应用¶

    SSE 近年来因为 AI 大模型而重新火了起来：

    • ChatGPT / Claude API — 流式输出使用 SSE 协议
    • OpenAI API — stream: true 参数返回 SSE 流
    • 各种 AI 应用 — 打字机效果几乎都用 SSE 实现
    # OpenAI API 的 SSE 响应示例
data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"你"},"index":0}]}

data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"好"},"index":0}]}

data: [DONE]

    理解 SSE 协议，对做 AI 应用开发非常重要。

    要点 内容
    SSE 是什么 基于 HTTP 的服务器→客户端单向推送技术
    核心优势 简单、自动重连、HTTP 兼容性好
    适用场景 通知、Feed、AI 流式输出
    不适用场景 双向通信、二进制传输
    Content-Type text/event-stream
    数据格式 data: xxx\n\n
