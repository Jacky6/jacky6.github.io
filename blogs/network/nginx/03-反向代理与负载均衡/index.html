    Nginx 教程（三）：反向代理与负载均衡¶

    参考： nginx.org/en/docs/

    一、反向代理（Reverse Proxy）¶

    什么是反向代理？¶

    客户端  →  Nginx（反向代理）  →  后端服务器
              ↘                →  后端服务器
               ↘               →  后端服务器

    正向代理：代理客户端，帮客户端访问外部资源（如翻墙代理） 反向代理：代理服务器，替后端服务器接收和分发请求

    基本配置¶

    server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://localhost:8080;
    }
}

    所有请求都会被转发到 http://localhost:8080。

    常用代理指令¶

    server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://localhost:8080;

        # 传递客户端真实信息
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;

        # 缓冲设置
        proxy_buffering on;
        proxy_buffer_size 4k;
        proxy_buffers 8 4k;
    }
}

    常用变量说明¶

    变量 含义
    $host 请求的 Host 头
    $remote_addr 客户端真实 IP
    $proxy_add_x_forwarded_for 累加的 X-Forwarded-For 链
    $scheme 协议（http 或 https）

    二、静态与动态分离¶

    将静态文件（图片、CSS、JS）由 Nginx 直接提供，动态请求转发给后端：

    server {
    listen 80;
    server_name example.com;

    # 静态文件：直接由 Nginx 处理
    location ~* \.(gif|jpg|png|css|js|ico)$ {
        root /data/static;
        expires 30d;  # 缓存 30 天
    }

    # 动态请求：转发到后端
    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

    三、负载均衡（Load Balancing）¶

    upstream 模块¶

    http {
    # 定义后端服务器组
    upstream backend {
        server srv1.example.com;
        server srv2.example.com;
        server srv3.example.com;
    }

    server {
        listen 80;

        location / {
            proxy_pass http://backend;
        }
    }
}

    四、负载均衡算法¶

    1. 轮询（Round-Robin）— 默认¶

    请求按顺序分发到每台服务器：

    upstream backend {
    server srv1.example.com;
    server srv2.example.com;
    server srv3.example.com;
}

    请求 1 → srv1
请求 2 → srv2
请求 3 → srv3
请求 4 → srv1
请求 5 → srv2
...

    2. 加权轮询（Weighted）¶

    给性能更好的服务器分配更多请求：

    upstream backend {
    server srv1.example.com weight=3;  # 每 5 个请求中 3 个给它
    server srv2.example.com;            # 1 个
    server srv3.example.com;            # 1 个
}

    3. 最少连接（Least Connections）¶

    将新请求分发给当前活跃连接数最少的服务器：

    upstream backend {
    least_conn;
    server srv1.example.com;
    server srv2.example.com;
    server srv3.example.com;
}

    适用场景： 请求处理时间差异大的场景（有的请求很快，有的很慢）

    4. IP Hash（会话保持）¶

    同一客户端的请求始终发往同一台服务器：

    upstream backend {
    ip_hash;
    server srv1.example.com;
    server srv2.example.com;
    server srv3.example.com;
}

    适用场景： 需要会话保持（Session Stickiness）的场景 原理： 用客户端 IP 地址做哈希计算

    五、服务器状态标记¶

    upstream backend {
    server srv1.example.com weight=3;    # 权重 3
    server srv2.example.com;              # 正常
    server srv3.example.com backup;       # 备用（只有其他都挂了才用它）
    server srv4.example.com down;         # 标记为下线（不参与分发）
}
    参数 说明
    weight=N 权重值，默认 1
    max_fails=N 连续失败 N 次后标记为失败（默认 1）
    fail_timeout=时间 失败超时时间，也是标记失败后的冷却时间（默认 10 秒）
    backup 备用服务器
    down 标记为永久下线

    健康检查示例¶

    upstream backend {
    server srv1.example.com max_fails=3 fail_timeout=30s;
    server srv2.example.com max_fails=3 fail_timeout=30s;
}

    如果 srv1 连续 3 次请求失败，Nginx 会标记它为失败，30 秒内不向其分发请求。30 秒后，Nginx 会用新的客户端请求试探它，如果成功则恢复。

    六、完整反向代理 + 负载均衡示例¶

    http {
    # 定义后端
    upstream myapp {
        least_conn;
        server 192.168.1.10:8080 weight=3 max_fails=3 fail_timeout=30s;
        server 192.168.1.11:8080 weight=2 max_fails=3 fail_timeout=30s;
        server 192.168.1.12:8080 backup;
    }

    server {
        listen 80;
        server_name api.example.com;

        # 静态资源
        location ~* \.(css|js|png|jpg|ico)$ {
            root /var/www/static;
            expires 7d;
        }

        # API 请求转发到后端集群
        location /api/ {
            proxy_pass http://myapp;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;

            proxy_connect_timeout 10s;
            proxy_read_timeout 30s;
            proxy_send_timeout 30s;
        }
    }
}

    七、FastCGI 代理（PHP 场景）¶

    Nginx 本身不能执行 PHP，需要通过 FastCGI 协议转发给 PHP-FPM：

    server {
    listen 80;
    server_name example.com;
    root /var/www/html;
    index index.php index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        fastcgi_pass 127.0.0.1:9000;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
    指令 说明
    fastcgi_pass FastCGI 服务器地址
    fastcgi_index 默认索引文件
    fastcgi_param 传递给 FastCGI 的参数
    SCRIPT_FILENAME PHP 需要知道要执行哪个脚本

    八、最佳实践¶

    1. 始终传递真实客户端信息（X-Real-IP、X-Forwarded-For）
    2. 合理设置超时，防止慢请求占满连接
    3. 使用 upstream 而非硬编码 后端地址
    4. 启用健康检查（max_fails + fail_timeout）
    5. 静态资源设置 expires 头，减少不必要的请求
