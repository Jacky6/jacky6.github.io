    Nginx 教程（六）：常用命令与排错指南¶

    参考： nginx.org/en/docs/

    一、常用命令速查¶

    服务管理¶

    # systemd 方式（推荐）
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx       # 重载配置，不断连
sudo systemctl status nginx

# 直接调用 nginx
nginx                             # 启动
nginx -s stop                     # 快速关闭
nginx -s quit                     # 优雅关闭
nginx -s reload                   # 重载配置
nginx -s reopen                   # 重新打开日志

# 检查
nginx -t                          # 测试配置文件语法
nginx -T                          # 测试语法并打印完整配置
nginx -v                          # 显示版本
nginx -V                          # 显示版本及编译参数

    reload vs restart¶

    方式 行为 推荐
    reload 主进程检查新配置 → 启动新 Worker → 旧 Worker 处理完当前请求后退出 ✅ 日常使用
    restart 完全停止再启动，会有短暂中断 ❌ 除非必要

    二、常见问题排查¶

    2.1 查看日志¶

    # 实时查看错误日志
tail -f /var/log/nginx/error.log

# 实时查看访问日志
tail -f /var/log/nginx/access.log

# 最近 50 条错误日志
tail -n 50 /var/log/nginx/error.log

# 搜索特定错误
grep "Permission denied" /var/log/nginx/error.log

    2.2 常见错误及解决方案¶

    错误信息 原因 解决方案
    nginx: [emerg] unknown directive 配置拼写错误或缺少模块 检查语法，确认模块已编译
    403 Forbidden 权限不足或无 index 文件 检查文件权限，确认 index 存在
    502 Bad Gateway 后端服务不可用 检查后端是否启动、端口是否正确
    504 Gateway Timeout 后端响应超时 增大 proxy_read_timeout
    413 Request Entity Too Large 请求体过大 增大 client_max_body_size
    connect() failed (111: Connection refused) 后端拒绝连接 确认后端服务运行中
    Permission denied Nginx 无权访问文件 chmod / chown 修正权限
    bind() to 0.0.0.0:80 failed (98: Address already in use) 端口被占用 sudo lsof -i:80 查找占用进程

    三、端口占用排查¶

    # 查看谁占用了 80 端口
sudo lsof -i:80

# 或使用 ss
sudo ss -tlnp | grep :80

# 或使用 netstat
sudo netstat -tlnp | grep :80

    四、权限问题¶

    文件权限¶

    # 网站根目录权限
sudo chown -R www-data:www-data /var/www/html
sudo chmod -R 755 /var/www/html

# 或使用 nginx 用户（CentOS）
sudo chown -R nginx:nginx /var/www/html

    SELinux（CentOS/RHEL）¶

    # 检查 SELinux 状态
sestatus

# 临时关闭
sudo setenforce 0

# 永久关闭（修改 /etc/selinux/config）
# 或设置正确的上下文：
sudo chcon -Rt httpd_sys_content_t /var/www/html

    五、防火墙配置¶

    UFW（Ubuntu）¶

    sudo ufw allow 'Nginx Full'    # 允许 HTTP + HTTPS
sudo ufw allow 'Nginx HTTP'    # 仅允许 HTTP
sudo ufw allow 'Nginx HTTPS'   # 仅允许 HTTPS

    firewalld（CentOS）¶

    sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload

    iptables¶

    sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

    六、Debug 模式¶

    启用 Debug 日志¶

    error_log /var/log/nginx/error.log debug;

    注意： debug 级别会产生大量日志，仅用于排查问题，用完记得改回 warn 或 error。

    查看进程状态¶

    # 查看所有 Nginx 进程
ps -ax | grep nginx

# 查看主进程 PID
cat /var/run/nginx.pid
# 或
cat /run/nginx.pid

# 发送信号到主进程
kill -s QUIT <master_pid>    # 优雅关闭
kill -s HUP <master_pid>     # 重载配置
kill -s USR1 <master_pid>    # 重新打开日志

    七、配置验证脚本¶

    #!/bin/bash
# nginx-check.sh

echo "=== Nginx 配置检查 ==="

echo -n "配置文件语法: "
nginx -t 2>&1 | tail -1

echo -n "Nginx 状态: "
systemctl is-active nginx

echo -n "Nginx 版本: "
nginx -v 2>&1

echo ""
echo "=== 监听端口 ==="
sudo ss -tlnp | grep nginx

echo ""
echo "=== 最近错误 ==="
tail -5 /var/log/nginx/error.log

    八、快速故障诊断流程¶

    网站无法访问？
├── Nginx 是否在运行？
│   └── systemctl status nginx
│       ├── 未运行 → systemctl start nginx
│       └── 运行中 ↓
│
├── 端口是否在监听？
│   └── ss -tlnp | grep :80
│       ├── 未监听 → 检查配置
│       └── 监听中 ↓
│
├── 防火墙是否放行？
│   └── ufw status / firewall-cmd --list-all
│       ├── 未放行 → 添加规则
│       └── 已放行 ↓
│
├── 配置文件是否正确？
│   └── nginx -t
│       ├── 有错误 → 查看并修复
│       └── 正确 ↓
│
├── 错误日志怎么说？
│   └── tail -f /var/log/nginx/error.log
│       └── 根据错误信息定位
│
└── 后端服务是否正常？
    ├── curl -I http://localhost:8080
    └── systemctl status <backend-service>

    九、实用调试技巧¶

    测试配置是否生效¶

    # 用 curl 测试
curl -I http://localhost/              # 查看响应头
curl -v http://localhost/              # 查看完整通信过程
curl -H "Host: example.com" http://localhost/  # 模拟域名访问

    查看 Nginx 加载的配置¶

    nginx -T    # 打印完整配置（包括 include 的文件）

    性能基准测试¶

    # 使用 ab（Apache Bench）
ab -n 1000 -c 100 http://localhost/

# 使用 wrk
wrk -t4 -c100 -d10s http://localhost/

    十、配置文件备份¶

    # 备份当前配置
sudo cp -r /etc/nginx /etc/nginx.backup.$(date +%Y%m%d)

# 备份主配置
sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.$(date +%Y%m%d)
