    MCP Inspector 调试与测试¶

    MCP Inspector 是官方参考调试工具。它同时提供 Web、CLI 和 TUI，并能显式测试 Legacy 与 Modern 协议时代。

    1. 能做什么¶

    Inspector 可以：

    • 启动并连接本地 stdio Server；
    • 连接远程 Streamable HTTP Server；
    • 查看 Discover、Capabilities 和协议版本；
    • 列出/调用 Tools；
    • 列出/读取 Resources；
    • 获取 Prompts；
    • 查看 JSON-RPC 与 HTTP Headers；
    • 测试 MRTR、Progress、Cancellation、Subscriptions；
    • 执行 OAuth；
    • 以 JSON 输出供 CI 使用。

    它不替代：

    • 单元测试；
    • 业务集成测试；
    • 安全扫描；
    • 目标 Host 的真实兼容测试；
    • 负载和故障演练。

    2. 环境要求¶

    当前 Inspector 需要 Node.js 22.19+，可通过 npx 直接运行：

    node --version
npx @modelcontextprotocol/inspector --help

    3. 三种模式¶

    模式 用途 启动方式
    Web 最丰富的可视化协议调试 默认
    CLI 自动化、CI、JSON 输出 --cli
    TUI 无浏览器交互 --tui

    Mode Flag 必须放在命令行前部。其后参数可能被解释为 Client 或 Server 参数。

    4. 连接 stdio Server¶

    4.1 Web¶

    npx @modelcontextprotocol/inspector \
  uv --directory /ABSOLUTE/PATH/server run server.py

    Inspector 启动本地 Web UI，并把后面的命令作为 stdio Server 启动命令。

    4.2 CLI¶

    列出 Tool：

    npx @modelcontextprotocol/inspector --cli \
  uv --directory /ABSOLUTE/PATH/server run server.py \
  --protocol-era modern \
  --method tools/list

    调用 Tool：

    npx @modelcontextprotocol/inspector --cli \
  uv --directory /ABSOLUTE/PATH/server run server.py \
  --protocol-era modern \
  --method tools/call \
  --tool-name search_documents \
  --tool-arg query=MCP \
  --format json

    4.3 TUI¶

    npx @modelcontextprotocol/inspector --tui \
  uv --directory /ABSOLUTE/PATH/server run server.py

    5. 连接远程 Server¶

    npx @modelcontextprotocol/inspector \
  --server-url https://api.example.com/mcp \
  --transport http

    CLI 示例：

    npx @modelcontextprotocol/inspector --cli \
  https://api.example.com/mcp \
  --transport http \
  --protocol-era modern \
  --method tools/list \
  --format json

    远程服务涉及 OAuth 时优先使用 Inspector 的授权能力，不要把真实 Token 写进 Shell History。

    6. Protocol Era¶

    Inspector 的 Era：

    Era 行为
    legacy 默认，直接 initialize，不探测
    auto 先 server/discover，非 Modern 结果则回退 initialize
    modern 固定 2026-07-28，不回退

    为什么默认不是 Auto：调试工具必须让流量可预测。对静默 Legacy stdio Server 的 Discover Probe 可能卡住并污染 Protocol Transcript。

    6.1 必测组合¶

    --protocol-era modern
--protocol-era legacy   # 如果宣称 Dual-era
--protocol-era auto     # 如果目标 Client 会自动探测

    只测试默认值会漏掉 Modern 协议问题。

    7. Web UI 调试顺序¶

    推荐顺序：

    1. Connection：进程/URL 是否连通；
    2. Server：版本、能力和 Instructions；
    3. Tools：Schema、正常调用、错误调用；
    4. Resources：URI、MIME、读取、订阅；
    5. Prompts：参数、消息和资源引用；
    6. Protocol：JSON-RPC ID、_meta、resultType；
    7. Network：HTTP Headers、状态码、SSE；
    8. Logs：stderr 或请求级日志；
    9. Subscriptions：Acknowledged 与重连；
    10. OAuth：Discovery、Scope、Token 状态。

    8. Modern 协议重点检查¶

    8.1 Discover¶

    确认：

    • server/discover 成功；
    • supportedVersions 含 2026-07-28；
    • Capability 与实际方法一致；
    • serverInfo 只用于显示；
    • ttlMs、cacheScope 合理。

    8.2 每请求 _meta¶

    确认 Request 有：

    {
  "io.modelcontextprotocol/protocolVersion": "2026-07-28",
  "io.modelcontextprotocol/clientCapabilities": {}
}

    缺失时应看到 -32602。

    8.3 resultType¶

    • 普通结果：complete；
    • MRTR：input_required；
    • 未协商的未知值应报错；
    • 旧版缺失字段按兼容规则显示为 Complete。

    8.4 HTTP Headers¶

    Network 面板检查：

    MCP-Protocol-Version
Mcp-Method
Mcp-Name
Mcp-Param-*

    典型现代错误：

    HTTP Code 含义
    400 -32020 HeaderMismatch
    400 -32021 缺少 Client Capability
    400 -32022 不支持协议版本
    404 -32601 Method Not Found

    9. Tool 测试矩阵¶

    对每个 Tool 至少覆盖：

    类型 用例
    正常 最小合法参数、完整参数
    Schema 缺少必填、类型错误、额外字段
    边界 空字符串、最大长度、数值上下界
    业务 无权限、资源不存在、状态冲突
    上游 Timeout、429、4xx、5xx、非法数据
    输出 Text、Structured、Resource、二进制
    可靠性 重复调用、并发调用、取消
    安全 注入、路径穿越、超大输入、敏感日志

    验证错误分类：

    • 请求结构错误 → JSON-RPC Error；
    • 模型可修正的执行错误 → isError: true。

    10. Resource 测试矩阵¶

    • resources/list 分页；
    • resources/templates/list；
    • 文本和 Blob；
    • 一个 Read 返回多个 Content；
    • 不存在 URI 返回 -32602；
    • 防路径穿越；
    • MIME 与内容匹配；
    • cacheScope 不泄露用户数据；
    • Resource Subscription 确认和更新通知；
    • 断线后重建 Subscription。

    11. MRTR 测试¶

    需要覆盖：

    • 单轮 Form Elicitation；
    • 用户 Accept；
    • 用户 Decline；
    • 用户 Cancel；
    • URL Elicitation；
    • 多个并行 inputRequests；
    • 仅 requestState 的 Round；
    • 多轮；
    • requestState 篡改、过期、跨用户复用；
    • 无限循环达到 Client 上限；
    • Retry 使用新 JSON-RPC ID。

    Inspector 在 Modern 模式下会把多个 Retry Round 聚合成一段 MRTR Conversation，便于确认每轮输入和状态。

    12. Subscription 测试¶

    现代模式：

    1. 发送 subscriptions/listen；
    2. 第一条订阅消息必须是 Acknowledged；
    3. 检查 Server 实际接受的 Filter；
    4. 触发 Tool/Resource/Prompt 变化；
    5. 检查每条消息的 Subscription ID；
    6. 关闭流测试取消；
    7. 模拟断线测试重建。

    Legacy 模式使用 resources/subscribe 或独立 GET 通知流，不能拿它证明 Modern Listen 正常。

    13. Progress 与 Cancellation¶

    长 Tool：

    • Request 带 Progress Token；
    • Progress 单调增加；
    • 消息频率受控；
    • 完成后不再发送；
    • Soft Timeout 可延长，Absolute Timeout 不延长。

    取消：

    • Modern HTTP：关闭当前 SSE Stream；
    • stdio：notifications/cancelled；
    • Server 释放资源；
    • 已发生副作用有明确状态；
    • 取消后迟到结果被忽略。

    14. stdio 常见问题¶

    Server 启动后没有输出¶

    正常。它在等 stdin。用 Inspector 发送协议消息。

    Unexpected token / JSON Parse Error¶

    通常是 stdout 被污染：

    • print()；
    • Banner；
    • 日志写 stdout；
    • 子库输出；
    • Traceback。

    把日志全部改到 stderr。

    Host 中启动失败，Terminal 正常¶

    通常是：

    • 使用相对路径；
    • GUI Host 的 PATH 不同；
    • 工作目录不同；
    • 虚拟环境未激活；
    • 环境变量没传入。

    使用绝对 command、绝对参数路径和显式 env。

    运行一段时间后卡死¶

    检查：

    • stderr 是否无人消费导致 Pipe 满；
    • stdout Reader 是否只有一个；
    • Pending ID 是否泄漏；
    • Tool 是否阻塞事件循环；
    • Server 是否等待不存在的 Session 状态。

    15. HTTP 常见问题¶

    400¶

    先看 JSON-RPC Body：

    • -32020：Header 与 Body；
    • -32021：Client Capability；
    • -32022：Version；
    • -32602：Request Params / _meta。

    401 / 403¶

    • 401：缺失、过期、Audience 错误 Token；
    • 403：Origin 或 Scope 不足；
    • 检查 WWW-Authenticate。

    SSE 有延迟¶

    • Nginx/代理 Buffering；
    • 缺少 X-Accel-Buffering: no；
    • 压缩或 CDN 缓冲；
    • Idle Timeout；
    • Server 未 Flush Event。

    断线后重复写操作¶

    Client 盲目重试非幂等 Tool。增加 Idempotency Key，并在重试前查询状态。

    16. 日志¶

    stdio¶

    写 stderr，记录：

    • 启动和依赖；
    • Request ID；
    • Method/Tool Name；
    • 参数摘要，不记录秘密；
    • 耗时和结果状态；
    • 上游错误；
    • 取消阶段。

    HTTP¶

    使用服务端日志和 OpenTelemetry：

    • traceparent；
    • HTTP Status；
    • JSON-RPC Error Code；
    • Server/SDK/Protocol Version；
    • Tenant、Scope；
    • SSE 生命周期。

    协议级 Logging 已 Deprecated，不应作为新系统的唯一观测方式。

    17. Inspector Secret 风险¶

    Inspector 可能存储：

    • OAuth Token；
    • OAuth Client Secret；
    • stdio env 值。

    有 OS Keychain 时使用 Keychain；Linux Headless/SSH/Container 可能回退到：

    ~/.mcp-inspector/secrets.json

    可能是未加密文件。开发环境应：

    • 使用测试凭据；
    • 配置加密或 Memory-only；
    • 不把真实生产 Secret 放入演示配置；
    • 测试后清理 Token；
    • 限制文件权限。

    18. CI 分层¶

    Unit Tests
    ↓
Schema / Handler Tests
    ↓
Inspector CLI Protocol Tests
    ↓
Target Host Integration Tests
    ↓
Security / Load / Failure Tests

    基础 CI 示例：

    set -euo pipefail

npx @modelcontextprotocol/inspector --cli \
  uv --directory "$PWD/server" run server.py \
  --protocol-era modern \
  --method tools/list \
  --format json > tools.json

jq -e '.result.tools | length > 0' tools.json

    如果宣称 Legacy：

    npx @modelcontextprotocol/inspector --cli \
  uv --directory "$PWD/server" run server.py \
  --protocol-era legacy \
  --method tools/list \
  --format json > tools-legacy.json

    固定 Inspector 和 Server 依赖版本，避免 CI 每次拉 latest 得到不同协议行为。

    19. Bug 报告模板¶

    Server version:
SDK + version:
Protocol era/version:
Transport:
OS/runtime:
Inspector version:
Expected:
Actual:
Minimal reproduction:
JSON-RPC transcript（已脱敏）:
HTTP status/headers（已脱敏）:
stderr/server logs（已脱敏）:

    不要提交 Token、Cookie、Authorization Code、完整用户文件或 PII。
