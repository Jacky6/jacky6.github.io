    Tools、Resources 与 Prompts¶

    三类 Server 原语看起来都在“给模型东西”，但它们的语义、控制方和协议方法不同。选错原语会导致安全、交互和上下文管理混乱。

    1. 总览¶

    原语 表达内容 典型控制方 是否通常有副作用 主要方法
    Tool 可执行动作 模型，经 Host 审批 可能有 tools/list、tools/call
    Resource URI 标识的上下文 Host/用户 通常只读 resources/list、resources/read
    Prompt 参数化消息模板 用户 无 prompts/list、prompts/get

    判断原则：

    要执行动作？                 → Tool
要按 URI 读取上下文？         → Resource
要提供用户显式选择的模板？     → Prompt

    2. Tools¶

    2.1 声明能力¶

    支持 Tool 的 Server 在 server/discover 中声明：

    {
  "capabilities": {
    "tools": {
      "listChanged": true
    }
  }
}
    • listChanged: true 表示可以在订阅流中发送工具列表变化；
    • Server 必须响应 tools/list；
    • 列表可以为空或动态变化；
    • 列表不能因为“同一连接之前做过什么”而变化；
    • 列表可以根据本次请求的授权上下文过滤；
    • 稳定集合应使用确定性排序，便于缓存与 LLM Prompt Cache。

    2.2 tools/list¶

    {
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {
    "cursor": "optional-opaque-cursor",
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    {
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "complete",
    "tools": [
      {
        "name": "orders.create",
        "title": "创建订单",
        "description": "为已确认的购物车创建订单。调用前必须获得用户确认。",
        "inputSchema": {
          "type": "object",
          "properties": {
            "cart_id": {
              "type": "string",
              "description": "create_cart 返回的购物车 ID"
            },
            "idempotency_key": {
              "type": "string",
              "description": "调用方生成的幂等键"
            }
          },
          "required": ["cart_id", "idempotency_key"],
          "additionalProperties": false
        },
        "outputSchema": {
          "type": "object",
          "properties": {
            "order_id": {"type": "string"},
            "status": {"type": "string"}
          },
          "required": ["order_id", "status"]
        }
      }
    ],
    "ttlMs": 300000,
    "cacheScope": "private"
  }
}

    2.3 Tool 定义¶

    关键字段：

    字段 含义
    name Server 内唯一的程序标识
    title UI 展示名
    description 给用户和模型看的行为说明
    inputSchema 参数 JSON Schema，必填
    outputSchema 结构化返回 JSON Schema，可选
    icons UI 图标，可选且必须按不可信资源处理
    annotations 行为提示，可选且不可信

    Tool 名建议：

    • 1 到 128 字符；
    • 区分大小写；
    • 仅字母、数字、_、-、.；
    • 在一个 Server 内唯一；
    • 多 Server 聚合时由 Host 处理重名，例如 github.search 与 docs.search。

    不要假设 Server name 全局唯一，不能只靠它消歧。

    2.4 描述设计¶

    差：

    Search stuff.

    好：

    在已授权的内部知识库中检索技术文档。仅用于产品、架构和运维问题；
不要用于互联网搜索。query 应包含关键实体和错误码，最多返回 10 条。

    描述应包含：

    • 使用场景与不适用场景；
    • 副作用；
    • 前置条件；
    • 参数含义与约束；
    • 结果范围；
    • 失败后的恢复方式。

    Tool 描述本身来自 Server，Host 必须把它视为不可信输入，防止 Tool Poisoning。

    2.5 tools/call¶

    {
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "orders.create",
    "arguments": {
      "cart_id": "cart_8f13",
      "idempotency_key": "req_f4b2"
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    Server 应依次校验：

    1. Tool 存在；
    2. Schema 合法且参数匹配；
    3. 调用者身份和 Scope；
    4. 资源所有权；
    5. 业务约束；
    6. 限流、幂等和超时。

    2.6 Tool Result¶

    Tool 可以返回：

    • TextContent；
    • ImageContent；
    • AudioContent；
    • ResourceLink；
    • Embedded Resource；
    • 任意 JSON structuredContent。
    {
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "resultType": "complete",
    "content": [
      {
        "type": "text",
        "text": "订单 order_123 已创建"
      },
      {
        "type": "resource_link",
        "uri": "orders://order_123",
        "name": "order_123"
      }
    ],
    "structuredContent": {
      "order_id": "order_123",
      "status": "created"
    },
    "isError": false
  }
}

    提供 outputSchema 时：

    • Server 的 structuredContent 必须符合 Schema；
    • Client 应重新验证，而不是盲信 Server；
    • 为兼容旧 Client，Server 最好同时提供 JSON 的 TextContent 表示。

    2.7 错误分类¶

    协议错误：

    {
  "error": {
    "code": -32602,
    "message": "Unknown tool: orders.creat"
  }
}

    工具执行错误：

    {
  "result": {
    "resultType": "complete",
    "content": [
      {"type": "text", "text": "购物车已过期，请先创建新购物车"}
    ],
    "isError": true
  }
}

    可由模型修正的业务/参数错误应使用 isError: true，让模型有机会恢复。

    2.8 有状态业务 Tool¶

    现代 MCP 没有 Session。跨调用状态使用显式句柄：

    create_basket() → basket_id
add_item(basket_id, sku)
checkout(basket_id)

    句柄设计：

    • 使用高熵不透明值；
    • 绑定认证主体；
    • 每次调用重新鉴权；
    • 有 TTL 和清理策略；
    • Tool 描述中说明有效期；
    • 过期时返回可恢复执行错误；
    • 高风险操作配合幂等键。

    3. Resources¶

    3.1 声明能力¶

    {
  "capabilities": {
    "resources": {
      "listChanged": true,
      "subscribe": true
    }
  }
}
    • listChanged：可发送资源列表变化；
    • subscribe：支持在 subscriptions/listen 中订阅具体 URI 更新；
    • 两者可以独立存在。

    3.2 resources/list¶

    {
  "jsonrpc": "2.0",
  "id": 10,
  "method": "resources/list",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    {
  "jsonrpc": "2.0",
  "id": 10,
  "result": {
    "resultType": "complete",
    "resources": [
      {
        "uri": "docs://architecture/overview",
        "name": "architecture-overview",
        "title": "架构总览",
        "description": "当前系统架构说明",
        "mimeType": "text/markdown",
        "size": 12840,
        "annotations": {
          "audience": ["user", "assistant"],
          "priority": 0.9,
          "lastModified": "2026-10-01T08:00:00Z"
        }
      }
    ],
    "ttlMs": 300000,
    "cacheScope": "private"
  }
}

    3.3 resources/read¶

    {
  "jsonrpc": "2.0",
  "id": 11,
  "method": "resources/read",
  "params": {
    "uri": "docs://architecture/overview",
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    文本内容：

    {
  "resultType": "complete",
  "contents": [
    {
      "uri": "docs://architecture/overview",
      "mimeType": "text/markdown",
      "text": "# Architecture\n..."
    }
  ],
  "ttlMs": 60000,
  "cacheScope": "private"
}

    二进制内容使用 Base64 blob：

    {
  "uri": "images://diagram.png",
  "mimeType": "image/png",
  "blob": "iVBORw0KGgoAAA..."
}

    一个 Read 可以返回多个 Content，例如读取目录时返回多个文件。

    不存在的资源必须返回 -32602，不能返回含糊的空 contents。旧版 Client 兼容时也应识别历史 -32002。

    3.4 URI 设计¶

    常见 URI：

    Scheme 使用建议
    file:// 文件系统语义，不要求一定是物理文件
    https:// Client 可以直接从 Web 获取时使用
    git:// Git 对象或仓库数据
    自定义 Scheme 遵守 RFC 3986，例如 orders://order_123

    如果内容必须经 MCP Server 鉴权、转换或审计，不应仅因为来源是 Web 就使用 https://；可以定义业务 Scheme 并通过 resources/read 获取。

    Server 必须防止：

    • 路径穿越；
    • 非法 Scheme；
    • 跨租户 URI；
    • 超大二进制内容；
    • MIME 欺骗；
    • 未授权资源枚举。

    3.5 Resource Templates¶

    参数化资源使用 RFC 6570 URI Template：

    {
  "uriTemplate": "repo://{owner}/{repo}/file/{path}",
  "name": "repository-file",
  "description": "读取仓库文件",
  "mimeType": "text/plain"
}

    通过 resources/templates/list 发现。参数值可配合 completion/complete 自动补全。

    3.6 资源更新订阅¶

    Client 用 subscriptions/listen 请求：

    {
  "notifications": {
    "resourceSubscriptions": [
      "docs://architecture/overview"
    ]
  }
}

    资源改变时 Server 发送：

    {
  "jsonrpc": "2.0",
  "method": "notifications/resources/updated",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/subscriptionId": 50
    },
    "uri": "docs://architecture/overview"
  }
}

    通知只表示“缓存可能过期”，Client 重新调用 resources/read 获取内容。

    4. Prompts¶

    4.1 声明能力¶

    {
  "capabilities": {
    "prompts": {
      "listChanged": true
    }
  }
}

    4.2 prompts/list¶

    {
  "jsonrpc": "2.0",
  "id": 20,
  "method": "prompts/list",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    {
  "resultType": "complete",
  "prompts": [
    {
      "name": "incident_review",
      "title": "事故复盘",
      "description": "根据事故时间线生成结构化复盘问题",
      "arguments": [
        {
          "name": "incident_id",
          "description": "事故编号",
          "required": true
        }
      ]
    }
  ],
  "ttlMs": 600000,
  "cacheScope": "public"
}

    Prompt 参数不是 Tool JSON Schema，而是参数描述列表。

    4.3 prompts/get¶

    {
  "jsonrpc": "2.0",
  "id": 21,
  "method": "prompts/get",
  "params": {
    "name": "incident_review",
    "arguments": {
      "incident_id": "INC-2026-42"
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    {
  "resultType": "complete",
  "description": "事故复盘工作流",
  "messages": [
    {
      "role": "user",
      "content": {
        "type": "text",
        "text": "请分析事故 INC-2026-42 的影响、根因和改进项。"
      }
    },
    {
      "role": "user",
      "content": {
        "type": "resource_link",
        "uri": "incidents://INC-2026-42/timeline",
        "name": "事故时间线"
      }
    }
  ]
}

    Prompt Message 角色只能是 user 或 assistant，内容可包含文本、图片、音频、ResourceLink 或 Embedded Resource。

    4.4 Prompt 安全¶

    Server 定义的 Prompt 仍是不可信内容：

    • 不应覆盖 Host 的系统安全策略；
    • 参数必须校验和转义；
    • Resource 访问必须独立鉴权；
    • Host 应向用户显示 Prompt 来源；
    • 不应把 Prompt 模板默认为系统级最高优先级指令。

    5. Completion¶

    支持参数自动补全的 Server 声明：

    {
  "capabilities": {
    "completions": {}
  }
}

    请求 Prompt 参数补全：

    {
  "jsonrpc": "2.0",
  "id": 30,
  "method": "completion/complete",
  "params": {
    "ref": {
      "type": "ref/prompt",
      "name": "code_review"
    },
    "argument": {
      "name": "language",
      "value": "py"
    },
    "context": {
      "arguments": {}
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

    {
  "resultType": "complete",
  "completion": {
    "values": ["python", "pytorch", "pyside"],
    "total": 10,
    "hasMore": true
  }
}

    Completion 支持 ref/prompt 和 ref/resource，最多返回 100 条。Client 应防抖，Server 应限流，并避免通过建议泄露无权限数据。

    6. 原语选择案例¶

    文件读取¶

    • 让用户从树中选择文档：Resource；
    • 让模型根据路径主动读取：可提供 read_file Tool；
    • 两者可以并存，但权限和语义应清楚。

    数据库¶

    • Schema、表说明：Resource；
    • 只读查询或写操作：Tool；
    • 常用分析问题模板：Prompt。

    GitHub¶

    • Issue/PR 内容：Resource；
    • 创建 Issue、合并 PR：Tool；
    • 代码审查模板：Prompt。

    7. 设计检查表¶

    Tool¶

    • 名称稳定、可消歧
    • 描述包含使用边界和副作用
    • 输入 Schema 严格
    • 结构化输出提供 outputSchema
    • 敏感操作由 Host 确认
    • 写操作有幂等策略
    • 执行错误对模型可行动

    Resource¶

    • URI 稳定且可验证
    • 防止路径穿越和跨租户访问
    • 正确声明 MIME 和大小
    • cacheScope 不泄露用户数据
    • 更新通知仅作缓存失效信号

    Prompt¶

    • 参数被校验
    • 用户能看到来源
    • 不提升为系统安全策略
    • 资源引用独立鉴权
    • 防止模板注入
