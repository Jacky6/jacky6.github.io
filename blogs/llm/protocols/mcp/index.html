    MCP 独立教程体系¶

    从协议原理、通信过程到 Server/Client 实现、OAuth、安全与生产部署。

    主线协议版本：2026-07-28（当前正式版本）

    资料核对日期：2026-10-28

    1. 为什么重建¶

    MCP 在 2026-07-28 发生了协议时代切换：

    • 从 initialize Session 改为每请求携带版本和能力；
    • 增加 server/discover；
    • 移除 Mcp-Session-Id；
    • 使用 MRTR 代替 Server→Client 独立 Request；
    • 使用 subscriptions/listen 代替旧订阅和 GET 通知流；
    • 所有成功结果增加 resultType；
    • List/Read/Discover 增加缓存提示。

    因此本目录不再使用一篇概念文章覆盖所有版本，而是把 Modern 协议作为主线，把 2025-11-25 及以前作为 Legacy 兼容专题。

    4. 现代协议速览¶

    sequenceDiagram
    participant C as MCP Client
    participant S as MCP Server

    opt 可选预发现
        C->>S: server/discover + _meta
        S-->>C: versions + capabilities
    end
    C->>S: tools/list + _meta
    S-->>C: tools + ttlMs + cacheScope
    C->>S: tools/call + _meta
    alt 直接完成
        S-->>C: resultType=complete
    else 需要输入
        S-->>C: resultType=input_required
        C->>C: 获取用户输入
        C->>S: 新 ID 重试 + inputResponses
        S-->>C: resultType=complete
    end

    每个现代 Request 必须携带：

    {
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",
    "io.modelcontextprotocol/clientCapabilities": {}
  }
}

    5. Modern 与 Legacy¶

    项目 Legacy：2025-11-25 及以前 Modern：2026-07-28
    初始化 initialize / initialized 无初始化握手
    协议状态 Session 级 每请求自包含
    发现 Initialize Result server/discover
    HTTP Session Mcp-Session-Id 已移除
    Server→Client 请求 独立 JSON-RPC Request MRTR input_required
    变化通知 GET SSE / Resource Subscribe subscriptions/listen
    SSE 恢复 Last-Event-ID 已移除
    成功结果 无统一类型字段 必须 resultType

    阅读旧文章和旧代码时，先确定其 Protocol Era，不能把两个时代的字段拼在一起。

    6. 关键事实¶

    1. MCP 与 Function Calling 不是替代关系：模型产生 Tool Call，MCP Client 再调用 Server。
    2. MCP stdio 是一行一条 JSON-RPC 消息，不是 Content-Length 分帧。
    3. server/discover 是 Modern Server 必须实现的方法，但 Client 调用是可选的。
    4. Modern 协议无 Session；业务状态使用显式 Handle。
    5. Tool 描述、Resource 和 Tool Result 都是不可信输入。
    6. 本地 stdio Server 是普通本机进程，不是 MCP 自动提供的沙箱。
    7. HTTP OAuth Token 必须绑定当前 MCP Server Audience，禁止 Token Passthrough。
    8. Roots、Sampling、协议 Logging 已 Deprecated，新实现不应采用。
    9. Tasks 已从 Core 移到 io.modelcontextprotocol/tasks 扩展。
    10. Inspector 默认可能使用 Legacy Era，测试 Modern 时必须显式选择。

    7. 术语¶

    术语 含义
    Host 承载 LLM、UI、权限和多个 Client 的 AI 应用
    Client 与一个 Server 通信的协议组件
    Server 提供 Tools、Resources、Prompts 的程序
    Tool 模型可选择调用的动作
    Resource URI 标识的上下文数据
    Prompt 用户可选择的参数化消息模板
    MRTR Server 返回补充输入要求，Client 以新 ID 重试原请求
    Protocol Era Legacy 初始化时代或 Modern 每请求元数据时代
    Capability 一方明确声明支持的可选协议功能
    Transport stdio 或 Streamable HTTP

    8. 版本维护约定¶

    本教程中的规范结论都应标注适用版本。协议更新时优先检查：

    1. Current Specification
    2. Versioning
    3. Changelog
    4. Deprecated Features
    5. Official SDKs

    SDK 示例必须同时标注 SDK 主版本，不能只写协议日期。
