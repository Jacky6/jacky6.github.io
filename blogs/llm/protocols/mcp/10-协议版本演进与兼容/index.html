    MCP 协议版本演进与兼容¶

    MCP 版本号不是 SDK 版本号。协议版本采用日期，当前正式版本是 2026-07-28。资料核对日期：2026-10-28。

    1. 版本标识¶

    协议版本格式：

    YYYY-MM-DD

    含义：该日期表示最后一次发生不向后兼容变更的日期。只要后续修改保持兼容，文档可以更新而不改变协议版本。

    版本状态：

    状态 含义
    Draft 正在演进，不适合作为生产兼容承诺
    Current 当前正式版本，可接受兼容性修订
    Final 历史完成版本，不再修改

    不要在生产中写 latest 或 draft 作为协议值。线上发送的是具体日期字符串。

    2. 协议版本 vs SDK 版本¶

    Protocol: 2026-07-28
Python SDK: 2.x.y
TypeScript SDK: package semantic version
你的 Server: 1.4.0

    三者独立：

    • 协议版本决定 Wire Semantics；
    • SDK 版本决定库 API 和实现覆盖；
    • Server 版本是业务软件版本。

    升级 SDK 不一定改变协议版本；升级协议支持也可能要求代码改造。

    3. 版本时间线¶

    协议版本 关键变化
    2024-11-05 初始公开协议；Legacy 初始化；HTTP+SSE
    2025-03-26 Streamable HTTP、OAuth 2.1、Tool Annotations、Audio；短暂加入 JSON-RPC Batch
    2025-06-18 移除 Batch；结构化 Tool Output；Elicitation；Resource Links；OAuth Resource Indicators；HTTP Version Header
    2025-11-25 URL Elicitation、Sampling Tools、实验性 Tasks、CIMD、Icons、JSON Schema 2020-12、SSE Poll/Resume 完善
    2026-07-28 无状态 Modern 时代：移除初始化 Session，加入 server/discover、MRTR、subscriptions/listen、结果类型、缓存提示

    4. 2024-11-05¶

    特点：

    • initialize → initialized；
    • Tools、Resources、Prompts；
    • Roots、Sampling；
    • stdio；
    • 旧 HTTP+SSE：GET 建立 SSE，Server 告诉 Client POST Endpoint。

    旧 HTTP+SSE 已 Deprecated，新系统不要实现。

    5. 2025-03-26¶

    主要变化：

    • OAuth 2.1 Authorization Framework；
    • Streamable HTTP 替换 HTTP+SSE；
    • Tool Annotations；
    • Audio Content；
    • Completion Capability；
    • Progress 增加 Message；
    • JSON-RPC Batching。

    Batch 在下一版就被移除，因此不要看到旧示例后加入 Batch 支持。

    6. 2025-06-18¶

    主要变化：

    • 移除 JSON-RPC Batching；
    • Tool 支持 structuredContent 和 outputSchema；
    • Tool Result 支持 Resource Link；
    • 增加 Elicitation；
    • MCP Server 明确为 OAuth Resource Server；
    • Protected Resource Metadata Discovery；
    • 强制 RFC 8707 Resource Indicators；
    • HTTP 后续请求带 MCP-Protocol-Version；
    • 增加面向 UI 的 title；
    • Completion 增加上下文参数。

    7. 2025-11-25¶

    主要变化：

    • OIDC Discovery；
    • 增量 Scope Consent；
    • Client ID Metadata Documents；
    • URL Mode Elicitation；
    • Sampling 支持 Tools 和 Tool Choice；
    • 实验性 Tasks；
    • Tool/Resource/Prompt Icons；
    • Tool Name 指导；
    • Elicitation Enum 改进；
    • JSON Schema 2020-12 成为默认；
    • Streamable HTTP SSE Polling/Resume 细化；
    • stdio stderr 可用于所有日志级别。

    它是最后一个以初始化 Session 为核心的正式版本。

    8. 2026-07-28：Modern 时代¶

    这是最重要的一次改版。

    8.1 协议无状态¶

    移除：

    • initialize；
    • notifications/initialized；
    • Mcp-Session-Id；
    • 连接级版本和能力状态。

    增加每请求 _meta：

    {
  "io.modelcontextprotocol/protocolVersion": "2026-07-28",
  "io.modelcontextprotocol/clientCapabilities": {},
  "io.modelcontextprotocol/clientInfo": {
    "name": "client",
    "version": "1.0.0"
  }
}

    8.2 server/discover¶

    所有 Modern Server 必须实现，用于返回：

    • supportedVersions；
    • capabilities；
    • serverInfo；
    • instructions；
    • 缓存提示。

    Client 调用可选，也可直接业务请求后处理版本错误。

    8.3 Result 类型¶

    所有现代成功 Result 必须有：

    {"resultType": "complete"}

    或者：

    {"resultType": "input_required"}

    8.4 MRTR¶

    Server 不再发送独立 JSON-RPC Request。需要 Elicitation/Sampling/Roots 时返回 InputRequiredResult，Client 用新 ID 重试原请求。

    8.5 Subscription¶

    移除：

    • HTTP GET 通知流；
    • resources/subscribe / resources/unsubscribe。

    改为长 POST Response：

    subscriptions/listen

    8.6 Streamable HTTP 改版¶

    移除：

    • Session ID；
    • GET/DELETE Session；
    • SSE Resume 与 Last-Event-ID；
    • SSE 上的独立 Server Request。

    增加：

    • Mcp-Method；
    • Mcp-Name；
    • x-mcp-header → Mcp-Param-*；
    • Header/Body 一致性错误 -32020。

    8.7 缓存¶

    以下结果增加必需的 ttlMs 和 cacheScope：

    • Discover；
    • Tool/Resource/Prompt List；
    • Resource Read；
    • Resource Template List。

    8.8 Tasks¶

    从 Core 移出，成为 io.modelcontextprotocol/tasks 扩展。

    8.9 Deprecated¶

    • Roots；
    • Sampling；
    • Logging；
    • Dynamic Client Registration；
    • HTTP+SSE；
    • Sampling 的 includeContext: thisServer/allServers。

    9. Modern 错误协商¶

    请求不支持版本：

    {
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32022,
    "message": "Unsupported protocol version",
    "data": {
      "requested": "2026-07-28",
      "supported": ["2025-11-25"]
    }
  }
}

    Client：

    1. 计算双方支持版本交集；
    2. 选择适当版本；
    3. 用新请求重试；
    4. 无交集则明确报错。

    不能“把未知版本当最新版试着解析”，因为日期更晚不代表向后兼容。

    10. Modern / Legacy 探测¶

    stdio¶

    带现代 _meta 的 server/discover
├─ DiscoverResult                    → Modern
├─ UnsupportedProtocolVersion        → Modern，重选版本
└─ 其他错误或合理超时                  → Legacy，initialize

    HTTP¶

    Modern POST
├─ 成功/现代错误 Body                 → Modern
├─ 400 且非现代错误                  → Legacy initialize
└─ 仍需兼容 2024 时再尝试旧 GET SSE

    Era 判定可以缓存：

    • stdio：Server 进程生命周期；
    • HTTP：Server Origin；
    • 假设失败时重新探测。

    11. 兼容矩阵¶

    Client Server 结果与处理
    Modern Modern 正常，每请求版本
    Modern Legacy 不兼容；可通过 Discover 提前失败
    Dual-era Modern 使用 Modern
    Dual-era Legacy 探测后回退 initialize
    Legacy Modern 不兼容，Legacy 没有向前机制
    Legacy Dual-era Server 进入 Legacy 模式
    Legacy Legacy 按旧版运行

    Dual-era Server 根据首个交互选择语义：

    • 现代 _meta Request → Modern；
    • initialize → Legacy。

    同一实现可以支持两个时代，但必须保持语义隔离，不能在一个请求中混用。

    12. 从 2025-11-25 迁移到 2026-07-28¶

    Server¶

    • 实现 server/discover
    • 不再依赖 initialize 保存状态
    • 每个 Handler 从本次 Request 获取能力和身份
    • 所有结果增加 resultType
    • List/Read 结果增加 ttlMs、cacheScope
    • Server→Client Request 改为 MRTR
    • Resource Subscribe 改为 subscriptions/listen
    • 跨请求状态改为显式 Handle
    • HTTP 移除 Session ID、GET、DELETE、Resume
    • 校验 Mcp-* Headers
    • Tasks 迁移到扩展

    Client¶

    • 每个 Request 附加版本和 Capabilities
    • 可选调用 server/discover
    • 处理 -32020/-32021/-32022
    • 处理 resultType
    • 实现 MRTR 新 ID Retry
    • 使用 Listen Stream 接收通知
    • 取消 HTTP 时关闭对应 SSE Stream
    • 支持 TTL/Cache Scope
    • 如需兼容旧 Server，实现 Era 探测和初始化回退

    基础设施¶

    • 反向代理只需要 Modern POST Endpoint
    • 移除对 Session Sticky Routing 的协议依赖
    • 关闭 SSE Response Buffering
    • 网关理解 Mcp-Method、Mcp-Name、Mcp-Param-*
    • 监控按 Request/Trace，不按 Session

    13. Deprecated 生命周期¶

    Deprecated 不等于立即删除：

    • 功能仍在当前规范中；
    • 新实现不应采用；
    • 规范给出迁移路径；
    • 通常至少保留 12 个月，特殊快速流程至少 90 天；
    • 到期只代表“可以删除”，实际删除由未来版本决定。

    当前迁移：

    Deprecated 建议替代
    Roots Tool 参数、Resource URI、Server 配置
    Sampling Server 直接调用 LLM Provider
    Logging stdio stderr、OpenTelemetry
    Dynamic Client Registration Client ID Metadata Documents
    HTTP+SSE Streamable HTTP
    includeContext 特殊值 省略或 none

    14. Extensions 与 Core¶

    扩展通过 Capabilities 的 extensions Map 协商：

    {
  "extensions": {
    "io.modelcontextprotocol/tasks": {},
    "io.modelcontextprotocol/ui": {
      "mimeTypes": ["text/html;profile=mcp-app"]
    }
  }
}
    • Extension ID 必须有命名空间；
    • Core 协议版本与 Extension 版本是不同维度；
    • 不支持扩展时必须回退 Core 或明确拒绝；
    • 不要把 Draft Extension 当 Core 必需能力。

    15. 文档和代码中的版本纪律¶

    推荐每篇文档开头注明：

    适用协议：2026-07-28
兼容说明：包含 2025-11-25 Legacy 对比
核对日期：2026-10-28

    代码：

    • 不写没有来源的 SUPPORTED_VERSIONS；
    • 从 SDK/配置定义支持列表；
    • Wire Test 覆盖每个支持版本；
    • 不根据 Server 软件版本猜协议版本；
    • 错误日志同时记录 Era、Protocol Version、SDK Version。

    16. 面试速记¶

    为什么版本是日期？¶

    表示最后一次 Breaking Change 日期，兼容修订不升级版本。

    当前版本最大变化？¶

    2026-07-28 把 MCP 从初始化 Session 协议改为每请求携带版本和能力的无状态协议，并加入 Discover、MRTR、Listen Subscription 和 Cache Hints。

    Modern 如何协商版本？¶

    每个 Request 在 _meta 声明版本；Server 不支持时返回 -32022 和支持列表；Client 选交集后重试。

    如何兼容 Legacy？¶

    Dual-era Client 先探测 server/discover，Modern Error 不回退，其他错误/超时再 initialize。
