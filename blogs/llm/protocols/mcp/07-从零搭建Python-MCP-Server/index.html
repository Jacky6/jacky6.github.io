    从零搭建 Python MCP Server¶

    本章使用官方 Python MCP SDK 2.0+ 构建一个可运行的本地 stdio Server，并解释 SDK 隐藏的协议工作。SDK API 可能随小版本演进，升级依赖时应同时查看官方 SDK Release Notes。

    1. 目标¶

    我们实现一个文档 Server：

    • Tool：search_documents；
    • Tool：get_document；
    • Resource：docs://catalog；
    • Prompt：summarize_document；
    • stdio 启动；
    • 使用 Inspector 验证 Modern 和 Legacy 兼容性。
    graph LR
    H[MCP Host / Inspector] -->|stdio| S[Document MCP Server]
    S --> D[内存文档库]

    2. 创建项目¶

    建议结构：

    mcp-document-server/
├── pyproject.toml
├── server.py
└── README.md

    使用 uv：

    uv init mcp-document-server
cd mcp-document-server
uv add "mcp[cli]>=2.0.0"

    最低要求以当前 Python SDK v2 文档为准：

    • Python 3.11+；
    • Python MCP SDK 2.0+；
    • 测试现代协议时使用支持 2026-07-28 的 Inspector/SDK。

    3. 完整 Server¶

    创建 server.py：

    from __future__ import annotations

import logging
from dataclasses import dataclass

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError
from pydantic import BaseModel


logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
logger = logging.getLogger("document-server")

mcp = MCPServer("document-server", version="1.0.0")


@dataclass(frozen=True)
class Document:
    doc_id: str
    title: str
    content: str


class SearchMatch(BaseModel):
    doc_id: str
    title: str


class SearchResult(BaseModel):
    matches: list[SearchMatch]


class DocumentResult(BaseModel):
    doc_id: str
    title: str
    content: str


DOCUMENTS = {
    "mcp-architecture": Document(
        doc_id="mcp-architecture",
        title="MCP Architecture",
        content=(
            "MCP uses a host-client-server architecture. "
            "The 2026-07-28 protocol is stateless."
        ),
    ),
    "mcp-transports": Document(
        doc_id="mcp-transports",
        title="MCP Transports",
        content=(
            "MCP defines stdio and Streamable HTTP transports. "
            "stdio uses one JSON-RPC message per line."
        ),
    ),
}


@mcp.tool()
def search_documents(query: str, limit: int = 5) -> SearchResult:
    """Search documents by title and content.

    Use this tool to find relevant document IDs before calling get_document.
    The search is case-insensitive. `limit` must be between 1 and 20.

    Args:
        query: Non-empty search text.
        limit: Maximum number of matches, from 1 to 20.
    """
    normalized = query.strip().lower()
    if not normalized:
        raise ToolError("query must not be empty")
    if not 1 <= limit <= 20:
        raise ToolError("limit must be between 1 and 20")

    matches = [
        SearchMatch(doc_id=doc.doc_id, title=doc.title)
        for doc in DOCUMENTS.values()
        if normalized in doc.title.lower() or normalized in doc.content.lower()
    ][:limit]

    logger.info("search_documents query=%r matches=%d", query, len(matches))
    return SearchResult(matches=matches)


@mcp.tool()
def get_document(doc_id: str) -> DocumentResult:
    """Read a document by the exact ID returned from search_documents.

    Args:
        doc_id: Exact document ID. Do not guess IDs.
    """
    document = DOCUMENTS.get(doc_id)
    if document is None:
        raise ToolError(
            f"unknown doc_id: {doc_id}; call search_documents to find a valid ID"
        )

    logger.info("get_document doc_id=%s", doc_id)
    return DocumentResult(
        doc_id=document.doc_id,
        title=document.title,
        content=document.content,
    )


@mcp.resource("docs://catalog")
def document_catalog() -> list[dict[str, str]]:
    """List the document catalog as JSON."""
    return [
        {"doc_id": doc.doc_id, "title": doc.title}
        for doc in DOCUMENTS.values()
    ]


@mcp.prompt()
def summarize_document(doc_id: str) -> str:
    """Create a prompt that asks the model to summarize a document."""
    return (
        f"请先调用 get_document 读取文档 {doc_id}，"
        "然后总结核心观点、适用场景和三个注意事项。"
    )


if __name__ == "__main__":
    mcp.run(transport="stdio")

    Python SDK v2 的高层类是 MCPServer，并正式提供 @mcp.tool()、@mcp.resource() 和 @mcp.prompt()。旧版 from mcp.server.fastmcp import FastMCP 属于 SDK v1，不能与本章代码混用。

    4. SDK 自动完成了什么¶

    上述代码看不到 JSON-RPC，但 SDK 会处理：

    • server/discover；
    • 请求 _meta 和协议版本；
    • Server Capability 声明；
    • tools/list / tools/call；
    • resources/list / resources/read；
    • prompts/list / prompts/get；
    • 参数 Schema 生成和校验；
    • resultType；
    • stdio 一行一消息的分帧；
    • Request ID 匹配；
    • Modern/Legacy 协议协商（取决于 SDK/Transport 支持）。

    业务代码仍负责：

    • 权限与租户隔离；
    • 业务参数校验；
    • 幂等性；
    • 限流、超时和资源释放；
    • 日志脱敏；
    • Tool 描述质量；
    • Tool Result 中不泄露秘密。

    5. 类型提示如何变成 Tool Schema¶

    例如：

    def search_documents(query: str, limit: int = 5) -> SearchResult:
    ...

    SDK 可根据签名和 Docstring 生成类似：

    {
  "name": "search_documents",
  "description": "Search documents by title and content...",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {"type": "string"},
      "limit": {"type": "integer", "default": 5}
    },
    "required": ["query"]
  }
}

    生产项目建议使用 Annotated + Pydantic Field 表达长度、范围和枚举，不能只依靠 Docstring。

    6. 结构化输出¶

    Python SDK v2 会根据返回类型生成 outputSchema。示例中的 SearchResult 与 DocumentResult 是 Pydantic Model，因此：

    • tools/list 会包含对应 outputSchema；
    • 返回值会被校验；
    • CallToolResult.content 包含供模型阅读的 JSON TextContent；
    • CallToolResult.structured_content 包含供应用代码使用的 JSON 对象。

    Client 应分别处理两个通道：

    result = await client.call_tool("search_documents", {"query": "MCP"})
print(result.content)             # 给模型或 UI 的 Content Blocks
print(result.structured_content) # 符合 outputSchema 的应用数据

    不要把 content 当作唯一返回值，也不要跳过对不可信 Server 返回的 structured_content 校验。

    7. 错误设计¶

    7.1 可恢复执行错误¶

    空 Query、未知文档、上游 API 失败属于 Tool Execution Error。高层 SDK 中应抛出 ToolError，它会转换成 is_error=True，并把安全、可行动的错误消息放入 content。其他未预期异常也会成为 Tool Error Result，但具体异常文本会被隐藏，只写入服务端日志。

    Client 端必须检查 result.is_error。错误文本应告诉模型下一步：

    unknown doc_id: x; call search_documents to find a valid ID

    不要只返回：

    Something went wrong

    7.2 协议错误¶

    以下由 SDK/协议层处理：

    • Tool 名不存在；
    • Request Schema 错误；
    • 不支持的方法；
    • 缺少现代 _meta；
    • 版本不支持。

    业务异常不要随意映射成 -32603，否则模型无法自我修正。

    8. stdio 日志纪律¶

    绝对不要向 stdout 写普通文本。

    错误：

    print("server started")

    正确：

    logger.info("server started")

    Python logging 默认写 stderr。Host 可以捕获 stderr，但不应因为存在 stderr 就判定协议失败。

    还应避免：

    • 导入库在 stdout 打 Banner；
    • uvicorn/框架日志错误配置到 stdout；
    • 未捕获 Traceback 污染 stdout；
    • 在 Tool 中直接 print(result)。

    9. 直接运行¶

    stdio Server 启动后等待 Client 从 stdin 发消息，手工运行时“没有输出”通常是正常状态：

    uv run server.py

    不要手敲 JSON 测试复杂流程，优先使用 Inspector。

    10. 用 Inspector 测试¶

    当前 Inspector 需要 Node 22.19+。

    10.1 Web UI¶

    npx @modelcontextprotocol/inspector uv --directory /ABSOLUTE/PATH/mcp-document-server run server.py

    检查：

    1. Server 能否启动；
    2. server/discover 的能力；
    3. Tool 列表和生成的 Schema；
    4. 正常调用；
    5. 空 Query、非法 Limit、未知 ID；
    6. Resource 和 Prompt；
    7. stderr 日志；
    8. Protocol 面板中的请求与响应。

    10.2 Modern CLI¶

    npx @modelcontextprotocol/inspector --cli \
  uv --directory /ABSOLUTE/PATH/mcp-document-server run server.py \
  --protocol-era modern \
  --method tools/list

    调用 Tool：

    npx @modelcontextprotocol/inspector --cli \
  uv --directory /ABSOLUTE/PATH/mcp-document-server run server.py \
  --protocol-era modern \
  --method tools/call \
  --tool-name search_documents \
  --tool-arg query=MCP \
  --tool-arg limit=5

    Inspector 默认 Era 可能是 legacy。必须显式运行一次 modern，否则“测试通过”只证明旧初始化流程可用。

    10.3 兼容性测试¶

    如果目标 Host 仍使用旧版：

    # 现代协议
... --protocol-era modern --method tools/list

# 旧初始化协议
... --protocol-era legacy --method tools/list

    两者都通过才说明 Server/SDK 是 Dual-era。

    11. 配置 Host¶

    不同 Host 的配置文件名不同，但 stdio 配置通常包含：

    {
  "mcpServers": {
    "documents": {
      "command": "uv",
      "args": [
        "--directory",
        "/ABSOLUTE/PATH/mcp-document-server",
        "run",
        "server.py"
      ],
      "env": {
        "LOG_LEVEL": "INFO"
      }
    }
  }
}

    使用绝对路径，因为 GUI Host 的工作目录通常不可预测。command 找不到时也应改为 uv 可执行文件绝对路径。

    不要在会提交到 Git 的配置中放 Token。优先使用 Host Secret Store；退而求其次使用仅当前 Server 可见的环境变量。

    12. 改成 Streamable HTTP¶

    SDK 提供相应 Transport 时，可切换为：

    if __name__ == "__main__":
    mcp.run(transport="streamable-http")

    但这不等于生产就绪。远程部署还必须补齐：

    • OAuth 2.1；
    • Origin 校验；
    • TLS；
    • MCP-Protocol-Version、Mcp-Method、Mcp-Name 校验；
    • SSE 代理配置；
    • 请求大小限制；
    • 租户隔离、限流和审计；
    • 横向扩容时不依赖进程内隐式 Session。

    监听地址、端口和 ASGI 集成方式以所安装 SDK 版本为准。

    13. 生产化重构¶

    建议分层：

    server.py              # MCP 注册与 transport
application/
  document_service.py  # 业务用例
adapters/
  repository.py        # 数据源
security/
  authorization.py     # 身份、scope、资源所有权
observability/
  telemetry.py         # metrics / traces / logs

    Tool Handler 应薄：

    协议参数 → 校验 → 调用 Application Service → 转换 Tool Result

    不要把数据库事务、OAuth Token、复杂重试和业务状态都堆在装饰器函数中。

    14. Server 测试清单¶

    协议¶

    • Modern server/discover 可用
    • 每种 Capability 与实际实现一致
    • Tool/Resource/Prompt Schema 合法
    • resultType 和缓存字段由 SDK 正确输出
    • 目标 Host 所需 Legacy 兼容通过

    功能¶

    • 正常参数
    • 缺少参数、错误类型、边界值
    • 上游超时、限流、5xx
    • Tool 执行错误可恢复
    • 重复写操作具有幂等性

    安全¶

    • Tool 输入和 Resource URI 校验
    • 每请求鉴权与租户隔离
    • 日志不含 Token/PII
    • stdout 只有协议消息
    • 本地 Server 权限最小化
    • 远程 Server 有 OAuth、Origin 和 TLS
