    A2A 协议教程（基础）¶

    类型：protocol | 协议版本：A2A 1.0 | SDK：a2a-sdk 1.3.0 | 最后核对：2026-10-30 本文已按官方 SDK 实测重写：所有数据模型在 a2a-sdk 1.3.0 上验证通过。

    1. 为什么需要 A2A¶

    A2A（Agent-to-Agent）是 Google 开源并捐赠给 Linux Foundation 的开放标准，解决独立 Agent 服务之间的互操作：

    • 不同框架、不同厂商构建的 Agent 相互发现；
    • 跨组织、跨网络的任务委托与协作；
    • 长任务的多轮协商、流式更新、结果交付。

    Agents Are Not Tools¶

    A2A 的核心理念：Agent ≠ Tool。

    维度 Tool Agent
    本质 原语（函数） 自治系统
    状态 通常无状态 有状态（维护上下文）
    交互 一次调用返回 多轮对话、协商、反问
    能力 执行特定函数 推理、规划、使用多个工具

    与本地多 Agent 的边界¶

    ⚠️ 常见误区：把"多 Agent"直接等同于 A2A。正确边界（详见 agent/concepts/05）：

    场景 方案
    同一进程内的子 Agent（框架子图、handoff） 框架原生机制
    跨组织、远程、独立身份、长任务的 Agent 互操作 A2A

    2. 核心数据模型（a2a-sdk 实测）¶

    SDK 的类型在 a2a.types（protobuf 生成）。以下字段清单全部实测验证：

    2.1 Message¶

    from a2a.types import Message, Part, Role

msg = Message(
    message_id="msg-001",          # 必填
    role=Role.ROLE_USER,           # 枚举：ROLE_USER / ROLE_AGENT
    parts=[Part(text="你好")],      # 内容块列表
    context_id="ctx-001",          # 会话上下文
    task_id="task-001",            # 关联任务（可选）
)
    字段 说明
    message_id 必填，唯一标识
    role Role.ROLE_USER / Role.ROLE_AGENT（枚举，不是小写字符串）
    parts 内容块列表
    context_id 会话上下文（多轮关联）
    task_id 关联的任务
    metadata / extensions 扩展数据

    2.2 Part（内容块）¶

    Part 是 oneof 结构（不是 {"kind": "text"} 这种旧写法）：

    Part(text="纯文本")           # 文本
Part(data={"key": "value"})   # 结构化数据
Part(url="https://...")       # URL 引用
Part(raw=b"...")              # 二进制（配 filename/media_type）
    字段 说明
    text / data / url / raw oneof：一个 Part 只设一种
    metadata 附加元数据
    filename / media_type 配合 raw 使用

    2.3 AgentCard（发现）¶

    from a2a.types import AgentCard, AgentInterface

card = AgentCard(
    name="my-agent",
    version="1.0.0",
    supported_interfaces=[        # 必填：接口列表（不是顶层 url！）
        AgentInterface(
            url="https://agent.example.com/a2a",
            protocol_binding="jsonrpc",   # 协议绑定
        )
    ],
    skills=[...],                 # AgentSkill 列表
)
    字段 说明
    name / description / version 基本信息
    supported_interfaces 接口列表（AgentInterface：url、protocol_binding、tenant、protocol_version）
    capabilities 能力声明（流式、推送等）
    skills AgentSkill 列表（id、name、description、tags）
    security_schemes / security_requirements 认证方案
    default_input_modes / default_output_modes 内容类型

    ⚠️ 旧版 Agent Card 的顶层 url 字段已废弃，改为 supported_interfaces 列表。

    2.4 Task 与 TaskState¶

    from a2a.types import Task, TaskStatus, TaskState

task = Task(
    id="task-001",
    context_id="ctx-001",
    status=TaskStatus(state=TaskState.Value("TASK_STATE_WORKING")),
)

    TaskState 枚举（proto 风格，带 TASK_STATE_ 前缀）：

    状态 含义
    TASK_STATE_UNSPECIFIED 未指定
    TASK_STATE_SUBMITTED 已提交
    TASK_STATE_WORKING 执行中
    TASK_STATE_INPUT_REQUIRED 需要补充输入
    TASK_STATE_COMPLETED 完成
    TASK_STATE_FAILED 失败
    TASK_STATE_CANCELED 已取消
    TASK_STATE_REJECTED 被拒绝
    TASK_STATE_AUTH_REQUIRED 需要认证

    Task 字段：id、context_id、status（含 state/message/timestamp）、artifacts、history、metadata。

    2.5 Artifact（交付物）¶

    Task 的产出：id、parts（Part 列表）、metadata 等字段。

    3. 请求生命周期¶

    Client                          Server（远程 Agent）
  │                                │
  │── 1. 发现：获取 AgentCard ────▶│
  │◀── AgentCard（skills/接口）────│
  │                                │
  │── 2. SendMessageRequest ─────▶│
  │   （Message: id+role+parts）   │
  │◀── Task（SUBMITTED/WORKING）──│
  │                                │
  │◀── 3. 流式更新（可选）────────│
  │   （status_update/artifact）   │
  │                                │
  │◀── 4. 最终 Task（COMPLETED）──│
  │   （artifacts 含结果）          │

    关键点：

    1. 消息必带 message_id——旧版可省略，1.0 必填；
    2. Task 是一等公民——委托的工作以 Task 跟踪，不是一次 RPC；
    3. context_id 关联多轮——同一上下文的消息共享 context；
    4. 流式可选——SubscribeToTaskRequest 订阅更新，或轮询 GetTaskRequest。

    4. Client 用法（a2a-sdk 实测）¶

    import asyncio
from a2a.client import create_client
from a2a.types import Message, Part, Role
from a2a.types.a2a_pb2 import SendMessageRequest

async def main():
    # create_client：传 URL 或 AgentCard，自动发现
    client = await create_client("https://agent.example.com")

    # 构造请求（注意：字段是 message，不是 params）
    request = SendMessageRequest(
        message=Message(
            message_id="msg-001",
            role=Role.ROLE_USER,
            parts=[Part(text="帮我分析这份报告")],
        )
    )

    # send_message 返回流式响应
    async for response in client.send_message(request):
        if response.HasField("task"):
            task = response.task
            print(f"Task: {task.id}, state={task.status.state}")
        if response.HasField("message"):
            print(f"回复: {response.message.parts[0].text}")

asyncio.run(main())

    StreamResponse 是 oneof：task / message / status_update / artifact_update。

    5. A2A vs MCP — 互补协议¶

    维度 MCP A2A
    连接对象 Host ↔ 工具/数据 Server Agent ↔ Agent
    解决问题 能力接入（工具、资源） 任务协作（委托、协商）
    交互模型 请求-响应（MRTR 多轮） Task 生命周期 + 多轮消息
    状态 Modern 无 Session Task/Context 显式状态

    组合使用：一个远程 Agent 通过 A2A 接收任务，内部通过 MCP 使用工具。

    MCP 事实源：../mcp/

    6. 关键设计原则速记¶

    1. Agent ≠ Tool：A2A 连接的是自治系统，不是函数。
    2. Task 是核心：委托的工作有完整生命周期（提交→执行→完成/失败）。
    3. 消息必带 message_id；role 用 ROLE_USER/ROLE_AGENT 枚举。
    4. AgentCard 用 supported_interfaces，不是顶层 url。
    5. Part 是 oneof（text/data/url/raw），没有 kind 字段。
    6. 本地多 Agent 不需要 A2A——跨服务互操作才需要。
