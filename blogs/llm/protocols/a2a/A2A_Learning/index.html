    A2A (Agent2Agent) Protocol 学习教程¶

    A2A 是一个开放标准协议，用于实现不同 AI Agent 之间的无缝通信与协作。 由 Google 开发并捐赠给 Linux Foundation，旨在解决异构 Agent 系统的互操作性问题。

    1. A2A 是什么？¶

    Agent2Agent (A2A) Protocol 是一个开放标准，旨在实现独立、可能完全不透明的 AI Agent 系统之间的通信与协作。

    关键特性¶

    • 互操作性：弥合不同 Agent 框架（LangGraph、CrewAI、Semantic Kernel 等）之间的鸿沟
    • 协作能力：支持 Agent 间任务委派、上下文交换和复杂问题协同解决
    • 动态发现：Agent 可以动态发现和理解其他 Agent 的能力
    • 灵活性：支持同步请求/响应、流式实时更新、异步推送通知
    • 安全性：基于标准 Web 安全实践的企业级安全模式
    • 异步优先：原生支持长时间运行任务和人在回路场景

    设计原则¶

    原则 说明
    Simple 复用现有标准（HTTP、JSON-RPC 2.0、SSE）
    Enterprise Ready 对齐企业认证、授权、安全、隐私、追踪和监控实践
    Async First 为长时间任务和人在回路交互设计
    Modality Agnostic 支持文本、音视频、结构化数据、甚至嵌入 UI
    Opaque Execution Agent 基于声明的能力协作，无需共享内部逻辑

    2. 为什么需要 A2A？¶

    当前 Agent 生态的问题¶

    在没有 A2A 之前，Agent 间的协作面临以下挑战：

    ┌─────────────┐         ┌─────────────┐
│  Agent A    │         │  Agent B    │
│ (LangGraph) │         │  (CrewAI)   │
│             │         │             │

│  │Tool 1 │  │         │  │Tool 3 │  │
│  │Tool 2 │  │         │  │Tool 4 │  │
│  └───────┘  │         │  └───────┘  │
└─────────────┘         └─────────────┘
      ║                        ║

      ║  需要定制集成代码       ║
      ║  框架锁定严重           ║

    A2A 解决的问题¶

    3. A2A vs MCP：互补而非竞争¶

    这是理解 A2A 定位的关键点。

    通信对象的差异¶

                        ┌─────────────────────┐
                    │   完整 Agent 应用     │
                    │                     │
                    │  ┌───────────────┐  │
                    │  │   Agent A     │  │
                    │  │               │  │
  ┌───────────┐     │  │  ┌─────────┐  │  │     ┌───────────┐
  │  Agent B  │◄────┼──┤  │  MCP    │  ├──┼────►│  Tool X   │
  │ (远程Agent)│  A2A│  │  │ (工具)   │  │  │     │ (数据库)   │
  └───────────┘     │  │  └─────────┘  │  │     └───────────┘
                    │  │               │  │
                    │  │  ┌─────────┐  │  │     ┌───────────┐
                    │  │  │  MCP    │  │  │     │  Tool Y   │
                    │  │  │ (工具)   │  ├──┼────►│ (API服务)  │
                    │  │  └─────────┘  │  │     └───────────┘
                    │  └───────────────┘  │
                    └─────────────────────┘

    详细对比¶

    维度 MCP A2A
    通信对象 Agent ↔ Tool Agent ↔ Agent
    交互性质 工具调用（函数执行） 任务协作（多轮对话）
    透明度 Tool 的 Schema 对 Agent 可见 Agent 内部逻辑不共享（Opaque）
    状态管理 通常无状态 有状态（Task 生命周期）
    典型场景 查询数据库、调用 API、读取文件 旅行规划、客服转接、多 Agent 协同研究
    协议层 工具描述与调用标准化 发现、协商、任务管理、数据交换

    协同工作示例：汽车修理店¶

    用户 ──(A2A)──► 店经理 Agent
                    │
                    ├──(A2A)──► 技师 Agent ──(MCP)──► 车辆诊断扫描器
                    │               │
                    │               └──(MCP)──► 维修手册数据库
                    │               │
                    │               └──(A2A)──► 零件供应商 Agent
                    │
                    └──(A2A)──► 客服 Agent

    总结：MCP 解决 Agent 如何用工具，A2A 解决 Agent 如何与其他 Agent 协作。两者缺一不可。

    4. 核心概念¶

    4.1 Agent Card（Agent 名片）¶

    Agent Card 是一个 JSON 文档，描述了 Agent 的身份、能力和端点信息。

    {
  "name": "TravelPlanner",
  "description": "综合旅行规划 Agent",
  "url": "https://travel-agent.example.com/a2a",
  "version": "1.0.0",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true,
    "stateTransitionHistory": true
  },
  "securitySchemes": {
    "bearerAuth": {
      "type": "http",
      "scheme": "bearer",
      "bearerFormat": "JWT"
    }
  },
  "skills": [
    {
      "id": "plan_trip",
      "name": "行程规划",
      "description": "根据偏好和预算规划完整行程",
      "tags": ["travel", "planning"],
      "examples": ["帮我规划一个东京5日游"]
    },
    {
      "id": "book_flight",
      "name": "机票预订",
      "description": "搜索并预订机票"
    }
  ]
}

    4.2 Task（任务）¶

    Task 是 A2A 中的基本工作单元，具有唯一 ID 和完整的生命周期。

    {
  "id": "task_001",
  "contextId": "ctx_trip_planning",
  "status": {
    "state": "completed",
    "message": "行程规划完成"
  },
  "artifacts": [
    {
      "name": "itinerary",
      "description": "东京5日行程",
      "parts": [
        {
          "kind": "text",
          "text": "Day 1: 抵达东京，入住酒店..."
        }
      ]
    }
  ],
  "history": [
    {"role": "user", "parts": [{"kind": "text", "text": "帮我规划东京5日游"}]},
    {"role": "agent", "parts": [{"kind": "text", "text": "好的，请告诉我您的预算和偏好..."}]}
  ]
}

    4.3 Message（消息）¶

    消息是 Agent 间单次通信的载体。

    {
  "role": "user",
  "parts": [
    {"kind": "text", "text": "帮我查一下明天北京到上海的机票"},
    {
      "kind": "data",
      "data": {
        "departure": "PEK",
        "arrival": "SHA",
        "date": "2026-06-04"
      }
    }
  ]
}

    4.4 Part（内容单元）¶

    Part 是 Message 或 Artifact 中的最小内容单元，支持多种类型：

    类型 说明 示例
    text 纯文本 "你好，请帮我..."
    file 文件引用 图片、PDF、音频
    data 结构化数据 JSON 对象

    5. 三层架构设计¶

    A2A 采用清晰的三层架构：

    ┌─────────────────────────────────────────────────┐
│  Layer 1: A2A Data Model（数据模型）               │
│  ┌─────────────────────────────────────────────┐ │
│  │ Task | Message | AgentCard | Part | Artifact │ │
│  └─────────────────────────────────────────────┘ │
│  定义所有实现必须理解的核心数据结构（Protocol Buffers）  │
├─────────────────────────────────────────────────┤
│  Layer 2: A2A Operations（抽象操作）                │
│  ┌─────────────────────────────────────────────┐ │
│  │ SendMessage | SendStreamingMessage | GetTask │ │
│  │ ListTasks | CancelTask | GetAgentCard       │ │
│  └─────────────────────────────────────────────┘ │
│  定义 Agent 必须支持的基本能力（与具体协议无关）        │
├─────────────────────────────────────────────────┤
│  Layer 3: Protocol Bindings（协议绑定）              │
│  ┌─────────────────────────────────────────────┐ │
│  │ JSON-RPC | gRPC | HTTP/REST | Custom        │ │
│  └─────────────────────────────────────────────┘ │
│  将抽象操作映射到具体的传输协议                      │
└─────────────────────────────────────────────────┘

    设计优势¶

    1. 一致性：核心语义在所有协议绑定中保持一致
    2. 可扩展：新增协议绑定无需修改数据模型
    3. 独立性：开发者可以独立于绑定方式理解 A2A 操作
    4. 互操作性：通过共享的数据模型确保互操作

    6. 任务生命周期¶

    6.1 状态机¶

                        ┌──────────┐
                    │submitted │ ◄── 任务已提交
                    └────┬─────┘
                         │
                    ┌────▼─────┐
                    │ working  │ ◄── 处理中
                    └────┬─────┘
                         │
          ┌──────────────┼──────────────┐
          │              │              │
     ┌────▼────┐   ┌────▼────┐   ┌─────▼─────┐
     │completed│   │ failed  │   │ canceled  │
     │  ✅完成  │   │  ❌失败  │   │  ⛔已取消  │
     └─────────┘   └─────────┘   └───────────┘
          ▲
          │
     ┌────┴────┐
     │ rejected│ ◄── 被拒绝（权限不足、无法处理等）
     └─────────┘

    6.2 中断状态（非终态）¶

    某些情况下任务可能进入需要外部介入的状态：

    状态 说明 处理方式
    input_required 需要用户提供额外信息 Agent 返回问题，等待用户回复
    auth_required 需要用户授权（如 OAuth 登录） 返回授权链接，用户完成后继续

    6.3 生命周期示例¶

    用户: "帮我规划一次日本旅行"
  │
  ▼
Client Agent ──SendMessage──► Remote Agent (TravelPlanner)
  │
  ▼
Task 创建: {id: "task_001", status: "submitted"}
  │
  ▼
Remote Agent 开始处理: {status: "working"}
  │
  ├── 流式更新: "正在查询航班信息..."
  ├── 流式更新: "正在查询酒店..."
  ├── Artifact 更新: {name: "初步行程", parts: [...]}
  │
  ▼
任务完成: {status: "completed", artifacts: [{name: "完整行程", ...}]}

    7. Agent 发现机制¶

    7.1 Well-Known URI（标准路径发现）¶

    最推荐的方式，符合 RFC 8615 标准：

    GET https://agent-domain.example.com/.well-known/agent-card.json

Response (200 OK):
{
  "name": "MyAgent",
  "url": "https://agent-domain.example.com/a2a",
  ...
}

    7.2 注册中心发现¶

    在企业环境或公共市场中，可以通过中心化注册表发现 Agent：

    GET https://registry.example.com/api/agents?skill=travel_planning

Response:
[
  {
    "name": "TravelPlanner A",
    "url": "https://agent-a.example.com/a2a",
    "skills": ["plan_trip", "book_flight"]
  },
  {
    "name": "TravelPlanner B", 
    "url": "https://agent-b.example.com/a2a",
    "skills": ["plan_trip", "book_hotel"]
  }
]

    7.3 直接配置¶

    适用于紧密耦合的系统或开发环境：

    # 硬配置方式
AGENT_ENDPOINTS = {
    "travel_planner": "https://travel-agent.example.com/a2a",
    "flight_booker": "https://flight-agent.example.com/a2a"
}

    8. 流式与异步通信¶

    8.1 SSE 流式（适合客户端在线）¶

    POST /sendMessageStream
Content-Type: application/json

{
  "message": {
    "role": "user",
    "parts": [{"kind": "text", "text": "帮我规划旅行"}]
  }
}

Response (SSE Stream):

event: message
data: {"taskId": "task_001", "status": {"state": "working"}}

event: message
data: {"type": "status_update", "status": {"state": "working", "message": "正在查询航班..."}}

event: message
data: {"type": "artifact_update", "artifact": {"name": "itinerary", "parts": [...]}}

event: message
data: {"taskId": "task_001", "status": {"state": "completed"}}

    8.2 推送通知（适合长时间任务）¶

    POST /sendMessage
Content-Type: application/json

{
  "message": {...},
  "pushNotificationConfig": {
    "url": "https://client.example.com/webhook",
    "token": "auth_token_for_webhook"
  }
}

--- 客户端可以断开连接 ---

--- 任务完成后，Server 主动推送 ---

POST https://client.example.com/webhook
Content-Type: application/json

{
  "taskId": "task_001",
  "status": {"state": "completed"},
  "artifact": {...}
}

    8.3 选择指南¶

    场景 推荐方式
    短任务（秒级） 同步 SendMessage
    中长任务（分钟级） SSE 流式
    超长任务（小时/天级） 推送通知
    移动端/Serverless 推送通知
    需要实时反馈 SSE 流式

    代码示例：使用 A2A 发起任务¶

    import httpx
from typing import Optional

class A2AClient:
    """A2A 客户端示例"""

    def __init__(self, agent_url: str, token: Optional[str] = None):
        self.agent_url = agent_url
        self.headers = {}
        if token:
            self.headers["Authorization"] = f"Bearer {token}"

    async def send_message(self, text: str) -> dict:
        """发送同步消息"""
        payload = {
            "message": {
                "role": "user",
                "parts": [{"kind": "text", "text": text}]
            }
        }
        async with httpx.AsyncClient() as client:
            resp = await client.post(
                f"{self.agent_url}/",
                json=payload,
                headers=self.headers
            )
            return resp.json()

    async def send_streaming(self, text: str):
        """发送流式消息，逐步接收结果"""
        payload = {
            "message": {
                "role": "user", 
                "parts": [{"kind": "text", "text": text}]
            }
        }
        async with httpx.AsyncClient() as client:
            async with client.stream(
                "POST",
                f"{self.agent_url}/",
                json=payload,
                headers=self.headers
            ) as resp:
                async for line in resp.aiter_lines():
                    if line.startswith("data: "):
                        yield line[6:]  # 解析 SSE 数据

    async def get_task(self, task_id: str) -> dict:
        """查询任务状态"""
        payload = {"id": task_id}
        async with httpx.AsyncClient() as client:
            resp = await client.post(
                f"{self.agent_url}/",
                json=payload,
                headers=self.headers
            )
            return resp.json()

    async def cancel_task(self, task_id: str) -> dict:
        """取消任务"""
        payload = {"id": task_id}
        async with httpx.AsyncClient() as client:
            resp = await client.post(
                f"{self.agent_url}/cancel",
                json=payload,
                headers=self.headers
            )
            return resp.json()


# 使用示例
async def main():
    # 1. 发现 Agent
    async with httpx.AsyncClient() as client:
        resp = await client.get(
            "https://travel-agent.example.com/.well-known/agent-card.json"
        )
        agent_card = resp.json()
        print(f"发现 Agent: {agent_card['name']}")
        print(f"支持技能: {[s['name'] for s in agent_card['skills']]}")

    # 2. 创建客户端
    a2a = A2AClient(
        agent_url=agent_card["url"],
        token="your_jwt_token"
    )

    # 3. 发送任务
    result = await a2a.send_message("帮我规划一个东京5日游")
    print(f"任务 ID: {result.get('taskId')}")

    # 4. 流式接收（可选）
    async for event in a2a.send_streaming("帮我规划东京5日游"):
        print(f"收到事件: {event}")


if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
