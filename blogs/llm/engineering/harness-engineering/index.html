    Harness Engineering（脚手架工程）¶

    2026 年 AI 工程演进路线：Prompt → Context → Harness → Loop Engineering

    一、什么是 Harness Engineering？¶

    Harness Engineering 是为 AI Agent 搭建运行环境（harness）的工程实践，包括沙箱、文件系统、权限、中间件等基础设施。

    类比理解： 

    Prompt Engineering    = 写指令
Context Engineering   = 准备信息
Harness Engineering   = 搭建工作环境
Loop Engineering      = 设计工作流

    三、核心组件¶

    3.1 沙箱（Sandbox）¶

    隔离 Agent 的执行环境，防止危险操作：

    # Deep Agents 沙箱配置
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="openai:gpt-5.4",
    sandbox={
        "type": "docker",           # 隔离类型
        "timeout": 30,              # 执行超时
        "network": False,           # 禁用网络
        "allowed_commands": [       # 白名单命令
            "python", "pip", "cat", "ls"
        ]
    }
)

    3.2 文件系统（Filesystem）¶

    Agent 的持久化存储：

    # 可插拔文件系统后端
from deepagents.backends import (
    InMemoryBackend,      # 内存（开发用）
    LocalDiskBackend,     # 本地磁盘
    LangGraphStoreBackend # LangGraph 存储
)

agent = create_deep_agent(
    model="openai:gpt-5.4",
    backend=LocalDiskBackend("./workspace")
)

    3.3 权限系统（Permissions）¶

    控制 Agent 的读写权限：

    # 权限规则
permissions = {
    "read": ["./src/**", "./docs/**"],     # 可读目录
    "write": ["./output/**"],              # 可写目录
    "deny": ["./secrets/**", "./.env"]     # 禁止访问
}

agent = create_deep_agent(
    model="openai:gpt-5.4",
    permissions=permissions
)

    3.4 中间件（Middleware）¶

    在 Agent 循环中插入处理逻辑：

    # 内置中间件
from langchain.middleware import (
    write_todos,        # 任务分解
    compress_context,   # 上下文压缩
    summarize_history,  # 历史摘要
)

agent = create_agent(
    model="openai:gpt-5.4",
    tools=tools,
    middleware=[
        write_todos,
        compress_context,
    ]
)

    3.5 检查点（Checkpoint）¶

    持久化 Agent 状态，支持恢复：

    from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model="openai:gpt-5.4",
    tools=tools,
    checkpointer=InMemorySaver()  # 对话持久化
)

# 通过 thread_id 恢复对话
config = {"configurable": {"thread_id": "session-123"}}
result = agent.invoke({"messages": [...]}, config=config)

    四、Harness vs Loop¶

    维度 Harness Engineering Loop Engineering
    关注点 运行环境 控制流程
    核心问题 Agent 在哪里执行？ Agent 怎么循环？
    典型组件 沙箱、文件系统、权限 循环策略、终止条件、重试
    抽象层级 基础设施层 业务逻辑层

    协作关系： 

    Loop Engineering（决策层）
    │
    │ 决定：调用什么工具、什么时候停止
    ▼
Harness Engineering（执行层）
    │
    │ 提供：在哪里执行、怎么执行、权限控制

    六、面试话术¶

    Q: 介绍一下 Harness Engineering？

    Harness Engineering 是为 Agent 搭建运行环境的工程实践。它关注的是 Agent 在哪里执行、怎么执行——沙箱隔离、文件系统、权限控制、中间件、持久化这些都是 harness 的范畴。

    和 Loop Engineering 的关系：Loop 是决策层（Agent 怎么循环），Harness 是执行层（Agent 在哪里执行）。一个好的 Agent 系统需要两者配合——Loop 决定调用什么工具，Harness 确保工具在安全隔离的环境中执行。

    LangChain 生态中，Deep Agents 就是典型的 harness 产品，它提供了开箱即用的沙箱、文件系统、权限、中间件等基础设施。
