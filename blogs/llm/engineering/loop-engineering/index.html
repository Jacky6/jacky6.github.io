    Loop Engineering（循环工程）¶

    2026 年 6 月爆火的新概念——从手动 prompt 转向设计自动循环系统。

    1. 什么是 Loop Engineering？¶

    一句话定义：

    Loop Engineering 是设计一个系统来自动 prompt、检查、记忆、重跑 AI Agent 的工程实践——而不是你手动输入每一条指令。

    核心思想： 不再手动 prompt Agent，而是设计循环（loop），让循环自动驱动 Agent 完成任务。

    谁提出来的： - Peter Steinberger（OpenClaw 创始人）：

    "You should be designing loops that prompt your agents." - Boris Cherny（Anthropic Claude Code 负责人）： "I don't prompt Claude anymore. I write loops that prompt Claude."

    2. 演进路线¶

    Prompt Engineering → Context Engineering → Harness Engineering → Loop Engineering
   (写好提示词)        (管好上下文)          (搭好运行环境)        (设计自动循环)

2023               2024-2025            2025-2026            2026.06+
    阶段 关注点 核心问题
    Prompt Engineering 单次提示词 怎么写好一个 prompt？
    Context Engineering 上下文管理 怎么让 Agent 拿到正确信息？
    Harness Engineering 运行环境 怎么搭建 Agent 的沙箱和工具？
    Loop Engineering 自动循环 怎么设计系统自动驱动 Agent？

    3. Agent Loop 核心循环¶

    ┌─────────────────────────────────────────────────┐
│              Agent Execution Loop                │
├─────────────────────────────────────────────────┤
│                                                 │
│   1. Assemble Context（组装上下文）               │
│          ↓                                      │
│   2. Invoke Model（调用 LLM 推理）               │
│          ↓                                      │
│   3. Act（执行工具/动作）                        │
│          ↓                                      │
│   4. Observe（观察结果）                         │
│          ↓                                      │
│   5. Check Stop Condition（是否完成？）           │
│          ↓                                      │
│      No → 回到 1                                │
│      Yes → 输出结果                             │
│                                                 │
└─────────────────────────────────────────────────┘

    本质： Reason → Act → Observe → Repeat（推理 → 行动 → 观察 → 重复）

    4. 好的 Loop 的 5 个要素¶

    要素 说明 示例
    明确目标 有可测试的终止条件 "测试全过" 而不是 "写好代码"
    工具集 Agent 能用的工具 读文件、写代码、跑测试、搜索
    上下文管理 防止 token 爆炸 压缩、摘要、清理旧结果
    失败出口 防止无限循环 最大迭代、超时、重复检测
    自适应错误处理 不是简单重试，而是换策略 换工具、换方法、问用户

    5. 三种 Loop 类型¶

    5.1 Agent Loop（智能体循环）¶

    ┌──────────────────────────────────────┐
│  Model calls tools repeatedly        │
│  until a task is complete            │
├──────────────────────────────────────┤
│  用途：自动化单次任务                 │
│  示例：写代码 → 跑测试 → 修复 → 重复  │
└──────────────────────────────────────┘

    5.2 Event-Driven Loop（事件驱动循环）¶

    ┌──────────────────────────────────────┐
│  Events trigger agent runs           │
│  that update a real system           │
├──────────────────────────────────────┤
│  用途：自动化持续工作                 │
│  示例：PR 提交 → 自动审查 → 评论      │
│        新 issue → 自动分类 → 分配     │
└──────────────────────────────────────┘

    5.3 Hill Climbing Loop（爬山循环）¶

    ┌──────────────────────────────────────┐
│  Traces from production runs feed    │
│  an analysis agent that improves     │
│  the harness config                  │
├──────────────────────────────────────┤
│  用途：自我优化系统                   │
│  示例：生产 trace → 分析 Agent        │
│        → 改进 harness 配置            │
└──────────────────────────────────────┘

    6. 三个层级（Oracle 定义）¶

    Level 描述 特点 复杂度
    L1 最小循环 LLM + 工具 + 响应 低
    L2 带生命周期 加入记忆，从 stateless 变成有状态推理引擎 中
    L3 完整系统 Loop 内外都有运维，harness 本身成为系统 高 
    L1: LLM → Tool → Response
     ↓
L2: LLM → Tool → Response → Memory → State
     ↓
L3: LLM → Tool → Response → Memory → State → Observability → Ops

    7. Loop Engineering 的工程实践¶

    7.1 循环防御机制（防止 Agent 陷入死循环）¶

    class LoopGuard:
    """Loop 防御机制"""

    def __init__(self, max_iterations=15, timeout_seconds=60):
        self.max_iterations = max_iterations
        self.timeout = timeout_seconds
        self.action_history = deque(maxlen=3)  # 检测重复动作
        self.start_time = None

    def should_stop(self, iteration: int, action: str) -> tuple[bool, str]:
        """检查是否应该停止"""
        # 1. 最大迭代次数
        if iteration >= self.max_iterations:
            return True, "Max iterations reached"

        # 2. 超时
        if time.time() - self.start_time > self.timeout:
            return True, "Timeout exceeded"

        # 3. 重复动作检测
        self.action_history.append(action)
        if len(self.action_history) == 3:
            if len(set(self.action_history)) == 1:
                return True, "Same action repeated 3 times"

        return False, ""

    7.2 上下文管理（防止 Token 爆炸）¶

    class ContextManager:
    """上下文管理"""

    def __init__(self, max_tokens=100000):
        self.max_tokens = max_tokens
        self.messages = []

    def add_message(self, message: dict):
        self.messages.append(message)
        self._compact_if_needed()

    def _compact_if_needed(self):
        """当 token 接近上限时压缩上下文"""
        total_tokens = self._count_tokens()

        if total_tokens > self.max_tokens * 0.8:
            # 策略 1: 清理旧的工具结果
            self._clear_old_tool_results()

            # 策略 2: 摘要早期对话
            if self._count_tokens() > self.max_tokens * 0.9:
                self._summarize_early_messages()

    def _clear_old_tool_results(self):
        """清理 3 轮前的工具调用结果"""
        for msg in self.messages[:-6]:
            if msg.get("role") == "tool":
                msg["content"] = "[Result cleared to save context]"

    7.3 自适应错误处理¶

    class AdaptiveErrorHandler:
    """自适应错误处理"""

    def handle_error(self, error: Exception, context: dict) -> str:
        """根据错误类型选择不同策略"""
        error_type = type(error).__name__

        if error_type == "ToolNotFoundError":
            return "Switch to alternative tool"

        elif error_type == "TimeoutError":
            return "Break task into smaller steps"

        elif error_type == "PermissionError":
            return "Ask user for permission"

        elif "rate_limit" in str(error).lower():
            return "Wait and retry with backoff"

        else:
            return "Analyze error and try different approach"

    Agent Loop（核心循环）
