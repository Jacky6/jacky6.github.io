    3. Skill 调用 Demo¶

    3.1 什么是 Skill?¶

    Skill 不是 函数/插件，也不注册任何工具。

    它是一份"说明书"，通过 SKILL.md 告诉模型： - 某个能力是什么 - 什么时候该用它 - 该用什么工具、怎么用（关键！）

    Skill 的本质：Prompt 工程 + 工具编排指南。

    3.2 核心真相：Skill 不注册工具¶

    这是最重要的概念！ Skill 的工作方式和 Tool 完全不同：

    Tool 方式:
  api.registerTool({name: "get_weather", execute: fn})
  → 注册到 tools 列表
  → 模型直接 tool_call("get_weather")

Skill 方式:
  写入 SKILL.md
  → 注入系统 Prompt 的 <available_skills> XML
  → 模型读取 SKILL.md
  → 按指南调用普通工具 (read, web_fetch, exec...)

    源码真相¶

    OpenClaw 实际注入系统 Prompt 的内容（来自源码 workspace-BoRIIBbL.js）：

    The following skills provide specialized instructions for specific tasks.
Use the read tool to load a skill's file when the task matches its description.
When a skill file references a relative path, resolve it against the skill directory...

<available_skills>
  <skill>
    <name>weather</name>
    <description>Check current weather and forecasts using wttr.in API</description>
    <location>/home/yixiu/.openclaw/workspace/skills/weather/SKILL.md</location>
  </skill>
  <skill>
    <name>stock-analysis</name>
    <description>Analyze stocks using Yahoo Finance data</description>
    <location>/home/yixiu/.openclaw/workspace/skills/stock-analysis/SKILL.md</location>
  </skill>
</available_skills>

    系统 Prompt 里还会加上这段指令（来自 system-prompt-config-BOuyiivW.js）：

    ## Skills
Scan <available_skills>. If one clearly applies, read its SKILL.md at exact <location> with `read`, then follow it.
If several apply, choose the most specific. If none clearly apply, read none.
One skill up front max. Never guess/fabricate skill paths.

    3.3 Skill 目录结构¶

    workspace/skills/weather/
├── SKILL.md              # 核心: 模型阅读的技能描述
└── scripts/              # (可选) 辅助脚本
    └── fetch_weather.sh

    SKILL.md 必须包含¶

    字段 必须 说明
    name ✅ 技能名称，匹配用户意图
    description ✅ 简短描述，决定何时触发
    工具说明 ✅ 明确写出用什么工具、怎么调用
    示例 推荐 给模型看调用范例

    3.4 SKILL.md 完整示例¶

    示例 1: 调用外部 API¶

    ---
name: weather
description: Check current weather and forecasts using wttr.in API
---

# Weather Skill

## When to use
- User asks about weather, temperature, rain forecast
- User plans travel or outdoor activities
- User mentions a city and wants weather info

## Tools needed
- `web_fetch` - to call wttr.in API

## How to use
1. Use the `web_fetch` tool to call wttr.in:
   - Quick format: `web_fetch(url="https://wttr.in/{city}?format=2")`
   - Detailed JSON: `web_fetch(url="https://wttr.in/{city}?format=j1")`
   - 3-day forecast: `web_fetch(url="https://wttr.in/{city}?format=3")`

2. Parse the response and summarize:
   - Temperature
   - Weather condition
   - Humidity/Wind

## Tips
- City names should be in English for best results
- Add `&lang=zh` for Chinese output
- Response is plain text, summarize concisely

    示例 2: 运行本地脚本¶

    ---
name: db-backup
description: Backup PostgreSQL database to local directory
---

# DB Backup Skill

## When to use
- User asks to backup database
- User wants to create a database dump
- Scheduled backup tasks

## Tools needed
- `exec` - to run pg_dump command

## How to use
1. Run backup command:
   ```
   exec(command="pg_dump -U postgres mydb > /backup/mydb_$(date +%Y%m%d).sql")
   ```

2. Verify the file was created:
   ```
   exec(command="ls -lh /backup/mydb_*.sql")
   ```

3. Report success with file size and location

    示例 3: 组合多个工具¶

    ---
name: code-review
description: Review code changes and generate report
---

# Code Review Skill

## When to use
- User asks to review recent changes
- User wants a code quality report
- Before merging a PR

## Tools needed
- `exec` - to run git commands
- `read` - to read source files
- `write` - to save review report

## How to use
1. Get the diff of recent changes:
   ```
   exec(command="git diff HEAD~1")
   ```

2. Read the changed files:
   ```
   read(path="path/to/changed/file.py")
   ```

3. Analyze the code for:
   - Security issues
   - Performance problems
   - Code style violations

4. Write the review report:
   ```
   write(path="review.md", content="...")
   ```

│                                                                 │
│  启动阶段:                                                       │
│  1. 扫描 workspace/skills/*/SKILL.md                             │

    3.6 关键对比: Skill 调用 vs Tool 调用¶

    维度 Tool 调用 Skill "调用"
    注册 api.registerTool() → 进入 tools 列表 不注册工具！只注入系统 Prompt
    模型看到的 {"name": "get_weather", "parameters": {...}} <skill><name>weather</name>...</skill>
    Tool Call 名称 get_weather read (读 SKILL.md) → 其他普通工具
    执行路径 Gateway 直接执行 execute() 模型自己决定用什么工具
    本质 函数 Prompt 指南
    灵活性 低（固定接口） 高（组合多个工具）
    Agent 怎么知道用什么工具？ 不需要知道，Gateway 执行 SKILL.md 必须写清楚！

    3.7 实战: 创建自己的 Skill¶

    步骤 1: 创建目录¶

    mkdir -p ~/.openclaw/workspace/skills/my-weather-skill

    步骤 2: 编写 SKILL.md¶

    cat > ~/.openclaw/workspace/skills/my-weather-skill/SKILL.md << 'EOF'
---
name: my-weather
description: Query weather information for any city worldwide
---

# My Weather Skill

## When to activate
- User asks about weather in any city
- User wants temperature forecast
- User asks about rain/sun/wind conditions

## Tools needed
- `web_fetch` - to call wttr.in API

## How to use
1. Use the `web_fetch` tool with wttr.in API:
   - Quick format: `web_fetch(url="https://wttr.in/{city}?format=2")`
   - Full data: `web_fetch(url="https://wttr.in/{city}?format=j1")`

2. Parse the response and summarize:
   - Temperature
   - Weather condition
   - Humidity/Wind

## Examples
- User: "上海天气？" → web_fetch(url="https://wttr.in/Shanghai?format=j1&lang=zh")
- User: "Will it rain in London?" → web_fetch(url="https://wttr.in/London?format=2")

## Tips
- Chinese users: append `&lang=zh` for Chinese output
- Use `format=2` for quick one-liner
- Use `format=j1` for detailed parsing
EOF

    步骤 3: 重启生效¶

    openclaw gateway restart

    下次对话中，模型就会自动加载这个 Skill 的指南。

    3.8 Token 开销¶

    Skill 注入会占用上下文窗口的 token：

    • 基础开销（有 ≥1 个 skill 时）: 195 字符
    • 每个 skill: 97 字符 + name + description + location 的长度
    total = 195 + Σ (97 + len(name) + len(description) + len(location))

    粗略估计：~4 字符/token，所以每个 skill 约 24-50 token。

    如果 skill 太多，OpenClaw 会自动截断或切换紧凑模式（省略 description）。
