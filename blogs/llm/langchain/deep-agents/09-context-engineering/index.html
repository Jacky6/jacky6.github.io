    第九章：上下文工程¶

    上下文构成 | Offloading 与 Summarization | Prompt caching | 检索 RAG 依据官方文档 https://docs.langchain.com/oss/python/deepagents/context-engineering 和 /retrieval 整理

    9.1 上下文的构成¶

    Deep Agent 每一轮看到的上下文分几类：

    输入上下文（Agent 起步时拥有的）
├── System prompt      系统提示（create_deep_agent 的 system_prompt）
├── Memory             记忆文件（AGENTS.md，启动加载）
├── Skills             技能元数据（frontmatter，激活后加载正文）
└── Tool prompts       工具 schema 和描述

运行时上下文
├── Runtime context    context_schema 传入的动态数据（如用户选择的模型）
└── Custom state       自定义状态 schema 的额外字段

压缩机制（控制增长）
├── Offloading         大工具输入/结果落盘换引用
├── Summarization      旧消息压缩成摘要
├── Isolation          子代理隔离重活（第 10 章）
└── Long-term memory   文件系统持久化跨 thread（第 8 章）

    完整系统提示长什么样¶

    启动时系统提示的组成：基础指令 + 记忆内容 + 技能 frontmatter 列表 + 工具 prompt。v0.7 起基础提示默认为空、工具描述精简（默认单轮输入 token 降了 65%）。

    💡 省 token 第一招：用 harness profile 的 excluded_tools 排除用不到的内置工具——每轮都少发一份工具 schema（第 11 章）。

    9.2 上下文压缩（内置，无需配置）¶

    每个 create_deep_agent 自带上下文压缩，不用加任何 middleware。长任务产生大工具输出和长对话历史，压缩机制保证上下文留在窗口内。

    Offloading（卸载）¶

    工具调用的输入或结果超过 token 阈值（默认 20,000）时自动卸载到文件系统：

    ① 工具输入超限：文件写入/编辑操作会在对话历史里留下包含完整文件内容的工具调用——内容已经落盘了，是冗余的。当会话上下文超过模型窗口的 85% 时，截断旧工具调用，替换为磁盘文件指针。

    ② 工具结果超限：结果存到后端，替换为文件路径引用 + 前 10 行预览。Agent 之后可以用 read_file/grep 按需回读。

    大搜索结果（5万 token）
    ↓ offload
上下文里变成：「结果已存到 /tool_results/xxx.md，前 10 行预览：...」
    ↓ Agent 需要细节时
read_file /tool_results/xxx.md（按需、分页）

    注意：内置压缩不处理图片（不缩放、不降分辨率、不生成视觉 embedding）。多模态交互见第 6 章。

    Summarization（摘要）¶

    SummarizationMiddleware 在默认栈里。当上下文超过窗口限制（如 max_input_tokens 的 85%）且没有更多可卸载内容时，自动摘要消息历史。双轨设计：

    1. In-context summary：LLM 生成结构化摘要（会话意图、已创建的产物、下一步）——替换工作记忆中的完整历史
    2. Filesystem preservation：原始对话的文本渲染写入文件系统作为规范记录——需要时可搜索恢复细节

    配置细节：

    项 默认值
    触发阈值 模型 profile max_input_tokens 的 85%
    保留近期上下文 10% 的 token
    模型 profile 不可用时 回退到 170,000 token 触发 / 保留 6 条消息
    ContextOverflowError 立即回退摘要并用「摘要 + 保留消息」重试

    流式输出中摘要步骤生成的 token 也会出现在流里，可用 metadata 过滤：

    for chunk in agent.stream({"messages": [...]}, stream_mode="messages", version="v2"):
    token, metadata = chunk["data"]
    if metadata.get("lc_source") == "summarization":
        continue
    # ...

    按需压缩工具¶

    除了自动触发，可以给 Agent 一个 compact_conversation 工具，让它在任务之间主动压缩，不必等 85% 阈值：

    from deepagents import create_deep_agent
from deepagents.backends import StateBackend
from deepagents.middleware.summarization import create_summarization_tool_middleware

backend = StateBackend()  # if using default backend（官方示例原文如此；注意要传实例）
model = "anthropic:claude-sonnet-4-6"

agent = create_deep_agent(
    model=model,
    middleware=[
        create_summarization_tool_middleware(model, backend),
    ],
)

    v0.7 起，传入 .name 匹配内置中间件的实例会原位替换默认实例——比如传自己的 SummarizationMiddleware(...) 改触发阈值或摘要模型，不必先禁用内置的。

    9.3 Prompt caching（提示缓存）¶

    对 Anthropic 和 Amazon Bedrock 模型，create_deep_agent 自动对系统提示的静态部分（基础指令、记忆、每轮重复的技能内容）应用 prompt caching——避免重复处理相同 token，降低长时运行 Agent 的延迟和成本。

    • 使用 Anthropic 或 Bedrock（Claude/Nova）模型时默认启用，无需配置
    • v0.7 新增：Bedrock 缓存走 deepagents[aws] extra；Fireworks 自动 prompt-cache 会话亲和
    • 其他 Provider 看 integrations/middleware 页面有没有对应缓存中间件

    9.4 检索 (Retrieval / RAG)¶

    LLM 两大限制：上下文有限（吃不下整个语料库）、知识静态（训练数据冻结在某个时间点）。检索在查询时拉取相关外部知识，即 RAG 的基础。

    知识库¶

    已有知识库（SQL 数据库、文档库、CRM、内部文档系统）不用重建，两条接入路：

    • 作为工具给 Agent（Agentic RAG）
    • 查询后把检索内容作为上下文喂给 LLM（2-step RAG）

    从零构建用 LangChain 的 document loaders + text splitters + embeddings + vector stores：

    Sources（Drive/Slack/Notion...） → Document Loaders → 分块 → Embeddings → Vector Store
User Query → Query embedding → Vector Store → Retriever → LLM → Answer

    三种 RAG 架构¶

    架构 说明 控制力 灵活性 延迟 适用
    2-Step RAG 检索总在生成前，简单可预测 高 低 快且可预测 FAQ、文档机器人
    Agentic RAG LLM Agent 在推理中决定何时、如何检索 低 高 不定 带多工具的研究助理
    Hybrid 两者结合 + 校验步骤 中 中 不定 带质量校验的领域问答

    Deep Agents 天然适合 Agentic RAG：把检索工具（向量库查询、SQL、搜索）传给 tools=，Agent 自己决定查什么、查几次、要不要补充查询。配合子代理还能把"检索 + 阅读 + 综合"整体隔离到子上下文。

    def search_docs(query: str, k: int = 5) -> str:
    """Search the internal documentation vector store."""
    return vector_store.similarity_search(query, k=k)

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    tools=[search_docs],
    system_prompt="Answer questions using search_docs. Cite document titles.",
)

    9.5 最佳实践（官方）¶

    1. 大结果落盘：自定义工具返回大数据时存后端、回引用，配合 offloading
    2. 重活外包子代理：主上下文只收最终报告（第 10 章）
    3. 记忆分层：总是相关的进 memory（启动加载），任务相关的做成 skills（按需加载）
    4. 排除不用的内置工具：减少每轮 schema token
    5. 多模态场景：媒体传引用不传 base64（第 6 章）
    6. 长任务开 tracing：LangSmith 里能看清压缩什么时候触发、丢了什么

    9.6 本章小结¶

    关键要点¶

    1. 上下文压缩内置且默认开启：offloading（20k token 阈值）+ summarization（85% 触发、保留 10%）
    2. 摘要双轨：in-context 摘要 + 原文落盘可恢复
    3. Anthropic/Bedrock 自动 prompt caching；v0.7 扩展到 Bedrock extra 和 Fireworks
    4. RAG 三种架构，Deep Agents 最适合 Agentic RAG（检索作为工具）
    5. 子代理是最强的上下文隔离手段
