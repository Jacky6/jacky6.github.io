    第八章：记忆系统 (Memory)¶

    AGENTS.md | 作用域记忆（Agent/User/Org）| 情景记忆 | 后台整合 依据官方文档 https://docs.langchain.com/oss/python/deepagents/memory 整理

    8.1 记忆系统概述¶

    Deep Agents 把记忆做成一等公民：文件系统式记忆——Agent 以文件形式读写记忆，你用后端（第 5 章）控制这些文件存在哪、谁能访问。

    📌 本章讲长期记忆（跨会话持久）。短期记忆（单会话内的对话历史和草稿文件）由上下文工程自动管理 → 第 9 章。

    ┌────────────────────────────────────────────────────────┐
│  短期记忆：thread 内，checkpoint 持久化，会话结束即归档    │
│  长期记忆：跨 thread，存在后端（通常 StoreBackend）        │
└────────────────────────────────────────────────────────┘

    工作机制（三步）¶

    1. 给 Agent 指路：创建 Agent 时传 memory= 文件路径（也可以传 skills= 提供程序性记忆）。后端决定存储位置和访问控制
    2. Agent 读记忆：启动时加载进系统提示，或对话中按需读取（技能就是按需加载的例子）
    3. Agent 更新记忆（可选）：学到新信息时用内置 edit_file 工具更新记忆文件。更新可以发生在对话中（默认）或会话间后台进行（background consolidation）。并非所有记忆都可写：开发者定义的技能、组织策略通常只读

    与技能的关键区别：记忆文件总是被加载（memory 参数指定的内容），技能按需加载。

    8.2 作用域记忆¶

    同一份记忆文件可以全员共享，也可以每人独立——由后端 namespace 决定。

    Agent 级记忆（共享）¶

    Agent 拥有随时间演化的持久身份：跨所有用户共享记忆，积累人格、知识、经验。

    关键在 namespace 设为 (assistant_id,)——该 Agent 的所有会话读写同一份记忆文件：

    from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    memory=["/memories/AGENTS.md"],
    skills=["/skills/"],
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.assistant_id,),
            ),
            "/skills/": StoreBackend(
                namespace=lambda rt: (rt.server_info.assistant_id,),
            ),
        },
    ),
)

    rt.server_info 需 deepagents>=0.5.0。

    完整示例：seed 记忆 → 跨 thread 验证

    from langchain_core.utils.uuid import uuid7
from deepagents.backends.utils import create_file_data
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()  # Use platform store when deploying to LangSmith

# Seed the memory file
store.put(
    ("my-agent",),
    "/memories/AGENTS.md",
    create_file_data("""## Response style
- Keep responses concise
- Use code examples where possible
"""),
)

# ... 创建 agent（namespace=("my-agent",)）...

# Thread 1: the agent learns a new preference and saves it to memory
config1 = {"configurable": {"thread_id": str(uuid7())}}
agent.invoke(
    {"messages": [{"role": "user", "content": "I prefer detailed explanations. Remember that."}]},
    config=config1,
)

# Thread 2: the agent reads memory and applies the preference
config2 = {"configurable": {"thread_id": str(uuid7())}}
agent.invoke(
    {"messages": [{"role": "user", "content": "Explain how transformers work."}]},
    config=config2,
)

    User 级记忆（隔离）¶

    每个用户独立的记忆文件：Agent 记住每个人的偏好、上下文、历史，核心指令保持固定。namespace 用 (user_id,)，User A 的偏好绝不泄漏给 User B：

    agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    memory=["/memories/preferences.md"],
    skills=["/skills/"],
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
            ),
            "/skills/": StoreBackend(
                namespace=lambda rt: (rt.server_info.user.identity,),
            ),
        },
    ),
)

    部署后，每个已认证请求的 rt.server_info.user.identity 自动解析为调用者——Alice 和 Bob 各自只看到自己的偏好。

    Organization 级记忆¶

    同一模式，namespace 换成组织维度（如 rt.context.org_id）。用于全组织的策略/知识。

    组织记忆通常设为只读——防止通过共享状态的提示注入：

    agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    memory=[
        "/memories/preferences.md",      # 用户级，可写
        "/policies/compliance.md",       # 组织级，只读
    ],
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(namespace=lambda rt: (rt.server_info.user.identity,)),
            "/policies/": StoreBackend(namespace=lambda rt: (rt.context.org_id,)),
        },
    ),
)

    组织记忆由应用代码写入（client.store.put_item(...)），用权限（第 6 章）强制只读。

    8.3 记忆设计维度¶

    官方给的高级参数矩阵——设计记忆系统时逐项决策：

    维度 回答的问题 选项
    持续时间 记多久？ 短期（单会话）/ 长期（跨会话）
    信息类型 记什么？ 情景记忆（经历）/ 程序性（技能指令）/ 语义（事实）
    作用域 谁能看/改？ User / Agent / Organization
    更新策略 何时写？ 对话中（默认）/ 会话间后台
    检索方式 怎么读？ 加载进提示（默认）/ 按需（如技能）
    写权限 Agent 能写吗？ 读写（默认）/ 只读（共享策略）

    8.4 情景记忆 (Episodic Memory)¶

    语义记忆（AGENTS.md 里的事实/偏好）记"学到了什么"；情景记忆保留完整对话上下文——"当时是怎么解决的"。

    Deep Agents 的 checkpointer 天然支持情景记忆：每个会话都是持久化的 checkpointed thread。要让历史会话可搜索，把 thread 搜索包装成工具：

    from langgraph_sdk import get_client
from langchain.tools import tool, ToolRuntime

client = get_client(url="<DEPLOYMENT_URL>")


@tool
async def search_past_conversations(query: str, runtime: ToolRuntime) -> str:
    """Search past conversations for relevant context."""
    user_id = runtime.server_info.user.identity
    threads = await client.threads.search(
        metadata={"user_id": user_id},
        limit=5,
    )
    results = []
    for thread in threads:
        history = await client.threads.get_history(thread_id=thread["thread_id"])
        results.append(history)
    return str(results)

    按 user 或 org 调整 metadata 过滤即可。用途：编码 Agent 回看过去的调试会话，直接跳到可能的根因。

    8.5 后台整合 (Background Consolidation)¶

    默认在对话中写记忆（hot path）。替代方案：会话间后台处理（sleep time compute）——一个独立的 deep agent 审阅近期会话、提取关键事实、合并进现有记忆。

    方式 优点 缺点
    Hot path（对话中） 记忆立即可用，对用户透明 增加延迟，Agent 要一心二用
    Background（会话间） 无用户侧延迟，可跨多会话综合 下次会话才可用，需要第二个 Agent

    多数应用 hot path 够用。要降延迟或提升跨会话记忆质量时再加后台整合。

    推荐模式：Consolidation Agent + Cron¶

    部署一个整合 Agent 与主 Agent 并行注册在 langgraph.json：

    # consolidation_agent.py
from datetime import datetime, timedelta, timezone
from deepagents import create_deep_agent
from langchain.tools import tool, ToolRuntime
from langgraph_sdk import get_client

sdk_client = get_client(url="<DEPLOYMENT_URL>")


@tool
async def search_recent_conversations(query: str, runtime: ToolRuntime) -> str:
    """Search this user's conversations updated in the last 6 hours."""
    user_id = runtime.server_info.user.identity
    since = datetime.now(timezone.utc) - timedelta(hours=6)
    threads = await sdk_client.threads.search(
        metadata={"user_id": user_id},
        updated_after=since.isoformat(),
        limit=20,
    )
    conversations = []
    for thread in threads:
        history = await sdk_client.threads.get_history(thread_id=thread["thread_id"])
        conversations.append(history["values"]["messages"])
    return str(conversations)


agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    system_prompt="""Review recent conversations and update the user's memory file.
Merge new facts, remove outdated information, and keep it concise.""",
    tools=[search_recent_conversations],
)

    // langgraph.json
{
  "dependencies": ["."],
  "graphs": {
    "agent": "./agent.py:agent",
    "consolidation_agent": "./consolidation_agent.py:agent"
  },
  "env": ".env"
}

    用 LangSmith cron job 定时触发：

    cron_job = await client.crons.create(
    assistant_id="consolidation_agent",
    schedule="0 */6 * * *",
    input={"messages": [{"role": "user", "content": "Consolidate recent memories."}]},
)

    ⚠️ cron 周期必须与 Agent 内的回看窗口对齐：上面每 6 小时跑一次，工具也回看 6 小时。跑得太勤 = 重复处理；跑得稀疏 = 丢窗口外的记忆。所有 cron 时间按 UTC 解释。

    频率建议贴合真实使用节奏：日活聊天产品每几小时整合一次；一周用几次的工具每晚或每周跑即可。

    8.6 只读 vs 可写记忆¶

    默认 Agent 对记忆文件可读可写。共享状态（组织策略、合规规则）应设为只读：

    • 防止通过共享记忆的提示注入
    • 保证只有应用代码控制文件内容

    手段：permissions deny write（第 6 章）或 backend policy hooks 做自定义校验。

    并发写入¶

    多个会话同时写同一份记忆文件时，StoreBackend 按 store 实现的语义处理（LangGraph Store 支持乐观并发）。高并发写同一文件场景建议用后台整合串行化写入。

    同一部署多个 Agent¶

    多个 Agent 共享部署时，各自用不同的 namespace 前缀（如 (assistant_id, "memories")）避免互相覆盖。

    8.7 本章小结¶

    关键要点¶

    1. 记忆 = 文件（AGENTS.md 等），memory= 指定路径，后端决定存储和作用域
    2. 作用域由 namespace factory 决定：(assistant_id,) 共享 / (user_id,) 隔离 / (org_id,) 组织级
    3. 记忆文件启动即加载（vs 技能按需加载）；Agent 用 edit_file 自我更新
    4. 组织记忆只读防注入；情景记忆靠 checkpointer + thread 搜索工具
    5. 后台整合：consolidation agent + cron，周期与回看窗口对齐（UTC）
