    第十四章：生产部署¶

    三条部署路径 | Managed Deep Agents (Beta) | Going to production 要点 | 多租户 依据官方文档 managed-deep-agents-overview / going-to-production 整理

    14.1 三条部署路径¶

    官方提供三种方式，按"你管多少基础设施"递增：

    路径 适用场景 你管 LangSmith 管
    Managed Deep Agents 想快速部署 code-first Deep Agent 到托管设施 Agent 代码、工具、中间件、指令、调度、可选身份 后端、store、checkpointer、记忆、技能、沙箱、托管部署、身份认证
    LangSmith Deployment 需要自定义应用代码/路由、高级认证、更强隔离、极限扩展 应用代码、服务器、部署配置 托管设施和扩缩容
    OSS Deep Agents（自托管） 要在自己的环境跑 harness 一切，含托管和持久化 无

    自托管方式：langgraph build 产出独立 Docker 镜像，部署到任何地方——与托管模式用同一份代码，无需修改。

    14.2 Managed Deep Agents（Private Beta）¶

    托管运行时，用于在 LangSmith 中部署和运维 code-first Deep Agents。你管不了也不需要管 agent server——用 Python/TypeScript 写 Agent，用 mda CLI 测试和部署。

    托管运行时提供：

    • Durable runs（持久运行）
    • LangSmith sandboxes（一方沙箱）
    • Context Hub 支撑的指令、技能、记忆
    • Traces
    • Hosted LangGraph deployment

    ⚠️ Private beta：仅 LangSmith Cloud 美国区；需申请 waitlist。Beta 期间 CLI-first（API 驱动的创建/更新/调用示例已移除）。

    项目结构¶

    Managed Deep Agent 组织为本地项目目录——文件的位置决定它的角色：CLI 读取目录找到 Agent 入口、托管指令、技能、connectors、channels、调度、可选身份、沙箱配置、本地 eval 任务，然后把部署相关部分打包成托管部署。

    推荐工作流¶

    1. 安装 managed-deepagents（Python 或 TypeScript）
    2. mda init 创建本地 code-first agent 项目
    3. 系统提示写到 instructions.md
    4. 添加工具、中间件、调度、技能、connectors、消息 channels、可选身份和沙箱
    5. 可选：mda evals compile 编译 Harbor 风格 evals 并运行
    6. mda dev 在 LangSmith Studio 本地测试 → mda deploy 部署
    7. 在 LangSmith 查看部署、traces、运行时状态

    Beta 注意事项¶

    • 模型：{provider}:{model_id} 格式（如 openai:gpt-5.5），运行时用 init_chat_model 解析——只要运行时有凭证，任何支持的 Provider 都行。key 放 .env、shell 导出或 LangSmith workspace secrets
    • Context Hub 记忆：托管记忆与部署的指令/技能同一个 Hub repo。运行时把一个 Hub 切片重挂载为 /memories/user/（热记忆在 /memories/user/AGENTS.md，冷记忆在同目录其他文件），可选组织事实挂 /memories/org/（只读）。部署会同步 instructions.md 和 skills/**，但保留已有 memories/**，不覆盖运行时创建的记忆。disableMemory: true 可关闭托管记忆
    • 限流：Beta 期间未公布 per-key/workspace/agent 限流
    • 不支持自托管/混合部署

    14.3 Going to production（自托管要点）¶

    官方 Going to production 文档覆盖自托管 LangSmith Deployments 的生产细节，关键主题：

    调用 Agent¶

    • 每个会话用 thread_id 标识；后续轮次复用同一 thread_id 保持上下文
    • 流式端点、run history、webhooks 由 agent server 提供

    多租户¶

    生产应用面向多用户，必须隔离：

    • Scoped threads：按用户隔离会话
    • 按用户沙箱：沙箱生命周期可配 thread-scoped 或 assistant-scoped（第 5 章）；LangSmith Sandbox 还提供 auth proxy，终端用户可以从沙箱调第三方 API 而无需你逐个配凭证
    • RBAC：团队访问控制
    • StoreBackend namespace：(user_id,) 隔离记忆（第 8 章）

    异步与持久性¶

    • 长任务异步执行，客户端轮询或订阅更新
    • checkpointer 保证运行可恢复（HITL、故障恢复都靠它）

    记忆的生产配置¶

    • 作用域选择：user / agent / org（第 8 章）
    • LangSmith Deployment 自动配 store；自托管用 PostgresStore/RedisStore

    执行环境¶

    • 生产环境文件系统交互优先用沙箱后端（不是 FilesystemBackend）
    • 沙箱生命周期表、graph factory 的异步注意事项、TTL 行为见官方 Sandbox lifecycle 节

    Guardrails¶

    • Permissions：第 6 章的声明式规则 + HITL 审批
    • 容错：工具失败重试、模型 fallback
    • 数据隐私：密钥不进沙箱、PII 处理

    前端¶

    • 第 13 章的 useStream 模式接入部署端点

    14.4 生产检查清单¶

    项 检查
    ✅ Checkpointer 持久化（Postgres/Redis），不是 InMemorySaver
    ✅ Store 生产级 BaseStore（Postgres/Redis/平台提供）
    ✅ 多租户 namespace 按 user 隔离；沙箱按 thread/user
    ✅ 密钥 环境变量/secrets 管理；不进沙箱；FilesystemBackend 场景排除密钥路径
    ✅ 审批 破坏性操作配 interrupt_on
    ✅ 沙箱 TTL 闲置自动清理，控制成本
    ✅ Tracing LangSmith 开启，便于调试长任务
    ✅ Eval LangSmith evaluation 对数据集跑自动化测试
    ✅ 记忆写权限 组织级记忆只读；个人记忆可写
    ✅ 监控 部署健康、运行历史、错误率

    14.5 本章小结¶

    关键要点¶

    1. 三条路径：Managed（最省心，Beta）→ LangSmith Deployment（自定义）→ 自托管（全控）；同一份代码可在托管/自托管间切换
    2. Managed Deep Agents = mda CLI 工作流（init → dev → deploy）+ Context Hub 记忆
    3. 多租户三板斧：scoped threads、按用户沙箱、namespace 隔离记忆
    4. 生产环境文件系统交互用沙箱，密钥永不进沙箱
