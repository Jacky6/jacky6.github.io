    第五章：后端与沙箱¶

    可插拔文件系统后端 | 远程沙箱执行 | 文件传输 | 安全边界 依据官方文档 https://docs.langchain.com/oss/python/deepagents/backends 和 /sandboxes 整理

    5.1 后端是什么？¶

    内置文件工具（ls/read_file/...）只是接口，真正读写数据的是后端 (backend)。通过 backend= 参数可插拔替换：

    文件工具（模型看到的） → Backend（你选择的） → 存储介质
                        ├── State        → LangGraph 状态（thread 内）
                        ├── Filesystem   → 本地磁盘
                        ├── Store        → LangGraph Store（跨 thread）
                        ├── ContextHub   → LangSmith Hub repo
                        ├── Sandbox      → 远程容器（+ execute 工具）
                        ├── LocalShell   → 本地磁盘 + 宿主机 shell
                        ├── Composite    → 按路径前缀路由到以上任意组合
                        └── Custom       → 你自己实现（S3、数据库……）

    不传 backend= 时默认是 StateBackend()。后端必须实现 BackendProtocol。

    5.2 内置后端速查¶

    后端 一句话 持久性
    StateBackend（默认） 文件存在 LangGraph 状态里 thread 内（靠 checkpointer），不跨 thread
    FilesystemBackend 读写本地磁盘真实文件 永久
    LocalShellBackend 本地磁盘 + 宿主机 shell 执行（execute 工具） 永久
    StoreBackend LangGraph Store，跨 thread 持久 永久
    ContextHubBackend 存到 LangSmith Context Hub repo（带 commit 历史） 永久
    沙箱后端（第 5.6 节） 远程隔离容器 + execute 取决于容器生命周期
    CompositeBackend 按路径前缀路由到不同后端 混合

    5.3 各后端详解¶

    StateBackend（默认）¶

    from deepagents import create_deep_agent
from deepagents.backends import StateBackend

agent = create_deep_agent(model="anthropic:claude-sonnet-4-6")  # 默认就是它
agent2 = create_deep_agent(model="anthropic:claude-sonnet-4-6", backend=StateBackend())  # 等价
    • 文件存在当前 thread 的 LangGraph agent state 里，靠检查点跨轮次持久；不跨 thread 共享
    • ⚠️ 设计为在 graph 运行内部使用——在 graph 外调用 state_backend.upload_files(...) 不会生效，要等 graph 执行
    • 适合：Agent 的草稿本（中间结果）、大工具输出自动卸载后按需回读
    • 注意：主 Agent 和子代理共享这个后端——子代理写的文件在它结束后仍然留在状态里，主 Agent 和其他子代理可继续访问

    FilesystemBackend（本地磁盘）¶

    from deepagents.backends import FilesystemBackend

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=FilesystemBackend(root_dir=".", virtual_mode=True),
)

    直接读写 root_dir 下的真实文件。官方说明 root_dir 应为绝对路径（如 /Users/nh/Desktop/；示例中的 "." 是官方文档写法，生产环境建议显式绝对路径）。

    ⚠️ 安全警告（官方原文）：

    • 适合：本地开发 CLI（编码助手、开发工具）、CI/CD 流水线
    • 不适合：Web 服务器/HTTP API——用 StateBackend、StoreBackend 或沙箱代替
    • 风险：Agent 能读任何可访问文件（含密钥、.env）；配合网络工具可能被 SSRF 窃取；文件修改永久不可逆
    • 防护措施：
    • 启用 HITL（第 11 章）审查敏感操作
    • 把密钥排除在可访问路径之外（尤其 CI/CD）
    • 生产环境改用沙箱后端
    • 务必用 virtual_mode=True + root_dir，启用路径限制（阻止 ..、~、root 外绝对路径）——默认 virtual_mode=False 时即使设了 root_dir 也没有安全性

    LocalShellBackend（本地 shell）¶

    from deepagents.backends import LocalShellBackend

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=LocalShellBackend(root_dir=".", virtual_mode=True, env={"PATH": "/usr/bin:/bin"}),
)
    • 在 FilesystemBackend 基础上加了 execute 工具，命令通过 subprocess.run(shell=True) 直接在宿主机运行，无任何沙箱隔离
    • 支持 timeout（默认 120s）、max_output_bytes（默认 100,000）、env、inherit_env
    • 命令以 root_dir 为工作目录，但能访问系统上任何路径
    • ⚠️ 只用于个人开发环境/受信 CI；virtual_mode=True 对有 shell 访问的情况不提供安全性
    • 官方强烈建议搭配 HITL 使用

    StoreBackend（LangGraph Store）¶

    from deepagents.backends import StoreBackend
from langgraph.store.memory import InMemoryStore

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=StoreBackend(
        namespace=lambda rt: (rt.server_info.user.identity,),
    ),
    store=InMemoryStore(),  # Good for local dev; omit for LangSmith Deployment
)
    • 跨 thread 持久存储——适合长期记忆、跨会话指令
    • store 传给 create_deep_agent(store=...)，不传给后端
    • 适合：已有 LangGraph store（Redis/Postgres/云实现）、通过 LangSmith Deployment 部署（自动配 store）

    namespace factory：namespace 参数接收 Callable[[Runtime], tuple[str, ...]]，控制数据隔离范围。Runtime 提供三组信息：

    • rt.context — 用户自定义 context（如 user_id）
    • rt.server_info — LangGraph Server 元数据（assistant ID、已认证用户）
    • rt.execution_info — 执行标识（thread ID、run ID、checkpoint ID）

    常见模式：

    # Per-user: each user gets their own isolated storage
backend = StoreBackend(namespace=lambda rt: (rt.server_info.user.identity,))

# Per-assistant: all users of the same assistant share storage
backend = StoreBackend(namespace=lambda rt: (rt.server_info.assistant_id,))

# Per-thread: storage scoped to a single conversation
backend = StoreBackend(namespace=lambda rt: (rt.execution_info.thread_id,))

    可以组合，如 (user_id, thread_id)。namespace 组件只允许字母数字、-_.@+:~，通配符会被拒绝（防 glob 注入）。

    ⚠️ v0.7 起 namespace 必须显式设置（旧版默认按 assistant_id，多用户场景会导致所有人共享存储）。

    ContextHubBackend（LangSmith Hub）¶

    from deepagents.backends import ContextHubBackend

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=ContextHubBackend("my-agent"),   # owner/name 或 name
)
# 需先设置 LANGSMITH_API_KEY

    把文件系统存进 LangSmith Context Hub repo：agent repo 挂到文件系统根目录，链接的 skill repo 出现在 /skills/ 下。写入以 Hub commit 形式持久化（带历史）。懒加载 + 内存缓存；乐观锁写入，冲突时重新 pull 再重试；只接受 UTF-8 文本。

    适合：LangSmith 原生持久化、不想单独接 LangGraph store、需要文件变更历史。

    CompositeBackend（路由器）¶

    按路径前缀把文件操作路由到不同后端——最常用的生产配置：

    from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(namespace=lambda _rt: ("memories",)),
        },
    ),
    store=InMemoryStore(),  # Store passed to create_deep_agent, not backend
)

    行为：

    • /workspace/plan.md → StateBackend（thread 内）
    • /memories/agent.md → StoreBackend（跨 thread）
    • ls/glob/grep 聚合各后端结果，保留原始路径前缀
    • 更长的前缀优先（/memories/projects/ 覆盖 /memories/）

    💡 Deep Agents 会把内部数据（卸载的工具结果、对话历史）写到默认后端。官方建议默认后端用 StateBackend，让这些临时产物不落盘/不进持久存储——尤其当其他路由指向本地磁盘或持久 store 时。

    5.4 自定义后端¶

    实现 BackendProtocol 的方法（返回结构化结果，不要抛异常，失败放 error 字段）：

    方法 签名 说明
    ls (path) -> LsResult 列目录
    read (file_path, offset, limit) -> ReadResult 读文件，可分页
    write (file_path, content) -> WriteResult 新建或覆盖
    edit (file_path, old_string, new_string, replace_all) -> EditResult 查找替换
    glob (pattern, path=None) -> GlobResult 模式匹配
    grep (pattern, path=None, glob=None) -> GrepResult 内容搜索
    delete (file_path) -> DeleteResult 可选；不支持时 delete 工具自动隐藏

    要支持 execute 工具，改为实现 SandboxBackendProtocol（多一个 execute 方法）。

    官方文档给了 S3 风格后端的骨架（路径映射到对象 key）；社区后端见 integrations/backends 页面。

    v0.7 迁移注意¶

    旧的 backend factory 写法已移除：必须传具体后端实例而非工厂函数；BackendFactory、BACKEND_TYPES、FileFormat、Unset 等符号删除；StoreBackend 要显式 namespace；旧的 BackendContext 参数改为 LangGraph Runtime。

    5.5 权限与后端的关系¶

    声明式文件系统权限（第 6 章）作用于内置文件工具，但不适用于沙箱后端——沙箱通过 execute 能执行任意命令，路径级权限拦不住。需要自定义校验逻辑时用 backend policy hooks（Backends 文档的 "Add policy hooks" 节）。

    5.6 沙箱 (Sandboxes)¶

    为什么用沙箱？¶

    让 Agent 执行任意代码、访问文件、使用网络，而不危及你的凭证、本地文件和宿主机。特别适合：

    • 编码 Agent：自主跑 shell/git、clone 仓库、Docker-in-Docker 构建测试
    • 数据分析 Agent：装 pandas/numpy、跑统计、生成 PPT 等产物

    LangSmith 提供一方托管沙箱（无需第三方账号），见 LangSmith Sandboxes 文档。Deep Agents Code 用 --sandbox flag 内置沙箱支持。

    基本用法（以 LangSmith Sandbox 为例）¶

    from deepagents import create_deep_agent
from deepagents.backends import LangSmithSandbox
from langsmith.sandbox import SandboxClient

client = SandboxClient()
ls_sandbox = client.create_sandbox()
backend = LangSmithSandbox(sandbox=ls_sandbox)

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    system_prompt="You are a Python coding assistant with sandbox access.",
    backend=backend,
)
try:
    result = agent.invoke(
        {"messages": [{"role": "user", "content": "Create a small Python package and run pytest"}]}
    )
finally:
    client.delete_sandbox(ls_sandbox.name)   # 沙箱按时计费，用完必须销毁

    安装：pip install "langsmith[sandbox]"。

    支持的 Provider¶

    官方沙箱集成（各自注册/认证/生命周期细节见 integrations/sandboxes）：

    LangSmith（一方托管）、AWS AgentCore、Daytona、Deno、E2B、Modal、Runloop、本地 VFS。没有你要的 Provider 可以自己实现（只需实现 execute()，见下文架构）。

    生命周期与作用域¶

    多数应用二选一：

    • Thread-scoped（默认）：每个会话一个沙箱。首轮创建，同 thread 后续轮次复用；thread 结束或 TTL 过期后销毁。用沙箱名/元数据存映射，保证每轮解析到同一个沙箱。用户可能长时间不活跃时，配置 TTL 让 Provider 自动清理
    • Assistant-scoped：同一 assistant 的所有 thread 共享一个沙箱

    ⚠️ 沙箱在销毁前持续消耗资源和费用——不用了一定要关。完整生命周期表、TTL 行为、LangGraph Deployment 接线见 Going to production 文档。

    两种集成架构¶

    Agent in sandbox Sandbox as tool（推荐）
    Agent 在哪跑 沙箱内部，通过网络通信 你的机器/服务器，沙箱只是工具
    ✅ 优点 贴近本地开发、环境紧耦合 Agent 代码即时更新不用重建镜像；状态与执行分离；API key 留在沙箱外；沙箱挂了不丢状态；可多沙箱并行；按执行时间付费
    🔴 代价 API key 必须进沙箱（安全风险）；更新要重建镜像；要自建通信层（WebSocket/HTTP） 每次执行有网络延迟

    沙箱的工作原理：一切基于 execute()¶

    Provider 只需实现一个 execute() 方法（跑 shell 命令返回输出）。其他所有文件操作（read/write/edit/delete/ls/glob/grep）由 BaseSandbox 基类构造脚本、经 execute() 在沙箱内运行。

    这带来两个结果：

    • 新增 Provider 很简单——实现 execute() 即可
    • execute 工具条件可用：每次模型调用时 harness 检查后端是否实现 SandboxBackendProtocol，没有就过滤掉该工具，模型永远看不到

    Agent 调用 execute 工具时传 command 字符串，拿回合并的 stdout/stderr、退出码，输出过大会带截断提示。

    文件进出沙箱的两个平面¶

    平面 谁调用 走什么 用途
    Agent 文件工具 LLM 在执行中 沙箱内 execute() 读代码、写文件、跑命令
    文件传输 API 你的应用代码 Provider 原生传输 API（非 shell） 运行前 seed 沙箱、运行后取回产物

    Seed 沙箱：运行前用 upload_files() 预置源码/配置/数据（路径必须绝对路径，内容为 bytes）。

    取回产物：运行后用 download_files() 拿到生成的代码、构建输出、报告。

    安全注意事项¶

    沙箱保护宿主机不被 Agent 的文件/shell 操作影响，但不防：

    • 上下文注入：控制 Agent 输入的攻击者可以指挥它在沙箱内执行任意命令——沙箱隔离了，但 Agent 在沙箱内是全能
    • 网络外泄：除非断网，被注入的 Agent 能通过 HTTP/DNS 把数据送出沙箱（部分 Provider 支持断网，如 Modal 的 blockNetwork: true）

    对策（官方 Security considerations）：

    1. 密钥不进沙箱——用沙箱外的代理调用第三方 API，或用 LangSmith Sandbox 的 auth proxy
    2. 能断网就断网
    3. 最小化沙箱内凭证暴露时间
    4. 对不可信输入场景加 HITL 审批（第 11 章）

    5.7 选型速查¶

    需求 选什么
    原型/测试 StateBackend（默认）
    本地编码助手（受信环境） FilesystemBackend 或 LocalShellBackend + HITL
    跨会话记忆 StoreBackend（配 namespace）或 Composite 路由 /memories/
    LangSmith 全家桶 ContextHubBackend
    生产多租户：临时文件 + 持久记忆 CompositeBackend(default=StateBackend, routes={"/memories/": StoreBackend})
    执行不可信代码/装依赖/跑测试 沙箱后端（Sandbox as tool 模式）

    5.8 本章小结¶

    关键要点¶

    1. 后端 = 文件工具背后的存储层，backend= 传入，默认 StateBackend
    2. 内置数据（卸载结果、对话历史）写默认后端——生产配置用 Composite + StateBackend 做默认
    3. StoreBackend 跨 thread，namespace factory 决定隔离粒度（v0.7 必须显式设置）
    4. 沙箱后端自动带来 execute 工具；其他文件操作全部构建在 execute() 之上
    5. 沙箱 ≠ 防注入/防外泄——密钥放沙箱外，能断网就断网
    6. 权限系统管不住沙箱（能执行任意命令）
