    第十章：子代理 (Subagents)¶

    task 工具 | 默认 general-purpose 子代理 | 自定义子代理 | 异步子代理 | 动态子代理 依据官方文档 https://docs.langchain.com/oss/python/deepagents/subagents 和 /async-subagents 整理

    10.1 为什么需要子代理？¶

    子代理解决上下文膨胀问题。Agent 用大输出工具（搜索、读文件、查数据库）时，上下文窗口很快被中间结果塞满。子代理把这些细节工作隔离出去——主 Agent 只收到最终结果，而不是产生它的几十个工具调用。

    内置 task 工具让主 Agent 动态创建临时子代理：

    • 全新上下文：每次调用创建独立的新 Agent 实例
    • 自主执行：子代理独立运行直到完成
    • 单次交接：只向主 Agent 返回一份最终报告
    • 无状态消息：子代理不能多次回传消息

    适合用子代理：

    • ✅ 会弄乱主上下文的多步任务
    • ✅ 需要专门指令/工具的领域任务
    • ✅ 需要不同模型能力的任务
    • ✅ 想让主 Agent 专注高层协调

    不适合：

    • ❌ 简单单步任务
    • ❌ 需要保留中间上下文的任务
    • ❌ 开销大于收益的场景

    10.2 默认子代理：general-purpose¶

    除非你已提供同名子代理，Deep Agents 自动添加一个同步的 general-purpose 子代理。它默认带文件系统工具，可以额外定制。

    • 替换它：传一个自己定义的、名为 general-purpose 的子代理
    • 改名/改提示：在 harness profile 上设 general_purpose_subagent=GeneralPurposeSubagentProfile(...)（第 11 章）
    • 禁用它：见下节

    完全去掉 task 工具（不用子代理）¶

    两步：

    1. 在激活的 harness profile 上设 general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False)
    2. create_deep_agent 不传任何同步子代理

    Deep Agents 只在至少存在一个同步子代理时才挂 SubAgentMiddleware（和 task 工具）。两者都没有，Agent 就没有委派能力。

    ⚠️ 别用 excluded_middleware 移除 SubAgentMiddleware——它是必需脚手架，列进去会抛 ValueError。general_purpose_subagent.enabled=False 才是官方支持的路径。

    异步子代理不受影响——它们走自己的 middleware 和工具。

    10.3 自定义子代理¶

    SubAgent（字典形式）¶

    字段 类型 说明 / 继承行为
    name str 必填。唯一标识，主 Agent 调 task() 时用这个名字；成为 AIMessage 元数据和流式标识
    description str 必填。写清楚干什么——主 Agent 靠它决定何时委派
    system_prompt str 必填，不继承主 Agent。含工具使用指导和输出格式要求
    tools list[Callable] 可选。默认继承主 Agent；指定则完全覆盖。保持最小化
    model str \| BaseChatModel 可选。默认继承；可传 'openai:gpt-5.5' 字符串或模型实例
    middleware list[Middleware] 可选，不继承。合并进同步子代理栈（.name 匹配默认中间件则原位替换）。如放 FilesystemMiddleware(tools=[...]) 单独限制该子代理的文件工具
    interrupt_on dict 可选。该子代理的 HITL 配置；默认继承，指定则覆盖。需 checkpointer
    skills list[str] 可选，不继承（只有 GP 子代理继承主 Agent 技能）。有技能时跑独立的 SkillsMiddleware，技能状态完全隔离
    response_format ResponseFormat 可选。结构化输出 schema：父级收到 JSON 而非自由文本（Pydantic 模型 / ToolStrategy / ProviderStrategy）
    permissions list[FilesystemPermission] 可选。设置则完全替换父级权限；默认继承 
    import os
from typing import Literal

from deepagents import create_deep_agent
from tavily import TavilyClient

tavily_client = TavilyClient(api_key=os.environ["TAVILY_API_KEY"])


def internet_search(
    query: str,
    max_results: int = 5,
    topic: Literal["general", "news", "finance"] = "general",
    include_raw_content: bool = False,
):
    """Run a web search"""
    return tavily_client.search(
        query,
        max_results=max_results,
        include_raw_content=include_raw_content,
        topic=topic,
    )


research_subagent = {
    "name": "research-agent",
    "description": "Used to research more in depth questions",
    "system_prompt": "You are a great researcher",
    "tools": [internet_search],
    "model": "openai:gpt-5.5",  # Optional override, defaults to main agent model
}

agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    subagents=[research_subagent],
)

    CompiledSubAgent（图形式）¶

    复杂工作流用预构建的 LangGraph 图当子代理（用 create_agent 或 graph API 构建，必须 .compile()）：

    字段 类型 说明
    name str 必填
    description str 必填
    runnable Runnable 必填。已编译的 LangGraph 图

    适合需要自定义控制流（循环、分支、多阶段）的场景。

    结构化输出¶

    子代理设 response_format 后，task 的返回值是 JSON——主 Agent 拿到结构化结果（如研究报告的固定字段、代码审查的问题列表），便于程序化处理。

    10.4 动态子代理（配合 Interpreter）¶

    启用解释器（第 6 章）后，子代理派发（task()）可以在解释器代码里调用——实现代码驱动的 fan-out：对大输入的每个单元派发一个子代理、收集验证结果、递归工作流。Agent 有子代理时默认开启，可关闭。

    10.5 异步子代理 (Async Subagents)¶

    Preview feature（deepagents 0.5.0+），API 可能变化。

    同步子代理会阻塞主 Agent 直到完成。异步子代理让 supervisor 启动后台任务立即返回，继续与用户交互，随时查进度、追加指令、取消任务。

    维度 同步子代理 异步子代理
    执行模型 supervisor 阻塞等待 立即返回 job ID，supervisor 继续
    并发 并行但阻塞 并行且非阻塞
    中途更新 不可能 update_async_task 追加指令
    取消 不可能 cancel_async_task
    状态 无状态 有状态，自己的 thread 跨交互保持
    适合 需要等结果再继续的任务 长任务、聊天中交互式管理

    异步子代理通过 Agent Protocol 与任何兼容服务器通信（LangSmith Deployments 或自托管）。

    配置¶

    from deepagents import AsyncSubAgent, create_deep_agent

async_subagents = [
    AsyncSubAgent(
        name="researcher",
        description="Research agent for information gathering and synthesis",
        graph_id="researcher",
        # No url → ASGI transport (co-deployed in the same deployment)
    ),
    AsyncSubAgent(
        name="coder",
        description="Coding agent for code generation and review",
        graph_id="coder",
        # url="https://coder-deployment.langsmith.dev"  # Optional: HTTP transport for remote
    ),
]

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    subagents=async_subagents,
)

    字段：name/description（必填）、graph_id（必填，Agent Protocol 服务器上的 graph/assistant ID，LangGraph 部署需与 langgraph.json 注册名一致）、url（省略 = ASGI 进程内传输；设置 = HTTP 远程）、headers（远程认证）。

    共部署时把所有 graph 注册到同一个 langgraph.json：

    {
  "graphs": {
    "supervisor": "./src/supervisor.py:graph",
    "researcher": "./src/researcher.py:graph",
    "coder": "./src/coder.py:graph"
  }
}

    Supervisor 的五个工具¶

    配置异步子代理后，AsyncSubAgentMiddleware 给 supervisor：

    工具 用途 返回
    start_async_task 启动后台任务 Task ID（立即）
    check_async_task 查状态和结果 状态 + 结果（若完成）
    update_async_task 给运行中的任务发新指令 确认 + 更新后状态
    cancel_async_task 停止任务 确认
    list_async_tasks 列出所有任务 全部任务摘要

    部署拓扑¶

    • Single deployment：supervisor 和子代理同一部署，ASGI 传输（无 url）
    • Split deployment：子代理独立部署，HTTP 传输（设 url）
    • Hybrid：部分共部署 + 部分远程

    10.6 流式观察子代理¶

    见第 6 章 6.4 节：event streaming 的 stream.subagents 为每个 task 调用提供独立流句柄（name/status/messages/tool_calls）。LangSmith tracing 里可按子代理名过滤 trace。

    10.7 最佳实践（官方）¶

    1. description 写清楚：主 Agent 靠 description 选子代理——具体、动作导向（"Researches X by doing Y, returns Z"）
    2. system_prompt 详细：子代理不继承主 Agent 提示，要把上下文、约束、输出格式写全
    3. 工具集最小化：只给需要的工具，减少干扰和 token
    4. 按任务选模型：研究用便宜的，关键推理用强的
    5. 返回简洁结果：子代理的价值就是压缩上下文——指令里明确要求"返回紧凑摘要而非原始数据"
    6. 常见模式：多个专业子代理（researcher / coder / reviewer），主 Agent 只做协调和整合

    10.8 故障排查¶

    问题 排查
    子代理没被调用 description 是否清晰匹配任务？主 Agent 是否知道有这个选项（系统提示里可提示委派策略）？
    上下文还是膨胀 子代理是否返回了太多原始数据？要求紧凑输出；检查主 Agent 是否自己也在做重活
    选错了子代理 多个 description 是否重叠？让各自职责更互斥

    10.9 本章小结¶

    关键要点¶

    1. task 工具 = 内置委派机制；默认带 general-purpose 子代理
    2. 子代理字段继承规则要记牢：tools/model/interrupt_on/permissions 继承（可覆盖），system_prompt/middleware/skills 不继承
    3. 去掉 task 工具：harness profile 禁用 GP 子代理 + 不传同步子代理（不是 excluded_middleware）
    4. CompiledSubAgent 用于自定义控制流；response_format 拿结构化结果
    5. 异步子代理 = 非阻塞 + 可中途干预 + 有状态，走 Agent Protocol
