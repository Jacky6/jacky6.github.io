    第三章：模型与 Provider 配置¶

    provider:model 模型字符串 | 模型参数 | Provider profiles | 运行时切换模型 依据官方文档 https://docs.langchain.com/oss/python/deepagents/models 整理

    3.1 模型字符串格式¶

    Deep Agents 用 provider:model 格式指定模型：

    from deepagents import create_deep_agent

agent = create_deep_agent(model="anthropic:claude-sonnet-4-6")
# 其他示例：
#   "google_genai:gemini-3.6-flash"
#   "openai:gpt-5.5"
#   "baseten:zai-org/GLM-5.2"          ← 有些 Provider 用带命名空间的 ID

    规则：

    • 冒号前的 provider 前缀选择 LangChain 集成包（合法值见 init_chat_model 的 model_provider 参数文档）
    • 冒号后的部分原样传给该 Provider 作为模型标识符——格式由 Provider 决定（有的用简单名如 gpt-5.5，有的用带命名空间的 ID 如 zai-org/GLM-5.2）
    • 底层通过 init_chat_model 解析

    官方评测推荐的模型¶

    官方维护了一个 Deep Agents eval suite（测试文件操作、检索、工具使用、记忆、对话、摘要等基础 Agent 能力）。通过评测是"够用"的必要条件，长复杂任务仍需自行验证：

    Provider 推荐模型
    Google gemini-3.1-pro-preview, gemini-3.6-flash
    OpenAI gpt-5.5, gpt-5.4
    Anthropic claude-opus-4-8, claude-opus-4-7, claude-opus-4-6
    开源权重 GLM-5.2, Kimi-K2.7 Code, MiniMax-M3（经 Baseten/Fireworks/OpenRouter/Ollama 等提供）

    评测亮点（2026-08 数据）：openrouter:z-ai/glm-5.1 总分 89% 领先；gemini-3.6-flash 文件操作和检索满分但记忆偏弱；各模型在 Memory/Conversation 维度普遍偏低——长会话场景建议实测。

    3.3 配置模型参数¶

    两种传法：

    方式一：直接传模型字符串（用默认参数）

    agent = create_deep_agent(model="google_genai:gemini-3.6-flash")

    方式二：传配置好的模型实例（完全控制参数）

    from langchain.chat_models import init_chat_model
from deepagents import create_deep_agent

model = init_chat_model(
    model="google_genai:gemini-3.6-flash",
    thinking_level="medium",      # 按 Provider 支持的参数传
)
agent = create_deep_agent(model=model)

    也可以直接实例化 Provider 类：

    from langchain_google_genai import ChatGoogleGenerativeAI

model = ChatGoogleGenerativeAI(
    model="gemini-3.1-pro-preview",
    thinking_level="medium",
)
agent = create_deep_agent(model=model)

    可用参数因 Provider 而异，查 chat model integrations 页面。

    3.4 Provider profiles（集中配置默认参数）¶

    ProviderProfile 把初始化参数打包注册，之后传 provider:model 字符串时自动应用（注意：传预配置好的模型实例时不应用）。

    支持两级注册，可以共存：

    • Provider 级：裸 key 如 "openai"，对该 Provider 的所有模型生效
    • 模型级："openai:gpt-5.5"，只对该模型生效，并合并在 Provider 级之上
    from deepagents import ProviderProfile, register_provider_profile

# Provider-wide default: every openai model gets temperature=0.
register_provider_profile(
    "openai",
    ProviderProfile(init_kwargs={"temperature": 0}),
)

# Model-level override: gpt-5.5 additionally gets a specific reasoning effort.
# Inherits temperature=0 from the provider-level profile above.
register_provider_profile(
    "openai:gpt-5.5",
    ProviderProfile(init_kwargs={"reasoning_effort": "medium"}),
)

    ProviderProfile 控制的是模型怎么初始化；想控制Agent 行为（系统提示、工具裁剪等），用 harness profile → 第 11 章。

    3.5 运行时切换模型¶

    让终端用户在 UI 里选模型（比如下拉框），不必重建 Agent——用 wrap_model_call 中间件在每次调用时覆盖模型：

    from dataclasses import dataclass
from typing import Callable

from langchain.agents.middleware import ModelRequest, ModelResponse, wrap_model_call
from langchain.chat_models import init_chat_model
from deepagents import create_deep_agent


@dataclass
class Context:
    model: str


@wrap_model_call
def configurable_model(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    model_name = request.runtime.context.model
    model = init_chat_model(model_name)
    return handler(request.override(model=model))


agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    middleware=[configurable_model],
    context_schema=Context,
)

# Invoke with the user's model selection
result = agent.invoke(
    {"messages": [{"role": "user", "content": "Hello!"}]},
    context=Context(model="openai:gpt-5.5"),
)

    更动态的模式（按对话复杂度路由、成本优化等）见 LangChain 文档的 Dynamic model selection。

    3.6 最佳实践¶

    1. 开发用便宜快的模型，关键任务换强模型：gemini-3.x-flash / gpt-5.x 级别做日常任务；长链路复杂任务用 opus 级或评测高分的开源模型
    2. 先跑官方 eval suite 再选型：File Ops / Retrieval / Tool Use 三项是 Deep Agent 的基本盘，分数低的模型会在文件操作上频繁出错
    3. 用 ProviderProfile 统一管理参数：避免在每个 create_deep_agent 调用点重复传参
    4. LangSmith Gateway：多 Provider 统一网关，支持自带 key 或 Gateway Credits，省去管理各家 key

    3.7 本章小结¶

    关键要点¶

    主题 一句话
    模型字符串 provider:model 格式，经 init_chat_model 解析
    调参数 传 init_chat_model / Provider 类实例
    集中默认值 register_provider_profile，Provider 级 + 模型级合并
    运行时切换 wrap_model_call 中间件 + runtime context
    选型依据 官方 eval suite + 自己场景实测
