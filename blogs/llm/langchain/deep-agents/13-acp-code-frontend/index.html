    第十三章：Deep Agents Code、ACP 与前端¶

    dcode 终端编码代理 | Agent Client Protocol（编辑器集成）| 前端 UI 模式 依据官方文档 /oss/deepagents/code/overview、/acp、/frontend/overview 整理

    13.1 Deep Agents Code (dcode)¶

    ⚠️ 早期版本的 deepagents CLI 已被 Deep Agents Code 取代，官方文档不再收录旧 CLI。

    Deep Agents Code (dcode) 是基于 Deep Agents SDK 构建的开源终端编码代理（类似 Claude Code / Codex CLI 的定位）：

    • 支持任意 LLM，可随时切换 Provider/模型
    • 持久记忆跨会话保留上下文
    • 可定制技能塑造行为
    • 审批控制把关代码执行

    安装与启动¶

    curl -LsSf https://langch.in/dcode | bash
dcode

    核心能力¶

    能力 说明
    Remote sandboxes --sandbox flag：工具在远程沙箱执行而非本机（--sandbox-id、--sandbox-setup）
    Goals and rubrics 定义可衡量的目标/评分标准，Agent 自查工作是否完成（对应第 11 章 Rubric）
    Subagents 委派任务给专用子代理并行执行
    Memory 跨会话存取信息：项目约定、学到的模式
    Context compaction 摘要旧消息、原文卸载到存储
    Human-in-the-loop 敏感工具操作需人工批准
    Skills 自定义专长和指令扩展能力
    MCP tools 从 MCP 服务器加载外部工具
    Tracing LangSmith 追踪 Agent 运行

    配置走 config.toml + 环境变量 + hooks + CLI flags（详见官方 Deep Agents Code 文档的 Configuration 页）。

    13.2 Agent Client Protocol (ACP)¶

    ACP 标准化编码代理与编辑器/IDE 之间的通信。通过 ACP，你的自定义 deep agent 可以接入任何 ACP 兼容客户端——编辑器提供项目上下文、接收富更新。

    📌 区分：ACP 管 agent ↔ 编辑器；MCP（第 4 章）管 agent ↔ 工具服务器。

    快速开始¶

    pip install deepagents-acp

    把 deep agent 暴露为 ACP server（stdio 模式：stdin 读请求、stdout 写响应；实际由 ACP 客户端如编辑器来启动这个进程）：

    import asyncio

from acp import run_agent
from deepagents import create_deep_agent
from langgraph.checkpoint.memory import MemorySaver

from deepagents_acp.server import AgentServerACP


async def main() -> None:
    agent = create_deep_agent(
        model="anthropic:claude-sonnet-4-6",
        # You can customize your deep agent here: set a custom prompt,
        # add your own tools, attach middleware, or compose subagents.
        system_prompt="You are a helpful coding assistant",
        checkpointer=MemorySaver(),
    )

    server = AgentServerACP(agent)
    await run_agent(server)

if __name__ == "__main__":
    asyncio.run(main())

    deepagents-acp 包里有开箱即用的示例编码代理（带文件系统和 shell）：libs/acp/examples/demo_agent.py。

    支持的客户端¶

    • Zed（官方 demo：clone deepagents 仓库 → libs/acp/run_demo_agent.sh 注册到 Zed settings.json 的 agent_servers）
    • JetBrains IDEs（AI Assistant 支持 ACP）
    • VS Code（via vscode-acp 插件）
    • Neovim（via ACP 兼容插件）
    • 本地开发可用 Toad 管理 ACP 进程：toad acp "python your_server.py" .

    13.3 前端 (Frontend)¶

    Deep Agents 的前端模式聚焦让委派可见：不是显示一个不透明的助手气泡，而是把协调者、子代理发现过程、自定义状态、沙箱产物都暴露给用户检视。

    架构¶

    Coordinator-worker 架构映射到前端：主 Agent 消息在 root stream，子代理通过 discovery snapshot 提供 scoped 视图。

    前端用 v1 SDK（@langchain/react 等，也有 Vue/Svelte/Angular 版本），核心是 useStream hook：

    import { useStream } from "@langchain/react";

function App() {
  const stream = useStream<typeof agent>({
    apiUrl: "http://localhost:2024",
    assistantId: "agent",
  });

  // Deep agent state beyond messages
  const todos = stream.values?.todos;
  const subagents = [...stream.subagents.values()];
}

    SDK 暴露的投影¶

    投影 用途
    stream.messages 协调者对话和最终综合
    stream.subagents 实时发现专业 worker：状态、任务元数据
    stream.values 共享状态：todos、计划、报告章节、沙箱元数据、Agent 写入的任意自定义 key
    工具调用状态 把文件系统/搜索/浏览器/领域工具渲染成带进度和结果的卡片
    Interrupts 暂停委派工作等待用户批准/补充输入，不丢运行状态

    官方 UI 模式¶

    模式 内容
    Subagent streaming 专业子代理的流式内容、进度追踪、可折叠卡片
    Todo list Agent opt-in 任务规划后，实时 todo 进度条（todos 来自 stream.values.todos）
    Sandbox IDE 风格 UI：文件浏览器、代码查看器、diff 面板，后端是沙箱

    LangChain 通用前端模式（markdown 消息、工具调用渲染、HITL UI）同样适用于 deep agents——同一个 LangGraph 运行时，useStream API 一致。

    13.4 本章小结¶

    关键要点¶

    1. dcode = 官方终端编码代理，取代旧 deepagents CLI；内置沙箱/记忆/技能/审批
    2. ACP 把任意自定义 deep agent 接入 Zed/JetBrains/VS Code/Neovim；与 MCP 职责不同（编辑器集成 vs 工具接入）
    3. 前端核心是 useStream + stream.subagents + stream.values，目标是让委派过程可见（任务板/工作流监控风格，而非纯聊天）
