    第一章：概述与核心概念¶

    Deep Agents 的设计哲学、agent harness 架构和四大能力组件 依据官方文档 https://docs.langchain.com/oss/python/deepagents/overview 整理（2026-08，deepagents v0.7）

    1.1 什么是 Deep Agents？¶

    Deep Agents 是 LangChain 团队推出的开源 agent harness（代理运行框架）：一个"开箱即用"的 Agent 构建工具，在标准的工具调用循环之上，内置了让 Agent 能可靠完成复杂、长时程任务的关键能力。

    官方一句话定位：

    Build agents that can plan, use subagents, and leverage file systems for complex tasks. 构建能规划、能派生子代理、能利用文件系统的 Agent，以完成复杂任务。

    设计哲学¶

    Deep Agents 面向的是"深度工作"类任务：普通 chatbot 是"一问一答"，而 Deep Agent 要能独立完成需要多步骤、长时间、大量中间状态的任务。这带来四个核心设计决策：

    ┌─────────────────────────────────────────────────────────────┐
│                  Deep Agents 设计哲学                        │
├─────────────────────────────────────────────────────────────┤
│  📁 虚拟文件系统是第一公民                                      │
│     长任务产生大量中间产物（研究笔记、草稿、数据），            │
│     不能全塞进上下文窗口，要落盘管理                           │
│                                                             │
│  🤖 子代理隔离上下文                                          │
│     重活外包给子代理，只把最终结果带回主上下文，                │
│     防止主上下文被撑爆                                        │
│                                                             │
│  🧠 主动管理上下文                                            │
│     自动摘要历史、卸载大结果、渐进式加载技能                   │
│                                                             │
│  🔌 模型与基础设施解耦                                        │
│     任意 LLM Provider × 任意后端（本地/沙箱/远程）             │
└─────────────────────────────────────────────────────────────┘

    技术栈定位：框架、运行时、Harness¶

    理解 Deep Agents 前，先分清 LangChain 生态的三个层次：

    层次 项目 职责
    框架 (Framework) LangChain 提供 Agent 核心构建块：模型抽象、工具、中间件、create_agent
    运行时 (Runtime) LangGraph 提供持久化执行引擎：状态检查点、流式输出、human-in-the-loop
    Harness（运行框架） Deep Agents 站在前两者之上的"全家桶"：文件系统、子代理、记忆、技能都装配好 
    ┌──────────────────────────────────────────┐
│  Deep Agents (harness)                   │
│  create_deep_agent：文件系统+子代理+记忆   │
├──────────────────────────────────────────┤
│  LangGraph (runtime)                     │
│  持久化执行 / 流式 / 中断恢复 / 检查点     │
├──────────────────────────────────────────┤
│  LangChain (framework)                   │
│  模型抽象 / 工具 / 中间件 / create_agent   │
└──────────────────────────────────────────┘

    deepagents 是独立的 PyPI 包，构建在 LangChain 核心组件之上，使用 LangGraph 运行时获得持久化执行、流式输出、human-in-the-loop 等能力。如果你要的是不带这些内置能力的自定义 Agent，可以直接用 LangChain 的 create_agent 或裸 LangGraph 工作流。

    最小示例¶

    from deepagents import create_deep_agent

def get_weather(city: str) -> str:
    """Get weather for a given city."""
    return f"It's always sunny in {city}!"

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",   # provider:model 格式
    tools=[get_weather],
    system_prompt="You are a helpful assistant",
)

# Run the agent
agent.invoke(
    {"messages": [{"role": "user", "content": "what is the weather in sf"}]}
)

    model 参数接受 provider:model 格式字符串（底层通过 init_chat_model 解析），也接受已配置好的模型实例。详见第三章。

    1.2 四大能力组件¶

    Deep Agents 把内置能力组织为四个组件，这也是官方文档的导航结构：

    ┌────────────────────────────────────────────────────────────┐
│                     Deep Agents Harness                     │
├──────────────┬──────────────┬─────────────┬────────────────┤
│ 执行环境      │ 上下文管理    │ 委派        │ 引导           │
│ Execution    │ Context      │ Delegation  │ Steering       │
├──────────────┼──────────────┼─────────────┼────────────────┤
│ 工具 + MCP   │ 技能 Skills  │ 任务规划    │ Human-in-      │
│ 虚拟文件系统  │ 记忆 Memory  │ (todos)     │ the-loop       │
│ 文件系统权限  │ 摘要/卸载    │ 子代理      │ (interrupt_on) │
│ 代码执行      │ Prompt 缓存  │ 异步子代理  │                │
│ 流式事件      │ 检索 RAG     │             │                │
└──────────────┴──────────────┴─────────────┴────────────────┘

    ① 执行环境 (Execution environment)¶

    Agent 行动的场所，分四层：

    层 说明 详见
    工具 (Tools) 自定义函数、LangChain 工具、任意 MCP 服务器的工具，通过 tools= 传入 第 4 章
    虚拟文件系统 ls/read_file/write_file/edit_file/delete/glob/grep 等内置文件工具，后端可插拔（内存/本地磁盘/LangGraph Store/组合后端） 第 5 章
    文件系统权限 声明式 read/write 规则，first-match-wins，限制 Agent 可访问的路径 第 6 章
    代码执行 沙箱后端提供 execute shell 工具；解释器（Beta）提供 QuickJS eval 工具 第 5、6 章

    流式 (Streaming) 贯穿执行环境：类型化事件流覆盖消息、工具调用、值和委派任务，stream.subagents 让每个子任务都有独立的流句柄。

    ② 上下文管理 (Context management)¶

    控制 Agent 知道什么、能运行多久、跨会话记住什么：

    层 说明 详见
    技能 (Skills) 按需渐进加载的领域知识，遵循 Agent Skills 标准（SKILL.md） 第 7 章
    记忆 (Memory) 启动时加载的持久指令/偏好（AGENTS.md 文件），Agent 也能主动更新记忆 第 8 章
    摘要与上下文卸载 自动压缩对话历史和大型工具结果，支撑超出单个上下文窗口的任务 第 9 章
    Prompt 缓存 Anthropic/Bedrock 模型默认对静态提示段启用缓存，降低延迟和成本 第 9 章
    检索 (Retrieval) 内置 RAG 支持 第 9 章

    ③ 委派 (Delegation)¶

    把大问题拆成可并行的小单元：

    层 说明 详见
    任务规划 可选的 write_todos 工具（v0.7 起需显式传入 TodoListMiddleware），结构化任务列表 第 10 章
    子代理 内置 task 工具动态创建临时子代理：独立上下文、自主执行、单次交接结果 第 10 章
    异步子代理 通过部署 URL 派生远程异步子代理 第 10 章

    ④ 引导 (Steering)¶

    运行时的人类控制层：

    • Human-in-the-loop：interrupt_on 参数接入 LangGraph 中断机制，敏感工具调用前暂停等待批准（可批准、补充指导、修改参数）。
    • 详见第 11 章（连同 Profiles、Grading rubrics）。

    内置能力速查¶

    Deep Agents 宣称的核心价值：

    • 在环境中行动：调用工具、读写文件、执行代码
    • 连接你的数据：在正确的时机加载记忆、技能、领域知识
    • 管理增长的上下文：长任务中摘要历史、卸载大结果
    • 并行化任务：委派给通用或专用子代理（隔离上下文窗口）
    • 人类保持在环中：关键决策点暂停等待批准
    • 随时间改进：根据真实使用情况更新记忆、技能和提示

    1.3 虚拟文件系统：一切的地基¶

    文件系统是 Deep Agents 区别于普通 Agent 框架的最核心设计，值得单独提前了解。

    harness 提供一个可配置的虚拟文件系统，由可插拔后端支撑：

    后端 存储位置 典型用途
    StateBackend Agent 状态（内存，随 thread 持久化） 默认；测试、轻量任务
    FilesystemBackend 本地磁盘 本地 CLI、代码助手
    LocalShellBackend 本地磁盘 + shell 需要真实命令执行
    StoreBackend LangGraph Store 跨会话/跨用户长期记忆
    CompositeBackend 路由组合 按路径前缀分发到不同后端
    沙箱后端 远程容器 隔离执行不可信代码（第 5 章）

    后端支撑的文件操作（内置工具）：

    工具 说明
    ls 列目录（含大小、修改时间元数据）
    read_file 读文件，带行号，支持 offset/limit 分页；支持多模态内容（图片/视频/音频/文档）
    write_file 新建或覆盖文件（v0.7 起覆盖不再报错）
    edit_file 精确字符串替换（支持全局替换模式）
    delete 删除文件或递归删除目录（需 deepagents>=0.7；后端不支持时自动隐藏该工具）
    glob 按模式查找文件（如 **/*.py）
    grep 内容搜索，多种输出模式（仅文件名/带上下文/计数）
    execute 在环境中执行 shell 命令（仅沙箱后端提供）

    文件系统不只是给模型读写数据用的——技能、记忆、代码执行、上下文管理等能力都构建在它之上。

    ⚠️ v0.7 注意：不要试图通过 excluded_middleware 移除 FilesystemMiddleware——它是默认中间件栈的必需脚手架，移除会被显式拒绝。要隐藏文件工具，用 harness profile 的 excluded_tools 或 FilesystemMiddleware(tools=[...]) allowlist（见第 11、12 章）。

    1.4 适用场景¶

    ✅ 适合 Deep Agents 的场景¶

    场景 依赖的能力
    深度研究 搜索工具 + 文件系统存中间笔记 + 子代理并行调研
    代码助手/软件工程 沙箱执行 + 文件编辑 + 技能
    长文档写作 文件系统多稿迭代 + 记忆存风格偏好
    数据分析流水线 代码执行 + 大结果卸载
    多步骤报告生成 任务规划 (todos) + 子代理分工

    ❌ 不适合的场景¶

    • 简单问答/单轮任务：普通 create_agent 甚至直接 API 调用即可，Deep Agents 的文件系统/中间件栈是多余开销
    • 需要完全定制控制流：直接用 LangGraph 写状态机
    • 对延迟极度敏感的实时场景：harness 的系统提示和工具栈有固定 token 开销（v0.7 已把默认单轮输入 token 降了 65%，但仍有成本）

    1.5 与 Claude Agent SDK 的对比¶

    官方提供了与 Anthropic Claude Agent SDK 的对比（两者都是 harness），核心差异：

    维度 Deep Agents Claude Agent SDK
    运行位置 沙箱内，或沙箱外远程执行命令 沙箱内
    执行后端 可插拔：本地/虚拟文件系统/远程沙箱/自定义 沙箱本地文件系统
    模型 任意 Provider（100+） Claude 系（Anthropic/Bedrock/Vertex/Azure）
    部署 Managed Deep Agents（托管）或 langgraph build 自托管镜像，同一份代码 自托管（自建服务器/认证/流式层）
    多租户 内置：scoped threads、按用户沙箱、RBAC 自建
    许可证 MIT MIT（Claude Code 本体闭源）

    选型一句话：要模型和基础设施灵活性、要内置多租户部署 → Deep Agents；已深度绑定 Anthropic 生态且愿意自建服务层 → Claude Agent SDK。

    1.6 版本与重要变更（v0.7，2026-07-24）¶

    本教程基于 deepagents v0.7。从旧版本迁移时的关键变更：

    变更 影响
    任务规划改为 opt-in write_todos 工具和 todos 状态不再默认存在，需显式传 TodoListMiddleware()（OpenAI Codex profile 除外）
    Lean prompts 基础提示默认为空、工具描述精简，默认单轮输入 token 降 65%
    新增 delete 工具；write_file 改为覆盖语义 文件工具行为变化
    FilesystemMiddleware 支持 tools allowlist 可只暴露部分文件工具
    移除后端兼容层 BackendFactory 等符号删除，必须传具体 BackendProtocol 实例；StoreBackend 需显式 namespace
    middleware 覆盖语义 传入 .name 匹配内置中间件的实例会原位替换默认实例（如自定义 SummarizationMiddleware 的触发阈值）

    1.8 本章小结¶

    关键要点¶

    1. Deep Agents = agent harness：在 LangChain（框架）+ LangGraph（运行时）之上，装配好文件系统、子代理、记忆、技能的"全家桶"
    2. 四大能力组件：执行环境 / 上下文管理 / 委派 / 引导
    3. 虚拟文件系统是地基：技能、记忆、代码执行、上下文管理都构建其上
    4. 模型与基础设施解耦：任意 LLM × 任意后端 × 托管或自托管
    5. v0.7 关键变化：任务规划 opt-in、精简提示、后端 API 收紧
