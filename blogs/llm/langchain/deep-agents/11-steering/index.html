    第十一章：引导 (Steering)¶

    Human-in-the-loop 中断 | Harness Profiles | Grading Rubrics (Beta) 依据官方文档 human-in-the-loop / profiles / rubric 整理

    11.1 Human-in-the-loop（人工审批）¶

    敏感工具操作（删文件、发邮件、花钱的 API）执行前暂停，等人类批准。Deep Agents 通过 LangGraph 的 interrupt 能力实现，用 interrupt_on 参数配置。

    Agent → 有 interrupt？ ── 否 → 执行
              │ 是
              ↓
            人类审查
        ┌──────┼──────┬────────┐
     approve  edit  reject  respond
        ↓      ↓      ↓        ↓
      执行   改参数  返回拒绝   返回回应
              后执行  ToolMessage

    设置 interrupt_on 时自动加入 HumanInTheLoopMiddleware。运行在工具返回前被取消/中断的话，PatchToolCallsMiddleware 会自动修复消息历史。

    ⚠️ HITL 必须有 checkpointer——中断要保存状态才能恢复。

    基本配置¶

    interrupt_on 是「工具名 → 中断配置」的字典：

    • True：启用中断，默认行为（允许 approve / edit / reject / respond）
    • False：该工具不中断
    • InterruptOnConfig：自定义。allowed_decisions 控制可选的审查动作；Python 里还可加 when 谓词做条件中断
    from langchain.tools import tool
from deepagents import create_deep_agent
from langgraph.checkpoint.memory import MemorySaver


@tool
def remove_file(path: str) -> str:
    """Delete a file from the filesystem."""
    return f"Deleted {path}"


@tool
def notify_email(to: str, subject: str, body: str) -> str:
    """Send an email."""
    return f"Sent email to {to}"


# Checkpointer is REQUIRED for human-in-the-loop
checkpointer = MemorySaver()

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    tools=[remove_file, notify_email],
    interrupt_on={
        "remove_file": True,  # Default: approve, edit, reject, respond
        "notify_email": {"allowed_decisions": ["approve", "reject"]},  # No editing
    },
    checkpointer=checkpointer,  # Required!
)

    决策类型设计¶

    按风险分级配置：

    风险级别 配置 审查者能做什么
    敏感操作 True 批准 / 编辑参数 / 拒绝 / 回应（全部）
    中等风险 {"allowed_decisions": ["approve", "reject"]} 只能批准或拒绝
    必须批准 {"allowed_decisions": ["approve"]} 无拒绝选项

    处理中断（恢复流程）¶

    config = {"configurable": {"thread_id": "1"}}  # thread_id for state persistence
result = agent.invoke({"messages": [{"role": "user", "content": "Delete temp.txt"}]}, config)

# Check if execution was interrupted
if result.get("__interrupt__"):
    interrupt_info = result["__interrupt__"][0]
    # Extract pending action requests, display to user, collect decisions...
    # Resume:
    result = agent.invoke(
        {"__interrupt__": [{"type": "response", "args": ..., "id": action_request_id}]},
        config,
    )

    要点：

    • 每个 action_request 对应一个待审工具调用，按顺序给出决策
    • 用 thread_id 保持状态连续
    • permissions 的 mode="interrupt" 规则（第 6 章）与 interrupt_on 合并，恢复方式相同

    条件中断¶

    InterruptOnConfig 可加 when 谓词，只对特定调用中断（如"只在删除 .env 文件时"），避免审批疲劳。

    11.2 Profiles（Beta）¶

    Profiles 是按 Provider/模型打包默认配置的系统，分两种：Harness profile（调 Agent 行为）和 Provider profile（调模型构造参数，见第 3 章）。

    Harness profiles¶

    当你选择某个 Provider 或具体模型时，Deep Agents 自动应用的配置包：系统提示调整、工具描述覆盖、排除工具/中间件、追加中间件、general-purpose 子代理修改。不改 create_deep_agent 调用点就能按模型调 harness 行为。

    Deep Agents 自带 OpenAI 和 Anthropic (Claude) 的内置 harness profile（如 Codex profile 自动开启 todos）。

    from deepagents import (
    GeneralPurposeSubagentProfile,
    HarnessProfile,
    register_harness_profile,
)

register_harness_profile(
    "openai:gpt-5.5",
    HarnessProfile(
        system_prompt_suffix="Respond in under 100 words.",
        excluded_tools={"execute"},
        excluded_middleware={"SummarizationMiddleware"},
        general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False),
    ),
)

    HarnessProfile 字段：

    字段 说明
    base_system_prompt 替换 Deep Agents 基础系统提示
    system_prompt_suffix 追加到组装后提示的最末尾（主 Agent + 声明式子代理 + GP 子代理都生效）
    tool_description_overrides 按工具名覆盖工具描述
    excluded_tools 从工具集移除指定工具（按名称匹配，post-injection 过滤，能同时去掉用户工具和 harness 注入的工具）
    excluded_middleware 从栈中剥离中间件（类或字符串名）
    extra_middleware 给所有应用该 profile 的栈追加中间件
    general_purpose_subagent 禁用/改名/改提示 GP 子代理

    注册 key：

    • Provider 级：裸名如 "openai" → 该 Provider 所有模型
    • 模型级："openai:gpt-5.5" → 仅该模型
    • 两者共存时合并：模型级未设置的字段继承 Provider 级，显式设置则覆盖
    • 同 key 重复注册是合并叠加，不是替换

    硬性限制：

    • 没有通配符 key——想全局生效就在每个 Provider key 下都注册（全局调整应该放在 create_deep_agent 调用点）
    • excluded_middleware 里列 FilesystemMiddleware、SubAgentMiddleware、内部权限中间件会抛 ValueError（必需脚手架）。想藏它们的工具用 excluded_tools
    • 传预配置模型实例时，按「精确 provider:identifier → identifier-only → provider-only」顺序查 profile

    从配置文件加载 / 插件分发¶

    Profile 可以用 YAML/JSON 文件定义（HarnessProfileConfig）加载保存，也可以打包成插件分发——给开源模型做适配时尤其有用（内置 Nemotron profile 就是这么来的）。

    11.3 Grading Rubrics（Beta）¶

    需 deepagents>=0.6.5，API 可能变化。

    有些任务有明确的"完成"定义，但模型一次做不对：音节正确的俳句、测试全过的重构、章节齐全的报告。RubricMiddleware 让你声明评分标准（rubric），Agent 自我评估并迭代直到满足或达到迭代上限。

    这是运行时的 LLM-as-a-judge：Agent 产出后，专门的 grader 模型按 rubric 审查并给出裁决；needs_revision 时把逐条反馈注入对话让 Agent 重跑。

    用户带 rubric 调用 → Deep Agent 产出 → Grader 裁决
    ↑                                    │
    │ needs_revision（注入逐条反馈）       ├── satisfied / failed / grader_error → 结束
    └──── 迭代次数 < max_iterations ──────┘

    终止条件：satisfied / max_iterations_reached / failed / grader_error。

    配置¶

    from deepagents import RubricMiddleware, create_deep_agent
from langgraph.checkpoint.memory import InMemorySaver

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    middleware=[
        RubricMiddleware(
            model="anthropic:claude-haiku-4-5",   # grader 模型（可用便宜的）
            max_iterations=3,
        ),
    ],
    checkpointer=InMemorySaver(),
)

    传入 rubric¶

    rubric 可以在调用时传入（同一 Agent 服务不同任务的不同标准），也可以持久化。每次迭代可以观察进度（grader pass events）。

    典型用例：生成受审校的代码——"代码必须通过这 3 个测试用例"作为 rubric，Agent 反复跑测试、修复，直到通过或迭代耗尽。

    11.4 本章小结¶

    关键要点¶

    1. HITL：interrupt_on + checkpointer（必需）；按风险分级配 allowed_decisions；permissions 的 interrupt 模式走同一套恢复流程
    2. Harness profile：按 provider/model 打包行为调整（提示后缀、工具裁剪、中间件增删、GP 子代理开关）；模型级合并覆盖 Provider 级
    3. 三大必需中间件（Filesystem/SubAgent/权限）不可排除，只能藏工具
    4. Rubric：运行时 LLM-as-a-judge 迭代直到满足标准；grader 用便宜模型
