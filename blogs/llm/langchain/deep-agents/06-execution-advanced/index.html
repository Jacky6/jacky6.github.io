    第六章：执行环境进阶¶

    文件系统权限 | 多模态 | Interpreters (Beta) | 流式与事件流 依据官方文档 permissions / multimodal / interpreters / streaming / event-streaming 整理

    6.1 文件系统权限 (Permissions)¶

    用声明式规则控制 Agent 能读写哪些路径，通过 permissions= 传入（需 deepagents>=0.5.2）。

    规则结构¶

    每条 FilesystemPermission 三个字段：

    字段 类型 说明
    operations ["read"] 和/或 ["write"] read 覆盖 ls/read_file/glob/grep；write 覆盖 write_file/edit_file/delete
    paths glob 模式列表 如 ["/workspace/**"]，支持 ** 递归和 {a,b} 选择
    mode allow / deny / interrupt 允许、拒绝、或暂停等人工批准（interrupt 需 deepagents>=0.6.8）

    评估语义：按声明顺序，first-match-wins；没有规则匹配时默认放行（宽松默认）。

    基本用法¶

    from deepagents import FilesystemPermission, create_deep_agent

# Read-only agent: deny all writes
agent = create_deep_agent(
    model=model,
    backend=backend,
    permissions=[
        FilesystemPermission(
            operations=["write"],
            paths=["/**"],
            mode="deny",
        ),
    ],
)

    常见配方¶

    隔离到工作区目录（只允许读写 /workspace/）：

    permissions=[
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/**"], mode="allow"),
    FilesystemPermission(operations=["read", "write"], paths=["/**"], mode="deny"),
]

    保护特定文件（.env 和 examples 目录碰不得）：

    permissions=[
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/.env", "/workspace/examples/**"], mode="deny"),
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/**"], mode="allow"),
    FilesystemPermission(operations=["read", "write"], paths=["/**"], mode="deny"),
]

    只读记忆（Agent 可读记忆但不能改——组织级策略、共享知识库）：

    permissions=[
    FilesystemPermission(operations=["write"], paths=["/memories/**", "/policies/**"], mode="deny"),
]

    规则顺序是坑¶

    first-match-wins 意味着具体规则必须放在宽泛规则前面：

    # Correct: deny .env, allow workspace, deny everything else
correct = [
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/.env"], mode="deny"),
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/**"], mode="allow"),
    FilesystemPermission(operations=["read", "write"], paths=["/**"], mode="deny"),
]

# Bug: /workspace/** matches .env first, so the deny never triggers
incorrect = [
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/**"], mode="allow"),
    FilesystemPermission(operations=["read", "write"], paths=["/workspace/.env"], mode="deny"),  # never reached
    ...
]

    interrupt 模式（写操作前暂停审批）¶

    mode="interrupt" 不直接允许/拒绝，而是触发 human-in-the-loop 中断，审查者可以批准、编辑或拒绝该调用：

    from langgraph.checkpoint.memory import InMemorySaver

agent = create_deep_agent(
    model=model,
    permissions=[
        # Pause for approval before writing anything under /secrets.
        FilesystemPermission(operations=["write"], paths=["/secrets/**"], mode="interrupt"),
    ],
    # Interrupt mode requires a checkpointer to pause and resume.
    checkpointer=InMemorySaver(),
)

    interrupt 规则自动接入 HITL 中间件，和你显式传的 interrupt_on 合并处理。

    细节注意：

    • delete 目录是 all-or-nothing：目标及所有后代路径都要有 write 权限，任何一处被拒就整体拒绝
    • interrupt 模式建议用字面前缀锚定（/secrets/**）；/**/secrets 这种无锚定模式在批量工具（ls/glob/grep/目录 delete）上会保守地过度触发

    子代理与权限¶

    子代理默认继承父 Agent 权限。给子代理不同的权限：在子代理 spec 里设 permissions 字段——它会完全替换父级规则（不是合并）：

    subagents=[
    {
        "name": "auditor",
        "description": "Read-only code reviewer",
        "system_prompt": "Review the code for issues.",
        "permissions": [
            FilesystemPermission(operations=["write"], paths=["/**"], mode="deny"),
            FilesystemPermission(operations=["read"], paths=["/workspace/**"], mode="allow"),
            FilesystemPermission(operations=["read"], paths=["/**"], mode="deny"),
        ],
    }
]

    边界与限制¶

    • 权限只管内置文件工具；自定义工具和 MCP 工具不受约束（需要时用 backend policy hooks：限流、审计日志、内容检查）
    • 不适用于沙箱后端（execute 能跑任意命令，路径规则拦不住）
    • CompositeBackend + 沙箱默认后端时：权限路径必须落在已知 route 前缀下，否则抛 NotImplementedError（因为沙箱默认路由上的路径权限无意义）

    6.2 多模态 (Multimodality)¶

    前提：模型要支持多模态输入/工具结果。

    多模态用户输入¶

    用标准 content block（和 LangChain chat model 一致）：

    result = agent.invoke({
    "messages": [{
        "role": "user",
        "content": [
            {"type": "text", "text": "What is in this screenshot?"},
            {"type": "image", "url": "https://example.com/screenshot.png"},
        ],
    }],
})

    read_file 读多模态文件¶

    内置 read_file 对支持的多模态文件返回 content block（而非纯文本），模型可以直接"看"文件：

    类型 扩展名
    图片 .png .jpg .jpeg .gif .webp .heic .heif
    视频 .mp4 .mpeg .mov .avi .flv .mpg .webm .wmv .3gpp
    音频 .wav .mp3 .aiff .aac .ogg .flac
    文档 .pdf .ppt .pptx

    多模态工具输出¶

    from langchain.tools import tool


@tool
def capture_screenshot() -> list[dict]:
    """Capture a screenshot of the current page."""
    return [
        {"type": "text", "text": "Screenshot of the current page:"},
        {"type": "image", "url": "https://example.com/page.png"},
    ]

    ⚠️ 多模态与上下文压缩的交互¶

    内置压缩机制以文本为主，多模态内容要小心：

    • Offloading 只按文本 token 计量；非文本块（含图片）保留在替换消息中不压缩
    • Summarization 把旧消息压成纯文本摘要——图片/音频/视频/文件块不会保留，模型只能看到摘要器写下的描述

    多模态密集场景的最佳实践：

    1. 媒体存后端/对象存储，消息里传路径或 URL
    2. 长会话优先引用，少用 base64 内嵌
    3. 图片密集的检查任务丢给子代理，主 Agent 只收紧凑文本结果
    4. Provider 对图片按高 token 计费时，调摘要阈值或自定义 token counter

    6.3 Interpreters（Beta）：进程内代码执行¶

    ⚠️ Beta：API 和生命周期行为可能随版本变化。需 langchain-quickjs>=0.2.0、Python ≥3.11。

    定位：Interpreter vs Sandbox¶

    Interpreter Sandbox（第 5 章）
    本质 Agent 循环内的内存中可编程工作区 对环境的代码执行
    能力 循环/分支/重试、编排工具、保存状态、决定什么返回模型 shell 命令、装依赖、测试、OS 级文件系统
    隔离 QuickJS 运行时，默认无文件系统/网络/shell/时钟访问 容器级隔离

    选型表：

    需求 用什么
    一两次简单外部调用 普通工具调用
    纯内存 JS：循环/分支/重试/数据变换 Interpreter
    从代码编排大量工具调用 Interpreter + PTC
    大量独立工作单元/多视角/递归分析 Interpreter + 动态子代理
    shell/装包/测试/OS 文件系统 Sandbox

    快速开始¶

    pip install -U "deepagents[quickjs]"

    from deepagents import create_deep_agent
from langchain_quickjs import CodeInterpreterMiddleware

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    middleware=[CodeInterpreterMiddleware()],
)

    中间件给 Agent 加一个 eval 工具：Agent 需要时写 JavaScript 调用 eval，运行时执行并只把相关结果返回模型——中间结果不进上下文。变量可以在多次 eval 之间持久（取决于 persistence mode）；捕获 console.log/warn/error，返回最后一个表达式的值。

    默认情况下解释器代码没有宿主文件系统、网络、shell、包管理器、时钟的访问权——只能计算、存状态、写 console。

    Programmatic Tool Calling (PTC)¶

    PTC 把选定的 Agent 工具以 async 函数形式暴露在解释器的全局 tools 命名空间下。模型不再"发一个调用→等结果→再决定"，而是写代码循环、重试、并行批量调用工具：

    agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    middleware=[CodeInterpreterMiddleware(ptc=["web_search"])],  # 显式 allowlist
)

    启用后 Agent 可以在解释器代码里并行搜索多个主题、合并结果后再返回模型：

    const topics = ["retrieval", "memory", "evaluation"];
const results = await Promise.all(topics.map(t => tools.web_search({query: t})));
// combine results...

    注意：

    • PTC 默认关闭，需显式 allowlist 开启
    • 子代理派发（task()）在 Agent 有子代理时默认开启，可关闭
    • ⚠️ PTC 调用走解释器桥接、不走正常工具调用路径——interrupt_on 审批对 PTC 发起的调用不生效，审批敏感工具时别把它放进 PTC allowlist

    6.4 流式 (Streaming)¶

    Deep Agents 基于 LangGraph 提供流式输出。有两套 API：

    新版：Event streaming（v0.6+，推荐，Beta）¶

    类型化投影 API：每个关注点一个独立迭代器（subagents / messages / tool calls / values），不用在 stream_mode chunk 上手动分支。用 stream_events(..., version="v3")。

    核心卖点：stream.subagents ——每个委派的 task 调用一个流句柄：

    stream = agent.stream_events(
    {"messages": [{"role": "user", "content": "Write me a haiku about the sea"}]},
    version="v3",
)

for subagent in stream.subagents:
    print(subagent.name, subagent.path, subagent.status)
    for message in subagent.messages:
        print(message.text)

    子代理流句柄字段：

    字段 说明
    name 子代理名（= task 调用里的 subagent_type）
    messages 子代理发出的消息
    tool_calls 子代理作用域内的工具调用
    subagents 嵌套子代理（可递归观察）
    values / output 值流 / 最终状态或完成信号
    path 命名空间路径
    status started / completed / failed / interrupted

    投影是轻量的：先发现子代理任务，只有访问句柄上的 messages/tool_calls 时才真正打开流。

    跟踪子代理生命周期（只关心开始/结束）：

    stream = agent.stream_events(input, version="v3")
for subagent in stream.subagents:
    print(f"{subagent.name}: started")
    try:
        _ = subagent.output
        print(f"{subagent.name}: completed")
    except Exception:
        print(f"{subagent.name}: failed")

    分层流式：顶层 stream.messages / stream.tool_calls 是主 Agent 的；subagent.messages / subagent.tool_calls 是各子代理的。

    旧版：subgraph streaming¶

    agent.stream(..., stream_mode="updates", subgraphs=True, version="v2")：子代理事件通过命名空间 (namespace) 标识来源——空 namespace 是主 Agent，非空是子代理。新应用直接用 event streaming。

    6.5 本章小结¶

    关键要点¶

    1. 权限：permissions= 声明式规则，first-match-wins，默认放行；具体规则放前面；管不了自定义工具/MCP/沙箱
    2. interrupt 模式把权限检查变成人工审批（需 checkpointer）
    3. 子代理可单独设权限（完全替换父级规则）
    4. 多模态：read_file 支持图片/视频/音频/文档；摘要压缩会丢掉媒体块——大媒体落盘传引用
    5. Interpreter：QuickJS eval 工具，进程内编排；PTC 让工具调用可循环/并行，但绕过 HITL 审批
    6. 流式：新项目用 event streaming（v3 + stream.subagents）
