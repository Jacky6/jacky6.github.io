    第七章：技能系统 (Skills)¶

    Agent Skills 标准 | progressive disclosure | SKILL.md 编写 | 后端加载与权限 依据官方文档 https://docs.langchain.com/oss/python/deepagents/skills 整理

    7.1 什么是 Skills？¶

    Skills（技能） 打包专门的工作流、领域知识和自定义指令。每个技能是一个目录，核心是 SKILL.md 文件，遵循 Agent Skills 规范（跨框架开放标准，Claude Code 等也用同一格式）。

    skills/
└── langgraph-docs/
    ├── SKILL.md              ← YAML frontmatter + 指令正文
    ├── scripts/
    │   └── fetch_docs.py     ← 可执行脚本
    ├── references/
    │   ├── api-patterns.md   ← 参考文档
    │   └── style-guide.md
    └── assets/
        ├── report-template.md ← 模板等资源
        └── schema.json

    为什么需要 Skills：Progressive Disclosure（渐进披露）¶

    Agent 任务越复杂，需要的上下文越多。把所有指令塞进系统提示 = 浪费 token 在无关信息上；每次会话手动粘贴指导 = 不可持续。

    技能用分层加载解决：

    层级 加载什么 何时
    1. 元数据 frontmatter 里的 name + description Agent 启动时，所有技能都加载
    2. 指令 完整 SKILL.md 正文 技能被激活时（read_file 读入）
    3. 资源 scripts/ references/ assets/ 下的文件 指令需要时才读 
    启动时上下文：[skill-A: 一句话描述] [skill-B: 一句话描述] [skill-C: 一句话描述]
                        ↓ 任务匹配到 skill-B
激活后上下文：+ skill-B 完整 SKILL.md
                        ↓ 指令引用了 references/api-patterns.md
执行中上下文：+ api-patterns.md（按需）

    机制实现：传了 skills 时，SkillsMiddleware（Deep Agents 默认栈的一部分）负责第 1、2 层——启动时扫描技能路径、解析 frontmatter、注入系统提示；第 3 层由 LLM 自己按指令读取。

    7.2 快速上手¶

    Step 1-2：创建技能目录和 SKILL.md

    ---
name: langgraph-docs
description: Use this skill for requests related to LangGraph in order to fetch relevant documentation to provide accurate, up-to-date guidance.
---

# langgraph-docs

## Overview

This skill explains how to access LangGraph documentation to help answer questions and guide implementation.

## Instructions

### 1. Fetch the documentation index

Use the fetch_url tool to read the following URL:
https://docs.langchain.com/llms.txt

This provides a structured list of all available documentation with descriptions.

### 2. Select relevant documentation

Based on the question, identify 2-4 most relevant documentation URLs from the index. Prioritize:

- Specific how-to guides for implementation questions
- Core concept pages for understanding questions
- Tutorials for end-to-end examples
- Reference docs for API details

### 3. Fetch and synthesize

Use the fetch_url tool to read the selected documentation URLs, then answer the user's question. Give a direct answer first, include the minimum necessary context, and link to the source pages rather than quoting long passages.

    Step 3：创建 Agent 时传 skills 路径

    from deepagents import create_deep_agent
from deepagents.backends.filesystem import FilesystemBackend

backend = FilesystemBackend(root_dir="./my-project")

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    backend=backend,
    skills=["./my-project/skills/"],
)

    skills 参数要点：

    • 路径用正斜杠，相对于后端 root
    • 省略则不加载技能
    • StateBackend（默认）时：通过 invoke(files={...}) 提供技能文件，用 deepagents.backends.utils 的 create_file_data() 格式化（不接受裸字符串）
    • FilesystemBackend 时：从磁盘 root_dir 相对路径加载
    • 同名技能：后面的 source 覆盖前面的（last wins）——可以分层：基础技能被项目特定版本覆盖

    Step 4：invoke

    result = agent.invoke(
    {"messages": [{"role": "user", "content": "What is LangGraph?"}]},
    config={"configurable": {"thread_id": "1"}},
)

    任务匹配到技能描述时，Agent 自动读取 SKILL.md 并按指令执行。

    7.3 Frontmatter 字段¶

    Agent Skills 规范定义：

    字段 必填 说明
    name ✅ 小写字母数字+连字符，1-64 字符，必须与父目录同名
    description ✅ 技能做什么、何时用。≤1024 字符
    license ❌ 许可证名称或文件引用
    compatibility ❌ 环境要求（系统包、网络访问）。≤500 字符
    metadata ❌ 任意键值对
    allowed-tools ❌ 空格分隔的预批准工具列表（实验性） 
    ---
name: langgraph-docs
description: Use this skill for requests related to LangGraph in order to fetch relevant documentation to provide accurate, up-to-date guidance.
license: MIT
compatibility: Requires internet access for fetching documentation URLs
metadata:
  author: langchain
  version: "1.0"
allowed-tools: fetch_url
---

    ⚠️ Deep Agents 中 SKILL.md 必须 <10 MB，超限的文件加载时跳过。

    7.4 什么时候用 Skills？¶

    如果你发现自己反复给 Agent 类似的指令（尤其是多步骤的详细指令），就该把它固化为技能。你甚至可以直接让 Agent 帮你把刚做过的任务写成技能。

    特别适合固化：

    • 分步工作流：跨多步的"菜谱"
    • 领域知识：告诉 Agent 工具怎么用、信息从哪来
    • 带可执行代码的指令：把流程和脚本打包，Agent 跑测试过的逻辑而不是每次重新生成
    • 守则：格式/风格指南、"必须跑测试"之类的护栏

    7.5 编写高效技能¶

    官方建议（基于 Agent Skills 规范）：

    1. frontmatter 精简，SKILL.md 正文 <5000 token：每个技能的 frontmatter 启动时都进系统提示；正文只在激活时读。两层都小，才能装很多技能不挤爆上下文
    2. description 写具体：发现阶段模型只看 name+description 决定要不要激活。"Use this skill for requests related to X in order to Y" 比 "Helps with stuff" 可靠得多
    3. ✅ 好：具体说明 what + when
    4. ❌ 差：太模糊，匹配不可靠
    5. 在 SKILL.md 里引用支撑文件时说明每个文件的内容和使用时机——Agent 通过这些引用发现文件

    7.6 后端与远程加载¶

    技能文件可以放在任何后端：

    • StateBackend：thread 内状态。适合动态注入（如从 URL 拉技能）：
    from urllib.request import urlopen
from deepagents.backends.utils import create_file_data

skill_url = "https://raw.githubusercontent.com/langchain-ai/deepagents/.../SKILL.md"
skill_content = urlopen(skill_url).read().decode("utf-8")

skills_files = {
    "/skills/langgraph-docs/SKILL.md": create_file_data(skill_content),
}

result = agent.invoke(
    {
        "messages": [{"role": "user", "content": "What is langgraph?"}],
        "files": skills_files,   # Seed StateBackend 的虚拟文件系统（路径以 / 开头）
    },
    config={"configurable": {"thread_id": "12345"}},
)
    • StoreBackend：跨 thread 持久
    • FilesystemBackend：磁盘

    7.7 运行时加载技能¶

    技能库很大、每次只用一个子集时，按运行时上下文（用户角色、租户、请求类型）选择加载：

    方式一：动态技能列表¶

    SKILLS_BY_ROLE = {
    "engineering": ["/skills/code-review/", "/skills/testing/", "/skills/deployment/"],
    "data": ["/skills/sql-analysis/", "/skills/visualization/"],
    "support": ["/skills/ticket-triage/", "/skills/runbook/"],
}

def create_agent_for_user(user_role: str):
    return create_deep_agent(
        model="anthropic:claude-sonnet-4-6",
        skills=SKILLS_BY_ROLE.get(user_role, []),
    )

    技能本身只存一份，变的只是每次传的路径。

    📌 SDK 只加载你传给 skills 的 source，不会自动扫描 ~/.deepagents/ 或 ~/.agents/ 等 CLI 目录（那是 dcode 的约定）。想在 SDK 里模拟 CLI 的分层顺序，按优先级从低到高显式传路径列表。

    方式二：Namespaced skills（多租户）¶

    把 /skills/ 路由到带 namespace factory 的 StoreBackend，每个用户/租户独立技能库：

    agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    skills=["/skills/"],
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/skills/": StoreBackend(
                namespace=lambda rt: (
                    rt.server_info.assistant_id,
                    rt.server_info.user.identity,
                ),
            ),
        },
    ),
)

    7.8 子代理的技能¶

    • General-purpose 子代理：自动继承主 Agent 的技能（传 skills 给 create_deep_agent 即可）
    • 自定义子代理：不继承，要在子代理定义里单独给 skills 参数

    技能状态完全隔离：主 Agent 的技能子代理看不到，反之亦然。

    research_subagent = {
    "name": "researcher",
    "description": "Research assistant with specialized skills",
    "system_prompt": "You are a researcher.",
    "tools": [web_search],
    "skills": ["/skills/research/", "/skills/web-search/"],  # Subagent-specific skills
}

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    skills=["/skills/main/"],        # Main agent and GP subagent get these
    subagents=[research_subagent],   # Researcher gets only its own skills
)

    7.9 技能权限（生产要点）¶

    生产部署通常要控制三件事：

    控制点 手段
    每个用户能看到哪些技能 skills 参数 + 后端路由
    Agent 能否修改技能文件 文件系统权限（第 6 章）：对 /skills/** deny write = 只读技能
    写技能是否要人工批准 interrupt_on / permissions 的 interrupt 模式

    典型配方：

    • 跨用户共享技能：/skills/ 路由到 assistant 级 namespace 的 StoreBackend，deny write
    • 个人技能可编辑：user namespace + 允许写自己的路径
    • 组织级技能只读：org namespace + FilesystemPermission(operations=["write"], paths=["/skills/**"], mode="deny")
    • 修改需审批：mode="interrupt"

    技能里执行代码¶

    技能可以带脚本（scripts/），在有 execute 能力的后端（沙箱）里运行。官方建议：脚本在沙箱里跑，注意脚本自身的注入风险。

    7.10 Skills vs Memory vs Tools¶

    三者都给 Agent 提供上下文/能力，官方对比表：

    Skills Memory Tools
    目的 按需能力，渐进披露发现 启动时加载的持久上下文 Agent 可调用的程序化动作
    加载 Agent 判断相关时才读 Agent 启动时加载 每轮都可用
    格式 命名目录里的 SKILL.md AGENTS.md 文件 绑定到 Agent 的函数
    分层 user → project（后者覆盖） user → project（合并） 创建 Agent 时定义
    用于 任务特定、可能很长的指令 总是相关的上下文（约定、偏好） 需要程序化动作，或无法访问文件系统

    这是光谱不是硬边界：Agent 可以在工作中更新自己的技能——技能因此也是一种"渐进披露式记忆"。

    7.11 故障排查¶

    问题 排查方向
    技能没被激活 description 是否具体描述了触发条件？任务是否真的匹配？
    启动时技能缺失 路径是否相对于后端 root、用正斜杠？StateBackend 是否用 create_file_data()？
    找不到支撑文件 SKILL.md 里的引用路径是否正确？文件是否在后端里？
    脚本跑不起来 后端是否支持 execute（沙箱）？
    子代理访问不到技能 自定义子代理不继承——要单独配 skills

    7.12 本章小结¶

    关键要点¶

    1. 技能 = 目录 + SKILL.md，遵循 Agent Skills 开放标准
    2. Progressive disclosure 三层：元数据（启动）→ 指令（激活）→ 资源（按需）
    3. frontmatter 的 description 决定激活可靠性；正文控制在 5000 token 内
    4. 同名技能后者优先；可按角色/租户动态选择技能列表
    5. GP 子代理继承技能，自定义子代理不继承
    6. 技能文件本身受文件系统权限管辖——生产环境注意只读/审批
