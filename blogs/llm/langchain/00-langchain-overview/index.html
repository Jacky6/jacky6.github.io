    第 00 章：LangChain 概述¶

    理解 LangChain 的定位、核心价值和生态系统

    本章目标¶

    学完本章后，你将能够：

    • ✅ 理解 LangChain 是什么以及为什么需要它
    • ✅ 区分 LangChain、Deep Agents 和 LangGraph
    • ✅ 了解 LangChain 的核心优势
    • ✅ 选择合适的框架开始构建

    0.1 什么是 LangChain？¶

    定义¶

    LangChain 是一个开源框架，提供预构建的 Agent 架构和集成，用于快速构建由大语言模型（LLM）驱动的 Agent 和应用程序。

    核心使命¶

    让开发者能够轻松构建完全定制的 Agent 和 LLM 应用

    关键特点¶

    特点 说明
    框架无关 支持 OpenAI、Anthropic、Google 等所有主流模型
    开箱即用 10 行代码即可构建功能完整的 Agent
    高度灵活 支持从简单到复杂的各种场景
    生态丰富 数百个 LLM 集成，数千个工具集成
    生产就绪 内置 LangSmith 用于追踪、调试和评估

    0.2 为什么需要 LangChain？¶

    问题：直接使用 LLM API 的痛点¶

    # ❌ 直接使用 OpenAI API 的问题

import openai

# 1. 每个 Provider API 不同，切换成本高
response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "Hello"}]
)

# 2. 需要手动管理工具调用
# 3. 需要自己实现 Agent 循环
# 4. 需要处理流式输出、错误重试、限流等
# 5. 难以追踪和调试

    解决方案：LangChain 的统一接口¶

    # ✅ 使用 LangChain

from langchain.chat_models import init_chat_model
from langchain.agents import create_agent

# 1. 统一接口，轻松切换模型
model = init_chat_model("gpt-4o")  # 或 "claude-sonnet-4-6"
#    = init_chat_model("claude-sonnet-4-6")  # 只需改这一行！

# 2. 工具自动绑定
def get_weather(city: str) -> str:
    return f"It's sunny in {city}"

# 3. Agent 循环内置
agent = create_agent(
    model=model,
    tools=[get_weather],
    system_prompt="你是 helpful assistant"
)

# 4. 流式、重试、追踪都内置
response = agent.invoke({"messages": [{"role": "user", "content": "天气如何？"}]})

    0.4 LangChain Agents 核心概念¶

    什么是 Agent？¶

    Agent = LLM + Tools + 推理循环

    Agent 能够： 1. 推理 - 分析任务，决定需要什么信息 2. 行动 - 调用工具获取信息或执行操作 3. 观察 - 从工具执行结果中学习 4. 循环 - 重复直到任务完成

    Agent 工作流程¶

    graph TD
    QUERY([用户输入]) --> LLM{LLM 思考}
    LLM -- 需要工具 --> TOOL[执行工具]
    TOOL -- 观察结果 --> LLM
    LLM -- 任务完成 --> ANSWER([输出答案])

    class QUERY,ANSWER blue;
    classDef green fill:#DCFCE7,stroke:#16A34A;
    class LLM,TOOL green;

    Agent 的核心组件¶

    from langchain.agents import create_agent

# 1. Model - 推理引擎
#    负责思考、决策、生成工具调用
model = "gpt-4o"

# 2. Tools - 执行能力
#    实际执行操作，返回结果
def get_weather(location: str) -> str:
    """获取天气信息"""
    return f"{location}: 晴，25°C"

def search_attractions(location: str) -> str:
    """搜索景点"""
    return "故宫、长城、颐和园"

# 3. System Prompt - 行为指导
#    定义 Agent 的角色和行为准则
system_prompt = """你是旅游助手。
- 先查询天气
- 再推荐景点
- 给出实用建议"""

# 4. 创建 Agent
agent = create_agent(
    model=model,
    tools=[get_weather, search_attractions],
    system_prompt=system_prompt
)

# 5. 运行 Agent
response = agent.invoke({
    "messages": [{"role": "user", "content": "我想去北京玩"}]
})

    0.5 核心优势详解¶

    1️⃣ 标准化模型接口¶

    问题：不同 Provider 的 API 不同

    # ❌ 不使用 LangChain - 每个 Provider API 不同

# OpenAI
import openai
response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[...],
    temperature=0.7
)

# Anthropic
import anthropic
client = anthropic.Client()
response = client.messages.create(
    model="claude-3",
    max_tokens=1000,
    messages=[...]
)

# Google
import google.generativeai as genai
model = genai.GenerativeModel('gemini-pro')
response = model.generate_content("...")

    解决：LangChain 统一接口

    # ✅ 使用 LangChain - 统一接口

from langchain.chat_models import init_chat_model

# 所有 Provider 使用相同接口

#   = init_chat_model("anthropic:claude-sonnet-4-6")
#   = init_chat_model("google_genai:gemini-2.0-flash")

# 统一调用方式

    复杂场景 - 完全定制

    from langchain.agents import create_agent
from langchain.agents.middleware import (
    before_model,
    after_model,
    wrap_tool_call
)
from pydantic import BaseModel

# 自定义状态
class CustomState(TypedDict):
    user_preferences: dict
    conversation_stage: str

# 自定义中间件
@before_model
def inject_context(state, runtime):
    # 注入用户偏好
    prefs = get_user_prefs(runtime.context.user_id)
    return {"user_preferences": prefs}

@wrap_tool_call
def validate_tool(request, handler):
    # 验证工具调用
    if not is_authorized(request.tool_call):
        raise PermissionError("Unauthorized")
    return handler(request)

# 结构化输出
class ResponseFormat(BaseModel):
    answer: str
    confidence: float
    sources: list[str]

# 创建高度定制的 Agent
agent = create_agent(
    model=advanced_model,
    tools=dynamic_tools,
    middleware=[inject_context, validate_tool],
    response_format=ToolStrategy(ResponseFormat),
    state_schema=CustomState
)

    3️⃣ 基于 LangGraph 构建¶

    LangChain Agents 构建在 LangGraph 之上，自动获得：

    • ✅ 持久化执行 - Agent 崩溃后可恢复
    • ✅ Human-in-the-loop - 关键步骤需要人工确认
    • ✅ 状态管理 - 自动跟踪对话历史
    • ✅ 流式输出 - 实时显示中间结果
    • ✅ 并行执行 - 同时调用多个工具
    # 持久化示例
from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string(
    "postgresql://localhost/langchain"
)

agent = create_agent(
    model=model,
    tools=tools,
    checkpointer=checkpointer  # 启用持久化
)

# 即使进程重启，对话也能继续
config = {"configurable": {"thread_id": "conversation-123"}}
response = agent.invoke({...}, config=config)

    研究助理 文献搜索和总结 学术论文、市场调研
    工作流自动化 连接多个系统 CRM、ERP 集成

    ❌ 不适合的场景¶

    场景 原因 替代方案
    简单问答 不需要工具调用 直接使用 LLM API
    确定性流程 不需要 Agent 推理 使用传统编程
    超低延迟 Agent 循环有开销 优化模型或使用缓存
    极低成本 多次调用成本高 使用小模型或缓存
