    三大组件定位分析¶

    依据官方概念页 Frameworks, runtimes, and harnesses 整理（2026-08）

    一句话定位（官网导航原文）¶

    组件 官方 slogan 角色
    langchain Quick start agents with any model provider Framework（框架）
    langgraph Build reliable agents with low-level control Runtime（运行时）
    deepagents Build long-running agents for complex tasks Harness（运行框架）

    三层架构：从低到高的抽象阶梯¶

    你要写多少代码 ←──────────────────────────→ 你拿到多少现成能力

┌─────────────────────────────────────────────────┐
│  Deep Agents (harness)                          │
│  "有主见的、开箱即用"：规划/子代理/文件系统/        │
│   token 管理全部预装，面向长时程复杂任务            │
├─────────────────────────────────────────────────┤
│  LangChain (framework)                          │
│  标准抽象：模型、工具、agent loop、middleware       │
│  快速起步，不需要懂 LangGraph 也能用               │
├─────────────────────────────────────────────────┤
│  LangGraph (runtime)                            │
│  生产级执行引擎：持久化执行/流式/HITL/状态持久化     │
│  低层控制，自己画图自己编排                         │
└─────────────────────────────────────────────────┘
依赖关系：Deep Agents 构建在 LangGraph 之上，
         LangChain 1.0 也构建在 LangGraph 之上

    关键点：LangChain 和 Deep Agents 是兄弟关系（都跑在 LangGraph 上），不是父子。LangGraph 是共同的地基。

    三者各自的价值与竞品坐标¶

    官方把每个类别都列了同类竞品，能看清定位：

    LangChain LangGraph Deep Agents
    类别 Agent Framework Agent Runtime Agent Harness
    核心价值 抽象 + 集成（100+ 模型/工具） 持久化执行、流式、HITL、持久化 预定义工具、提示、子代理
    什么时候用 快速起步；团队标准化；直接了当的 Agent 应用 需要细粒度编排控制；长时程有状态工作流；确定性+智能体混合流程 更自主的 Agent；复杂、非确定性的多步骤任务
    同类竞品 Vercel AI SDK、CrewAI、OpenAI Agents SDK、Google ADK、LlamaIndex Temporal、Inngest 等 durable execution 引擎 Claude Agent SDK、Manus、各类 coding CLI

    有意思的对比：LangGraph 的竞品不是其他 Agent 框架，而是 Temporal 这类通用持久化执行引擎——官方把它定位为"执行基础设施"而非"AI 框架"。

    功能对比：同一件事在三层怎么做¶

    官方对照表（同一个能力，集成层次不同）：

    能力 LangChain LangGraph Deep Agents
    短期记忆 short-term memory API checkpointer StateBackend（自动）
    长期记忆 long-term memory API store memory= 参数（自动）
    子代理 multi-agent subagents subgraphs（手搓） task 工具（自动）
    Human-in-the-loop HITL middleware interrupts（底层原语） interrupt_on= 一个参数
    流式 event streaming streaming（底层原语） event streaming + stream.subagents
    技能 multi-agent skills — skills=（progressive disclosure）

    规律：越往上越"声明式"——LangGraph 给你原语自己组装，LangChain 给你中等抽象，Deep Agents 直接一个参数搞定。

    选型决策树¶

    你的任务是什么？
│
├─ 需要完全自定义控制流（状态机、审批流、
│  确定性+AI 混合管线）？
│  └─→ LangGraph（裸写）
│
├─ 标准 Agent：工具调用 + 对话，想快速出活？
│  └─→ LangChain 的 create_agent
│
└─ 长时程复杂任务：深度研究、编码、
   大量中间产物、需要规划和分工？
   └─→ Deep Agents 的 create_deep_agent

    官方原话标准：

    • LangChain："straightforward agent applications without complex orchestration needs"
    • LangGraph："fine-grained, low-level control"、"combine deterministic and agentic steps"
    • Deep Agents："agents that run over long time periods"、"complex, multi-step tasks"、想要预定义的工具/提示/子代理

    补充：官网的商业版图¶

    三者都是开源（MIT），但官网主推的是商业产品 LangSmith Platform：

    开源三件套（你写的代码）
   │
   └─→ LangSmith（商业闭环）
       ├── Engine        自动改进 Agent
       ├── Observability 追踪调试
       ├── Evaluation    评测
       ├── Deployment    托管部署
       ├── Sandboxes     托管沙箱
       ├── LLM Gateway   模型调用网关
       └── Fleet         无代码 Agent（给非技术人员）

    典型路径：开源三件套开发 → LangSmith 观测/评测 → Deployment 或 Managed Deep Agents 上线。官网案例（Rippling、Klarna、Lyft）基本都是这个组合。

    对本知识库的启示¶

    学习路径上，LangGraph 是理解一切的地基（checkpointer、interrupt、store 这些概念在三层都出现），LangChain 是日常快速开发的主力，Deep Agents 是复杂任务的专用武器。三者不是替代关系，是同一个技术栈的不同高度。
