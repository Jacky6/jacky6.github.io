    第 25 章：长期记忆 - Long-term Memory¶

    本章内容：跨会话持久记忆——LangGraph Store、namespace 组织、语义搜索、工具中读写记忆

    官方文档：https://docs.langchain.com/oss/python/langchain/long-term-memory 短期记忆（thread 内）见本章同目录 01-short-term-memory.md；会话持久化见 02-session-memory.md

    📚 本章目标¶

    学完本章后，你将掌握：

    • ✅ 区分短期记忆（thread 内）和长期记忆（跨 thread）
    • ✅ 用 LangGraph Store 存储长期记忆（JSON 文档 + namespace + key）
    • ✅ 配置 InMemoryStore / PostgresStore
    • ✅ 用 IndexConfig 启用语义搜索
    • ✅ 在工具中通过 runtime.store 读写记忆
    • ✅ 结合 context_schema 实现按用户隔离的记忆

    25.1 长期记忆是什么？¶

    长期记忆让 Agent 跨不同对话和会话存储和回忆信息。

    短期记忆 长期记忆
    范围 单个 thread 内 跨 thread 持久
    机制 checkpointer（对话历史） LangGraph Store
    召回 自动（消息历史） 随时主动召回
    典型内容 当前对话上下文 用户偏好、事实档案、学到的经验

    长期记忆构建在 LangGraph stores 之上——把数据存为 JSON 文档，按 namespace（类似文件夹）和 key（类似文件名）组织。

    💡 记忆类型的 deeper dive（语义记忆 semantic、情景记忆 episodic、程序记忆 procedural）和写入策略，见官方 Memory conceptual guide。

    25.2 基本用法¶

    创建 store，传给 create_agent：

    InMemoryStore（开发）¶

    from langchain.agents import create_agent
from langchain_core.runnables import Runnable
from langgraph.store.memory import InMemoryStore

# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production use.
store = InMemoryStore()

agent: Runnable = create_agent(
    "anthropic:claude-sonnet-4-6",
    tools=[],
    store=store,
)

    PostgreSQL（生产）¶

    pip install -U langgraph-checkpoint-postgres "psycopg[binary]"

    from langchain.agents import create_agent
from langchain_core.runnables import Runnable
from langgraph.store.postgres import PostgresStore

DB_URI = "postgresql://postgres:***@localhost:5432/postgres?sslmode=disable"

with PostgresStore.from_conn_string(DB_URI) as store:
    store.setup()
    agent: Runnable = create_agent(
        "anthropic:claude-sonnet-4-6",
        tools=[],
        store=store,
    )

    📌 默认安装的 langgraph-checkpoint-postgres 带 Psycopg 3 无 extras；推荐加 psycopg[binary]。

    之后工具就能通过 runtime.store 读写 store（见 25.4、25.5）。

    25.3 记忆的存储结构¶

    每条记忆是一个 JSON 文档，组织在自定义 namespace（元组，类似文件夹路径）+ 唯一 key 下。namespace 常包含用户 ID、组织 ID 或其他标签，便于组织信息。

    这个结构支持层级化组织，跨 namespace 搜索通过内容过滤器实现。

    带语义搜索的配置（IndexConfig）¶

    给 store 配置 embedding 函数后，search 支持向量相似度排序：

    from collections.abc import Sequence

from langgraph.store.base import IndexConfig
from langgraph.store.memory import InMemoryStore


def embed(texts: Sequence[str]) -> list[list[float]]:
    # Replace with an actual embedding function or LangChain embeddings object
    return [[1.0, 2.0] for _ in texts]


# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production use.
store = InMemoryStore(index=IndexConfig(embed=embed, dims=2))
user_id = "my-user"
application_context = "chitchat"
namespace = (user_id, application_context)
store.put(
    namespace,
    "a-memory",
    {
        "rules": [
            "User likes short, direct language",
            "User only speaks English & python",
        ],
        "my-key": "my-value",
    },
)
# get the "memory" by ID
item = store.get(namespace, "a-memory")
# search for "memories" within this namespace, filtering on content equivalence, sorted by vector similarity
items = store.search(
    namespace, filter={"my-key": "my-value"}, query="language preferences"
)

    核心 API：

    方法 说明
    store.put(namespace, key, value) 写入/覆盖一条记忆
    store.get(namespace, key) 按 key 精确读取
    store.search(namespace, filter=..., query=...) namespace 内搜索：filter 按内容过滤，query 按向量相似度排序
    store.delete(namespace, key) 删除

    PostgresStore 用法相同（with PostgresStore.from_conn_string(DB_URI, index=IndexConfig(...)) as store: + store.setup()）。

    25.4 在工具中读取长期记忆¶

    工具通过 runtime.store 访问传入 create_agent 的同一个 store；配合 context_schema 拿到当前用户身份：

    from dataclasses import dataclass

from langchain.agents import create_agent
from langchain.tools import ToolRuntime, tool
from langchain_core.runnables import Runnable
from langgraph.store.memory import InMemoryStore


@dataclass
class Context:
    user_id: str


# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production.
store = InMemoryStore()

# Write sample data to the store using the put method
store.put(
    ("users",),        # Namespace to group related data together
    "user_123",        # Key within the namespace (user ID as key)
    {
        "name": "John Smith",
        "language": "English",
    },
)


@tool
def get_user_info(runtime: ToolRuntime[Context]) -> str:
    """Look up user info."""
    # Access the store - same as that provided to `create_agent`
    assert runtime.store is not None
    user_id = runtime.context.user_id
    # Retrieve data from store - returns StoreValue object with value and metadata
    user_info = runtime.store.get(("users",), user_id)
    return str(user_info.value) if user_info else "Unknown user"


agent: Runnable = create_agent(
    model="openai:gpt-5.5",
    tools=[get_user_info],
    store=store,
    context_schema=Context,
)

# Run the agent
agent.invoke(
    {"messages": [{"role": "user", "content": "What's my name?"}]},
    # user_id passed in context to identify which user's info to retrieve
    context=Context(user_id="user_123"),
)

    要点：

    • ToolRuntime[Context] 类型参数让工具拿到 runtime.store 和 runtime.context
    • runtime.context.user_id 来自调用时传入的 context=Context(...)——记忆按谁在调用隔离
    • store.get 返回 StoreValue 对象（.value 是数据，另有元数据）

    25.5 在工具中写入长期记忆¶

    让 Agent 自己更新用户信息（聊天应用常见需求）：

    from dataclasses import dataclass

from langchain.agents import create_agent
from langchain.tools import ToolRuntime, tool
from langchain_core.runnables import Runnable
from langgraph.store.memory import InMemoryStore
from typing_extensions import TypedDict

# InMemoryStore saves data to an in-memory dictionary. Use a DB-backed store in production.
store = InMemoryStore()


@dataclass
class Context:
    user_id: str


# TypedDict defines the structure of user information for the LLM
class UserInfo(TypedDict):
    name: str


# Tool that allows agent to update user information (useful for chat applications)
@tool
def save_user_info(user_info: UserInfo, runtime: ToolRuntime[Context]) -> str:
    """Save user info."""
    # Access the store - same as that provided to `create_agent`
    assert runtime.store is not None
    store = runtime.store
    user_id = runtime.context.user_id
    # Store data in the store (namespace, key, data)
    store.put(("users",), user_id, dict(user_info))
    return "Successfully saved user info."


agent: Runnable = create_agent(
    model="openai:gpt-5.5",
    tools=[save_user_info],
    store=store,
    context_schema=Context,
)

# Run the agent
agent.invoke(
    {"messages": [{"role": "user", "content": "My name is John Smith"}]},
    # user_id passed in context to identify whose information is being updated
    context=Context(user_id="user_123"),
)

# You can access the store directly to get the value
item = store.get(("users",), "user_123")

    要点：

    • 用 TypedDict 定义记忆结构——它会成为工具 schema，LLM 知道该存什么字段
    • store.put(namespace, key, value) 写入；同一 key 覆盖旧值
    • 应用代码也可以直接访问 store 验证/读取

    25.6 完整示例：记住偏好的助手¶

    综合读写，做一个跨会话记住用户偏好的助手：

    # preference_assistant.py
from dataclasses import dataclass

from langchain.agents import create_agent
from langchain.tools import ToolRuntime, tool
from langgraph.store.memory import InMemoryStore


@dataclass
class Context:
    user_id: str


store = InMemoryStore()  # 生产换 PostgresStore


@tool
def remember(fact: str, runtime: ToolRuntime[Context]) -> str:
    """Save a durable user preference or fact to long-term memory."""
    assert runtime.store is not None
    user_id = runtime.context.user_id
    # Use one key per fact so facts accumulate instead of overwriting
    import hashlib
    key = hashlib.md5(fact.encode()).hexdigest()[:12]
    runtime.store.put(("users", user_id, "facts"), key, {"fact": fact})
    return f"Remembered: {fact}"


@tool
def recall(query: str, runtime: ToolRuntime[Context]) -> str:
    """Search long-term memory for relevant facts about the user."""
    assert runtime.store is not None
    user_id = runtime.context.user_id
    items = runtime.store.search(("users", user_id, "facts"), query=query)
    if not items:
        return "No relevant memories found."
    return "\n".join(str(item.value["fact"]) for item in items)


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[remember, recall],
    store=store,
    context_schema=Context,
    system_prompt=(
        "You have long-term memory. Use `recall` at the start of tasks to "
        "check for relevant user preferences. Use `remember` when the user "
        "shares a durable preference or fact."
    ),
)

# Session 1: user shares preferences
config = {"configurable": {"thread_id": "session-1"}}
agent.invoke(
    {"messages": [{"role": "user", "content": "I prefer concise answers and Python examples"}]},
    config=config,
    context=Context(user_id="xiaozhi"),
)

# Session 2: different thread, same user — memory persists
config2 = {"configurable": {"thread_id": "session-2"}}
result = agent.invoke(
    {"messages": [{"role": "user", "content": "How do I read a CSV file?"}]},
    config=config2,
    context=Context(user_id="xiaozhi"),
)
# Agent recalls preferences and answers concisely with Python code

    记忆组织设计：

    namespace 设计模式：
("users", user_id, "facts")      ← 按用户隔离的事实
("users", user_id, "preferences") ← 偏好
("orgs", org_id, "policies")     ← 组织级共享（只读使用）
(user_id, application_context)   ← 按用户+应用场景隔离

    25.7 生产要点¶

    1. 存储选型：开发 InMemoryStore（进程重启丢失）；生产 PostgresStore（或托管平台自动配的 store）
    2. namespace 即隔离边界：多用户应用永远把 user_id 放进 namespace，防止跨用户泄漏
    3. 语义搜索：配置 IndexConfig(embed=..., dims=...) 后用 search(query=...) 按相似度召回；embedding 函数可用 LangChain embeddings
    4. 写入策略：
    5. 一个 key 一条事实（可累积）vs 一个 key 整份档案（覆盖更新）——按场景选
    6. 重要记忆去重：写入前 search 相似内容
    7. 记忆 vs RAG：记忆存"关于用户/交互的持久事实"；外部知识库检索见第 26 章（Retrieval）
    8. 与短期记忆配合：checkpointer 管会话内历史（第 8 章），store 管跨会话记忆——两者独立配置，都要持久化才完整

    📝 本章小结¶

    关键要点¶

    1. 长期记忆 = LangGraph Store：JSON 文档按 (namespace, key) 组织，跨 thread 持久
    2. create_agent(store=...) 接入；工具内用 runtime.store 读写
    3. context_schema 传用户身份 → namespace 按用户隔离
    4. IndexConfig + embedding 启用语义搜索（store.search(query=...)）
    5. store.put/get/search/delete 四个核心方法；应用代码和工具共享同一个 store 实例
    6. 短期（checkpointer）+ 长期（store）双持久化才是完整的记忆系统
