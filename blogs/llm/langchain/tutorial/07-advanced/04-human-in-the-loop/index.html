    第 22 章：Human-in-the-Loop - 人在环中¶

    本章内容：工具调用人工审批：interrupt 机制、4 种决策类型、条件中断、恢复流程

    官方文档：https://docs.langchain.com/oss/python/langchain/human-in-the-loop 中间件本身见上一章（02-builtin-middleware.md §21.3）

    📚 本章目标¶

    学完本章后，你将掌握：

    • ✅ 理解 HITL 的 interrupt 机制（为什么必须要 checkpointer）
    • ✅ 用 interrupt_on 配置工具级审批策略
    • ✅ 掌握 4 种决策类型（approve/edit/reject/respond）的语义和适用场景
    • ✅ 用 when 谓词实现条件中断（按参数选择性审批）
    • ✅ 完整实现"中断 → 审查 → 恢复"流程

    22.1 HITL 是什么？¶

    Human-in-the-Loop（HITL）中间件给 Agent 的工具调用加人工监督。当模型提出一个可能需要审查的动作（写文件、执行 SQL、发邮件）时，中间件暂停执行等待人类决策。

    工作机制：

    模型提出工具调用
      ↓
对照 interrupt_on 策略检查
      ↓ 匹配
发出 interrupt，执行停止
      ↓
图状态保存到持久层（checkpointer）
      ↓
人类决策：approve / edit / reject / respond
      ↓
恢复执行（同一 thread_id）

    关键点：

    • 每次工具调用都对照可配置的策略检查
    • 需要干预时发出 interrupt 停止执行
    • 图状态通过 LangGraph 持久层保存——可以安全暂停、稍后恢复
    • 必须配置 checkpointer（生产用 AsyncPostgresSaver/MongoDBSaver，测试用 InMemorySaver）

    22.2 四种决策类型¶

    决策 说明 典型场景
    ✅ approve 按 Agent 提议的原参数执行 邮件草稿原样发送
    ✏️ edit 执行前修改工具参数 发送前改收件人
    ❌ reject 完全跳过执行，把拒绝反馈返回 Agent 拒绝删除文件并说明原因
    💬 respond 人类回复直接作为合成的工具结果返回（跳过执行） 回答 ask_user 式工具的提问

    语义辨析（重要）：

    • 拒绝一个动作 → 用 reject（它的消息会告诉模型"工具没执行"）
    • 人类充当工具本身（如回答澄清提问）→ 用 respond（它的消息被当作成功的工具结果）
    • ⚠️ 不要用 respond 来拒绝有副作用的工具——模型会以为工具成功执行了

    其他规则：

    • 多个工具调用同时暂停时，每个动作需要一个独立决策
    • 决策顺序必须与 interrupt 请求中动作的顺序一致

    💡 edit 要保守：大幅修改原始参数可能导致模型重新评估策略，重复执行工具或采取意外动作。

    22.3 配置中断策略¶

    创建 Agent 时加入 HumanInTheLoopMiddleware，用 interrupt_on 映射「工具 → 允许的决策类型」：

    from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[write_file, execute_sql, read_data],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "write_file": True,  # All decisions (approve, edit, reject, respond) allowed
                "execute_sql": {"allowed_decisions": ["approve", "reject"]},  # No editing allowed
                "read_data": False,  # Safe operation, no approval needed
            },
            # Prefix for interrupt messages - combined with tool name and args
            description_prefix="Tool execution pending approval",
        ),
    ],
    # Human-in-the-loop requires checkpointing to handle interrupts.
    # In production, use a persistent checkpointer like AsyncPostgresSaver.
    checkpointer=InMemorySaver(),
)

    interrupt_on 取值¶

    值 含义
    True 中断，允许全部 4 种决策
    False 自动批准，不中断
    InterruptOnConfig 自定义配置（见下）

    InterruptOnConfig 字段¶

    字段 说明
    allowed_decisions 允许的决策列表：'approve' / 'edit' / 'reject' / 'respond'
    description 静态字符串或可调用对象，自定义动作描述
    when 可选谓词：接收 ToolCallRequest，返回 True 中断 / False 自动批准（需 langchain>=1.3.3）

    22.4 条件中断（when 谓词）¶

    默认情况下 interrupt_on 里的每次工具调用都暂停。想只暂停部分调用，给工具配置加 when 谓词——按工具参数决定是否中断（需 langchain>=1.3.3）：

    from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware, ToolCallRequest
from langgraph.checkpoint.memory import InMemorySaver


def writes_outside_workspace(request: ToolCallRequest) -> bool:
    """Pause writes to paths outside the workspace directory."""
    path = request.tool_call["args"].get("path", "")
    return not path.startswith("/workspace/")


def is_write_query(request: ToolCallRequest) -> bool:
    """Pause SQL that isn't a read-only SELECT."""
    query = request.tool_call["args"].get("query", "")
    return not query.lstrip().upper().startswith("SELECT")


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[write_file, execute_sql, read_data],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "write_file": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                    "when": writes_outside_workspace,
                },
                "execute_sql": {
                    "allowed_decisions": ["approve", "reject"],
                    "when": is_write_query,
                },
            },
        ),
    ],
    checkpointer=InMemorySaver(),
)

    行为：

    • when 返回 False → 调用直接执行，不中断
    • when 返回 True（或省略 when）→ 照常暂停
    • 评估为 False 的调用不会进入 interrupt 批次——审查者只看到真正需要决策的动作

    典型用法：只审批 workspace 外的写入、只审批非 SELECT 的 SQL、只审批大额转账。

    22.5 响应中断（完整流程）¶

    调用 Agent 后，它运行到完成或触发 interrupt。用 version="v2" 时结果是带 interrupts 属性的 GraphOutput：

    Step 1：调用并检查中断¶

    from langgraph.types import Command

# thread ID associates the execution with a conversation thread,
# so the conversation can be paused and resumed.
config = {"configurable": {"thread_id": "some_id"}}

# Run the graph until the interrupt is hit.
result = agent.invoke(
    {
        "messages": [
            {
                "role": "user",
                "content": "Delete old records from the database",
            }
        ]
    },
    config=config,
    version="v2",
)

# result is a GraphOutput with .value and .interrupts
print(result.interrupts)
# > (
# >    Interrupt(
# >       value={
# >          'action_requests': [
# >             {
# >                'name': 'execute_sql',
# >                'arguments': {'query': 'DELETE FROM records WHERE ...'},
# >                'description': 'Tool execution pending approval\n\nTool: execute_sql\nArgs: {...}'
# >             }
# >          ],
# >          'review_configs': [
# >             {
# >                'action_name': 'execute_sql',
# >                'allowed_decisions': ['approve', 'reject']
# >             }
# >          ]
# >       }
# >    ),
# > )

    interrupt 的 value 包含：

    • action_requests：待审动作列表（工具名、参数、描述）
    • review_configs：每个动作允许的决策类型

    Step 2：按决策恢复¶

    ✅ approve（原样执行）：

    agent.invoke(
    Command(
        # Decisions are provided as a list, one per action under review.
        # The order of decisions must match the order of actions.
        resume={
            "decisions": [
                {
                    "type": "approve",
                }
            ]
        }
    ),
    config=config,  # Same thread ID to resume the paused conversation
    version="v2",
)

    ✏️ edit（改参数后执行）：

    agent.invoke(
    Command(
        resume={
            "decisions": [
                {
                    "type": "edit",
                    # Edited action with tool name and args
                    "edited_action": {
                        # Tool name to call (usually same as the original action)
                        "name": "new_tool_name",
                        # Arguments to pass to the tool
                        "args": {"key1": "new_value", "key2": "original_value"},
                    }
                }
            ]
        }
    ),
    config=config,
    version="v2",
)

    ❌ reject（拒绝 + 反馈）：

    agent.invoke(
    Command(
        resume={
            "decisions": [
                {
                    "type": "reject",
                    # Optional: explain why rejected and whether to retry
                    "message": "User rejected this action. Do not retry this tool call.",
                }
            ]
        }
    ),
    config=config,
    version="v2",
)

    message 作为反馈加入对话，帮 Agent 理解为什么被拒、接下来该做什么。省略时用默认拒绝消息（告诉模型工具未执行、除非用户要求否则别重试）。对有副作用的工具，建议写明确的领域化消息：放弃动作、追问、还是换更安全的方式。

    💬 respond（人类直接作答）：

    agent.invoke(
    Command(
        resume={
            "decisions": [
                {
                    "type": "respond",
                    # The human's reply, returned directly as the tool result
                    "message": "Blue.",
                }
            ]
        }
    ),
    config=config,
    version="v2",
)

    message 作为成功的 ToolMessage 返回给 Agent。用于工具本来就是"问人"的占位符（如 ask_user）。

    多个动作同时待审¶

    按 interrupt 中动作的顺序，每个动作给一个决策：

    {
    "decisions": [
        {"type": "approve"},                          # 第 1 个动作
        {"type": "reject", "message": "Too risky"},   # 第 2 个动作
    ]
}

    22.6 生产要点¶

    1. checkpointer 必须持久化：InMemorySaver 只适合原型；生产用 AsyncPostgresSaver / MongoDBSaver——进程重启后仍能恢复暂停的审批
    2. thread_id 是恢复的钥匙：暂停和恢复必须用同一个 thread_id
    3. 审批 UI：把 action_requests 渲染给审查者（工具名、参数高亮、风险说明），收集决策后按顺序提交
    4. 超时处理：审批可能永远不来——应用层要有超时策略（自动拒绝 / 升级 / 通知）
    5. 审计：把每次 interrupt 和决策记入 LangSmith 或自有日志，合规场景必须可追溯
    6. 按风险分级配 allowed_decisions：
    7. 高危（删数据、转账）：["approve", "reject"]，不给 edit 避免歧义
    8. 中危（发邮件）：["approve", "edit", "reject"]
    9. "问用户"型工具：["respond"]

    22.7 实战：带审批的数据库 Agent¶

    # db_agent_with_approval.py
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware, ToolCallRequest
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command


@tool
def execute_sql(query: str) -> str:
    """Execute a SQL query against the database."""
    # Real implementation would run the query
    return f"Executed: {query}"


@tool
def read_schema() -> str:
    """Read the database schema (read-only, safe)."""
    return "Tables: users(id, name, email), orders(id, user_id, total)"


def is_destructive(request: ToolCallRequest) -> bool:
    """Interrupt DELETE/DROP/UPDATE/TRUNCATE statements."""
    query = request.tool_call["args"].get("query", "").lstrip().upper()
    return query.startswith(("DELETE", "DROP", "UPDATE", "TRUNCATE"))


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[execute_sql, read_schema],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "execute_sql": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                    "when": is_destructive,
                },
            },
        ),
    ],
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "db-session-1"}}

# First invoke: SELECT runs freely, DELETE triggers interrupt
result = agent.invoke(
    {"messages": [{"role": "user", "content": "Clean up orders older than 1 year"}]},
    config=config,
    version="v2",
)

if result.interrupts:
    for interrupt in result.interrupts:
        for action in interrupt.value["action_requests"]:
            print(f"⚠️  Pending: {action['name']}({action['arguments']})")

    # Human approves...
    result = agent.invoke(
        Command(resume={"decisions": [{"type": "approve"}]}),
        config=config,
        version="v2",
    )

print(result.value["messages"][-1].content)

    📝 本章小结¶

    关键要点¶

    1. HITL = HumanInTheLoopMiddleware + interrupt_on 策略 + checkpointer（必需）
    2. 四种决策：approve（原样执行）/ edit（改参数）/ reject（拒绝+反馈）/ respond（人当工具）
    3. reject 和 respond 语义完全不同：前者是"没执行"，后者是"执行成功且结果是人的回复"
    4. when 谓词实现参数级条件中断（langchain>=1.3.3），避免审批疲劳
    5. 恢复流程：同一 thread_id + Command(resume={"decisions": [...]})，决策顺序 = 动作顺序
    6. 多动作待审时每个动作一个决策，按顺序对应
