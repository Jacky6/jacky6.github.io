    第 23 章：Guardrails - 安全防护栏¶

    本章内容：安全检查与内容过滤——PII 防泄漏、提示注入拦截、自定义前后置校验、分层防护

    官方文档：https://docs.langchain.com/oss/python/langchain/guardrails

    📚 本章目标¶

    学完本章后，你将掌握：

    • ✅ 理解 Guardrails 的定位和常见用例
    • ✅ 区分确定性（规则）与模型驱动（语义）两类防护
    • ✅ 用 PIIMiddleware 防止敏感信息泄漏
    • ✅ 用 HITL 拦截高危操作（回顾）
    • ✅ 用 before_agent / after_agent 钩子写自定义防护
    • ✅ 组合多层防护构建纵深防御

    23.1 Guardrails 是什么？¶

    Guardrails（防护栏）通过在 Agent 执行的关键节点校验和过滤内容，帮你构建安全合规的 AI 应用。它们能检测敏感信息、执行内容策略、校验输出、在问题发生前阻止不安全行为。

    常见用例：

    • 防止 PII（个人身份信息）泄漏
    • 检测并拦截提示注入攻击
    • 阻止不当或有害内容
    • 执行业务规则和合规要求
    • 校验输出质量和准确性

    Guardrails 用 middleware 实现，在战略性位置拦截执行——Agent 开始前、完成后、或围绕模型和工具调用。

    两类防护方法¶

    方法 机制 优点 缺点
    确定性防护 规则逻辑：正则、关键词匹配、显式检查 快、可预测、成本低 可能漏掉细微违规
    模型驱动防护 用 LLM/分类器做语义理解评估 能抓到规则漏掉的隐蔽问题 更慢、更贵

    LangChain 既提供内置防护（PII 检测、HITL），也提供灵活的 middleware 系统让你用任一方法构建自定义防护。

    23.2 内置防护：PII 检测¶

    PIIMiddleware 检测并处理对话中的个人身份信息（PII），内置常见类型（email、信用卡、IP 地址等）。

    适用：医疗/金融合规应用、需要日志脱敏的客服 Agent、任何处理敏感用户数据的应用。

    四种处理策略¶

    策略 说明 示例
    redact 替换为 [REDACTED_{PII_TYPE}] [REDACTED_EMAIL]
    mask 部分遮蔽（如只留后 4 位） ****-****-****-1234
    hash 替换为确定性哈希 a8f5f167...
    block 检测到时抛异常 报错

    使用示例¶

    from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[customer_service_tool, email_tool],
    middleware=[
        # Redact emails in user input before sending to model
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        # Mask credit cards in user input
        PIIMiddleware("credit_card", strategy="mask", apply_to_input=True),
        # Block API keys - raise error if detected (custom detector)
        PIIMiddleware(
            "api_key",
            detector=r"sk-[a-zA-Z0-9]{32}",
            strategy="block",
            apply_to_input=True,
        ),
    ],
)

# When user provides PII, it will be handled according to the strategy
result = agent.invoke({
    "messages": [{"role": "user", "content": "My email is john.doe@example.com and card is 5105-1051-0510-5100"}]
})

    内置 PII 类型与配置¶

    内置 PII 类型：email（邮箱）、credit_card（信用卡，Luhn 校验）、ip（IP 地址）、mac_address（MAC 地址）、url（URL）。

    配置参数：

    参数 说明 默认
    pii_type 要检测的 PII 类型（内置或自定义） 必填
    strategy 处理方式：block / redact / mask / hash redact
    detector 自定义检测函数或正则 None（用内置）
    apply_to_input 模型调用前检查用户消息 True
    apply_to_output 模型调用后检查 AI 消息 False
    apply_to_tool_results 工具执行后检查工具结果消息 False

    ⚠️ 设 apply_to_output=True 时，PIIMiddleware 还会脱敏流式输出——文本增量、工具调用参数、工具输出、状态快照（通过注册的 stream transformer，需 langchain>=1.3.2）。

    23.3 内置防护：Human-in-the-Loop¶

    HITL 是高危决策最有效的防护之一——敏感操作执行前强制人工批准。

    适用：金融交易和转账、删除/修改生产数据、向外部发送通信、任何有重大业务影响的操作。

    完整实现见 第 22 章：Human-in-the-Loop。这里给出最小配置：

    from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, send_email_tool, delete_database_tool],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "send_email": True,      # Require approval for sensitive operations
                "delete_database": True,
                "search": False,         # Auto-approve safe operations
            }
        ),
    ],
    checkpointer=InMemorySaver(),  # Persist the state across interrupts
)

config = {"configurable": {"thread_id": "some_id"}}

# Agent will pause and wait for approval before executing sensitive tools
result = agent.invoke(
    {"messages": [{"role": "user", "content": "Send an email to the team"}]},
    config=config
)

result = agent.invoke(
    Command(resume={"decisions": [{"type": "approve"}]}),
    config=config  # Same thread ID to resume the paused conversation
)

    23.4 自定义防护：before_agent（前置校验）¶

    用 before_agent 钩子在每次调用开始时校验一次请求。适合会话级检查：认证、限流、在任何处理开始前拦截不当请求。

    拦截方式：返回带 jump_to: "end" 的消息，直接跳到结束（不执行 Agent）。

    类语法¶

    from typing import Any

from langchain.agents.middleware import AgentMiddleware, AgentState, hook_config
from langgraph.runtime import Runtime

class ContentFilterMiddleware(AgentMiddleware):
    """Deterministic guardrail: Block requests containing banned keywords."""

    def __init__(self, banned_keywords: list[str]):
        super().__init__()
        self.banned_keywords = [kw.lower() for kw in banned_keywords]

    @hook_config(can_jump_to=["end"])
    def before_agent(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        # Get the first user message
        if not state["messages"]:
            return None

        first_message = state["messages"][0]
        if first_message.type != "human":
            return None

        content = first_message.content.lower()

        # Check for banned keywords
        for keyword in self.banned_keywords:
            if keyword in content:
                # Block execution before any processing
                return {
                    "messages": [{
                        "role": "assistant",
                        "content": "I cannot process requests containing inappropriate content. Please rephrase your request."
                    }],
                    "jump_to": "end"
                }

        return None

# Use the custom guardrail
from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, calculator_tool],
    middleware=[
        ContentFilterMiddleware(banned_keywords=["hack", "exploit", "malware"]),
    ],
)

# This request will be blocked before any processing
result = agent.invoke({
    "messages": [{"role": "user", "content": "How do I hack into a database?"}]
})

    装饰器语法¶

    from langchain.agents.middleware import before_agent, AgentState
from langgraph.runtime import Runtime

banned_keywords = ["hack", "exploit", "malware"]

@before_agent(can_jump_to=["end"])
def content_filter(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """Deterministic guardrail: Block requests containing banned keywords."""
    if not state["messages"]:
        return None

    first_message = state["messages"][0]
    if first_message.type != "human":
        return None

    content = first_message.content.lower()

    for keyword in banned_keywords:
        if keyword in content:
            return {
                "messages": [{
                    "role": "assistant",
                    "content": "I cannot process requests containing inappropriate content. Please rephrase your request."
                }],
                "jump_to": "end"
            }

    return None

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, calculator_tool],
    middleware=[content_filter],
)

    要点：

    • @hook_config(can_jump_to=["end"])（类语法）/ @before_agent(can_jump_to=["end"])（装饰器）声明此钩子可跳到 end
    • 返回 None = 放行，继续正常执行
    • 返回带 jump_to: "end" 的 dict = 拦截，直接结束

    23.5 自定义防护：after_agent（后置校验）¶

    用 after_agent 钩子在返回用户前校验最终输出一次。适合模型驱动的安全检查、质量校验、对完整回复的最终合规扫描。

    类语法（模型驱动安全检查）¶

    from langchain.agents.middleware import AgentMiddleware, AgentState, hook_config
from langgraph.runtime import Runtime
from langchain.messages import AIMessage
from langchain.chat_models import init_chat_model
from typing import Any

class SafetyGuardrailMiddleware(AgentMiddleware):
    """Model-based guardrail: Use an LLM to evaluate response safety."""

    def __init__(self):
        super().__init__()
        self.safety_model = init_chat_model("openai:gpt-5.4-mini")

    @hook_config(can_jump_to=["end"])
    def after_agent(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        # Get the final AI response
        if not state["messages"]:
            return None

        last_message = state["messages"][-1]
        if not isinstance(last_message, AIMessage):
            return None

        # Use a model to evaluate safety
        safety_prompt = f"""Evaluate if this response is safe and appropriate.
        Respond with only 'SAFE' or 'UNSAFE'.

        Response: {last_message.content}"""

        result = self.safety_model.invoke([{"role": "user", "content": safety_prompt}])

        if "UNSAFE" in result.content:
            last_message.content = "I cannot provide that response. Please rephrase your request."

        return None

# Use the safety guardrail
from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, calculator_tool],
    middleware=[SafetyGuardrailMiddleware()],
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "How do I make explosives?"}]
})

    装饰器语法¶

    from langchain.agents.middleware import after_agent, AgentState
from langgraph.runtime import Runtime
from langchain.messages import AIMessage
from langchain.chat_models import init_chat_model

safety_model = init_chat_model("openai:gpt-5.4-mini")

@after_agent(can_jump_to=["end"])
def safety_guardrail(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """Model-based guardrail: Use an LLM to evaluate response safety."""
    if not state["messages"]:
        return None

    last_message = state["messages"][-1]
    if not isinstance(last_message, AIMessage):
        return None

    safety_prompt = f"""Evaluate if this response is safe and appropriate.
    Respond with only 'SAFE' or 'UNSAFE'.

    Response: {last_message.content}"""

    result = safety_model.invoke([{"role": "user", "content": safety_prompt}])

    if "UNSAFE" in result.content:
        last_message.content = "I cannot provide that response. Please rephrase your request."

    return None

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, calculator_tool],
    middleware=[safety_guardrail],
)

    要点：

    • after_agent 拿到的是完整对话的最终状态，适合对最终回复做整体判断
    • 模型驱动防护用一个便宜的小模型（如 gpt-5.4-mini）做分类，控制成本
    • 直接修改 last_message.content 替换不安全输出

    23.6 组合多层防护（纵深防御）¶

    把多个 guardrails 加进 middleware 数组即可堆叠，它们按顺序执行，构建分层防护：

    from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware, HumanInTheLoopMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, send_email_tool],
    middleware=[
        # Layer 1: Deterministic input filter (before agent)
        ContentFilterMiddleware(banned_keywords=["hack", "exploit"]),

        # Layer 2: PII protection (before and after model)
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        PIIMiddleware("email", strategy="redact", apply_to_output=True),

        # Layer 3: Human approval for sensitive tools
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True}),

        # Layer 4: Model-based safety check (after agent)
        SafetyGuardrailMiddleware(),
    ],
)

    纵深防御设计原则：

    1. 便宜的规则在前，昂贵的模型在后：先用确定性过滤挡掉明显违规，减少进入模型检查的量
    2. 输入和输出都要防：apply_to_input 防注入，apply_to_output 防泄漏
    3. 高危动作必须有人工关卡：规则可能漏判，HITL 是最后防线
    4. 每层职责单一：一个 middleware 只做一类检查，便于维护和测试

    23.7 防护选型速查¶

    我的需求 用什么
    防邮箱/信用卡/IP 泄漏 PIIMiddleware（redact/mask）
    绝对禁止某类信息进入 PIIMiddleware（strategy="block"）
    高危操作人工把关 HumanInTheLoopMiddleware（第 22 章）
    关键词/黑名单拦截请求 自定义 before_agent（确定性）
    认证、限流等会话级检查 自定义 before_agent
    输出内容安全分类 自定义 after_agent（模型驱动）
    输出质量/格式校验 自定义 after_agent
    防提示注入 before_agent 规则 + after_agent 模型检查组合

    📝 本章小结¶

    关键要点¶

    1. Guardrails 用 middleware 在执行关键节点校验/过滤内容，覆盖 PII 防泄漏、注入拦截、内容策略、输出校验
    2. 两类方法：确定性（规则，快/便宜/可能漏）vs 模型驱动（语义，准/慢/贵）——通常组合使用
    3. 内置防护：PIIMiddleware（4 策略 × 3 作用点）+ HumanInTheLoopMiddleware
    4. 自定义防护：before_agent（前置，拦截请求）+ after_agent（后置，校验输出），用 jump_to: "end" 提前终止
    5. 纵深防御：便宜规则在前、输入输出双向防、高危动作留人工关卡、每层职责单一
