    第 19 章：Skills — 按需技能架构¶

    本章内容：Skills 架构、渐进式披露、SQL Assistant 实战教程

    官方文档：https://docs.langchain.com/oss/python/langchain/multi-agent/skills

    📚 本章目标¶

    学完本章后，你将掌握：

    • ✅ 理解 Skills 架构的核心概念：prompt-driven specialization
    • ✅ 掌握渐进式披露（Progressive Disclosure）模式
    • ✅ 实现按需加载技能的工具
    • ✅ 构建基于 Skills 的 SQL Assistant 实战
    • ✅ 了解 Skills 的扩展模式：动态工具注册、层级 Skills、引用感知

    19.1 什么是 Skills¶

    Skills 是 按需触发的专门化能力，让一个 Agent 拥有多种专业角色，但只在需要时才加载详细信息。

    核心思想：Agent 在 system prompt 中只看到轻量的技能描述，当任务需要时通过工具调用加载完整技能内容。

    graph LR
    A[用户] --> B[Agent]
    B --> C[Skill A]
    B --> D[Skill B]
    B --> E[Skill C]
    B --> A

    关键特性¶

    特性 说明
    Prompt-driven 专门化 Skills 主要由专门的 prompt 定义
    渐进式披露 根据上下文或用户需求按需加载
    团队独立开发 不同团队可独立开发维护技能
    轻量组合 比完整子 Agent 更轻量
    引用感知 技能可引用脚本、模板等资源

    与子 Agent 的区别¶

    维度 Skills 子 Agent
    架构 同一个 Agent，不同 prompt specialization 独立的 Agent 实例
    上下文 共享同一对话线程 隔离上下文
    复杂度 轻量，纯 prompt 驱动 较重，独立工具和配置
    适用 单个 Agent 多种专业角色 需要隔离的并行任务

    适用场景¶

    • 编码助手：不同语言/任务的技能
    • 知识库：不同领域的专业知识
    • 创意助手：不同格式的输出技能
    • SQL 助手：不同业务线的数据库 schema

    19.2 渐进式披露（Progressive Disclosure）¶

    渐进式披露 = 按需加载信息，而非一次性全部注入上下文窗口。

    ┌─────────────────────────────────────────────────┐
│                    三层架构                       │
├─────────────────────────────────────────────────┤
│                                                 │
│  第一层：元数据（始终可见）                        │
│  ├── 技能名称                                    │
│  └── 简短描述（1-2 句）                          │
│                                                 │
│  第二层：核心内容（按需加载）                      │
│  ├── 详细指令                                   │
│  └── 领域知识                                   │
│                                                 │
│  第三层：详细资源（深层需要时加载）                 │
│  ├── 参考脚本                                   │
│  ├── 模板文件                                   │
│  └── 示例代码                                   │
│                                                 │
└─────────────────────────────────────────────────┘

    为什么有效¶

    优势 说明
    减少上下文占用 只加载 2-3 个需要的技能，而非全部
    支持团队自治 不同团队独立开发专业领域技能
    高效扩展 添加数十/数百个技能不压垮上下文窗口
    简化对话历史 单一 Agent，一个对话线程

    权衡¶

    缺点 说明
    延迟 按需加载技能需要额外工具调用，首次请求有延迟
    工作流控制 基本实现依赖 prompt 引导，无法硬编码"先用 A 再用 B"

    19.3 基础实现¶

    定义技能结构¶

    from typing import TypedDict


class Skill(TypedDict):
    """可渐进式披露给 Agent 的技能。"""
    name: str          # 唯一标识符
    description: str   # 1-2 句描述，显示在 system prompt 中
    content: str       # 完整技能内容，按需加载

    定义示例技能¶

    SKILLS: list[Skill] = [
    {
        "name": "sql_expert",
        "description": "SQL query writing expert for PostgreSQL databases.",
        "content": """# SQL Expert

## Guidelines
- Use CTEs for complex queries
- Always include EXPLAIN ANALYZE for performance analysis
- Use proper JOIN syntax, not implicit joins

## Common Patterns
-- Pagination
SELECT * FROM users ORDER BY created_at LIMIT 20 OFFSET 0;
""",
    },
    {
        "name": "data_analyst",
        "description": "Data analysis and visualization specialist using Python.",
        "content": """# Data Analyst

## Tools
- pandas for data manipulation
- matplotlib/seaborn for visualization
- scipy for statistical analysis

## Workflow
1. Load data
2. Clean and transform
3. Analyze
4. Visualize
""",
    },
]

    创建技能加载工具¶

    from langchain.tools import tool


@tool
def load_skill(skill_name: str) -> str:
    """Load a specialized skill.

    Available skills:
    - sql_expert: SQL query writing expert for PostgreSQL databases.
    - data_analyst: Data analysis and visualization specialist using Python.

    Returns the skill's full content and context.
    """
    for skill in SKILLS:
        if skill["name"] == skill_name:
            return skill["content"]
    return f"Unknown skill: {skill_name}"

    创建 Agent¶

    from langchain.agents import create_agent

agent = create_agent(
    "openai:gpt-5.5",
    tools=[load_skill],
    system_prompt=(
        "You are a helpful assistant. "
        "You have access to these skills via load_skill: "
        "- sql_expert: SQL query writing expert for PostgreSQL databases. "
        "- data_analyst: Data analysis and visualization specialist using Python. "
        "Use load_skill to load a skill when you need its specialized capabilities."
    ),
)

# 测试
result = agent.invoke({
    "messages": [{"role": "user", "content": "帮我写一个 SQL 查询，找出月销售额 Top 10 的产品"}]
})
print(result["messages"][-1].content)

    工作流程¶

    用户: "帮我写一个 SQL 查询..."
  ↓
Agent: 看到 system prompt 中的技能描述
  ↓
Agent: 判断需要 sql_expert 技能
  ↓
Agent: 调用 load_skill("sql_expert")
  ↓
Agent: 获取完整技能内容（详细指令 + SQL 模式）
  ↓
Agent: 使用技能知识生成高质量 SQL
  ↓
返回结果给用户

    19.4 实战：SQL Assistant with On-Demand Skills¶

    来自官方教程：Build a SQL assistant with on-demand skills

    场景¶

    企业有多个业务线的数据库，一次性加载所有 schema 会压垮上下文窗口。 使用 Skills 架构，只按需加载相关的 schema。

    完整实现¶

    from typing import TypedDict
from langchain.tools import tool
from langchain.agents import create_agent


class Skill(TypedDict):
    """A skill that can be progressively disclosed to the agent."""
    name: str
    description: str
    content: str


# ── 定义技能 ─────────────────────────────────────────

SKILLS: list[Skill] = [
    {
        "name": "sales_analytics",
        "description": "Database schema and business logic for sales data analysis including customers, orders, and revenue.",
        "content": """# Sales Analytics Schema

## Tables
### customers
- customer_id (PRIMARY KEY)
- name, email, signup_date
- status (active/inactive)
- customer_tier (bronze/silver/gold/platinum)

### orders
- order_id (PRIMARY KEY)
- customer_id (FOREIGN KEY -> customers)
- order_date, status (pending/completed/cancelled/refunded)
- total_amount, sales_region (north/south/east/west)

### order_items
- item_id (PRIMARY KEY)
- order_id (FOREIGN KEY -> orders)
- product_id, quantity, unit_price, discount_percent

## Business Logic
**Active customers**: status = 'active' AND signup_date <= CURRENT_DATE - INTERVAL '90 days'
**Revenue**: Only count orders with status = 'completed'.
**Customer lifetime value (CLV)**: Sum of all completed order amounts.
""",
    },
    {
        "name": "inventory_management",
        "description": "Database schema and business logic for inventory tracking including products, warehouses, and stock levels.",
        "content": """# Inventory Management Schema

## Tables
### products
- product_id (PRIMARY KEY)
- product_name, sku, category
- unit_cost, reorder_point, discontinued (boolean)

### warehouses
- warehouse_id (PRIMARY KEY)
- warehouse_name, location, capacity

### inventory
- inventory_id (PRIMARY KEY)
- product_id (FOREIGN KEY -> products)
- warehouse_id (FOREIGN KEY -> warehouses)
- quantity_on_hand, last_updated

## Business Logic
**Available stock**: quantity_on_hand > 0
**Products needing reorder**: total quantity_on_hand <= reorder_point
**Active products only**: Exclude discontinued = true unless specifically analyzing.
""",
    },
]

# ── 技能加载工具 ──────────────────────────────────────

@tool
def load_skill(skill_name: str) -> str:
    """Load the full content of a specialized skill.

    Available skills:
    - sales_analytics: Database schema and business logic for sales data analysis including customers, orders, and revenue.
    - inventory_management: Database schema and business logic for inventory tracking including products, warehouses, and stock levels.

    Args:
        skill_name: The name of the skill to load (e.g., 'sales_analytics').

    Returns:
        The full skill content with detailed schema, business logic, and example queries.
    """
    for skill in SKILLS:
        if skill["name"] == skill_name:
            return skill["content"]
    return f"Unknown skill: {skill_name}. Available: {[s['name'] for s in SKILLS]}"


# ── 创建 Agent ────────────────────────────────────────

agent = create_agent(
    "openai:gpt-5.5",
    tools=[load_skill],
    system_prompt=(
        "You are a helpful SQL assistant. "
        "You have access to these skills via the load_skill tool: "
        "- sales_analytics: Database schema and business logic for sales data analysis including customers, orders, and revenue. "
        "- inventory_management: Database schema and business logic for inventory tracking including products, warehouses, and stock levels. "
        "Use load_skill to load a skill when you need its detailed schema information to write SQL queries. "
        "Always load the relevant skill before writing SQL."
    ),
)

# ── 测试 ──────────────────────────────────────────────

result = agent.invoke({
    "messages": [{
        "role": "user",
        "content": "Write a SQL query to find the top 10 customers by revenue in the last quarter."
    }]
})
print(result["messages"][-1].content)

    内部流程¶

    用户: "Find top 10 customers by revenue..."
  ↓
Agent: 读取 system prompt 中的技能描述
Agent: 判断需要 sales_analytics 的 schema
  ↓
Agent: 调用 load_skill("sales_analytics")
  ↓
Agent: 获取完整 schema（customers, orders, order_items 表结构 + 业务逻辑）
  ↓
Agent: 使用 schema 信息编写 SQL:
  SELECT c.customer_id, c.name, c.customer_tier,
         SUM(o.total_amount) as total_revenue
  FROM customers c
  JOIN orders o ON c.customer_id = o.customer_id
  WHERE o.status = 'completed'
    AND o.order_date >= CURRENT_DATE - INTERVAL '3 months'
  GROUP BY c.customer_id, c.name, c.customer_tier
  ORDER BY total_revenue DESC
  LIMIT 10;
  ↓
返回 SQL 给用户

    19.5 Skills 扩展模式¶

    19.5.1 动态工具注册（Dynamic Tool Registration）¶

    技能加载时不仅添加上下文，还注册相关工具：

    from langchain.agents import create_agent
from langchain.tools import tool

SKILL_TOOLS = {}  # 技能 → 工具映射

@tool
def backup_db() -> str:
    """Backup the database."""
    return "Backup complete"

@tool
def restore_db() -> str:
    """Restore the database."""
    return "Restore complete"

SKILL_TOOLS["database_admin"] = [backup_db, restore_db]


@tool
def load_skill_with_tools(skill_name: str, runtime) -> str:
    """Load a skill and register its associated tools."""
    skill_content = SKILLS_DB.get(skill_name)
    if skill_name in SKILL_TOOLS:
        # 动态注册工具
        for t in SKILL_TOOLS[skill_name]:
            runtime.register_tool(t)
    return skill_content

    19.5.2 层级 Skills（Hierarchical Skills）¶

    技能可以有子技能，形成树状结构：

    HIERARCHICAL_SKILLS = {
    "data_science": {
        "description": "Data science expert with multiple sub-specialties.",
        "sub_skills": {
            "pandas_expert": "Pandas data manipulation specialist.",
            "visualization": "Data visualization specialist using matplotlib/seaborn.",
            "statistical_analysis": "Statistical analysis specialist using scipy/statsmodels.",
        },
        "content": "...",
    },
}


@tool
def load_skill(skill_name: str) -> str:
    """Load a skill or list sub-skills.

    Available:
    - data_science: Data science expert (sub-skills: pandas_expert, visualization, statistical_analysis)
    """
    skill = HIERARCHICAL_SKILLS.get(skill_name)
    if skill and "sub_skills" in skill:
        return f"Sub-skills available: {list(skill['sub_skills'].keys())}"
    return skill.get("content", f"Unknown skill: {skill_name}")

    19.5.3 引用感知（Reference Awareness）¶

    技能可引用外部资源，需要时才读取：

    @tool
def load_skill(skill_name: str) -> str:
    """Load a skill that may reference external resources."""
    skill = SKILLS.get(skill_name)
    # 技能内容可能包含：
    # "See /scripts/data_pipeline.py for the ETL template"
    # "Use the format in /templates/report.md"
    return skill

    Agent 在任务进行中判断需要这些资源时，会主动读取相关文件。

    19.6 最佳实践¶

    Do ✅¶

    做法 说明
    轻量描述，详细内容 描述 1-2 句，内容可以很长
    按需加载 不要在 system prompt 中放完整技能内容
    独立维护 每个技能独立开发测试
    引用资源而非嵌入 技能引用文件路径，而非嵌入整个文件

    Don't ❌¶

    做法 问题
    所有技能内容放进 system prompt 上下文窗口爆炸
    技能之间互相依赖 加载顺序复杂化
    过度细分技能 频繁加载增加延迟

    3. 基础实现：定义技能结构 → 创建加载工具 → 创建 Agent
    4. SQL Assistant 实战：多业务线数据库场景下的按需 schema 加载

    与子 Agent 对比¶

    维度 Skills 子 Agent (第 14 章)
    架构 同一 Agent，不同 prompt 独立 Agent 实例
    上下文 共享同一线程 隔离
    复杂度 轻量 较重
    适用 单 Agent 多专业 并行任务/隔离
