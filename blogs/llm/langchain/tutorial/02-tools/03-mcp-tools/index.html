    03 MCP Tools — Model Context Protocol 工具集成¶

    官方文档：https://docs.langchain.com/oss/python/langchain/tools

    MCP (Model Context Protocol) 是 Anthropic 推出的开放标准，让模型通过统一协议连接外部工具和数据源。

    ✅ 本文已重写（2026-10-30）。MCP 协议事实源见 ../../../protocols/mcp/（主线版本 2026-07-28）。

    📚 本章目标¶

    学完本章后，你将掌握：

    • ✅ 理解 MCP 协议的核心概念与 LangChain 的接入方式
    • ✅ 按已安装的 langchain 版本选择正确的接入路径
    • ✅ 本地（stdio）和远程（Streamable HTTP）MCP Server 配置
    • ✅ MCP + create_agent 的最佳实践

    03.1 什么是 MCP¶

    Model Context Protocol (MCP) 是一个开放标准，让 AI 应用通过统一协议：

    • 访问外部数据（数据库、API、文件系统）
    • 调用工具（搜索、计算、代码执行）
    • 获取上下文（提示模板、资源）

    架构¶

    ┌──────────────┐         ┌──────────────┐         ┌──────────────┐
│   LangChain  │◄───────►│  MCP Client   │◄───────►│  MCP Server   │
│   Agent      │         │  (JSON-RPC)   │         │  (任何语言)   │
└──────────────┘         └──────────────┘         └──────────────┘
                                                      │
                                          ┌───────────┴───────────┐
                                          │                       │
                                    ┌─────┴─────┐          ┌──────┴──────┐
                                    │ 数据库     │          │ 文件系统     │
                                    │ API       │          │ Git 仓库     │
                                    │ 搜索       │          │ ...         │
                                    └───────────┘          └──────────────┘

    为什么用 MCP¶

    优势 说明
    标准化 统一协议，不依赖特定 Provider
    解耦 工具开发者只需写 MCP Server，不关心 Agent 框架
    多语言 MCP Server 可用 Python/Node/Go 等编写
    安全 通过权限控制 Agent 可访问的资源

    协议细节（版本、传输、鉴权、MRTR）见 ../../../protocols/mcp/。

    03.2 安装：按版本选择路径¶

    MCP 接入方式取决于你安装的 langchain 版本：

    langchain 版本 接入方式 安装命令
    1.4+ 内置 langchain.mcp.MCPAdapter pip install "langchain[mcp]>=1.4"
    1.3.x 独立包 langchain-mcp-adapters pip install langchain-mcp-adapters

    检查你的版本：

    python3 -c "import importlib.metadata as im; print(im.version('langchain'))"

    ⚠️ 两条路径的 API 名称不同（MCPAdapter.list_tools() vs MultiServerMCPClient.get_tools()），不要混用。新项目建议直接上 1.4+。

    03.3 路径 A：langchain 1.4+（内置 MCPAdapter）¶

    连接本地 MCP Server（stdio）¶

    from langchain.agents import create_agent
from langchain.mcp import MCPAdapter

# MCPAdapter 统一管理多个 Server 连接
adapter = MCPAdapter(
    {
        "filesystem": {
            "transport": "stdio",
            "command": "npx",
            "args": [
                "-y",
                "@modelcontextprotocol/server-filesystem",
                "/path/to/allowed/dir",
            ],
        },
    }
)

# 发现工具（1.4+ 用 list_tools，不是 get_tools）
tools = await adapter.list_tools()

agent = create_agent(
    model="openai:gpt-5.5",
    tools=tools,
)

result = await agent.ainvoke(
    {"messages": [("user", "读取 ./README.md 的内容")]}
)

    连接远程 MCP Server（Streamable HTTP）¶

    adapter = MCPAdapter(
    {
        "my_remote_server": {
            "transport": "streamable-http",
            "url": "https://mcp.example.com/mcp",
            # 认证头按 Server 要求配置
            "headers": {"Authorization": f"Bearer {token}"},
        },
    }
)
tools = await adapter.list_tools()

    远程传输用 Streamable HTTP（当前标准）。旧 sse 传输已过时，新项目不要使用。

    03.4 路径 B：langchain 1.3.x（langchain-mcp-adapters）¶

    pip install langchain-mcp-adapters

    from langchain.agents import create_agent
from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient(
    {
        "filesystem": {
            "command": "npx",
            "args": [
                "-y",
                "@modelcontextprotocol/server-filesystem",
                "/path/to/allowed/dir",
            ],
        },
    }
)

# 1.3.x 用 get_tools()
tools = await client.get_tools()

agent = create_agent(
    model="openai:gpt-5.5",
    tools=tools,
)

result = await agent.ainvoke(
    {"messages": [("user", "读取 ./README.md 的内容")]}
)

    ⚠️ 此包为过渡方案，langchain 1.4+ 后应迁移到内置 MCPAdapter（get_tools() → list_tools()）。

    03.5 自定义 MCP Server（Python）¶

    用官方 Python SDK 写一个最小 Server：

    # my_server.py — pip install "mcp>=2.0"
from mcp.server import Server
from mcp.types import Tool, TextContent

app = Server("my-tools")

@app.list_tools()
async def list_tools() -> list[Tool]:
    return [
        Tool(
            name="search_docs",
            description="搜索内部文档库",
            inputSchema={
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "搜索关键词"}
                },
                "required": ["query"],
            },
        )
    ]

@app.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    if name == "search_docs":
        return [TextContent(type="text", text=f"（模拟搜索 {arguments['query']}）")]

if __name__ == "__main__":
    # 本地用 stdio；远程用 streamable-http
    app.run(transport="stdio")

    Server 端协议细节（Modern 无握手、resultType、MRTR）见 ../../../protocols/mcp/07-从零搭建Python-MCP-Server.md。

    03.6 MCP 工具 vs 原生 Python 工具¶

    维度 原生 @tool MCP 工具
    定义位置 Agent 进程内 独立进程/远程服务
    发现 静态注册 list_tools() 动态发现
    复用 需复制代码 多 Host 共享同一 Server
    语言 Python 任意
    适用 项目私有逻辑 第三方能力、跨语言、隔离执行

    对模型来说两者没有区别——都是 tools 列表里的 Schema 条目（见 agent/concepts/02）。

    03.7 最佳实践¶

    Do ✅¶

    • 工具描述写清"什么时候用、什么时候不用"
    • 文件系统 Server 限定允许目录（不要开放 /）
    • 远程 Server 用 Streamable HTTP + 认证
    • 工具结果视为不可信输入（可能含注入）

    Don't ❌¶

    • 不要把 stdio Server 当沙箱（它只是普通本机进程）
    • 不要混用两条接入路径的 API
    • 不要在工具描述或结果中放敏感信息
    • 不要假设 Server 状态（Modern 协议无 Session）

    📝 本章小结¶

    1. langchain 1.4+ 用内置 MCPAdapter（list_tools()）；1.3.x 用 langchain-mcp-adapters（get_tools()）。
    2. 本地 stdio、远程 Streamable HTTP；旧 SSE 传输不要用于新项目。
    3. MCP 工具与原生工具对模型无区别，区别在发现、复用和隔离。
    4. 协议细节以 protocols/mcp/ 为准。
