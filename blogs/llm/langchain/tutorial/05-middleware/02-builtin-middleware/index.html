    第 21 章：内置中间件目录 - Prebuilt Middleware¶

    本章内容：LangChain 官方内置中间件全目录 + 选型速查

    官方文档：https://docs.langchain.com/oss/python/langchain/middleware/built-in 中间件基础概念见上一章（01-middleware.md）

    📚 本章目标¶

    学完本章后，你将掌握：

    • ✅ 知道官方提供了哪些开箱即用的中间件
    • ✅ 按需求（可靠性/成本/合规/测试）快速选型
    • ✅ 掌握常用中间件的关键配置参数
    • ✅ 了解 Provider 特定中间件的存在

    21.1 内置中间件全景¶

    LangChain 提供两大类内置中间件：

    Provider 无关（任何模型都能用）
├── 上下文管理
│   ├── SummarizationMiddleware      摘要压缩历史
│   └── ContextEditingMiddleware     清理旧工具输出
├── 执行控制
│   ├── ModelCallLimitMiddleware     限制模型调用次数
│   ├── ToolCallLimitMiddleware      限制工具调用次数
│   └── HumanInTheLoopMiddleware     人工审批（第 22 章）
├── 可靠性
│   ├── ModelRetryMiddleware         模型调用重试
│   ├── ToolRetryMiddleware          工具调用重试
│   ├── ModelFallbackMiddleware      模型故障切换
│   └── ToolErrorMiddleware          工具异常转消息
├── 工具增强
│   ├── LLMToolSelectorMiddleware    LLM 预选工具
│   ├── ProviderToolSearchMiddleware Provider 服务端工具搜索
│   ├── ShellToolMiddleware          持久 shell 会话
│   └── FilesystemFileSearchMiddleware  glob/grep 文件搜索
├── 规划
│   └── TodoListMiddleware           write_todos 任务清单
├── 合规
│   └── PIIMiddleware                PII 检测/脱敏
└── 测试
    └── LLMToolEmulator              LLM 模拟工具执行

来自 Deep Agents（可装进 create_agent）
├── FilesystemMiddleware             虚拟文件系统工具
├── SubAgentMiddleware               task 子代理工具
└── RubricMiddleware (Beta)          评分标准迭代

Provider 特定
├── Anthropic：prompt caching / bash / text editor / memory / file search
├── AWS：Bedrock prompt caching
└── OpenAI：content moderation

    21.2 上下文管理类¶

    SummarizationMiddleware（摘要）¶

    接近 token 上限时自动摘要对话历史，保留近期消息、压缩旧上下文。

    from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[your_weather_tool, your_calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="openai:gpt-5.4-mini",   # 摘要模型（可用便宜的）
            trigger=("tokens", 4000),       # 触发条件
            keep=("messages", 20),          # 保留最近 20 条
        ),
    ],
)

    关键参数：

    • model：生成摘要的模型（字符串或实例）
    • trigger：触发条件，支持 token 数、消息数、上下文比例（比例依赖模型 profile，langchain>=1.1）
    • keep：保留多少近期上下文不压缩

    ⚠️ 摘要是文本导向的压缩：不处理图片/音频/视频。多模态密集场景把媒体存文件系统/对象存储，消息里传 URL。

    ContextEditingMiddleware（上下文编辑）¶

    达到 token 上限时清除旧的工具调用输出（保留最近 N 个），比摘要更便宜（不调 LLM）：

    from langchain.agents.middleware import ContextEditingMiddleware, ClearToolUsesEdit

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[],
    middleware=[
        ContextEditingMiddleware(
            edits=[
                ClearToolUsesEdit(
                    trigger=100000,   # token 阈值
                ),
            ],
        ),
    ],
)

    适合工具结果很长的场景（搜索、RAG）——旧工具输出往往不再需要。

    21.3 执行控制类¶

    ModelCallLimitMiddleware（模型调用限制）¶

    防止无限循环和成本失控：

    from langchain.agents.middleware import ModelCallLimitMiddleware
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model="openai:gpt-5.5",
    checkpointer=InMemorySaver(),  # Required for thread limiting
    middleware=[
        ModelCallLimitMiddleware(
            thread_limit=10,        # 整个 thread 累计上限
            run_limit=5,            # 单次 invoke 上限
            exit_behavior="end",    # 'end'（优雅结束）或 'error'（抛异常）
        ),
    ],
)

    ToolCallLimitMiddleware（工具调用限制）¶

    全局或按工具限制调用次数——防止昂贵 API 被刷爆、限制搜索/查询次数、对抗失控循环。

    HumanInTheLoopMiddleware（人工审批）¶

    工具执行前暂停等待人工批准/编辑/拒绝。必须配 checkpointer。完整内容见第 22 章。

    from langchain.agents.middleware import HumanInTheLoopMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[your_read_email_tool, your_send_email_tool],
    checkpointer=InMemorySaver(),
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "your_send_email_tool": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                },
                "your_read_email_tool": False,
            }
        ),
    ],
)

    21.4 可靠性类¶

    ModelRetryMiddleware / ToolRetryMiddleware（重试）¶

    指数退避自动重试，处理瞬时故障（网络抖动、限流）：

    from langchain.agents.middleware import ModelRetryMiddleware, ToolRetryMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_tool, database_tool],
    middleware=[
        ModelRetryMiddleware(max_retries=3, backoff_factor=2.0, initial_delay=1.0),
        ToolRetryMiddleware(max_retries=3, backoff_factor=2.0, initial_delay=1.0),
    ],
)
    • max_retries：初次调用之外的最大重试次数（默认 2，即总共 3 次）
    • retry_on：指定哪些异常类型触发重试
    • tools（仅 ToolRetry）：限定哪些工具参与重试

    ModelFallbackMiddleware（模型故障切换）¶

    主模型失败时自动切换备用模型：

    from langchain.agents.middleware import ModelFallbackMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    middleware=[
        ModelFallbackMiddleware(
            "openai:gpt-5.4-mini",                 # 第一备用
            "anthropic:claude-sonnet-4-6",         # 第二备用
        ),
    ],
)

    用途：故障容灾、成本优化（降级到便宜模型）、跨 Provider 冗余。

    ToolErrorMiddleware（工具异常转消息）¶

    把工具执行抛出的异常转成错误 ToolMessage 让模型看到并自我恢复，而不是整个 Agent 崩溃（需 langchain>=1.3.14）：

    from langchain.agents.middleware import ToolErrorMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[flaky_tool],
    middleware=[ToolErrorMiddleware()],
)

    📌 本中间件不自动重试。要"重试耗尽后转错误消息"，把 ToolRetryMiddleware 放在列表更靠前（更内层）且配 on_failure="error"，让异常最终到达 ToolErrorMiddleware。

    21.5 工具增强类¶

    LLMToolSelectorMiddleware（LLM 预选工具）¶

    工具很多（10+）但每次只用得到几个时，先用一个（便宜的）LLM 筛选相关工具再调主模型——省 token、提高主模型专注度：

    from langchain.agents.middleware import LLMToolSelectorMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[tool1, tool2, tool3, tool4, tool5],
    middleware=[
        LLMToolSelectorMiddleware(
            model="openai:gpt-5.4-mini",
            max_tools=3,                  # 最多保留 3 个
            always_include=["search"],    # 始终保留的工具
        ),
    ],
)

    ProviderToolSearchMiddleware（Provider 服务端工具搜索）¶

    把选定工具放到 Provider 的服务端工具搜索后面，模型按需发现而不是一次性收到所有工具 schema：

    from langchain.agents.middleware import ProviderToolSearchMiddleware

agent = create_agent(
    model="anthropic:claude-opus-4-8",
    tools=[get_weather, lookup_order],
    middleware=[
        ProviderToolSearchMiddleware(searchable_tools=["lookup_order"]),
    ],
)

    ⚠️ 要求模型支持服务端工具搜索：Anthropic（Claude Sonnet 4+/Opus 4+/Haiku 4.5+）或 OpenAI（gpt-5.5+），其他 Provider 抛 ValueError。

    ShellToolMiddleware（持久 shell 会话）¶

    给 Agent 一个持久的 shell 会话执行命令（cd 状态、环境变量跨调用保持）：

    from langchain.agents.middleware import ShellToolMiddleware, HostExecutionPolicy

agent = create_agent(
    model="openai:gpt-5.5",
    middleware=[
        ShellToolMiddleware(policy=HostExecutionPolicy()),
    ],
)

    ⚠️ 安全：按部署环境选执行策略——HostExecutionPolicy（宿主机）、DockerExecutionPolicy（容器）、CodexSandboxExecutionPolicy（沙箱）。 ⚠️ 限制：持久 shell 目前不支持 interrupts（HITL）。

    FilesystemFileSearchMiddleware（文件搜索）¶

    提供 glob/grep 搜索工具，适合代码探索：

    from langchain.agents.middleware import FilesystemFileSearchMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    middleware=[
        FilesystemFileSearchMiddleware(
            root_path="/workspace",
            use_ripgrep=True,
        ),
    ],
)

    21.6 规划类¶

    TodoListMiddleware（任务清单）¶

    给 Agent 一个 write_todos 工具 + 规划引导提示，适合复杂多步任务、需要进度可见的长任务：

    from langchain.agents.middleware import TodoListMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[read_file, write_file, run_tests],
    middleware=[TodoListMiddleware()],
)

    可自定义 system_prompt（规划引导）和 tool_description（工具描述）。

    📌 Deep Agents v0.7 起默认不带此中间件，需显式 opt-in（见 deep-agents 教程第 1 章）。

    21.7 合规类¶

    PIIMiddleware（PII 检测）¶

    检测和处置对话中的个人身份信息（PII），支持多种策略：

    from langchain.agents.middleware import PIIMiddleware

agent = create_agent(
    model="openai:gpt-5.5",
    middleware=[
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        PIIMiddleware("credit_card", strategy="mask", apply_to_input=True),
    ],
)
    • 策略：redact（整块替换）、mask（部分掩码）、block（阻断）
    • 方向：apply_to_input（进模型前）/ apply_to_output（出模型后；langchain>=1.3.2 起连流式输出也脱敏）
    • 自定义 PII 类型：传 detector（正则字符串 / 编译正则 / 自定义函数）
    # 自定义检测器示例：API key
PIIMiddleware("api_key", detector=r"sk-[a-zA-Z0-9]{32}", strategy="block")

    用途：医疗/金融合规、客服日志脱敏、任何处理敏感用户数据的应用。

    21.8 测试类¶

    LLMToolEmulator（工具模拟）¶

    用 LLM 模拟工具执行——不真正调用工具，测试 Agent 决策逻辑：

    from langchain.agents.middleware import LLMToolEmulator

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_weather, search_database, send_email],
    middleware=[
        LLMToolEmulator(),  # Emulate all tools
    ],
)
    • tools=None：模拟所有工具；tools=[]：不模拟；指定列表：只模拟列表内的
    • 用途：外部工具不可用/昂贵时开发、原型验证、测试 Agent 行为

    21.9 来自 Deep Agents 的中间件¶

    这几个中间件定义在 deepagents 包里，但也能装进普通 create_agent——把 Deep Agents 的能力拆出来单用：

    FilesystemMiddleware（虚拟文件系统）¶

    提供 ls / read_file / write_file / edit_file 工具（完整工具表见 deep-agents 教程第 4 章）：

    from langchain.agents import create_agent
from deepagents.middleware.filesystem import FilesystemMiddleware

agent = create_agent(
    model="anthropic:claude-sonnet-4-6",
    middleware=[
        FilesystemMiddleware(
            backend=None,  # Optional: custom backend (defaults to StateBackend)
        ),
    ],
)

    SubAgentMiddleware（子代理）¶

    提供 task 工具委派子代理（完整内容见 deep-agents 教程第 10 章）：

    from deepagents.middleware.subagents import SubAgentMiddleware

agent = create_agent(
    model="anthropic:claude-sonnet-4-6",
    middleware=[
        SubAgentMiddleware(
            default_model="anthropic:claude-sonnet-4-6",
            default_tools=[],
            subagents=[
                {
                    "name": "weather",
                    "description": "This subagent can get weather in cities.",
                    "system_prompt": "Use the get_weather tool to get the weather in a city.",
                    "tools": [get_weather],
                },
            ],
        ),
    ],
)

    RubricMiddleware（评分标准迭代，Beta）¶

    声明"完成"的标准，Agent 自评迭代直到满足（需 deepagents>=0.6.5）：

    from deepagents import RubricMiddleware, create_deep_agent

agent = create_deep_agent(
    model="anthropic:claude-sonnet-4-6",
    middleware=[
        RubricMiddleware(model="anthropic:claude-haiku-4-5", max_iterations=3),
    ],
    checkpointer=InMemorySaver(),
)

    21.10 Provider 特定中间件¶

    按 Provider 优化的中间件（详见 integrations/middleware 文档）：

    Provider 中间件
    Anthropic prompt caching、bash tool、text editor、memory、file search
    AWS Bedrock prompt caching
    OpenAI content moderation（内容审核）

    21.11 选型速查¶

    我的需求 用
    长对话超上下文窗口 SummarizationMiddleware
    工具结果太长占上下文 ContextEditingMiddleware / FilesystemMiddleware
    防成本失控/死循环 ModelCallLimitMiddleware + ToolCallLimitMiddleware
    网络抖动、限流 ModelRetryMiddleware + ToolRetryMiddleware
    Provider 故障容灾 ModelFallbackMiddleware
    工具崩溃别拖垮 Agent ToolErrorMiddleware
    敏感操作要人批 HumanInTheLoopMiddleware（第 22 章）
    工具太多模型选花眼 LLMToolSelectorMiddleware / ProviderToolSearchMiddleware
    代码助手要搜文件 FilesystemFileSearchMiddleware / ShellToolMiddleware
    多步任务要规划 TodoListMiddleware
    合规脱敏 PIIMiddleware
    无真实工具测 Agent LLMToolEmulator

    组合原则¶

    1. 重试 + 错误处理：ToolRetry（内层）→ ToolError（外层），重试耗尽后转错误消息
    2. 限制 + 审批：先 limit 兜底成本，再 HITL 把关敏感操作
    3. middleware 列表顺序：靠前的更"外层"（先处理请求、后处理响应）

    📝 本章小结¶

    关键要点¶

    1. LangChain 内置 17+ 个 Provider 无关中间件，覆盖上下文/执行控制/可靠性/工具增强/规划/合规/测试七大类
    2. 上下文管理两件套：Summarization（LLM 摘要，保真）vs ContextEditing（清工具输出，免费）
    3. 可靠性四件套：ModelRetry / ToolRetry / ModelFallback / ToolError
    4. Deep Agents 的 Filesystem/SubAgent/Rubric 中间件可拆出来装进 create_agent
    5. 组合使用时注意 middleware 顺序（列表靠前 = 外层）
