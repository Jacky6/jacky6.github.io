    05. 高级特性¶

    对齐版本：langgraph v1.2（2026-05，含 v1.1 类型安全流式、v1.2 容错增强与事件流 API）

    子图（Subgraphs）¶

    子图允许你将复杂的图分解为可重用的模块。

    创建子图¶

    from langgraph.graph import StateGraph, START, END

# 子图的状态
class SubGraphState(TypedDict):
    value: int

# 创建子图
subgraph = StateGraph(SubGraphState)
subgraph.add_node("add_one", lambda s: {"value": s["value"] + 1})
subgraph.add_node("add_two", lambda s: {"value": s["value"] + 2})
subgraph.add_edge(START, "add_one")
subgraph.add_edge("add_one", "add_two")
subgraph.add_edge("add_two", END)

# 编译子图
compiled_subgraph = subgraph.compile()

    在主图中使用子图¶

    class MainState(TypedDict):
    value: int

main_graph = StateGraph(MainState)

# 将子图作为节点添加
main_graph.add_node("subgraph", compiled_subgraph)
main_graph.add_edge(START, "subgraph")
main_graph.add_edge("subgraph", END)

app = main_graph.compile()
result = app.invoke({"value": 0})  # value: 0 → 1 → 3

    状态映射¶

    # 子图状态和主图状态可能不同
class MainState(TypedDict):
    input_value: int
    output_value: int

class SubState(TypedDict):
    value: int

# 需要在进入和离开子图时转换状态
def to_subgraph_state(state: MainState) -> SubState:
    return {"value": state["input_value"]}

def from_subgraph_state(sub_result: SubState) -> MainState:
    return {"output_value": sub_result["value"]}

    并行执行¶

    自动并行¶

    # 当一个节点连接到多个节点时，这些节点会并行执行
graph.add_edge("start", "node_a")
graph.add_edge("start", "node_b")
graph.add_edge("start", "node_c")

# node_a, node_b, node_c 会并行执行

    配置并行度¶

    app = graph.compile(
    checkpointer=memory,
    # 配置最大并行节点数
    config={"recursion_limit": 10}
)

    等待所有并行节点完成¶

    # 所有并行节点完成后，才会执行下一个节点
graph.add_edge("node_a", "merge")
graph.add_edge("node_b", "merge")
graph.add_edge("node_c", "merge")

# merge 节点会收到所有并行节点的结果

    中断与恢复（Interrupt & Resume）¶

    设置中断点¶

    # 在特定节点前中断
app = graph.compile(
    checkpointer=memory,
    interrupt_before=["human_review"]
)

    运行到中断点¶

    # 运行会在 human_review 节点前停止
result = app.invoke({"value": 0}, config)

# 检查当前状态
snapshot = app.get_state(config)
print(f"下一个节点：{snapshot.next}")  # ['human_review']

    恢复执行¶

    # 更新状态（可选）
app.update_state(config, {"value": 100})

# 继续执行
result = app.invoke(None, config)

    人工审核模式¶

    class State(TypedDict):
    draft: str
    approved: bool

def generate_draft(state: State) -> dict:
    return {"draft": "AI generated content"}

def human_review(state: State) -> dict:
    # 这个节点会等待人工输入
    print(f"请审核：{state['draft']}")
    # 实际应用中，这里会等待用户输入
    return {"approved": True}

graph = StateGraph(State)
graph.add_node("generate", generate_draft)
graph.add_node("review", human_review)
graph.add_edge(START, "generate")
graph.add_edge("generate", "review")
graph.add_edge("review", END)

# 在 review 前中断，等待人工审核
app = graph.compile(
    checkpointer=memory,
    interrupt_before=["review"]
)

# 第一次运行：生成草稿后停止
app.invoke({}, config)

# 人工审核后，更新状态并继续
app.update_state(config, {"approved": True})
app.invoke(None, config)

    流式处理（Streaming）¶

    三套 API 并存：v1（stream_mode 原始模式）、v2（类型安全的统一输出，v1.1+）、v3 事件流（类型化投影，v1.2+ beta，官方推荐）。

    v1：stream_mode 原始模式¶

    # values 模式：完整的状态
for state in app.stream(input, stream_mode="values"):
    print(state)

# updates 模式：增量更新
for update in app.stream(input, stream_mode="updates"):
    print(update)

# messages 模式：LLM token 流
for message in app.stream(input, stream_mode="messages"):
    print(message)

# 其他模式：custom / checkpoints / tasks / debug
# 多模式同时订阅：stream_mode=["values", "updates", "messages"]

    v1 的输出格式随选项变化：单模式返回裸数据，多模式返回 (mode, data) 元组，子图返回 (namespace, data) 元组。

    v2：类型安全的统一输出（v1.1+）¶

    传 version="v2"，每个 chunk 都是统一的 StreamPart dict——不管几种模式、有没有子图：

    for chunk in graph.stream(inputs, stream_mode="updates", version="v2"):
    print(chunk["type"])  # "updates"
    print(chunk["ns"])    # () —— 子图事件时为 namespace 元组
    print(chunk["data"])  # {"node_name": {"key": "value"}}

    每种模式有对应的 TypedDict（ValuesStreamPart、UpdatesStreamPart、MessagesStreamPart 等，都从 langgraph.types 导入），支持编辑器类型收窄：

    for part in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["values", "updates", "messages", "custom"],
    version="v2",
):
    if part["type"] == "messages":
        # part["data"] 收窄为 MessagesStreamPart 的载荷类型
        message, metadata = part["data"]

    v2 同样适用于 invoke()：返回带 .value 和 .interrupts 属性的 GraphOutput 对象，声明了 Pydantic/dataclass 状态时自动强转类型。

    result = graph.invoke(inputs, config, version="v2")
result.value       # 最终状态（强转为你的状态类型）
result.interrupts  # 待处理的中断列表

    v3：事件流 API（v1.2+ beta，官方推荐）¶

    stream_events(version="v3") 返回一个运行流对象，暴露类型化投影——多个消费者可同时读取不同投影，互不消耗：

    stream = graph.stream_events({
    "messages": [{"role": "user", "content": "What is 42 * 17?"}],
}, version="v3")

for message in stream.messages:
    for token in message.text:
        print(token, end="", flush=True)

final_state = stream.output
    投影 用途
    stream.messages 聊天模型消息和 token 增量
    stream.values 状态快照，可等待最终值
    stream.output 等待最终输出
    stream.subgraphs 发现和观察嵌套图执行
    stream.interrupts / stream.interrupted HITL 中断载荷 / 是否暂停
    stream.extensions 自定义 transformer 的投影

    消息投影带类型化子投影：

    stream = graph.stream_events(input, version="v3")

for message in stream.messages:
    text = str(message.text)               # 完整文本（或直接迭代拿逐 token）
    usage = message.output.usage_metadata  # token 用量
    # message.reasoning  → 推理增量
    # message.tool_calls → 工具调用参数增量

    子图观察不用解析 namespace 字符串：

    stream = graph.stream_events(input, version="v3")

for subgraph in stream.subgraphs:
    print(subgraph.graph_name, subgraph.path)
    for message in subgraph.messages:
        print(message.text)

    选型建议：应用层代码用 v3 事件流（类型化、多投影并发）；需要底层原始模式访问时用 streaming；旧代码可留在 v1，逐步迁 v2。

    容错：重试、超时与错误恢复¶

    重试策略（RetryPolicy）¶

    from langgraph.types import RetryPolicy

# 节点级重试（推荐）
graph.add_node(
    "flaky_node",
    flaky_function,
    retry_policy=RetryPolicy(max_attempts=3),
)

# 图级默认：compile 时传入
app = graph.compile(retry_policy=RetryPolicy(max_attempts=3))

    retry_on 指定触发重试的异常类型；重试状态可通过 checkpoint 检查。

    节点超时（v1.2+）¶

    add_node 的 timeout= 限制单次尝试的运行时长，可传秒数、timedelta 或 TimeoutPolicy：

    from datetime import timedelta
from langgraph.types import TimeoutPolicy

# Simple wall-clock cap
builder.add_node("call_model", call_model, timeout=60)
builder.add_node("call_model", call_model, timeout=timedelta(minutes=2))

# Separate run and idle limits
builder.add_node(
    "call_model",
    call_model,
    timeout=TimeoutPolicy(run_timeout=120, idle_timeout=30),
)

    两种时限：

    • run_timeout：硬性墙钟上限，不因节点活动刷新
    • idle_timeout：空闲时限，节点有进展就重置计时（状态写入、流式输出、LLM token、工具调用等都算进展信号）
    # 严格空闲定义：只有显式 heartbeat 才重置计时
builder.add_node(
    "call_model",
    call_model,
    timeout=TimeoutPolicy(idle_timeout=30, refresh_on="heartbeat"),
)

# 长任务手动发心跳
from langgraph.runtime import Runtime

async def long_running_node(state: State, runtime: Runtime) -> State:
    for batch in fetch_batches():
        process(batch)
        runtime.heartbeat()  # 重置空闲时钟（非超时尝试中是 no-op）
    return {"result": "done"}

    超时时抛出 NodeTimeoutError，清除该次尝试的写入，交给重试策略决定是否重试。

    ⚠️ 节点超时只对异步节点生效；同步节点设 timeout 会在编译期被拒绝。包装阻塞 IO 用异步节点 + asyncio.to_thread。

    节点级错误处理器（v1.2+）¶

    error_handler= 在节点失败且重试耗尽后运行，可更新状态、用 Command 路由到其他节点——适合 Saga/补偿模式：

    from langgraph.errors import NodeError
from langgraph.types import Command, RetryPolicy
from langgraph.graph import StateGraph, START
from typing_extensions import TypedDict

class State(TypedDict):
    status: str

def charge_payment(state: State) -> State:
    raise RuntimeError("payment gateway timeout")

def payment_error_handler(state: State, error: NodeError) -> Command:
    return Command(
        update={"status": f"compensated: {error.error}"},
        goto="finalize",
    )

def finalize(state: State) -> State:
    return state

graph = (
    StateGraph(State)
    .add_node(
        "charge_payment",
        charge_payment,
        retry_policy=RetryPolicy(max_attempts=3, retry_on=ConnectionError),
        error_handler=payment_error_handler,
    )
    .add_node("finalize", finalize)
    .add_edge(START, "charge_payment")
    .compile()
)

    要点：

    • NodeError 是 frozen dataclass：error.node（失败节点名）+ error.error（异常）；通过类型注解注入，签名可简化为 (state) 或 (state, runtime)
    • 无重试策略时 handler 立即触发；重试和补偿逻辑解耦配置
    • 失败来源会被 checkpoint——中断/崩溃后恢复时 handler 看到相同的 NodeError
    • ⚠️ 节点内的 interrupt() 不会进错误处理器（它走 GraphBubbleUp 暂停机制）
    • 子图未处理异常会冒泡到父节点，父节点有 handler 则由它处理

    图级默认值：set_node_defaults（v1.2+）¶

    不想每个 add_node 都重复 retry_policy=/error_handler=/timeout=？一次性设全图默认：

    from langgraph.errors import NodeError
from langgraph.types import RetryPolicy, TimeoutPolicy

def default_error_handler(state: State, error: NodeError) -> State:
    return {"status": f"handled: {error.error}"}

graph = (
    StateGraph(State)
    .set_node_defaults(
        retry_policy=RetryPolicy(max_attempts=3),
        error_handler=default_error_handler,
        timeout=TimeoutPolicy(run_timeout=30),
    )
    .add_node("step_a", step_a)
    .add_node("step_b", step_b)
    .add_edge(START, "step_a")
    .compile()
)
    • add_node 的显式参数覆盖默认值；默认在 compile() 时解析，set_node_defaults 调用顺序无关
    • 适用性：retry_policy/timeout 对 handler 节点也生效；error_handler/cache_policy 不作用于 handler 节点（handler 不能捕获自己、结果不应缓存）

    优雅停机（v1.2+）¶

    协作式停止进行中的运行：当前 superstep 完成后停下，保存可恢复的 checkpoint（适合 SIGTERM 处理、资源回收）：

    from langgraph.runtime import RunControl
from langgraph.errors import GraphDrained

control = RunControl()

# In a signal handler or supervisor:
# control.request_drain("sigterm")

try:
    result = graph.invoke(inputs, config, control=control)
except GraphDrained as e:
    # The graph stopped early and saved a checkpoint.
    print(f"Drained: {e.reason}")

# 恢复：同一 thread_id
result = graph.invoke(None, config)

    语义：drain 在 superstep 之间协作生效，不抢占正在运行的节点；正在重试的节点跑完重试循环；子图的 drain 冒泡到父图。节点内可读 runtime.drain_requested 提前跳过昂贵工作。

    存储（Store）¶

    使用 Store 持久化数据¶

    from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

def read_from_store(state: State, config: dict) -> dict:
    store = get_store()
    value = store.get(("user_data",), config["user_id"])
    return {"stored_value": value}

def write_to_store(state: State, config: dict) -> dict:
    store = get_store()
    store.put(("user_data",), config["user_id"], {"data": state["value"]})
    return {}

app = graph.compile(store=store)

    命名空间¶

# 读取

    命令模式（Command）¶

    使用 Command 控制流程¶

    from langgraph.types import Command

def conditional_node(state: State) -> Command:
    if state["value"] > 10:
        return Command(
            goto="high_path",
            update={"value": state["value"] * 2}
        )
    else:
        return Command(
            goto="low_path",
            update={"value": state["value"] + 1}
        )

    发送到特定节点¶

    from langgraph.types import Send

def fanout_node(state: State) -> list[Command]:
    return [
        Send("process_node", {"item": item})
        for item in state["items"]
    ]

    功能型 API（Functional API）¶

    使用 @entrypoint 装饰器¶

    from langgraph.func import entrypoint

@entrypoint(checkpointer=memory)
def my_workflow(input: dict) -> dict:
    # 直接编写工作流逻辑
    step1 = process(input)
    step2 = transform(step1)
    return finalize(step2)

    使用 @task 装饰器¶

    from langgraph.func import task

@task
def process(data: dict) -> dict:
    return {"processed": data}

@task
def transform(data: dict) -> dict:
    return {"transformed": data}

@entrypoint
def workflow(input: dict) -> dict:
    p = process(input)
    t = transform(p)
    return t

    使用回调¶

    from langchain_core.callbacks import BaseCallbackHandler

class MyCallback(BaseCallbackHandler):
    def on_chain_start(self, serialized, inputs, **kwargs):
        print(f"开始：{serialized.get('name')}")

    def on_chain_end(self, outputs, **kwargs):
        print(f"结束，输出：{outputs}")

app = graph.compile()
result = app.invoke(input, config={"callbacks": [MyCallback()]})

    最佳实践总结¶

    ✅ 推荐¶

    1. 使用子图模块化复杂逻辑
    2. 在需要人工审核时使用中断点
    3. 使用流式模式提升用户体验
    4. 为昂贵操作添加缓存
    5. 使用 Store 持久化用户数据

    ❌ 避免¶

    1. 避免状态过大
    2. 避免无限循环（始终设置退出条件）
    3. 避免在节点中使用全局变量
    4. 避免忽略错误处理
