    🧠 核心概念速记¶

    概念 一句话解释 类比
    Agent 有控制循环、能用工具、有记忆的 LLM 系统 不只是大脑，是完整的人
    ReAct Thought → Action → Observation 循环 边走边看
    CoT 让模型显式写出推理步骤 把心算变成笔算
    Plan-and-Execute 先全局规划，再逐步执行 先看导航再开车
    ToT 多路径探索，选最优 并行试错
    Self-Consistency 多次采样取共识 三个臭皮匠
    Memory 三层 短期(窗口) / 会话(摘要) / 长期(向量库) 工作记忆 / 日记 / 图书馆
    Supervisor LLM 动态分配任务给 Worker 项目经理
    MCP 标准化协议接入外部工具 USB 接口
    Human-in-Loop 关键操作需人工审批 领导签字

    💡 高频考点一句话回答¶

    Q: "ReAct 的缺点是什么？"¶

    A: 串行导致慢；上下文窗口限制；错误容易传播；难以并行独立任务。

    Q: "如何提高 Tool Calling 的准确率？"¶

    A: 工具描述要精确（含示例）；减少工具数量（相关性筛选）；用 Few-shot 示例；验证模型输出参数。

    Q: "Agent 成本太高怎么优化？"¶

    A: ① 用轻量模型做路由/分类 ② 缓存重复调用 ③ 减少不必要的工具调用预判 ④ 压缩/摘要历史消息 ⑤ 降低 Self-Consistency 采样次数

    Q: "Memory 检索不准怎么办？"¶

    A: ① 优化 embedding 模型 ② 增加 metadata 过滤 ③ 混合检索（向量 + BM25） ④ 定期清理/更新记忆 ⑤ 增加重排序（reranker）步骤

    Q: "多 Agent 怎么避免冲突？"¶

    A: ① 明确职责边界 ② Supervisor 统一调度 ③ 共享 State 需加锁/版本控制 ④ 任务级隔离

    Q: "Self-Reflection 和普通的 error handling 有什么区别？"¶

    A: Error handling 是处理技术错误（网络超时、API 失败）；Self-Reflection 是评估输出质量（答案对不对、好不好），属于认知层面的纠错。

    Q: "Agent 陷入循环怎么办？"（高频必考）¶

    A: 五层防御：① MAX_ITER（10-15）② 重复动作检测（deque 窗口，连续 3 次相同）③ Token 预算 ④ 超时 60s ⑤ 状态收敛检测。检测到循环后尝试恢复：换工具 / 问用户 / 最佳猜测。

    6. Loop 检测（核心逻辑，面试精简版）¶

    from collections import deque
class LoopDetector:
    def __init__(self, window=3):
        self.history = deque(maxlen=window)
    def add(self, action, inp):
        self.history.append((action, str(inp)))
    def is_looping(self):
        if len(self.history) < self.history.maxlen: return False
        return len(set(h[0] for h in self.history)) == 1

# 使用：detector.add(action, inp); if detector.is_looping(): return "Loop!"

    7. MCP Client 手搓（6 个核心方法）¶

    import json, subprocess

class MCPClient:
    def start(self): self.process = subprocess.Popen(cmd, stdin=PIPE, stdout=PIPE, text=True)
    def _send(self, msg):
        body = json.dumps(msg); self.process.stdin.write(f"Content-Length: {len(body)}\r\n\r\n{body}"); self.process.stdin.flush()
    def _read(self):
        header = ""
        while True:
            line = self.process.stdout.readline()
            if line == "\r\n" or line == "\n": break
            header += line
        cl = int(header.split("Content-Length:")[1].strip())
        return json.loads(self.process.stdout.read(cl))
    def _request(self, method, params=None):
        self.id += 1; self._send({"jsonrpc": "2.0", "id": self.id, "method": method, "params": params or {}})
        r = self._read(); return r.get("result", {})
    def initialize(self): self._request("initialize", {...}); self._send({"jsonrpc":"2.0","method":"notifications/initialized"})
    def list_tools(self): return self._request("tools/list", {}).get("tools", [])
    def call_tool(self, name, args): return self._request("tools/call", {"name": name, "arguments": args})

    谈 Memory "用向量数据库存记忆" "记忆分三层：短期靠滑动窗口控制 token，会话靠LLM 摘要提炼关键信息，长期靠向量检索 + 元数据过滤，还要有记忆巩固机制定期整理"
    谈评估 "人工看看就行" "评估分三层：离线基准测试（Golden Set 跑回归）、LLM-as-Judge（强模型给弱模型打分）、在线监控（采样 + 用户反馈），形成闭环"
    谈安全 "加个审核就行" "安全是纵深防御：输入层防注入和敏感信息，运行时控 Token 预算和速率，工具层做权限和沙箱，输出层做事实核查和脱敏，关键操作引入 Human-in-the-Loop"

    ⚡ 快速问答¶

    Q: LangGraph vs LangChain? A: LangChain 是工具链（串联工具），LangGraph 是状态机（有向图编排）。Agent 场景用 LangGraph 更合适，因为天然支持循环和分支。

    Q: 什么时候不用 Agent？ A: 简单问答、纯信息检索、格式化任务。Agent 的开销（多轮 LLM 调用）不值得。

    Q: Agent 最常见的坑？ A: 1. 工具描述不精确导致调用错误 2. 无限循环 3. 上下文爆炸（token 太多）4. 错误传播 5. 没有评估体系

    Q: 如何调试 Agent？ A: 1. Trace 每一步（Thought/Action/Observation）2. 用 LangSmith 可视化执行流 3. 单元测试每个节点 4. 回放历史对话

    Q: Agent 未来方向？ A: 1. 更长上下文窗口 2. 更好的工具学习 3. 多模态 Agent 4. 自主学习/改进 5. 标准化协议（如 MCP）

    Q: MCP 协议的传输格式是什么？ A: Content-Length: N\r\n\r\n{json-body}，基于 JSON-RPC 2.0。initialize → tools/list → tools/call 是核心流程。

    Q: MCP 和 Function Calling 有什么区别？ A: Function Calling 是 LLM 单次调用工具（模型决定调哪个）；MCP 是长期连接一个 Server，动态发现工具列表，支持跨进程/跨语言通信。MCP 更像是工具集成的基础设施。
