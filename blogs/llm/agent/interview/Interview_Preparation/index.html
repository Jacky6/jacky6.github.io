    AI Agent 面试突击手册¶

    基于 Wiki 教程提炼的面试高频考点 + 手搓代码方案。

    一、面试高频问题 TOP 20¶

    🔥 必考题¶

    Q1: "你来讲讲 ReAct 是什么，手写一个 ReAct 循环"¶

    这是最常考的一道题，也是面试的核心筛选题。

    答题要点：

    1. ReAct = Reasoning + Acting，核心思想是 Thought → Action → Observation 循环
    2. 每轮 LLM 输出包含 Thought（思考）、Action（调用什么工具）、Action Input（参数）
    3. 执行工具后把 Observation 拼回对话历史，继续下一轮
    4. 遇到 Final Answer 则终止循环
    5. 必须有最大迭代次数防止死循环

    手搓代码（面试精简版，30 行内）：

    def react(agent_llm, tools, question, max_iter=5):
    """手写 ReAct 循环"""
    history = ""
    for _ in range(max_iter):
        prompt = f"""Answer the question using tools.
Tools: {describe_tools(tools)}
Question: {question}
{history}
Thought:"""
        resp = agent_llm(prompt).text
        if "Final Answer:" in resp:
            return resp.split("Final Answer:")[-1].strip()
        action, inp = parse_action(resp)
        obs = tools[action](**inp)
        history += f"\n{resp}\nObservation: {obs}"
    return "Max iterations reached"

    加分项： - 提到 LangGraph 的实现：StateGraph + agent_node + tool_node + 条件边 - 提到 llm.bind_tools(tools) 是现代框架的标准做法 - 提到工具调用失败时的恢复策略（返回错误信息让模型重试）

    Q2: "ReAct 和 Plan-and-Execute 有什么区别？什么时候用哪个？"¶

    答题要点：

    维度 ReAct Plan-and-Execute
    思维方式 边想边做，逐步推进 先全局规划，再逐步执行
    适用场景 交互式、需实时反馈 复杂多步任务、可预规划
    上下文压力 较小（只维护当前轮） 较大（需维护完整计划）
    灵活性 高（随时调整方向） 中（需动态重规划机制）
    典型用例 客服问答、搜索问答 代码生成项目、数据分析流水线

    关键洞察：

    ReAct 像走路——走一步看一步；Plan-and-Execute 像导航——先看地图再走。 复杂任务最好的方案是 Plan + ReAct：先规划大方向，每个子任务用 ReAct 执行。

    Q3: "CoT、ToT、Self-Consistency 分别是什么？什么时候用？"¶

    一句话回答： - CoT：让模型一步步想（线性）。适合需要逻辑推导的题目。 - ToT：在关键节点探索多条思路，选最优（树状）。适合创意、策略等有多条可行路径的问题。 - Self-Consistency：同样的问题多采样几次，取共识答案。适合对准确性要求极高的场景。

    成本排序：CoT < Self-Consistency < ToT（通常）

    面试加分：提到 Self-Consistency 可以用"轻量模型多次采样 + 重模型验证"来优化成本。

    Q4: "如何设计 Agent 的记忆系统？"¶

    三层架构（这是标准答案）：

    短期记忆（Short-term）  →  当前轮次的上下文窗口
会话记忆（Session）     →  本次对话的摘要/关键信息
长期记忆（Long-term）   →  跨会话的知识库（向量数据库）

    关键实现细节： - 短期：滑动窗口 / 摘要压缩，控制 token 成本 - 会话：LLM 自动提取关键信息写入 - 长期：ChromaDB / Milvus 等向量库，embedding + 语义检索 - 记忆巩固：定期把会话记忆提炼为长期记忆（类似人脑的睡眠巩固）

    手搓向量检索（面试可能要求）：

    import chromadb

class MemoryStore:
    def __init__(self, path="./memory_db"):
        client = chromadb.PersistentClient(path)
        self.collection = client.get_or_create_collection("memories")
        self.id_counter = 0

    def store(self, content: str, metadata: dict = None):
        self.collection.add(
            documents=[content],
            ids=[str(self.id_counter)],
            metadatas=[metadata or {}],
        )
        self.id_counter += 1

    def retrieve(self, query: str, top_k: int = 3) -> list:
        results = self.collection.query(
            query_texts=[query],
            n_results=top_k,
        )
        return results["documents"][0]

    Q5: "Agent 陷入循环，一直进行同一个操作怎么办？"（高频必考）¶

    面试官可能追问： - "为什么会循环？" - "检测到循环后怎么处理？" - "你在 LangGraph 里怎么实现？"

    标准回答（见 Interview_Loop_Prevention.md 完整文档）：

    "我在 Agent 设计中做了五层防御：

第一层：最大迭代次数（10-15 次）—— 硬兜底
第二层：重复动作检测（deque 窗口，连续 3 次相同 action）—— 识别循环模式
第三层：Token 预算控制 —— 防止 token 爆炸
第四层：超时机制（60 秒）—— 防止永远跑不完
第五层：状态收敛检测 —— 判断 Agent 是否在原地踏步

五层配合，层层兜底。检测到循环后不是直接报错，而是
尝试恢复：换工具、问用户、或给出最佳猜测。"

    手搓代码（核心检测逻辑，30 行）：

    from collections import deque

class LoopDetector:
    """循环检测器"""
    def __init__(self, window_size=3):
        self.history = deque(maxlen=window_size)

    def add(self, action, action_input):
        self.history.append((action, action_input))

    def is_looping(self):
        if len(self.history) < self.history.maxlen:
            return False
        # 最近 N 次 action 全部相同
        actions = [h[0] for h in self.history]
        return len(set(actions)) == 1

# 使用
detector = LoopDetector(window_size=3)
for step in range(MAX_ITER):
    resp = llm(prompt)
    action, inp = parse_action(resp)

    detector.add(action, str(inp))
    if detector.is_looping():
        return f"Loop detected: repeating '{action}'. Trying different approach."

    obs = tools[action](**inp)
    history += f"\n{resp}\nObservation: {obs}"

    为什么 Agent 会循环？（面试官可能追问）：

    原因 例子 对应防御
    工具调用失败后重试同一工具 参数不对→报错→不调整参数直接重试 重复动作检测
    工具返回信息不足以推进 返回内容为空，模型无法推导下一步 状态收敛检测
    Prompt 指令冲突 既要 A 又要 B，来回摇摆 任务前置验证
    没有明确终止条件 Agent 不知道什么时候该停 MAX_ITER
    多 Agent 互相等待 A 等 B，B 等 A 超时 + 死锁检测

    Q7: "Tool Calling 的原理是什么？"¶

    要点： 1. 开发者定义工具 schema（名称、描述、参数 JSON Schema） 2. 工具定义随 System Prompt 一起发送给 LLM 3. LLM 判断需要调用工具时，输出结构化 JSON（工具名 + 参数） 4. 框架解析 JSON，执行对应函数 5. 执行结果作为 Observation 送回给 LLM 6. LLM 基于结果生成最终回答

    关键细节： - OpenAI 用 function_calling，Anthropic 用 tool_use block - 现代框架统一为 llm.bind_tools(tools) → 自动处理各 provider 差异 - 工具描述质量直接影响调用准确率

    Q8: "什么是 MCP？手搓一个 MCP Client"¶

    要点： - MCP（Model Context Protocol）是 Anthropic 提出的标准化协议 - 解决的问题：以前每个 AI 应用都要单独写集成代码接入数据源/工具 - MCP 的方案：定义统一协议，Server 端按协议暴露工具，Client 端按协议调用 - 类比：MCP 之于 AI 工具集成 = USB 之于外设

    面试一句话：MCP 让工具集成从"一对一定制"变成"即插即用"。

    手搓 MCP Client（高频考题）：

    import json, subprocess, threading

class MCPClient:
    """从零实现的 MCP Client（JSON-RPC over stdio）"""

    def __init__(self, command, args=None):
        self.command = command
        self.args = args or []
        self.process = None
        self.request_id = 0

    def start(self):
        self.process = subprocess.Popen(
            [self.command] + self.args,
            stdin=subprocess.PIPE, stdout=subprocess.PIPE,
            stderr=subprocess.PIPE, text=True, bufsize=1,
        )

    def stop(self):
        if self.process and self.process.poll() is None:
            self.process.terminate()
            self.process.wait(timeout=5)

    def _send(self, msg):
        """发送 JSON-RPC 消息（Content-Length 头 + body）"""
        body = json.dumps(msg, ensure_ascii=False)
        self.process.stdin.write(f"Content-Length: {len(body)}\r\n\r\n{body}")
        self.process.stdin.flush()

    def _read_response(self):
        """读取响应：先读头，再按 Content-Length 读 body"""
        header = ""
        while True:
            line = self.process.stdout.readline()
            if line == "" or line == "\r\n" or line == "\n":
                break
            header += line

        content_length = 0
        for h in header.strip().split("\r\n"):
            if h.startswith("Content-Length:"):
                content_length = int(h.split(":")[1].strip())

        body = self.process.stdout.read(content_length)
        return json.loads(body)

    def _request(self, method, params=None):
        """发送请求并等待响应"""
        self.request_id += 1
        self._send({
            "jsonrpc": "2.0", "id": self.request_id,
            "method": method, "params": params or {},
        })
        resp = self._read_response()
        if "error" in resp:
            raise RuntimeError(resp["error"]["message"])
        return resp.get("result", {})

    def initialize(self):
        """MCP 握手"""
        result = self._request("initialize", {
            "protocolVersion": "2024-11-05",
            "capabilities": {"tools": {}},
            "clientInfo": {"name": "my-client", "version": "1.0"},
        })
        self._send({"jsonrpc": "2.0", "method": "notifications/initialized"})
        return result

    def list_tools(self):
        """获取工具列表"""
        return self._request("tools/list", {}).get("tools", [])

    def call_tool(self, name, arguments):
        """调用工具"""
        result = self._request("tools/call", {
            "name": name, "arguments": arguments,
        })
        return [c["text"] for c in result.get("content", []) if c.get("type") == "text"]

# 使用
client = MCPClient("python", ["my_server.py"])
client.start()
client.initialize()
for t in client.list_tools():
    print(f"{t['name']}: {t['description']}")
result = client.call_tool("search_docs", {"query": "AI Agent"})
client.stop()

    考点拆解： 1. 传输协议：MCP 用 Content-Length: N\r\n\r\n{json} 格式，不是纯换行分隔 2. JSON-RPC 2.0：request 有 id，response 用相同 id 匹配；notification 没有 id（不需要响应） 3. 核心流程：initialize → tools/list → tools/call 4. 进程管理：subprocess.Popen + stdin/stdout 管道 + stderr 后台读取防阻塞

    Q10: "如何评估一个 Agent 的好坏？"¶

    三个维度：

    1. 任务质量：准确率、完整性、有用性（LLM-as-Judge 或人工评分）
    2. 系统指标：延迟、Token 消耗、成本、错误率
    3. 用户体验：用户满意度、任务完成率、NPS

    具体方案： - Golden Set：预定义的测试用例集，跑回归测试 - LLM-as-Judge：用更强的模型给输出打分 - A/B Testing：对比不同方案的线上表现

    🧪 场景 1：从零搭建一个 Agent 框架¶

    面试官可能说："不用任何框架，从零实现一个能调用工具的 Agent。"

    import json

class SimpleAgent:
    """从零实现的 Agent，支持工具调用"""

    def __init__(self, llm, tools: dict, max_steps=5):
        self.llm = llm
        self.tools = tools
        self.max_steps = max_steps

    def run(self, user_input: str) -> str:
        messages = [{"role": "user", "content": user_input}]

        # 构建工具描述
        tool_desc = "\n".join(
            f"  {name}: {desc}" for name, (desc, _) in self.tools.items()
        )

        system = f"""You are a helpful assistant. You have access to these tools:
{tool_desc}

To use a tool, respond with:
TOOL_CALL: <tool_name>
TOOL_INPUT: <json>

When done, respond with:
FINAL: <your answer>
"""
        messages.insert(0, {"role": "system", "content": system})

        for step in range(self.max_steps):
            # 1. LLM 回复
            response = self.llm(messages)

            # 2. 判断类型
            if response.startswith("FINAL:"):
                return response[6:].strip()

            if response.startswith("TOOL_CALL:"):
                lines = response.split("\n")
                tool_name = lines[0].replace("TOOL_CALL:", "").strip()
                tool_input = json.loads(lines[1].replace("TOOL_INPUT:", "").strip())

                # 3. 执行工具
                if tool_name in self.tools:
                    _, func = self.tools[tool_name]
                    result = func(**tool_input)
                else:
                    result = f"Error: Unknown tool '{tool_name}'"

                # 4. 追加到对话
                messages.append({"role": "assistant", "content": response})
                messages.append({"role": "tool", "content": str(result)})

        return "Max steps reached without a final answer."

    考点： - 工具描述怎么构造 → 影响 LLM 的选择准确性 - 循环终止条件 → max_steps + Final 检测 - 错误处理 → 工具不存在/执行失败怎么办 - 消息格式 → 正确维护 conversation history

    class MemoryAgent(SimpleAgent):
    """带长期记忆的 Agent"""

    def __init__(self, llm, tools, memory_store, max_steps=5):

Relevant past memories:
{memory_context}

[tools description...]
"""
        # 3. 正常执行
        messages = [{"role": "system", "content": system_with_memory}]
        # ... (同上 SimpleAgent 的 run 逻辑)

        result = super().run(user_input)  # 简化，实际需要注入 memory_context

        # 4. 存储重要信息到长期记忆
        self.memory.store(f"User asked: {user_input} → Answer: {result[:200]}")

        return result

    🧪 场景 3：实现 CoT + Self-Consistency¶

    def self_consistency_cot(llm, question, n=5, temperature=0.7):
    """Self-Consistency + Chain-of-Thought"""
    answers = []

    for _ in range(n):
        response = llm(
            f"{question}\nLet's think step by step. Final Answer:",
            temperature=temperature,
        )
        # 提取 Final Answer
        if "Final Answer:" in response:
            answers.append(response.split("Final Answer:")[-1].strip())
        else:
            answers.append(response.strip()[-50:])

    # 投票取共识
    from collections import Counter
    best, count = Counter(answers).most_common(1)[0]

    return {
        "answer": best,
        "consensus": count / n,
        "all_answers": answers,
    }

    class Supervisor:
    """简单的任务分发 Supervisor"""

    def __init__(self, llm, workers: dict):
        self.llm = llm
        self.workers = workers  # {"name": (description, agent)}

    def dispatch(self, task: str) -> dict:
        # 1. 选择 worker
        worker_desc = "\n".join(
            f"- {name}: {desc}" for name, (desc, _) in self.workers.items()
        )

        choice = self.llm(f"""
Task: {task}
Available workers: {worker_desc}
Which worker should handle this? Reply with ONE name.
""").text.strip()

        # 2. 分发给对应 worker
        if choice in self.workers:
            _, agent = self.workers[choice]
            return {"worker": choice, "result": agent.run(task)}

        return {"worker": None, "error": f"No suitable worker for: {task}"}

    def execute_plan(self, plan: list[dict]) -> list[dict]:
        """执行一个计划（多步骤）"""
        results = {}
        for step in plan:
            task_with_context = step["description"]
            # 注入依赖步骤的结果
            for dep_id in step.get("depends_on", []):
                if dep_id in results:
                    task_with_context += f"\nDependency result: {results[dep_id]}"

            outcome = self.dispatch(task_with_context)
            results[step["id"]] = outcome.get("result", "")

        return results

    三、实战场景题¶

    场景 A："设计一个代码审查 Agent"¶

    回答框架：

    1. Perception: 接收代码文件/PR diff
2. Memory: 加载项目编码规范、历史审查记录
3. Reasoning: CoT（逐步检查代码质量、安全性、性能）
4. Tool Use: 
   - read_file（读取代码）
   - run_linter（运行静态分析）
   - run_test（运行测试）
5. Planning: 
   - Step 1: 读取代码
   - Step 2: Lint 检查
   - Step 3: 代码审查（LLM）
   - Step 4: 生成修复建议
6. Self-Reflection: Critique 自己的审查结果
7. Safety: 只读操作，不修改代码
8. Output: 结构化审查报告

    场景 B："设计一个自动数据分析 Agent"¶

    1. User: "分析这份销售数据，找出下降原因"
2. Agent 规划:
   - Load data → Explore → Analyze → Visualize → Report
3. 工具链:
   - read_csv / read_excel
   - python_repl（pandas 分析）
   - chart_generator
4. Self-Reflection: 检查分析结论是否有数据支撑
5. Output: 图表 + 文字报告

    场景 C："如何处理 Agent 调用工具失败的情况？"¶

    标准答案：

    def robust_tool_call(tool_name, tool_func, tool_input, max_retries=2):
    """带重试的工具调用"""
    for attempt in range(max_retries + 1):
        try:
            return tool_func(**tool_input)
        except Exception as e:
            if attempt < max_retries:
                # 返回错误给 LLM，让它调整参数重试
                return f"Error: {e}. Please check your input and try again."
            return f"Error: {e}. Max retries reached."

    要点： 1. 工具失败不应让 Agent 崩溃 2. 错误信息要返回给 LLM，让它调整策略 3. 限制最大重试次数 4. 对不可恢复的错误，Agent 应该明确告知用户

    四、常见面试陷阱¶

    ❌ 陷阱 1："你用的是 LangGraph 还是自己写的？"¶

    正确回答：

    "生产环境用 LangGraph 做编排，因为它内置了状态管理、持久化、条件路由等能力。 但我从零实现过 ReAct/CoT 的核心逻辑，理解底层原理。 LangGraph 本质就是一个 StateGraph + 节点执行器，核心思想是 有向图 + 条件边。"

    ❌ 陷阱 2："Agent 和普通的 prompt 有什么区别？"¶

    正确回答：

    "Prompt 是一次性的问答，Agent 是循环系统。Agent 能： 1. 使用工具（不只是生成文本） 2. 维护状态（记忆） 3. 自主决策（下一步做什么） 4. 自我纠正（反思和改进）

    本质区别：Agent 有 控制循环（Control Loop），能自主推进任务。"

    ❌ 陷阱 3："多 Agent 协作会不会效率很低？"¶

    正确回答：

    "看架构： - 并行（Parallel）：独立任务并行执行，效率高 - 串行（Sequential）：有依赖关系，只能串行 - Supervisor：Supervisor 本身有一次 LLM 调用开销

    优化手段： 1. 能并行的尽量并行 2. Supervisor 用轻量模型 3. 关键节点缓存结果

    多 Agent 的价值不在速度，在于任务隔离、专业化、可维护性。"

核心是三层架构：思维层（CoT/ReAct 推理）、行动层（工具调用/自我纠错）、
任务层（规划/多体协作）。

安全方面有输入防护、输出审查、权限控制、Human-in-the-Loop 审批。
