    AI Agent Planning

    ****# AI Agent 规划能力：ReAct、CoT、Plan-and-Execute 的区别

    来源: 一文看懂 AI Agent 的规划能力 整理日期: 2026-04-23

    核心观点¶

    ReAct、CoT、Plan-and-Execute 根本不在同一个层级上：

    范式 一句话 控制粒度 关注点
    CoT 把思考过程写出来 推理步骤层 答案怎么推出来
    ReAct 边想边做，根据反馈调整 下一步动作层 当前局面下接下来做什么
    Plan-and-Execute 先规划全局，再组织执行 全局任务结构层 整件事怎么拆、怎么排、怎么推进

    CoT（Chain-of-Thought）¶

    是什么¶

    让模型在回答前先把推理链展开，提升推理深度和复杂问题求解能力。

    工作原理¶

    模型内部：步骤1 → 步骤2 → 步骤3 → 结论

    优势¶

    • 减少跳步、偷懒、算错
    • 在数学、逻辑、多跳推理任务上表现明显提升
    • 把"脑内推理"显式化

    局限¶

    • 停留在"想"的阶段，不连接真实环境
    • 不涉及外部工具调用
    • 没有显式的任务拆解、状态管理和动态重排

    ❌ 常见误区¶

    以为加一句"请一步一步思考"就有规划能力了——这最多让回答更像经过思考，不代表具备执行组织能力。

    ReAct（Reasoning + Acting）¶

    是什么¶

    将 Reasoning + Acting 绑在一起，让模型边想边做。

    工作流程¶

    思考 → 行动（调用工具）→ 观察（拿到反馈）→ 再思考 → 再行动 → ...

    优势¶

    • 把工具使用纳入决策链路
    • 能根据反馈修正行为（换关键词、换策略、换路径）
    • 不再是一条路走到黑

    局限¶

    • 只关心"下一步怎么办"，不关心全局任务安排
    • 长任务容易出现：
    • 路径漂移：做着做着偏题了
    • 成本失控：工具乱调、上下文越来越长
    • 局部正确、全局失败：每一步都努力，但没完成目标

    类比¶

    ReAct 像一个经验丰富的现场执行者，能根据眼前情况不断调整动作，但不一定会先画出完整作战图。

    Plan-and-Execute¶

    是什么¶

    先生成计划，再按计划执行，必要时重规划——将系统拆为独立的规划器和执行器。

    工作流程¶

    规划器（拆任务 → 排顺序）
    ↓
执行器（按步骤调用工具）
    ↓
反馈 → 重规划（必要时）→ 继续执行

    适用场景¶

    类型 示例
    长任务 写研究报告、竞品分析、多阶段业务流程
    多子任务 查资料 → 生成表格 → 写总结 → 输出邮件
    高成本任务 有计划层后可将执行阶段交给轻量模型

    优势¶

    • 比纯 ReAct 更省 token
    • 具备更强的"任务组织能力"
    • 适合复杂目标

    风险与对策¶

    风险 对策
    初始计划可能不对 加入 re-planning 机制
    计划太僵硬，执行越跑越偏 执行一段后重新审视：原计划是否成立、是否需要调整步骤、新增/删除子任务

    关键点¶

    Plan-and-Execute 不是写死的流程图，而是"显式规划 + 动态修正"的任务管理方式。

    场景选择指南¶

    场景 推荐方案 理由
    单轮复杂推理（风险研判、策略分析、复杂问答） CoT 重点是提升思考质量，不需要复杂 Agent 编排
    频繁与环境交互（网页浏览、知识检索、工具调用） ReAct 适合"先试一下，再根据结果修正"的过程
    长链路、多阶段、多目标复杂任务（深度研究、自动化运营、复杂工单流转） Plan-and-Execute 需要组织整个过程，而非某一步会不会做

    成熟方案：三层叠加¶

    现实中的成熟 Agent 系统不是三选一，而是叠起来用：

    ┌─────────────────────────────────────────┐
│  Plan-and-Execute（全局调度）            │
│  管任务拆解和重规划                       │
├─────────────────────────────────────────┤
│  ReAct（动态交互）                       │
│  根据反馈决定下一步行动                    │
├─────────────────────────────────────────┤
│  CoT（局部推理）                         │
│  提升每一步的思考质量                      │
└─────────────────────────────────────────┘

    总结¶

    层级 效果 比喻
    CoT 让模型更会想 在纸上演算
    ReAct 让模型能动起来 边走边看路
    Plan-and-Execute 让 Agent 像任务管理者 先看地图再走

    "规划能力的分水岭，从来不是'它会不会思考'，而是——它能不能先看到整张地图，再决定每一步怎么走。"

    关键教训¶

    没有分层，Agent 就容易变成"想到哪做到哪"。 有了分层，Agent 才可能真正进入"可控完成任务"的阶段。
