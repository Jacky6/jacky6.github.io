    Planning 规划模块¶

    Agent 的"项目经理"——把模糊目标拆解为可执行步骤，动态调整计划。

    1. 模块定位¶

    Planning 是 Agent 从 "会思考" 到 "能完成任务" 的关键跨越。

    没有 Planning 的 Agent:          有 Planning 的 Agent:

用户: "帮我写一份竞品分析报告"    用户: "帮我写一份竞品分析报告"
  │                              │
  ▼                              ▼
"好的，我来写..."               规划器:
直接开始写                        1. 确定竞品范围
可能跑偏、遗漏                    2. 收集各竞品信息
可能写到一半忘记目标             3. 对比分析
                               4. 生成报告
                               5. 检查完整性
                               ↓
                               执行器按步骤推进
                               ↓
                               完成 ✓

    核心能力： - 任务分解（Task Decomposition）—— 把大目标拆成小步骤 - 依赖管理（Dependency Management）—— 识别步骤间的先后关系 - 动态重规划（Re-planning）—— 执行中发现计划不对时调整

    2. 任务分解¶

    2.1 基础任务分解¶

    from pydantic import BaseModel, Field
from typing import Literal

class SubTask(BaseModel):
    """子任务定义"""
    id: str = Field(description="任务唯一ID")
    title: str = Field(description="任务标题")
    description: str = Field(description="任务详细描述")
    dependencies: list[str] = Field(
        default_factory=list,
        description="依赖的前置任务ID"
    )
    estimated_complexity: Literal["low", "medium", "high"] = Field(
        description="预估复杂度"
    )
    requires_tools: list[str] = Field(
        default_factory=list,
        description="需要的工具列表"
    )

class Plan(BaseModel):
    """完整计划"""
    goal: str = Field(description="总体目标")
    subtasks: list[SubTask] = Field(description="子任务列表")
    notes: str = Field(default="", description="注意事项")

def decompose_task(goal: str, llm) -> Plan:
    """将目标分解为可执行的子任务"""
    prompt = f"""
    Decompose the following goal into actionable subtasks.

    Goal: {goal}

    Requirements:
    - Each subtask should be specific and actionable
    - Identify dependencies between tasks
    - Estimate complexity for each task
    - List tools that might be needed

    Return a JSON object matching the Plan schema.
    """

    return llm.with_structured_output(Plan).invoke(prompt)

# 使用
plan = decompose_task("帮我写一份关于 AI Agent 框架的竞品分析报告", llm)
print(f"目标: {plan.goal}")
for task in plan.subtasks:
    deps = f" [依赖: {', '.join(task.dependencies)}]" if task.dependencies else ""
    print(f"  [{task.id}] {task.title}{deps} (复杂度: {task.estimated_complexity})")

    2.2 递归分解（复杂任务）¶

    class RecursiveDecomposer:
    """递归任务分解器——大任务拆到足够小"""

    MAX_DEPTH = 3
    MIN_TASK_SIZE = "small"  # 任务足够小就不再分解

    def __init__(self, llm):
        self.llm = llm

    def decompose(self, goal: str, depth: int = 0) -> dict:
        """递归分解任务"""
        if depth >= self.MAX_DEPTH:
            return self._create_leaf_task(goal, depth)

        # 先判断是否需要分解
        should_decompose = self._should_decompose(goal)
        if not should_decompose:
            return self._create_leaf_task(goal, depth)

        # 分解为子任务
        plan = self._decompose_once(goal)

        # 递归分解每个子任务
        result = {
            "goal": goal,
            "depth": depth,
            "children": [
                self.decompose(task.description, depth + 1)
                for task in plan.subtasks
            ],
        }

        return result

    def _should_decompose(self, task: str) -> bool:
        """判断任务是否足够小"""
        prompt = f"""
        Is this task simple enough to execute directly, or does it need further decomposition?

        Task: {task}

        Answer "decompose" if it needs to be broken down further, or "execute" if it's ready.
        """
        response = self.llm.invoke(prompt).content.strip().lower()
        return "decompose" in response

    def _decompose_once(self, goal: str) -> Plan:
        """单次分解"""
        return decompose_task(goal, self.llm)

    def _create_leaf_task(self, goal: str, depth: int) -> dict:
        """创建叶子任务（不再分解）"""
        return {
            "goal": goal,
            "depth": depth,
            "children": [],
            "is_leaf": True,
        }

    2.3 LangGraph Plan-and-Execute¶

    from typing import TypedDict, Literal
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI

class PlanningState(TypedDict):
    goal: str
    plan: Plan | None
    current_task_index: int
    task_results: dict  # {task_id: result}
    final_result: str

llm_planner = ChatOpenAI(model="gpt-4o")
llm_executor = ChatOpenAI(model="gpt-4o-mini")  # 执行用轻量模型

def create_plan(state: PlanningState) -> PlanningState:
    """规划器：创建任务计划"""
    plan = decompose_task(state["goal"], llm_planner)
    return {**state, "plan": plan, "current_task_index": 0}

def execute_task(state: PlanningState) -> PlanningState:
    """执行器：执行当前任务"""
    plan = state["plan"]
    idx = state["current_task_index"]

    if idx >= len(plan.subtasks):
        return state  # 所有任务完成

    current_task = plan.subtasks[idx]

    # 收集前置任务结果作为上下文
    context_parts = []
    for dep_id in current_task.dependencies:
        if dep_id in state["task_results"]:
            context_parts.append(
                f"Task {dep_id} result: {state['task_results'][dep_id]}"
            )

    context = "\n".join(context_parts) if context_parts else "No dependencies."

    # 执行当前任务
    prompt = f"""
    Execute this task:

    Task: {current_task.title}
    Description: {current_task.description}

    Context from previous tasks:
    {context}

    Overall goal: {state['goal']}

    Provide your result.
    """

    result = llm_executor.invoke(prompt).content

    # 更新状态
    new_results = {**state["task_results"], current_task.id: result}

    return {
        **state,
        "task_results": new_results,
        "current_task_index": idx + 1,
    }

def should_continue_execution(state: PlanningState) -> Literal["execute", "summarize", "replan"]:
    """决定下一步：继续执行 / 总结 / 重规划"""
    plan = state["plan"]
    idx = state["current_task_index"]

    if idx >= len(plan.subtasks):
        return "summarize"

    # 检查是否需要重规划（简单规则：执行了3步后检查进度）
    if idx > 0 and idx % 3 == 0:
        return "replan"

    return "execute"

def replan(state: PlanningState) -> PlanningState:
    """重规划：根据已完成的结果调整后续计划"""
    completed_tasks = {
        tid: result
        for tid, result in state["task_results"].items()
    }

    remaining_tasks = state["plan"].subtasks[state["current_task_index"]:]

    prompt = f"""
    Review the progress and adjust the plan.

    Original goal: {state['goal']}

    Completed tasks:
    {json.dumps(completed_tasks, ensure_ascii=False, indent=2)}

    Remaining planned tasks:
    {json.dumps([t.dict() for t in remaining_tasks], ensure_ascii=False, indent=2)}

    Should we:
    1. Continue with the remaining plan?
    2. Modify the remaining plan?
    3. Add new tasks?
    4. Skip some tasks?

    Return the updated Plan JSON. If no changes needed, return the remaining tasks as-is.
    """

    new_plan = llm_planner.with_structured_output(Plan).invoke(prompt)

    # 合并已完成和新的计划
    completed_subtasks = state["plan"].subtasks[:state["current_task_index"]]
    new_plan.subtasks = completed_subtasks + new_plan.subtasks

    return {
        **state,
        "plan": new_plan,
    }

def summarize(state: PlanningState) -> PlanningState:
    """汇总所有任务结果"""
    results_text = "\n\n".join(
        f"Task {tid}:\n{result}"
        for tid, result in state["task_results"].items()
    )

    prompt = f"""
    Synthesize all task results into a cohesive final answer.

    Goal: {state['goal']}

    Task Results:
    {results_text}

    Provide a well-structured final answer that addresses the original goal.
    """

    final = llm_planner.invoke(prompt).content

    return {**state, "final_result": final}

# 构建图
builder = StateGraph(PlanningState)
builder.add_node("create_plan", create_plan)
builder.add_node("execute", execute_task)
builder.add_node("replan", replan)
builder.add_node("summarize", summarize)

builder.set_entry_point("create_plan")
builder.add_edge("create_plan", "execute")
builder.add_conditional_edges("execute", should_continue_execution)
builder.add_edge("replan", "execute")
builder.add_edge("summarize", END)

plan_execute_graph = builder.compile()

# 使用
result = plan_execute_graph.invoke({
    "goal": "调研 Python 主流 Web 框架（Flask, FastAPI, Django）的优缺点，并给出选型建议",
    "plan": None,
    "current_task_index": 0,
    "task_results": {},
    "final_result": "",
})
print(result["final_result"])

    3. 依赖管理与任务调度¶

    3.1 依赖图¶

    from graphlib import TopologicalSorter

class TaskScheduler:
    """基于依赖关系的任务调度器"""

    def __init__(self, plan: Plan):
        self.plan = plan
        self.results: dict[str, str] = {}
        self.status: dict[str, str] = {}  # pending/running/completed/failed

        # 构建依赖图
        self._build_dependency_graph()

    def _build_dependency_graph(self):
        """构建拓扑排序依赖图"""
        self.graph = {}
        for task in self.plan.subtasks:
            self.graph[task.id] = set(task.dependencies)
            self.status[task.id] = "pending"

        # 验证无环
        try:
            sorter = TopologicalSorter(self.graph)
            self.execution_order = list(sorter.static_order())
        except:
            raise ValueError("Task dependency graph contains a cycle!")

    def get_ready_tasks(self) -> list[SubTask]:
        """获取当前可以执行的任务（依赖已满足）"""
        ready = []
        for task in self.plan.subtasks:
            if self.status[task.id] != "pending":
                continue

            # 检查所有依赖是否完成
            deps_met = all(
                self.status.get(dep) == "completed"
                for dep in task.dependencies
            )

            if deps_met:
                ready.append(task)

        return ready

    def mark_completed(self, task_id: str, result: str):
        """标记任务完成"""
        self.status[task_id] = "completed"
        self.results[task_id] = result

    def mark_failed(self, task_id: str, error: str):
        """标记任务失败"""
        self.status[task_id] = "failed"
        self.results[task_id] = f"ERROR: {error}"

    def get_progress(self) -> dict:
        """获取执行进度"""
        total = len(self.plan.subtasks)
        completed = sum(1 for s in self.status.values() if s == "completed")
        failed = sum(1 for s in self.status.values() if s == "failed")

        return {
            "total": total,
            "completed": completed,
            "failed": failed,
            "pending": total - completed - failed,
            "percentage": round(completed / total * 100, 1),
        }

    def is_complete(self) -> bool:
        """检查是否所有任务完成"""
        return all(s in ("completed", "failed") for s in self.status.values())

# 使用示例
plan = Plan(
    goal="生成竞品分析报告",
    subtasks=[
        SubTask(id="t1", title="确定竞品列表", description="...", dependencies=[]),
        SubTask(id="t2", title="收集竞品A信息", description="...", dependencies=["t1"]),
        SubTask(id="t3", title="收集竞品B信息", description="...", dependencies=["t1"]),
        SubTask(id="t4", title="对比分析", description="...", dependencies=["t2", "t3"]),
        SubTask(id="t5", title="生成报告", description="...", dependencies=["t4"]),
    ],
)

scheduler = TaskScheduler(plan)

# 第一轮：t1 无依赖，可以执行
ready = scheduler.get_ready_tasks()
print(f"可执行: {[t.title for t in ready]}")  # ['确定竞品列表']

# 执行 t1
scheduler.mark_completed("t1", "竞品: Flask, FastAPI, Django")

# 第二轮：t2, t3 依赖 t1 已满足
ready = scheduler.get_ready_tasks()
print(f"可执行: {[t.title for t in ready]}")  # ['收集竞品A信息', '收集竞品B信息']

    3.2 并行执行¶

    import asyncio
from concurrent.futures import ThreadPoolExecutor

class ParallelExecutor:
    """并行任务执行器"""

    def __init__(self, scheduler: TaskScheduler, llm, max_workers: int = 3):
        self.scheduler = scheduler
        self.llm = llm
        self.max_workers = max_workers

    async def execute_all(self) -> dict:
        """执行所有任务（自动处理依赖和并行）"""
        while not self.scheduler.is_complete():
            ready_tasks = self.scheduler.get_ready_tasks()

            if not ready_tasks:
                # 没有可执行的任务但未完成，可能有循环依赖或错误
                break

            # 并行执行当前批次
            tasks = [
                self._execute_single(task)
                for task in ready_tasks[:self.max_workers]
            ]

            results = await asyncio.gather(*tasks, return_exceptions=True)

            for task, result in zip(ready_tasks, results):
                if isinstance(result, Exception):
                    self.scheduler.mark_failed(task.id, str(result))
                else:
                    self.scheduler.mark_completed(task.id, result)

            print(f"进度: {self.scheduler.get_progress()}")

        return self.scheduler.results

    async def _execute_single(self, task: SubTask) -> str:
        """执行单个任务"""
        # 收集依赖结果
        context = self._get_dependency_context(task)

        prompt = f"""
        Task: {task.title}
        Description: {task.description}

        Context from dependencies:
        {context}

        Execute this task and return the result.
        """

        response = await self.llm.ainvoke(prompt)
        return response.content

    def _get_dependency_context(self, task: SubTask) -> str:
        context_parts = []
        for dep_id in task.dependencies:
            if dep_id in self.scheduler.results:
                context_parts.append(
                    f"[{dep_id}] {self.scheduler.results[dep_id][:200]}"
                )
        return "\n".join(context_parts) if context_parts else "No dependencies."

    4.1 触发条件¶

    class ReplanningChecker:
    """判断是否需要重规划"""

    def __init__(self, llm):
        self.llm = llm

    def check(self, goal: str, plan: Plan, completed: dict, current_index: int) -> dict:
        """检查是否需要重规划"""
        completed_text = "\n".join(
            f"- {tid}: {result[:100]}..."
            for tid, result in completed.items()
        )

        remaining = plan.subtasks[current_index:]
        remaining_text = "\n".join(
            f"- {t.id}: {t.title}"
            for t in remaining
        )

        prompt = f"""
        Evaluate whether the current plan needs adjustment.

        Goal: {goal}

        Completed:
        {completed_text}

        Remaining tasks:
        {remaining_text}

        Check for:
        1. Are completed results sufficient to achieve the goal?
        2. Are remaining tasks still relevant?
        3. Are there gaps in the plan?
        4. Should tasks be reordered?

        Return JSON:
        {{
            "needs_replan": true/false,
            "reason": "why replanning is needed",
            "suggested_changes": ["list of changes"]
        }}
        """

        return json.loads(
            self.llm.invoke(
                prompt,
                response_format={"type": "json_object"}
            ).content
        )

    4.2 重规划策略¶

    class ReplanningStrategies:
    """重规划策略库"""

    @staticmethod
    def add_missing_tasks(plan: Plan, missing_description: str, llm) -> Plan:
        """添加缺失的任务"""
        prompt = f"""
        The current plan is missing some tasks. Add them.

        Current plan:
        {json.dumps([t.dict() for t in plan.subtasks], indent=2)}

        What's missing: {missing_description}

        Return the updated Plan with new tasks added.
        """
        return llm.with_structured_output(Plan).invoke(prompt)

    @staticmethod
    def skip_completed(plan: Plan, completed_ids: list[str]) -> Plan:
        """跳过已完成的任务（创建新计划只包含未完成部分）"""
        remaining = [t for t in plan.subtasks if t.id not in completed_ids]
        # 更新依赖关系
        for task in remaining:
            task.dependencies = [
                d for d in task.dependencies
                if d not in completed_ids
            ]
        return Plan(
            goal=plan.goal,
            subtasks=remaining,
            notes=plan.notes,
        )

    @staticmethod
    def reorder_by_priority(plan: Plan, llm) -> Plan:
        """按优先级重新排序"""
        prompt = f"""
        Reorder these tasks by priority and logical sequence.

        Tasks:
        {json.dumps([t.dict() for t in plan.subtasks], indent=2)}

        Return the reordered Plan.
        """
        return llm.with_structured_output(Plan).invoke(prompt)

def plan_approval_node(state: PlanningState) -> PlanningState:

    return state

    5.2 计划可视化¶

    def visualize_plan(plan: Plan) -> str:
    """将计划可视化为文本图表"""
    output = []
    output.append(f" Plan: {plan.goal}")
    output.append("=" * 50)

    # 构建依赖图
    task_map = {t.id: t for t in plan.subtasks}

    for task in plan.subtasks:
        deps_str = ""
        if task.dependencies:
            dep_titles = [task_map[d].title for d in task.dependencies if d in task_map]
            deps_str = f" ← [{', '.join(dep_titles)}]"

        complexity_icon = {"low": "🟢", "medium": "🟡", "high": "🔴"}.get(
            task.estimated_complexity, ""
        )

        output.append(f"  {complexity_icon} {task.title}{deps_str}")

    output.append("=" * 50)
    return "\n".join(output)

    5.3 面试速记：ReAct vs Plan-and-Execute¶

    面试官常问："ReAct 和 Plan-and-Execute 有什么区别？什么时候用哪个？"

    维度 ReAct Plan-and-Execute
    思维方式 边想边做，逐步推进 先全局规划，再逐步执行
    适用场景 交互式、需实时反馈 复杂多步任务、可预规划
    上下文压力 较小（只维护当前轮） 较大（需维护完整计划）
    灵活性 高（随时调整方向） 中（需动态重规划机制）
    典型用例 客服问答、搜索问答 代码生成项目、数据分析流水线

    关键洞察：ReAct 像走路——走一步看一步；Plan-and-Execute 像导航——先看地图再走。 复杂任务最佳方案是 Plan + ReAct：先规划大方向，每个子任务用 ReAct 执行。

    5.4 面试速记：任务分解手写¶

    def decompose_task(llm, goal: str) -> list[dict]:
    """将复杂任务分解为可执行的子任务"""
    prompt = f"""
Break down this goal into executable subtasks:
Goal: {goal}
Return JSON:
{{"subtasks": [
    {{"id": 1, "description": "...", "depends_on": [], "complexity": "easy"}},
    {{"id": 2, "description": "...", "depends_on": [1], "complexity": "medium"}}
]}}
"""
    result = json.loads(llm(prompt, response_format="json").text)
    return result["subtasks"]

    6. 规划模块 Checklist¶

    • 任务分解：结构化输出（Pydantic），包含依赖关系
    • 递归分解：复杂任务自动拆到可执行粒度
    • 依赖图：拓扑排序确保执行顺序正确
    • 并行执行：无依赖关系的任务并行处理
    • 动态重规划：定期检查进度，必要时调整计划
    • Human-in-the-Loop：关键计划步骤可引入人工审批
    • 进度跟踪：实时展示执行进度和状态
    • Plan Visualization：可视化计划便于理解和调试

    7. 与 Reasoning 的关系¶

    Planning 和 Reasoning 不是二选一，而是互补协作：

    ┌─────────────────────────────────────────┐
│  Planning Layer (全局)                   │
│  "整件事怎么拆、怎么排、怎么推进"         │
│  ↓                                      │
│  每个子任务 → Reasoning Layer (局部)      │
│  "这个子任务怎么想清楚、怎么做"           │
│  ↓                                      │
│  每一步 → CoT (微观)                     │
│  "这个具体推理怎么做"                    │
└─────────────────────────────────────────┘
    • Planning 管 任务组织（宏观）
    • Reasoning 管 思考质量（中观）
    • CoT 管 推理深度（微观）

    10. 与其他模块的关系¶

    Planning (规划模块)
    │
    ├──← Perception (感知层)：接收意图分类结果
    ├──← Memory (记忆层)：获取历史任务经验

    ├──→ Tool Use (工具层)：为每个子任务分配工具

    12. 面试话术速记¶

    Q: Planning 模块的核心能力是什么？

    "Planning 是 Agent 的'项目经理'，核心能力有三个： 1. 任务分解：把大目标拆成可执行的子任务 2. 依赖管理：识别任务间的先后关系，构建 DAG 3. 动态重规划：执行中发现计划不对时及时调整

    工程上，我们用 Pydantic 结构化输出定义任务，用 TopologicalSorter 处理依赖，用 LLM 做重规划决策。"

    Q: Plan-and-Execute 和 ReAct 有什么区别？

    "两者适用场景不同： - ReAct：边想边做，每一步都推理下一步，适合探索性任务 - Plan-and-Execute：先全局规划，再逐步执行，适合目标明确的多步任务

    核心区别：ReAct 是反应式的（看到什么做什么），Plan-and-Execute 是前瞻式的（先想好再做）。

    生产环境推荐：简单任务用 ReAct，复杂任务用 Plan-and-Execute。"

    加分项：提到"Planning 是 Harness Engineering 的核心，好的规划能让 Agent 像项目经理一样高效推进任务"。
