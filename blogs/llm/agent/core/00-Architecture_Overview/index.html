    2026 工程演进路线¶

    Agent 工程实践经历了四个阶段的演进：

    2023           2024           2025           2026
  │              │              │              │
  ▼              ▼              ▼              ▼
┌──────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│Prompt│───▶│ Context  │───▶│ Harness  │───▶│  Loop    │
│ Eng. │    │ Eng.     │    │ Eng.     │    │ Eng.     │
└──────┘    └──────────┘    └──────────┘    └──────────┘
  │              │              │              │
  │              │              │              │

写指令        准备信息       搭建环境       设计循环
"怎么问"     "给什么"       "在哪跑"       "怎么转"
    阶段 核心问题 关键技术 详细文档
    Prompt Engineering 怎么问出好答案 Few-shot, CoT, ToT —
    Context Engineering 给模型什么信息 RAG, 记忆, 上下文压缩 engineering/context-engineering/
    Harness Engineering 在哪里执行 沙箱, 文件系统, 权限 engineering/harness-engineering/
    Loop Engineering 怎么循环驱动 Agent Loop, 终止策略, 重试 engineering/loop-engineering/

    关系理解：

    • Prompt 是点（单次调用）
    • Context 是线（信息管道）
    • Harness 是面（运行环境）
    • Loop 是体（完整循环）

    三层架构关系¶

    成熟 Agent 不是各模块的简单拼装，而是 分层叠加 的有机整体：

    ┌─────────────────────────────────────────────────────────────┐
│                    Task Level (任务层)                        │
│         Planning + Multi-Agent + Control Loop                │
│         "整件事怎么拆、怎么排、怎么推进"                        │
├─────────────────────────────────────────────────────────────┤
│                    Action Level (行动层)                      │
│         ReAct + Tool Use + Self-Reflection                   │
│         "当前局面下下一步做什么"                                │
├─────────────────────────────────────────────────────────────┤
│                    Thought Level (思维层)                     │
│         CoT + Memory + Perception                            │
│         "这个具体问题怎么想清楚"                                │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  Foundation (基础设施层)                      │
│    Safety + Evaluation + Observability                       │
│    "贯穿所有层，确保可靠、可观测、可评估"                        │
└─────────────────────────────────────────────────────────────┘
    • 思维层 解决"想清楚"——让模型理解问题、检索记忆、多模态感知
    • 行动层 解决"做出来"——调用工具、边想边做、自我纠错
    • 任务层 解决"管得好"——全局规划、多体协作、流程控制
    • 基础设施层 解决"靠得住"——安全护栏、评估体系、可观测性

    核心概念速记¶

    概念 一句话解释 类比
    Agent 有控制循环、能用工具、有记忆的 LLM 系统 不只是大脑，是完整的人
    ReAct Thought → Action → Observation 循环 边走边看
    CoT 让模型显式写出推理步骤 把心算变成笔算
    Plan-and-Execute 先全局规划，再逐步执行 先看导航再开车
    ToT 多路径探索，选最优 并行试错
    Self-Consistency 多次采样取共识 三个臭皮匠
    Memory 三层 短期(窗口) / 会话(摘要) / 长期(向量库) 工作记忆 / 日记 / 图书馆
    Supervisor LLM 动态分配任务给 Worker 项目经理
    MCP 标准化协议接入外部工具 USB 接口
    A2A Agent 之间互相通信协作 同事之间开会
    Human-in-Loop 关键操作需人工审批 领导签字
    Loop Engineering 设计 Agent 循环驱动的系统 设计流水线

    LangGraph 实战模板¶

    基础模板¶

    from langgraph.graph import StateGraph, END
from typing import TypedDict

class State(TypedDict):
    messages: list
    # 其他状态字段...

def node_a(state): return {...}
def node_b(state): return {...}

def should_continue(state):
    return "node_b" if condition else END

builder = StateGraph(State)
builder.add_node("a", node_a)
builder.add_node("b", node_b)
builder.set_entry_point("a")
builder.add_conditional_edges("a", should_continue)
builder.add_edge("b", "a")  # 循环
graph = builder.compile()

result = graph.invoke({"messages": [...]})

    带工具调用的完整模板¶

    from langchain.agents import create_agent
from langchain_core.tools import tool
from langgraph.checkpoint.memory import InMemorySaver

# 1. 定义工具
@tool
def get_weather(city: str) -> str:
    """获取天气信息"""
    return f"{city}：晴，25°C"

@tool
def search_web(query: str) -> str:
    """搜索网页"""
    return f"搜索结果：{query}..."

# 2. 创建 Agent
agent = create_agent(
    model="openai:gpt-5.4",
    tools=[get_weather, search_web],
    system_prompt="你是一个有用的助手",
    checkpointer=InMemorySaver(),  # 对话持久化
)

# 3. 调用（带对话记忆）
config = {"configurable": {"thread_id": "session-123"}}
result = agent.invoke(
    {"messages": [{"role": "user", "content": "北京天气怎么样？"}]},
    config=config
)

    关键点：

    • StateGraph 是图，compile() 生成可执行对象
    • add_conditional_edges 实现分支/路由
    • 节点函数返回更新（不是完整 State）
    • 循环靠 add_edge(b, a) 实现
    • create_agent 是 LangChain 2026 推荐的快速入口

    架构设计题答题模板¶

    面试让你设计一个 Agent 系统，按这个框架回答：

    1. 需求分析（30s）：这个场景需要哪些能力？工具？记忆？多步规划？
2. 架构选择（30s）：用 Single/Workflow/Team？为什么？
3. 核心模块（1min）：Perception / Reasoning / Memory / Tools / Safety
4. 技术实现（1min）：LangGraph StateGraph 编排，State 包含…节点包括…
5. 评估方案（30s）：Golden Set + LLM-as-Judge + 生产环境采样

    面试加分话术对比¶

    场景 普通回答 加分回答
    谈 LangGraph "我用 LangGraph 做过项目" "LangGraph 本质是有向状态图，比 LangChain 的 LCEL 更适合 Agent，因为它支持循环、中断、持久化"
    谈 ReAct "ReAct 就是边想边做" "ReAct 的核心是 interleaving——推理和动作交替，每轮 Action 后 Observation 改变上下文，驱动下一轮 Thought"
    谈 Memory "用向量数据库存记忆" "记忆分三层：短期靠滑动窗口控制 token，会话靠LLM 摘要提炼关键信息，长期靠向量检索 + 元数据过滤，还要有记忆巩固机制定期整理"
    谈评估 "人工看看就行" "评估分三层：离线基准测试（Golden Set 跑回归）、LLM-as-Judge（强模型给弱模型打分）、在线监控（采样 + 用户反馈），形成闭环"
    谈安全 "加个审核就行" "安全是纵深防御：输入层防注入和敏感信息，运行时控 Token 预算和速率，工具层做权限和沙箱，输出层做事实核查和脱敏，关键操作引入 Human-in-the-Loop"
    谈工程演进 "就是写 prompt" "Agent 工程经历了四个阶段：Prompt Engineering → Context Engineering → Harness Engineering → Loop Engineering，从单次调用演进到完整循环系统"
