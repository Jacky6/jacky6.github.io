    00 Agent 系统总览¶

    类型：canonical | 最后核对：2026-10-29

    1. Agent 是什么¶

    一个 Agent 是具备以下三件事的 LLM 系统：

    1. 控制循环——模型可以多轮决定"下一步做什么"，而不是一问一答；
    2. 工具使用——模型可以请求执行外部动作（搜索、读写文件、调 API）；
    3. 状态——系统在多轮之间保留和更新信息。

    一句话：Agent = LLM + 工具 + 循环 + 状态。

    与之区分：

    系统 有循环 有工具 有状态 例子
    单次调用 ❌ ❌ ❌ 翻译一句话
    Chain / Workflow 固定流程 可有 可有 RAG 管线
    Agent 模型决定 ✅ ✅ 编码助手

    关键区别：Workflow 的控制流由开发者写死，Agent 的控制流由模型在运行时决定。这个区别决定了成本、延迟、可靠性和测试方式都不同。

    2. 系统组成¶

    一个生产级 Agent 系统由四部分组成：

    ┌─────────────────────────────────────────────────────────┐
│                    Agent 系统                            │
│                                                         │
│  ┌─────────────┐   ┌──────────┐   ┌─────────────────┐  │
│  │   模型层     │   │  工具层   │   │    状态层        │  │
│  │  LLM 推理    │   │ 工具执行  │   │ State/Memory    │  │
│  └──────┬──────┘   └────┬─────┘   └────────┬────────┘  │
│         │               │                  │            │
│  ┌──────┴───────────────┴──────────────────┴─────────┐  │
│  │                  运行时层（Runtime）                │  │
│  │   循环控制 · 权限 · 重试 · 持久化 · 流式 · 追踪     │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
    层 职责 典型问题
    模型层 产生决策：调哪个工具、何时结束 选错工具、参数错误、不终止
    工具层 执行动作并返回结果 执行失败、超时、副作用不可逆
    状态层 跨轮保留信息 上下文爆炸、记忆检索不准
    运行时层 兜底和治理 无限循环、凭据泄漏、无法恢复

    核心观点：模型层只是 Agent 的一部分。生产系统的可靠性主要来自运行时层，而不是更聪明的模型。

    3. 边界：什么时候不该用 Agent¶

    Agent 的代价：多轮调用（成本、延迟）、不确定性（测试难）、错误传播（一步错步步错）。

    场景 建议
    输入输出格式固定 用 Workflow，不要用 Agent
    单步可完成的任务 直接调用，不要套循环
    错误代价极高且不可逆 Workflow + 人工审批
    步骤需要动态决定、环境反馈驱动 ✅ Agent
    长任务、多工具、需要自主恢复 ✅ Agent

    选型原则：先用最简单的方案（单次调用 → Workflow → Agent），Agent 是最后手段，不是默认选项。

    4. 与外部世界的连接¶

    Agent 通过两类标准协议与外部交互：

    ┌─────────────┐                    ┌─────────────┐
│   Agent A   │──── A2A ──────────▶│   Agent B   │
└──────┬──────┘  (独立服务间互操作)  └──────┬──────┘
       │                                  │
       │ MCP (工具/数据接入)               │ MCP
       ▼                                  ▼
┌─────────────┐                    ┌─────────────┐
│  工具/数据   │                    │  工具/数据   │
└─────────────┘                    └─────────────┘
    协议 解决的问题 本库事实源
    MCP Host/Client 与外部 Server 的能力发现和通信（工具、数据、上下文） protocols/mcp/
    A2A 独立 Agent 服务之间的互操作（发现、任务、流式） protocols/a2a/

    注意层级关系：Function Calling 描述模型与 Host 之间的工具请求；MCP 描述 Host 与外部 Server 之间的通信。两者不是替代关系。

    6. 本章要点¶

    1. Agent = LLM + 工具 + 循环 + 状态；控制流由模型决定是与 Workflow 的本质区别。
    2. 系统分四层：模型、工具、状态、运行时；可靠性主要来自运行时层。
    3. Agent 是最后手段，不是默认选项；能用固定流程就用固定流程。
    4. MCP 管工具接入，A2A 管 Agent 互操作，Function Calling 管模型内部请求——三者不在同一层级。
