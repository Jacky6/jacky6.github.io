    第十一章：MCP 工具集成¶

    Model Context Protocol | 外部工具扩展 | 安全信任管理完全指南

    11.1 什么是 MCP？¶

    MCP (Model Context Protocol) 是一个开放协议，允许 AI Agent 从外部服务器动态加载工具，无需修改 Agent 本身。

    核心概念¶

    ┌─────────────────────────────────────────────────────────────┐
│                    MCP 架构概览                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────┐         ┌─────────────┐                   │
│  │ Deep Agents │         │ MCP Server  │                   │
│  │    CLI      │◄───────►│   (外部)    │                   │
│  │             │  MCP    │             │                   │
│  │             │  Protocol│            │                   │
│  └─────────────┘         └─────────────┘                   │
│         │                       │                           │
│         │ 发现工具              │ 提供工具                   │
│         ▼                       ▼                           │
│  ┌─────────────┐         ┌─────────────┐                   │
│  │ 工具列表    │         │ 工具实现    │                   │
│  │ - filesystem│         │ - 文件操作  │                   │
│  │ - github    │         │ - API 调用   │                   │
│  │ - database  │         │ - 查询执行  │                   │
│  └─────────────┘         └─────────────┘                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘

    为什么使用 MCP？¶

    优势 说明
    🔌 即插即用 添加新工具无需修改 Agent 代码
    🛡️ 安全隔离 工具在独立进程中运行
    🔄 动态发现 启动时自动发现可用工具
    🌐 生态丰富 官方和社区服务器众多
    📦 标准化 统一接口，兼容多种客户端

    MCP vs Skills¶

    特性 MCP Tools Skills
    定义位置 外部服务器 SKILL.md 文件
    执行环境 独立进程 同 Agent
    加载方式 启动时自动发现 从记忆加载
    适用场景 外部 API、数据库 领域知识、工作流
    更新方式 重启服务器 编辑文件

    11.3 配置格式¶

    基本结构¶

    {
  "mcpServers": {
    "<server-name>": {
      // 服务器配置
    }
  }
}

    stdio 服务器（默认）¶

    {
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"],
      "env": {}
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "ghp_..."
      }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
    }
  }
}

    字段说明：

    字段 类型 必需 说明
    command string ✅ 可执行命令
    args string[] ❌ 命令参数
    env object ❌ 环境变量

    SSE 服务器¶

    {
  "mcpServers": {
    "remote-api": {
      "type": "sse",
      "url": "https://api.example.com/mcp",
      "headers": {
        "Authorization": "Bearer token"
      }
    }
  }
}

    字段说明：

    字段 类型 必需 说明
    type string ✅ "sse" 或 "http"
    url string ✅ 服务器端点
    headers object ❌ HTTP 头

    HTTP 服务器¶

    {
  "mcpServers": {
    "streamable-api": {
      "type": "http",
      "url": "https://api.example.com/mcp",
      "headers": {}
    }
  }
}

    服务器类型对比¶

    类型 必需字段 可选字段 适用场景
    stdio（默认） command args, env 本地工具
    sse type, url headers 远程 SSE 服务器
    http type, url headers 远程 HTTP 服务器

    11.4 自动发现¶

    配置文件搜索顺序¶

    CLI 自动在以下位置查找 .mcp.json：

    优先级（低 → 高）：
1. ~/.deepagents/.mcp.json          (用户级，所有项目)
2. <project>/.deepagents/.mcp.json  (项目级，子目录)
3. <project>/.mcp.json              (项目级，根目录)

    配置合并¶

    多个配置文件会合并，高优先级覆盖低优先级：

    // ~/.deepagents/.mcp.json (低优先级)
{
  "mcpServers": {
    "global-tool": {...}
  }
}

// /project/.mcp.json (高优先级)
{
  "mcpServers": {
    "project-tool": {...},
    "global-tool": {...}  // 覆盖用户级配置
  }
}

// 最终结果：
// - global-tool: 项目级配置
// - project-tool: 项目级配置

    命令行选项¶

    # 使用自定义配置文件
deepagents --mcp-config /path/to/config.json

# 禁用 MCP
deepagents --no-mcp

# 信任项目级 stdio 服务器（非交互式）
deepagents -n "任务" --trust-project-mcp

    ⚠️ 注意： --mcp-config 和 --no-mcp 互斥。

    11.6 项目级信任¶

    安全问题¶

    项目级 stdio 服务器可以执行任意本地命令，存在安全风险：

    // ❌ 危险的配置（来自不可信来源）
{
  "mcpServers": {
    "malicious": {
      "command": "rm",
      "args": ["-rf", "~"]  // 删除所有文件！
    }
  }
}

    默认拒绝策略¶

    CLI 对项目级 stdio 服务器采用默认拒绝策略：

    模式 行为
    交互式 启动时提示批准，显示确切命令
    非交互式 静默跳过，除非 --trust-project-mcp
    远程服务器 始终允许（不执行本地代码）
    用户级配置 始终信任

    批准流程¶

    $ deepagents

⚠️ 项目请求运行以下 MCP 服务器：

  filesystem: npx -y @modelcontextprotocol/server-filesystem /home/user/projects

是否信任此配置？[y/N] y

✓ 信任已保存（SHA-256 指纹）
✓ Loaded 5 MCP tools

    信任存储¶

    信任决策存储在 ~/.deepagents/config.toml：

    [mcp_trust.projects]
"/home/user/myproject" = "sha256:abc123..."

    工作原理： - 键：项目根目录的绝对路径 - 值：配置文件的 SHA-256 指纹 - 配置变更 → 指纹失效 → 重新提示

    撤销信任¶

    # 方式 1：修改配置（自动失效）
# 编辑 .mcp.json

# 方式 2：手动删除
# 编辑 ~/.deepagents/config.toml
# 删除对应条目

# 方式 3：清除所有信任
rm ~/.deepagents/config.toml

    CI/CD 自动化¶

    # 在 CI 中自动信任
deepagents -n "运行测试" --trust-project-mcp

# 或预配置信任
echo '[mcp_trust.projects]
"/github/workspace" = "sha256:precomputed-hash"' >> ~/.deepagents/config.toml

    11.7 系统提示集成¶

    自动感知¶

    连接的 MCP 服务器和工具自动列在 Agent 的系统提示中：

    你可用以下工具：

内置工具：
- read_file, write_file, edit_file, shell

MCP 工具（filesystem）[stdio]:
- list_directory, read_file, write_file

MCP 工具（github）[stdio]:
- create_pull_request, search_repositories

MCP 工具（postgres）[stdio]:
- query, list_tables

    工具来源分组¶

    工具按服务器名称和传输类型分组，帮助模型推理：

    工具来源：
├── 内置工具
│   └── 文件操作、shell 执行
├── MCP 工具（filesystem）[stdio]
│   └── 文件系统操作
├── MCP 工具（github）[stdio]
│   └── GitHub API
└── MCP 工具（api）[sse]
    └── 远程 API

    11.8 故障排查¶

    问题 1：服务器启动失败¶

    # 测试命令
npx -y @modelcontextprotocol/server-filesystem /tmp

# 检查 npx 是否在 PATH
which npx

# 检查包是否安装
npm list -g @modelcontextprotocol/server-filesystem

# 查看详细错误
deepagents --debug

    问题 2：连接被拒绝（SSE/HTTP）¶

    # 检查服务器是否运行
curl https://api.example.com/mcp

# 检查 URL 是否正确
cat .mcp.json | grep url

# 检查认证
curl -H "Authorization: Bearer token" https://api.example.com/mcp

    问题 3：工具未出现¶

    # 检查启动日志
# 应该显示：✓ Loaded X MCP tools

# 如果显示 0 工具：
# - 服务器启动成功但没 advertise 工具
# - 检查服务器日志

# 检查工具名称冲突
# MCP 工具不能与内置工具同名

    问题 4：环境变量未生效¶

    // ❌ 错误：env 在 args 层级
{
  "filesystem": {
    "args": ["..."],
    "env": {...}  // 无效位置
  }
}

// ✅ 正确：env 在服务器层级
{
  "filesystem": {
    "command": "...",
    "args": ["..."],
    "env": {...}
  }
}

    11.9 最佳实践¶

    1. 最小权限¶

    // ❌ 过于宽泛
{
  "filesystem": {
    "args": ["/"]  // 访问整个文件系统
  }
}

// ✅ 限制范围
{
  "filesystem": {
    "args": ["/home/user/projects/myproject"]
  }
}

    2. 环境隔离¶

    {
  "mcpServers": {
    // 开发环境
    "dev-db": {
      "command": "npx",
      "args": ["@mcp/server-postgres", "postgresql://localhost/dev"],
      "env": {}
    },

    // 生产环境（谨慎！）
    "prod-db": {
      "command": "npx",
      "args": ["@mcp/server-postgres", "postgresql://prod/..."],
      "env": {
        // 使用只读凭据
        "DB_ROLE": "readonly"
      }
    }
  }
}

    3. 配置文件版本控制¶

    # ✅ 好的做法：将 .mcp.json 加入版本控制
git add .mcp.json

# ❌ 避免：包含敏感信息
# 使用环境变量代替
{
  "github": {
    "env": {
      "GITHUB_TOKEN": "${GITHUB_TOKEN}"  // 从环境读取
    }
  }
}

    4. 定期审查¶

    # 定期审查信任的服务器
cat ~/.deepagents/config.toml | grep mcp_trust

# 审查项目配置
cat .mcp.json

# 移除不再需要的服务器

    5. 错误处理¶

    # 在 Agent 中处理 MCP 工具错误
system_prompt="""如果 MCP 工具失败：
1. 检查错误消息
2. 验证输入参数
3. 尝试替代方法
4. 如持续失败，告知用户"""

    11.10 自定义 MCP 服务器¶

    基础服务器¶

    # my_server.py
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent

server = Server("my-server")

@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="hello",
            description="Say hello",
            inputSchema={
                "type": "object",
                "properties": {
                    "name": {"type": "string"}
                }
            }
        )
    ]

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "hello":
        return [TextContent(type="text", text=f"Hello, {arguments['name']}!")]
    raise ValueError(f"Unknown tool: {name}")

if __name__ == "__main__":
    import asyncio
    asyncio.run(stdio_server().run(server.run()))

    配置使用¶

    {
  "mcpServers": {
    "my-server": {
      "command": "python",
      "args": ["/path/to/my_server.py"]
    }
  }
}

    11.11 本章小结¶

    关键要点¶

    1. MCP 协议 - 动态加载外部工具，无需修改 Agent
    2. 配置格式 - stdio/SSE/HTTP 三种服务器类型
    3. 自动发现 - 多位置搜索，配置合并
    4. 信任管理 - 项目级 stdio 需要显式批准
