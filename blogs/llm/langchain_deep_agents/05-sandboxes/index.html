    第五章：沙箱与执行环境¶

    安全隔离的代码执行环境 | 文件系统后端完全指南

    5.1 什么是沙箱？¶

    沙箱（Sandbox） 是一个隔离的容器环境，为 Deep Agent 提供： - 独立的文件系统 - 受限的 shell 命令执行 - 与主机环境隔离 - 资源限制和 TTL 自动清理

    为什么需要沙箱？¶

    ┌─────────────────────────────────────────────────────────────┐
│                    没有沙箱 vs 有沙箱                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ❌ 没有沙箱                    ✅ 有沙箱                    │
│  ├─ 直接访问主机文件系统        ├─ 隔离的文件系统            │
│  ├─ 命令影响主机                ├─ 命令在容器内执行          │
│  ├─ 崩溃影响服务                ├─ 崩溃不影响主机            │
│  ├─ 状态难以清理                ├─ TTL 自动清理              │
│  └─ 多用户冲突                  └─ 完全隔离                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘

    沙箱 vs 文件系统后端¶

    特性 文件系统后端 沙箱
    文件读写 ✅ ✅
    Shell 命令 ❌ ✅ (execute 工具)
    隔离性 低 高（容器级）
    资源限制 无 CPU/内存/磁盘
    适用场景 简单文件操作 代码执行、安装依赖

    5.2 沙箱作用域¶

    两种作用域¶

    沙箱作用域：
├── Thread-scoped（线程级）
│   ├── 每个对话独立沙箱
│   ├── 对话结束自动清理
│   └── 适用：数据分析、临时任务
│
└── Assistant-scoped（助手级）
    ├── 所有对话共享沙箱
    ├── 状态持久化
    └── 适用：开发环境、项目上下文

    Thread-scoped（推荐）¶

    每个对话（thread）拥有独立沙箱：

    from daytona import CreateSandboxFromSnapshotParams, Daytona
from deepagents import create_deep_agent
from langchain_core.runnables import RunnableConfig
from langchain_daytona import DaytonaSandbox

client = Daytona()

async def agent(config: RunnableConfig):
    thread_id = config["configurable"]["thread_id"]
    try:
        # 查找现有沙箱
        sandbox = await client.find_one(labels={"thread_id": thread_id})
    except Exception:
        # 创建新沙箱
        sandbox = await client.create(
            CreateSandboxFromSnapshotParams(
                labels={"thread_id": thread_id},
                auto_delete_interval=3600,  # TTL: 1 小时 idle 后清理
            )
        )
    return create_deep_agent(backend=DaytonaSandbox(sandbox=sandbox))

    特点： - ✅ 安全隔离 - ✅ 自动清理 - ✅ 无状态污染 - ⚠️ 每次对话重新初始化

    Assistant-scoped¶

    所有对话共享一个沙箱：

    async def agent(config: RunnableConfig):
    assistant_id = config["metadata"]["assistant_id"]
    try:
        sandbox = await client.find_one(labels={"assistant_id": assistant_id})
    except Exception:
        sandbox = await client.create(
            CreateSandboxFromSnapshotParams(
                labels={"assistant_id": assistant_id}
            )
        )
    return create_deep_agent(backend=DaytonaSandbox(sandbox=sandbox))

    特点： - ✅ 状态持久化 - ✅ 避免重复初始化 - ⚠️ 需要管理磁盘增长 - ⚠️ 多用户可能冲突

    适用场景： - 代码助手（保持项目克隆） - 持续开发环境 - 共享知识库

    5.4 文件传输¶

    沙箱是隔离容器，需要通过专门 API 传输文件。

    上传文件到沙箱¶

    # 在 Agent 运行前上传
await backend.upload_files([
    ("/skills/code_review.py", b"def review(code): ..."),
    ("/memories/preferences.txt", b"style = 'google'"),
])

    从沙箱下载文件¶

    # 在 Agent 运行后下载
results = await backend.download_files([
    "/output/report.md",
    "/output/analysis.csv",
])

for result in results:
    if result.content:
        print(f"{result.path}: {result.content.decode()}")

    同步技能和记忆¶

    使用中间件自动同步：

    from langchain.agents.middleware import AgentMiddleware, AgentState
from langgraph.runtime import Runtime

class SandboxSyncMiddleware(AgentMiddleware):
    """同步技能和记忆到沙箱"""

    def __init__(self, backend):
        super().__init__()
        self.backend = backend

    async def abefore_agent(self, state: AgentState, runtime: Runtime) -> None:
        """运行前：上传技能和记忆"""
        user_id = runtime.context.user_id
        store = runtime.store

        files = []
        # 上传技能
        for item in await store.asearch(("skills", user_id)):
            files.append((f"/skills/{item.key}", item.value["content"].encode()))
        # 上传记忆
        for item in await store.asearch(("memories", user_id)):
            files.append((f"/memories/{item.key}", item.value["content"].encode()))

        if files:
            await self.backend.upload_files(files)

    async def aafter_agent(self, state: AgentState, runtime: Runtime) -> None:
        """运行后：下载更新的记忆"""
        user_id = runtime.context.user_id
        store = runtime.store

        items = await store.asearch(("memories", user_id))
        results = await self.backend.download_files([
            f"/memories/{item.key}" for item in items
        ])

        for result in results:
            if result.content:
                await store.aput(
                    ("memories", user_id),
                    result.path.split("/")[-1],
                    {"content": result.content.decode()}
                )

# 使用中间件
agent = create_deep_agent(
    backend=backend,
    middleware=[SandboxSyncMiddleware(backend)]
)

    5.6 文件系统后端¶

    如果不需要执行 shell 命令，只需文件读写，可使用文件系统后端。

    StateBackend（默认）¶

    临时存储，会话级持久：

    from deepagents import create_deep_agent
from deepagents.backends import StateBackend

# StateBackend 是默认值
agent = create_deep_agent()
# 等价于
agent = create_deep_agent(backend=StateBackend(runtime))

    特点： - ✅ 无需额外配置 - ✅ 检查点自动保存 - ⚠️ 会话结束清除 - ⚠️ 不适合大文件

    StoreBackend¶

    持久存储，跨会话：

    from deepagents.backends import StoreBackend
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

def make_backend(runtime):
    return StoreBackend(
        runtime,
        namespace=lambda ctx: (ctx.runtime.context.user_id,),
    )

agent = create_deep_agent(
    store=store,
    backend=make_backend
)

    特点： - ✅ 持久化 - ✅ 支持命名空间隔离 - ⚠️ 需要配置 Store

    CompositeBackend（推荐）¶

    混合存储，按路径路由：

    from deepagents.backends import CompositeBackend, StateBackend, StoreBackend

def make_backend(runtime):
    return CompositeBackend(
        # 默认：临时存储（scratch 文件）
        default=StateBackend(runtime),
        # 路由：/memories/ 路径持久化
        routes={
            "/memories/": StoreBackend(
                runtime,
                namespace=lambda ctx: (
                    runtime.context.assistant_id,
                    ctx.runtime.context.user_id,
                ),
            ),
        },
    )

agent = create_deep_agent(
    store=InMemoryStore(),
    backend=make_backend,
    system_prompt="""你有持久记忆在 /memories/ 目录。
    读取 /memories/instructions.txt 获取用户偏好。
    学习到的持久知识保存到 /memories/knowledge/"""
)

    路径路由规则：

    路径 后端 持久性
    /scratch/* StateBackend 会话级
    /memories/* StoreBackend 持久
    /skills/* StoreBackend 持久
    其他 StateBackend 会话级

    5.7 后端对比¶

    后端类型 文件读写 Shell 执行 持久性 隔离性 适用场景
    StateBackend ✅ ❌ 会话级 低 临时文件
    StoreBackend ✅ ❌ 持久 中 记忆/技能
    CompositeBackend ✅ ❌ 混合 中 通用
    SandboxBackend ✅ ✅ 可配置 高 代码执行

    5.8 实战配置¶

    配置 1：数据分析 Agent¶

    from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend
from langchain_daytona import DaytonaSandbox
from daytona import Daytona, CreateSandboxFromSnapshotParams

client = Daytona()

async def agent(config: RunnableConfig):
    thread_id = config["configurable"]["thread_id"]
    sandbox = await client.find_one(labels={"thread_id": thread_id})
    if not sandbox:
        sandbox = await client.create(
            CreateSandboxFromSnapshotParams(
                labels={"thread_id": thread_id},
                auto_delete_interval=1800,  # 30 分钟 TTL
            )
        )

    return create_deep_agent(
        backend=CompositeBackend(
            default=DaytonaSandbox(sandbox=sandbox),
            routes={
                "/memories/": StoreBackend(
                    runtime,
                    namespace=lambda ctx: ("user_data", ctx.runtime.context.user_id),
                ),
            },
        ),
        system_prompt="""你是数据分析专家。
        上传的数据文件在 /data/ 目录。
        分析结果保存到 /output/ 目录。
        使用 pandas 和 matplotlib 进行分析。"""
    )

    配置 3：研究助理 Agent¶

    from langgraph.store.postgres import PostgresStore

# 使用持久化存储
store = PostgresStore.from_conn_string(os.environ["DATABASE_URL"])
store.setup()

def make_backend(runtime):
    return CompositeBackend(
        default=StateBackend(runtime),
        routes={

    - /memories/research/report.md - 报告草稿"""
)

    5.9 安全最佳实践¶

    1. 最小权限原则¶

    # ❌ 避免：完全访问
DockerSandbox(image="python:3.11", network_mode="host")

# ✅ 推荐：限制访问
DockerSandbox(
    image="python:3.11-slim",
    network_mode="none",      # 无网络
    mem_limit="512m",         # 内存限制
    cpu_quota=50000,          # CPU 限制
    volumes=["/tmp/data:/data:ro"],  # 只读挂载
)

    2. 镜像选择¶

    # ✅ 使用最小化镜像
image="python:3.11-slim"
image="alpine:latest"

# ❌ 避免：包含敏感信息的镜像
image="my-internal-image:latest"  # 可能包含密钥

    3. TTL 配置¶

    # 始终配置 TTL 防止资源泄漏
CreateSandboxFromSnapshotParams(
    auto_delete_interval=3600,  # 1 小时 idle 后清理
)

    4. 输入验证¶

    def _safe_filename(key: str) -> str:
    """拒绝包含路径遍历或 glob 字符的键"""
    name = key.split("/")[-1]
    if ".." in name or any(c in name for c in ("*", "?")):
        raise ValueError(f"Invalid key: {key}")
    return name

    5.11 本章小结¶

    关键要点¶

    1. 沙箱提供隔离执行环境 - 保护主机，限制资源
    2. 两种作用域 - Thread-scoped（推荐）和 Assistant-scoped
    3. 文件传输需要专门 API - upload_files / download_files
    4. 后端选择 - State/Store/Composite/Sandbox 根据需求

    配置速查¶

    # 临时文件操作
backend = StateBackend(runtime)

# 持久记忆
backend = StoreBackend(runtime, namespace=...)

# 混合使用
backend = CompositeBackend(
    default=StateBackend(runtime),
    routes={"/memories/": StoreBackend(...)}
)

# 代码执行
backend = DaytonaSandbox(sandbox=sandbox)
