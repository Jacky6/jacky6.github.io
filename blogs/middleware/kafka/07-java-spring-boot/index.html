    07 - Java/Spring Boot 实战集成¶

    版本对应关系（2026-08）¶

    Spring Boot spring-kafka Kafka client 说明
    4.1.x 4.1.x 4.2.x 最新，支持 Share Groups
    4.0.x 4.0.x 4.1.x Spring Boot 4 起步版本
    3.5.x（维护末期） 3.3.x 3.x 存量项目常见

    spring-kafka 3.0 起 KafkaTemplate.send() 返回 CompletableFuture， 旧的 ListenableFuture API 已彻底移除。本文所有示例均为新 API。

    application.yml 配置¶

    spring:
  kafka:
    bootstrap-servers: broker1:9092,broker2:9092,broker3:9092

    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
      acks: all
      properties:
        enable.idempotence: true
        max.in.flight.requests.per.connection: 5

    consumer:
      group-id: order-service
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      auto-offset-reset: earliest
      enable-auto-commit: false
      max-poll-records: 500
      properties:
        # Kafka 4.x 新 rebalance 协议（KIP-848），按需开启
        group.protocol: consumer
        max.poll.interval.ms: 300000
        # 静态成员（KIP-345）：重启不触发 rebalance，值必须稳定且组内唯一
        # K8s 环境常用 Pod 名：group.instance.id: ${HOSTNAME}
        group.instance.id: order-service-1

    listener:
      ack-mode: manual      # 手动提交
      concurrency: 3        # 消费线程数（<= partition 数）
      shutdown-timeout: 30s

    Producer 示例¶

    基础发送¶

    @Service
public class OrderProducer {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    public void sendOrder(String orderId, String orderData) {
        kafkaTemplate.send("orders", orderId, orderData);
    }

    // 带回调（spring-kafka 3.0+：CompletableFuture，不再是 ListenableFuture）
    public void sendOrderWithCallback(String orderId, String orderData) {
        kafkaTemplate.send("orders", orderId, orderData)
            .whenComplete((result, ex) -> {
                if (ex == null) {
                    System.out.println("Sent to partition "
                        + result.getRecordMetadata().partition()
                        + " at offset " + result.getRecordMetadata().offset());
                } else {
                    System.err.println("Failed to send: " + ex.getMessage());
                }
            });
    }
}

    Consumer 示例¶

    基础消费¶

    @Service
public class OrderConsumer {

    @KafkaListener(topics = "orders", groupId = "order-service")
    public void consume(ConsumerRecord<String, String> record) {
        System.out.printf("Consumed: partition=%d, offset=%d, key=%s, value=%s%n",
            record.partition(), record.offset(), record.key(), record.value());
        processOrder(record.value());
    }
}

    手动提交 Offset¶

    @Service
public class ManualCommitConsumer {

    @KafkaListener(topics = "orders", groupId = "order-service")
    public void consume(ConsumerRecord<String, String> record, Acknowledgment ack) {
        try {
            processOrder(record.value());
            ack.acknowledge();  // 手动提交
        } catch (Exception e) {
            // 不提交，抛出异常交给错误处理器（重试/DLQ）
            throw e;
        }
    }
}

    对应配置：ack-mode: manual（单条）；批量监听用 batch + AckMode.BATCH。

    批量消费¶

    @KafkaListener(topics = "orders", groupId = "order-service",
               containerFactory = "batchFactory")
public void consumeBatch(List<ConsumerRecord<String, String>> records) {
    for (ConsumerRecord<String, String> record : records) {
        processOrder(record.value());
    }
    // BATCH ack 模式下由容器在监听返回后统一提交
}

    @Bean
public ConcurrentKafkaListenerContainerFactory<String, String> batchFactory(
        ConsumerFactory<String, String> cf) {
    ConcurrentKafkaListenerContainerFactory<String, String> factory =
        new ConcurrentKafkaListenerContainerFactory<>();
    factory.setConsumerFactory(cf);
    factory.setBatchListener(true);
    return factory;
}

    错误处理¶

    DefaultErrorHandler（全局）¶

    @Configuration
public class KafkaErrorHandlerConfig {

    @Bean
    public DefaultErrorHandler errorHandler() {
        // 重试 3 次、每次间隔 1s，之后交给 recoverer
        DefaultErrorHandler handler =
            new DefaultErrorHandler(new FixedBackOff(1000L, 3L));
        // 反序列化异常不重试，直接跳过（避免毒丸消息卡死分区）
        handler.addNotRetryableExceptions(DeserializationException.class);
        return handler;
    }
}

    @RetryableTopic（重试 + 死信队列）¶

    @Service
public class RetryableConsumer {

    @RetryableTopic(
        attempts = "3",
        backoff = @Backoff(delay = 1000, multiplier = 2.0),
        autoCreateTopics = "true"
    )
    @KafkaListener(topics = "orders", groupId = "order-service")
    public void consume(Order order) {
        processOrder(order);  // 失败自动投递到重试 topic（orders-retry-0...）
    }

    @DltHandler
    public void handleDlt(Order order, @Header(KafkaHeaders.RECEIVED_TOPIC) String topic) {
        System.err.println("Dead letter received on " + topic + ": " + order.getId());
    }
}

    原理：失败消息被投递到重试 topic（orders-retry-0、orders-retry-1，延迟递增； attempts="3" 表示共 3 次尝试），最终失败进入 orders-dlt 死信 topic， 全部自动创建和管理。

    事务支持¶

    发送端事务¶

    spring:
  kafka:
    producer:
      transaction-id-prefix: tx-   # 开启后 KafkaTemplate 自动使用事务 Producer

    @Service
public class TransactionalProducer {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    // 多个 send 原子提交（要么全成功要么全回滚）
    public void sendAtomically() {
        kafkaTemplate.executeInTransaction(ops -> {
            ops.send("account-a", "debit", "100");
            ops.send("account-b", "credit", "100");
            return true;
        });
    }
}

    注意：@Transactional（Spring 事务）不会自动把 Kafka send 和数据库操作 绑成一个分布式事务。要真正原子，需要 KafkaTransactionManager 与 DataSourceTransactionManager 链式组合（ChainedKafkaTransactionManager）， 或者把 DB 写入和 Kafka 发送都收敛到 consume-transform-produce 模式。

    Consume-Transform-Produce（EOS）¶

    把"消费 + 处理 + 发送 + 提交 offset"放进同一个 Kafka 事务：

    kafkaTemplate.executeInTransaction(ops -> {
    // 提交消费进度（offsets 纳入当前事务）
    ops.sendOffsetsToTransaction(offsets, consumer.groupMetadata());
    ops.send(new ProducerRecord<>("output", key, value));    // 输出结果
    return true;
});

    配合 Consumer 端 isolation.level=read_committed，实现端到端 Exactly-Once。

    Share Group 消费（spring-kafka 4.x，Kafka 4.1+）¶

    队列式消费：注解还是 @KafkaListener，换用 ShareKafkaListenerContainerFactory：

    @Configuration
@EnableKafka
public class ShareConsumerConfig {

    @Bean
    public ShareConsumerFactory<String, String> shareConsumerFactory() {
        Map<String, Object> props = new HashMap<>();
        props.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG, "broker1:9092");
        props.put(ConsumerConfig.GROUP_ID_CONFIG, "task-workers");
        props.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class);
        props.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class);
        return new DefaultShareConsumerFactory<>(props);
    }

    @Bean
    public ShareKafkaListenerContainerFactory<String, String> shareFactory(
            ShareConsumerFactory<String, String> scf) {
        ShareKafkaListenerContainerFactory<String, String> factory =
            new ShareKafkaListenerContainerFactory<>(scf);
        // 需要监听器自己控制 ACK 时切到 MANUAL（默认 EXPLICIT：容器自动 ACCEPT，异常 REJECT）
        factory.getContainerProperties()
               .setShareAckMode(ContainerProperties.ShareAckMode.MANUAL);
        return factory;
    }
}

@Service
public class TaskShareConsumer {

    // groupId 此时是 share group，不是 consumer group
    @KafkaListener(topics = "tasks", groupId = "task-workers",
                   containerFactory = "shareFactory")
    public void listen(ConsumerRecord<String, String> record,
                       ShareAcknowledgment ack) {
        try {
            process(record);
            ack.acknowledge();   // ACCEPT，处理成功
        } catch (RetriableException e) {
            ack.release();       // RELEASE，临时失败，稍后重新投递
        } catch (Exception e) {
            ack.reject();        // REJECT，永久失败，不再重投
        }
    }
}

    注意：Share 监听器不支持批量监听、不支持 topic pattern、不支持手动 offset 管理； 超过 group.share.delivery.count.limit（默认 5）次投递后记录自动归档（Broker 防毒丸消息）。

    监控¶

    只要引入 spring-boot-starter-actuator + micrometer-registry-prometheus， Spring Boot 会自动为 Kafka 客户端注册 Micrometer 指标（MicrometerConsumerListener / MicrometerProducerListener），无需手写代码：

    management:
  endpoints:
    web:
      exposure:
        include: health,metrics,prometheus

    访问 /actuator/prometheus 即可看到 kafka.consumer.records.consumed.total、 kafka.producer.record.send.total、records.lag.max（消费延迟）等指标， 接入 Prometheus + Grafana。

    重点关注：records-lag-max（消费延迟）、commit-latency-avg（提交延迟）、 request-latency-avg。

    生产环境最佳实践¶

    1. 配置外置：bootstrap-servers、SASL 凭证走环境变量
    2. 优雅关闭：spring.kafka.listener.shutdown-timeout 给足时间提交 offset
    3. 并发：listener.concurrency <= partition 数，多了也是空闲线程
    4. 幂等消费：业务侧用唯一键去重，rebalance 必然带来重复投递风险
    5. 毒丸防护：DefaultErrorHandler 对 DeserializationException 不重试
    6. 日志降噪：org.apache.kafka 设 WARN，避免刷屏

    常见问题¶

    Q: Consumer 重复消费¶

    A:

    1. 检查 offset 提交是否成功（ack-mode、异常是否吞掉）
    2. 使用幂等性处理（数据库唯一约束 / Redis 去重）
    3. rebalance 期间未提交的 offset 必然重复，接受它并做幂等

    Q: 消息顺序错乱¶

    A:

    1. 使用相同 Key 保证分区内有序
    2. 单 Partition 保证全局有序
    3. concurrency=1（多线程监听会破坏分区内顺序，除非用按 key 哈希的监听容器）

    Q: Consumer Lag 持续增长¶

    A:

    1. 增加 Consumer 数量（concurrency / 实例数）
    2. 增加 Partition 数量
    3. 优化处理逻辑 / 批量处理

    Q: 内存溢出¶

    A:

    1. 减小 max.poll.records / max.partition.fetch.bytes
    2. 检查监听器是否无限缓冲
    3. 及时 close consumer
