    06 - 运维指南¶

    本章基于 Kafka 4.x（KRaft 模式）。4.0 起 ZooKeeper 相关命令/配置全部移除， 下面所有示例均为 KRaft 写法。

    KRaft 集群搭建¶

    1. 生成集群 ID 并格式化存储¶

    Kafka 4.x 推荐动态 Controller Quorum（KIP-853）：格式化时用 --initial-controllers 声明初始投票成员，之后可用 kafka-metadata-quorum.sh 在线增删 Controller， 配置上不再写静态的 controller.quorum.voters，改用 controller.quorum.bootstrap.servers。

    # 所有节点共享同一个 cluster-id（只生成一次）
CLUSTER_ID=$(bin/kafka-storage.sh random-uuid)

# 每个 Controller 还要有自己的 directory-id
C1_UUID=$(bin/kafka-storage.sh random-uuid)
C2_UUID=$(bin/kafka-storage.sh random-uuid)
C3_UUID=$(bin/kafka-storage.sh random-uuid)

# Controller 节点：三个 controller 上用相同的 --initial-controllers 值格式化
bin/kafka-storage.sh format \
  -t $CLUSTER_ID \
  -c config/kraft/controller.properties \
  --initial-controllers "101@host1:9093:${C1_UUID},102@host2:9093:${C2_UUID},103@host3:9093:${C3_UUID}"

# Broker（以及后续新增的 Controller）：不指定初始成员
bin/kafka-storage.sh format \
  -t $CLUSTER_ID \
  -c config/kraft/broker.properties --no-initial-controllers
    • 合并模式（broker+controller 同节点，开发用）：format -t $CLUSTER_ID -c config/server.properties
    • 官方 quickstart 用 --standalone 一键起步单节点
    • 静态 quorum（controller.quorum.voters）仍可用，但属于旧模式，新集群建议动态模式

    2. 典型 3 Controller + 3 Broker 部署（生产推荐拆分角色）¶

    # controller 节点（controller1/controller2/controller3）
process.roles=controller
node.id=101
controller.quorum.bootstrap.servers=controller1:9093,controller2:9093,controller3:9093
controller.listener.names=CONTROLLER
listeners=CONTROLLER://controller1:9093
log.dirs=/data/kraft-logs

# broker 节点（broker1/broker2/broker3）
process.roles=broker
node.id=1
controller.quorum.bootstrap.servers=controller1:9093,controller2:9093,controller3:9093
listeners=PLAINTEXT://:9092
advertised.listeners=PLAINTEXT://broker1:9092
log.dirs=/data/kafka-logs

    小规模/开发环境可用 process.roles=broker,controller 合并模式。

    3. Docker 快速启动¶

    docker run -d --name kafka -p 9092:9092 apache/kafka:4.2.0

    常用命令¶

    Topic 管理¶

    # 创建 Topic
kafka-topics.sh --create \
  --bootstrap-server broker1:9092 \
  --topic orders \
  --partitions 3 \
  --replication-factor 3

# 查看所有 Topic
kafka-topics.sh --list --bootstrap-server broker1:9092

# 查看 Topic 详情
kafka-topics.sh --describe --topic orders --bootstrap-server broker1:9092

# 修改 Topic 配置
kafka-topics.sh --alter --topic orders \
  --partitions 6 \
  --bootstrap-server broker1:9092

# 删除 Topic
kafka-topics.sh --delete --topic orders --bootstrap-server broker1:9092

    Consumer Group 管理¶

    # 查看所有 Consumer Group
kafka-consumer-groups.sh --list --bootstrap-server broker1:9092

# 查看 Group 详情
kafka-consumer-groups.sh --describe --group order-service \
  --bootstrap-server broker1:9092

# 重置 Offset
kafka-consumer-groups.sh --group order-service \
  --topic orders \
  --reset-offsets --to-earliest \
  --execute \
  --bootstrap-server broker1:9092

# 重置到指定时间
kafka-consumer-groups.sh --group order-service \
  --topic orders \
  --reset-offsets --to-datetime 2024-01-01T00:00:00.000 \
  --execute \
  --bootstrap-server broker1:9092

    生产/消费测试¶

    # 生产消息（命令行）
kafka-console-producer.sh --topic orders --bootstrap-server broker1:9092

# 消费消息（命令行）
kafka-console-consumer.sh --topic orders \
  --from-beginning \
  --bootstrap-server broker1:9092

# 带 Key 消费
kafka-console-consumer.sh --topic orders \
  --property print.key=true \
  --bootstrap-server broker1:9092

    副本管理¶

    # 查看副本分布（describe 会显示每个分区的 Leader/Replicas/ISR）
kafka-topics.sh --describe --topic orders --bootstrap-server broker1:9092

# 查看副本落后情况（运维排查 ISR 收缩）
kafka-topics.sh --describe --under-replicated-partitions \
  --bootstrap-server broker1:9092

# 重新分配副本
kafka-reassign-partitions.sh --bootstrap-server broker1:9092 \
  --reassignment-json-file reassign.json \
  --execute

# 验证分配进度
kafka-reassign-partitions.sh --bootstrap-server broker1:9092 \
  --reassignment-json-file reassign.json \
  --verify

    Share Group 管理（4.2+）¶

    # 列出 share groups
kafka-share-groups.sh --bootstrap-server broker1:9092 --list

# 查看 share group 状态（start-offset / members / state）
kafka-share-groups.sh --bootstrap-server broker1:9092 \
  --describe --group task-workers --members

    日志查看¶

    # 查看日志大小（KIP-849 起 JSON 输出还包含磁盘 totalBytes/usableBytes）
kafka-log-dirs.sh --bootstrap-server broker1:9092 \
  --describe --broker-list 0,1,2

# 查看 Topic 日志大小
kafka-log-dirs.sh --bootstrap-server broker1:9092 \
  --describe --topic-list orders

    监控指标¶

    关键指标¶

    指标 说明 告警阈值
    UnderReplicatedPartitions 副本落后的分区数 > 0
    OfflinePartitionsCount 离线分区数量 > 0
    ActiveControllerCount Controller 数量 != 1（KRaft 下指 active controller）
    RequestsPerSec 每秒请求数 根据容量
    ConsumerLag 消费者延迟 > 10000
    BytesInPerSec 每秒写入字节数 根据带宽
    BytesOutPerSec 每秒读取字节数 根据带宽

export KAFKA_JMX_OPTS="-Dcom.sun.management.jmxremote \
  -Dcom.sun.management.jmxremote.port=9999 \
  -Dcom.sun.management.jmxremote.authenticate=false \
  -Dcom.sun.management.jmxremote.ssl=false"

kafka-server-start.sh config/server.properties

    性能调优¶

    Broker 端¶

    # 线程数
num.network.threads=3
num.io.threads=8

# 消息大小
message.max.bytes=1048576        # 1MB
replica.fetch.max.bytes=1048576

# 日志刷盘
# 注意：官方建议不要配置这两项（依赖副本机制保证持久性），
# 强制刷盘会显著降低吞吐，仅在特殊合规需求下使用
log.flush.interval.messages=10000
log.flush.interval.ms=1000

# 日志保留
log.retention.hours=168          # 7 天
log.retention.bytes=1073741824   # 1GB（每个分区）
log.segment.bytes=1073741824     # 1GB

# 日志压缩（仅对 compact 型 topic 有意义，如 __consumer_offsets；
# 普通 topic 默认 policy=delete，不要全局改成 compact）
log.cleaner.enable=true
# topic 级配置：log.cleanup.policy=compact

    Producer 端¶

    # 提高吞吐
batch.size=32768                 # 32KB
linger.ms=10
compression.type=lz4
buffer.memory=67108864           # 64MB

# 降低延迟
batch.size=0
linger.ms=0

    Consumer 端¶

    # 提高吞吐
fetch.min.bytes=1048576          # 1MB
fetch.max.wait.ms=500
max.poll.records=1000

# 降低延迟
fetch.min.bytes=1
fetch.max.wait.ms=100
max.poll.records=100

    集群扩缩容¶

    增加 Broker¶

    1. 启动新 Broker
    2. 使用 kafka-reassign-partitions.sh 重新分配分区
    3. 等待数据迁移完成

    减少 Broker¶

    1. 将要下线的 Broker 上的分区迁移到其他 Broker
    2. 等待迁移完成
    3. 停止 Broker

    增加 Partition¶

    kafka-topics.sh --alter --topic orders \
  --partitions 6 \
  --bootstrap-server broker1:9092

    注意： - 只能增加，不能减少 - 已存在的消息不会重新分配 - 如果使用了 Key 分区，增加 Partition 会改变分区逻辑

    故障排查¶

    Consumer Lag 持续增长¶

    # 查看 Lag
kafka-consumer-groups.sh --describe --group order-service \
  --bootstrap-server broker1:9092

# 原因：
# 1. Consumer 处理太慢 → 优化处理逻辑
# 2. Consumer 数量不够 → 增加 Consumer
# 3. Partition 太少 → 增加 Partition

# 临时方案：创建临时 Topic 和 Consumer Group 快速消费

    Broker 频繁 Full GC¶

    # 调整 JVM 参数
export KAFKA_HEAP_OPTS="-Xmx6G -Xms6G"

# 检查内存使用
jstat -gcutil <pid> 1000

    磁盘空间不足¶

    # 减少保留时间
log.retention.hours=24

# 减少保留大小
log.retention.bytes=10737418240  # 10GB

# 启用日志压缩
log.cleanup.policy=compact

    网络瓶颈¶

    # 增加网络线程
num.network.threads=8

# 增加 socket buffer
socket.send.buffer.bytes=1048576
socket.receive.buffer.bytes=1048576

    安全配置¶

    SASL 认证¶

    # server.properties
listeners=SASL_PLAINTEXT://0.0.0.0:9092
sasl.enabled.mechanisms=PLAIN
sasl.mechanism.inter.broker.protocol=PLAIN

# kafka_server_jaas.conf
KafkaServer {
    org.apache.kafka.common.security.plain.PlainLoginModule required
    username="admin"
    password="admin-secret"
    user_admin="admin-secret"
    user_alice="alice-secret";
};

    SSL 加密¶

    # server.properties（KRaft 部署下 9093 通常留给 CONTROLLER listener，SSL 用 9094）
listeners=SSL://0.0.0.0:9094
ssl.keystore.location=/var/ssl/private/kafka.keystore.jks
ssl.keystore.password=keystore-password
ssl.truststore.location=/var/ssl/private/kafka.truststore.jks
ssl.truststore.password=truststore-password

    ACL 授权¶

    Kafka 4.x 使用 --bootstrap-server（ZooKeeper 授权方式已随 ZK 一起移除）， 需要 broker 配置了 KafkaAuthorizer（如 org.apache.kafka.metadata.authorizer.StandardAuthorizer）：

    # server.properties
authorizer.class.name=org.apache.kafka.metadata.authorizer.StandardAuthorizer
super.users=User:admin

    # 给用户授权
kafka-acls.sh --bootstrap-server broker1:9092 \
  --add --allow-principal User:alice \
  --operation Read --operation Write \
  --topic orders

# 查看授权
kafka-acls.sh --bootstrap-server broker1:9092 --list --topic orders

    版本升级¶

    Kafka 4.x 滚动升级（KRaft）¶

    1. 备份配置和数据
    2. 逐台升级 Broker（一台一台：停机 → 换二进制 → 启动 → 等 ISR 恢复）
    3. Controller 最后升级，active controller 放最后
    4. 等待 ISR 恢复、UnderReplicatedPartitions == 0
    5. 所有节点升级完成后，finalize 升级（提升 metadata.version）：
    # 查看当前特性 / 元数据版本
kafka-features.sh --bootstrap-server broker1:9092 describe

# finalize 升级（KRaft 时代用 metadata.version 取代了旧的
# inter.broker.protocol.version，后者已在 4.0 移除）
kafka-features.sh --bootstrap-server broker1:9092 upgrade \
  --release-version 4.2

    注意：finalize 之前集群以旧 metadata.version 运行；finalize 之后 不能降级回更低版本（metadata 变更不可逆），务必先验证稳定。

    从 ZooKeeper 模式迁移到 KRaft（升级 4.x 前必做）¶

    Kafka 4.0 不支持从 ZooKeeper 模式直接升级，必须先迁移：

    1. 在 3.x（推荐 3.9.x）上以 migration mode 加入 KRaft Controller
    2. 双写元数据，逐步切换
    3. 下线 ZooKeeper，完成迁移后再升级 4.x

    官方文档：搜索 "ZooKeeper to KRaft migration"（kafka.apache.org/documentation）。
