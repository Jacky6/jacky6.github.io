    03 - 生产者（Producer）¶

    发送消息的流程¶

    Producer
  │
  ├─ 1. 序列化 Key/Value
  ├─ 2. 分区器选择 Partition
  ├─ 3. 消息进入 RecordAccumulator（发送缓冲区）
  ├─ 4. 攒批（batch）
  ├─ 5. Sender 线程批量发送
  └─ 6. Broker 响应 → 回调 Callback

    分区策略¶

    Producer 如何决定消息发到哪个 Partition？

    1. 指定 Partition¶

    producer.send(new ProducerRecord<>("topic", 2, "key", "value"));
// 直接发到 Partition 2

    2. 指定 Key（默认策略）¶

    producer.send(new ProducerRecord<>("topic", "key", "value"));
// 对 key 做哈希，映射到某个 partition
// 相同 key → 相同 partition → 保证有序

    Kafka 默认使用 MurmurHash2 对 key 哈希： 

    partition = hash(key) % numPartitions

    3. 既不指定 Key 也不指定 Partition¶

    使用 粘性分区（Sticky Partitioning）（Kafka 2.4+）： - 攒满一个 batch 后换一个 partition - 提高并行度

    ACK 机制（确认机制）¶

    Producer 发送消息后，Broker 如何确认？

    acks 含义 延迟 可靠性
    0 不等确认，发完就走 最低 可能丢消息
    1 Leader 写入成功即确认 中等 Leader 挂可能丢
    all / -1 ISR 所有副本写入成功 最高 不丢消息

    Kafka 3.0 起 acks 默认值改为 all，enable.idempotence 默认 true， 即默认配置就是"不丢消息"档。开启幂等性时客户端会强制校验 acks=all 且 max.in.flight.requests.per.connection <= 5。

    acks=all + min.insync.replicas=2:
  Leader 写入 ✓
  Follower 1 写入 ✓
  → 返回成功

acks=all + min.insync.replicas=3，ISR 只有 2 个:
  → 返回 NotEnoughReplicasException

    重试机制¶

    Properties props = new Properties();
props.put("retries", 3);                    // 重试次数
props.put("retry.backoff.ms", 100);         // 重试间隔
props.put("delivery.timeout.ms", 120000);   // 总超时时间
props.put("enable.idempotence", true);      // 幂等性

    幂等性（Idempotence）¶

    开启 enable.idempotence=true（默认开启）：

    • 每条消息分配一个 Producer ID + Sequence Number
    • Broker 去重，防止重试导致消息重复
    Producer PID=1:
  msg1 (seq=0) → Broker 接收 ✓
  msg1 (seq=0) → 重试 → Broker 发现重复，丢弃 ✓
  msg2 (seq=1) → Broker 接收 ✓

    批量发送配置¶

    props.put("batch.size", 16384);        // 16KB，一个 batch 的大小
props.put("linger.ms", 5);             // 等待 5ms 攒批
props.put("buffer.memory", 33554432);  // 32MB，发送缓冲区总大小
props.put("compression.type", "lz4");  // 压缩算法：gzip/snappy/lz4/zstd

    压缩算法选择：lz4 吞吐与压缩比均衡（默认推荐），zstd 压缩比最高（CPU 开销略大）， snappy 老牌低延迟选择。

    调优思路： - 提高吞吐 → 增大 batch.size + linger.ms - 降低延迟 → 减小 linger.ms

    代码示例（Java）¶

    Properties props = new Properties();
props.put("bootstrap.servers", "broker1:9092,broker2:9092");
props.put("key.serializer", "org.apache.kafka.common.serialization.StringSerializer");
props.put("value.serializer", "org.apache.kafka.common.serialization.StringSerializer");
props.put("acks", "all");
props.put("enable.idempotence", true);

try (KafkaProducer<String, String> producer = new KafkaProducer<>(props)) {
    // 异步发送 + 回调
    producer.send(new ProducerRecord<>("orders", "order-123", "{\"amount\": 99.9}"),
        (metadata, exception) -> {
            if (exception == null) {
                System.out.println("Sent to partition " + metadata.partition()
                    + " at offset " + metadata.offset());
            } else {
                exception.printStackTrace();
            }
        });
}

    Producer 常见配置速查¶

    配置 默认值 说明
    acks all 确认机制
    retries 2147483647 重试次数
    batch.size 16384 批次大小（字节）
    linger.ms 0 攒批等待时间
    buffer.memory 33554432 缓冲区大小
    compression.type none 压缩算法
    max.in.flight.requests.per.connection 5 未确认请求最大数
    enable.idempotence true 幂等性
