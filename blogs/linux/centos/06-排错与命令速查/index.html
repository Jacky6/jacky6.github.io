    06. CentOS 排错与命令速查¶

    1. 推荐排障流程¶

    1. 描述现象：发生时间、影响范围、是否可复现。
    2. 确认变更：代码、配置、软件包、证书、网络和安全策略。
    3. 检查状态：服务、进程、端口、CPU、内存、磁盘。
    4. 读取日志：定位第一条异常，不只关注连锁报错。
    5. 检查安全层：Unix 权限、firewalld、SELinux、云安全组。
    6. 一次改一项：记录操作和结果，保留回滚方式。
    7. 验证恢复：健康检查、业务请求、监控和日志均正常。

    2. 系统与资源¶

    uptime
hostnamectl
uname -a
free -h
vmstat 1
lsblk -f
df -hT
df -ih
sudo du -xhd1 /var | sort -h
top

    安装诊断工具：

    sudo dnf install htop iotop sysstat lsof

    htop
sudo iotop -oPa
pidstat 1

    磁盘仍有空间却提示 “No space left on device” 时，用 df -ih 检查 inode。

    3. 进程与端口¶

    ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head
pgrep -af process-name
pstree -ap
sudo lsof -p PID
sudo lsof -iTCP:8080 -sTCP:LISTEN
ss -lntup

    优先发送 TERM：

    kill PID
kill -KILL PID       # 仅在无法正常退出时使用

    systemd 管理的服务应通过 systemctl stop/restart 操作，否则可能被自动拉起。

    4. 日志¶

    journalctl -p warning..alert --since today
journalctl -u service-name -f
journalctl -b -p err
journalctl -b -1 -p err
sudo tail -f /var/log/secure
sudo tail -f /var/log/messages
dmesg --level=err,warn

    按关键字筛选：

    journalctl -u service-name --since "1 hour ago" | grep -iE 'error|fail|timeout'

    分享日志前隐藏令牌、Cookie、连接串和用户隐私数据。

    5. 网络¶

    nmcli device status
ip -br a
ip route
ss -lntup
ping -c 4 host
getent hosts host
dig host
curl -v --connect-timeout 5 https://host/path
nc -vz host 443
mtr -rwzc 20 host

    判断思路：

    • IP 不通：路由、接口、VPN、安全组或网络 ACL。
    • IP 通但域名不通：DNS。
    • 端口不通：监听地址、firewalld、端口映射或上游网络策略。
    • 本机通、远程不通：服务可能只监听 127.0.0.1。
    • TCP 通但请求失败：TLS、HTTP、反向代理或应用层错误。

    6. 文件权限与 SELinux¶

    namei -l /path/to/file
stat /path/to/file
id
getfacl /path/to/file
ls -lZ /path/to/file
ps -eZ | grep process-name
getenforce
sudo ausearch -m AVC -ts recent

    修复默认文件标签：

    sudo restorecon -Rv /path/to/file-or-directory

    如果文件位于非标准服务目录，应使用 semanage fcontext 建立持久规则，而不是长期依赖 chcon。

    排查 SELinux：

    1. 确认普通 Unix 权限正确。
    2. 复现问题并记录时间。
    3. 使用 ausearch -m AVC -ts recent 查看拒绝。
    4. 检查目标文件类型、进程域、端口类型和相关布尔值。
    5. 优先采用已有策略支持的标签和布尔值。
    6. 只有确认应用行为合理且现有策略无法表达时，才创建最小化本地策略。

    不把 setenforce 0 或禁用 SELinux 当作修复。

    7. firewalld¶

    sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all
sudo firewall-cmd --list-all-zones

    临时规则与永久规则是两套配置。使用 --permanent 修改后需 firewall-cmd --reload，并再次检查生效结果。

    8. systemd 服务失败¶

    systemctl status service-name --no-pager
journalctl -u service-name -b --no-pager
systemctl cat service-name
systemctl show service-name -p User,Group,Environment,ExecStart

    检查项目：

    • ExecStart 路径和参数。
    • 运行用户与组。
    • 环境变量和工作目录。
    • 文件权限与 SELinux 标签。
    • 依赖服务和挂载点。
    • 端口占用与防火墙规则。

    修改后：

    sudo systemctl daemon-reload
sudo systemctl restart service-name
systemctl status service-name --no-pager

    9. DNF 与 RPM¶

    sudo dnf check
sudo dnf clean all
sudo dnf makecache --refresh
dnf history
dnf repoquery --duplicates
dnf repoquery --unsatisfied
rpm -Va

    rpm -Va 输出可能很多，配置文件变化也不一定是故障。应结合软件包、时间和预期配置判断。

    10. 常用命令速查¶

    目标 命令
    查看发行版 cat /etc/os-release
    查看 IP ip -br a
    查看路由 ip route
    查看端口 ss -lntup
    查看磁盘 df -hT
    查看目录大小 du -sh <目录>
    查看内存 free -h
    查看进程 ps aux / top
    查看服务 systemctl status <服务>
    查看服务日志 journalctl -u <服务>
    查看防火墙 sudo firewall-cmd --list-all
    查看 SELinux getenforce / sestatus
    查看 AVC 拒绝 sudo ausearch -m AVC -ts recent
    查包提供者 dnf provides '*/<命令>'
