    04. CentOS 服务、网络与安全策略¶

    1. systemd 服务管理¶

    systemctl status nginx --no-pager
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx
sudo systemctl enable --now nginx
sudo systemctl disable nginx
systemctl is-active nginx
systemctl is-enabled nginx
systemctl --failed

    查看单元定义和依赖：

    systemctl cat nginx
systemctl list-dependencies nginx
systemd-analyze critical-chain

    使用覆盖文件修改软件包提供的服务：

    sudo systemctl edit nginx
sudo systemctl daemon-reload
sudo systemctl restart nginx

    不要直接修改 /usr/lib/systemd/system/ 下的文件，升级软件包时可能被覆盖。

    2. journald 日志¶

    journalctl -u nginx
journalctl -u nginx -f
journalctl -u nginx --since "30 minutes ago"
journalctl -p err..alert --since today
journalctl -b
journalctl -b -1
sudo journalctl --disk-usage

    传统安全日志通常位于 /var/log/secure，系统消息可能位于 /var/log/messages。具体文件取决于 rsyslog 配置。

    3. NetworkManager¶

    nmcli general status
nmcli device status
nmcli connection show
ip -br address
ip route

    查看连接配置：

    nmcli connection show "connection-name"

    修改 DNS 示例：

    sudo nmcli connection modify "connection-name" \
  ipv4.ignore-auto-dns yes \
  ipv4.dns "1.1.1.1 8.8.8.8"
sudo nmcli connection up "connection-name"

    远程修改网络配置可能断开 SSH。生产机器应通过带外控制台操作，或准备可自动回滚的方案。

    网络诊断：

    ss -lntup
ping -c 4 1.1.1.1
getent hosts example.com
dig example.com
curl -v https://example.com
nc -vz example.com 443

    安装工具：

    sudo dnf install bind-utils iputils traceroute mtr nmap-ncat tcpdump

    4. firewalld¶

    检查状态和活动区域：

    sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

    放行服务：

    sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload

    放行端口：

    sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports

    删除规则：

    sudo firewall-cmd --permanent --remove-port=8080/tcp
sudo firewall-cmd --reload

    修改前确认接口属于哪个 zone。远程服务器应先放行 SSH，再调整默认区域。云环境还需要检查安全组和网络 ACL。

    5. SELinux 状态与日志¶

    getenforce
sestatus
ls -Z /srv/app
ps -eZ | grep nginx
sudo ausearch -m AVC -ts recent

    安装分析与管理工具：

    sudo dnf install policycoreutils-python-utils setroubleshoot-server

    解释最近的拒绝：

    sudo ausearch -m AVC -ts recent | audit2why

    不要看到拒绝就直接生成并安装宽泛的本地策略。先判断文件标签、端口类型、布尔值和应用行为是否正确。

    6. 配置文件上下文¶

    为站点目录设置持久规则：

    sudo semanage fcontext -a -t httpd_sys_content_t '/srv/site(/.*)?'
sudo restorecon -Rv /srv/site

    需要 Web 服务写入的目录可使用适当的可写类型，例如 httpd_sys_rw_content_t，但仅授予实际需要写入的子目录。

    chcon 修改通常会在重新标记后丢失；持久配置应使用 semanage fcontext 加 restorecon。

    7. SELinux 端口与布尔值¶

    查看允许的 HTTP 端口：

    sudo semanage port -l | grep http_port_t

    允许 Web 服务绑定 8080：

    sudo semanage port -a -t http_port_t -p tcp 8080

    若端口已存在于其他类型，需先查明用途，再决定是否使用 -m 修改。

    查看并启用 Web 服务主动连接上游：

    getsebool httpd_can_network_connect
sudo setsebool -P httpd_can_network_connect on

    只开启业务实际需要的布尔值。

    8. 定时任务¶

    crontab -e
crontab -l
systemctl status crond
systemctl list-timers --all

    需要依赖管理、日志与失败状态的任务优先使用 systemd timer。任务中应使用绝对路径，并确保运行用户拥有正确的 Unix 权限和 SELinux 上下文。
