    05. CentOS 容器开发环境¶

    1. Podman¶

    CentOS/RHEL 生态优先提供 Podman。安装容器工具：

    sudo dnf install podman buildah skopeo
podman info

    运行测试容器：

    podman run --rm docker.io/library/alpine:latest echo hello

    常用命令：

    podman ps
podman ps -a
podman images
podman logs -f container-name
podman exec -it container-name sh
podman inspect container-name
podman stats

    Podman 默认可由普通用户运行 rootless 容器，不依赖常驻守护进程。

    2. 构建镜像¶

    podman build -t localhost/example/app:dev .
podman run --rm -p 127.0.0.1:8080:8080 localhost/example/app:dev

    建议：

    • 使用明确版本或镜像摘要，不依赖 latest。
    • 使用多阶段构建并在容器中采用非 root 用户。
    • 添加 .containerignore 或 .dockerignore，排除 .git、密钥和构建产物。
    • 从不受信任仓库拉取镜像前核实来源。

    3. rootless 存储与用户会话¶

    podman info --debug
loginctl show-user "$USER" -p Linger

    需要用户服务在注销后继续运行：

    sudo loginctl enable-linger "$USER"

    rootless 容器不能直接绑定小于 1024 的端口，通常通过反向代理、高位端口或受控的系统配置解决。

    4. 数据卷与 SELinux¶

    绑定挂载在 SELinux 系统上需要正确标签：

    podman run --rm \
  -v "$PWD/data:/data:Z" \
  docker.io/library/alpine:latest ls -la /data
    • :Z：为单个容器设置私有标签。
    • :z：允许多个容器共享该内容。

    不要为了让挂载工作而关闭 SELinux。生产数据应有独立备份，容器和命名卷本身不是备份。

    5. Podman Compose¶

    CentOS 主版本和仓库提供的 Compose 工具可能不同，先查询：

    dnf search podman-compose
podman compose --help

    如果团队依赖 Compose，应在 CI 中验证 Docker Compose 与 Podman Compose 的兼容性。网络、健康检查、构建和扩展字段并非始终完全一致。

    6. 使用 systemd 管理容器¶

    新项目优先使用 Quadlet，将容器声明放入用户或系统级目录：

    ~/.config/containers/systemd/
/etc/containers/systemd/

    示例 web.container：

    [Unit]
Description=Example web container
After=network-online.target

[Container]
Image=localhost/example/app:dev
PublishPort=127.0.0.1:8080:8080

[Service]
Restart=on-failure

[Install]
WantedBy=default.target

    用户级加载与启动：

    systemctl --user daemon-reload
systemctl --user start web.service
systemctl --user status web.service
journalctl --user -u web.service

    Quadlet 支持范围取决于 Podman 版本，使用前查看 man podman-systemd.unit。

    7. Docker Engine（可选）¶

    如果项目明确依赖 Docker，可配置 Docker 官方仓库：

    sudo dnf install dnf-plugins-core
sudo dnf config-manager --add-repo \
  https://download.docker.com/linux/centos/docker-ce.repo
sudo dnf install docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world

    CentOS Stream 与 Docker 支持范围可能变化，应以 Docker 官方 CentOS 安装文档 为准。

    普通用户加入 Docker 组：

    sudo usermod -aG docker "$USER"
newgrp docker

    docker 组基本拥有主机 root 等级能力，只授予可信用户。与 Podman 并存时应明确命令、Socket、网络和镜像存储，避免误操作。

    8. 清理与排错¶

    podman system df
podman container prune
podman image prune
podman volume ls
podman logs container-name

    谨慎执行带卷的全局清理。端口不可访问时依次检查：

    podman ps
ss -lntp
curl -v http://127.0.0.1:8080
sudo firewall-cmd --list-all
sudo ausearch -m AVC -ts recent

    依次确认应用监听地址、容器端口映射、firewalld、SELinux、云安全组和反向代理。
