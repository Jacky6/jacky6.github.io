    Linux 进程与作业常用命令¶

    进程是正在运行的程序实例。排查进程问题时，通常按“找到 PID → 查看状态与资源 → 查看日志或打开文件 → 发送合适信号”的顺序处理。

    1. ps：查看进程快照¶

    ps aux

    USER   PID  %CPU %MEM    VSZ   RSS TTY   STAT START  TIME COMMAND
root     1   0.0  0.2 167404 11800 ?     Ss   09:00  0:02 /sbin/init
alice  1842   2.3  8.5 4123456 348160 ?   Sl   09:05  1:12 java -jar app.jar
alice  2101   0.0  0.1  12344  3400 pts/0 R+   10:12  0:00 ps aux
    • PID：进程 ID，后续 kill 等命令用它定位进程。
    • %CPU/%MEM：CPU 和内存使用率。
    • RSS：实际驻留内存（KiB），示例中 Java 进程约 340 MB。
    • STAT：S 睡眠、R 运行、Sl 多线程睡眠。
    • TIME：累计 CPU 时间，与已运行时长（etime）不同。

    自定义字段并排序：

    ps -eo pid,ppid,user,stat,%cpu,%mem,etime,cmd --sort=-%cpu | head

      PID  PPID USER    STAT %CPU %MEM     ELAPSED CMD
 1842     1 alice   Sl   2.3  8.5    01:07:23 java -jar app.jar
  950     1 root    Ss   0.7  1.2    01:07:20 /usr/sbin/sshd -D
    1     0 root    Ss   0.0  0.2    01:07:25 /sbin/init

    --sort=-%cpu 按 CPU 降序，head 只看前几名。ELAPSED 是进程已存活时长。

    ps aux 属于 BSD 风格，ps -ef 属于 UNIX 风格，不建议随意混合两套选项。

    常见字段：

    字段 含义
    PID 进程 ID
    PPID 父进程 ID
    USER 进程所有者
    STAT 进程状态
    %CPU CPU 使用率
    %MEM 内存占比
    ETIME 已运行时长
    CMD 命令行

    按资源排序：

    ps -eo pid,user,%cpu,%mem,etime,cmd --sort=-%cpu | head
ps -eo pid,user,%cpu,%mem,etime,cmd --sort=-%mem | head

    查看进程树：

    ps -ef --forest
pstree -ap

    2. pgrep 与 pidof¶

    pgrep -a nginx

    1201 nginx: master process /usr/sbin/nginx
1202 nginx: worker process
1203 nginx: worker process

    每行是 PID 和进程名。-a 显示完整命令名，-f 匹配完整命令行，-u 按用户筛选：

    pgrep -af 'java.*app.jar'

    1842 java -jar app.jar

    使用 ps aux | grep name 可能同时匹配到 grep 自身，并且不能精确表达进程属性；优先使用 pgrep。

    3. top 与动态观察¶

    top

    常用按键：

    按键 作用
    P 按 CPU 排序
    M 按内存排序
    1 展开每个逻辑 CPU
    H 显示线程
    k 向指定 PID 发送信号
    q 退出

    批处理模式适合记录快照：

    top -b -n 1 | head -n 30

    若已安装，也可使用交互更友好的 htop。

    持续查看单个进程：

    watch -n 2 'ps -p 1234 -o pid,ppid,stat,%cpu,%mem,etime,cmd'

    4. 查看进程详细信息¶

    /proc/<PID> 是内核提供的进程信息接口：

    cat /proc/1842/status | head -n 5

    Name:   java
Umask:  0022
State:  S (sleeping)
Tgid:   1842
Pid:    1842

    State 行显示进程当前状态。查看进程的完整命令行、可执行文件和工作目录：

    tr '\0' ' ' < /proc/1842/cmdline; echo
readlink -f /proc/1842/cwd

    java -jar app.jar
/home/alice/app

    cmdline 中参数以 NUL 分隔，所以要用 tr 转换显示；cwd 是进程的工作目录，排查“进程在哪个目录下运行”时很有用。

    查看打开的文件与端口：

    sudo lsof -p 1842 | head -n 8

    COMMAND  PID  USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
java    1842 alice  cwd    DIR  252,0     4096 1329123 /home/alice/app
java    1842 alice  txt    REG  252,0   172432  1442351 /usr/lib/jvm/.../java
java    1842 alice    9u  IPv6  21034      0t0  TCP *:8080 (LISTEN)
java    1842 alice   10w  REG  252,0  1048576  1329200 /home/alice/app/logs/app.log

    FD 列是文件描述符：cwd 工作目录、txt 程序本身、9u 打开的 Socket、10w 以写模式打开的日志文件。最后一列 TCP *:8080 (LISTEN) 直接说明该进程监听 8080 端口。

    5. kill 与信号¶

    kill 实际是向进程发送信号，不一定代表强制终止。

    kill -l
kill -TERM 1234
kill -HUP 1234
kill -KILL 1234

    常用信号：

    信号 编号 常见含义
    SIGHUP 1 终端断开；部分服务将其用于重新加载配置
    SIGINT 2 交互中断，通常由 Ctrl+C 产生
    SIGTERM 15 请求进程优雅终止，默认信号
    SIGKILL 9 由内核立即终止，进程无法清理资源
    SIGSTOP 19 暂停进程，不能捕获或忽略
    SIGCONT 18 恢复暂停进程

    推荐流程：

    kill -TERM 1234
# 等待并确认进程是否退出
ps -p 1234
# 仅在无法正常退出且已评估影响时
kill -KILL 1234

    不要直接对数据库、消息队列等有状态服务发送 SIGKILL，否则可能造成恢复变慢或数据风险。

    按名称发送信号：

    pkill -TERM -x process-name

    -x 要求进程名精确匹配。执行前先用对应条件的 pgrep 检查目标。

    6. 前台、后台与 Shell 作业¶

    在命令末尾加 & 可后台启动：

    long-command > run.log 2>&1 &

    [1] 2105

    方括号中的 1 是作业号，2105 是 PID。

    查看当前 Shell 的作业：

    jobs -l

    [1]+  2105 Running                 long-command > run.log 2>&1 &

    + 表示当前默认作业。控制作业：

    # Ctrl+Z 暂停当前前台作业，会显示：
# [1]+  Stopped                 long-command
bg %1    # 让作业 1 在后台继续运行
fg %1    # 把作业 1 调回前台
kill %1  # 向作业 1 发送终止信号

    jobs 只显示当前 Shell 管理的作业，不等于系统全部进程。

    7. nohup 与脱离终端¶

    nohup long-command > run.log 2>&1 &

    nohup 让进程忽略 SIGHUP，但并不是完整的进程守护和日志管理方案。长期服务优先创建 systemd 服务，交互任务可使用 tmux 或 screen。

    Bash 中可将作业从当前 Shell 作业表移除：

    disown %1

    8. 等待和超时¶

    time sleep 2

    real    0m2.003s
user    0m0.001s
sys 0m0.002s

    real 是实际经过时间，user 是用户态 CPU 时间，sys 是内核态 CPU 时间。I/O 密集任务通常 real 远大于 user+sys。

    timeout 3 sleep 100
echo "$?"

    124

    退出码 124 是 timeout 的约定：命令超时被终止。脚本中可据此区分“执行失败”和“执行太慢”。

    指定信号及强制终止宽限时间：

    timeout --signal=TERM --kill-after=5s 30s command

    脚本中等待后台任务：

    command1 &
pid1=$!
command2 &
pid2=$!
wait "$pid1"
wait "$pid2"

    $! 是最近一个后台管道的 PID。

    9. nice 与 renice¶

    启动时设置调度优先级：

    nice -n 10 cpu-heavy-command

    调整已有进程：

    renice 10 -p 1234

    nice 值通常从 -20 到 19；数值越大，CPU 调度优先级越低。降低 nice 值通常需要额外权限。nice 不是 CPU 硬限制，资源隔离应使用 cgroup 或 systemd 资源控制。

    10. 常见进程状态¶

    ps 的 STAT 常见首字母：

    状态 含义
    R 正在运行或可运行
    S 可中断睡眠，常见等待状态
    D 不可中断睡眠，常与 I/O 等待有关
    T 已暂停或被跟踪
    Z 僵尸进程，已退出但父进程尚未回收

    僵尸进程本身不再消耗常规内存，但占用进程表项。应检查父进程：

    ps -o pid,ppid,stat,cmd -p 1234

    通常需要修复或重启未正确调用 wait 的父进程，而不是对僵尸 PID 执行 kill -9。

    D 状态进程不能被普通信号立即终止，应继续排查磁盘、网络文件系统或设备 I/O。

    11. 排查流程¶

    CPU 使用率高¶

    top
ps -eo pid,ppid,user,%cpu,%mem,stat,etime,cmd --sort=-%cpu | head

    然后检查进程日志、线程和调用链，不要仅凭瞬时快照下结论。

    内存使用率高¶

    free -h
ps -eo pid,user,rss,%mem,etime,cmd --sort=-rss | head

    RSS 是进程当前驻留内存，但共享页会导致简单相加不准确。

    进程无法退出¶

    1. 查看状态：ps -o pid,ppid,stat,wchan:32,cmd -p <PID>。
    2. 发送 SIGTERM 并观察日志。
    3. 检查子进程和打开资源。
    4. 只有在确认无法恢复且可接受风险时使用 SIGKILL。

    12. 命令速查¶

    需求 命令
    查看全部进程 ps aux
    自定义字段 ps -eo pid,ppid,user,stat,%cpu,%mem,etime,cmd
    按名称定位 pgrep -af name
    动态监控 top
    查看进程树 pstree -ap
    优雅终止 kill -TERM PID
    强制终止 kill -KILL PID
    查看后台作业 jobs -l
    后台持续运行 nohup command > run.log 2>&1 &
    添加超时 timeout 30s command

    终止进程前先确认 PID、所有者、父子关系和业务作用，优先使用服务管理器停止受管服务。
