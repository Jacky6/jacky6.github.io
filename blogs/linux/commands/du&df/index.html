    df 与 du：磁盘空间排查教程¶

    df 查看文件系统整体空间，du 统计目录和文件实际占用。磁盘告警时通常先用 df 确认分区，再用 du 逐层定位大目录。

    1. 核心区别¶

    命令 统计对象 数据来源 典型用途
    df 已挂载文件系统 文件系统元数据 查看分区总量、已用、可用空间
    du 指定目录或文件 遍历目录树 定位哪些目录或文件占用空间

    二者结果可能不一致，例如文件已被删除但仍被进程打开时，df 显示空间未释放，而 du 已经找不到该文件。

    2. df 常用命令¶

    以易读单位显示¶

    df -h

    Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        98G   42G   51G  46% /
/dev/sda1       512M  6.1M  506M   2% /boot/efi
tmpfs           7.8G     0  7.8G   0% /dev/shm
    • Size：分区总容量。
    • Used/Avail：已用和可用容量。
    • Use%：使用率，超过 80% 时应开始规划清理或扩容。
    • Mounted on：挂载点，/ 是根分区。

    tmpfs 是内存文件系统，重启后清空，不算磁盘占用。

    查看指定路径所在文件系统¶

    df -h /var/lib

    排查某个目录时优先使用这种方式，避免在完整列表中找错挂载点。

    查看文件系统类型¶

    df -hT

    查看 inode 使用率¶

    df -i

    Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sda2      6553600 182340 6371260    3% /

    IUse% 是 inode 使用率。磁盘仍有容量但无法创建文件时，可能是 inode 耗尽——此时 df -h 显示 Avail 充足，但 df -i 的 IUse% 接近 100%。大量小文件会快速消耗 inode。

    POSIX 格式输出¶

    df -P

    -P 可让每个文件系统保持单行输出，更适合脚本解析。

    3. du 常用命令¶

    查看目录总占用¶

    du -sh /var/log
    • -s：只显示合计。
    • -h：使用 KiB、MiB、GiB 等易读单位。

    查看当前目录一级子项¶

    du -h --max-depth=1 . | sort -h

    4.0K    ./docs
12M ./scripts
1.2G    ./node_modules
2.5G    ./data
3.7G    .

    每行是“大小 目录名”，按从小到大排序，最后一行 . 是当前目录合计。示例中 data 和 node_modules 是主要占用，应优先检查。--max-depth=1 是 GNU du 选项。

    兼容性更好的一级目录写法是：

    du -sh ./* 2>/dev/null | sort -h

    ./* 不包含隐藏文件。需要检查隐藏目录时可单独查看，例如 du -sh ./.??*；执行前确认 glob 的展开结果。

    查看所有文件并排序¶

    du -ah /var/log 2>/dev/null | sort -h | tail -n 20

    这会递归遍历目录，大型文件系统上可能耗时并产生明显 I/O。

    限制在当前文件系统¶

    du -xhd1 /

    -x 可避免进入其他挂载点，如网络盘、容器挂载和伪文件系统。

    查看表观大小¶

    du -sh --apparent-size sparse-file

    默认 du 统计占用的数据块；--apparent-size 统计文件逻辑长度。稀疏文件、压缩文件系统和支持去重的存储上，两者可能差异很大。

    4. 标准磁盘排查流程¶

    第一步：确定哪个分区已满¶

    df -hT

df -i

    同时检查容量和 inode。

    第二步：定位挂载点中的大目录¶

    假设 /var 所在分区空间不足：

    sudo du -xhd1 /var 2>/dev/null | sort -h

    然后逐层进入最大的目录：

    sudo du -xhd1 /var/lib 2>/dev/null | sort -h
sudo du -xhd1 /var/log 2>/dev/null | sort -h

    第三步：定位大文件¶

    查找同一文件系统内超过 1 GiB 的普通文件：

    sudo find /var -xdev -type f -size +1G -printf '%s\t%p\n' 2>/dev/null |
sort -n |
tail -n 20

    GNU find 的 %s 输出字节数。只需人工查看时也可使用：

    sudo find /var -xdev -type f -size +1G -ls 2>/dev/null

    第四步：判断是否可以清理¶

    先确认文件来源和用途，不要直接删除未知的大文件。常见处理方式包括：

    • 使用应用自身的保留策略或清理命令。
    • 为日志配置 logrotate，或使用 journalctl --vacuum-time=7d 清理旧 journal。
    • 使用对应包管理器清理缓存。
    • 清理容器资源前先用 docker system df 或 podman system df 确认占用。
    • 数据库、消息队列和容器存储目录应通过对应服务管理，不能直接删除内部文件。

    5. df 与 du 不一致¶

    原因一：已删除文件仍被进程占用¶

    sudo lsof +L1

    COMMAND  PID  USER   FD   TYPE DEVICE SIZE/OFF NLINK    NODE NAME
java    1842 alice   10w  REG  252,0 5368709120     0 1329200 /home/alice/app/logs/app.log (deleted)

    NLINK 列为 0 且名称带 (deleted)：文件已从目录中删除，但进程仍持有打开的文件描述符，约 5 GB 空间（SIZE/OFF）不会释放。优先平滑重启或让服务重新打开文件，不要随意终止生产进程。

    若未安装 lsof，可检查 /proc：

    sudo find /proc/[0-9]*/fd -lname '* (deleted)' -ls 2>/dev/null

    原因二：权限不足¶

    普通用户无法遍历某些目录时，du 会漏算。需要完整结果时使用 sudo，并保留错误输出进行判断。

    原因三：挂载覆盖了原目录¶

    目录中原有文件可能被后来的挂载点遮挡，df 仍计算其占用，但当前路径无法直接看到。处理挂载前先确认业务影响，不要在生产环境随意卸载。

    原因四：预留空间和文件系统元数据¶

    某些文件系统会为管理员预留空间，并消耗空间保存日志、索引和其他元数据，因此 df 与文件总和不会完全相等。

    原因五：稀疏文件、快照、压缩或去重¶

    逻辑文件大小、实际数据块占用和底层存储占用可能是三个不同概念，应结合文件系统或存储平台工具分析。

    6. inode 耗尽排查¶

    先确认 inode 使用率：

    df -i

    Filesystem      Inodes IUsed IFree IUse% Mounted on
/dev/sda2      655360 655100   260  100% /

    IUse% 达到 100% 而 df -h 显示空间充足，即可确认是 inode 耗尽。粗略统计一级目录的目录项数量：

    sudo du --inodes -x -d1 /var 2>/dev/null | sort -n

    1200    /var/log
45000   /var/cache
580000  /var/spool
630000  /var

    示例中 /var/spool 占了绝大多数 inode，是海量小文件的来源，应优先进入排查。--inodes 是 GNU du 选项。

    常见来源包括邮件队列、缓存、会话文件、构建产物和未轮转日志。应先修复产生海量文件的程序或保留策略，再进行清理。

    7. 持续观察空间¶

    watch -n 5 'df -h /var'

    观察目录增长：

    watch -n 10 'du -sh /var/log 2>/dev/null'

    watch 会反复执行命令。对大目录运行 du 会产生持续 I/O，不应设置过短间隔。

    8. 常见误区¶

    du -sh * 为什么漏掉内容？¶

    Shell 的 * 默认不匹配隐藏项。可以直接统计当前目录总量：

    du -sh .

    为什么删除文件后空间没有立即恢复？¶

    先运行 lsof +L1，确认是否仍有进程打开该文件。

    为什么 du 显示的总量比 df 小？¶

    重点检查已删除但仍打开的文件、权限、被挂载覆盖的目录、快照和文件系统预留空间。

    可以直接删除 /var/log 下的大文件吗？¶

    不建议。先确定日志归属，优先使用服务重载、日志轮转或 journal 清理机制。直接删除当前日志可能无法释放空间，也可能影响审计与故障调查。

    9. 命令速查¶

    需求 命令
    查看全部文件系统容量 df -hT
    查看路径所在分区 df -h /path
    查看 inode df -i
    查看目录总量 du -sh /path
    查看一级目录占用 du -xhd1 /path \| sort -h
    查看最大的 20 个条目 du -ah /path \| sort -h \| tail -n 20
    查找超过 1 GiB 的文件 find /path -xdev -type f -size +1G -ls
    查找已删除但仍打开的文件 sudo lsof +L1

    推荐顺序：df -hT → df -i → du -xhd1 → find → 检查服务保留策略 → 安全清理。
