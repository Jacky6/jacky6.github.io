    Linux 网络诊断常用命令¶

    网络故障应按层次排查：接口与地址 → 路由 → DNS → 端口 → TLS/HTTP → 应用日志。不要只依赖 ping，许多主机会禁用 ICMP，但业务端口仍可能正常。

    1. ip：接口、地址与路由¶

    查看接口和地址¶

    ip -brief address

    lo               UNKNOWN        127.0.0.1/8 ::1/128
eth0             UP             192.168.1.23/24 fe80::5054:ff:fe9f:1a2b/64
docker0          DOWN           172.17.0.1/16

    每列依次是：接口名、链路状态、IPv4/IPv6 地址。UP 表示接口已启用；192.168.1.23/24 中的 /24 是前缀长度，对应子网掩码 255.255.255.0。

    ip -s link show eth0

    2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 52:54:00:9f:1a:2b brd ff:ff:ff:ff:ff:ff
    RX:  bytes packets errors dropped overrun mcast
        1846723   21034      0       0       0       12
    TX:  bytes packets errors dropped overrun carrier collsns
        1123841   16021      0       0       0       0       0     0

    RX/TX 分别是接收和发送方向。errors 非零通常表示硬件或驱动问题；dropped 非零可能是缓冲不足、流量过载或策略丢包，需要结合其他指标判断。

    启用或禁用接口会中断连接，远程机器上谨慎执行：

    sudo ip link set dev eth0 up
sudo ip link set dev eth0 down

    查看路由¶

    ip route

    default via 192.168.1.1 dev eth0 proto dhcp metric 100
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.23 metric 100

    第一行是默认路由：没有更精确匹配的流量都发往网关 192.168.1.1。第二行表示本机直连子网，src 指定该子网内通信的源地址。

    ip route get 1.1.1.1

    1.1.1.1 via 192.168.1.1 dev eth0 src 192.168.1.23 uid 1000
cache

    ip route get 可显示到目标地址实际选择的网关、出口接口和源地址。排查“为什么连不上”时，先看这一步选路是否符合预期。

    查看邻居表¶

    ip neigh

    192.168.1.1 dev eth0 lladdr 52:54:00:12:34:56 REACHABLE
192.168.1.50 dev eth0 lladdr 52:54:00:ab:cd:ef STALE

    lladdr 是对方的链路层（MAC）地址。REACHABLE 表示最近确认可达；STALE 表示条目过期但仍在使用；出现 FAILED 说明 ARP/NDP 解析失败，通常是对方不在线、VLAN 划错或防火墙拦截。

    ifconfig、route 和 netstat 已被 iproute2 中的 ip、ss 等工具取代，新脚本优先使用新命令。

    2. ss：Socket 与端口¶

    ss -lnt

    State   Recv-Q  Send-Q   Local Address:Port    Peer Address:Port   Process
LISTEN  0       128      0.0.0.0:22            0.0.0.0:*
LISTEN  0       511      127.0.0.1:6379        0.0.0.0:*
LISTEN  0       511      0.0.0.0:8080          0.0.0.0:*
LISTEN  0       128      [::]:22               [::]:*
    • State 为 LISTEN 表示正在监听。
    • Recv-Q 对监听 Socket 表示当前等待 accept 的连接数；Send-Q 表示监听队列长度上限。若 Recv-Q 长期接近 Send-Q，说明应用接受连接的速度跟不上。
    • 127.0.0.1:6379 只能本机访问（如 Redis 默认绑定）；0.0.0.0:8080 对所有 IPv4 地址开放。

    加 -p（需要相应权限）可看到进程：

    sudo ss -lntp

    LISTEN 0 511 0.0.0.0:8080 0.0.0.0:* users:(("java",pid=1842,fd=9))

    users: 中是进程名、PID 和打开该 Socket 的文件描述符编号。

    选项含义：

    选项 含义
    -l 仅监听 Socket
    -n 不解析服务名和主机名
    -t TCP
    -u UDP
    -p 显示进程，需要相应权限
    -a 全部 Socket

    查看指定端口：

    sudo ss -lntp 'sport = :8080'
ss -nt 'dport = :443'

    判断服务是否监听时，还要关注绑定地址：

    • 127.0.0.1:8080：仅本机 IPv4 可访问。
    • 0.0.0.0:8080：监听所有 IPv4 地址。
    • [::]:8080：监听 IPv6 任意地址；是否同时接受 IPv4 取决于系统配置。

    3. ping：连通性和延迟¶

    ping -c 4 1.1.1.1

    PING 1.1.1.1 (1.1.1.1) 56(84) bytes of data.
64 bytes from 1.1.1.1: icmp_seq=1 ttl=57 time=8.42 ms
64 bytes from 1.1.1.1: icmp_seq=2 ttl=57 time=8.51 ms
64 bytes from 1.1.1.1: icmp_seq=3 ttl=57 time=9.03 ms
64 bytes from 1.1.1.1: icmp_seq=4 ttl=57 time=8.47 ms

--- 1.1.1.1 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3005ms
rtt min/avg/max/mdev = 8.42/8.61/9.03/0.24 ms
    • icmp_seq：序号，不连续说明中间有丢包。
    • ttl：每经过一个路由器减 1，可粗略估计跳数。
    • time：往返延迟。mdev 反映抖动，对实时应用很重要。
    • 统计行中 0% packet loss 是关键结论；丢包率明显非零时，延迟数字本身已不可信。

    比较 IP 与域名：

    • IP 能通、域名不通：重点检查 DNS。
    • 两者都不通：继续检查接口、路由、防火墙和上游网络。
    • ping 不通但业务正常：可能仅是 ICMP 被过滤。

    不要用洪泛参数测试非自有网络。

    4. DNS 查询¶

    getent：按系统实际解析路径查询¶

    getent hosts example.com

    93.184.216.34 example.com

    getent 会遵循 /etc/nsswitch.conf，可覆盖 /etc/hosts、DNS、mDNS 等系统配置，适合判断应用常见的系统解析结果。如果 getent 返回的地址与 dig 不同，优先怀疑 /etc/hosts 或本地缓存。

    dig：详细查询 DNS¶

    dig example.com

    ;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 12345
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; QUESTION SECTION:
;example.com.           IN  A

;; ANSWER SECTION:
example.com.        3600    IN  A   93.184.216.34

;; Query time: 12 msec
;; SERVER: 127.0.0.53#53(127.0.0.53) (UDP)
;; WHEN: Fri Oct 10 10:00:00 CST 2026

    重点看：

    • status: NOERROR：解析成功；NXDOMAIN 表示域名不存在；SERVFAIL 表示上游或 DNSSEC 问题。
    • ANSWER SECTION：3600 是 TTL（缓存秒数），A 是记录类型，最后是地址。
    • SERVER：实际使用的 DNS 服务器，127.0.0.53 通常是 systemd-resolved 的本地 stub。
    dig example.com A +short

    93.184.216.34

    +short 只输出答案，适合脚本使用。

    查看 DNS 配置：

    cat /etc/resolv.conf

    nameserver 127.0.0.53
options edns0 trust-ad
search example.internal

    使用 systemd-resolved 的系统中，/etc/resolv.conf 可能只指向本地 stub，完整上游信息应查看 resolvectl status。

    5. curl：测试 HTTP/HTTPS¶

    基本请求¶

    curl https://example.com/
curl -I https://example.com/
curl -i https://example.com/
    • -I：只请求响应头，实际发送 HEAD。
    • -i：在响应正文前显示响应头。

    失败处理和调试¶

    curl -fSsv https://example.com/ -o /dev/null

    * Host example.com:443 was resolved.
* IPv6: 2606:2800:220:1:248:1893:25c8:1946
* IPv4: 93.184.216.34
*   Trying 93.184.216.34:443...
* Connected to example.com (93.184.216.34) port 443
* TLS 1.3 handshake using TLS_AES_256_GCM_SHA384
* Server certificate:
*  subject: CN=example.com
*  start date: Jan 30 00:00:00 2026
*  expire date: Mar  2 23:59:59 2026
*  issuer: C=US; O=DigiCert Inc; CN=DigiCert TLS RSA SHA256 2024 CA-1
* SSL certificate verify ok.
> GET / HTTP/2
> Host: example.com
> User-Agent: curl/8.5.0
>
< HTTP/2 200
< content-type: text/html; charset=UTF-8
< content-length: 1256
<

    以 * 开头的行是连接过程：DNS 解析、TCP 连接、TLS 握手和证书校验。> 是发出的请求头，< 是收到的响应头。排障时按顺序检查：解析到的地址是否正确、连接是否建立、证书是否校验通过、状态码是多少。

    • -f：HTTP 4xx/5xx 返回失败退出码。
    • -S：静默模式下仍显示错误。
    • -s：关闭进度条。
    • -v：显示连接、TLS 和请求头细节。

    -v 可能输出认证头、Cookie 等敏感信息，分享日志前必须脱敏。

    超时和重试¶

    curl --connect-timeout 3 --max-time 10 \
  --retry 2 --retry-all-errors \
  https://example.com/health

    指定域名解析¶

    curl --resolve example.com:443:192.0.2.10 https://example.com/

    这会绕过常规 DNS，同时保留 URL 中的 Host 和 TLS SNI，适合测试指定后端。

    输出耗时¶

    curl -sS -o /dev/null \
  -w 'code=%{http_code} dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} total=%{time_total}\n' \
  https://example.com/

    code=200 dns=0.012 connect=0.035 tls=0.089 total=0.156

    各阶段单位是秒：dns 是解析耗时，connect 是 TCP 建立完成，tls 是 TLS 握手完成，total 是整个请求。若 dns 占比很高，考虑本地缓存或检查 DNS 服务；connect 高说明网络距离或链路质量差。

    不要用 -k 忽略生产环境证书校验问题；应检查证书链、主机名、时间和信任库。

    6. 端口连通性¶

    使用 netcat：

    nc -vz -w 3 example.com 443

    Connection to example.com 443 port [tcp/https] succeeded!

    输出 succeeded 表示 TCP 三次握手成功，端口开放且网络可达。若超时，通常是被防火墙静默丢弃；若收到 refused，说明目标可达但该端口没有服务监听——这两种失败原因不同。

    • -z：只扫描连接，不传输数据。
    • -v：详细输出。
    • -w 3：3 秒超时。

    nc 有多个实现（GNU netcat、OpenBSD netcat、Nmap ncat），-w 等选项语义略有差异，以本机 man nc 为准。

    Bash 在支持 /dev/tcp 时也可测试：

    timeout 3 bash -c '</dev/tcp/example.com/443' && echo open

    open

    退出码为 0 且输出 open 表示连接成功；超时或被拒绝时 timeout 返回非零。

    检查 TLS：

    openssl s_client -connect example.com:443 -servername example.com </dev/null

    CONNECTED(00000003)
---
Certificate chain
 0 s:CN=example.com
   i:C=US; O=DigiCert Inc; CN=DigiCert TLS RSA SHA256 2024 CA-1
 1 s:C=US; O=DigiCert Inc; CN=DigiCert TLS RSA SHA256 2024 CA-1
   i:C=US; O=DigiCert Inc; CN=DigiCert Global Root CA
---
Verify return code: 0 (ok)

    Certificate chain 列出服务器证书及中间证书；Verify return code: 0 (ok) 表示校验通过。非零返回码通常对应证书过期、域名不匹配或缺少中间证书。

    7. 路径追踪¶

    tracepath example.com

     1?: [LOCALHOST]                      pmtu 1500
 1:  192.168.1.1                          0.311ms
 2:  10.10.0.1                            1.204ms
 3:  no reply
 4:  93.184.216.34                        8.912ms reached
     Resume: pmtu 1500 hops 4 back 3

    每行是一跳路由器。no reply 表示该跳不响应探测报文，只要后续跳和最终 reached 正常就不影响连通；pmtu 1500 是发现的路径 MTU。

    • tracepath：通常不需要管理员权限，并可发现路径 MTU。
    • traceroute：逐跳显示路径。
    • mtr：持续结合延迟和丢包统计。

    某一中间跳不响应不代表业务故障，路由器可能限制探测报文。应关注后续跳和最终目标，并从客户端、服务端两个方向验证。

    8. 下载和传输¶

    curl 下载¶

    curl -fLO https://example.com/releases/app.tar.gz

      % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
100 12.3M  100 12.3M      0      0   8.2M      0  0:00:01  0:00:01 --:--:--  9.1M

    进度条显示总大小、已下载、百分比和速度。100% 且退出码为 0 表示完整下载；-f 会在 404 等错误时不保存错误页面为文件。

    • -L：跟随重定向。
    • -O：使用远端文件名。
    • -o：指定本地文件名。
    • -C -：尝试断点续传。

    下载后应验证发布方提供的校验和或签名。

    scp 与 rsync¶

    scp file.txt user@host:/tmp/
rsync -av --progress source/ user@host:/srv/target/

    rsync 中源目录结尾的 / 很重要：

    • source/：复制目录中的内容。
    • source：在目标下创建 source 目录。

    涉及删除同步时先预演：

    rsync -av --delete --dry-run source/ target/

    sending incremental file list
deleting old-report.txt
./
report.txt

    --dry-run 只显示将要发生的操作：deleting 行列出会被删除的文件。确认列表安全后再去掉 --dry-run 实际执行。

    9. 抓包基础¶

    sudo tcpdump -ni any port 443

    tcpdump: data link type PKTAP
listening on any, link-type PKTAP (Linux "any" v1), snapshot length 262144 bytes
10:00:01.123456 IP 192.168.1.23.52344 > 93.184.216.34.443: Flags [S], seq 1234567890, win 64240, options [mss 1460,...]
10:00:01.131234 IP 93.184.216.34.443 > 192.168.1.23.52344: Flags [S.], seq 987654321, ack 1234567891, win 62640, ...
10:00:01.131401 IP 192.168.1.23.52344 > 93.184.216.34.443: Flags [.], ack 1, win 64240, length 0

    每行一个报文：时间戳、方向（> 前后分别是源和目标）、TCP 标志和序号。[S]/[S.]/[.] 依次是握手 SYN、SYN-ACK、ACK，三行连续即一次成功的连接建立。只看到 [S] 没有回应，说明 SYN 被丢弃或拦截。

    • -n：不做名称解析，避免额外 DNS 流量。
    • -i：指定接口。
    • -w：写入 pcap 文件供 Wireshark 分析。

    抓包可能包含凭据、Cookie、业务数据和个人信息，应限定接口、主机、端口和时长，妥善保存并及时清理。

    10. 分层排查流程¶

    第一步：本机接口¶

    ip -brief address
ip -s link

    第二步：路由¶

    ip route
ip route get <目标IP>

    第三步：DNS¶

    getent hosts <域名>
dig <域名>

    第四步：监听与连接¶

    服务端：

    sudo ss -lntup

    客户端：

    nc -vz -w 3 <主机> <端口>

    第五步：应用协议¶

    curl -fSsv --connect-timeout 3 https://<域名>/health

    第六步：防火墙与日志¶

    根据发行版检查 nftables、firewalld 或 ufw，并同时核对云安全组、负载均衡和容器网络策略。

    11. 命令速查¶

    需求 命令
    查看接口地址 ip -brief address
    查看路由 ip route
    查看目标出站路径 ip route get 1.1.1.1
    查看监听端口 sudo ss -lntup
    测试 ICMP ping -c 4 host
    按系统配置解析域名 getent hosts domain
    查询 DNS dig domain +short
    测试 TCP 端口 nc -vz -w 3 host port
    调试 HTTPS curl -fSsv URL -o /dev/null
    路径追踪 tracepath host
    抓包 sudo tcpdump -ni any port 443

    网络诊断要明确测试方向、目标地址、端口、协议和时间点，并保留客户端与服务端的证据。
