    Shell 管道与重定向教程¶

    Shell 不仅用于执行单条命令，还能把多个小工具通过标准流组合起来。掌握引号、变量、管道、重定向和退出状态，是安全编写命令与脚本的基础。

    1. 标准输入、输出与错误¶

    每个进程默认有三个标准文件描述符：

    编号 名称 默认位置
    0 标准输入 stdin 键盘或上游管道
    1 标准输出 stdout 终端
    2 标准错误 stderr 终端

    程序通常把正常结果写到 stdout，把诊断信息写到 stderr。两者分离后，可以独立保存或传递。

    2. 输出重定向¶

    覆盖写入¶

    command > output.txt

    文件不存在时创建，存在时会先清空。重要文件应避免直接覆盖。

    追加写入¶

    command >> output.txt

    单独保存错误¶

    command > output.txt 2> error.log

    合并标准输出与错误¶

    command > all.log 2>&1

    顺序很重要：

    command > all.log 2>&1  # stderr 指向已经重定向后的 stdout
command 2>&1 > all.log  # stderr 仍指向原终端

    Bash 简写：

    command &> all.log
command &>> all.log

    &> 不是 POSIX sh 语法，编写可移植脚本时使用 > file 2>&1。

    丢弃输出¶

    command > /dev/null
command > /dev/null 2>&1

    排障期间不要过早丢弃 stderr，否则会隐藏关键错误。

    3. 输入重定向与 Here Document¶

    从文件读取标准输入¶

    command < input.txt

    例如：

    wc -l < input.txt

    此时输出只有数字，不包含文件名。

    Here Document¶

    cat <<EOF
hello
user=$USER
EOF

    hello
user=alice

    默认会展开变量、命令替换和部分转义，$USER 被替换成了实际用户名。若希望原样保留内容，引用结束标记：

    cat <<'EOF'
$USER will not be expanded
$(date) will not run
EOF

    $USER will not be expanded
$(date) will not run

    引号让 Here Document 变成纯文本，适合写配置模板和脚本内容。

    Here String¶

    Bash 支持：

    grep pattern <<< "$text"

    简单场景也可使用可移植性更好的：

    printf '%s\n' "$text" | grep pattern

    4. 管道¶

    管道 | 将左侧命令的 stdout 连接到右侧命令的 stdin：

    journalctl -u nginx | grep -i error | less

    stderr 默认不会进入管道。需要合并时：

    command 2>&1 | less

    Bash 也支持：

    command |& less

    常见组合¶

    ps -eo pid,%cpu,%mem,cmd --sort=-%cpu | head
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -nr
find . -type f -name '*.log' -print0 | xargs -0 grep -n -- 'ERROR'

    不要把结构化数据当普通文本盲目按列切分。JSON 优先使用 jq，YAML 可使用 yq，CSV 应使用支持引号和转义的工具。

    5. 引号与转义¶

    单引号¶

    单引号内几乎所有字符都按字面量处理：

    printf '%s\n' '$HOME $(date) *'

    双引号¶

    双引号会展开变量和命令替换，但防止空白分词和文件名展开：

    printf '%s\n' "$HOME"
printf '%s\n' "$(date -Is)"

    不加引号¶

    printf '%s\n' $value

    未引用变量会发生字段分割和通配符展开，脚本中通常是不安全的。默认规则是：

    command "$value"

    转义¶

    printf '%s\n' hello\ world

    反斜杠可让下一个字符失去特殊含义。

    6. 变量与环境变量¶

    定义 Shell 变量时，等号两侧不能有空格：

    name='alice'
printf 'hello %s\n' "$name"

    导出为子进程可见的环境变量：

    export APP_ENV=production

    仅对一条命令设置环境变量：

    APP_ENV=test command

    查看：

    printenv APP_ENV
env

    删除变量：

    unset APP_ENV

    推荐使用花括号消除边界歧义：

    printf '%s\n' "${name}_backup"

    设置默认值：

    printf '%s\n' "${PORT:-8080}"
    • ${var:-default}：变量未设置或为空时使用默认值。
    • ${var:=default}：变量未设置或为空时赋默认值。
    • ${var:?message}：变量未设置或为空时输出错误并退出当前展开。

    7. 命令替换与算术¶

    命令替换¶

    now=$(date -Is)
echo "$now"

    2026-10-12T10:30:01+08:00

    $(...) 先执行内部命令，再把输出赋给变量。优先使用 $(...)，不要使用难以嵌套的反引号。

    命令替换会移除末尾换行；输出中间的换行仍会保留。

    算术展开¶

    count=$((count + 1))
bytes=$((1024 * 1024))

    Bash 算术主要处理整数，不适合直接进行浮点运算。

    8. 通配符与花括号展开¶

    文件名通配符¶

    模式 含义
    * 任意长度字符串，不默认匹配开头的 .
    ? 任意单个字符
    [abc] a、b 或 c 中一个
    [0-9] 范围内单个字符 
    printf '%s\n' ./*.log
printf '%s\n' image-?.png

    模式不匹配时，Bash 默认可能保留模式原文。批量修改或删除前必须检查展开结果。

    花括号展开¶

    mkdir -p project/{src,test,docs}
printf '%s\n' file-{1..5}.txt

    花括号展开不检查文件是否存在，只负责生成字符串。

    9. 组合命令与退出状态¶

    每条命令结束后都会返回退出状态，0 通常表示成功，非 0 表示失败：

    true
echo "$?"

    0

    false
echo "$?"

    1

    $? 保存上一条命令的退出状态，脚本中据此分支处理。

    成功后继续¶

    mkdir -p build && cd build

    只有左侧成功才执行右侧。若 mkdir 失败（如权限不足），cd 不会执行，避免在错误目录中继续操作。

    失败后执行¶

    command || printf '%s\n' 'command failed' >&2

    无条件顺序执行¶

    command1; command2

    命令分组¶

    当前 Shell 中执行：

    { command1; command2; } > output.log

    子 Shell 中执行：

    (command1; command2) > output.log

    圆括号内的目录切换和变量修改不会影响外层 Shell。

    10. 管道退出状态与 pipefail¶

    默认情况下，管道的退出状态通常是最后一条命令的状态：

    false | true
echo "$?"

    0

    左侧 false 失败被忽略，只看右侧 true 的成功——这在排障时会掩盖前半段失败。

    Bash 脚本可启用：

    set -o pipefail
false | true
echo "$?"

    1

    启用后，只要管道中有命令失败，整个管道就不会因为最后一条命令成功而被误判为成功。

    常见脚本开头：

    set -Eeuo pipefail

    但这些选项会改变错误处理语义：

    • -e：部分未处理失败会退出。
    • -u：读取未设置变量时报错。
    • -o pipefail：管道传播失败。
    • -E：函数和子 Shell 中继承 ERR trap。

    不要机械复制，应理解条件判断、预期失败和清理逻辑中的行为，并通过测试验证。

    11. tee 与管理员权限¶

    同时显示和保存：

    command | tee output.log

    追加：

    command | tee -a output.log

    写入受保护文件：

    printf '%s\n' 'setting=value' | sudo tee /etc/app.conf > /dev/null

    以下写法通常失败：

    sudo printf '%s\n' 'setting=value' > /etc/app.conf

    因为重定向由尚未提权的当前 Shell 完成。

    12. 后台执行¶

    command > command.log 2>&1 &
pid=$!
printf 'pid=%s\n' "$pid"
wait "$pid"

    长期任务：

    nohup command > command.log 2>&1 &

    nohup 不提供自动重启、健康检查、日志轮转或资源限制。长期服务应使用 systemd、容器编排平台或专用进程管理器。

    13. 实用示例¶

    日志筛选并保存¶

    journalctl -u myapp --since today |
grep -E 'ERROR|WARN' |
tee filtered.log |
less

    安全读取文本文件¶

    while IFS= read -r line; do
  printf 'line=%s\n' "$line"
done < input.txt

    IFS= 保留前导和尾随空白，-r 防止反斜杠转义。

    对任意文件名循环¶

    find . -type f -name '*.log' -print0 |
while IFS= read -r -d '' file; do
  printf '%s\n' "$file"
done

    这是 Bash 写法，使用 NUL 分隔可处理文件名中的空格和换行。

    原子化生成配置¶

    tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT

command > "$tmp" &&
chmod 640 "$tmp" &&
mv "$tmp" config.generated

    只有前序步骤成功才替换目标文件，trap 负责清理临时文件。

    14. 命令速查¶

    需求 写法
    覆盖保存 stdout command > file
    追加 stdout command >> file
    保存 stderr command 2> error.log
    合并 stdout/stderr command > all.log 2>&1
    从文件读取 stdin command < file
    建立管道 command1 \| command2
    命令成功后继续 command1 && command2
    命令失败后处理 command1 \|\| handler
    获取命令输出 value=$(command)
    后台执行 command > run.log 2>&1 &
    获取后台 PID pid=$!
    引用变量 "$variable"

    可靠 Shell 命令的核心：正确引用变量、区分 stdout/stderr、检查退出状态，并在执行破坏性操作前验证展开结果。
