    Linux 系统与服务常用命令¶

    本篇覆盖系统版本、时间、CPU、内存、块设备、挂载、systemd 服务和系统日志。不同发行版和容器环境的可用工具可能不同。

    1. 系统与内核信息¶

    cat /etc/os-release

    PRETTY_NAME="Ubuntu 24.04.1 LTS"
NAME="Ubuntu"
VERSION_ID="24.04"
ID=ubuntu

    VERSION_ID 是发行版版本，ID 是发行版标识，编写跨发行版脚本时常用它们做判断。

    uname -r

    6.8.0-45-generic

    当前运行内核版本。排查驱动、模块和内核相关问题时，先确认实际运行的内核，而不是已安装的最新内核包。

    修改主机名：

    sudo hostnamectl set-hostname app-01

    还应确认 /etc/hosts、DNS 和自动化平台中的主机名配置是否一致。

    2. 时间与运行时长¶

    uptime

     10:30:01 up 5 days,  1:07,  2 users,  load average: 0.52, 0.58, 0.59
    • up 5 days：已连续运行 5 天，重启后清零。
    • 2 users：当前登录会话数。
    • load average：过去 1、5、15 分钟的负载。
    timedatectl

                   Local time: Sun 2026-10-12 10:30:01 CST
           Universal time: Sun 2026-10-12 02:30:01 UTC
                 Time zone: Asia/Shanghai (CST, +0800)
System clock synchronized: yes
              NTP service: active

    System clock synchronized: yes 和 NTP service: active 表示时间同步正常；若为 no，证书校验、集群和日志时间线都可能出问题。

    理解负载平均值¶

    nproc
cat /proc/loadavg

    8
0.52 0.58 0.59 3/481 12345

    示例机器有 8 个逻辑 CPU，负载约 0.6，远低于 8，说明 CPU 空闲充足。负载平均值通常表示过去 1、5、15 分钟内处于可运行状态或不可中断睡眠状态的任务平均数。应结合 CPU 数量、CPU 使用率和 I/O 状态判断，负载高不一定等于 CPU 已满。

    3. CPU 信息¶

    lscpu
nproc
cat /proc/cpuinfo

    快速观察 CPU 使用：

    top
vmstat 1

    vmstat 1 第一行常是自开机以来的平均值，后续行才是采样周期数据。

    常见 CPU 字段：

    • us：用户态时间。
    • sy：内核态时间。
    • id：空闲时间。
    • wa：I/O 等待时间。
    • st：虚拟机被宿主机占用的时间。

    4. 内存与 Swap¶

    free -h

                   total        used        free      shared  buff/cache   available
Mem:           15Gi        6.2Gi       1.1Gi       210Mi       8.1Gi       8.6Gi
Swap:         2.0Gi          0B       2.0Gi
    • total：总内存。
    • used：已用内存，计算方式因版本略有差异。
    • buff/cache：内核缓冲与页缓存，需要时可立即释放。
    • available：在不发生大量交换的情况下可供新程序使用的估算内存。

    判断内存余量时优先关注 available：示例中 free 只有 1.1 GiB，但 available 有 8.6 GiB，说明内存并不紧张——大部分“占用”只是可回收的缓存。Linux 会主动使用空闲内存作为缓存。

    持续采样：

    vmstat 1 3

    procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 1  0      0 110432 524288 8388608    0    0    12    35  120  300  3  1 95  0  0
 0  0      0 109800 524288 8388608    0    0     0    40  118  290  2  1 97  0  0
    • si/so：每秒从 Swap 换入/换出，持续非零说明内存压力。
    • r：等待 CPU 的任务数；b：不可中断阻塞的任务数，持续偏高通常是 I/O 瓶颈。
    • us/sy/id/wa：用户态、内核态、空闲、I/O 等待的 CPU 占比。

    第一行常是自开机以来的平均值，后续行才是采样周期数据。

    5. 块设备与文件系统¶

    lsblk -f

    NAME   FSTYPE   FSVER LABEL UUID                                 MOUNTPOINTS
sda
├─sda1 vfat     FAT32       3A5B-1C2D                            /boot/efi
├─sda2 ext4     1.0         4f8a9b2c-...-e3d1                    /
└─sda3 swap     1           7c1d2e3f-...-a4b5                    [SWAP]
sr0    iso9660              2026-01-01-10-00-00-00

    树形结构展示设备和分区：sda 是磁盘，sda1/2/3 是分区，MOUNTPOINTS 显示各自挂载位置。FSTYPE 是文件系统类型。/etc/fstab 中优先使用 UUID 引用分区，避免设备名顺序变化导致启动失败。

    查看指定路径的挂载来源：

    findmnt -T /var/lib

    TARGET SOURCE FSTYPE OPTIONS
/      /dev/sda2 ext4 rw,relatime

    说明 /var/lib 位于根文件系统上，没有单独挂载。排查磁盘空间时，先用这一步确认目录属于哪个分区。

    查看文件系统容量和目录占用详见 df 与 du。

    6. 挂载与卸载¶

    临时挂载：

    sudo mount /dev/sdb1 /mnt/data
findmnt /mnt/data

    卸载：

    sudo umount /mnt/data

    提示目标忙时检查使用者：

    sudo fuser -vm /mnt/data
sudo lsof +D /mnt/data

    lsof +D 会递归扫描目录，大目录上可能很慢。

    永久挂载通常配置在 /etc/fstab。修改后先验证：

    sudo findmnt --verify
sudo mount -a

    远程服务器修改根文件系统或关键挂载配置前，应准备恢复方式。优先使用 UUID，避免设备名顺序变化。

    7. systemctl：管理 systemd 服务¶

    查看状态¶

    systemctl status nginx

    ● nginx.service - A high performance web server
     Loaded: loaded (/usr/lib/systemd/system/nginx.service; enabled; preset: enabled)
     Active: active (running) since Sun 2026-10-12 09:00:12 CST; 1h 30min ago
   Main PID: 1201 (nginx)
      Tasks: 3 (limit: 38147)
     Memory: 12.4M
        CPU: 1.230s
     CGroup: /system.slice/nginx.service
             ├─1201 "nginx: master process /usr/sbin/nginx"
             ├─1202 "nginx: worker process"
             └─1203 "nginx: worker process"
    • Loaded：unit 文件路径；enabled 表示开机自启。
    • Active: active (running)：当前正在运行，后面的时间是本次启动时刻。
    • Main PID：主进程，CGroup 列出其全部子进程。
    • Memory/CPU：该服务当前资源占用。

    常见异常状态：inactive (dead) 未运行、failed 启动失败、activating 正在启动。

    启动、停止和重启¶

    sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx
    • restart：停止后重新启动，可能中断服务。
    • reload：让支持该功能的服务重新读取配置，通常中断更小。

    修改配置后，先使用应用自带命令校验，例如：

    sudo nginx -t && sudo systemctl reload nginx

    开机启动¶

    sudo systemctl enable nginx
sudo systemctl disable nginx
sudo systemctl enable --now nginx

    enable 只配置开机启动，不一定立即启动；--now 会同时执行当前启动或停止操作。

    修改单元后重新加载¶

    sudo systemctl daemon-reload
sudo systemctl restart myapp

    daemon-reload 用于重新读取 unit 文件，不会自动重启服务。

    查看完整配置：

    systemctl cat nginx
systemctl show nginx
systemctl list-dependencies nginx

    8. journalctl：查看 systemd 日志¶

    journalctl -u nginx -n 5 --no-pager

    Oct 12 09:00:12 app-01 systemd[1]: Starting nginx.service - A high performance web server...
Oct 12 09:00:12 app-01 nginx[1201]: nginx: configuration file /etc/nginx/nginx.conf test is successful
Oct 12 09:00:12 app-01 systemd[1]: Started nginx.service - A high performance web server.
Oct 12 10:15:30 app-01 nginx[1202]: 192.168.1.50 - - "GET / HTTP/1.1" 200

    每行格式：时间、主机名、进程[PID]、消息。-u nginx 只看该服务，-n 5 只取最近 5 行，--no-pager 直接输出不进入分页器。

    按时间过滤：

    journalctl -u nginx --since '1 hour ago' --no-pager

    只输出最近一小时的日志，缩小排障范围。

    实时追踪：

    journalctl -u nginx -f

    类似 tail -f，持续输出新日志，Ctrl+C 退出。

    查看本次启动日志：

    journalctl -b

    -b 是本次启动，-b -1 是上一次启动，适合对比“重启前发生了什么”。

    磁盘占用与清理：

    journalctl --disk-usage

    Archived and active journals take up 804M in the file system.

    清理日志会影响历史排障和审计，应先确认保留要求，并优先在 journald.conf 中设置长期上限。

    9. dmesg：查看内核环形缓冲区¶

    dmesg -T | less
dmesg --level=err,warn
dmesg -w

    常见用途：

    dmesg -T | grep -iE 'error|fail|oom|nvme|ext4'

    -T 转换为可读时间，但在系统休眠或时钟调整后可能不完全准确；严谨分析优先使用带持久时间戳的 journal。

    普通用户是否可读取 dmesg 取决于系统安全配置。

    10. 关机与重启¶

    systemctl reboot
systemctl poweroff
shutdown -r +10 'maintenance reboot'
shutdown -c

    生产环境操作前应：

    1. 确认主机和环境。
    2. 通知相关人员并停止流量。
    3. 检查有状态服务是否已安全落盘。
    4. 确认远程控制台或恢复路径可用。

    11. 常用排查组合¶

    系统整体概况¶

    uptime
free -h
df -hT
systemctl --failed

    服务启动失败¶

    systemctl status myapp
journalctl -u myapp -b -n 200 --no-pager
systemctl cat myapp

    最近的严重系统日志¶

    journalctl -p err..alert --since '1 hour ago'

    OOM 排查¶

    journalctl -k -g 'oom|Out of memory|Killed process' --since today

    journalctl -g 依赖较新的 systemd；不支持时可通过 journalctl -k | grep -Ei ... 过滤。

    12. 命令速查¶

    需求 命令
    查看发行版 cat /etc/os-release
    查看内核 uname -r
    查看时间与时区 timedatectl
    查看负载 uptime
    查看 CPU lscpu
    查看内存 free -h
    查看磁盘设备 lsblk -f
    查看挂载 findmnt
    查看服务状态 systemctl status service
    查看服务日志 journalctl -u service -n 100
    查看失败服务 systemctl --failed
    查看本次启动日志 journalctl -b

    先收集状态和日志，再执行重启、清理或配置修改，避免破坏故障现场。
