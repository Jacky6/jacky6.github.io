    Linux 归档与压缩常用命令¶

    “归档”和“压缩”是两个概念：tar 将多个文件打包成一个归档，gzip、bzip2、xz、zstd 等负责压缩数据。.tar.gz 表示先归档，再使用 gzip 压缩。

    1. 常见格式¶

    扩展名 含义 常用工具
    .tar 未压缩 tar 归档 tar
    .tar.gz / .tgz gzip 压缩的 tar tar、gzip
    .tar.bz2 bzip2 压缩的 tar tar、bzip2
    .tar.xz xz 压缩的 tar tar、xz
    .tar.zst zstd 压缩的 tar tar、zstd
    .gz 单个数据流的 gzip 压缩 gzip
    .zip ZIP 归档和压缩 zip、unzip
    .7z 7-Zip 归档 7z

    选择建议：

    • Linux 文件归档：优先 tar.gz 或 tar.zst。
    • 跨平台分享：优先 ZIP。
    • 追求较高压缩率：可用 tar.xz，但速度通常较慢。
    • 追求速度和并行能力：可用 zstd。

    2. tar 基本语法¶

    常见操作字母：

    选项 作用
    -c 创建归档
    -x 解开归档
    -t 列出内容
    -f 指定归档文件，后面紧跟文件名
    -v 显示处理过程
    -z gzip
    -j bzip2
    -J xz

    创建未压缩归档¶

    tar -cf project.tar project/

    查看归档内容¶

    tar -tvf project.tar

    drwxr-xr-x alice/alice    0 2026-10-12 10:00 project/
-rw-r--r-- alice/alice 1024 2026-10-12 10:00 project/README.md
-rw-r--r-- alice/alice 2048 2026-10-12 09:58 project/src/main.py

    每行依次是：权限、所有者/组、大小（字节）、修改时间、归档内路径。解压前先看这一步，确认路径层级和文件归属是否符合预期。

    解包¶

    tar -xf project.tar
tar -xf project.tar -C /tmp/target

    -C 的目标目录必须事先存在：

    mkdir -p /tmp/target
tar -xf project.tar -C /tmp/target

    3. 创建压缩 tar 归档¶

    tar -czf project.tar.gz project/
tar -cjf project.tar.bz2 project/
tar -cJf project.tar.xz project/
tar --zstd -cf project.tar.zst project/

    现代 GNU tar 解压时通常可自动识别压缩格式：

    tar -xf project.tar.gz

    为增强对旧版本的兼容性，也可显式指定：

    tar -xzf project.tar.gz
tar -xJf project.tar.xz

    4. 控制归档内路径¶

    推荐先切换归档根目录，避免保存过长路径：

    tar -czf app-config.tar.gz -C /etc app/

    归档中路径为 app/...，而不是绝对路径。

    排除内容：

    tar -czf source.tar.gz \
  --exclude='.git' \
  --exclude='node_modules' \
  --exclude='*.log' \
  project/

    模式通常相对于归档中的路径匹配。复杂任务应先列出归档内容验证。

    从文件读取列表：

    printf '%s\n' file1.txt dir/file2.txt > files.list
tar -czf selected.tar.gz -T files.list

    5. 只解压部分内容¶

    先查看路径：

    tar -tf project.tar.gz

    解压指定文件或目录：

    tar -xf project.tar.gz project/README.md
tar -xf project.tar.gz project/config/

    去掉前导路径层级：

    mkdir extracted
tar -xf package.tar.gz -C extracted --strip-components=1

    执行前先查看归档，确认所有条目确实具有预期的共同目录层级。

    6. gzip、bzip2、xz 与 zstd¶

    这些工具默认压缩单个文件，并可能用压缩文件替换原文件。

    gzip¶

    gzip -k file.log
ls -lh file.log*

    -rw-r--r-- 1 alice alice 10M Oct 12 10:00 file.log
-rw-r--r-- 1 alice alice 2.1M Oct 12 10:00 file.log.gz

    -k 保留原文件（不加时原文件会被压缩文件替换）。示例中 10M 日志压缩到 2.1M，文本日志的压缩率通常很可观。

    gzip -dc file.log.gz | head -n 2

    2026-10-12 09:00:01 INFO server started
2026-10-12 09:00:05 INFO request handled

    -dc 解压到标准输出，不落盘即可查看内容。

    xz¶

    xz -k file.tar
unxz file.tar.xz
xz -dc file.xz | less

    zstd¶

    zstd file.tar
zstd -d file.tar.zst
zstd -dc file.zst | less
    • -k：保留输入文件，具体支持情况以工具版本为准。
    • -d：解压。
    • -c：输出到标准输出。

    并行压缩大文件时可使用 pigz（并行 gzip）或 zstd。压缩级别越高不一定越合适，应综合 CPU 时间、压缩率和恢复速度。

    7. zip 与 unzip¶

    查看内容：

    unzip -l project.zip

    Archive:  project.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
     1024  2026-10-12 10:00   README.md
     2048  2026-10-12 09:58   src/main.py
---------                     -------
     3072                     2 files

    Length 是解压后的原始大小，末行是合计。解压前先确认路径中没有 ../ 等可疑条目。

    解压：

    unzip project.zip -d target/

    Archive:  project.zip
  inflating: target/README.md
  inflating: target/src/main.py

    inflating 表示正常解压写入；若出现 caution: filename not matched 或覆盖提示，应停下来检查。

    覆盖行为：

    unzip -n project.zip -d target/  # 不覆盖
unzip -o project.zip -d target/  # 自动覆盖

    使用 -o 前应确认目标目录，避免覆盖重要文件。

    8. 校验文件完整性¶

    计算 SHA-256：

    sha256sum archive.tar.gz

    3a5f8c9d2e1b4a7c6d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c  archive.tar.gz

    第一列是文件内容的 SHA-256 摘要，任何一位内容变化都会让摘要完全不同。

    验证：

    sha256sum -c archive.tar.gz.sha256

    archive.tar.gz: OK

    OK 表示与校验文件中记录的摘要一致；显示 FAILED 时文件已损坏或不完整，不应使用。

    校验和能发现传输损坏，但如果校验文件与下载文件来自同一个不可信来源，不能证明发布者身份。发布包应优先验证项目提供的数字签名或可信渠道中的校验值。

    其他工具：

    md5sum file       # 仅适合非安全性完整性检查
sha512sum file

    MD5 已不适合安全用途。

    9. 安全解压¶

    不可信归档可能包含：

    • ../ 路径穿越。
    • 绝对路径。
    • 指向目标目录外的符号链接。
    • 特殊设备文件。
    • 解压后占用巨量空间的压缩炸弹。
    • 覆盖现有文件。

    推荐流程：

    # 1. 查看内容
tar -tvf untrusted.tar.gz | less

# 2. 创建独立目录
mkdir -m 700 inspect-dir

# 3. 在隔离目录解压
tar -xf untrusted.tar.gz -C inspect-dir

# 4. 检查结果
find inspect-dir -maxdepth 3 -ls

    不要以 root 身份直接将不可信归档解压到 /、/etc、应用目录或用户主目录。即便 tar 会对部分危险路径做防护，也不应省略人工检查和隔离。

    10. 保留权限与元数据¶

    tar 通常会保存权限、时间、符号链接等信息。是否完整保留所有者、ACL、扩展属性和 SELinux 上下文，取决于权限、文件系统和参数：

    sudo tar --acls --xattrs --selinux -cpf backup.tar /srv/data

    恢复前需要确认目标系统支持这些元数据，且归档来源可信。普通数据传输不应盲目恢复归档中的所有者或特殊权限位。

    tar 不是完整备份系统：一致性、增量、加密、校验、保留策略和恢复演练仍需专门设计。

    11. 常用组合¶

    按日期命名备份¶

    tar -czf "config-$(date +%Y%m%d-%H%M%S).tar.gz" config/

    通过 SSH 流式传输¶

    tar -cf - project/ | ssh user@host 'tar -xf - -C /srv/backup'

    这不会先生成本地归档文件。使用前要确认远端目录、权限、网络稳定性和可用空间。

    查看压缩日志但不落盘¶

    gzip -dc app.log.gz | less
xz -dc app.log.xz | grep ERROR

    也可按系统安装情况使用 zless、zgrep、xzless 和 xzgrep。

    12. 命令速查¶

    需求 命令
    创建 tar.gz tar -czf archive.tar.gz directory/
    查看 tar 内容 tar -tf archive.tar.gz
    解压 tar tar -xf archive.tar.gz -C target/
    创建 ZIP zip -r archive.zip directory/
    查看 ZIP 内容 unzip -l archive.zip
    解压 ZIP unzip archive.zip -d target/
    压缩单个文件并保留原件 gzip -k file
    计算 SHA-256 sha256sum file
    验证校验文件 sha256sum -c checksums.txt

    归档前确认包含内容，解压前查看路径，恢复前验证完整性，重要备份必须定期演练恢复。
