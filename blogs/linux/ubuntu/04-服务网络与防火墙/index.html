    04. Ubuntu 服务、网络与防火墙¶

    1. systemd 服务管理¶

    systemctl status nginx --no-pager
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx
sudo systemctl enable --now nginx
sudo systemctl disable nginx
systemctl is-enabled nginx
systemctl is-active nginx
systemctl --failed

    reload 让支持热加载的服务重读配置；restart 会停止并重新启动服务，可能造成短暂中断。

    查看单元定义和依赖：

    systemctl cat nginx
systemctl list-dependencies nginx
systemd-analyze critical-chain

    修改自定义覆盖配置：

    sudo systemctl edit nginx
sudo systemctl daemon-reload
sudo systemctl restart nginx

    不要直接修改 /lib/systemd/system/ 下由软件包管理的文件。

    2. journald 日志¶

    journalctl -u nginx
journalctl -u nginx -f
journalctl -u nginx --since "30 minutes ago"
journalctl -p err..alert --since today
journalctl -b                         # 本次启动
journalctl -b -1                      # 上次启动
sudo journalctl --disk-usage

    应用写入标准输出和标准错误后，systemd 可统一收集日志。长期保存策略可在 /etc/systemd/journald.conf 中配置。

    3. 网络信息与连通性¶

    ip -br address
ip route
ip neigh
ss -lntup
ping -c 4 1.1.1.1
curl -v https://example.com
tracepath example.com

    安装常用诊断工具：

    sudo apt install dnsutils iputils-ping traceroute mtr-tiny netcat-openbsd tcpdump

    测试 TCP 端口：

    nc -vz example.com 443
curl -v http://127.0.0.1:8080/health

    抓包需要管理员权限：

    sudo tcpdump -ni any port 8080

    抓包可能包含敏感数据，排障完成后及时停止并妥善处理文件。

    4. DNS 排查¶

    resolvectl status
resolvectl query example.com
dig example.com
dig @1.1.1.1 example.com
getent hosts example.com

    推荐排查顺序：

    1. ip route 确认默认路由。
    2. 用 IP 测试网络是否连通。
    3. 用 resolvectl query 检查系统解析。
    4. 用指定 DNS 的 dig 对比结果。
    5. 检查 VPN、代理、/etc/hosts 和云平台网络策略。

    不要长期手改 /etc/resolv.conf，它通常由 systemd-resolved 或网络管理器生成。

    5. UFW 防火墙¶

    安装并查看状态：

    sudo apt install ufw
sudo ufw status verbose

    远程服务器启用前先放行 SSH：

    sudo ufw allow OpenSSH
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable

    常用规则：

    sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from 10.0.0.0/8 to any port 5432 proto tcp
sudo ufw status numbered
sudo ufw delete 3

    数据库和调试端口通常只应监听 127.0.0.1 或内网地址，不要直接对公网开放。云服务器还需同时检查安全组或网络 ACL。

    6. 代理环境¶

    临时代理：

    export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export NO_PROXY=localhost,127.0.0.1,.internal.example.com

    排查时同时检查大小写变量：

    env | grep -i proxy

    服务进程不会自动继承交互式 Shell 的环境变量，应通过 systemd 的 Environment=、EnvironmentFile= 或应用配置显式设置。

    7. 定时任务¶

    查看传统 Cron：

    crontab -e
crontab -l
sudo systemctl status cron

    对需要日志、依赖和失败状态管理的任务，优先使用 systemd timer：

    systemctl list-timers --all

    无论使用哪种方式，都应使用绝对路径、设置明确的工作目录，并让任务失败时返回非零退出码。
