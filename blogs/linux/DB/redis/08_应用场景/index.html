    08_应用场景¶

    Redis 典型应用场景实战：缓存、分布式锁、消息队列、会话管理等

    1. 缓存设计¶

    1.1 缓存模式¶

    （1）Cache-Aside（旁路缓存）¶

    读：先读缓存 → 未命中读数据库 → 写入缓存
写：先写数据库 → 删除缓存

┌────────┐     ┌────────┐     ┌────────┐
│  应用  │────▶│  缓存  │────▶│  数据库 │
└────────┘     └────────┘     └────────┘

    def get_user(user_id):
    # 读缓存
    user = redis.get(f"user:{user_id}")
    if user:
        return json.loads(user)

    # 读数据库
    user = db.query("SELECT * FROM users WHERE id = ?", user_id)

    # 写缓存
    if user:
        redis.setex(f"user:{user_id}", 3600, json.dumps(user))

    return user

def update_user(user_id, data):
    # 写数据库
    db.execute("UPDATE users SET ? WHERE id = ?", data, user_id)

    # 删缓存
    redis.delete(f"user:{user_id}")

    （2）Read-Through（读穿透）¶

    应用只与缓存交互，缓存负责与数据库同步

┌────────┐     ┌────────────────────────┐
│  应用  │────▶│  缓存（含 DB 逻辑）      │
└────────┘     └────────────────────────┘

    注： Read-Through / Write-Through 需要缓存组件自带数据加载逻辑，Redis 原生不直接支持，通常通过 Redis Modules 或应用层封装实现。

    （3）Write-Through（写穿透）¶

    写操作先写缓存，缓存同步写数据库

┌────────┐     ┌────────────────────────┐
│  应用  │────▶│  缓存（含 DB 逻辑）      │
└────────┘     └────────────────────────┘

    1.2 缓存更新策略¶

    策略 说明 适用场景
    删除缓存 写 DB 后删除缓存 读多写少
    更新缓存 写 DB 后更新缓存 写多读少
    带过期时间 设置 TTL 自动过期 一般场景
    永不过期 手动更新缓存 配置数据

    1.3 缓存与数据库一致性¶

    为什么「先写 DB，再删缓存」？¶

    Cache-Aside 模式中，写操作推荐 先更新数据库，再删除缓存，而不是反过来。原因：

    ❌ 错误做法：先删缓存，再写 DB

T1: 线程 A 删除缓存
T2: 线程 B 读取缓存 → 未命中 → 读 DB（旧值）→ 写入缓存（旧值）
T3: 线程 A 更新 DB（新值）
结果：缓存中一直是旧值，直到过期

    ✅ 正确做法：先写 DB，再删缓存

T1: 线程 A 更新 DB（新值）
T2: 线程 A 删除缓存
T3: 线程 B 读取缓存 → 未命中 → 读 DB（新值）→ 写入缓存（新值）
结果：最终一致

    注意： 「先写 DB 再删缓存」仍有极小概率不一致（删缓存失败），但实际中比反过来的方案好得多。

    延迟双删¶

    进一步降低不一致窗口期的方案：

    def update_user(user_id, data):
    # 1. 先删缓存（可选，降低读取旧数据的概率）
    redis.delete(f"user:{user_id}")

    # 2. 写数据库
    db.execute("UPDATE users SET ? WHERE id = ?", data, user_id)

    # 3. 延迟后再删一次（清除 T1~T2 期间被写入的旧缓存）
    # 延迟时间 > 读请求的 DB 查询耗时
    threading.Thread(target=lambda: (
        time.sleep(0.5),
        redis.delete(f"user:{user_id}")
    )).start()

    注： 延迟双删是兜底方案，不是银弹。500ms 的延迟需要根据实际 DB 查询耗时调整。

    Canal 监听 Binlog 异步删缓存¶

    生产环境更优雅的方案：通过 Canal 监听 MySQL binlog，异步删除对应缓存。

    MySQL Binlog → Canal → MQ → 消费端删除 Redis 缓存

    优点： 解耦业务代码，缓存删除失败可重试，保证最终一致性。

    1.4 缓存三大问题¶

    （1）缓存穿透¶

    问题： 查询一个一定不存在的数据，缓存不命中，每次都打到 DB。

    场景： 恶意攻击者伪造不存在的 ID（如 id=-1）反复查询。

    解决方案：

    # 方案一：缓存空值（最常用）
def get_product(product_id: int):
    key = f"product:{product_id}"
    value = redis.get(key)
    if value is not None:
        return None if value == "NULL" else json.loads(value)

    # 查 DB
    product = db.query(product_id)
    if product is None:
        # 缓存空值，TTL 较短
        redis.setex(key, 60, "NULL")
        return None

    redis.setex(key, 3600, json.dumps(product))
    return product

    # 方案二：布隆过滤器
from pybloom_live import ScalableBloomFilter

bloom = ScalableBloomFilter(initial_capacity=100000, error_rate=0.001)

# 初始化：把所有合法 ID 加进去
for pid in all_valid_product_ids:
    bloom.add(str(pid))

def get_product_bloom(product_id: int):
    if str(product_id) not in bloom:
        return None  # 一定不存在，直接拦截
    # 可能存在 → 走正常缓存/DB 流程
    ...

    （2）缓存击穿¶

    问题： 一个热点 key 突然过期，瞬间大量请求同时打到 DB。

    场景： 秒杀商品、热门新闻的缓存过期瞬间。

    解决方案：

    # 方案一：互斥锁（SETNX）
import time

def get_hot_product(product_id: int):
    key = f"product:{product_id}"
    lock_key = f"lock:product:{product_id}"

    value = redis.get(key)
    if value:
        return json.loads(value)

    # 只有一个请求去查 DB
    if redis.set(lock_key, "1", nx=True, ex=10):
        try:
            # 双重检查（其他请求可能已经写入了）
            value = redis.get(key)
            if value:
                return json.loads(value)

            product = db.query(product_id)
            redis.setex(key, 3600, json.dumps(product))
            return product
        finally:
            redis.delete(lock_key)
    else:
        # 等待其他请求加载完成
        time.sleep(0.05)
        return get_hot_product(product_id)  # 递归重试

    # 方案二：逻辑过期（后台异步更新）
import threading

def get_with_logical_expire(product_id: int):
    key = f"product:{product_id}"
    data = redis.get(key)

    if data:
        wrapper = json.loads(data)
        # 数据仍然返回，但后台异步刷新
        if time.time() > wrapper["expire_at"]:
            threading.Thread(target=refresh_cache, args=(product_id,)).start()
        return wrapper["data"]

    # 首次加载，设置较长的逻辑过期时间
    product = db.query(product_id)
    wrapper = {
        "data": product,
        "expire_at": time.time() + 300  # 5 分钟后逻辑过期
    }
    redis.setex(key, 7200, json.dumps(wrapper))  # 物理 TTL 2 小时
    return product

def refresh_cache(product_id: int):
    """后台异步刷新缓存"""
    product = db.query(product_id)
    wrapper = {
        "data": product,
        "expire_at": time.time() + 300
    }
    redis.setex(f"product:{product_id}", 7200, json.dumps(wrapper))

    （3）缓存雪崩¶

    问题： 大量 key 同时过期，或者Redis 宕机，请求全部打到 DB。

    场景： 批量设置缓存时用了相同的 TTL，到时间一起过期。

    解决方案：

    import random

def set_cache_with_jitter(key: str, value: str, base_ttl: int = 3600):
    """TTL 加随机值，避免同时过期"""
    jitter = random.randint(0, 300)  # 0~5 分钟随机
    redis.setex(key, base_ttl + jitter, value)

# 批量设置时各自有不同的过期时间
for product in products:
    set_cache_with_jitter(
        f"product:{product['id']}",
        json.dumps(product),
        base_ttl=3600
    )
    方案 适用场景 说明
    TTL 加随机值 防止批量过期 简单有效，必做
    热点 key 永不过期 + 异步更新 核心热点数据 逻辑过期方案
    Redis 高可用（哨兵/集群） 防止 Redis 宕机 基础设施层面
    服务降级 & 熔断 Redis 宕机时的兜底 配合 Hystrix/Sentinel

    1.5 实战：商品缓存¶

    import redis
import json
from typing import Optional

class ProductCache:
    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client
        self.KEY_PREFIX = "product:"
        self.TTL = 3600  # 1 小时

    def get(self, product_id: int) -> Optional[dict]:
        """获取商品"""
        key = f"{self.KEY_PREFIX}{product_id}"
        data = self.redis.get(key)
        if data:
            return json.loads(data)
        return None

    def set(self, product_id: int, product: dict):
        """设置商品缓存"""
        key = f"{self.KEY_PREFIX}{product_id}"
        self.redis.setex(key, self.TTL, json.dumps(product))

    def delete(self, product_id: int):
        """删除商品缓存"""
        key = f"{self.KEY_PREFIX}{product_id}"
        self.redis.delete(key)

    def get_multi(self, product_ids: list) -> dict:
        """批量获取商品"""
        if not product_ids:
            return {}

        keys = [f"{self.KEY_PREFIX}{pid}" for pid in product_ids]
        values = self.redis.mget(keys)

        result = {}
        for pid, val in zip(product_ids, values):
            if val:
                result[pid] = json.loads(val)
        return result

    def set_multi(self, products: dict):
        """批量设置商品缓存"""
        pipe = self.redis.pipeline()
        for pid, product in products.items():
            key = f"{self.KEY_PREFIX}{pid}"
            pipe.setex(key, self.TTL, json.dumps(product))
        pipe.execute()

    2. 分布式锁¶

    2.1 基础实现¶

    import redis
import time
import uuid

class DistributedLock:
    def __init__(self, redis_client: redis.Redis, lock_name: str, timeout: int = 10):
        self.redis = redis_client
        self.lock_name = f"lock:{lock_name}"
        self.timeout = timeout
        self.lock_id = str(uuid.uuid4())

    def acquire(self) -> bool:
        """获取锁"""
        # SETNX + EXPIRE 原子操作
        return self.redis.set(
            self.lock_name,
            self.lock_id,
            nx=True,  # 不存在才设置
            ex=self.timeout  # 过期时间
        )

    def release(self) -> bool:
        """释放锁（Lua 脚本保证原子性）"""
        script = """
        if redis.call("get", KEYS[1]) == ARGV[1] then
            return redis.call("del", KEYS[1])
        else
            return 0
        end
        """
        return self.redis.eval(script, 1, self.lock_name, self.lock_id)

    def __enter__(self):
        if not self.acquire():
            raise Exception(f"Failed to acquire lock: {self.lock_name}")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.release()

# 使用示例
redis_client = redis.Redis()

# 方式 1：手动获取释放
lock = DistributedLock(redis_client, "order:1001")
if lock.acquire():
    try:
        # 临界区代码
        process_order()
    finally:
        lock.release()

# 方式 2：上下文管理器
with DistributedLock(redis_client, "order:1001"):
    process_order()

    2.2 Redisson 实现（Java）¶

    import org.redisson.Redisson;
import org.redisson.api.RLock;
import org.redisson.api.RedissonClient;
import org.redisson.config.Config;

import java.util.concurrent.TimeUnit;

public class RedissonLockExample {

    public static void main(String[] args) {
        // 配置
        Config config = new Config();
        config.useSingleServer()
              .setAddress("redis://127.0.0.1:6379")
              .setPassword("password");

        RedissonClient redisson = Redisson.create(config);

        // 获取锁
        RLock lock = redisson.getLock("order:1001");

        // 尝试获取锁
        boolean isLocked = false;
        try {
            isLocked = lock.tryLock(5, 30, TimeUnit.SECONDS);
            if (isLocked) {
                // 临界区代码
                processOrder();
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            if (isLocked && lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }

        redisson.shutdown();
    }
}

    2.3 红锁（RedLock）¶

    ⚠️ 生产环境慎用： RedLock 强依赖各 Redis 节点时钟基本同步，在极端时钟漂移或网络分区场景下可能不安全。 Martin Kleppmann 和 Redis 官方对此有过著名争论。生产环境建议优先使用 etcd / Consul / ZooKeeper 实现分布式锁，或在单机 Redis 场景使用单节点锁即可。

    from redis import Redis
from redis.lock import Lock
import time

class RedLock:
    def __init__(self, redis_instances: list, resource: str, ttl: int = 10000):
        self.instances = redis_instances
        self.resource = f"lock:{resource}"
        self.ttl = ttl
        self.lock_id = str(uuid.uuid4())

    def acquire(self) -> bool:
        """获取红锁"""
        start_time = int(time.time() * 1000)
        acquired = 0

        for instance in self.instances:
            if instance.set(self.resource, self.lock_id, nx=True, ex=self.ttl // 1000 + 1):
                acquired += 1

        elapsed = int(time.time() * 1000) - start_time
        validity = self.ttl - elapsed

        # 获取成功条件：
        # 1. 超过半数实例获取成功
        # 2. 锁有效期大于 0
        if acquired >= (len(self.instances) // 2 + 1) and validity > 0:
            return True

        # 获取失败，释放所有锁
        self.release()
        return False

    def release(self):
        """释放红锁"""
        script = """
        if redis.call("get", KEYS[1]) == ARGV[1] then
            return redis.call("del", KEYS[1])
        else
            return 0
        end
        """
        for instance in self.instances:
            try:
                instance.eval(script, 1, self.resource, self.lock_id)
            except:
                pass

# 使用示例（5 个 Redis 实例）
instances = [
    Redis(host='redis1', port=6379),
    Redis(host='redis2', port=6379),
    Redis(host='redis3', port=6379),
    Redis(host='redis4', port=6379),
    Redis(host='redis5', port=6379),
]

redlock = RedLock(instances, "order:1001", ttl=10000)
if redlock.acquire():
    try:
        process_order()
    finally:
        redlock.release()

    3. 消息队列¶

    3.1 List 实现简单队列¶

    import redis
import json
from typing import Optional, Any

class SimpleQueue:
    def __init__(self, redis_client: redis.Redis, queue_name: str):
        self.redis = redis_client
        self.queue_name = f"queue:{queue_name}"

    def push(self, message: Any) -> int:
        """生产者：推送消息"""
        return self.redis.rpush(self.queue_name, json.dumps(message))

    def pop(self, timeout: int = 0) -> Optional[Any]:
        """消费者：弹出消息"""
        if timeout > 0:
            # 阻塞式弹出
            result = self.redis.brpop(self.queue_name, timeout=timeout)
            if result:
                return json.loads(result[1])
            return None
        else:
            # 非阻塞式弹出
            result = self.redis.lpop(self.queue_name)
            if result:
                return json.loads(result)
            return None

    def size(self) -> int:
        """队列长度"""
        return self.redis.llen(self.queue_name)

    def is_empty(self) -> bool:
        """是否为空"""
        return self.size() == 0

# 使用示例
redis_client = redis.Redis()
queue = SimpleQueue(redis_client, "tasks")

# 生产者
queue.push({"task": "send_email", "user_id": 1001})
queue.push({"task": "generate_report", "report_id": 2001})

# 消费者
while True:
    message = queue.pop(timeout=5)  # 阻塞等待 5 秒
    if message:
        process_task(message)
    else:
        print("No tasks, waiting...")

    3.2 Stream 实现可靠队列¶

    import redis
import json
from typing import Optional, Dict, Any

class ReliableQueue:
    def __init__(self, redis_client: redis.Redis, stream_name: str, group_name: str, consumer_name: str):
        self.redis = redis_client
        self.stream_name = f"stream:{stream_name}"
        self.group_name = group_name
        self.consumer_name = consumer_name

        # 创建消费者组（如果不存在）
        try:
            self.redis.xgroup_create(self.stream_name, group_name, id="0", mkstream=True)
        except redis.exceptions.ResponseError:
            pass  # 组已存在

    def push(self, message: Dict[str, Any]) -> str:
        """生产者：发送消息"""
        return self.redis.xadd(self.stream_name, message)

    def pop(self, timeout: int = 5000) -> Optional[Dict[str, Any]]:
        """消费者：读取消息"""
        result = self.redis.xreadgroup(
            groupname=self.group_name,
            consumername=self.consumer_name,
            streams={self.stream_name: ">"},
            count=1,
            block=timeout
        )

        if result:
            stream, messages = result[0]
            if messages:
                message_id, message_data = messages[0]
                return {
                    "id": message_id.decode(),
                    "data": {k.decode(): v.decode() for k, v in message_data.items()}
                }
        return None

    def ack(self, message_id: str):
        """确认消息处理完成"""
        self.redis.xack(self.stream_name, self.group_name, message_id)

    def pending(self) -> Dict:
        """查看待处理消息"""
        return self.redis.xpending(self.stream_name, self.group_name)

# 使用示例
redis_client = redis.Redis()
queue = ReliableQueue(redis_client, "orders", "order-processors", "consumer-1")

# 生产者
queue.push({
    "event": "order_created",
    "order_id": "1001",
    "user_id": "101",
    "amount": "99.99"
})

# 消费者
while True:
    message = queue.pop(timeout=5000)
    if message:
        try:
            process_order(message["data"])
            queue.ack(message["id"])
        except Exception as e:
            print(f"Error processing message: {e}")
            # 不 ack，消息会重新进入待处理队列
    else:
        print("No messages, waiting...")

    3.3 发布订阅模式¶

    import redis
import json

class PubSub:
    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client
        self.pubsub = redis_client.pubsub()

    def publish(self, channel: str, message: Any) -> int:
        """发布消息"""
        return self.redis.publish(channel, json.dumps(message))

    def subscribe(self, channel: str):
        """订阅频道"""
        self.pubsub.subscribe(channel)

    def listen(self):
        """监听消息"""
        for message in self.pubsub.listen():
            if message["type"] == "message":
                yield {
                    "channel": message["channel"].decode(),
                    "data": json.loads(message["data"].decode())
                }

    import redis
import json
import uuid
import time
from typing import Optional, Dict

class SessionManager:
    def __init__(self, redis_client: redis.Redis, session_ttl: int = 1800):
        self.redis = redis_client
        self.session_ttl = session_ttl
        self.prefix = "session:"

    def create(self, user_id: int, data: Dict = None) -> str:
        """创建会话"""
        session_id = str(uuid.uuid4())
        key = f"{self.prefix}{session_id}"

        session_data = {
            "user_id": user_id,
            "data": data or {},
            "created_at": int(time.time())
        }

        self.redis.setex(key, self.session_ttl, json.dumps(session_data))
        return session_id

    def get(self, session_id: str) -> Optional[Dict]:
        """获取会话（同时刷新 TTL）"""
        key = f"{self.prefix}{session_id}"
        # 使用 Lua 保证 GET + EXPIRE 原子性，避免网络抖动导致数据返回但 TTL 未刷新
        script = """
        local data = redis.call("GET", KEYS[1])
        if data then
            redis.call("EXPIRE", KEYS[1], ARGV[1])
        end
        return data
        """
        data = self.redis.eval(script, 1, key, self.session_ttl)
        if data:
            return json.loads(data)
        return None

    def update(self, session_id: str, data: Dict):
        """更新会话"""
        session = self.get(session_id)
        if session:
            session["data"].update(data)
            key = f"{self.prefix}{session_id}"
            self.redis.setex(key, self.session_ttl, json.dumps(session))

    def delete(self, session_id: str):
        """删除会话（登出）"""
        key = f"{self.prefix}{session_id}"
        self.redis.delete(key)

    def refresh(self, session_id: str):
        """刷新会话过期时间"""
        key = f"{self.prefix}{session_id}"
        self.redis.expire(key, self.session_ttl)

# Flask 集成示例

    def __init__(self, redis_client: redis.Redis, name: str):
        self.redis = redis_client
        self.name = f"leaderboard:{name}"

    def add_score(self, member: str, score: float):

    def get_rank(self, member: str) -> int:
        """获取排名（从高到低）"""
        rank = self.redis.zrevrank(self.name, member)
        return rank + 1 if rank is not None else None

    def get_score(self, member: str) -> float:
        """获取分数"""
        score = self.redis.zscore(self.name, member)
        return float(score) if score else None

    def get_top(self, count: int = 10) -> List[Tuple[str, float]]:
        """获取前 N 名"""
        return self.redis.zrevrange(self.name, 0, count - 1, withscores=True)

    def get_around(self, member: str, count: int = 5) -> List[Tuple[str, float]]:
        """获取某成员附近的排名"""
        rank = self.redis.zrevrank(self.name, member)
        if rank is None:
            return []

        start = max(0, rank - count)
        end = rank + count
        return self.redis.zrevrange(self.name, start, end, withscores=True)

    def remove(self, member: str):
        """移除成员"""
        self.redis.zrem(self.name, member)

    class MultiLeaderboard:
    def __init__(self, redis_client: redis.Redis, name: str):
        self.redis = redis_client
        self.name = name

    def add_score(self, member: str, dimension: str, score: float):
        """添加维度分数"""
        key = f"leaderboard:{self.name}:{dimension}"
        self.redis.zadd(key, {member: score})

    def get_combined_rank(self, member: str, weights: Dict[str, float]) -> Tuple[int, float]:
        """计算加权综合排名"""
        # 计算所有成员的加权总分
        dimensions = self.redis.keys(f"leaderboard:{self.name}:*")
        pipe = self.redis.pipeline()

        all_members = set()
        for dim_key in dimensions:
            dim_name = dim_key.decode().split(":")[-1]
            weight = weights.get(dim_name, 1.0)
            members = self.redis.zrange(dim_key, 0, -1, withscores=True)
            for member_id, score in members:
                pipe.zincrby(f"leaderboard:{self.name}:total", weight * score, member_id)
                all_members.add(member_id.decode())

        pipe.execute()

        # 获取排名
        total_key = f"leaderboard:{self.name}:total"
        rank = self.redis.zrevrank(total_key, member)
        score = self.redis.zscore(total_key, member)

        return (rank + 1, score) if rank is not None else (None, None)

    6.1 限流器¶

    class RateLimiter:
    def __init__(self, redis_client: redis.Redis, key: str, max_requests: int, window_seconds: int):
        self.redis = redis_client
        self.key = f"ratelimit:{key}"
        self.max_requests = max_requests
        self.window_seconds = window_seconds

    def is_allowed(self) -> bool:
        """检查是否允许请求"""
        current_time = int(time.time())
        window_key = f"{self.key}:{current_time // self.window_seconds}"

        # 原子操作：计数 + 设置过期时间
        current = self.redis.incr(window_key)
        if current == 1:
            self.redis.expire(window_key, self.window_seconds)

        return current <= self.max_requests

# 使用示例
limiter = RateLimiter(redis_client, "api:user:1001", max_requests=100, window_seconds=60)

if limiter.is_allowed():
    process_request()
else:
    return "Rate limit exceeded", 429
    上面限流存在两个问题： 1. 竞态条件（Race Condition）： incr 和 expire 不是原子操作！高并发下可能出现： + 线程 A 执行 incr 返回 1 + 线程 B 执行 incr 返回 2 + 线程 A 执行 expire 设置过期时间 + 线程 B 也判断 current == 1 ❌ 不成立，但假设并发时序不同可能导致 expire 没被设置 + 结果：key 永不过期，内存泄漏 
    时间线（内存泄漏场景）：
T1: 线程 A 执行 incr，返回 1
T2: 线程 A 宕机了/网络断了/代码抛异常了...
T3: 线程 B、C、D... 继续 incr，但再也没有人执行 expire ❌
    2. 固定时间窗口边界问题:这是固定窗口限流，在窗口边界会被突破： 
    window_key = f"{self.key}:{current_time // self.window_seconds}"
    + 假设窗口 60 秒，0-60 秒一个窗口 + 59 秒时来了 100 个请求（用满配额） + 61 秒时又来 100 个请求（新窗口） + 实际 2 秒内处理了 200 个请求，是限流值的 2 倍

    完善版本如下： 1. 用 Lua 脚本保证 INCR + EXPIRE + 判断 的原子性 2. 固定窗口问题仍存在，如需更精确可用滑动窗口或令牌桶算法 

    import time

class RateLimiter:
    def __init__(self, redis_client: redis.Redis, key: str, max_requests: int, window_seconds: int):
        self.redis = redis_client
        self.key = f"ratelimit:{key}"
        self.max_requests = max_requests

            redis.call("EXPIRE", KEYS[1], ARGV[1])
        end
        if current <= tonumber(ARGV[2]) then
            return 1
        else
            return 0
        end
        """
        return bool(self.redis.eval(script, 1, window_key, self.window_seconds, self.max_requests))

    滑动窗口限流器：ZSET 滑动窗口（推荐）¶
    import time
import redis
from typing import Tuple

class SlidingWindowRateLimiter:
    """
    基于 Redis ZSET 的滑动窗口限流器

    原理：
    - 用 ZSET 存储每个请求的时间戳（score）和唯一 ID（member）
    - 每次请求时，删除窗口外的旧数据
    - 统计窗口内的请求数量，判断是否超限
    """

    def __init__(self, redis_client: redis.Redis, key: str, max_requests: int, window_seconds: int):
        self.redis = redis_client
        self.key = f"ratelimit:{key}"
        self.max_requests = max_requests
        self.window_seconds = window_seconds

    def is_allowed(self) -> Tuple[bool, int]:
        """
        检查是否允许请求

        Returns:
            (是否允许, 剩余可用次数)
        """
        now = time.time()
        window_start = now - self.window_seconds

        # 使用 Lua 脚本保证原子性
        script = """
        local key = KEYS[1]
        local now = tonumber(ARGV[1])
        local window_start = tonumber(ARGV[2])
        local max_requests = tonumber(ARGV[3])
        local request_id = ARGV[4]

        -- 1. 删除窗口外的旧数据
        redis.call("ZREMRANGEBYSCORE", key, "-inf", window_start)

        -- 2. 统计当前窗口内的请求数
        local current = redis.call("ZCARD", key)

        -- 3. 判断是否超限
        if current < max_requests then
            -- 4. 未超限，记录当前请求
            redis.call("ZADD", key, now, request_id)
            -- 5. 设置过期时间（自动清理）
            redis.call("EXPIRE", key, ARGV[5])
            return {1, max_requests - current - 1}
        else
            -- 6. 已超限
            return {0, 0}
        end
        """

        # 生成唯一请求 ID（时间戳 + 随机数）
        request_id = f"{now}:{time.time_ns()}"

        result = self.redis.eval(
            script, 1, 
            self.key, 
            now, 
            window_start, 
            self.max_requests, 
            request_id,
            self.window_seconds + 1  # 过期时间略大于窗口
        )

        return bool(result[0]), int(result[1])

    def get_remaining(self) -> int:
        """获取剩余可用次数（不消耗配额）

        注意：Pipeline 不保证原子性（Pipeline ≠ Lua），
        两次命令之间可能有新请求进来，返回值为近似值。
        如需精确查询应改用 Lua 脚本。
        """
        now = time.time()
        window_start = now - self.window_seconds

        # 清理旧数据并统计
        pipe = self.redis.pipeline()
        pipe.zremrangebyscore(self.key, "-inf", window_start)
        pipe.zcard(self.key)
        results = pipe.execute()

        current_count = results[1]
        return max(0, self.max_requests - current_count)

    def reset(self):
        """重置限流器"""
        self.redis.delete(self.key)


# ============ 使用示例 ============

if __name__ == "__main__":
    redis_client = redis.Redis(host="localhost", port=6379, db=0)

    # 创建限流器：60 秒内最多 100 次请求

        redis_client, 
        key="api:user:1001",
        max_requests=100,
        window_seconds=60
    )

            print(f"请求 {i+1}: ✅ 允许，剩余 {remaining} 次")

    滑动窗口限流器：令牌桶算法（更平滑）¶
    import time
import redis
from typing import Tuple

class TokenBucketRateLimiter:
    """
    令牌桶限流器

    原理：
    - 桶里有固定数量的令牌
    - 每次请求消耗 1 个令牌
    - 令牌以固定速率自动补充
    - 无令牌时拒绝请求

    特点：允许短时突发流量，但长期平均速率受限
    """

    def __init__(self, redis_client: redis.Redis, key: str, capacity: int, refill_rate: float):
        """
        Args:
            capacity: 桶容量（最大令牌数）
            refill_rate: 补充速率（每秒补充多少个令牌）
        """
        self.redis = redis_client
        self.key = f"tokenbucket:{key}"
        self.capacity = capacity
        self.refill_rate = refill_rate

    def is_allowed(self, tokens: int = 1) -> Tuple[bool, int]:
        """
        检查是否允许请求

        Args:
            tokens: 需要消耗的令牌数

        Returns:
            (是否允许, 剩余令牌数)
        """
        now = time.time()

        script = """
        local key = KEYS[1]
        local now = tonumber(ARGV[1])
        local capacity = tonumber(ARGV[2])
        local refill_rate = tonumber(ARGV[3])
        local requested = tonumber(ARGV[4])

        -- 获取当前状态
        local bucket = redis.call("HMGET", key, "tokens", "last_update")
        local tokens = tonumber(bucket[1])
        local last_update = tonumber(bucket[2])

        -- 初始化
        if not tokens then
            tokens = capacity
            last_update = now
        end

        -- 计算新增令牌数
        local elapsed = now - last_update
        local new_tokens = elapsed * refill_rate
        tokens = math.min(capacity, tokens + new_tokens)

        -- 判断是否足够
        if tokens >= requested then
            tokens = tokens - requested
            redis.call("HMSET", key, "tokens", tokens, "last_update", now)
            redis.call("EXPIRE", key, math.ceil(capacity / refill_rate) + 1)
            return {1, math.floor(tokens)}
        else
            redis.call("HMSET", key, "tokens", tokens, "last_update", now)
            return {0, math.floor(tokens)}
        end
        """

        result = self.redis.eval(
            script, 1,
            self.key,
            now,
            self.capacity,
            self.refill_rate,
            tokens
        )

        return bool(result[0]), int(result[1])


# ============ 使用示例 ============

if __name__ == "__main__":
    redis_client = redis.Redis(host="localhost", port=6379, db=0)

    # 创建令牌桶：容量 100，每秒补充 10 个令牌
    # 意味着：平时每秒 10 次，但可以突发到 100 次
    limiter = TokenBucketRateLimiter(
        redis_client,
        key="api:user:1001",
        capacity=100,
        refill_rate=10
    )

    # 模拟突发请求
    for i in range(120):
        allowed, remaining = limiter.is_allowed()
        if allowed:
            print(f"请求 {i+1}: ✅ 允许，剩余 {remaining} 令牌")
        else:
            print(f"请求 {i+1}: ❌ 令牌不足，剩余 {remaining}")

    特性 固定窗口 滑动窗口 令牌桶
    实现难度 ⭐ 简单 ⭐⭐ 中等 ⭐⭐ 中等
    内存占用 低 中（ZSET） 低
    边界问题 ❌ 有（2 倍突破） ✅ 无 ✅ 无

            if self.is_checked_in(user_id, date_str):
                continuous += 1
                current -= timedelta(days=1)
            else:
                break

        return continuous

    6.3 HyperLogLog — UV 统计¶

    import redis

class UVCounter:

        self.key = f"uv:{page}"

        self.redis.pfmerge(self.key, other_keys)
        return self.count()

from typing import List, Tuple

    def __init__(self, redis_client: redis.Redis, key: str = "geo:stores"):

    def get_pos(self, name: str) -> Tuple[float, float]:
        """获取位置的经纬度"""
        pos = self.redis.geopos(self.key, name)[0]
        return (pos[0], pos[1]) if pos else None

    def nearby(self, longitude: float, latitude: float, radius: float = 5) -> List:
        """查找附近的位置（默认 5 公里）"""
        return self.redis.georadius(
            self.key, longitude, latitude, radius, unit="km",
            withdist=True, withcoord=True, sort="ASC"
        )

    def nearby_by_member(self, member: str, radius: float = 5) -> List:
        """以某个位置为中心查找附近"""
        return self.redis.georadiusbymember(
            self.key, member, radius, unit="km",
            withdist=True, sort="ASC"
        )

    6.5 Bitmap 进阶 — 用户活跃分析¶

    签到系统用了 Bitmap 的基础功能，下面是进阶用法：

    class UserActivity:
    """基于 Bitmap 的用户活跃分析"""

    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client

    def mark_active(self, user_id: int, date: str):
        """标记用户当天活跃"""
        key = f"active:{date}"
        self.redis.setbit(key, user_id, 1)

    def daily_active_count(self, date: str) -> int:
        """某天活跃用户数"""
        return self.redis.bitcount(f"active:{date}")

    def weekly_active_count(self, start_date: str, end_date: str) -> int:
        """某周活跃用户数（去重）"""
        # 把一周的 Bitmap 做 OR 运算
        dates = self._date_range(start_date, end_date)
        keys = [f"active:{d}" for d in dates]

        if not keys:
            return 0
        if len(keys) == 1:
            return self.redis.bitcount(keys[0])

        # BITOP OR 合并
        dest_key = "temp:weekly_active"
        self.redis.bitop("OR", dest_key, *keys)
        count = self.redis.bitcount(dest_key)
        self.redis.delete(dest_key)  # 清理临时 key
        return count

    def continuous_active(self, user_id: int, dates: list) -> int:
        """用户在连续日期中的活跃天数"""
        keys = [f"active:{d}" for d in dates]
        if not keys:
            return 0

        # 对每个日期做 AND 运算，找出都活跃的用户
        # 注意：这里简化为逐个检查，也可以用 BITOP AND 后 GETBIT
        dest_key = "temp:continuous"
        self.redis.bitop("AND", dest_key, *keys)
        result = self.redis.getbit(dest_key, user_id)
        self.redis.delete(dest_key)
        return result

    @staticmethod
    def _date_range(start: str, end: str) -> list:
        """生成日期范围"""
        from datetime import datetime, timedelta
        start_dt = datetime.strptime(start, "%Y-%m-%d")
        end_dt = datetime.strptime(end, "%Y-%m-%d")
        dates = []
        current = start_dt
        while current <= end_dt:
            dates.append(current.strftime("%Y-%m-%d"))
            current += timedelta(days=1)
        return dates


# 使用示例
activity = UserActivity(redis_client)

# 标记活跃
activity.mark_active(1001, "2024-03-25")
activity.mark_active(1002, "2024-03-25")
activity.mark_active(1001, "2024-03-26")

# 某天活跃
print(f"3/25 活跃：{activity.daily_active_count('2024-03-25')} 人")

# 本周活跃（去重，1001 两天都活跃但只算 1 次）
print(f"本周活跃：{activity.weekly_active_count('2024-03-25', '2024-03-31')} 人")

    内存优势： Bitmap 每个用户每天只占 1 bit，1 亿用户一天的活跃数据仅需约 12 MB。

    7. 本章小结¶

    核心应用场景¶

    ✅ 缓存设计（Cache-Aside、更新策略、缓存一致性） ✅ 缓存三大问题（穿透、击穿、雪崩）
    ✅ 分布式锁（基础实现、红锁）
    ✅ 消息队列（List、Stream、PubSub）
    ✅ 会话管理（Session 存储）
    ✅ 排行榜系统（Sorted Set）
    ✅ 限流器、签到系统

    最佳实践¶

    1. 缓存：先写 DB 再删缓存；TTL 加随机值；空值缓存或布隆过滤器防穿透；互斥锁防击穿
    2. 分布式锁：Lua 脚本保证原子释放；设置超时防死锁；生产环境慎用 RedLock
    3. 消息队列：Stream 比 List 更可靠（支持 ACK、消费者组、重试）
    4. 会话：设置合理过期时间，支持刷新；GET + EXPIRE 用 Lua 保证原子性
    5. 排行榜：使用 ZSet，注意内存控制
    6. 限流：固定窗口用 Lua 保证原子性；精确限流推荐滑动窗口或令牌桶
    7. Bitmap：适合签到、活跃统计，1 亿用户仅需 12 MB/天
    8. HyperLogLog：UV 统计神器，12 KB 内存估算 2^64 基数
