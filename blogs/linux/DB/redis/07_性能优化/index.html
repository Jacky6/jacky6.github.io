    07_性能优化¶

    Redis 性能调优、内存优化、最佳实践

    1. 性能基准¶

    1.1 Redis 为什么快？¶

    因素 说明
    纯内存操作 数据存储在内存中，无磁盘 I/O
    单线程模型 无线程切换和锁竞争
    I/O 多路复用 epoll/kqueue 高效处理并发连接
    高效数据结构 针对场景优化的内部编码
    简单协议 RESP 协议解析简单

    1.2 性能指标¶

    # 基准测试

    2.2 数据结构优化¶

    （1）String 优化¶

    # 避免大字符串（>10KB）
# 差：存储整个 JSON
SET user:1001 '{"name":"张三","email":"zhangsan@example.com",...}'

# 好：使用 Hash 分字段存储
HSET user:1001 name "张三" email "zhangsan@example.com"

    （2）Hash 优化¶

    # Hash 比 String 节省内存（存储对象）
# String 方式：100 个字段 ≈ 10KB
# Hash 方式：100 个字段 ≈ 5KB（ziplist 编码）

# 查看编码
127.0.0.1:6379> OBJECT ENCODING user:1001
"ziplist"  # 压缩列表，节省内存

    （3）List 优化¶

    # 控制 List 长度
# 差：无限增长的 List
LPUSH logs:app "log entry..."

# 好：限制长度
LPUSH logs:app "log entry..."
LTRIM logs:app 0 9999  # 保留最近 10000 条

    （4）Set/ZSet 优化¶

    # 使用整数成员（intset 编码）
SADD tags:article 1 2 3 4 5  # 整数，节省内存

# 避免过多成员（>10000）
# 考虑分片
SADD tags:article:shard1 1 2 3
SADD tags:article:shard2 4 5 6

    2.3 内存淘汰策略¶

    # redis.conf

# 最大内存
maxmemory 2gb

# 淘汰策略
# volatile-lru：从有过期时间的 key 中 LRU 淘汰
# allkeys-lru：从所有 key 中 LRU 淘汰（推荐用于缓存）
# volatile-lfu：从有过期时间的 key 中 LFU 淘汰
# allkeys-lfu：从所有 key 中 LFU 淘汰
# volatile-random：从有过期时间的 key 中随机淘汰
# allkeys-random：从所有 key 中随机淘汰
# volatile-ttl：从有过期时间的 key 中淘汰即将过期的
# noeviction：不淘汰，写操作返回错误（默认）

maxmemory-policy allkeys-lru

# LRU 采样数（7.0+ 使用 LFU）
maxmemory-samples 10

    2.4 键值设计优化¶

    # 1. 合理的 key 命名
# 差：过长的 key
SET user:1001:profile:basic:information:name "张三"

# 好：简洁的 key
SET user:1001:name "张三"

# 2. 使用 Hash 存储对象
# 差：多个 String
SET user:1001:name "张三"
SET user:1001:age "25"
SET user:1001:email "zhangsan@example.com"

# 好：一个 Hash
HSET user:1001 name "张三" age 25 email "zhangsan@example.com"

# 3. 批量操作
# 差：多次网络往返
SET a 1
SET b 2
SET c 3

# 好：批量操作
MSET a 1 b 2 c 3
# 或管道
redis-cli --pipe < commands.txt

# 4. 合理设置过期时间
# 避免同时过期（缓存雪崩）
# 差：所有缓存 1 小时后过期
SETEX cache:1 3600 "value1"
SETEX cache:2 3600 "value2"

# 好：添加随机偏移
SETEX cache:1 3580 "value1"  # 3600 ± 120 秒
SETEX cache:2 3620 "value2"

    # redis.conf

# ==================== 网络优化 ====================

# 禁用危险命令
rename-command FLUSHDB ""
rename-command FLUSHALL ""
rename-command DEBUG ""

# 日志级别
loglevel notice

    4. 最佳实践¶

    4.1 命令使用建议¶

    推荐 不推荐 原因
    HGETALL 多次 HGET 减少网络往返
    MSET/MGET 多次 SET/GET 批量操作效率高
    LRANGE 0 10 LRANGE 0 -1 避免返回全部
    ZRANGE 0 9 ZRANGE 0 -1 限制返回数量
    SCAN KEYS KEYS 阻塞主线程
    管道批量 单条执行 减少网络延迟

    4.2 避免阻塞命令¶

    # 阻塞命令（生产环境慎用）
KEYS *              # 使用 SCAN 替代
HGETALL big_hash    # 使用 HSCAN
SMEMBERS big_set    # 使用 SSCAN
ZRANGE big_zset 0 -1  # 使用 ZSCAN

# 使用 SCAN 替代 KEYS
127.0.0.1:6379> SCAN 0 MATCH user:* COUNT 100
1) "100"  # 游标
2) 1) "user:1001"
   2) "user:1002"
   3) "user:1003"

# 继续扫描
127.0.0.1:6379> SCAN 100 MATCH user:* COUNT 100

    4.3 大 Key 处理¶

    # 发现大 Key
redis-cli --bigkeys

# 删除大 Key（避免阻塞）
# 差：直接删除（阻塞）
DEL big_key

# 好：分批删除
# Hash
redis-cli HSCAN big_hash 0 COUNT 100 | awk '{print $1}' | xargs -n 2 redis-cli HDEL big_hash

# Set
redis-cli SSCAN big_set 0 COUNT 100 | awk '{print $1}' | xargs -n 1 redis-cli SREM big_set

# 使用 UNLINK（异步删除，Redis 4.0+）
UNLINK big_key

    4.4 缓存设计模式¶

    （1）缓存穿透¶

    问题：查询不存在的数据，请求直达数据库

解决方案：
1. 布隆过滤器
2. 缓存空值

    # 缓存空值
def get_user(user_id):
    # 尝试从缓存获取
    user = redis.get(f"user:{user_id}")
    if user is not None:
        return user if user != "NULL" else None

    # 从数据库获取
    user = db.query_user(user_id)

    # 缓存结果（包括空值）
    if user:
        redis.setex(f"user:{user_id}", 3600, user)
    else:
        redis.setex(f"user:{user_id}", 300, "NULL")  # 空值缓存 5 分钟

    return user

    （2）缓存击穿¶

    问题：热点 key 过期，大量请求直达数据库

解决方案：
1. 互斥锁
2. 逻辑过期

    # 互斥锁
import threading

lock = threading.Lock()

def get_hot_data(key):
    data = redis.get(key)
    if data:
        return data

    # 获取分布式锁
    if redis.set(f"lock:{key}", "1", nx=True, ex=10):
        try:
            # 双重检查
            data = redis.get(key)
            if data:
                return data

            # 从数据库获取
            data = db.query(key)
            redis.setex(key, 3600, data)
            return data
        finally:
            redis.delete(f"lock:{key}")
    else:
        # 等待后重试
        time.sleep(0.1)
        return get_hot_data(key)

    （3）缓存雪崩¶

    问题：大量 key 同时过期

解决方案：
1. 随机过期时间
2. 多级缓存
3. 限流降级

    # 随机过期时间
import random

def set_cache(key, value):
    base_ttl = 3600
    random_ttl = random.randint(-300, 300)  # ±5 分钟
    redis.setex(key, base_ttl + random_ttl, value)

    5. 常见问题¶

    Q1: Redis CPU 使用率高？¶

    A: 1. 检查慢查询：SLOWLOG GET 10 2. 检查大 Key：redis-cli --bigkeys 3. 检查是否有 KEYS 等阻塞命令 4. 考虑读写分离

    Q2: Redis 内存不足？¶

    A: 1. 设置 maxmemory 和淘汰策略 2. 分析大 Key 并优化 3. 使用 Hash 替代多个 String 4. 定期清理过期数据

    Q3: 连接数过多？¶

    A: 1. 使用连接池 2. 设置合理的 timeout 3. 检查客户端连接泄漏 4. 增加 maxclients

    Q4: 主从延迟大？¶

    A: 1. 检查网络带宽 2. 减少主库写压力 3. 使用更快的磁盘（AOF 刷盘） 4. 考虑增加从库数量

    Q5: 如何监控 Redis？¶

    A: 1. 内置命令：INFO、SLOWLOG 2. 监控工具：Prometheus + Grafana 3. 云服务：Redis Cloud、阿里云 Redis 监控 4. 开源方案：Redis Exporter
