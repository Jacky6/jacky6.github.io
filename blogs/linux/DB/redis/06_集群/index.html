    06_集群¶

    Redis Cluster 是 Redis 的分布式解决方案，支持自动分片和高可用

    1. 集群概述¶

    1.1 为什么需要集群？¶

    问题 单机限制 集群方案
    内存容量 单实例内存有限 多实例分片，总容量 = 各节点之和
    写性能 单线程写瓶颈 多主库并行写
    高可用 单点故障 主从复制 + 自动故障转移

    1.2 集群架构¶

    Redis Cluster 典型架构（6 节点）：

  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
  │  Master A   │     │  Master B   │     │  Master C   │
  │ 192.168.1.1 │     │ 192.168.1.2 │     │ 192.168.1.3 │
  │   :7000     │     │   :7001     │     │   :7002     │
  │  0-5460 槽   │     │ 5461-10922 槽│     │10923-16383 槽│
  └──────┬──────┘     └──────┬──────┘     └──────┬──────┘
         │                   │                   │
         │                   │                   │
         ▼                   ▼                   ▼
  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
  │   Slave A   │     │   Slave B   │     │   Slave C   │
  │ 192.168.1.4 │     │ 192.168.1.5 │     │ 192.168.1.6 │
  │   :7003     │     │   :7004     │     │   :7005     │
  └─────────────┘     └─────────────┘     └─────────────┘

    1.3 核心概念¶

    概念 说明
    槽（Slot） 16384 个槽，数据分片的基本单位
    主节点 负责处理读写请求，持有槽
    从节点 复制主节点数据，主库故障时提升
    哈希槽 key 通过 CRC16(key) % 16384 计算槽位
    Gossip 协议 节点间通信协议，传播集群状态

    2. 集群部署¶

    2.1 环境准备¶

    # 创建目录
mkdir -p /data/redis/cluster/{7000..7005}

# 下载 Redis（需要 3.0+）
wget https://download.redis.io/releases/redis-7.2.4.tar.gz
tar xzf redis-7.2.4.tar.gz
cd redis-7.2.4 && make && sudo make install

    2.2 节点配置¶

    # /data/redis/cluster/7000/redis.conf

# 端口
port 7000

# 绑定地址
bind 0.0.0.0

# 守护进程
daemonize yes

# 工作目录
dir /data/redis/cluster/7000

# 日志文件
logfile "/data/redis/cluster/7000/redis.log"

# 启用集群模式
cluster-enabled yes

# 集群配置文件（自动生成）
cluster-config-file nodes-7000.conf

# 节点超时时间（毫秒）
cluster-node-timeout 5000

# 密码（可选）
requirepass your-password
masterauth your-password

# 持久化
appendonly yes

    方式二：手动创建¶

    # 1. 启动所有节点
for port in 7000 7001 7002 7003 7004 7005; do
    redis-server /data/redis/cluster/$port/redis.conf
done

# 2. 互相 MEET（让节点互相认识）
redis-cli -p 7000 CLUSTER MEET 192.168.1.2 7001
redis-cli -p 7000 CLUSTER MEET 192.168.1.3 7002
redis-cli -p 7000 CLUSTER MEET 192.168.1.4 7003
redis-cli -p 7000 CLUSTER MEET 192.168.1.5 7004
redis-cli -p 7000 CLUSTER MEET 192.168.1.6 7005

# 3. 分配槽给主节点
for slot in $(seq 0 5460); do
    redis-cli -p 7000 CLUSTER ADDSLOTS $slot
done

for slot in $(seq 5461 10922); do
    redis-cli -p 7001 CLUSTER ADDSLOTS $slot
done

for slot in $(seq 10923 16383); do
    redis-cli -p 7002 CLUSTER ADDSLOTS $slot
done

# 4. 设置从节点
redis-cli -p 7003 CLUSTER REPLICATE abc123...  # Master A 的 nodeId
redis-cli -p 7004 CLUSTER REPLICATE def456...  # Master B 的 nodeId
redis-cli -p 7005 CLUSTER REPLICATE ghi789...  # Master C 的 nodeId

    3. 集群操作¶

    3.1 数据读写¶

    # 连接集群（任意节点）
redis-cli -c -h 192.168.1.1 -p 7000 -a your-password

# -c 选项启用集群模式，自动重定向

# 写操作
127.0.0.1:7000> SET user:1001:name "张三"
# -> Redirected to slot [1234] located at 192.168.1.2:7001
# OK

# 读操作
127.0.0.1:7000> GET user:1001:name
# -> Redirected to slot [1234] located at 192.168.1.2:7001
# "张三"

# 查看 key 所在槽
127.0.0.1:7000> CLUSTER KEYSLOT user:1001:name
(integer) 1234

# 批量操作（key 必须在同一槽）
127.0.0.1:7000> MSET {user:1001}:name "张三" {user:1001}:age 25
OK

    3.2 添加节点¶

    # 1. 启动新节点
redis-server /data/redis/cluster/7006/redis.conf

# 2. 加入集群（作为从节点）
redis-cli --cluster add-node 192.168.1.7:7006 192.168.1.1:7000

# 3. 作为主节点并分配槽
redis-cli --cluster add-node 192.168.1.7:7006 192.168.1.1:7000 \
  --cluster-master-id abc123...

# 4. 重新分片（移动槽）
redis-cli --cluster reshard 192.168.1.1:7000
# >>> How many slots do you want to move? 2000
# >>> What is the receiving node ID? xyz789...  # 新节点 ID
# >>> Source node #1: abc123...  # 从哪个节点移动
# >>> Source node #2: done  # 结束

# 5. 检查集群
redis-cli --cluster check 192.168.1.1:7000

    3.3 删除节点¶

    # 1. 迁移该节点的槽到其他节点
redis-cli --cluster reshard 192.168.1.1:7000
# 将该节点的所有槽移走

# 2. 如果是主节点，确保有从节点
# 如果没有从节点，先添加一个

# 3. 删除节点
redis-cli --cluster del-node 192.168.1.1:7000 abc123...

# 4. 检查集群
redis-cli --cluster check 192.168.1.1:7000

    3.4 故障转移¶

    # 手动故障转移（从节点提升为主节点）
redis-cli -p 7003 CLUSTER FAILOVER

# 强制故障转移（即使主节点正常）
redis-cli -p 7003 CLUSTER FAILOVER FORCE

# 接管故障转移
redis-cli -p 7003 CLUSTER FAILOVER TAKEOVER

# 查看故障转移状态
redis-cli -p 7003 CLUSTER INFO | grep cluster_state

    3.5 槽迁移详解¶

    # 查看槽状态
redis-cli -p 7000 CLUSTER SLOTS

# 迁移槽（手动）
# 1. 在源节点设置槽为 MIGRATING
redis-cli -p 7000 CLUSTER SETSLOT 100 MIGRATING xyz789...

# 2. 在目标节点设置槽为 IMPORTING
redis-cli -p 7006 CLUSTER SETSLOT 100 IMPORTING abc123...

# 3. 迁移 key
redis-cli -p 7000 MIGRATE 192.168.1.7 7006 "key_name" 0 5000

# 4. 完成槽迁移
redis-cli -p 7000 CLUSTER SETSLOT 100 NODE xyz789...
redis-cli -p 7006 CLUSTER SETSLOT 100 NODE xyz789...

    4. 客户端连接¶

    4.1 Python 示例¶

    from redis.cluster import RedisCluster, ClusterNode

# 连接集群
rc = RedisCluster(
    startup_nodes=[
        ClusterNode('192.168.1.1', 7000),
        ClusterNode('192.168.1.2', 7001),
        ClusterNode('192.168.1.3', 7002),
    ],
    password='your-password',
    decode_responses=True,
)

# 写操作
rc.set('user:1001:name', '张三')

# 读操作
name = rc.get('user:1001:name')
print(name)  # 张三

# 批量操作（key 必须在同一槽）
rc.mset({
    '{user:1001}:name': '张三',
    '{user:1001}:age': '25',
    '{user:1001}:email': 'zhangsan@example.com',
})

# 关闭连接
rc.close()

    4.2 Java 示例（Jedis）¶

    import redis.clients.jedis.ClusterCommandArguments;
import redis.clients.jedis.HostAndPort;
import redis.clients.jedis.JedisCluster;

import java.util.HashSet;
import java.util.Set;

Set<HostAndPort> nodes = new HashSet<>();
nodes.add(new HostAndPort("192.168.1.1", 7000));
nodes.add(new HostAndPort("192.168.1.2", 7001));
nodes.add(new HostAndPort("192.168.1.3", 7002));

JedisCluster cluster = new JedisCluster(nodes);

// 写操作
cluster.set("user:1001:name", "张三");

// 读操作
String name = cluster.get("user:1001:name");
System.out.println(name);  // 张三

// 关闭连接
cluster.close();

    4.3 Node.js 示例（ioredis）¶

    const Redis = require('ioredis');

const cluster = new Redis.Cluster([
  { host: '192.168.1.1', port: 7000 },
  { host: '192.168.1.2', port: 7001 },
  { host: '192.168.1.3', port: 7002 },
], {
  redisOptions: {
    password: 'your-password',
  },
});

// 写操作
await cluster.set('user:1001:name', '张三');

// 读操作
const name = await cluster.get('user:1001:name');
console.log(name);  // 张三

// 关闭连接
await cluster.quit();

    5. 哈希槽（Hash Slot）¶

    5.1 槽计算¶

    槽位计算公式：
SLOT = CRC16(key) % 16384

示例：
CRC16("user:1001:name") = 12345
SLOT = 12345 % 16384 = 12345

    5.2 哈希标签（Hash Tag）¶

    使用 {} 强制 key 在同一槽：

{user:1001}:name → CRC16("user:1001") % 16384
{user:1001}:age  → CRC16("user:1001") % 16384
{user:1001}:email → CRC16("user:1001") % 16384

所有 key 都在同一槽，支持批量操作

    # 验证哈希标签
127.0.0.1:7000> CLUSTER KEYSLOT {user:1001}:name
(integer) 5398
127.0.0.1:7000> CLUSTER KEYSLOT {user:1001}:age
(integer) 5398  # 相同槽
127.0.0.1:7000> CLUSTER KEYSLOT {user:1001}:email
(integer) 5398  # 相同槽

# 没有哈希标签
127.0.0.1:7000> CLUSTER KEYSLOT user:1001:name
(integer) 12345
127.0.0.1:7000> CLUSTER KEYSLOT user:1001:age
(integer) 67890  # 不同槽

    6. 集群运维¶

    6.1 备份与恢复¶

    # 备份（在每个主节点执行）
redis-cli -p 7000 BGSAVE
redis-cli -p 7001 BGSAVE
redis-cli -p 7002 BGSAVE

# 复制 RDB 文件
scp 192.168.1.1:/data/redis/cluster/7000/dump.rdb /backup/
scp 192.168.1.2:/data/redis/cluster/7001/dump.rdb /backup/
scp 192.168.1.3:/data/redis/cluster/7002/dump.rdb /backup/

# 恢复
# 1. 停止集群
redis-cli --cluster call 192.168.1.1:7000 shutdown

# 2. 替换 RDB 文件
cp /backup/dump.rdb /data/redis/cluster/7000/

# 3. 启动集群
redis-server /data/redis/cluster/7000/redis.conf

    6.2 监控指标¶

    # 关键监控指标
redis-cli -p 7000 INFO cluster
# cluster_state:ok
# cluster_slots_assigned:16384
# cluster_slots_ok:16384
# cluster_known_nodes:6
# cluster_size:3

# 内存使用
redis-cli -p 7000 INFO memory | grep used_memory_human

# 连接数
redis-cli -p 7000 INFO clients | grep connected_clients

    6.3 常见故障处理¶

    （1）节点下线¶

    # 检查集群状态
redis-cli --cluster check 192.168.1.1:7000

# 如果有节点 FAIL
# 1. 重启故障节点
redis-server /data/redis/cluster/7000/redis.conf

# 2. 让其他节点重新认识它
redis-cli -p 7001 CLUSTER MEET 192.168.1.1 7000

    （2）槽未覆盖¶

    # 查看未覆盖的槽
redis-cli -p 7000 CLUSTER INFO | grep cluster_slots

# 修复
redis-cli --cluster fix 192.168.1.1:7000

    （3）数据不一致¶

    # 重新同步
redis-cli -p 7003 CLUSTER REPLICATE abc123...

    7. 集群 vs 哨兵¶

    特性 哨兵模式 集群模式
    数据分片 ❌ ✅
    写扩展 ❌ ✅
    读扩展 ✅ ✅
    高可用 ✅ ✅
    运维复杂度 低 高
    适用场景 中小规模 大规模

    8. 本章小结¶

    核心知识点¶

    ✅ Redis Cluster 架构原理
    ✅ 槽分配与数据分片
    ✅ 集群部署与配置
    ✅ 节点管理（添加/删除）
    ✅ 槽迁移与重新分片
    ✅ 客户端连接集群
    ✅ 哈希标签使用

    最佳实践¶

    1. 节点数量：至少 3 主 3 从（6 节点）
    2. 密码设置：生产环境必须设置密码
    3. 持久化：开启 AOF 保证数据安全
    4. 监控告警：监控集群状态、槽分布
    5. 定期演练：故障转移、节点扩容演练
