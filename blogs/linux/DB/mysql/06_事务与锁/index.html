    06_事务与锁¶

    事务 ACID、隔离级别、锁类型、MVCC、死锁分析

    1. 事务基础¶

    1.1 什么是事务？¶

    事务是数据库操作的最小工作单元，要么全部成功，要么全部失败。

    -- 转账示例
START TRANSACTION;

-- 从 A 账户扣款
UPDATE accounts SET balance = balance - 100 WHERE id = 1;

-- 向 B 账户加款
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- 提交事务
COMMIT;

-- 或回滚
-- ROLLBACK;

    1.2 ACID 特性¶

    特性 说明 实现机制
    原子性（Atomicity） 事务是不可分割的整体 undo log
    一致性（Consistency） 事务前后数据一致 约束、触发器
    隔离性（Isolation） 并发事务互不干扰 锁、MVCC
    持久性（Durability） 提交后永久保存 redo log

    1.3 事务操作¶

    -- 开启事务
START TRANSACTION;
-- 或
BEGIN;

-- 提交事务
COMMIT;

-- 回滚事务
ROLLBACK;

-- 设置保存点
SAVEPOINT sp1;

-- 回滚到保存点
ROLLBACK TO sp1;

-- 释放保存点
RELEASE SAVEPOINT sp1;

-- 查看事务状态
SELECT * FROM information_schema.innodb_trx;

    1.4 自动提交¶

    -- 查看自动提交状态
SELECT @@autocommit;

-- 关闭自动提交
SET autocommit = 0;

-- 开启自动提交
SET autocommit = 1;

-- 注意：DDL 语句（CREATE、ALTER、DROP）会自动提交

    2. 隔离级别¶

    2.1 并发问题¶

    问题 说明 示例
    脏读 读到未提交的数据 A 修改未提交，B 读到
    不可重复读 同一事务内多次读取结果不同 A 读取后 B 修改提交，A 再读不同
    幻读 同一事务内多次查询结果集不同 A 查询后 B 插入，A 再查多出行

    2.2 SQL 标准隔离级别¶

    隔离级别 脏读 不可重复读 幻读
    READ UNCOMMITTED ✅ ✅ ✅
    READ COMMITTED ❌ ✅ ✅
    REPEATABLE READ ❌ ❌ ❌*
    SERIALIZABLE ❌ ❌ ❌

    *MySQL InnoDB 通过 MVCC 和间隙锁解决幻读

    2.3 查看和设置隔离级别¶

    -- 查看全局隔离级别
SELECT @@global.transaction_isolation;

-- 查看会话隔离级别
SELECT @@session.transaction_isolation;

-- 设置全局隔离级别
SET GLOBAL TRANSACTION ISOLATION LEVEL REPEATABLE READ;

-- 设置会话隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 设置当前事务隔离级别
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

    2.4 各隔离级别详解¶

    READ UNCOMMITTED¶

    -- 会话 A
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
UPDATE users SET age = 26 WHERE id = 1;  -- 未提交

-- 会话 B（可以读到未提交的数据 - 脏读）
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
SELECT age FROM users WHERE id = 1;  -- 读到 26（脏数据）

    READ COMMITTED¶

    -- 会话 A
START TRANSACTION;
UPDATE users SET age = 26 WHERE id = 1;
COMMIT;  -- 提交

-- 会话 B（只能读到已提交的数据）
START TRANSACTION;
SELECT age FROM users WHERE id = 1;  -- 提交前读不到
SELECT age FROM users WHERE id = 1;  -- 提交后读到 26（不可重复读）

    REPEATABLE READ（MySQL 默认）¶

    -- 会话 A
START TRANSACTION;
SELECT age FROM users WHERE id = 1;  -- 读到 25
-- 会话 B 修改并提交
-- UPDATE users SET age = 26 WHERE id = 1; COMMIT;
SELECT age FROM users WHERE id = 1;  -- 还是 25（可重复读）
COMMIT;
SELECT age FROM users WHERE id = 1;  -- 提交后才能读到 26

    SERIALIZABLE¶

    -- 会话 A
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
START TRANSACTION;
SELECT * FROM users WHERE id = 1;  -- 加共享锁

-- 会话 B（被阻塞）
START TRANSACTION;
UPDATE users SET age = 26 WHERE id = 1;  -- 等待 A 提交

    3. 锁基础¶

    3.1 锁粒度¶

    粒度 说明 开销 并发
    表锁 锁整张表 小 低
    行锁 锁单行 大 高
    页锁 锁数据页 中 中

    3.2 锁类型¶

    锁类型 说明 兼容性
    共享锁（S 锁） 读锁，允许其他事务读 S-S 兼容，S-X 不兼容
    排他锁（X 锁） 写锁，不允许其他事务读写 X-X、X-S 都不兼容 
    -- 共享锁
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;
-- 或（8.0+）
SELECT * FROM users WHERE id = 1 FOR SHARE;

-- 排他锁
SELECT * FROM users WHERE id = 1 FOR UPDATE;

-- 更新自动加排他锁
UPDATE users SET age = 26 WHERE id = 1;
DELETE FROM users WHERE id = 1;
INSERT INTO users ...;

    3.3 InnoDB 锁类型¶

    记录锁（Record Lock）¶

    -- 锁单条记录
SELECT * FROM users WHERE id = 1 FOR UPDATE;

    间隙锁（Gap Lock）¶

    -- 锁范围（不包含记录本身）
SELECT * FROM users WHERE id > 1 AND id < 10 FOR UPDATE;
-- 锁住 (1, 10) 区间，防止其他事务插入

    临键锁（Next-Key Lock）¶

    -- 记录锁 + 间隙锁
-- REPEATABLE READ 级别下，范围查询使用
SELECT * FROM users WHERE id > 1 FOR UPDATE;
-- 锁住 (1, +∞) 区间

    意向锁（Intention Lock）¶

    意向锁是表级锁，表示事务要在某个粒度上加锁

意向共享锁（IS）：事务打算给数据行加 S 锁
意向排他锁（IX）：事务打算给数据行加 X 锁

IS 和 IX 自动添加，无需手动干预

    4. MVCC（多版本并发控制）¶

    4.1 MVCC 原理¶

    MVCC 通过保存数据的历史版本实现读写并发：

行记录结构：
┌─────────────────────────────────────────┐
│ 数据 │ DB_TRX_ID │ DB_ROLL_PTR │ ...   │
│      │ 事务 ID   │ 回滚指针    │       │
└─────────────────────────────────────────┘

undo log 链：
当前版本 → undo log1 → undo log2 → ...

    4.2 Read View¶

    Read View 包含：
- m_ids: 活跃事务 ID 列表
- min_trx_id: 最小活跃事务 ID
- max_trx_id: 下一个事务 ID
- creator_trx_id: 创建 Read View 的事务 ID

可见性判断：
1. trx_id < min_trx_id → 可见（老版本）
2. trx_id >= max_trx_id → 不可见（新版本）
3. trx_id in m_ids → 不可见（活跃事务）
4. 其他情况 → 可见

    4.3 隔离级别与 MVCC¶

    -- READ COMMITTED：每次 SELECT 生成新的 Read View
START TRANSACTION;
SELECT * FROM users WHERE id = 1;  -- 生成 Read View 1
-- 其他事务提交
SELECT * FROM users WHERE id = 1;  -- 生成 Read View 2（能看到新数据）

-- REPEATABLE READ：第一次 SELECT 生成 Read View，后续复用
START TRANSACTION;
SELECT * FROM users WHERE id = 1;  -- 生成 Read View
-- 其他事务提交
SELECT * FROM users WHERE id = 1;  -- 复用 Read View（看不到新数据）
COMMIT;

    5. 死锁¶

    5.1 死锁示例¶

    事务 A:                    事务 B:
START TRANSACTION;         START TRANSACTION;
UPDATE users SET ... WHERE id = 1;  -- 锁 id=1
                            UPDATE users SET ... WHERE id = 2;  -- 锁 id=2
UPDATE users SET ... WHERE id = 2;  -- 等待 id=2（被 B 锁）
                            UPDATE users SET ... WHERE id = 1;  -- 等待 id=1（被 A 锁）
                            ↓ 死锁！

    5.2 查看死锁¶

    -- 查看死锁日志
SHOW ENGINE INNODB STATUS;

-- 查看锁等待
SELECT * FROM information_schema.innodb_lock_waits;

-- 查看锁信息（8.0+）
SELECT * FROM performance_schema.data_locks;
SELECT * FROM performance_schema.data_lock_waits;

    5.3 避免死锁¶

    -- 1. 固定顺序访问表
-- 所有事务都按 id 从小到大访问

-- 2. 一次性锁定所有资源
SELECT * FROM users WHERE id IN (1, 2) FOR UPDATE;

-- 3. 降低隔离级别
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 4. 设置锁等待超时
SET innodb_lock_wait_timeout = 10;  -- 10 秒

-- 5. 使用小事务
-- 避免大事务长时间持有锁

    5.4 死锁处理¶

    -- InnoDB 会自动检测死锁并回滚其中一个事务
-- 被回滚的事务收到错误：
-- ERROR 1213 (40001): Deadlock found when trying to get lock; try restarting transaction

-- 应用层处理：捕获异常，重试

    6. 锁监控¶

    6.1 查看锁状态¶

    -- 查看事务
SELECT * FROM information_schema.innodb_trx;

-- 查看锁
SELECT * FROM information_schema.innodb_locks;  -- 5.7
SELECT * FROM performance_schema.data_locks;    -- 8.0+

-- 查看锁等待
SELECT * FROM information_schema.innodb_lock_waits;  -- 5.7
SELECT * FROM performance_schema.data_lock_waits;    -- 8.0+

-- 查看进程
SHOW PROCESSLIST;

    6.2 杀死阻塞会话¶

    -- 找到阻塞的会话
SELECT 
    r.trx_id AS waiting_trx_id,
    r.trx_mysql_thread_id AS waiting_thread,
    b.trx_id AS blocking_trx_id,
    b.trx_mysql_thread_id AS blocking_thread
FROM information_schema.innodb_lock_waits w
JOIN information_schema.innodb_trx b ON b.trx_id = w.blocking_trx_id
JOIN information_schema.innodb_trx r ON r.trx_id = w.requesting_trx_id;

-- 杀死会话
KILL 123;

    7. 长事务问题¶

    7.1 长事务危害¶

    • 占用 undo log 空间
    • 导致主从延迟
    • 持有锁时间长，影响并发
    • 可能导致内存溢出

    7.2 监控长事务¶

    -- 查看运行时间超过 60 秒的事务
SELECT * FROM information_schema.innodb_trx
WHERE TIME_TO_SEC(TIMEDIFF(NOW(), trx_started)) > 60;

-- 设置长事务阈值
SET GLOBAL innodb_monitor_enable = 'innodb_metrics';

-- 自动杀死长事务（谨慎使用）
SET GLOBAL max_execution_time = 30000;  -- 30 秒

    7.3 避免长事务¶

    -- 1. 及时提交事务
START TRANSACTION;
-- 操作
COMMIT;

-- 2. 避免在事务中等待用户输入

-- 3. 分批处理大数据
START TRANSACTION;
DELETE FROM logs WHERE created_at < '2023-01-01' LIMIT 1000;
COMMIT;
-- 重复执行

-- 4. 设置超时
SET SESSION max_execution_time = 30000;

    核心知识点¶

    ✅ 事务 ACID 特性

    最佳实践¶

    1. 选择合适隔离级别：默认 RR，高并发用 RC
    2. 避免长事务：及时提交，分批处理
    3. 固定访问顺序：避免死锁
    4. 使用短索引：减少锁范围
    5. 监控锁等待：及时发现性能问题
