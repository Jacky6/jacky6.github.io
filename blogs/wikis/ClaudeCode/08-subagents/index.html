    Claude Code 教程 08：子代理（Subagents）¶

    创建和使用专门的 AI 子代理来处理特定类型的任务，实现更好的上下文管理和任务委派。

    官方文档参考： https://code.claude.com/docs/en/sub-agents

    什么是子代理？¶

    子代理是 Claude Code 内部的专业 AI 助手，每个子代理有独立的上下文窗口、特定的工具集和权限。

    为什么需要子代理？¶

    问题 子代理如何解决
    旁支任务用搜索、日志、文件内容淹没主对话 子代理在独立上下文中工作，只返回摘要
    需要限制某些任务的工具访问 子代理可以配置专用工具集
    重复创建相同类型的 Worker 定义一次，多次复用
    需要更便宜的模型做简单任务 子代理可以使用不同的模型
    需要并行处理多个任务 多个子代理可以同时工作（Agent Teams）

    与 Agent Teams 的区别： 子代理在单个会话内工作；Agent Teams 在独立会话之间协调并可以并行通信。

    内置子代理¶

    Claude Code 自带以下子代理：

    子代理 模型 工具 用途 何时使用
    Explore Haiku（快速） 只读（禁止 Write/Edit） 文件发现、代码搜索、代码库探索 Claude 需要理解代码结构时
    Plan 继承主会话 只读 Plan 模式下的代码库研究 你在 Plan 模式中需要方案时
    General-purpose 继承主会话 全部工具 复杂研究、多步操作、代码修改 需要独立探索+修改的复杂任务
    statusline-setup Sonnet — 配置状态行 运行 /statusline 时
    claude-code-guide Haiku — 回答 Claude Code 功能问题 你问 "怎么用 Hooks" 时

    Explore 子代理的深入级别¶

    Claude 委派给 Explore 时可以指定三种深入程度：

    级别 说明 示例场景
    quick 快速查找 "formatDate 函数在哪里定义的？"
    medium 平衡探索 "认证模块的架构是怎样的？"
    very thorough 全面分析 "梳理整个支付流程，包括所有相关文件"

    创建自定义子代理¶

    方式一：使用 /agents 命令（推荐）¶

    /agents

    打开交互式管理界面：

    1. 切换到 Library 选项卡
    2. 选择 Create new agent
    3. 选择保存位置：
    4. Personal → 保存到 ~/.claude/agents/（所有项目可用）
    5. Project → 保存到 .claude/agents/（仅当前项目）
    6. 选择 Generate with Claude 或手动编写
    7. 描述你想要的子代理，Claude 会帮你生成配置

    示例描述： 

    一个代码审查子代理，扫描文件并给出可读性、性能和最佳实践的改进建议。
它应该解释每个问题，展示当前代码，并提供改进版本。

    1. 选择工具访问（只读、全部、或自定义）
    2. 选择使用的模型（Sonnet、Opus、Haiku）
    3. 选择颜色（UI 标识）
    4. 配置持久记忆（可选）
    5. 保存并测试

    方式二：手动创建文件¶

    子代理是带 YAML frontmatter 的 Markdown 文件：

    # 项目级子代理
mkdir -p .claude/agents
touch .claude/agents/code-reviewer.md

# 个人级子代理
mkdir -p ~/.claude/agents
touch ~/.claude/agents/code-reviewer.md

    子代理文件结构¶

    ---
name: code-reviewer                                    # ⚠️ 必填
description: 审查代码并给出改进建议                       # ⚠️ 必填
model: sonnet                                          # 可选
tools: read                                            # 可选
disallowedTools: [Write, Edit]                         # 可选
permissionMode: default                                # 可选
maxTurns: 20                                           # 可选
skills: [code-style-guide]                             # 可选
---

你是一个代码审查专家。分析提供的代码并：

1. 指出潜在问题（Bug、边界情况、性能瓶颈）
2. 建议改进（可读性、设计模式、代码风格）
3. 引用相关的项目约定（参考 CLAUDE.md）
4. 对每个建议给出修改前后的代码对比

    Frontmatter 字段详解¶

    字段 必需 默认值 说明
    name ✅ — 唯一标识符，小写字母和连字符
    description ✅ — Claude 何时委派给此子代理。描述越清晰，自动委派越准确
    tools ❌ all（继承全部） 子代理可使用的工具
    disallowedTools ❌ [] 禁止的工具（从继承列表中移除）
    model ❌ inherit（继承主会话） 使用的模型
    permissionMode ❌ inherit 权限模式
    maxTurns ❌ 无限制 最大代理轮次
    skills ❌ [] 子代理启动时加载的 Skills
    mcpServers ❌ [] 子代理可用的 MCP 服务器
    isolation ❌ none 隔离级别：none 或 worktree

    tools 字段写法¶

    # 只读工具
tools: read

# 全部工具
tools: all

# 自定义列表
tools:
  - Read
  - Grep
  - Glob
  - Bash

    常用权限配置示例¶

    # 只读审查子代理
---
name: code-reviewer
description: 审查代码
tools: read
disallowedTools: [Write, Edit, Bash]
---

# 测试专用子代理（可以运行测试但不能修改生产代码）
---
name: test-runner
description: 运行和修复测试
tools:
  - Read
  - Grep
  - Bash
disallowedTools: [Write, Edit]
---

# 完整能力子代理（使用更便宜的模型）
---
name: quick-fix
description: 快速修复简单问题
model: haiku
---

    子代理作用域¶

    位置 作用域 优先级 如何创建
    Managed settings 组织级 1（最高） IT 部署
    --agents CLI 当前会话 2 claude --agents agents.json
    .claude/agents/ 当前项目 3 创建 .md 文件
    ~/.claude/agents/ 所有项目 4 创建 .md 文件
    插件的 agents/ 插件启用位置 5（最低） 安装插件

    同名子代理： 高优先级覆盖低优先级。

    工作模式¶

    1. Claude 自动委派¶

    Claude 根据子代理的 description 自动判断是否委派。

    # ✅ 好的描述 — 清晰、具体
description: 搜索和阅读代码库中的模式和依赖关系。当需要理解大型代码库的结构、找到特定实现、或分析模块间依赖时使用。

# ❌ 不好的描述 — 太模糊
description: 帮我查代码

    2. 手动委派¶

    在对话中直接要求使用：

    使用 code-reviewer 子代理审查 src/auth/ 目录

    3. Skill 中调用¶

    在 Skill 的 frontmatter 中设置 context: fork 让 Skill 在子代理中运行：

    ---
name: deploy
description: 部署应用到生产环境
context: fork
agent: deployer
---

    这样 Skill 的执行不会占用主会话的上下文。

    子代理与 Skills 结合¶

    子代理可以使用 Skills 来加载专业知识：

    ---
name: db-migrator
description: 管理和审查数据库迁移
model: sonnet
skills:
  - db-conventions    # 加载数据库约定
  - migration-guide   # 加载迁移指南
---

你是一个数据库迁移专家...

    示例子代理¶

    示例 1：代码审查子代理¶

    ---
name: code-reviewer
description: 审查代码变更，关注正确性、安全性和代码质量。当用户要求审查代码、检查代码质量、或提到 code review 时使用。
model: sonnet
tools:
  - Read
  - Grep
  - Glob
disallowedTools:
  - Write
  - Edit
  - Bash
---

你是一个经验丰富的代码审查专家。分析提供的代码变更并输出结构化审查报告：

## 🔍 审查报告

### 严重问题（必须修复）
- 列出 Bug、安全漏洞、数据丢失风险

### 改进建议（建议修复）
- 列出可读性问题、性能优化、设计改进

### 小建议（可选）
- 命名优化、格式调整

### ✅ 做得好的地方
- 列出代码中的亮点

对每个问题：
1. 说明问题所在
2. 解释为什么是问题
3. 提供修改建议（当前代码 → 建议代码）

    示例 2：测试专用子代理¶

    ---
name: test-runner
description: 运行测试套件并分析失败原因。当测试失败、需要调试、或需要编写新测试时使用。
model: haiku
tools:
  - Read
  - Grep
  - Glob
  - Bash
---

分析测试失败：

1. 运行测试并收集输出
   !`npm test 2>&1 | tail -100`

2. 定位失败的测试用例

3. 分析失败原因：
   - 是代码 Bug 还是测试问题？
   - 涉及哪些文件和函数？

4. 提供修复建议

5. 如果测试通过，报告覆盖率

    示例 3：文档生成子代理¶

    ---
name: doc-writer
description: 为代码模块生成技术文档。当用户要求写文档、生成注释、或提到 documentation 时使用。
model: sonnet
skills:
  - doc-template
---

为以下模块生成技术文档：

1. 读取模块代码
2. 理解函数关系和流程
3. 生成以下内容：
   - 模块概览
   - API 接口说明
   - 使用示例
   - 注意事项

    示例 4：安全审查子代理¶

    ---
name: security-reviewer
description: 安全专项审查，检查代码中的安全漏洞。当用户提到安全审查、安全审计、或 security review 时使用。
model: opus
tools:
  - Read
  - Grep
  - Glob
---

进行全面安全审查：

## 检查项

1. **输入验证**
   - SQL 注入风险
   - XSS 攻击风险
   - 命令注入漏洞

2. **认证与授权**
   - JWT 令牌安全性
   - 权限检查是否到位
   - 敏感操作是否需要认证

3. **数据安全**
   - 硬编码的密钥或凭证
   - 敏感数据是否加密
   - 日志中是否暴露敏感信息

4. **依赖安全**
   - 已知的漏洞依赖
   - 过期的依赖版本

## 报告格式

按严重程度（Critical/High/Medium/Low）分类，每个问题包含：
- 风险描述
- 涉及的文件和代码行
- 修复建议和示例代码

    持久化记忆¶

    子代理可以维护自己的持久化记忆目录，在跨会话时积累学习成果：

    ---
name: code-reviewer
description: 代码审查专家
---

    配置持久记忆后，子代理可以在 ~/.claude/agent-memory/ 中保存： - 发现的项目模式 - 反复出现的问题 - 用户的偏好

    这些知识会在后续会话中自动加载。
