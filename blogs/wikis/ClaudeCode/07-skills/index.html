    Claude Code 教程 07：Skills 扩展¶

    创建和管理 Skills 来扩展 Claude 的能力。包括自定义命令和打包的 Skill。

    官方文档参考： https://code.claude.com/docs/en/skills

    什么是 Skills？¶

    Skills 是扩展 Claude 能力的可复用指令包。创建一个包含指令的 SKILL.md 文件，Claude 会将其加入工具箱。

    Skills 的工作方式¶

    触发方式 说明 示例
    自动触发 Claude 根据你的描述自动判断何时使用 你说"部署代码"，Claude 自动调用 deploy skill
    手动调用 用 /skill-name 直接调用 输入 /deploy

    何时创建 Skill？¶

    场景 说明
    反复粘贴相同的指令 每次都要解释同样的流程 → 做成 Skill
    多步骤工作流 需要按顺序执行多个操作 → 做成 Skill
    CLAUDE.md 中某个部分太长 流程性内容而非事实性内容 → 移到 Skill
    团队需要统一流程 所有人执行相同的步骤 → 做成项目级 Skill

    💡 Anthropic 内部经验： 每天执行两次以上的任务就应该做成 Skill。

    Skills vs CLAUDE.md¶

    特性 CLAUDE.md Skills
    加载时机 每次会话启动时加载 仅在使用时加载
    上下文消耗 始终占用 Token 不用时不占 Token
    内容类型 事实、约定、规则 流程、步骤、模板
    调用方式 自动生效 自动匹配或手动 /name
    适合长度 建议 200 行以内 可以更长（因为按需加载）

    创建你的第一个 Skill¶

    示例：Git 变更摘要¶

    这个 Skill 会总结未提交的 Git 变更，并标记风险项。

    步骤 1：创建 Skill 目录¶

    # 个人级（所有项目可用）
mkdir -p ~/.claude/skills/summarize-changes

# 项目级（仅当前项目可用，团队共享）
mkdir -p .claude/skills/summarize-changes

    步骤 2：编写 SKILL.md¶

    ---
name: summarize-changes
description: 总结未提交的 Git 变更并标记风险。当用户询问改了什么、想要提交信息或要求审查 diff 时使用。
---

## 当前变更

!`git diff HEAD`

## 指令

用 2-3 个要点总结以上变更，然后列出你注意到的任何风险，例如：
- 缺少错误处理
- 硬编码的值
- 需要更新但没有更新的测试

如果 diff 为空，说明没有未提交的变更。

    步骤 3：测试¶

    cd your-git-project
claude

    # 方式一：让 Claude 自动调用
我改了什么？

# 方式二：手动调用
/summarize-changes

    Skill 存储位置¶

    位置 路径 适用范围 共享方式
    企业级 见 managed settings 组织内所有用户 IT 部署
    个人级 ~/.claude/skills/<名称>/SKILL.md 所有你的项目 仅自己
    项目级 .claude/skills/<名称>/SKILL.md 仅当前项目 通过 Git 共享
    插件级 <plugin>/skills/<名称>/SKILL.md 插件启用位置 安装插件

    同名优先级¶

    企业 > 个人 > 项目

    如果多个层级有同名 Skill，高优先级的覆盖低优先级的。

    自动发现¶

    Claude Code 会监控 Skill 目录的文件变更，无需重启会话即可生效：

    # 编辑已有的 Skill，当前会话立即生效
vim ~/.claude/skills/summarize-changes/SKILL.md

# 新增 Skill 到已存在的目录，当前会话自动发现
mkdir -p ~/.claude/skills/new-skill

    Monorepo 嵌套发现¶

    在 Monorepo 中，Claude 会自动发现子目录中的 Skills：

    my-monorepo/
├── .claude/skills/deploy/SKILL.md        ← 根目录 Skill
├── packages/
│   ├── frontend/
│   │   └── .claude/skills/build-fe/SKILL.md  ← 前端专属 Skill
│   └── backend/
│       └── .claude/skills/build-be/SKILL.md  ← 后端专属 Skill

    当你在 packages/frontend/ 中工作时，Claude 会发现 build-fe 和 deploy 两个 Skills。

    Frontmatter 配置¶

    SKILL.md 的 YAML frontmatter 控制 Skill 的行为：

    ---
name: deploy                    # 可选，默认使用目录名
description: 部署应用到生产环境    # ⚠️ 必填，Claude 据此判断何时自动调用
disable-model-invocation: true   # 可选，禁止 Claude 自动调用
context: fork                    # 可选，在子代理中运行
user-invocable: true             # 可选，允许用户手动调用
arguments: [environment, version] # 可选，声明接受的参数
model: claude-sonnet-4-6        # 可选，指定使用的模型
---

    各字段详解¶

    字段 类型 默认值 说明
    name string 目录名 Skill 名称（/ 后的命令名）
    description string 无 Claude 何时自动调用此 Skill。必填。
    disable-model-invocation bool false true 时 Claude 不会自动调用，只能手动 /name
    context string inline fork 表示在子代理中运行，不占主会话上下文
    user-invocable bool true false 时用户无法手动调用，仅 Claude 自动触发
    arguments array [] 声明 Skill 接受的参数名
    model string 当前模型 强制指定使用的模型
    paths array/string 无 Glob 模式，限定 Skill 只在特定文件类型下自动激活
    shell string bash Windows 上可设为 powershell

    调用控制矩阵¶

    配置 你能 /name 调用 Claude 能自动调用
    （默认，什么都不设） ✅ ✅
    disable-model-invocation: true ✅ ❌
    user-invocable: false ❌ ✅
    两者都设 ❌ ❌（Skill 基本没用）

    动态上下文注入¶

    Skill 可以使用特殊语法在 Claude 看到之前执行命令并注入结果。

    行内命令注入 !`command`¶

    ---
description: 审查代码变更
---

## 最近的提交

!`git log --oneline -5`

## 当前变更

!`git diff HEAD~5`

## 指令

审查以上代码变更，指出潜在问题。

    当用户调用 /code-review 时，Claude 看到的实际内容是：

    ## 最近的提交

a1b2c3d feat: 添加用户认证
e4f5g6h fix: 修复登录逻辑
...

## 当前变更

diff --git a/src/auth.ts b/src/auth.ts
...

## 指令

审查以上代码变更，指出潜在问题。

    参数系统¶

    声明参数¶

    ---
description: 修复 GitHub 问题
arguments:
  - issue      # 问题编号
  - branch     # 目标分支（可选）
---

    使用参数¶

    变量 说明 示例
    $ARGUMENTS 所有参数 /fix-issue 123 main → $ARGUMENTS = 123 main
    $ARGUMENTS[0] / $0 第一个参数 $0 = 123
    $ARGUMENTS[1] / $1 第二个参数 $1 = main
    $issue 按名称引用 $issue = 123
    $branch 按名称引用 $branch = main

    完整示例¶

    ---
name: fix-issue
description: 修复指定的 GitHub Issue
arguments: [issue, branch]
---

!`gh issue view $issue --repo $REPO`

## 任务

修复 Issue #$issue 在 $branch 分支上：

1. 阅读问题描述
2. 定位相关代码
3. 实现修复
4. 运行测试验证
5. 总结修改内容

    调用： 

    /fix-issue 42 fix/auth-bug

    位置参数简写¶

    ---
name: deploy
description: 部署应用
---

部署到环境 $0，版本 $1。

    调用： 

    /deploy production v2.3.1

    内置变量¶

    变量 说明
    ${CLAUDE_SESSION_ID} 当前会话 ID
    ${CLAUDE_SKILL_DIR} Skill 文件所在目录
    ${CLAUDE_PROJECT_DIR} 项目根目录

    打包辅助文件¶

    Skill 目录可以包含任意文件：

    security-review/
├── SKILL.md              # 主指令（必需）
├── checklist.md          # 安全检查清单
├── templates/
│   └── report.md         # 审查报告模板
├── examples/
│   └── sample-output.md  # 输出示例
└── scripts/
    └── scan.sh           # 自动化扫描脚本

    在 SKILL.md 中引用：

    ---
name: security-review
description: 安全审查
---

## 安全检查

参照以下清单进行审查：
@checklist.md

## 报告格式

按照以下模板输出报告：
@templates/report.md

## 运行扫描

执行自动化扫描：
!`bash ${CLAUDE_SKILL_DIR}/scripts/scan.sh`

## 输出示例

参考预期的输出格式：
@examples/sample-output.md

    💡 使用 @ 语法引用同目录文件。Claude 会读取这些文件作为 Skill 的一部分。

    内置 Skills¶

    Claude Code 自带以下内置 Skills：

    命令 功能 适用场景
    /simplify 简化代码，提升可读性 重构冗长函数
    /debug 系统化根因分析 定位难以复现的 bug
    /batch 并行执行相同任务 大批量重复性改动
    /loop 循环执行直到满足条件 自动化 CI 修复循环
    /claude-api 生成 API 调用示例代码 搭建 Claude API 集成原型

    内置命令 vs 内置 Skills 的区别¶

    类型 执行方式 速度 适用场景
    内置命令（如 /clear、/compact） 固定逻辑，不涉及 AI 极快 简单操作
    内置 Skills（如 /debug、/simplify） AI 推理执行 较慢但更智能 复杂分析任务

    自定义命令（旧格式，兼容）¶

    .claude/commands/ 中的 .md 文件仍然有效，工作方式与 Skills 相同：

    mkdir -p .claude/commands

    # .claude/commands/fix-issue.md
---
argument-hint: <issue-number>
---

!`gh issue view $ARGUMENTS`

调查并修复以上问题。

    如果 Skill 和 Command 同名，Skill 优先。

    建议：新项目使用 Skills 而非 Commands，因为 Skills 支持辅助文件、子代理执行等更多功能。

    实战示例¶

    示例 1：部署 Skill¶

    mkdir -p .claude/skills/deploy

    ---
name: deploy
description: 部署应用到指定环境
arguments: [environment]
---

## 部署流程

部署到 **$environment** 环境。按以下步骤执行：

1. 确认当前分支是 main
   !`git branch --show-current`

2. 运行测试
   !`npm test`

3. 构建
   !`npm run build`

4. 部署
   !`./scripts/deploy.sh $environment`

5. 验证部署
   !`curl -s https://$environment.example.com/health`

## 注意事项
- 只在 main 分支上部署
- 部署前确保测试全部通过
- production 环境需要确认

    调用： 

    /deploy staging
/deploy production

    示例 2：代码审查 Skill¶

    mkdir -p .claude/skills/code-review

    ---
name: code-review
description: 审查最近的代码变更
context: fork
---

## 变更内容

!`git diff HEAD~3`

## 审查清单 @checklist.md

1. 代码逻辑是否正确
2. 是否有边界情况未处理
3. 性能是否有问题
4. 是否符合项目约定
5. 测试是否充分

    示例 3：路径限定的 Skill¶

    ---
name: react-review
description: 审查 React 组件代码
paths:
  - "src/components/**/*.{ts,tsx}"
---

审查此 React 组件：

1. 组件是否正确使用了 Props 类型
2. 是否有不必要的重渲染
3. 是否正确使用了 Hooks 规则
4. 样式是否使用 Tailwind

    这个 Skill 只在 Claude 处理 src/components/ 下的 React 文件时自动激活。
