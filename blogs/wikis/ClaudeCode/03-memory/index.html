    Claude Code 教程 03：记忆系统¶

    通过 CLAUDE.md 文件给 Claude 持久指令，并通过 Auto Memory 让 Claude 自动积累学习。

    官方文档参考： https://code.claude.com/docs/en/memory

    两种记忆机制概览¶

    Claude Code 有两种互补的记忆系统，都在每次会话开始时加载：

    CLAUDE.md 文件 Auto Memory（自动记忆）
    谁写的 你（手动编写） Claude（自动积累）
    内容 指令、规则、约定 学习成果、模式、偏好
    范围 项目 / 用户 / 组织 每个工作树（working tree）
    加载时机 每次会话启动时 每次会话启动时（前 200 行 / 25KB）
    适用场景 编码标准、工作流、架构约定 构建命令、调试洞察、Claude 发现的偏好
    存储位置 多个位置（见下表） ~/.claude/ 或项目 .claude/ 中的 MEMORY.md

    CLAUDE.md 文件¶

    CLAUDE.md 是 Markdown 文件，包含你给 Claude 的持久指令。Claude 在每次会话开始时读取它，作为理解和执行任务的上下文。

    存放位置与作用域¶

    范围 路径 用途 共享对象
    组织策略 macOS: /Library/Application Support/ClaudeCode/CLAUDE.md
    Linux: /etc/claude-code/CLAUDE.md
    Windows: C:\Program Files\ClaudeCode\CLAUDE.md    		 IT/DevOps 管理的全公司级指令 组织内所有用户
    项目指令 ./CLAUDE.md 或 ./.claude/CLAUDE.md 团队共享的项目级指令 通过版本控制共享给团队成员
    用户指令 ~/.claude/CLAUDE.md 个人偏好，适用于所有项目 仅自己（所有项目）
    本地指令 ./CLAUDE.local.md 个人项目级偏好 仅自己（当前项目），应加入 .gitignore

    加载优先级： 越具体的位置优先级越高。组织策略 > 项目 > 本地 > 用户。

    什么时候该写 CLAUDE.md？¶

    当以下情况出现时，应该更新 CLAUDE.md：

    场景 示例
    Claude 重复犯错 第二次用了错误的 import 路径
    Code Review 发现问题 "你应该知道这个项目的约定"
    反复解释同一件事 每次都要说"用 2 空格缩进"
    新人需要相同上下文 新团队成员也需要这些背景知识

    编写有效指令的原则¶

    原则 1：控制在 200 行以内¶

    每个 CLAUDE.md 文件建议控制在 200 行以内。超长的文件会消耗更多上下文 Token，降低指令遵循率。

    如果指令超过 200 行，考虑： - 拆分为 .claude/rules/ 中的多个规则文件 - 将多步流程放入 Skill（见 07 - Skills 扩展） - 使用 @ 引用语法导入外部文件

    原则 2：使用清晰的结构¶

    # 好的结构
## 命令
## 技术栈
## 编码规范
## 测试约定
## 部署流程

    Claude 扫描结构化的指令比扫描大段文字更容易遵循。

    原则 3：指令必须具体可验证¶

    # ❌ 不好 — 太模糊
"正确格式化代码"
"测试你的改动"
"保持代码整洁"

# ✅ 好 — 具体可验证
"使用 2 空格缩进"
"提交前运行 `npm test`"
"函数名使用 camelCase，类名使用 PascalCase"

    原则 4：避免矛盾¶

    如果两个规则互相矛盾，Claude 可能随意选择一个。定期检查并清理：

    # ❌ 矛盾
"使用 2 空格缩进"
...
"使用 4 空格缩进"

# ✅ 统一
"所有代码使用 2 空格缩进"

    完整示例：TypeScript + React 项目¶

    # 项目约定

## 常用命令
- 开发: `npm run dev`
- 构建: `npm run build`
- 测试: `npm test`
- 测试覆盖率: `npm test -- --coverage`
- Lint: `npm run lint`
- 格式化: `npx prettier --write src/`

## 技术栈
- TypeScript 5.x（严格模式）
- React 19，仅使用函数式组件 + Hooks
- Next.js 15（App Router）
- Tailwind CSS 4
- Vitest 测试框架

## 目录结构
- `src/app/` — 页面和路由
- `src/components/` — 可复用 UI 组件
- `src/lib/` — 工具函数和业务逻辑
- `src/hooks/` — 自定义 React Hooks
- `src/types/` — TypeScript 类型定义

## 编码规范
- 使用命名导出（named exports），**禁止默认导出**
- 组件文件使用 PascalCase：`UserProfile.tsx`
- 工具文件使用 camelCase：`formatDate.ts`
- 测试文件与源码同级：`foo.ts` → `foo.test.ts`
- 所有 API 路由返回 `{ data, error }` 格式
- 使用 async/await，不使用 .then()

## 测试约定
- 每个组件至少有一个渲染测试
- 工具函数需要边界条件测试
- 使用 `describe()` 分组，`it()` 描述预期行为
- Mock 所有外部 API 调用

## Git 工作流
- 分支命名: `feature/xxx` / `fix/xxx` / `refactor/xxx`
- 提交信息使用 Conventional Commits: `feat:`, `fix:`, `chore:`
- 提交前必须通过 lint 和 test

    使用 /init 自动生成¶

    Claude Code 可以自动分析你的项目并生成初始的 CLAUDE.md：

    /init

    Claude 会： 1. 扫描项目结构 2. 识别使用的技术栈 3. 推断构建和测试命令 4. 生成一份初始 CLAUDE.md

    如果已存在 CLAUDE.md，/init 会建议改进而不是覆盖。

    交互式多阶段初始化（实验性）：

    # 启用交互式多阶段流程
export CLAUDE_CODE_NEW_INIT=1
claude
/init

    这会引导你设置： - CLAUDE.md 文件 - Skills - Hooks

    引用其他文件¶

    CLAUDE.md 可以使用 @path/to/import 语法引用其他文件：

    # CLAUDE.md

查看 @README.md 获取项目概览。
可用命令参考 @package.json 中的 scripts 部分。

## 额外指令
- Git 工作流 @docs/git-workflow.md
- API 规范 @docs/api-spec.md
- 部署流程 @docs/deployment.md

    规则： - 相对路径基于包含引用的文件所在目录解析 - 支持最多 5 层递归引用 - 被引用的文件也会在会话启动时加载到上下文中

    个人私有配置¶

    # 创建个人项目级配置（不提交到 Git）
touch CLAUDE.local.md
echo "CLAUDE.local.md" >> .gitignore

    # CLAUDE.local.md

## 我的个人偏好
- 调试时使用 console.log 而不是 debugger
- 本地开发数据库地址: localhost:5433
- 测试数据使用 fixtures/dev-data.json

    自动记忆（Auto Memory）¶

    Auto Memory 让 Claude 在工作过程中自动记录学习成果。

    Auto Memory 如何工作¶

    1. 你纠正了 Claude 的做法
    2. Claude 发现了项目中的模式
    3. Claude 将这些写入 MEMORY.md
    ~/.claude/
└── <project-hash>/
    └── MEMORY.md        ← Claude 自动写入的学习笔记

    查看和编辑自动记忆¶

    /memory

    在会话中使用 /memory 命令可以快速打开并编辑： - 项目的 CLAUDE.md - Claude 的自动记忆（MEMORY.md）

    配置 Auto Memory¶

    Claude 首次发现需要记忆的内容时自动创建 MEMORY.md。你可以通过 /memory 手动编辑或删除它。

    Auto Memory 记录的内容示例：

    # Auto Memory

## 项目模式
- 构建命令是 `npm run build:prod`，不是 `npm run build`
- 测试需要设置 NODE_ENV=test 环境变量

## 用户偏好
- 用户更喜欢用 pnpm 而不是 npm
- 用户要求所有修复都先写失败的测试

## 调试洞察
- auth 模块的错误通常在 middleware.ts 第 45 行
- 数据库连接池默认 10 个连接，高峰时需要调大

    使用 .claude/rules/ 组织规则¶

    对于大型项目，将规则按主题拆分到 .claude/rules/ 目录：

    .claude/
└── rules/
    ├── api.md           # API 开发规则
    ├── components.md    # 组件开发规则
    └── testing.md       # 测试编写规则

    无条件规则（始终加载）¶

    不带 paths 字段的规则无条件加载，适用于所有文件：

    # .claude/rules/general.md

# 通用规则
- 所有代码必须有注释
- 使用 TypeScript 严格模式
- 禁止使用 any 类型

    路径限定规则¶

    使用 YAML frontmatter 的 paths 字段限定只在特定文件类型下加载：

    # .claude/rules/api.md
---
paths:
  - "src/api/**/*.ts"
---

# API 开发规则

- 所有 API 端点必须包含输入验证
- 使用标准错误响应格式: `{ error: { code, message } }`
- 包含 OpenAPI/Swagger 文档注释
- 所有路由必须有对应的测试

    # .claude/rules/components.md
---
paths:
  - "src/components/**/*.{ts,tsx}"
---

# 组件开发规则

- 每个组件要有明确的 Props 类型
- 使用 React.memo 优化性能
- 样式使用 Tailwind CSS utility classes
- 导出组件时使用命名导出

    # .claude/rules/testing.md
---
paths:
  - "tests/**/*.test.ts"
  - "src/**/*.test.ts"
---

# 测试规则

- 使用 Vitest 框架
- 每个测试文件顶部 import 必要的 mock
- 测试描述使用 "should + 行为" 格式
- 覆盖率目标: 80% 行覆盖率

    支持的 Glob 模式¶

    模式 匹配
    **/*.ts 所有 TypeScript 文件
    src/**/* src/ 目录下所有文件
    *.md 项目根目录的 Markdown 文件
    src/components/*.tsx 特定目录下的 React 组件
    src/**/*.{ts,tsx} 使用花括号匹配多种扩展名
    lib/**/*.ts lib/ 目录下所有 TS 文件

    通过符号链接共享规则¶

    .claude/rules/ 目录支持符号链接，可以在多个项目间共享规则：

    # 创建共享规则目录
mkdir -p ~/shared-claude-rules

# 在项目中创建符号链接
ln -s ~/shared-claude-rules .claude/rules/shared
ln -s ~/company-standards/security.md .claude/rules/security.md

    用户级规则¶

    ~/.claude/rules/ 中的规则适用于所有项目：

    ~/.claude/rules/
├── preferences.md     # 个人编码偏好
└── workflows.md       # 偏好的工作流

    # ~/.claude/rules/preferences.md

# 我的个人偏好
- 始终使用中文注释
- 变量名使用英文，注释用中文
- 优先使用函数式编程风格
- 不喜欢过多的 console.log，调试完要删掉

    加载顺序： 用户级规则在项目的规则之前加载，因此项目规则优先级更高。

    大型团队的 CLAUDE.md 管理¶

    部署组织级 CLAUDE.md¶

    组织可以通过集中管理的方式部署 CLAUDE.md 到所有开发者的机器上：

    平台 路径
    macOS /Library/Application Support/ClaudeCode/CLAUDE.md
    Linux / WSL /etc/claude-code/CLAUDE.md
    Windows C:\Program Files\ClaudeCode\CLAUDE.md

    使用 MDM、Group Policy、Ansible 等工具分发。

    组织级 CLAUDE.md 不能被个人设置排除，适用于： - 公司编码标准 - 安全策略 - 合规要求

    使用 claudeMdExcludes 排除不需要的文件¶

    在 Monorepo 中，可以用 claudeMdExcludes 跳过其他团队的不相关 CLAUDE.md：

    {
  "claudeMdExcludes": [
    "packages/other-team/CLAUDE.md",
    "**/vendor/CLAUDE.md"
  ]
}

    常见问题¶

    CLAUDE.md 没有被遵循？¶

    排查清单：

    1. 文件太长 — 超过 200 行会降低遵循率

    2. 解决： 拆分为 .claude/rules/ 中的规则文件

    3. 指令矛盾 — 不同层级的 CLAUDE.md 冲突

    4. 解决： 检查用户级、项目级、本地级文件，移除矛盾规则

    5. 太笼统 — 指令不够具体

    6. 解决： "代码要整洁" → "使用 2 空格缩进，函数不超过 30 行"

    7. 加载问题 — 确认文件在正确的位置

    8. 解决： 运行 /memory 查看加载的指令文件

    指令太多怎么办？¶

    内容类型 存放位置
    项目通用约定 CLAUDE.md
    特定文件类型的规则 .claude/rules/api.md（使用 paths 限定）
    多步骤流程 .claude/skills/deploy/SKILL.md（Skill）
    个人偏好 CLAUDE.local.md 或 ~/.claude/CLAUDE.md
    自动化脚本 .claude/hooks/ 目录
