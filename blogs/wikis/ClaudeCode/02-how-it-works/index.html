    Claude Code 教程 02：工作原理¶

    理解 Claude Code 的核心架构：代理循环（Agentic Loop）、内置工具能力、以及 Claude 与项目的交互方式。

    官方文档参考： https://code.claude.com/docs/en/how-claude-code-works

    代理循环（The Agentic Loop）¶

    这是 Claude Code 的核心工作机制。当你给 Claude 一个任务，它会经历三个阶段：

    你的提示 → 收集上下文 → 采取行动 → 验证结果 →（循环直到完成）
                            ↑_______________|

    这三个阶段不是线性的——它们交织在一起。Claude 会持续使用各种工具：搜索文件理解代码、编辑修改、运行测试验证。

    代理循环的三个阶段¶

    阶段 Claude 在做什么 使用的工具示例
    收集上下文 阅读代码、搜索文件、理解结构 Read、Grep、Glob
    采取行动 编辑文件、运行命令、创建新文件 Edit、Write、Bash
    验证结果 运行测试、检查输出、确认修改 Bash(npm test)、Read

    实际运行示例¶

    你说："修复登录失败的 Bug"

    Claude 的代理循环过程：

    循环 1：收集上下文
  ├─ Grep 搜索 "login" 相关文件
  ├─ Read 读取 src/auth/login.ts
  └─ Read 读取 src/api/auth.ts

循环 2：采取行动
  ├─ Edit 修改 login.ts 中的错误处理逻辑
  └─ Write 创建新的测试用例

循环 3：验证结果
  ├─ Bash 运行 npm test -- login
  └─ 发现新测试通过，但旧测试失败

循环 4：修正
  ├─ Read 读取失败的测试输出
  ├─ Edit 调整修改以避免破坏原有功能
  └─ Bash 再次运行 npm test

循环 5：完成
  └─ 所有测试通过，向你报告修复结果

    代理循环的三个关键特性¶

    1. 自适应 — 简单问题可能只需要 1-2 个循环；复杂 Bug 可能需要 10+ 个循环
    2. 链式行动 — Claude 可以将数十个操作串联，并根据前一步结果调整下一步
    3. 人在环中 — 你可以随时中断 Claude，改变方向或提供额外信息

    内置工具分类¶

    Claude Code 拥有多种内置工具，分为五大类：

    1. 文件操作¶

    工具 功能 示例场景
    Read 读取文件内容 查看源代码、配置文件
    Edit 编辑文件（精确替换） 修改函数逻辑、修复 Bug
    Write 创建或覆盖文件 新建测试文件、生成文档
    MultiEdit 同一文件多次编辑 重构一个文件的多个位置

    实际示例：

    # 你：读取文件
> 查看 src/utils/helpers.ts 的内容

# Claude 使用 Read 工具后返回内容摘要
# 然后你让它修改
> 把 formatDate 函数改为使用 date-fns 库

# Claude 使用 Edit 工具：
# - 定位原函数代码
# - 精确替换为新实现
# - 请求你确认 diff

    2. 搜索¶

    工具 功能 示例
    Grep 正则搜索文件内容 Grep("login.*password", src/)
    Glob 按模式匹配文件名 Glob("**/*.test.ts")
    LS 列出目录内容 LS(src/api/)

    实际示例：

    # 你：查找所有使用 axios 的地方
> 项目中哪些文件用了 axios？

# Claude 使用 Grep 搜索
Grep("import.*axios|require.*axios", .)
→ 找到 12 个匹配，分布在 5 个文件中

    3. 执行¶

    工具 功能 示例
    Bash 运行 Shell 命令 npm test、git status
    BashOutput 查看后台命令输出 查看长时间运行的日志
    KillShell 终止后台命令 停止卡住的进程

    实际示例：

    # 你：运行测试
> 跑一下单元测试

# Claude 使用 Bash 工具
Bash("npm test -- --coverage")
→ 读取输出
→ 分析结果
→ 向你报告：23 个通过，2 个失败

    4. Web¶

    工具 功能 示例
    WebFetch 抓取网页内容 获取 API 文档、查看错误 StackOverflow 回答
    WebSearch 搜索互联网 查找最新库的使用方法

    实际示例：

    # 你：这个错误怎么解决？
> TypeError: Cannot read properties of undefined (reading 'map')

# Claude 使用 WebSearch 查找解决方案
→ 找到相关 StackOverflow 回答
→ 结合你的代码给出修复建议

    5. 代码智能¶

    需要安装代码智能插件后才可用：

    能力 功能
    类型检查 编辑后自动查看 TypeScript 类型错误
    跳转到定义 找到函数/变量的定义位置
    查找引用 找到某处代码的所有使用位置

    Claude 可以访问什么？¶

    在项目目录中运行 claude 后，Claude 获得以下访问能力：

    资源 说明 实际意义
    项目文件 当前目录及子目录中的所有文件 可以读取、搜索、修改任何文件
    终端 任何你能在命令行执行的命令 构建、测试、安装依赖、Git 操作
    Git 状态 当前分支、未提交变更、最近提交 了解项目变更历史
    CLAUDE.md 项目级指令文件 每次会话自动加载你的约定
    Auto Memory Claude 自动积累的学习笔记 记住你的偏好和项目模式
    扩展 MCP 服务器、Skills、子代理 连接外部工具、自定义工作流

    执行环境¶

    环境 代码运行位置 适用场景 示例
    本地（Local） 你的机器 日常开发，完全访问本地环境 claude 在项目中启动
    云端（Cloud） Anthropic 托管 VM 处理没有本地克隆的仓库 快速查看陌生项目
    远程控制 你的机器，浏览器控制 远程办公时操作本地开发环境 从 iPad 控制办公室电脑

    高效使用 Claude Code 的 7 个技巧¶

    技巧 1：像对话一样迭代¶

    不需要一次性写出完美的提示。先说大方向，然后迭代细化：

    第一轮：修复登录 Bug

（Claude 调查后给出方案）

第二轮：方向不对，问题出在 Session 处理上

（Claude 调整方案）

第三轮：好多了，但还需要处理 Token 过期的情况

（Claude 最终给出完整修复）

    💡 不要怕第一次不完美——迭代是正常的。

    技巧 2：在提示中包含具体细节¶

    越精确的初始提示，需要的纠正越少：

    ❌ 模糊的提示：
"修复结账的问题"

✅ 精确的提示：
"过期卡用户的结账流程已损坏。
检查 src/payments/，特别是 Token 刷新逻辑。
先写一个失败的测试，再修复它。"

    技巧 3：给 Claude 验证标准¶

    Claude 在有明确验证标准时表现更好：

    实现 validateEmail 函数。
测试用例：
  - 'user@example.com' → true
  - 'invalid' → false
  - 'user@.com' → false
完成后运行测试验证。

    实现用户头像上传功能。
验收标准：
  1. 支持 JPG/PNG/GIF 格式
  2. 文件大小限制 5MB
  3. 上传后返回 URL
  4. 参考 @src/components/avatar.tsx 的现有实现风格

    技巧 4：先探索，再实现¶

    面对复杂问题时，先用 Plan 模式（Shift+Tab 两次）进行探索：

    阅读 src/auth/ 目录，理解我们当前的 Session 处理方式。
然后制定一个添加 OAuth 支持的方案。

    审查方案后，再让 Claude 实施：

    方案可以，开始实施。先写测试，再实现功能。

    技巧 5：委派，而非指挥¶

    把 Claude 当成能干的同事。给出上下文和方向，信任它自己搞定细节：

    ❌ 过度指挥：
"打开 src/payments/checkout.ts，找到第 45 行，
把 if 语句改为 switch，然后添加一个 case..."

✅ 有效委派：
"过期卡用户的结账流程有问题。
相关代码在 src/payments/。请调查并修复。"

    技巧 6：使用 @ 注入关键文件¶

    当你想让 Claude 参考特定文件时：

    参考 @docs/api-spec.md 来实现新的用户接口。
已有的实现在 @src/api/users.ts。

    对比 @src/auth/v1.ts 和 @src/auth/v2.ts 的实现差异，
告诉我 v2 改进了什么。

    技巧 7：用 ! 快速执行命令¶

    不需要让 Claude 来执行简单命令时：

    > !git log --oneline -10
> !npm test -- --coverage 2>&1 | tail -30
> !find . -name "*.log" -mtime +7 -delete

    会话管理¶

    保存与恢复¶

    Claude Code 自动保存每次会话：

    # 继续最近一次对话
claude -c

# 选择历史会话恢复
claude -r

# 或在会话内部
/resume

    会话存储位置¶

    ~/.claude/projects/
└── <project-hash>/
    └── <session-id>.jsonl

    每次会话的消息、工具调用、结果都保存为 JSONL 文件。

    跨分支工作¶

    Claude Code 会话绑定到当前目录。切换分支时：

    • Claude 看到新分支的文件
    • 对话历史保持不变
    • 可以继续在同一个会话中讨论不同分支的代码
