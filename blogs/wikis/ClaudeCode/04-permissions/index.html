    Claude Code 教程 04：权限系统¶

    通过细粒度的权限规则、模式和策略，精确控制 Claude Code 可以访问什么、能做什么。

    官方文档参考： https://code.claude.com/docs/en/permissions

    为什么需要权限系统？¶

    Claude Code 可以直接修改你的文件、运行 Shell 命令。权限系统确保它在你的控制范围内工作——既不会意外破坏文件，也不会执行危险命令。

    权限体系概览¶

    Claude Code 使用分层权限系统来平衡能力与安全性：

    工具类型 示例 需要批准？ "是，不再询问"的行为
    只读 文件读取、Grep、Glob ❌ 不需要 不适用
    Bash 命令 Shell 执行 ✅ 需要 按项目目录和命令永久记住
    文件修改 编辑/写入文件 ✅ 需要 会话结束前有效

    权限规则的三种类型¶

    使用 /permissions 查看和管理所有权限规则：

    类型 效果 优先级
    Allow 允许 Claude 使用指定工具，无需手动批准 低
    Ask 使用指定工具时弹出确认提示 中
    Deny 禁止 Claude 使用指定工具 高

    规则优先级：Deny → Ask → Allow。拒绝规则始终优先。

    这意味着即使你有一条 Allow 规则允许所有 Bash 命令，只要有一条 Deny 规则禁止 rm -rf *，rm -rf 仍然会被阻止。

    权限模式¶

    Claude Code 支持多种权限模式，控制工具如何被批准。在 settings.json 中通过 defaultMode 设置，或使用 /permissions 交互切换。

    模式 描述 适用场景
    default 标准行为：首次使用每个工具时提示权限 日常使用，最安全
    acceptEdits 自动接受文件编辑和工作目录内的常见文件系统命令（mkdir、touch、mv、cp 等） 信任 Claude 的修改能力时
    plan Plan 模式：Claude 仅读取文件和运行只读命令进行探索，不编辑源文件 分析代码、制定方案时
    auto 自动批准工具调用，后台安全检查验证操作是否符合你的请求 研究预览阶段，高风险高回报
    dontAsk 自动拒绝工具，除非通过 /permissions 或 permissions.allow 预先批准 高度受控环境
    bypassPermissions 跳过所有权限提示（rm -rf / 和 rm -rf ~ 仍会提示） 容器/VM 等隔离环境

    切换权限模式¶

    # 在会话中交互切换
/permissions

# 启动时指定模式
claude --permission-mode plan
claude --permission-mode acceptEdits

    ⚠️ bypassPermissions 警告¶

    此模式跳过所有权限提示，包括对 .git、.claude、.vscode、.idea、.husky 等目录的写入。rm -rf / 和 rm -rf ~ 仍会提示作为断路器。

    仅在隔离环境（容器、VM）中使用。 管理员可以通过设置 permissions.disableBypassPermissionsMode: "disable" 来禁止此模式。

    {
  "permissions": {
    "disableBypassPermissionsMode": "disable",
    "disableAutoMode": "disable"
  }
}

    权限规则语法¶

    权限规则遵循格式：Tool 或 Tool(specifier)

    匹配工具的所有使用¶

    只用工具名，不加括号：

    "Bash"       // 匹配所有 Bash 命令
"Read"       // 匹配所有文件读取
"Edit"       // 匹配所有文件编辑
"Write"      // 匹配所有文件写入
"WebFetch"   // 匹配所有网页抓取
"Glob"       // 匹配所有文件匹配
"Grep"       // 匹配所有内容搜索

    Bash(*) 等价于 Bash。

    使用说明符精确匹配¶

    "Bash(npm run build)"             // 精确匹配命令
"Bash(npm test)"                  // 精确匹配 npm test
"Read(./.env)"                    // 匹配读取 .env 文件
"Read(./src/config.ts)"           // 匹配读取特定文件
"Edit(./src/auth/login.ts)"       // 匹配编辑特定文件
"WebFetch(domain:example.com)"   // 匹配对 example.com 的抓取

    通配符模式¶

    Bash 规则支持 * 通配符，可以出现在任何位置：

    {
  "permissions": {
    "allow": [
      "Bash(npm run *)",           // 所有 npm run 子命令
      "Bash(npm test *)",          // npm test 及其参数
      "Bash(git commit *)",        // git commit 相关
      "Bash(git * main)",          // git checkout main, git merge main 等
      "Bash(* --version)",         // 所有 --version 命令
      "Bash(* --help *)",          // 所有 --help 命令
      "Bash(ls *)",                // ls 及其参数
      "Bash(cat *)",               // cat 及其参数
      "Bash(grep * package.json)"  // 在 package.json 中搜索
    ],
    "deny": [
      "Bash(rm -rf *)",            // 禁止 rm -rf
      "Bash(git push *)",          // 禁止 git push
      "Bash(* --force *)",         // 禁止带 --force 的命令
      "Bash(sudo *)"               // 禁止 sudo
    ]
  }
}

    空格与通配符的关键区别¶

    "Bash(ls *)"    // 匹配 ls -la，但**不匹配** lsof（空格强制单词边界）
"Bash(ls*)"     // 匹配 ls -la **也匹配** lsof（无边界约束）
"Bash(git:*)"   // 等价于 "Bash(git *)"，末尾的 :* 是通配符简写

    只读命令（无需提示）¶

    以下命令在任何模式下都自动执行，无需权限提示：

    ls, cat, head, tail, grep, find, wc, diff, stat, du, cd
以及只读形式的 git 命令（git status, git log, git diff 等）

    Settings 文件层级¶

    权限配置保存在 settings 文件中，有四个层级：

    文件 范围 提交到 Git？
    组织策略文件 IT 管理的系统级配置 —
    ~/.claude/settings.json 全局（所有项目） 否
    .claude/settings.json 当前项目（团队共享） 是
    .claude/settings.local.json 当前项目的个人覆盖 否（自动 gitignore）

    层级优先级： 组织策略 > CLI 参数 > 项目 > 全局 > 本地

    数组设置的合并行为¶

    • 数组设置（如 permissions.allow）：跨层级合并（并集）
    • 标量设置（如 model、defaultMode）：使用最具体的值（覆盖）

    示例：项目 settings.json¶

    {
  "permissions": {
    "allow": [
      "Bash(npm test *)",
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push *)",
      "Bash(sudo *)"
    ]
  },
  "env": {
    "NODE_ENV": "development"
  },
  "model": "claude-sonnet-4-6"
}

    示例：本地 settings.local.json¶

    {
  "permissions": {
    "allow": [
      "Bash(docker *)",
      "Bash(docker-compose *)"
    ]
  }
}

    这个本地文件在 permissions.allow 数组中添加了 Docker 权限，不会覆盖项目级设置。

    实战示例¶

    示例 1：允许所有 npm 命令，但禁止 npm publish¶

    {
  "permissions": {
    "allow": [
      "Bash(npm *)"
    ],
    "deny": [
      "Bash(npm publish *)",
      "Bash(npm unpublish *)"
    ]
  }
}

    注意 Deny 优先：npm install、npm run build、npm test 都会被 Allow 放行，但 npm publish 会被 Deny 阻止。

    示例 2：允许 Git 操作，但禁止 Push¶

    {
  "permissions": {
    "allow": [
      "Bash(git add *)",
      "Bash(git commit *)",
      "Bash(git checkout *)",
      "Bash(git merge *)",
      "Bash(git status)",
      "Bash(git log *)",
      "Bash(git diff *)"
    ],
    "deny": [
      "Bash(git push *)",
      "Bash(git force *)",
      "Bash(git reset --hard *)"
    ]
  }
}

    示例 3：允许读取特定目录，禁止访问敏感文件¶

    {
  "permissions": {
    "allow": [
      "Read(src/**)",
      "Read(tests/**)",
      "Read(docs/**)"
    ],
    "deny": [
      "Read(.env*)",
      "Read(**/secrets.*)",
      "Read(**/*.key)"
    ]
  }
}

    示例 4：限制 WebFetch 域名¶

    {
  "permissions": {
    "allow": [
      "WebFetch(domain:github.com)",
      "WebFetch(domain:stackoverflow.com)",
      "WebFetch(domain:docs.anthropic.com)"
    ],
    "deny": [
      "WebFetch(domain:*) "
    ]
  }
}

    复合命令处理¶

    Claude Code 能识别 Shell 操作符（&&、||、;、|、|&、& 和换行符）。

    git status && npm test

    这个复合命令中：

    • Bash(git status *) 规则不会给你执行 npm test 的权限
    • 你需要分别为每个子命令设置权限

    当你用"是，不再询问"批准复合命令时，Claude 会分别保存每个子命令的规则：

    // 批准 "git status && npm test" 后自动保存：
"permissions": {
  "allow": [
    "Bash(git status)",
    "Bash(npm test *)"
  ]
}

    最多保存 5 条规则（对应最多 5 个子命令）。

    环境变量包装器剥离¶

    Claude Code 在匹配 Bash 规则前会剥离一组固定的环境变量包装器：

    timeout 30 npm test      → 匹配 Bash(npm test *)
time npm run build       → 匹配 Bash(npm run build *)
nice -10 npm test        → 匹配 Bash(npm test *)
nohup npm test           → 匹配 Bash(npm test *)
xargs grep pattern       → 匹配 Bash(grep pattern)  (bare xargs 无标志)

    不被剥离的 Runner：

    • direnv exec、devbox run、mise exec、npx、docker exec

    这些需要写完整的规则：

    "allow": [
  "Bash(devbox run npm test)",
  "Bash(npx jest *)"
]

    始终提示的特殊命令： watch、setsid、ionice、flock 以及 find -exec/find -delete 始终提示，无法通过前缀规则自动批准。

    工具级权限¶

    MCP 服务器工具¶

    {
  "permissions": {
    "allow": [
      "mcp__github__create_issue",
      "mcp__github__list_issues",
      "mcp__github__get_pull_request"
    ],
    "deny": [
      "mcp__github__delete_repository",
      "mcp__github__force_push"
    ]
  }
}

    通配符语法：

    "mcp__puppeteer__*"       // 匹配 puppeteer 服务器的所有工具
"mcp__puppeteer__navigate" // 精确匹配特定工具

    子代理权限¶

    {
  "permissions": {
    "deny": [
      "Agent(Explore)"        // 禁止 Explore 子代理
    ]
  }
}

    或使用 CLI 参数：

    claude --disallowedTools "Agent(Explore)"

    工作目录与权限¶

    默认访问范围¶

    Claude 默认可以访问启动时所在的目录及其子目录。

    扩展访问¶

    # 启动时添加额外目录
claude --add-dir ../shared-lib

# 会话中添加
/add-dir ../another-dir

# settings.json 中持久配置
{
  "additionalDirectories": ["../shared-lib", "../common"]
}

    额外目录的权限行为¶

    添加到额外目录后：

    • 目录中的文件变为可读，无需提示
    • 文件编辑权限遵循当前权限模式
    • 不会从额外目录中发现 .claude/ 配置（但有少数例外，如 Skills）
