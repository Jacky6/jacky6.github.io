    远程协作¶

    与团队协同：远程仓库、推送、拉取、Pull Request 工作流。

    1. 远程仓库管理¶

    # 查看远程仓库
git remote
git remote -v          # 显示 URL

# 添加远程仓库
git remote add origin https://github.com/user/repo.git
git remote add upstream https://github.com/other/repo.git

# 修改远程 URL
git remote set-url origin https://github.com/user/new-repo.git

# 重命名远程
git remote rename origin github

# 删除远程
git remote remove origin

# 查看远程仓库详细信息
git remote show origin

    2. Fetch、Pull、Push¶

    Fetch（抓取）¶

    # 抓取所有远程更新（不合并）
git fetch

# 抓取指定远程仓库
git fetch origin

# 抓取并清理已删除的远程分支
git fetch --prune

# 查看所有远程分支
git branch -r

    fetch 只下载不合并，是安全的。它会更新 origin/* 远程跟踪分支。

    Pull（拉取）¶

    # 拉取并合并（fetch + merge）
git pull origin main

# 拉取并变基（fetch + rebase）
git pull --rebase origin main

# 配置默认 pull 使用 rebase
git config --global pull.rebase true

    Push（推送）¶

    # 推送到远程（首次需要指定分支）
git push origin main

# 设置上游分支并推送
git push -u origin main
# 之后直接 git push 即可

# 推送所有分支
git push --all origin

# 推送所有标签
git push --tags origin

# 强制推送（⚠️ 会覆盖远程历史）
git push --force origin main
git push -f origin main

# 安全强制推送（仅在远程没有新提交时才覆盖）
git push --force-with-lease origin main

# 删除远程分支
git push origin --delete feature-old
# 等价于
git push origin :feature-old

    3. 分支追踪¶

    # 查看分支追踪关系
git branch -vv

# 设置追踪关系
git branch -u origin/main

# 新建分支并追踪远程
git checkout -b dev origin/dev

# 推送并自动设置追踪
git push -u origin feature

    4. 典型协作工作流¶

    Fork 工作流（开源项目）¶

    你的 Fork (GitHub)         上游仓库 (GitHub)
     │                          │
     ↓ clone                    │
本地仓库                        │
     │                          │
     ├── 开发、commit            │
     ├── push 到你的 Fork        │
     └── 发起 Pull Request ────→ 审查、合并

    # 1. Fork 后克隆自己的仓库
git clone https://github.com/yourname/repo.git
cd repo

# 2. 添加上游仓库
git remote add upstream https://github.com/original/repo.git

# 3. 保持同步上游
git fetch upstream
git checkout main
git merge upstream/main

# 4. 创建特性分支开发
git checkout -b feature/xxx
# ... 开发 ...
git push origin feature/xxx

# 5. 在 GitHub 发起 PR

    团队协作工作流¶

    main (保护分支)
  ↑ merge PR
  │
feature/xxx (开发者 A)    feature/yyy (开发者 B)
  │                         │
  push to origin ───────→  PR → Review → Merge

    5. 冲突处理¶

    # 推送时远程有新提交
git push
# ! [rejected] main -> main (fetch first)

# 先拉取再推送
git pull --rebase origin main    # 推荐：保持线性历史
# 或
git pull origin main              # 合并模式

# 解决冲突后
git add .
git rebase --continue             # 如果用了 rebase
git commit                        # 如果用了 merge
git push origin main

    6. 多远程仓库¶

    # 添加多个远程
git remote add origin git@github.com:user/repo.git
git remote add gitee git@gitee.com:user/repo.git

# 推送到不同远程
git push origin main
git push gitee main

# 从不同远程拉取
git pull origin main
git pull gitee main
