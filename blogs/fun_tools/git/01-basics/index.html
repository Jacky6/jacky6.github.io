    Git 基础操作¶

    从零开始：初始化仓库、配置身份、日常提交、查看历史。

    1. 配置 Git¶

    安装 Git 后，第一件事是设置身份：

    # 全局配置（所有仓库通用）
git config --global user.name "你的名字"
git config --global user.email "your@email.com"

# 仅当前仓库生效
git config user.name "仓库专用名"
git config user.email "repo@email.com"

# 设置默认编辑器
git config --global core.editor vim

# 设置默认分支名
git config --global init.defaultBranch main

# 查看当前配置
git config --list              # 所有配置
git config user.name           # 单个配置

    配置文件优先级（从高到低）：

    级别 文件路径 说明
    仓库级 .git/config 仅当前仓库
    全局级 ~/.gitconfig 当前用户所有仓库
    系统级 /etc/gitconfig 系统所有用户

    2. 初始化与克隆¶

    # 在现有目录初始化
cd my-project
git init

# 克隆远程仓库（自动创建目录）
git clone https://github.com/user/repo.git

# 克隆到指定目录
git clone https://github.com/user/repo.git my-folder

# 克隆并指定分支
git clone -b dev https://github.com/user/repo.git

    3. 工作区、暂存区、仓库¶

    Git 的三个区域是理解一切操作的基础：

    ┌──────────────┐     add      ┌──────────────┐    commit    ┌──────────────┐
│   工作区      │ ──────────→ │   暂存区       │ ──────────→ │   本地仓库    │
│ Working Tree │              │  Staging Area │             │  Repository  │
│              │ ←─────────── │               │ ←────────── │               │
│  你编辑的文件  │    restore   │  git rm --cached│    reset    │  完整历史记录  │
└──────────────┘              └──────────────┘             └──────────────┘
    • 工作区：你实际看到的文件目录
    • 暂存区：准备提交的"购物车"，决定下次提交包含哪些改动
    • 本地仓库：完整的历史记录，每次 commit 保存一个快照

    4. 查看状态¶

    # 简洁状态（最常用）
git status -s

# 详细状态
git status

    状态符号速查：

    符号 含义 示例
    ?? 未跟踪（新文件） 刚创建的文件
    A 已暂存（新增） git add 后的新文件
    M 已修改 暂存区或工作区有改动
    D 已删除 文件被删除
    R 已重命名 文件被重命名
    C 已复制 文件被复制
    U 未合并（冲突） merge/rebase 后

    git status -s 输出示例：

     M README.md          # 工作区修改，未暂存
M  src/main.py        # 已暂存，工作区还有新修改
MM src/utils.py       # 暂存区和工作区都有修改
?? new_file.txt       # 未跟踪
D  old_file.txt       # 已删除（暂存区）

    5. 添加到暂存区¶

    # 添加所有改动（含新建、修改、删除）
git add .

# 添加所有改动（不含未跟踪的新文件）
git add -u

# 交互式选择（逐个文件确认）
git add -p

# 添加指定文件/目录
git add src/main.py
git add src/

# 添加所有 .py 文件
git add "*.py"

    6. 提交¶

    # 基本提交
git commit -m "feat: add user login"

# 跳过暂存区，直接提交所有已跟踪文件的修改
git commit -am "fix: correct typo"

# 修改最后一次提交（合并到上一次 commit）
git commit --amend

# 修改提交信息但不改动内容
git commit --amend -m "new message"

# 空提交（常用于触发 CI）
git commit --allow-empty -m "trigger CI"

    注意：--amend 会改变 commit hash，如果已经 push 到共享分支，需要 push --force。

    提交信息规范（Conventional Commits）¶

    <type>(<scope>): <subject>

<body>

<footer>

    常用 type：

    type 说明 示例
    feat 新功能 feat: add search API
    fix 修复 bug fix: handle null input
    docs 文档 docs: update README
    style 格式（不影响代码逻辑） style: format with black
    refactor 重构 refactor: simplify auth logic
    test 测试 test: add login tests
    chore 杂项 chore: update dependencies
    perf 性能优化 perf: optimize query
    ci CI 配置 ci: add github actions

    7. 查看差异¶

    # 工作区 vs 暂存区
git diff

# 工作区 vs 暂存区（指定文件）
git diff src/main.py

# 暂存区 vs 上次提交
git diff --cached

# 工作区 vs 上次提交
git diff HEAD

# 两次提交之间
git diff commit1..commit2

# 两个分支之间
git diff main..feature

# 只查看文件名（不显示具体内容）
git diff --name-only

# 查看改动统计
git diff --stat

    8. 查看历史¶

    # 基本日志
git log

# 单行简洁模式
git log --oneline

# 图形化分支历史
git log --oneline --graph --all

# 查看指定文件的历史
git log --follow -- src/main.py

# 搜索提交信息
git log --grep="fix bug"

# 搜索代码内容
git log -S"function_name"

# 查看某人的提交
git log --author="xiaozhi"

# 时间范围
git log --after="2024-01-01" --before="2024-06-01"

# 最近 N 次提交
git log -5

# 查看每次提交的具体改动
git log -p

# 统计每个人的提交数
git shortlog -sn

    常用格式化别名（加入 ~/.gitconfig）：

    [alias]
    lg = log --oneline --graph --all --decorate
    last = log -1 HEAD --stat

    9. 删除文件¶

    # 删除文件（同时从工作区和仓库删除）
git rm file.txt

# 仅从仓库删除，保留工作区文件（用于 .gitignore 后）
git rm --cached file.txt

# 递归删除目录
git rm -r dir/

    10. 移动/重命名文件¶

    # 重命名文件
git mv old_name.txt new_name.txt

# 等同于：
# mv old_name.txt new_name.txt
# git rm old_name.txt
# git add new_name.txt
