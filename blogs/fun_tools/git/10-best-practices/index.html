    最佳实践¶

    让 Git 成为你的助力而不是负担。

    1. 提交习惯¶

    小步提交¶

    ❌ 一次 commit 改了 20 个文件，包含了新功能、重构、修 bug
✅ 每个 commit 只做一件事，提交信息清晰描述改动

    好处： - 容易 code review - 容易 cherry-pick - 容易 revert 单个功能 - 用 git bisect 定位 bug 更精确

    有意义的提交信息¶

    ❌ "update" / "fix" / "..."
✅ "fix: handle null email in registration form"
✅ "feat: add pagination to search results"

    频繁提交，适时推送¶

    # 本地可以频繁 commit（甚至写给自己看的）
git commit -m "wip: trying approach A"
git commit -m "wip: approach A didn't work, try B"

# 推送到共享分支前整理历史
git rebase -i main
# squash wip commits, reword messages
git push origin feature

    2. 分支策略¶

    分支命名¶

    feature/user-auth
bugfix/login-crash
hotfix/security-patch
release/v2.1.0

    分支生命周期¶

    创建 → 开发 → PR/MR → Review → 合并 → 删除
    • 合并后及时删除已合并的本地和远程分支
    • 长期分支（main, develop）外，所有分支都应该有明确的生命周期

    保护主分支¶

    在 GitHub/GitLab 上配置： - ✅ 禁止直接 push 到 main - ✅ PR 需要至少 1 个 review 批准 - ✅ CI 检查通过后才能合并 - ✅ 禁止 force push

    4. 有用的 Git 配置¶

    # 默认编辑器
git config --global core.editor vim

# 默认分支名
git config --global init.defaultBranch main

# 自动纠正拼写错误的命令
git config --global help.autocorrect 1

# pull 默认使用 rebase
git config --global pull.rebase true

# 合并冲突时使用 diff3 风格（显示三方内容）
git config --global merge.conflictstyle diff3

# 显示命令建议
git config --global advice.detachedHead false

# 全局 .gitignore
git config --global core.excludesFile ~/.gitignore_global

# 有用的别名
git config --global alias.lg "log --oneline --graph --all --decorate"
git config --global alias.st "status -s"
git config --global alias.co "checkout"
git config --global alias.br "branch"
git config --global alias.ci "commit"
git config --global alias.unstage "reset HEAD --"
git config --global alias.last "log -1 HEAD --stat"
git config --global alias.who "shortlog -sn --"
git config --global alias.graph "log --oneline --graph --all"

    5. 常见陷阱¶

    不要提交敏感信息¶

    # 如果不小心提交了密码/API Key
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch config/secrets.py" \
  --prune-empty --tag-name-filter cat -- --all

# 更好的工具：BFG Repo-Cleaner
bfg --delete-files secrets.txt

# 然后强制推送
git push --force --all

    一旦敏感信息被推送到远程，应该立即轮换密钥，而不仅仅是从 Git 历史中删除。

    大文件¶

    # 检查仓库大小
git count-objects -vH

# 使用 Git LFS 管理大文件
git lfs install
git lfs track "*.psd"
git lfs track "*.mp4"
git add .gitattributes

    Force Push 的危险¶

    # ❌ 危险：可能覆盖同事的提交
git push --force

# ✅ 安全：只在远程没有新提交时才覆盖
git push --force-with-lease

    6. 日常检查清单¶

    # 开始工作前
git pull --rebase            # 同步最新代码

# 工作中
git status                   # 经常检查状态
git diff                     # 确认改动

# 提交前
git diff --staged            # 检查暂存的内容
git commit -m "type: message"

# 推送前
git log origin/main..HEAD    # 确认要推送的内容
git push

# 下班前
git push                     # 推送到远程
