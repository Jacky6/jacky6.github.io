    撤销与回退¶

    时光倒流：从简单的撤销到重写历史，安全地修正错误。

    1. 工作区修改¶

    # 丢弃工作区的修改（恢复到暂存区或 HEAD 的状态）
git restore <file>
git restore .                  # 丢弃所有修改

# 丢弃指定文件的修改
git restore src/main.py

# 恢复到指定提交的版本
git restore --source HEAD~1 src/main.py

    旧版命令（仍可用）：git checkout -- <file>

    2. 暂存区操作¶

    # 从暂存区移除（保留工作区文件）
git restore --staged <file>
git reset HEAD <file>

# 取消所有暂存
git reset HEAD

    3. Reset（重置）¶

    Reset 移动当前分支的指针，并可选择性地更新暂存区和工作区。

              reset --soft          reset --mixed          reset --hard
              │                      │                      │
    ┌─────────┴─────────┐   ┌────────┴────────┐   ┌────────┴────────┐
    │     HEAD 移动      │   │   HEAD 移动      │   │   HEAD 移动     │
    │   暂存区保留        │   │   暂存区更新      │   │   暂存区更新    │
    │   工作区保留        │   │   工作区保留      │   │   工作区更新    │
    └───────────────────┘   └─────────────────┘   └─────────────────┘

    # --soft：只移动 HEAD，改动回到暂存区
git reset --soft HEAD~1

# --mixed（默认）：移动 HEAD + 更新暂存区，改动回到工作区
git reset HEAD~1

# --hard：全部重置，丢弃所有改动
git reset --hard HEAD~1

# 重置到指定 commit
git reset --hard abc1234

# 重置到远程分支的状态
git reset --hard origin/main

    常见场景：

    # 场景1：撤销 commit 但保留修改（重新编辑后再次提交）
git reset --soft HEAD~1

# 场景2：撤销 commit 且取消暂存（重新 add）
git reset --mixed HEAD~1

# 场景3：完全放弃最近一次 commit 和所有修改
git reset --hard HEAD~1

# 场景4：回退多个 commit
git reset --hard HEAD~3

# 场景5：同步远程，丢弃本地所有改动
git fetch origin
git reset --hard origin/main

    4. Revert（反转）¶

    与 reset 不同，revert 创建一个新的 commit 来撤销之前的改动，适合公共分支。

    # 撤销最近一次提交
git revert HEAD

# 撤销指定提交
git revert abc1234

# 撤销一段范围
git revert abc1234..def5678

# 撤销但不自动提交（方便编辑）
git revert --no-commit abc1234

# 撤销合并提交（需要指定父分支）
git revert -m 1 abc1234   # -m 1 表示保留第一个父分支的改动

    Reset vs Revert¶

    Reset Revert
    创建新 commit ❌ ✅
    改变历史 ✅ ❌
    安全用于公共分支 ❌ ✅
    可撤销多个 commit ✅ ✅

    5. 强制推送（重置远程）¶

    # 本地回退后强制推送到远程
git reset --hard abc1234
git push origin main --force

# 更安全的做法（不会覆盖别人的推送）
git push origin main --force-with-lease

    ⚠️ 强制推送会覆盖远程历史，确保团队知晓后再操作。

    6. 从提交中恢复单个文件¶

    # 从上次提交恢复文件
git checkout HEAD -- file.txt

# 从指定提交恢复文件
git checkout abc1234 -- file.txt

# 用新版命令
git restore --source abc1234 -- file.txt

    7. 清理未跟踪文件¶

    # 预览会删除什么（dry run）
git clean -n

# 删除未跟踪的文件
git clean -f

# 删除未跟踪的文件和目录
git clean -fd

# 删除未跟踪的文件、目录和 .gitignore 忽略的文件
git clean -fdx

# 交互式清理
git clean -i
