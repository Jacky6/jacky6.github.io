    分支管理¶

    Git 的灵魂所在。每个特性、每个 bugfix 都在独立分支上开发。

    1. 分支的本质¶

    分支只是一个指向某个 commit 的可移动指针。

    A---B---C  ← main
        \
         D---E  ← feature (当前分支)
    • main 指向 commit C
    • feature 指向 commit E
    • HEAD 指向当前所在分支

    2. 创建与切换¶

    # 创建分支（不切换）
git branch feature-login

# 创建并切换（最常用）
git checkout -b feature-login

# 基于指定 commit 创建分支
git checkout -b hotfix abc1234

# 从远程分支创建本地分支
git checkout -b dev origin/dev

# 切换到已有分支
git checkout main

# 新版命令（Git 2.23+）
git switch feature-login           # 切换
git switch -c feature-login        # 创建并切换
git switch -c feature origin/dev   # 基于远程分支创建并切换

    3. 查看分支¶

    # 列出本地分支（* 标记当前分支）
git branch

# 查看远程分支
git branch -r

# 查看本地 + 远程
git branch -a

# 显示最后一次提交（-vv 还会显示跟踪的远程分支）
git branch -v
git branch -vv

# 已合并到当前分支的分支（可安全删除）
git branch --merged

# 未合并的分支
git branch --no-merged

    示例输出：

    $ git branch -vv
* feature-login    abc1234 [origin/feature-login] feat: add login page
  main             def5678 [origin/main] chore: update deps
  hotfix-urgent    9876abc fix: critical security issue

    4. 删除分支¶

    # 删除本地分支（安全模式：拒绝删除未合并的分支）
git branch -d feature-login

# 强制删除（不管是否合并）
git branch -D feature-login

# 删除远程分支
git push origin --delete feature-login

# 清理远程已删除的分支引用
git fetch --prune
# 或简写
git fetch -p

    5. 分支命名规范¶

    推荐格式：<类型>/<描述>

    类型 用途 示例
    feature/ 新功能 feature/user-auth
    bugfix/ 或 fix/ 修复 bug fix/login-crash
    hotfix/ 紧急修复（通常基于 release） hotfix/security-patch
    release/ 发版分支 release/v2.1.0
    refactor/ 代码重构 refactor/auth-module
    docs/ 文档更新 docs/api-guide
    chore/ 杂项 chore/update-deps
    experiment/ 实验性尝试 experiment/new-algo

    6. 分支保护与追踪¶

    # 设置本地分支追踪远程分支
git branch -u origin/main

# 查看所有分支的追踪关系
git branch -vv

# 移除追踪关系
git branch --unset-upstream

# 重命名分支
git branch -m old-name new-name

    7. 典型分支工作流¶

    GitHub Flow（简单项目）¶

    main ───────────────────────────────→ 生产
  └── feature ──→ PR ──→ merge ──→ main
    1. 从 main 创建特性分支
    2. 开发并 commit
    3. 发起 Pull Request
    4. Review 后合并到 main
    5. 部署

    Git Flow（复杂项目）¶

    main ─── v1.0 ──────── v1.1 ───────→ 发布版本
  │        ╲            ╱
release/ ─── release/v1.1 ──╱
  │            ╱        ╲
develop ─────╱          hotfix ──→ 紧急修复
  │  ╲      ╱
  │   feature ──→ 特性开发
  │
hotfix ───────────────────────→ 直接修复 main

    核心分支：

    • main：生产环境，只接受来自 release 和 hotfix 的合并
    • develop：开发集成，所有特性合并到这里
    • feature/*：从 develop 创建，完成后合并回 develop
    • release/*：从 develop 创建，测试后合并到 main 和 develop
    • hotfix/*：从 main 创建，修复后合并到 main 和 develop
