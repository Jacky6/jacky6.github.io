    Git Worktree 完全指南¶

    在同一仓库的多个分支上并行工作，无需来回 stash 或重复 clone。

    参考文档

    什么是 Worktree？¶

    Git Worktree 允许你从同一个仓库检出多个工作目录，每个目录可以独立切换不同的分支。所有 worktree 共享同一个 .git 目录（对象数据库、引用等），因此：

    • 节省磁盘空间：不需要多次 clone
    • 切换零成本：不用 stash 保存/恢复现场
    • 并行工作：一个分支跑测试，另一个分支写代码，互不干扰

    典型使用场景¶

    场景 传统做法 Worktree 做法
    正在开发 feature，突然需要修 bug stash → checkout → fix → stash pop 另一个 worktree 直接修
    需要对比两个分支的构建结果 来回 checkout，每次重新编译 两个 worktree 同时编译
    Code Review 时想跑一下 PR 分支 切换本地分支 在独立 worktree 中检出
    长期维护多个版本分支 多个 clone，磁盘爆炸 多个 worktree，共享对象库

    最佳实践¶

    1. 创建一个新的工作区¶

    # 1-1 从已有分支创建一个工作区
git worktree add <路径> <分支>

# 1-2 新建分支并创建工作区（自动设置 upstream 跟踪）
git worktree add --track -b <新分支> <路径> <远程仓库>/<分支>

# 1-3 便捷模式：自动创建分支，分支名取自路径的最后一段
#     适合快速开一个新主题分支
git worktree add <路径>

# 1-4 创建"抛弃式"工作区（detached HEAD，不关联任何分支）
#     适合实验性修改、临时测试
git worktree add -d <路径>

    示例：

    (search-agent) ➜  search-agent git:(feat/async_law_tools) ✗ git worktree add ../search-agent_test
准备工作区（新分支 'search-agent_test'）
HEAD 现在位于 026da21 feat: 添加 visit_case_with_title

(search-agent) ➜  search-agent git:(feat/async_law_tools) ✗ cd ../search-agent_test
➜  search-agent_test git:(search-agent_test)

    2. 列举已有工作区¶

    git worktree list

    示例输出：

    /Users/jackyzheng/Repositories/search-agent             026da21 [feat/async_law_tools]
/Users/jackyzheng/Repositories/search-agent_parse_file  0127a47 [feat/parse_file]
/Users/jackyzheng/Repositories/search-agent_test        026da21 [search-agent_test]

    每行包含：路径、HEAD commit、所在分支（方括号内）。

    3. 移除一个工作区¶

    git worktree remove [-f] <工作区路径>
    • 只能移除干净的工作区（无未跟踪文件、无修改的跟踪文件）
    • 脏工作区或含子模块的工作区需要加 -f 强制删除
    • 主工作区（最初 clone 的那个）不能被移除

    示例：

    (search-agent) ➜  search-agent git worktree remove ../search-agent_test
(search-agent) ➜  search-agent ls ../
search-agent/             search-agent_parse_file/

    注意： remove 不会删除对应的分支。如果分支不再需要，需手动 git branch -d <分支>。

    进阶用法¶

    4. 将已存在的工作区重新关联（锁定/解锁）¶

    # 锁定工作区，防止被 `git worktree prune` 清理
git worktree lock <路径>

# 解锁
git worktree unlock <路径>

    适合长期存在的工作区，避免被误清理。

    5. 清理失效的工作区记录¶

    当工作区目录被手动删除（而非通过 git worktree remove）后，记录会残留：

    # 查看失效记录
git worktree list
# 可能显示路径不存在但记录还在

# 清理失效的工作区（超过 2 天未访问的）
git worktree prune

# 强制清理（不等待 2 天）
git worktree prune --expire now

    6. 移动工作区¶

    如果工作区目录需要移动位置，不能直接 mv，否则 Git 会找不到它。正确做法：

    # 方法一：重新注册（推荐）
mv old_path new_path
git worktree move old_path new_path    # Git ≥ 2.35

# 方法二：旧版本 Git
mv old_path new_path
git worktree prune
git worktree add <new_path> <分支>     # 重新关联

    实用技巧¶

    统一存放目录¶

    建议将所有 worktree 放在一个专属目录下，保持整洁：

    ~/projects/myrepo/           ← 主工作区
~/projects/myrepo-wt/bugfix  ← worktree 1
~/projects/myrepo-wt/feature ← worktree 2

    配合 IDE 使用¶

    • VS Code：直接 code <worktree-path> 打开，每个窗口独立工作
    • PyCharm / IDEA：作为独立项目打开即可，Git 操作互不干扰

    在 CI / 调试中使用¶

    # 快速验证 PR 分支的构建
git worktree add --detach /tmp/pr-check FETCH_HEAD
cd /tmp/pr-check
# ... 运行测试、编译等
git worktree remove /tmp/pr-check

    避免的坑¶

    1. 不能同时在两个 worktree 检出同一分支 — Git 会阻止，除非用 --force（不推荐）
    2. 子模块 — worktree 中的子模块需要单独初始化：git submodule update --init
    3. Git 版本 — worktree 功能从 Git 2.5 引入，建议使用 Git 2.15+ 以获得完整功能
    4. bare 仓库 — 可以在 bare 仓库上创建 worktree，这是 bare 仓库的唯一使用场景之一

    命令速查表¶

    命令 说明
    git worktree add <路径> <分支> 创建工作区
    git worktree add -d <路径> 创建 detached 工作区
    git worktree add --detach <路径> <commit> 检出指定 commit
    git worktree list 列出所有工作区
    git worktree remove <路径> 移除工作区
    git worktree remove -f <路径> 强制移除（含未提交修改）
    git worktree move <旧> <新> 移动工作区位置 (Git ≥ 2.35)
    git worktree lock <路径> 锁定工作区
    git worktree unlock <路径> 解锁工作区
    git worktree prune 清理失效记录
