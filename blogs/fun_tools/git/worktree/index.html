    Worktree

    ref:git-worktree

    最佳实践¶

    1. 创建一个新的工作区¶

    # 1-1 从已有分支拉一个新的工作区
git worktree add <路径> <分支>
# 1-2 新建一个分支拉一个新的工作区
git worktree add --track -b <分支> <路径> <远程仓库>/<分支>
# 或：自动创建一个新的分支，其名称是<路径>的最后一个组成部分，如果你计划在一个新的主题上工作，这很方便
git worktree add <路径>
`git worktree add .../hotfix`创建了新的分支`hotfix，并在路径`…​/hotfix`处签出它
# 1-3 如果你只是打算做一些实验性的修改，或者在不影响现有开发的情况下进行测试，创建一个不与任何分支相关联的 "抛弃式 "工作区通常是很方便的。
git worktree add -d <路径>

    例如：

    (search-agent) ➜  search-agent git:(feat/async_law_tools) ✗ git worktree add ../search-agent_test

    2. 列举已经存在的工作区¶

    git worktree list

    (search-agent) ➜  search-agent git:(feat/async_law_tools) ✗ git worktree list
/Users/jackyzheng/Repositories/search-agent             026da21 [feat/async_law_tools]
/Users/jackyzheng/Repositories/search-agent_parse_file  0127a47 [feat/parse_file]
/Users/jackyzheng/Repositories/search-agent_test        026da21 [search-agent_test]

    3. 移除一个工作区¶

    git worktree remove [-f] <工作区>

    • 移除一个工作区。只有干净的工作区（没有未跟踪的文件和未修改的跟踪文件）可以被删除。脏工作区或有子模块的工作区可以用 --force 删除。主工作区不能被删除
    (search-agent) ➜  search-agent git:(feat/async_law_tools) ✗ git worktree list
/Users/jackyzheng/Repositories/search-agent             026da21 [feat/async_law_tools]
/Users/jackyzheng/Repositories/search-agent_parse_file  0127a47 [feat/parse_file]
/Users/jackyzheng/Repositories/search-agent_test        026da21 [search-agent_test]
(search-agent) ➜  search-agent git:(feat/async_law_tools) ✗ git worktree remove search-agent_test
