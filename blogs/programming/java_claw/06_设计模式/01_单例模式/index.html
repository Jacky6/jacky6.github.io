    32_单例模式¶

    1. 单例模式概述¶

    1.1 什么是单例模式¶

    单例模式（Singleton Pattern）确保一个类只有一个实例，并提供全局访问点。

    应用场景： - ✅ 配置管理器 - ✅ 数据库连接池 - ✅ 日志记录器 - ✅ 线程池 - ✅ 缓存系统

    1.2 实现要点¶

    1. 私有构造方法：防止外部创建实例
    2. 私有静态变量：保存唯一实例
    3. 公共静态方法：提供全局访问点

    2. 饿汉式单例¶

    2.1 实现方式¶

    public class Singleton {
    // 类加载时创建实例
    private static final Singleton INSTANCE = new Singleton();

    // 私有构造
    private Singleton() {
    }

    // 全局访问点
    public static Singleton getInstance() {
        return INSTANCE;
    }
}

    2.2 特点¶

    优点 缺点
    线程安全 可能浪费资源
    实现简单 无法延迟加载
    无锁开销 类加载就创建

    2.3 使用¶

    Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();
System.out.println(s1 == s2);  // true

    3. 懒汉式单例¶

    3.1 线程不安全版本¶

    public class Singleton {
    private static Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();  // 线程不安全
        }
        return instance;
    }
}

    3.2 线程安全版本（同步方法）¶

    public class Singleton {
    private static Singleton instance;

    private Singleton() {
    }

    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}

    缺点：每次调用都同步，性能低

    3.3 双重检查锁定（DCL）⭐¶

    public class Singleton {
    // volatile 保证可见性和禁止指令重排
    private static volatile Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {  // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) {  // 第二次检查
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

    优点： - ✅ 线程安全 - ✅ 延迟加载 - ✅ 性能高（只在第一次同步）

    4. 静态内部类¶

    4.1 实现方式¶

    public class Singleton {
    private Singleton() {
    }

    // 静态内部类，类加载时不初始化
    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}

    4.2 特点¶

    优点 缺点
    线程安全 理解略复杂
    延迟加载
    无锁开销
    JVM 保证线程安全

    原理： - 外部类加载时，内部类不加载 - 调用 getInstance() 时才加载内部类 - JVM 保证类加载的线程安全性

    5. 枚举单例¶

    5.1 实现方式¶

    public enum Singleton {
    INSTANCE;

    public void doSomething() {
        System.out.println("Hello");
    }
}

    5.2 使用¶

    Singleton s1 = Singleton.INSTANCE;
Singleton s2 = Singleton.INSTANCE;
s1.doSomething();

    5.3 特点¶

    优点 缺点
    线程安全 不够灵活
    防止反射攻击 无法继承
    防止序列化破坏
    最简洁

    推荐：Effective Java 推荐的实现方式

    6. 单例模式对比¶

    实现方式 线程安全 延迟加载 性能 推荐度
    饿汉式 ✅ ❌ 高 ⭐⭐⭐
    懒汉式（同步） ✅ ✅ 低 ⭐⭐
    双重检查（DCL） ✅ ✅ 高 ⭐⭐⭐⭐
    静态内部类 ✅ ✅ 高 ⭐⭐⭐⭐⭐
    枚举 ✅ ✅ 高 ⭐⭐⭐⭐⭐

    7. 单例模式破坏¶

    7.1 反射攻击¶

    // DCL 实现可以被反射破坏
Singleton s1 = Singleton.getInstance();

Constructor<Singleton> constructor = Singleton.class.getDeclaredConstructor();
constructor.setAccessible(true);
Singleton s2 = constructor.newInstance();

System.out.println(s1 == s2);  // false（单例被破坏）

// 防御：构造方法中检查
private Singleton() {
    if (instance != null) {
        throw new RuntimeException("Cannot create more than one instance");
    }
}

    7.2 序列化攻击¶

    // 序列化会创建新实例
Singleton s1 = Singleton.getInstance();

ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("obj.dat"));
oos.writeObject(s1);

ObjectInputStream ois = new ObjectInputStream(new FileInputStream("obj.dat"));
Singleton s2 = (Singleton) ois.readObject();

System.out.println(s1 == s2);  // false（单例被破坏）

// 防御：实现 readResolve 方法
private Object readResolve() {
    return instance;
}

    7.3 枚举防止破坏¶

    // 枚举天然防止反射和序列化攻击
public enum Singleton {
    INSTANCE;
}

// 测试
Singleton s1 = Singleton.INSTANCE;
Singleton s2 = Singleton.INSTANCE;
System.out.println(s1 == s2);  // true（始终安全）

    8. 实战示例¶

    8.1 配置管理器¶

    public class ConfigManager {
    private static volatile ConfigManager instance;
    private Properties properties;

    private ConfigManager() {
        properties = new Properties();
        loadConfig();
    }

    public static ConfigManager getInstance() {
        if (instance == null) {
            synchronized (ConfigManager.class) {
                if (instance == null) {
                    instance = new ConfigManager();
                }
            }
        }
        return instance;
    }

    private void loadConfig() {
        try (InputStream input = new FileInputStream("config.properties")) {
            properties.load(input);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public String getProperty(String key) {
        return properties.getProperty(key);
    }
}

    8.2 日志记录器¶

    public class Logger {
    private static volatile Logger instance;
    private PrintWriter writer;

    private Logger() {
        try {
            writer = new PrintWriter(new FileWriter("app.log", true));
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public static Logger getInstance() {
        if (instance == null) {
            synchronized (Logger.class) {
                if (instance == null) {
                    instance = new Logger();
                }
            }
        }
        return instance;
    }

    public void log(String message) {
        writer.println(new Date() + " - " + message);
        writer.flush();
    }

    public void close() {
        writer.close();
    }
}

    9. 本章小结¶

    核心知识点¶

    ✅ 饿汉式：类加载创建，线程安全
    ✅ 懒汉式：延迟加载，需同步
    ✅ 双重检查：线程安全 + 延迟加载 + 高性能
    ✅ 静态内部类：JVM 保证线程安全
    ✅ 枚举：最安全，防止攻击

    最佳实践¶

    1. 优先使用枚举：最安全、最简洁
    2. 使用静态内部类：次选，灵活性好
    3. 使用双重检查：需要更多控制时
    4. 避免懒汉式（同步）：性能低
    5. 注意反射和序列化攻击：使用枚举或添加防御

    推荐实现¶

    // 最推荐：枚举
public enum Singleton {
    INSTANCE;
}

// 次推荐：静态内部类
public class Singleton {
    private Singleton() {}

    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
