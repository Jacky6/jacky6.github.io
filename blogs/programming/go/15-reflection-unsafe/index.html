    15 反射与 unsafe¶

    reflect 包、结构体标签、动态调用、unsafe 与性能边界。

    1. 反射基础¶

    反射在运行时检查与操作类型和值：

    import "reflect"

// 获取类型与值
t := reflect.TypeOf(42)      // int
v := reflect.ValueOf(42)     // 42

v.Kind()                     // reflect.Int
v.Type()                     // int
v.Int()                      // 64（int64 形式）

// 静态类型 vs 动态类型
var i any = "hello"
reflect.TypeOf(i).Kind()     // reflect.String

    1.1 三大定律¶

    1. 反射可以从接口值到反射对象（TypeOf / ValueOf）
2. 反射可以从反射对象回到接口值（v.Interface()）
3. 要修改反射对象，值必须可设置（CanSet）

    // 定律 2：回到接口
v := reflect.ValueOf(42)
i := v.Interface()   // any
n := i.(int)

// 定律 3：可设置性
x := 42
v := reflect.ValueOf(x)
v.SetInt(100)   // panic！传的是 x 的拷贝

v = reflect.ValueOf(&x).Elem()   // 取指针指向的元素
v.CanSet()      // true
v.SetInt(100)   // ✅ 修改成功，x 变为 100

    2. 常用操作¶

    2.1 结构体遍历¶

    type User struct {
    Name string `json:"name"`
    Age  int    `json:"age"`
}

u := User{"Alice", 30}
t := reflect.TypeOf(u)
v := reflect.ValueOf(u)

for i := 0; i < t.NumField(); i++ {
    field := t.Field(i)
    value := v.Field(i)
    fmt.Printf("%s (%s) = %v, tag=%s\n",
        field.Name, field.Type, value.Interface(),
        field.Tag.Get("json"))
}
// Name (string) = Alice, tag=name
// Age (int) = 30, tag=age

    2.2 动态调用方法¶

    type Calc struct{}

func (c Calc) Add(a, b int) int { return a + b }

c := Calc{}
v := reflect.ValueOf(c)
m := v.MethodByName("Add")

args := []reflect.Value{reflect.ValueOf(1), reflect.ValueOf(2)}
result := m.Call(args)
fmt.Println(result[0].Int())   // 3

    2.3 动态创建与修改¶

    // 创建新值
t := reflect.TypeOf(User{})
v := reflect.New(t)            // *User
v.Elem().FieldByName("Name").SetString("Bob")

// make 切片/map
sliceType := reflect.SliceOf(reflect.TypeOf(0))
s := reflect.MakeSlice(sliceType, 0, 10)
s = reflect.Append(s, reflect.ValueOf(1))

    4. 结构体标签解析¶

    // 标准格式：key1:"val1" key2:"val2"
tag := `json:"name,omitempty" validate:"required,max=32"`

// reflect.StructTag.Get：取第一个值
t, _ := reflect.TypeOf(User{}).FieldByName("Name")
t.Tag.Get("json")        // "name,omitempty"

// StructTag.Lookup：区分"不存在"与"空值"
v, ok := t.Tag.Lookup("json")

    5. unsafe¶

    unsafe 绕过类型系统直接操作内存：

    import "unsafe"

// 1. 指针类型转换
var f float64 = 3.14
bits := *(*uint64)(unsafe.Pointer(&f))   // 重解释位模式

// 2. string 与 []byte 零拷贝（危险！）
func String2Bytes(s string) []byte {
    return unsafe.Slice(unsafe.StringData(s), len(s))   // Go 1.20+
}
// ⚠️ 修改返回的 []byte = 修改字符串底层内存（不可变约定被破坏）

// 3. 偏移访问
type T struct{ X int32; Y int64 }
var t T
pY := (*int64)(unsafe.Pointer(uintptr(unsafe.Pointer(&t)) + unsafe.Offsetof(t.Y)))

    5.1 unsafe.Pointer 规则¶

    uintptr            ← 只是整数，GC 不感知（随时可能失效）
unsafe.Pointer     ← GC 感知的指针，转换中转站

合法转换链：
*T1 → unsafe.Pointer → *T2
unsafe.Pointer → uintptr（仅用于同一表达式内的地址计算）

    原则：uintptr 不能长期保存地址（GC 移动对象后失效），地址运算必须在单个表达式内完成。

    5.2 实际用途¶

    // 标准库内部大量使用
- strings/bytes 零拷贝互转
- sync.Pool 内部指针操作
- runtime 底层
- 原子操作：atomic.Pointer

// 第三方极致性能库
- sonic（JSON）：直接操作内存加速解析
- 常见面试题：string 与 []byte 转换的零拷贝实现

    6. 面试高频：string 与 []byte¶

    // 常规转换（拷贝）
b := []byte(s)    // 分配新内存，拷贝
s := string(b)

// 底层结构
type stringHeader struct {
    Data unsafe.Pointer
    Len  int
}
type sliceHeader struct {
    Data unsafe.Pointer
    Len  int
    Cap  int
}
// 两者前两个字段相同 → 可零拷贝互转

// 为什么默认拷贝？字符串不可变约定 + 修改 b 会破坏 s

    7. 性能对比¶

    // 直接调用:            ~1ns
// 接口调用:            ~2ns
// 反射 Method.Call:    ~100ns+
// unsafe 指针操作:     ~1ns（但失去安全）

// 结论：反射用于框架层（一次性开销可摊薄），
// 热路径用代码生成（easyjson）或泛型替代

    8. 小结¶

    • 反射三定律：接口→反射对象、反射对象→接口、可设置性
    • 修改值必须传指针并 .Elem()
    • 反射慢且不安全，框架层才用，业务代码避免
    • unsafe 绕过类型系统，uintptr 不可长期持有
    • string/[]byte 零拷贝是面试高频，理解不可变约定
