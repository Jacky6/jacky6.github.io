    14 工程化：模块、工具链、项目布局¶

    项目结构、依赖管理、代码规范、性能分析、CI。

    1. 项目布局¶

    Go 官方没有强制布局，社区标准是 golang-standards/project-layout：

    myapp/
├── cmd/                    # 主应用入口
│   ├── server/
│   │   └── main.go
│   └── cli/
│       └── main.go
├── internal/               # 私有代码（编译器强制不可被外部导入！）
│   ├── handler/
│   ├── service/
│   ├── repository/
│   └── config/
├── pkg/                    # 公共库（可被外部导入；小项目可不建）
│   └── logger/
├── api/                    # API 定义（proto/OpenAPI）
├── configs/                # 配置文件
├── scripts/                # 脚本
├── test/                   # 集成测试数据
├── go.mod
├── go.sum
├── Makefile
└── README.md

    关键点：

    • internal/ 是 Go 编译器强制的：internal 目录下的包只能被其父目录树内的包导入
    • cmd/ 下每个子目录是一个二进制，main.go 只做启动装配
    • 业务逻辑放 internal/，保持入口薄

    2. 模块进阶¶

    2.1 go.mod 完整解析¶

    module github.com/user/myapp

go 1.23

toolchain go1.23.1   // 指定工具链（GOTOOLCHAIN=auto 时自动下载）

require (
    github.com/gin-gonic/gin v1.10.0
    golang.org/x/sync v0.8.0
)

require (
    // indirect：间接依赖
    github.com/bytedance/sonic v1.12.0 // indirect
)

exclude github.com/bad/pkg v1.0.0     // 排除版本
replace github.com/local/pkg => ../local   // 本地替换（开发联调）
replace github.com/pkg/x => github.com/fork/x v1.2.0   // fork 替换

retract v1.0.1   // 撤回有问题的版本

    2.2 版本选择：MVS¶

    Go 使用最小版本选择（Minimal Version Selection）：

    • 每个依赖选满足所有要求的最旧版本
    • 不像 npm 自动选最新 → 构建可重现
    • go get 升级、go mod tidy 清理

    2.3 工作区（Go 1.18+）¶

    多模块本地联调：

    go work init ./myapp ./lib1
go work use ./lib2

    // go.work
go 1.23

use (
    ./myapp
    ./lib1
    ./lib2
)

    工作区内模块互相引用走本地路径，无需 replace。

    3. 代码规范与静态检查¶

    # 官方三件套
gofmt -l .            # 格式检查（-w 重写）
go vet ./...          # 可疑代码检查
go vet -shadow ./...  # 变量遮蔽

# gofmt 升级版：整理 import 分组
goimports -local github.com/user/myapp -w .

# 社区最强 linter（聚合 100+ 检查）
golangci-lint run
golangci-lint run --fix

    .golangci.yml 常用配置：

    linters:
  enable:
    - errcheck        # 未检查的错误
    - govet
    - staticcheck
    - unused
    - gosimple
    - misspell
    - revive          # golint 继任者
    - gosec           # 安全检查
    - gofmt
    - goimports

    4. Makefile 模板¶

    BINARY := myapp
VERSION := $(shell git describe --tags --always)
LDFLAGS := -s -w -X main.version=$(VERSION)

.PHONY: build run test lint clean

build:
    CGO_ENABLED=0 go build -ldflags "$(LDFLAGS)" -o $(BINARY) ./cmd/server

run:
    go run ./cmd/server

test:
    go test -race -cover ./...

lint:
    golangci-lint run

fmt:
    gofmt -w .
    goimports -w .

clean:
    rm -f $(BINARY)

    5. 性能分析¶

    5.1 pprof¶

    import _ "net/http/pprof"   // 注册到默认 mux

go func() {
    http.ListenAndServe("localhost:6060", nil)
}()

    # CPU profile 30 秒
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30

# 内存
go tool pprof http://localhost:6060/debug/pprof/heap

# goroutine（排查泄漏）
go tool pprof http://localhost:6060/debug/pprof/goroutine

# 常用命令：top、list 函数名、web（调用图）

    5.2 基准对比¶

    # 保存基准结果
go test -bench=. -count=10 > old.txt

# 修改代码后
go test -bench=. -count=10 > new.txt

# 统计对比（显著性检验）
benchstat old.txt new.txt

    5.3 竞态与逃逸分析¶

    go build -gcflags="-m" ./...   # 逃逸分析（哪些变量分配到堆）
go test -race ./...            # 竞态检测

    6. 交叉编译与发布¶

    # 多平台构建
for os in linux darwin windows; do
  for arch in amd64 arm64; do
    CGO_ENABLED=0 GOOS=$os GOARCH=$arch \
      go build -ldflags "-s -w" -o dist/myapp-$os-$arch ./cmd/server
  done
done

# -s -w：去掉符号表与调试信息，体积减 ~30%

# Docker 多阶段构建
FROM golang:1.23 AS builder
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -ldflags "-s -w" -o /app ./cmd/server

FROM gcr.io/distroless/static-debian12
COPY --from=builder /app /app
ENTRYPOINT ["/app"]

    7. 目录级规范¶

    internal/
├── handler/       # HTTP 层：参数解析、响应
├── service/       # 业务逻辑
├── repository/    # 数据访问
└── domain/        # 实体与核心接口

依赖方向：handler → service → repository → domain
（domain 不依赖任何上层）

    8. CI 模板（GitHub Actions）¶

    # .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.23'
      - run: go vet ./...
      - run: golangci-lint run
      - run: go test -race -coverprofile=coverage.out ./...
      - run: go tool cover -func=coverage.out

    9. 小结¶

    • cmd/ 薄入口 + internal/ 私有业务是标准布局
    • MVS 版本选择保证可重现构建，go work 解决多模块联调
    • gofmt + go vet + golangci-lint 是质量底线
    • pprof 挂 localhost:6060 随时抓 CPU/内存/goroutine
    • CGO_ENABLED=0 + distroless 镜像 = 极简部署
