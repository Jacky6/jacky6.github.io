    11_Java 新特性（9-21）¶

    1. 版本概览¶

    Java 从 9 开始改为每 6 个月一个版本，LTS（长期支持）版本是生产选型的主要参考。

    版本 年份 LTS 核心特性
    8 2014 ✅ Lambda、Stream、Optional、新日期 API（老 LTS，至今大量存量）
    11 2018 ✅ var 局部变量（10 引入）、HTTP Client、直接运行 .java
    17 2021 ✅ sealed 类、模式匹配 instanceof、switch 表达式、record、文本块
    21 2023 ✅ 虚拟线程、switch 模式匹配定稿、record 模式、Sequenced Collections

    新项目首选 JDK 17 / 21（SpringBoot 3.x 最低要求 JDK 17）；存量系统大多还在 8，面试两边都要会。

    2. Java 9-11：基础改进¶

    知识点： - Java 9：集合工厂 List.of、模块化（JPMS）、接口私有方法 - Java 10：var 局部变量推断；Java 11（LTS）：HTTP Client、单文件直接运行

    2.1 集合工厂方法（Java 9）¶

    // 不可变集合，一行创建，不允许 null
List<String> list = List.of("A", "B", "C");
Set<Integer> set = Set.of(1, 2, 3);
Map<String, Integer> map = Map.of("a", 1, "b", 2);
Map<String, Integer> map2 = Map.ofEntries(
    Map.entry("a", 1),
    Map.entry("b", 2)
);

list.add("D");  // ❌ UnsupportedOperationException

    2.2 接口私有方法（Java 9）¶

    public interface Logger {
    default void logInfo(String msg)  { log("INFO", msg); }
    default void logError(String msg) { log("ERROR", msg); }

    // 接口内可以有 private 方法，供 default 方法复用（Java 9+）
    private void log(String level, String msg) {
        System.out.println("[" + level + "] " + msg);
    }
}

    2.3 var 局部变量类型推断（Java 10）¶

    var list = new ArrayList<String>();      // 推断为 ArrayList<String>
var stream = list.stream();              // 推断为 Stream<String>
var i = 0;                               // int

// ❌ 不允许：成员变量、方法参数、返回值类型
// 建议：类型明显时用 var，否则显式写出，可读性优先

// Java 15：文本块（多行字符串）

    2.5 HTTP Client（Java 11 定稿）¶

    import java.net.http.*;
import java.net.URI;

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .header("Accept", "application/json")
    .GET()
    .build();

// 同步
HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
System.out.println(response.statusCode());
System.out.println(response.body());

// 异步
client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
      .thenApply(HttpResponse::body)
      .thenAccept(System.out::println);

    取代了难用的 HttpURLConnection；生产中也常用 OkHttp/Apache HttpClient，但 JDK 自带的已足够。

    2.7 switch 表达式（Java 14 定稿）¶

    // 传统 switch：语句，容易忘 break
// Java 14：switch 表达式，箭头语法 + 必须覆盖所有分支 + 可赋值
int numLetters = switch (day) {
    case "MONDAY", "FRIDAY", "SUNDAY" -> 6;   // 多值逗号分隔
    case "TUESDAY"                    -> 7;
    case "THURSDAY", "SATURDAY"       -> 8;
    case "WEDNESDAY"                  -> 9;
};  // 作为表达式必须有返回值且覆盖所有情况

// 需要多行逻辑时用 yield 返回值
int result = switch (mode) {
    case "A" -> 1;
    case "B" -> {
        System.out.println("计算中...");
        yield 2;
    }
    default -> 0;
};

    3. Java 16/17：数据建模革新（LTS）¶

    知识点： - ⭐ record（16 定稿）：一行生成不可变数据类；模式匹配 instanceof（16） - ⭐ sealed 类（17 定稿）：限定继承体系，配合 switch 穷举检查 - Java 17 是 SpringBoot 3 的最低要求

    3.1 record 记录类（Java 16 定稿）¶

    record = 不可变数据载体，一行生成构造器、getter、equals、hashCode、toString：

    // 传统 POJO 要写 30 行；record 一行
public record Point(int x, int y) {}

// 编译器自动生成：
// - private final int x; private final int y;
// - 全参构造 Point(int x, int y)
// - 访问器 x()、y()（注意不是 getX()）
// - equals / hashCode / toString

Point p = new Point(1, 2);
System.out.println(p.x());       // 1
System.out.println(p);           // Point[x=1, y=2]

// 紧凑构造器：参数校验
public record Age(int value) {
    public Age {
        if (value < 0) throw new IllegalArgumentException("年龄不能为负");
    }
}

// record 可以实现接口，但不能继承类（隐式继承 Record）

    适用：DTO、VO、Map 的 key、元组。业务实体（需要可变、需要继承）仍用普通类。

    3.2 模式匹配 instanceof（Java 16 定稿）¶

    // 传统：instanceof 判断后还要强转
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// Java 16：判断 + 绑定一步到位
if (obj instanceof String s) {
    System.out.println(s.length());  // s 直接可用
}

// 结合逻辑运算
if (obj instanceof String s && s.length() > 5) {
    System.out.println(s.toUpperCase());
}

    3.3 sealed 密封类（Java 17 定稿）¶

    限定一个类/接口允许被哪些类继承实现，让类型层次"封闭可控"：

    // permits 显式列出所有子类，其他类不许继承
public sealed interface Shape
    permits Circle, Square, Triangle {}

public record Circle(double radius) implements Shape {}
public record Square(double side) implements Shape {}
public final class Triangle implements Shape {  // 子类必须三选一：
    // ...                                      // final / sealed / non-sealed
}

    意义：配合 switch 模式匹配，编译器能检查分支是否覆盖所有子类——代数数据类型（ADT）在 Java 中的落地。

    4. Java 21：并发与模式匹配的里程碑（LTS）⭐⭐⭐¶

    知识点： - ⭐ 虚拟线程（JEP 444）：JVM 调度的轻量线程，IO 密集场景'同步写法，异步性能' - switch 模式匹配/record 模式定稿；Sequenced Collections 统一首尾访问 - 虚拟线程不要池化，用完即弃；synchronized 里阻塞会钉住载体线程

    4.1 虚拟线程（Virtual Threads，JEP 444）⭐⭐⭐⭐¶

    背景：平台线程 1:1 映射内核线程，创建成本约 1MB 栈内存，单机几千个就到头了。高并发 IO 场景（Web 服务、RPC）长期靠线程池 + 异步硬撑。

    虚拟线程：JVM 调度的轻量线程，M 个虚拟线程跑在 N 个平台线程（载体线程）上，创建成本极低，可以一次开上百万个。

    // 创建虚拟线程
Thread.startVirtualThread(() -> System.out.println("虚拟线程: " + Thread.currentThread()));

Thread vThread = Thread.ofVirtual().name("worker-1").start(() -> {
    System.out.println("运行在虚拟线程上");
});

// 虚拟线程执行器：每个任务一个虚拟线程，不再"池化"线程
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 100_000; i++) {
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));  // IO 等待
            return 42;
        });
    }
}  // try-with-resources 自动等所有任务完成

    关键点： - 虚拟线程阻塞时自动让出载体线程，阻塞不再昂贵——"同步写法，异步性能" - 适合 IO 密集任务；CPU 密集任务虚拟线程没有优势 - 不要把虚拟线程放进池子（太便宜，用完即弃）；synchronized 块内阻塞会"钉住"载体线程（pinning），长时间 IO 建议改用 ReentrantLock - SpringBoot 3.2+ 一行开启：spring.threads.virtual.enabled=true

    4.2 switch 模式匹配（Java 21 定稿）¶

    // 按类型匹配，不再需要 if-else instanceof 链
static String describe(Object obj) {
    return switch (obj) {
        case Integer i -> "整数: " + i;
        case String s  -> "字符串，长度 " + s.length();
        case Long l    -> "长整数: " + l;
        case null      -> "空值";        // 可以显式匹配 null
        default        -> "其他: " + obj;
    };
}

// 配合 sealed 类 + record：编译期检查覆盖性
sealed interface Payment permits Cash, Card {}
record Cash(int amount) implements Payment {}
record Card(String number, int amount) implements Payment {}

static String pay(Payment p) {
    return switch (p) {
        case Cash c  -> "现金支付 " + c.amount();
        case Card c  -> "刷卡 " + c.number();
        // 不需要 default！编译器知道只有两种实现
    };
}

// record 解构（record 模式）：直接拆出字段
record Point(int x, int y) {}
if (obj instanceof Point(int x, int y)) {
    System.out.println(x + ", " + y);
}

// 带条件守卫 when
switch (value) {
    case Integer i when i < 0  -> "负数";
    case Integer i             -> "非负整数";  // i 重复命名合法（作用域各自独立）
    default                    -> "其他";
}

    4.3 Sequenced Collections（JEP 431）¶

    为"有顺序"的集合统一加了首尾访问接口：

    // 新接口：SequencedCollection / SequencedSet / SequencedMap
// List、LinkedHashSet、ArrayDeque、LinkedHashMap 都实现了

List<String> list = new ArrayList<>(List.of("A", "B", "C"));
list.getFirst();    // A（原 list.get(0)）
list.getLast();     // C
list.addFirst("Z");
list.reversed();    // 反转视图

LinkedHashMap<String, Integer> map = new LinkedHashMap<>();
map.firstEntry();
map.lastEntry();

    4.4 其他（了解）¶

    • ScopedValue（预览，JEP 446）：虚拟线程时代的 ThreadLocal 替代，详见 ThreadLocal
    • 结构化并发（预览，JEP 453）：把多个子任务当作一个单元管理，统一取消与错误处理
    • String Templates（预览）：字符串模板插值（后续版本形态有变化，以最新版为准）

    5. 升级路线与兼容要点¶

    知识点： - ⚠️ 升级三大坑：javax→jakarta（Java EE 移出）、模块化封装内部 API、移除的 API（Nashorn 等） - 选型：新项目 JDK 21 LTS，存量 8 先升 17 过渡

    5.1 从 JDK 8 升级到 17/21 常见坑¶

    问题 原因/解决
    javax.* 包消失 Java EE 模块移出 JDK，改引 Jakarta EE 依赖（javax → jakarta）
    反射访问内部 API 报错（illegal access） 模块化（JPMS）封装了 JDK 内部类，用 --add-opens 临时放开
    JAXB / JAX-WS 类找不到 JDK 11 移除了这些模块，单独加依赖
    Nashorn 脚本引擎没了 JDK 15 移除，换 GraalVM JS 或依赖 org.openjdk.nashorn
    Lombok/旧框架报错 升级到支持新 JDK 的版本

    5.2 选型建议¶

    • 新项目：JDK 21 LTS（SpringBoot 3.2+ / 3.4+），虚拟线程真香
    • 存量 JDK 8：先升 17 LTS 过渡（SpringBoot 3 最低要求），再平滑到 21
    • 构建工具：Maven 设置 <maven.compiler.release>21</maven.compiler.release>

    6. 常见面试题¶

    Q1：record 和普通 POJO 的区别？ record 不可变（字段 final）、自动生成构造器/访问器/equals/hashCode/toString、不能继承类；适合纯数据载体。POJO 可变、可继承，适合业务实体。

    Q2：虚拟线程解决了什么问题？和线程池什么关系？ 解决平台线程数量受限导致的高并发 IO 瓶颈。虚拟线程极轻量，不再需要池化（每任务一个虚拟线程）；阻塞 IO 时自动让出载体线程，同步代码获得异步吞吐。CPU 密集场景无优势。

    Q3：switch 表达式和传统 switch 的区别？ 箭头语法无需 break、可作为表达式返回值（赋值）、编译器强制覆盖所有分支、支持模式匹配（21）。

    Q4：sealed 类有什么用？ 限定继承体系，配合 switch 模式匹配实现编译期穷举检查，用于领域建模（代数数据类型）。

    Q5：var 能用在哪些地方？ 只能用于局部变量（有初始化器）。不能用于成员变量、方法参数、返回值、lambda 参数推断。

    7. 练习题¶

    练习 1（record）：定义 record User(String name, int age)，验证自动生成的方法；再加一个紧凑构造器校验 age ≥ 0。

    练习 2（switch 模式匹配）：写方法 String format(Object o)，用 Java 21 的 switch 模式匹配分别处理 Integer/String/Double/null/其他。

    练习 3（sealed + record）：定义 sealed interface Expr permits Num, Add, Mul 表示算术表达式（Num 存值，Add/Mul 存两个子表达式），写递归求值方法 eval，再用 switch 模式匹配重写 eval。

    练习 4（虚拟线程）：用 Executors.newVirtualThreadPerTaskExecutor() 提交 10000 个任务，每个 sleep 1 秒后返回，统计总耗时，与固定 10 线程的线程池对比。

    参考答案¶

    import java.util.concurrent.*;

public class NewFeaturesExercises {

    // 练习 1
    record User(String name, int age) {
        User {  // 紧凑构造器
            if (age < 0) throw new IllegalArgumentException("age 不能为负");
        }
    }
    // 自动生成：new User("Tom", 18)、user.name()、equals/hashCode/toString

    // 练习 2：模式匹配 switch
    static String format(Object o) {
        return switch (o) {
            case Integer i -> "整数 " + i;
            case String s  -> "字符串(长度" + s.length() + ") " + s;
            case Double d  -> "小数 " + d;
            case null      -> "空值";
            default        -> "未知类型 " + o.getClass().getSimpleName();
        };
    }

    // 练习 3：sealed + record 表达式树
    sealed interface Expr permits Num, Add, Mul {}
    record Num(double value) implements Expr {}
    record Add(Expr left, Expr right) implements Expr {}
    record Mul(Expr left, Expr right) implements Expr {}

    static double eval(Expr expr) {
        return switch (expr) {
            case Num n      -> n.value();
            case Add a      -> eval(a.left()) + eval(a.right());
            case Mul m      -> eval(m.left()) * eval(m.right());
            // 无 default：编译器穷举检查，新增子类忘改这里会直接编译报错
        };
    }

    public static void main(String[] args) throws Exception {
        // 练习 3 验证：(1 + 2) * 3 = 9
        Expr expr = new Mul(new Add(new Num(1), new Num(2)), new Num(3));
        System.out.println(eval(expr));  // 9.0

        // 练习 4：虚拟线程
        long start = System.currentTimeMillis();
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 10_000; i++) {
                executor.submit(() -> { Thread.sleep(1000); return 1; });
            }
        }
        System.out.println("虚拟线程耗时: " + (System.currentTimeMillis() - start) + "ms");
        // 约 1 秒出头（全部并发 sleep）
        // 对比固定 10 线程池：10000 / 10 × 1s ≈ 1000 秒
    }
}

    练习 2-4 需要 JDK 21 运行（java --version 检查）；练习 4 的结果直观展示虚拟线程的并发能力。
