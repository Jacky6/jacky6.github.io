    1. 线程基础¶

    知识点：

    • 线程是程序执行的最小单元，一个进程含多个线程，共享进程内存
    • ⭐ Java 线程六种状态：NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED（没有 RUNNING）
    • HotSpot 的 Java 线程 1:1 映射内核线程，创建/切换成本高（虚拟线程见进阶篇第 11 章）

    1.1 什么是线程¶

    线程（Thread）是程序执行的最小单元，一个进程可以包含多个线程。

    进程 vs 线程：

    特性 进程 线程
    资源 独立内存空间 共享进程资源
    开销 大 小
    通信 复杂（IPC） 简单（共享内存）

    Java 线程与内核线程：HotSpot 的 Java 线程是 1:1 映射到操作系统内核线程的（一个 Java 线程对应一个内核线程），创建/切换成本较高，这也是后来引入虚拟线程（JDK 21）的原因。

    1.2 线程生命周期（六种状态）⭐⭐⭐¶

    Java 中线程状态由 Thread.State 枚举定义，共 6 种（注意：没有 RUNNING 状态，"运行中"和"就绪"都归入 RUNNABLE）：

                     start()
NEW ───────────────→ RUNNABLE ⇄ （CPU 调度，就绪/运行中）
                       │  │  │
        等待 synchronized │  │  wait()/join()/park()
        锁被占用        │  │         │
                       ↓  │         ↓
                   BLOCKED │     WAITING（无限期等待）
                       ↑  │         ↑
                       │  │  sleep(ms)/join(ms)/wait(ms)
                       │  └───→ TIMED_WAITING（限期等待）
                       │
                 run() 结束或抛未捕获异常
                       ↓
                  TERMINATED
    状态 触发 退出方式
    NEW new Thread() 之后 start()
    RUNNABLE start() 后（含就绪和运行中） CPU 调度切换/结束
    BLOCKED 等待进入 synchronized 块/方法 获得锁
    WAITING wait()、join()、LockSupport.park() notify/notifyAll、被 join 线程结束、unpark
    TIMED_WAITING sleep(ms)、wait(ms)、join(ms) 超时或被唤醒
    TERMINATED run() 执行完毕 — 
    Thread t = new Thread(() -> {});
System.out.println(t.getState());  // NEW
t.start();
// 之后可用 t.getState() 观察状态变化

    1.3 线程的常用方法¶

    方法 作用 释放锁？
    start() 启动线程（只能调用一次） —
    run() 任务体；直接调用只是普通方法调用，不会启动线程 —
    sleep(ms) 当前线程休眠，不释放锁 ❌
    yield() 提示调度器让出 CPU（不保证） ❌
    join() 等待目标线程结束再继续 ❌
    interrupt() 给线程打中断标记（不强制停止） —
    setDaemon(true) 设为守护线程（需在 start 前调用） —

    sleep vs wait（高频面试）：

    sleep wait
    所属类 Thread（静态方法） Object
    是否释放锁 ❌ 不释放 ✅ 释放锁
    使用位置 任意 必须在 synchronized 块内
    唤醒方式 时间到自动醒 notify/notifyAll 或超时 
    // join：主线程等待子线程完成
Thread t = new Thread(() -> System.out.println("子线程干活"));
t.start();
t.join();  // 主线程阻塞，直到 t 结束
System.out.println("等子线程干完了");

    2. 创建线程¶

    知识点：

    • 四种方式：继承 Thread、实现 Runnable、实现 Callable（有返回值）、线程池 ⭐
    • ⭐ 推荐 Runnable/Callable：Java 单继承限制 + 任务与线程解耦
    • start() 启动新线程，直接调 run() 只是普通方法调用；start 只能调一次

    2.1 继承 Thread 类¶

    class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println(Thread.currentThread().getName() + " - " + i);
        }
    }
}

// 使用
MyThread t1 = new MyThread();
t1.start();  // 启动线程，JVM 调用 run()

    2.2 实现 Runnable 接口¶

    class MyRunnable implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println(Thread.currentThread().getName() + " - " + i);
        }
    }
}

// 使用
Thread t1 = new Thread(new MyRunnable());
t1.start();

// Lambda 简化（Runnable 是函数式接口）
Thread t2 = new Thread(() -> {
    for (int i = 0; i < 5; i++) {
        System.out.println(Thread.currentThread().getName() + " - " + i);
    }
});
t2.start();

    2.3 实现 Callable 接口（有返回值）¶

    import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) {
            sum += i;
        }
        return sum;
    }
}

// 使用
FutureTask<Integer> task = new FutureTask<>(new MyCallable());
Thread t1 = new Thread(task);
t1.start();

// 获取返回值
Integer result = task.get();  // 阻塞等待结果，可抛 InterruptedException/ExecutionException
System.out.println("结果：" + result);  // 5050

    2.4 四种方式对比¶

    方式 优点 缺点 推荐
    Thread 简单 不能继承其他类 ❌
    Runnable 可继承、可共享 无返回值 ⭐⭐
    Callable 有返回值、可抛异常 较复杂 ⭐⭐⭐
    线程池 高效、可管理 需理解配置 ⭐⭐⭐⭐

    为什么推荐 Runnable/Callable？① Java 单继承，继承 Thread 就不能继承别的类；② 任务与线程解耦，同一个任务可以提交给线程池；③ 实际开发中几乎总是通过线程池提交任务。

    3. 线程同步¶

    知识点：

    • 三大同步手段：synchronized（JVM 级）、volatile（可见性+有序性）、ReentrantLock（API 级，功能多）
    • ⭐ synchronized 锁升级：无锁→偏向锁→轻量级锁→重量级锁（JDK 15+ 偏向锁默认禁用）
    • ⭐ volatile 不保证原子性，count++ 仍不安全
    • 死锁四条件：互斥、持有并等待、不可剥夺、循环等待——破坏任一即可避免

    3.1 synchronized 关键字¶

    三种用法：

    class Counter {
    private int count = 0;

    // 1. 同步实例方法：锁是 this
    public synchronized void increment() {
        count++;
    }

    // 2. 同步静态方法：锁是 Counter.class
    public static synchronized void staticMethod() { }

    // 3. 同步代码块：锁是指定对象（推荐，锁粒度可控）
    private final Object lock = new Object();
    public void blockDemo() {
        synchronized (lock) {
            count++;
        }
    }
}

    底层原理：

    • 代码块层面：字节码 monitorenter / monitorexit 指令，每个对象关联一个 monitor（管程）
    • 方法层面：方法访问标志 ACC_SYNCHRONIZED
    • monitor 记录持有线程和重入次数，所以 synchronized 是可重入锁（同一线程重复进入同一把锁不会死锁）

    锁升级 ⭐⭐⭐（JDK 6 引入的优化，由 JVM 自动完成）：

    无锁 → 偏向锁 → 轻量级锁 → 重量级锁（只能升级不能降级）
    锁状态 场景 实现 开销
    偏向锁 始终只有一个线程访问 对象头记录线程 ID，下次进入只比对 ID 几乎无
    轻量级锁 两个线程交替访问（无竞争） CAS 修改对象头，失败则自旋 自旋消耗 CPU
    重量级锁 多线程真正竞争 升级为 OS 互斥量，未获得锁的线程阻塞挂起 用户态↔内核态切换

    ⚠️ JDK 15 起偏向锁被默认禁用（JEP 374）。现代 CPU 上偏向锁收益甚微且维护成本高，-XX:+UseBiasedLocking 相关选项已废弃。面试时答"无锁→偏向锁→轻量级锁→重量级锁"的同时补一句"JDK 15+ 偏向锁默认关闭"，是加分项。

    对象头（Mark Word）存储锁信息，64 位 JVM 中占 8 字节，锁状态就记录在其中。

    3.2 volatile 关键字¶

    class Flag {
    private volatile boolean running = true;

    public void stop() {
        running = false;
    }

    public void run() {
        while (running) {
            // 每次循环都会读取最新值
        }
    }
}

    volatile 作用：

    • ✅ 保证可见性（一个线程修改，写回主内存，其他线程立即看到）
    • ✅ 禁止指令重排序（内存屏障；经典应用：双重检查单例的 instance 必须加 volatile，防止拿到"半初始化"对象）
    • ❌ 不保证原子性（count++ 这种复合操作仍然不安全，要用 AtomicInteger 或锁）

    volatile vs synchronized：volatile 只能修饰变量，保证可见性/有序性；synchronized 可修饰方法/代码块，同时保证原子性、可见性、有序性。

    3.3 ReentrantLock¶

    import java.util.concurrent.locks.ReentrantLock;

class Counter {
    private int count = 0;
    private final ReentrantLock lock = new ReentrantLock();

    public void increment() {
        lock.lock();
        try {
            count++;
        } finally {
            lock.unlock();  // 必须在 finally 释放，否则异常时死锁
        }
    }
}

    ReentrantLock 独有能力：

    ReentrantLock lock = new ReentrantLock(true);  // true = 公平锁（按等待顺序获取）

// 1. 可中断获取锁
lock.lockInterruptibly();

// 2. 超时尝试
if (lock.tryLock(1, TimeUnit.SECONDS)) {
    try { /* ... */ } finally { lock.unlock(); }
}

// 3. 条件变量（比 wait/notify 更精确的唤醒）
Condition notEmpty = lock.newCondition();
notEmpty.await();      // 等待（替代 wait）
notEmpty.signal();     // 唤醒一个（替代 notify）
notEmpty.signalAll();  // 唤醒全部（替代 notifyAll）

    synchronized vs ReentrantLock：

    特性 synchronized ReentrantLock
    实现 JVM 层面（字节码） API 层面（java.util.concurrent）
    锁释放 自动（出块/抛异常） 手动（必须 finally unlock）
    可中断 ❌ ✅ lockInterruptibly
    超时获取 ❌ ✅ tryLock(timeout)
    公平锁 ❌ ✅ 构造参数可选
    条件变量 单一等待队列 多个 Condition
    可重入 ✅ ✅

    选择建议：简单同步优先 synchronized（写法简单、JVM 持续优化）；需要可中断/超时/公平/多条件时用 ReentrantLock。

    3.4 死锁 ⭐⭐⭐¶

    死锁的四个必要条件（破坏任意一个即可避免）：

    1. 互斥：资源一次只能被一个线程占用
    2. 持有并等待：持有资源的同时等待其他资源
    3. 不可剥夺：已获得的资源不能被强行夺走
    4. 循环等待：线程间形成等待环路
    // 经典死锁示例：两个线程以相反顺序获取两把锁
Object lockA = new Object();
Object lockB = new Object();

new Thread(() -> {
    synchronized (lockA) {
        try { Thread.sleep(100); } catch (InterruptedException e) {}
        synchronized (lockB) { System.out.println("线程1完成"); }
    }
}).start();

new Thread(() -> {
    synchronized (lockB) {
        try { Thread.sleep(100); } catch (InterruptedException e) {}
        synchronized (lockA) { System.out.println("线程2完成"); }
    }
}).start();
// 两线程互相等待对方手里的锁 → 永远阻塞

    排查与避免：

    • jstack <pid> 打印线程栈，会直接标注 Found one Java-level deadlock
    • jconsole 图形界面点"检测死锁"
    • 避免方法：固定加锁顺序、使用 tryLock 超时退让、缩小锁粒度

    3.5 线程中断机制¶

    Java 没有强制停止线程的安全方法（stop() 已废弃），标准做法是协作式中断：

    Thread worker = new Thread(() -> {
    // 循环检查中断标记
    while (!Thread.currentThread().isInterrupted()) {
        try {
            Thread.sleep(1000);  // sleep 期间被中断 → 抛 InterruptedException 并清除标记
        } catch (InterruptedException e) {
            // 二选一：
            // 1. 退出循环
            Thread.currentThread().interrupt();  // 恢复标记（因为异常清除了它）
            break;
            // 2. 或者向上抛出，让调用者处理
        }
    }
    System.out.println("线程收到中断，清理资源后退出");
});
worker.start();

// 主线程请求中断（只是设置标记，不是强杀）
worker.interrupt();
    方法 说明
    t.interrupt() 设置 t 的中断标记；若 t 正在 sleep/wait/join，则抛 InterruptedException
    t.isInterrupted() 查询 t 的中断标记（不清除）
    Thread.interrupted() 查询当前线程的中断标记（会清除）

    4. 线程池 ⭐⭐⭐¶

    知识点：

    • ⭐ 为什么用线程池：复用线程降低开销、控制并发度防 OOM、统一管理
    • ⭐ ThreadPoolExecutor 七大参数 + 四步提交流程（核心线程→队列→非核心线程→拒绝策略）必背
    • ⚠️ 禁止用 Executors 工厂创建（无界队列/无上限线程数可能 OOM）
    • 四种拒绝策略：AbortPolicy（默认）/CallerRunsPolicy/DiscardPolicy/DiscardOldestPolicy

    4.1 为什么用线程池¶

    • 降低开销：线程创建/销毁成本高，池化复用
    • 可控并发度：防止无限创建线程耗尽内存（每个线程默认 1MB 栈空间）
    • 统一管理：调度、监控、拒绝策略

    4.2 使用 Executors 创建（了解即可，不推荐）¶

    import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

// 固定大小线程池（队列无界，可能 OOM）
ExecutorService fixedPool = Executors.newFixedThreadPool(10);

// 单线程池（保证任务顺序执行）
ExecutorService singlePool = Executors.newSingleThreadExecutor();

// 缓存线程池（最大线程数 Integer.MAX_VALUE，可能创建海量线程）
ExecutorService cachedPool = Executors.newCachedThreadPool();

// 定时任务
ScheduledExecutorService scheduledPool = Executors.newScheduledThreadPool(5);
scheduledPool.scheduleAtFixedRate(() -> {
    System.out.println("定时执行");
}, 0, 1, TimeUnit.SECONDS);

    《阿里巴巴 Java 开发手册》强制规定：禁止使用 Executors 创建线程池——fixed/single 的阻塞队列是无界的 LinkedBlockingQueue（可能堆积 OOM），cached 的最大线程数是 Integer.MAX_VALUE（可能创建海量线程 OOM）。应手动 new ThreadPoolExecutor 明确参数。

    4.3 ThreadPoolExecutor（推荐）¶

    import java.util.concurrent.*;

ThreadPoolExecutor executor = new ThreadPoolExecutor(
    5,                      // corePoolSize：核心线程数
    10,                     // maximumPoolSize：最大线程数
    60L,                    // keepAliveTime：非核心线程空闲存活时间
    TimeUnit.SECONDS,       // 时间单位
    new ArrayBlockingQueue<>(100),  // workQueue：有界任务队列
    Executors.defaultThreadFactory(),  // 线程工厂（可自定义线程名便于排查）
    new ThreadPoolExecutor.CallerRunsPolicy()  // handler：拒绝策略
);

executor.submit(() -> {
    System.out.println("任务执行");
});

executor.shutdown();  // 平滑关闭：不再接新任务，已提交的任务执行完

    七大参数：corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler。

    任务提交流程 ⭐（必背）：

    提交任务
  │
  ├─ 核心线程未满（< corePoolSize）→ 创建核心线程执行
  │
  ├─ 核心线程已满 → 任务入队 workQueue
  │
  ├─ 队列已满且总线程 < maximumPoolSize → 创建非核心线程执行
  │
  └─ 队列已满且达到 maximumPoolSize → 执行拒绝策略

    四种拒绝策略：

    策略 行为
    AbortPolicy（默认） 抛 RejectedExecutionException
    CallerRunsPolicy 由提交任务的线程自己执行（天然限流）
    DiscardPolicy 静默丢弃新任务
    DiscardOldestPolicy 丢弃队列最老任务，重试提交

    线程数经验值：

    • CPU 密集型：线程数 ≈ CPU 核数 + 1（多一个防偶发缺页中断）
    • IO 密集型：线程数 ≈ CPU 核数 × 2（或 核数 × (1 + 等待时间/计算时间)）
    • 实际要压测调参，公式只是起点

    execute vs submit：execute 提交 Runnable 无返回值；submit 提交 Runnable/Callable 返回 Future，且能捕获任务异常（execute 的异常直接抛出）。

    shutdown vs shutdownNow：shutdown 不接新任务、等已提交任务完成；shutdownNow 尝试中断正在执行的任务、返回未执行的任务列表。

    5. 线程通信¶

    知识点：

    • wait/notify：Object 方法，必须在 synchronized 块内；wait 释放锁，sleep 不释放
    • ⭐ CountDownLatch（一次性，一个等多个）vs CyclicBarrier（可复用，互相等）
    • wait 判断条件必须用 while 循环（防虚假唤醒），推荐 notifyAll

    5.1 wait/notify（Object 方法）¶

    // wait/notify 必须在 synchronized 块内调用，否则抛 IllegalMonitorStateException
synchronized (lock) {
    while (条件不满足) {   // 必须用 while，防止虚假唤醒
        lock.wait();       // 释放锁并等待
    }
    // 条件满足，执行业务
}

// 另一线程
synchronized (lock) {
    // 改变条件
    lock.notifyAll();      // 唤醒所有等待线程（推荐 notifyAll 而非 notify）
}

    5.2 CountDownLatch¶

    import java.util.concurrent.CountDownLatch;

CountDownLatch latch = new CountDownLatch(3);

// 线程 1
new Thread(() -> {
    System.out.println("任务 1 完成");
    latch.countDown();
}).start();

// 线程 2
new Thread(() -> {
    System.out.println("任务 2 完成");
    latch.countDown();
}).start();

// 线程 3
new Thread(() -> {
    System.out.println("任务 3 完成");
    latch.countDown();
}).start();

// 主线程等待
latch.await();
System.out.println("所有任务完成");

    5.3 CyclicBarrier¶

    import java.util.concurrent.CyclicBarrier;

CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("所有线程到达，执行屏障动作");
});

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        System.out.println("线程到达");
        try {
            barrier.await();
        } catch (Exception e) {
            e.printStackTrace();
        }
        System.out.println("继续执行");
    }).start();
}

    5.4 CountDownLatch vs CyclicBarrier¶

    CountDownLatch CyclicBarrier
    计数 减到 0 触发，一次性 全部到达触发，可复用（reset）
    角色 一个线程等多个线程 多个线程互相等待
    典型场景 主线程等所有子任务完成 多线程分段计算后合并

    更多工具类见 并发工具类详解。

    6. 经典问题¶

    知识点：

    • ⭐ 生产者-消费者：手写用 wait/notify + while 判条件；生产直接用 BlockingQueue
    • 双重检查单例：instance 必须 volatile（防指令重排导致半初始化对象）

    6.1 生产者 - 消费者¶

    class ProducerConsumer {
    private final Queue<Integer> queue = new LinkedList<>();
    private final int LIMIT = 10;
    private final Object lock = new Object();

    class Producer implements Runnable {
        public void run() {
            int value = 0;
            while (true) {
                synchronized (lock) {
                    while (queue.size() == LIMIT) {
                        try { lock.wait(); } catch (InterruptedException e) {}
                    }
                    queue.offer(value++);
                    lock.notifyAll();
                }
            }
        }
    }

    class Consumer implements Runnable {
        public void run() {
            while (true) {
                synchronized (lock) {
                    while (queue.isEmpty()) {
                        try { lock.wait(); } catch (InterruptedException e) {}
                    }
                    queue.poll();
                    lock.notifyAll();
                }
            }
        }
    }
}

    生产环境直接用 BlockingQueue：queue.put() / queue.take() 自带阻塞语义，不需要手写 wait/notify。

    6.2 单例模式（双重检查）¶

    class Singleton {
    private static volatile Singleton instance;  // volatile 防止指令重排

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

    instance = new Singleton() 实际分三步：① 分配内存 → ② 初始化对象 → ③ 引用赋值。不加 volatile 可能被重排为 ①③②，其他线程会拿到未初始化完成的对象。

    7. 常见面试题¶

    Q1：start() 和 run() 的区别？ start() 启动新线程并由 JVM 调用 run()；直接调 run() 只是当前线程的普通方法调用，不会并发执行。start() 只能调用一次，重复调用抛 IllegalStateException。

    Q2：sleep 和 wait 的区别？ → 见 1.3 节对比表。

    Q3：synchronized 的锁升级过程？ → 见 3.1 节。注意 JDK 15+ 偏向锁默认禁用。

    Q4：volatile 能保证线程安全吗？ 不能完全保证。它解决可见性和有序性，但 count++ 这类复合操作不是原子的，仍需要锁或原子类。

    Q5：如何停止一个线程？ 不能强杀（stop() 已废弃）。用中断机制：interrupt() 设置标记，任务内部检查 isInterrupted() 或捕获 InterruptedException 后自行退出。

    Q6：为什么线程池不推荐用 Executors 创建？ 无界队列/无上限线程数可能导致 OOM，应手动 new ThreadPoolExecutor 指定参数。

    Q7：说说线程池的工作流程？ → 见 4.3 节四步流程。

    Q8：如何避免死锁？ 破坏四个必要条件之一：固定加锁顺序（破坏循环等待）、tryLock 超时（破坏持有并等待）、减小锁粒度。

    8. 练习题¶

    练习 1（Callable）：使用 Callable + FutureTask 计算 1~100 的和，主线程获取并打印结果。

    练习 2（线程安全取款）：账户余额 1000，两个线程各尝试取款 800，用 synchronized 保证不会出现超额取款。

    练习 3（线程池 + CountDownLatch）：用固定大小线程池执行 3 个任务，主线程通过 CountDownLatch 等待全部完成后输出汇总。

    练习 4（交替打印）：两个线程交替打印 1-100（线程 A 打印奇数，线程 B 打印偶数），用 wait/notify 实现。

    练习 5（中断）：写一个工作线程循环打印计数，主线程 3 秒后 interrupt 它，工作线程优雅退出。

    参考答案¶

    import java.util.concurrent.*;

public class ThreadExercises {

    public static void main(String[] args) throws Exception {
        // 练习 1：Callable 有返回值，配合 FutureTask 获取
        Callable<Integer> sumTask = () -> {
            int sum = 0;
            for (int i = 1; i <= 100; i++) sum += i;
            return sum;
        };
        FutureTask<Integer> future = new FutureTask<>(sumTask);
        new Thread(future).start();
        System.out.println("1~100 的和 = " + future.get()); // get() 阻塞等待结果：5050
        // 练习 2：同步取款
        Account account = new Account(1000);
        Runnable withdraw = () -> account.withdraw(800);
        new Thread(withdraw, "线程A").start();
        new Thread(withdraw, "线程B").start();
        Thread.sleep(500); // 等待两个取款线程执行完

        // 练习 3：线程池 + CountDownLatch
        int taskCount = 3;
        CountDownLatch latch = new CountDownLatch(taskCount);
        ExecutorService pool = Executors.newFixedThreadPool(taskCount);
        for (int i = 1; i <= taskCount; i++) {
            int taskId = i;
            pool.submit(() -> {
                try {
                    System.out.println("任务" + taskId + " 完成");
                } finally {
                    latch.countDown(); // 每完成一个任务，计数减 1
                }
            });
        }
        latch.await(); // 阻塞，直到计数归零
        System.out.println("全部任务完成，开始汇总");
        pool.shutdown(); // 用完关闭线程池

        // 练习 4：交替打印
        printAlternate();

        // 练习 5：中断
        interruptDemo();
    }

    // 练习 2：线程安全账户
    static class Account {
        private int balance;

        Account(int balance) { this.balance = balance; }

        // synchronized 保证同一时刻只有一个线程执行取款，
        // "检查余额 + 扣款"成为原子操作
        synchronized void withdraw(int amount) {
            if (balance >= amount) {
                balance -= amount;
                System.out.println(Thread.currentThread().getName() + " 取款 " + amount + " 成功，余额 " + balance);
            } else {
                System.out.println(Thread.currentThread().getName() + " 余额不足，取款失败");
            }
        }
    }

    // 练习 4：wait/notify 交替打印
    static void printAlternate() throws InterruptedException {
        Object lock = new Object();
        final int MAX = 100;
        Runnable printer = () -> {
            // 每个线程负责步长为 2 的数列：A 从 1 开始，B 从 2 开始
            int start = Thread.currentThread().getName().equals("A") ? 1 : 2;
            for (int i = start; i <= MAX; i += 2) {
                synchronized (lock) {
                    System.out.println(Thread.currentThread().getName() + ": " + i);
                    lock.notify();   // 唤醒对方
                    try {
                        if (i + 2 <= MAX) lock.wait();  // 自己等待（最后一轮不再等）
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                    }
                }
            }
        };
        new Thread(printer, "A").start();
        Thread.sleep(50);  // 确保 A 先启动先拿锁
        new Thread(printer, "B").start();
    }

    // 练习 5：中断优雅退出
    static void interruptDemo() throws InterruptedException {
        Thread worker = new Thread(() -> {
            int count = 0;
            while (!Thread.currentThread().isInterrupted()) {
                System.out.println("工作中... " + (++count));
                try {
                    Thread.sleep(500);
                } catch (InterruptedException e) {
                    // sleep 被打断会清除中断标记，这里恢复标记并退出
                    Thread.currentThread().interrupt();
                }
            }
            System.out.println("收到中断信号，优雅退出");
        });
        worker.start();
        Thread.sleep(3000);
        worker.interrupt();  // 3 秒后请求中断
        worker.join();
    }
}

    9. 本章小结¶

    核心知识点¶

    ✅ 线程状态：NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED 六种
    ✅ 创建线程：Thread、Runnable、Callable、线程池
    ✅ 线程同步：synchronized（锁升级）、volatile（可见性+有序性）、ReentrantLock（可中断/超时/公平/Condition）
    ✅ 死锁：四条件、jstack 排查、固定加锁顺序
    ✅ 中断机制：interrupt + isInterrupted 协作式退出
    ✅ 线程通信：wait/notify、CountDownLatch、CyclicBarrier
    ✅ 线程池：七大参数、四步提交流程、四种拒绝策略

    最佳实践¶

    1. 优先使用线程池，不要手动创建线程；不用 Executors 工厂，手动指定参数
    2. 优先使用并发工具类（ConcurrentHashMap、CountDownLatch、BlockingQueue）
    3. 避免死锁：按顺序获取锁、使用 tryLock
    4. 停止线程用中断，不用已废弃的 stop()
    5. wait 用 while 循环判断条件，推荐 notifyAll
    6. 合理设置线程池参数：CPU 密集 vs IO 密集
