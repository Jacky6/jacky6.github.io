    03_注解¶

    1. 注解概述¶

    知识点： - ⭐ 注解本质：贴在代码上的'便利贴'（元数据），本身不执行逻辑，起作用靠读取者 - 三个使用层面：编译检查（@Override）、运行时反射读取（Spring）、编译期代码生成（Lombok）

    1.1 什么是注解¶

    注解（Annotation）是 Java 5 引入的元数据机制，用于为代码添加标记和信息。

    ⭐ 注解的本质（理解的关键）：注解本身不执行任何逻辑——它只是贴在代码上的"便利贴"（元数据，即"描述数据的数据"）。真正起作用的是读取便利贴的人： - 编译器读 @Override → 检查是否真的重写了 - Spring 框架在启动时读 @Component → 把类注册成 Bean - 你写的代码读自定义注解 → 做任何你想做的事（反射章节有示例）

    所以学注解要学两件事：怎么写便利贴（定义注解）和怎么读便利贴（反射/注解处理器）。

    作用： - ✅ 编译检查（如 @Override） - ✅ 运行时处理（如 Spring 的 @Autowired） - ✅ 生成文档（如 @author）

    // 使用注解
@Override
public String toString() {
    return "Hello";
}

@Deprecated
public void oldMethod() {
}

    1.2 内置注解¶

    注解 说明
    @Override 重写父类方法
    @Deprecated 标记已过时
    @SuppressWarnings 忽略警告
    @FunctionalInterface 标记函数式接口

    2. 元注解¶

    知识点： - 元注解 = 定义注解的注解，四个：@Target（贴哪）、@Retention（活多久）、@Documented、@Inherited - ⭐ Retention 三档：SOURCE（编译器看）/ CLASS（默认）/ RUNTIME（反射可读，自定义注解必选）

    2.1 元注解类型¶

    元注解是用于定义注解的注解。

    元注解 说明
    @Target 注解作用目标
    @Retention 注解保留策略
    @Documented 是否包含在 Javadoc
    @Inherited 是否可继承
    @Repeatable 是否可重复

    2.2 @Target¶

    import java.lang.annotation.*;

// 注解可以用于类、方法、字段
@Target({ElementType.TYPE, ElementType.METHOD, ElementType.FIELD})
@interface MyAnnotation {
}

// 可用目标
ElementType.TYPE           // 类、接口、枚举
ElementType.METHOD         // 方法
ElementType.FIELD          // 字段
ElementType.PARAMETER      // 参数
ElementType.CONSTRUCTOR    // 构造方法
ElementType.LOCAL_VARIABLE // 局部变量

    2.3 @Retention¶

    // 保留策略
@Retention(RetentionPolicy.SOURCE)  // 仅源代码，编译后丢弃
@Retention(RetentionPolicy.CLASS)   // 编译到 class 文件，运行时不可见
@Retention(RetentionPolicy.RUNTIME) // 运行时可见（反射可用）

// 示例
@Retention(RetentionPolicy.RUNTIME)
@interface MyAnnotation {
}

    ⭐ 三种策略的实际对应（帮助记忆）： - SOURCE：只给编译器/代码生成器看 → @Override（编译检查）、Lombok 注解（编译期生成代码） - CLASS：默认值，很少直接用 - RUNTIME：需要反射读取 → Spring 的 @Component/@Autowired、自定义注解几乎都选它

    3. 自定义注解¶

    知识点： - 语法：@interface + 属性方法（可带 default 默认值） - ⚠️ 属性类型受限：基本类型/String/Class/枚举/数组

    3.1 定义注解¶

    @Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MyAnnotation {
    // 属性
    String value();
    int count() default 1;
}

    3.2 使用注解¶

    public class Test {
    @MyAnnotation(value = "test", count = 5)
    public void method() {
    }

    // 如果只有一个 value 属性，可以省略
    @MyAnnotation("test")
    public void method2() {
    }
}

    3.3 注解属性¶

    public @interface MyAnnotation {
    // 基本类型
    int value();
    String name() default "default";

    // 数组
    String[] tags() default {};

    // 枚举
    Level level() default Level.INFO;

    // 注解
    AnotherAnnotation another();

    // Class
    Class<?> clazz() default Object.class;
}

enum Level {
    INFO, WARN, ERROR
}

    4. 注解处理器¶

    知识点： - 读注解两条路：运行时反射（isAnnotationPresent + getAnnotation）、编译期 APT - Spring 启动时扫描 @Component 就是'读便利贴'的典型例子

    4.1 反射获取注解¶

    public class AnnotationProcessor {
    public static void processMethod(Method method) {
        if (method.isAnnotationPresent(MyAnnotation.class)) {
            MyAnnotation anno = method.getAnnotation(MyAnnotation.class);
            System.out.println("Value: " + anno.value());
            System.out.println("Count: " + anno.count());
        }
    }

    public static void processClass(Class<?> clazz) {
        for (Method method : clazz.getDeclaredMethods()) {
            processMethod(method);
        }
    }
}

    4.2 注解处理示例¶

    // 定义注解
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Test {
    String name();
}

// 使用注解
public class TestClass {
    @Test(name = "test1")
    public void testMethod1() {
    }

    @Test(name = "test2")
    public void testMethod2() {
    }
}

// 处理器
public class TestRunner {
    public static void runTests(Object obj) throws Exception {
        Class<?> clazz = obj.getClass();

        for (Method method : clazz.getDeclaredMethods()) {
            if (method.isAnnotationPresent(Test.class)) {
                Test test = method.getAnnotation(Test.class);
                System.out.println("Running: " + test.name());
                method.setAccessible(true);
                method.invoke(obj);
            }
        }
    }
}

    6. 进阶用法¶

    知识点： - @Repeatable：同一位置重复贴（Java 8）；类型注解（Java 8）可贴在类型使用处 - ⭐ APT（编译期注解处理）：Lombok/MapStruct 的原理，编译时生成代码，零运行时开销

    6.1 @Repeatable：可重复注解¶

    Java 8 之前，同一位置不能重复使用同一个注解。@Repeatable 解决此问题。

    // 容器注解
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Schedules {
    Schedule[] value();
}

// 可重复注解
@Repeatable(Schedules.class)   // ⭐ 指定容器
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Schedule {
    String cron();
}

// 使用：同一方法上重复标注
public class Job {
    @Schedule(cron = "0 0 9 * * ?")
    @Schedule(cron = "0 0 18 * * ?")
    public void report() { }
}

// 读取
Schedule[] schedules = method.getAnnotationsByType(Schedule.class);

    6.2 编译期注解处理（APT）¶

    除了运行时反射，注解还能在编译期被处理——这就是 Lombok、MapStruct、Dagger 的原理。

    // 注解处理器（简化示意）
@SupportedAnnotationTypes("com.example.MyAnnotation")
@SupportedSourceVersion(SourceVersion.RELEASE_17)
public class MyProcessor extends AbstractProcessor {

    @Override
    public boolean process(Set<? extends TypeElement> annotations,
                           RoundEnvironment roundEnv) {
        for (Element element : roundEnv.getElementsAnnotatedWith(MyAnnotation.class)) {
            // 编译期扫描被标注的元素，可以生成新代码
            System.out.println("发现注解：" + element.getSimpleName());
        }
        return true;
    }
}

    运行期 vs 编译期处理对比：

    对比项 运行期（反射） 编译期（APT）
    时机 程序运行时 javac 编译时
    Retention RUNTIME SOURCE/CLASS
    性能开销 有（反射慢） 无（编译完就结束）
    典型框架 Spring、JUnit Lombok、MapStruct

    Lombok 的 @Getter/@Setter 就是在编译期自动生成 getter/setter 字节码，源码里看不到。

    6.3 Java 8 类型注解¶

    Java 8 起注解可以出现在更多位置（TYPE_USE）：

    // 泛型参数
List<@NonNull String> names;

// 方法返回值
@NonNull String getName() { ... }

// 类型转换
Object obj = (@NonNull String) input;

    7. 常见面试题¶

    Q1：注解的本质是什么？

    注解本质是继承 java.lang.annotation.Annotation 的接口。@interface 定义注解，属性其实是接口的抽象方法，反射拿到的注解实例是 JDK 动态代理生成的。

    Q2：@Retention 三种策略的区别和使用场景？

    • SOURCE：编译后丢弃，如 @Override（给编译器看的）、Lombok 注解
    • CLASS：保留在 class 文件但运行时不可见（默认值），字节码增强工具用
    • RUNTIME：运行时可反射读取，Spring/JUnit 注解都用这个

    Q3：Spring 注解是运行期还是编译期处理？

    运行期。Spring 启动时通过反射扫描 @Component、@Autowired 等注解，完成 Bean 注册和依赖注入。

    Q4：@Inherited 的作用？

    让注解可以被子类继承（仅对类生效，对接口/方法无效）。比如父类标了 @MyAnno，子类未标注时也能通过 getClass().getAnnotation() 读到。

    8. 练习题¶

    1. 权限注解：定义 @RequireRole(value = "admin")，配合反射实现简易权限检查：方法上有注解且角色匹配才允许调用。
    2. 单测框架雏形：定义 @Test 注解（无属性），写一个 Runner 扫描并执行所有标注方法，统计成功/失败数。
    3. 判断输出：@Retention(SOURCE) 的注解能通过反射读到吗？为什么？

    参考答案¶

    // 练习 1
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface RequireRole {
    String value();
}

public class PermissionChecker {
    public static void invoke(Object target, String methodName, String userRole)
            throws Exception {
        Method method = target.getClass().getMethod(methodName);
        RequireRole anno = method.getAnnotation(RequireRole.class);
        if (anno != null && !anno.value().equals(userRole)) {
            throw new SecurityException("需要角色：" + anno.value());
        }
        method.invoke(target);
    }
}

// 练习 2 核心逻辑
int pass = 0, fail = 0;
for (Method m : clazz.getDeclaredMethods()) {
    if (m.isAnnotationPresent(Test.class)) {
        try {
            m.invoke(obj);
            pass++;
        } catch (Exception e) {
            fail++;
            System.out.println("失败：" + m.getName());
        }
    }
}
System.out.printf("通过 %d，失败 %d%n", pass, fail);

// 练习 3：读不到。
// SOURCE 策略的注解在编译时就被丢弃，不会进入 class 文件，运行时自然不存在。

    9. 本章小结¶

    核心知识点¶

    ✅ 内置注解：@Override、@Deprecated
    ✅ 元注解：@Target、@Retention、@Documented
    ✅ 自定义注解：定义、属性、使用
    ✅ 注解处理：反射获取注解

    最佳实践¶

    1. 使用 RUNTIME 保留策略：运行时可通过反射获取
    2. 明确 Target：指定注解可用位置
    3. 提供默认值：简化注解使用
    4. 使用 value 属性：简化单属性注解
    5. 结合反射使用：实现框架功能
