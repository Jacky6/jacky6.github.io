    06_SpringBoot 进阶¶

    前置：已学完 03_SpringBoot 基础篇。本篇基于 JDK 17 + Spring Boot 3.5.x，深挖六大进阶主题：自动配置原理、手写 Starter、配置体系、3.x 新特性、生产部署、问题排查。 ⭐ 本篇所有代码与结论均在 Spring Boot 3.5.16 实机验证（验证工程位于本机 /tmp/sbverify/）。

    本篇总览： - ⭐ 自动配置 = @EnableAutoConfiguration → 读 AutoConfiguration.imports → 条件装配（@Conditional 家族） - ⭐ 手写 Starter 四件套：Properties 类 + 自动配置类 + .imports 注册文件 + @ConditionalOnMissingBean - ⭐ 配置绑定首选 @ConfigurationProperties（类型安全 + 校验），@Value 只用于单值 - ⭐ Boot 3.x 三大变化：JDK 17 起步、jakarta 命名空间、GraalVM Native Image - ⭐ 生产部署四配置：优雅停机、Tomcat 线程池、HikariCP 连接池、JVM 参数 - ⭐ 排查五连问：启动失败看 Caused by、Bean 冲突看 --debug、配置不生效看 Environment

    1. 本章定位：从"会用"到"懂原理"¶

    基础篇（03 章）解决的问题：怎么创建项目、怎么写配置、怎么测试打包
进阶篇（本章）解决的问题：
    ① 为什么引入 starter 就自动有了功能？（自动配置原理）
    ② 能不能自己写一个 starter？（Starter 机制）
    ③ 配置到底怎么加载的，谁覆盖谁？（配置优先级）
    ④ Boot 3.x 相对 2.x 变了什么？（版本迁移）
    ⑤ 上线前还差什么配置？（生产部署）
    ⑥ 出了问题怎么查？（排查方法论）

    一句话类比：基础篇教你"开车"，进阶篇教你"打开引擎盖看发动机"——面试问的全是发动机。

    2. 自动配置原理深挖 ⭐⭐⭐⭐¶

    知识点： - ⭐ @SpringBootApplication = @SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan - ⭐ 自动配置类清单在 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（Boot 2.7+ 新机制，取代旧的 spring.factories） - ⭐ 条件装配：每个自动配置类都带 @Conditional 条件，满足才生效 - 排除自动配置：exclude 属性或 spring.autoconfigure.exclude

    2.1 @SpringBootApplication 三合一拆解¶

    // 你每天写的启动类，其实是三个注解的合体
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

// 展开看源码（简化）：
@SpringBootConfiguration      // 本质是 @Configuration：启动类本身是配置类，可写 @Bean
@EnableAutoConfiguration      // ⭐ 核心：触发自动配置
@ComponentScan                // 扫描启动类所在包及子包
public @interface SpringBootApplication { }

    ⚠️ @ComponentScan 不指定包名时扫描启动类所在包——所以启动类必须放在项目根包（com.example），不能放进 com.example.config，否则扫不到 Controller/Service。这是新手最常见的"Bean 找不到"原因。

    2.2 自动配置类的发现机制¶

    核心问题：引入 spring-boot-starter-web 后，Tomcat、DispatcherServlet、Jackson 是怎么"凭空出现"的？

    启动流程（自动配置部分）：

① @EnableAutoConfiguration
       ↓
② @Import(AutoConfigurationImportSelector.class)
       ↓
③ AutoConfigurationImportSelector 读取所有 jar 中的：
   META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
   （每行一个自动配置类全限定名，Boot 2.7+ 机制）
       ↓
④ 收集到 ~150 个自动配置类（如 ServletWebServerFactoryAutoConfiguration、
   DispatcherServletAutoConfiguration、JacksonAutoConfiguration...）
       ↓
⑤ 条件过滤：逐个评估每个类上的 @Conditional 条件
       ↓
⑥ 只有条件满足的才真正注册为 Bean（150 个通常只剩 30~50 个生效）

    验证方法：启动时加 --debug（或 debug: true），控制台打印 CONDITIONS EVALUATION REPORT，三个段落：

    Positive matches:      ← 条件满足、已生效的自动配置（及满足原因）
Negative matches:      ← 条件不满足、未生效的（及不满足原因）
Exclusions:            ← 被手动排除的

    # 实机验证输出（Boot 3.5.16 --debug）：
Positive matches:
-----------------
   AopAutoConfiguration matched:
      - @ConditionalOnProperty (spring.aop.auto=true) matched (OnPropertyCondition)

    💡 排查"为什么某功能没生效"的第一手段就是看 Negative matches 里的原因（比如 @ConditionalOnClass did not find required class 'javax.sql.DataSource' = 缺依赖）。

    2.3 条件装配：@Conditional 家族¶

    自动配置的"智能"全靠条件注解。常用的：

    条件注解 含义 典型用途
    @ConditionalOnClass classpath 存在某类 有 Jackson 才配 ObjectMapper
    @ConditionalOnMissingClass classpath 不存在某类 反向判断
    @ConditionalOnBean 容器已有某 Bean 依赖其他自动配置
    @ConditionalOnMissingBean ⭐ 容器还没有某 Bean 用户自定义优先
    @ConditionalOnProperty ⭐ 配置属性满足条件 功能开关
    @ConditionalOnWebApplication 是 Web 应用 只在 Web 环境生效

    最重要的两个：

    // ① @ConditionalOnMissingBean —— "我提供默认值，你随时可以覆盖"
@Bean
@ConditionalOnMissingBean
public ObjectMapper jacksonObjectMapper() {
    // 只有用户没有自己定义 ObjectMapper 时，才用这个默认的
    return new ObjectMapper();
}
// → 这就是"约定优于配置"的实现：引依赖就有默认行为，想定制就自己定义 Bean

// ② @ConditionalOnProperty —— 配置开关
@ConditionalOnProperty(prefix = "hello", name = "enabled",
        havingValue = "true", matchIfMissing = true)
// matchIfMissing=true：配置里不写这个属性时，默认视为 true（默认开启）

    实机验证：--hello.enabled=false 启动，starter 的 Bean 不再创建，注入方抛 UnsatisfiedDependencyException——证明开关真实生效。

    2.4 排除自动配置¶

    // 方式 1：注解排除（编译期确定）
@SpringBootApplication(exclude = { DataSourceAutoConfiguration.class })
public class DemoApplication { }

// 方式 2：配置排除（运行期可变，推荐）
// application.yml
spring:
  autoconfigure:
    exclude: org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration

    ⚠️ 经典场景：项目暂时不接数据库，但引了 spring-boot-starter-jdbc，启动会因缺数据源报错——排除 DataSourceAutoConfiguration 即可。

    3. 手写一个完整的 Starter ⭐⭐⭐⭐¶

    知识点： - ⭐ Starter 命名：官方 spring-boot-starter-xxx，第三方 xxx-spring-boot-starter - ⭐ 自动配置类靠 .imports 文件注册（Boot 2.7+，替代 spring.factories 的 EnableAutoConfiguration 条目） - ⭐ 三件套：Properties（配置绑定）+ AutoConfiguration（条件装配）+ .imports（注册） - 本节代码全部实机验证：mvn install 后在 demo 工程中注入成功

    3.1 Starter 的本质¶

    Starter = 依赖聚合（pom） + 自动配置（autoconfigure）

spring-boot-starter-web 的 pom 里其实只有依赖：
    spring-web、spring-webmvc、spring-boot-starter-json、
    spring-boot-starter-tomcat、spring-boot-starter-validation
真正的自动配置逻辑在 spring-boot-autoconfigure 这个 jar 里。

自己的 Starter 通常一个模块搞定（依赖 + 自动配置放一起）。

    3.2 实战：hello-spring-boot-starter¶

    目标：提供 hello.greet(name) 功能，支持 hello.* 配置，默认开启，用户可自定义实现。

    第 1 步：pom.xml

    <dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-autoconfigure</artifactId>
    </dependency>
    <!-- 可选依赖：用到才传递，用户工程按需引入 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
        <optional>true</optional>
    </dependency>
</dependencies>

    第 2 步：配置属性类（@ConfigurationProperties）

    @Validated  // 开启 JSR-380 校验
@ConfigurationProperties(prefix = "hello")
public class HelloProperties {
    private boolean enabled = true;              // 默认开启

    @NotBlank(message = "hello.prefix 不能为空")
    private String prefix = "Hello";             // 默认前缀

    @Min(value = 1, message = "hello.retry-count 最小为 1")
    private int retryCount = 3;

    private Duration timeout = Duration.ofSeconds(1);  // 支持 "3s" 自动转换
    // getter/setter 省略
}

    第 3 步：核心功能类

    public class HelloService {
    private final HelloProperties properties;

    public HelloService(HelloProperties properties) {
        this.properties = properties;
    }

    public String greet(String name) {
        return properties.getPrefix() + ", " + name + "!";
    }
}

    第 4 步：自动配置类（条件装配三件套）

    @AutoConfiguration  // Boot 2.7+ 专用，自带 @Configuration(proxyBeanMethods=false)
@ConditionalOnProperty(prefix = "hello", name = "enabled",
        havingValue = "true", matchIfMissing = true)   // 开关，默认开
@EnableConfigurationProperties(HelloProperties.class)  // 注册并绑定属性类
public class HelloAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean  // 用户自定义 HelloService 优先
    public HelloService helloService(HelloProperties properties) {
        return new HelloService(properties);
    }
}

    第 5 步：注册文件（关键！）

    文件路径（一字不差）：
src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports

文件内容（每行一个自动配置类全限定名）：
com.example.hello.HelloAutoConfiguration

    第 6 步：使用方验证

    <!-- demo 工程 pom 引入 -->
<dependency>
    <groupId>com.example</groupId>
    <artifactId>hello-spring-boot-starter</artifactId>
    <version>1.0.0</version>
</dependency>

    # demo 工程 application.yml
hello:
  prefix: 你好
  retry-count: 5
  timeout: 3s

    @RestController
public class HelloController {
    private final HelloService helloService;  // 自动注入，无需任何配置！

    public HelloController(HelloService helloService) {
        this.helloService = helloService;
    }

    @GetMapping("/hello")
    public String hello() {
        return helloService.greet("yixiu");
    }
}

    实机验证输出：

    greet = 你好, yixiu!          ← 配置绑定 + 自动注入全部生效

    3.3 Starter 开发检查清单¶

    □ 属性类：@ConfigurationProperties + 合理默认值 + 校验注解
□ 自动配置类：@AutoConfiguration + @EnableConfigurationProperties
□ 所有 @Bean 都带 @ConditionalOnMissingBean（允许用户覆盖）
□ 提供 @ConditionalOnProperty 开关，且 matchIfMissing 符合直觉
□ .imports 文件路径拼写正确（最常见的错误）
□ 文档写清楚：有哪些配置项、默认值是什么

    ⚠️ Boot 2.7 前后差异（面试可能问）：2.7 之前用 META-INF/spring.factories 里的 org.springframework.boot.autoconfigure.EnableAutoConfiguration=... 注册；2.7+ 拆成独立的 .imports 文件（spring.factories 仍保留给其他 SPI 用途，但自动配置条目已废弃）。

    4. 配置体系深挖 ⭐⭐⭐¶

    知识点： - ⭐ 配置绑定首选 @ConfigurationProperties（类型安全、可校验、支持嵌套/列表/Duration） - 配置优先级：命令行 > 环境变量 > 系统属性 > profile 文件 > application 文件 > @PropertySource > 默认值 - 松散绑定：retry-count ↔ retryCount、APP_NAME ↔ app.name

    4.1 @ConfigurationProperties 全解¶

    // 支持：嵌套对象、List、Map、Duration、校验
@Validated
@ConfigurationProperties(prefix = "app")
public class AppProperties {

    @NotBlank
    private String name;

    private Admin admin = new Admin();   // 嵌套对象
    private List<Integer> ports;          // 逗号分隔或 yaml 列表
    private List<Feature> features;       // 复杂对象列表
    // getter/setter 省略

    public static class Admin {
        private String email;
        private Duration timeout;         // "2s" 自动转 Duration
        // getter/setter 省略
    }

    public static class Feature {
        private String name;
        private int weight;
        // getter/setter 省略
    }
}

// 激活绑定（二选一）：
// ① 配置类上加 @EnableConfigurationProperties(AppProperties.class)
// ② 启动类上加 @ConfigurationPropertiesScan（推荐，自动扫描）

    # 对应的 application.yml
app:
  name: demo-service
  admin:
    email: admin@example.com
    timeout: 2s
  ports: 8080,8081,8082      # 逗号分隔 → List
  features:                   # yaml 列表 → List<Feature>
    - name: order
      weight: 1
    - name: pay
      weight: 2

    实机验证：以上配置全部绑定成功；把 app.name 设为空启动，直接报 Binding validation errors——校验在启动期拦截，不会带病上线。

    @ConfigurationProperties vs @Value：

    对比项 @ConfigurationProperties @Value
    绑定粒度 整组属性（对象） 单个值
    类型转换 强（Duration、嵌套、列表） 弱
    校验 支持 @Validated ❌
    松散绑定 ✅ ❌
    SpEL ❌ ✅ #{...}
    使用场景 一组业务配置 偶尔取单个值 
    @Value("${app.name}")              // 单值
@Value("${app.name:default}")      // 带默认值
@Value("#{systemProperties['java.version']}")  // SpEL
private String appName;

    4.2 配置优先级（从高到低）¶

    Spring Boot 2.x 官方文档列出 17 级，3.x 合并 Config data 后为 15 项。核心记忆顺序：

    命令行参数（--server.port=9090）          ← 最高，运维救急用
  ↓
SPRING_APPLICATION_JSON 环境变量
  ↓
Servlet 环境（ServletConfig/ServletContext/JNDI）
  ↓
Java 系统属性（-Dserver.port=9090）
  ↓
操作系统环境变量（SERVER_PORT=9090）     ⚠️ 环境变量 > 系统属性
  ↓
random.* 随机值
  ↓
jar 外的 profile 配置文件（application-{profile}.yml）
  ↓
jar 内的 profile 配置文件
  ↓
jar 外的 application.yml
  ↓
jar 内的 application.yml
  ↓
@PropertySource 注解
  ↓
SpringApplication.setDefaultProperties()  ← 最低

    三条实战结论： 1. 命令行永远最大——java -jar app.jar --server.port=9090 覆盖一切 2. 同名 profile 配置 > 通用配置（application-prod.yml 覆盖 application.yml） 3. jar 外的配置文件 > jar 内的——改配置不用重新打包

    4.3 松散绑定（Relaxed Binding）¶

    同一个属性，多种写法都能绑定（只对 @ConfigurationProperties 生效）：

    app.retry-count   （yml 推荐：短横线）
app.retryCount    （驼峰）
app.retry_count   （下划线，环境变量风格）
APP_RETRYCOUNT    （系统环境变量：全大写 + 下划线）

    ⚠️ 环境变量名不允许 . 和 -，所以 app.retry-count 对应 APP_RETRYCOUNT——Docker/K8s 注入配置时靠这个规则。

    4.4 敏感配置加密¶

    密码、密钥不要明文进 git。常见方案：

    方案 1：环境变量注入（最简单，12-Factor 推荐）
    spring:
      datasource:
        password: ${DB_PASSWORD}        # 启动时从环境变量读
    运行：DB_PASSWORD=*** java -jar app.jar

方案 2：Jasypt 加密（配置文件中存密文）
    依赖：com.github.ulisesbocchio:jasypt-spring-boot-starter
    配置：spring.datasource.password=ENC(加密后的密文)
    运行：-Djasypt.encryptor.password=主密钥
    （主密钥本身仍要通过环境变量/启动参数传入，不能进 git）

方案 3：配置中心（生产主流）
    Nacos / Apollo / Spring Cloud Config
    配置集中管理 + 动态刷新 + 权限控制

    5. Spring Boot 3.x 新特性 ⭐⭐⭐¶

    知识点： - ⭐ Boot 3.0（2022-11）三大变化：最低 JDK 17、javax→jakarta、GraalVM Native Image 支持 - HTTP Interface Client：声明式 HTTP 客户端（Spring 6.0+） - Observability：Micrometer 统一可观测性（指标 + 追踪）

    5.1 版本迁移要点（2.7 → 3.x）¶

    变化 影响 处理
    最低 JDK 17 编译/运行环境 升级 JDK
    javax.* → jakarta.* ⭐ 所有 import IDE 全局替换 javax.servlet → jakarta.servlet 等
    Spring Security 配置重写 废弃 WebSecurityConfigurerAdapter 改用 SecurityFilterChain Bean
    路径尾斜杠匹配取消 /api/user/ 不再匹配 /api/user 前端修正或显式配置
    Native Image 支持 可选 加 native profile

    ⚠️ javax → jakarta 是升级最大的坑：Servlet、Validation、Persistence、Annotation 全部换包名。老项目升级前先跑 spring-boot-properties-migrator 检查。

    5.2 HTTP Interface Client（声明式远程调用）¶

    Spring 6.0 引入，写法类似 Feign，但属于 Spring 官方：

    // ① 用接口 + 注解声明远程调用（实机验证代码）
public interface UserClient {

    @GetExchange("/api/user/{id}")
    Map<String, Object> getUser(@PathVariable("id") Long id);
}

// ② 注册为 Bean（基于 RestClient 或 WebClient）
@Configuration
public class RemoteConfig {

    @Bean
    UserClient userClient() {
        RestClient restClient = RestClient.builder()
                .baseUrl("http://localhost:8080")
                .build();
        HttpServiceProxyFactory factory = HttpServiceProxyFactory
                .builderFor(RestClientAdapter.create(restClient))
                .build();
        return factory.createClient(UserClient.class);
    }
}

// ③ 注入即用，像调用本地方法
Map<String, Object> user = userClient.getUser(1L);

    适用场景：微服务间调用不想引 Spring Cloud / Feign 全家桶时的轻量选择。

    5.3 Observability（可观测性）¶

    Boot 3.x 用 Micrometer 统一指标与链路追踪：

    # application.yml：开启端点 + 全量采样
management:
  endpoints:
    web:
      exposure:
        include: health,metrics
  tracing:
    sampling:
      probability: 1.0            # 采样率 1.0 = 全量（生产建议 0.1）
  observations:
    key-values:
      region: cn-hangzhou         # 全局标签，所有指标/追踪都带上

    访问 /actuator/health   → 健康检查（K8s 探针用）
访问 /actuator/metrics  → 指标清单（jvm.memory.used、http.server.requests...）
日志自动带 traceId      → 实机验证日志格式：[traceId spanId] 已自动织入

    5.4 GraalVM Native Image（了解）¶

    原理：AOT 编译，把应用编译成原生可执行文件
优势：启动毫秒级（vs JVM 秒级）、内存占用减半 —— Serverless/CLI 工具场景香
代价：反射/动态代理受限（需 hints 声明）、编译慢、部分库不兼容
开启：pom 加 native profile，mvn -Pnative native:compile
现状：适合新项目的轻量服务，老项目不建议强行迁

    6. 生产部署最佳实践 ⭐⭐⭐¶

    知识点： - ⭐ 优雅停机：server.shutdown: graceful，停止接收新请求、等存量请求完成 - ⭐ Tomcat 线程池：server.tomcat.threads.max（默认 200）按下游承载能力调 - ⭐ HikariCP：连接数不是越大越好，经验值 = 核心数 × 2 + 磁盘数 - JVM 参数：容器环境注意 -XX:MaxRAMPercentage

    6.1 优雅停机（实机验证）¶

    server:
  shutdown: graceful                        # 开启优雅停机
spring:
  lifecycle:
    timeout-per-shutdown-phase: 15s         # 最长等待 15 秒，超时强制停

    实机验证日志（kill -TERM 触发）：

    o.s.b.w.e.tomcat.GracefulShutdown : Commencing graceful shutdown.
                                    Waiting for active requests to complete
o.s.b.w.e.tomcat.GracefulShutdown : Graceful shutdown complete

    ⚠️ K8s 里 terminationGracePeriodSeconds 必须大于 timeout-per-shutdown-phase，否则 K8s 先 SIGKILL，优雅停机形同虚设。

    6.2 线程池与连接池¶

    server:
  tomcat:
    threads:
      max: 200          # 工作线程上限（默认 200）
      min-spare: 20     # 最小空闲线程（默认 10）
    max-connections: 8192
    accept-count: 100   # 队列满后拒绝新连接

spring:
  datasource:
    hikari:
      maximum-pool-size: 20       # ⚠️ 别盲目调大！见下方公式
      minimum-idle: 5
      connection-timeout: 3000    # 拿连接超时 3s（默认 30s 太长）
      max-lifetime: 1800000       # 连接最大存活 30min（要小于数据库 wait_timeout）

    HikariCP 连接数经验公式（官方 wiki）：

    connections = (core_count × 2) + effective_spindle_count
8 核机器 + 1 块磁盘 ≈ 17 个连接就够了
连接池过大 → 数据库上下文切换开销 → 反而更慢

    6.3 JVM 参数（容器环境）¶

    # 容器环境推荐（JDK 10+ 能感知 cgroup 限制）
java -XX:MaxRAMPercentage=75.0 \
     -XX:+UseG1GC \
     -XX:+HeapDumpOnOutOfMemoryError \
     -XX:HeapDumpPath=/data/logs/ \
     -jar app.jar

# ⚠️ 容器里不要写死 -Xmx2g —— 容器内存限额改了会忘改参数

    7. 常见问题排查 ⭐⭐⭐¶

    排查心法：Spring Boot 的错误信息很有层次——先看 Caused by 最深一层，那才是根因。

    7.1 启动失败五大类¶

    现象 根因 解法
    Port 8080 was already in use 端口被占 lsof -i:8080 找进程，或换端口
    BeanCreationException + Caused by 依赖缺失/配置错误 读最深 Caused by
    NoSuchBeanDefinitionException Bean 没注册 包扫描范围？注解加了？条件装配没满足？
    NoUniqueBeanDefinitionException 同类型多个 Bean @Primary 或 @Qualifier
    APPLICATION FAILED TO START 启动期校验失败 看 Description/Action 段落（Boot 自带诊断）

    7.2 事务不生效（回顾清单）¶

    ① 方法是不是 public？
② 是不是自调用（this.xxx() 绕过代理）？
③ 异常是不是被 catch 吞了？
④ 抛的是不是受检异常且没配 rollbackFor？
⑤ 类是不是 Spring Bean？
（完整 8 大场景见 01_Spring 基础 8.4 节）

    7.3 配置不生效排查三步¶

    ① 拼写：yml 缩进错了属性就挂在别的层级（用 IDE 校验缩进）
② 优先级：是不是被更高优先级来源覆盖了？
   加 --debug 看 CONFIGURATION PROPERTIES，或打日志确认：
   @Value 打印 / Actuator /actuator/configprops 查看实际绑定值
③ 类型：属性名松散绑定写了，但用了 @Value（@Value 不支持松散绑定）

    7.4 一键诊断工具¶

    --debug                        # 条件装配报告 + 详细日志
--trace                        # Bean 创建过程
/actuator/env                  # 所有配置来源及优先级
/actuator/configprops          # @ConfigurationProperties 绑定结果

    8. 高频面试题¶

    Q1：@SpringBootApplication 包含哪三个注解？各自作用？

    @SpringBootConfiguration（标记为配置类）+ @EnableAutoConfiguration（触发自动配置）+ @ComponentScan（扫描启动类所在包）。

    Q2：说说 SpringBoot 自动配置原理？

    @EnableAutoConfiguration 通过 @Import 引入 AutoConfigurationImportSelector，它读取所有 jar 的 META-INF/spring/...AutoConfiguration.imports 文件，收集自动配置类；每个配置类上的 @Conditional 条件（OnClass/OnMissingBean/OnProperty 等）决定是否真正生效。本质是"条件装配 + SPI"。

    Q3：Boot 2.7 前后自动配置注册机制的区别？

    2.7 前用 META-INF/spring.factories 的 EnableAutoConfiguration 条目；2.7+ 拆为独立的 .imports 文件，加载更快、职责更清晰。

    Q4：@ConfigurationProperties 和 @Value 怎么选？

    一组配置用 @ConfigurationProperties（类型安全、可校验、支持嵌套和松散绑定）；偶尔取单值用 @Value（支持 SpEL 和默认值）。

    Q5：如何实现"引入依赖即有默认功能，用户又能定制"？

    自动配置类的 @Bean 方法加 @ConditionalOnMissingBean——用户没自定义就用默认的，自定义了就自动让位。这是约定优于配置的落地。

    Q6：Boot 3.x 相对 2.x 的主要变化？

    最低 JDK 17；javax. 全面迁移到 jakarta.；原生支持 GraalVM Native Image；Spring Security 配置模型更新；HTTP Interface Client 声明式调用；Observability 统一。

    9. 练习题¶

    1. 自动配置验证：用 --debug 启动任意 Boot 项目，在 CONDITIONS EVALUATION REPORT 中找到 JacksonAutoConfiguration，说明它 Positive match 的条件是什么。
    2. 手写 Starter：仿照本章第 3 节，写一个 sms-spring-boot-starter：提供 SmsService.send(phone, content)，配置前缀 sms，支持 sms.sign-name（签名，默认"【我的应用】"），默认开启、可配置关闭。
    3. 配置优先级实验：在 application.yml 设 server.port: 8081，再分别用环境变量 SERVER_PORT=8082 和命令行 --server.port=8083 启动，验证最终端口。
    4. 排查模拟：写一个接口有两个实现（都加 @Service），注入时不指定 @Qualifier，观察启动报错；说出异常类型和三种修复方式。

    // ========== 练习 2：sms-spring-boot-starter ==========

// SmsProperties.java
@ConfigurationProperties(prefix = "sms")
public class SmsProperties {
    private boolean enabled = true;
    private String signName = "【我的应用】";   // 默认签名
    // getter/setter 省略
}

// SmsService.java
public class SmsService {
    private final SmsProperties properties;

    public SmsService(SmsProperties properties) {
        this.properties = properties;
    }

    public void send(String phone, String content) {
        // 真实项目调用短信厂商 API
        System.out.println("发送短信到 " + phone + "："
                + properties.getSignName() + content);
    }
}

// SmsAutoConfiguration.java
@AutoConfiguration
@ConditionalOnProperty(prefix = "sms", name = "enabled",
        havingValue = "true", matchIfMissing = true)
@EnableConfigurationProperties(SmsProperties.class)
public class SmsAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean
    public SmsService smsService(SmsProperties properties) {
        return new SmsService(properties);
    }
}

    10. 本章小结¶

    核心知识点： - ✅ 自动配置原理：@EnableAutoConfiguration → .imports 清单 → @Conditional 条件装配 - ✅ 手写 Starter 四件套：Properties + AutoConfiguration + .imports + @ConditionalOnMissingBean - ✅ 配置绑定首选 @ConfigurationProperties；优先级：命令行 > 环境变量 > 配置文件 - ✅ Boot 3.x：JDK 17、jakarta 迁移、Native Image、HTTP Interface Client - ✅ 生产四配置：优雅停机、线程池、HikariCP、JVM 容器参数 - ✅ 排查靠 --debug 条件报告 + Actuator 端点 + Caused by 根因

    最佳实践： 1. 启动类永远放项目根包，避免组件扫描漏扫 2. 写 Starter 时所有 @Bean 都加 @ConditionalOnMissingBean，把定制权留给用户 3. 敏感配置走环境变量或配置中心，不进 git 4. 容器部署用 -XX:MaxRAMPercentage，别写死 -Xmx 5. 配置不生效先看 Actuator /env 确认实际生效值，再谈排查
