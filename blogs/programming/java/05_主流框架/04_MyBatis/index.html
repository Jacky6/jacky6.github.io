    1. MyBatis 概述¶

    知识点： - MyBatis 是半自动化 ORM 持久层框架：SQL 自己写，映射交给框架，支持 XML 或注解配置 - 核心特性：SQL 与代码分离、动态 SQL、结果映射自动转 Java 对象、一二级缓存、拦截器插件 - ⭐ MyBatis vs JPA：MyBatis 半自动、SQL 完全可控，适合复杂 SQL/国内互联网团队；JPA 全自动、SQL 由框架生成，适合简单 CRUD - 国内互联网公司普遍用 MyBatis，原因就是 SQL 可控、易优化

    1.1 什么是 MyBatis¶

    MyBatis 是一款优秀的半自动化 ORM 持久层框架，支持自定义 SQL、存储过程以及高级映射。

    核心特性： - ✅ SQL 与代码分离：XML 或注解配置 - ✅ 动态 SQL：强大的 SQL 动态生成 - ✅ 结果映射：自动映射到 Java 对象 - ✅ 缓存机制：一级缓存和二级缓存 - ✅ 插件机制：拦截器扩展（分页、监控、加密都靠它）

    1.2 MyBatis vs JPA¶

    特性 MyBatis JPA/Hibernate
    ORM 程度 半自动（SQL 自己写，映射框架做） 全自动（SQL 框架生成）
    SQL 控制 完全控制 自动生成
    学习曲线 平缓 较陡
    灵活性 高（复杂报表、分库分表友好） 一般
    适用场景 复杂 SQL、DBA 文化强的团队 简单 CRUD、领域模型驱动

    国内互联网公司普遍用 MyBatis（SQL 可控、易优化）；JPA 在 DDD 风格和海外项目中更常见。

    2. 快速开始¶

    知识点： - 依赖：mybatis-spring-boot-starter（SpringBoot 2.x 配 2.3.x，3.x 配 3.0.x）+ MySQL 8 驱动新坐标 com.mysql:mysql-connector-j - application.yml 配置数据源 + mybatis.mapper-locations 指向 XML 位置 - ⭐ map-underscore-to-camel-case: true 自动完成下划线转驼峰（create_time → createTime） - 开发期可开 log-impl: StdOutImpl 打印 SQL 日志

    2.1 添加依赖¶

    <!-- SpringBoot 2.x 用 2.3.x；SpringBoot 3.x 用 3.0.x（注意配套） -->
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>2.3.0</version>
</dependency>

<!-- MySQL 8 驱动（新坐标，旧坐标 mysql:mysql-connector-java 已停更） -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
</dependency>

    2.2 配置文件¶

    # application.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/test?serverTimezone=Asia/Shanghai
    username: root
    password: password
    driver-class-name: com.mysql.cj.jdbc.Driver

mybatis:
  mapper-locations: classpath:mapper/*.xml
  type-aliases-package: com.example.entity
  configuration:
    map-underscore-to-camel-case: true  # 下划线转驼峰（create_time → createTime）
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl  # SQL 日志（开发用）

    3. 基本使用¶

    知识点： - 开发四步：Entity → @Mapper 接口 → Mapper XML（namespace = 接口全限定名，SQL id = 方法名）→ Service 注入调用 - 接口不需要实现类，MyBatis 用动态代理生成；增删改返回 int（受影响行数） - useGeneratedKeys="true" keyProperty="id"：插入后把自增主键回填到入参对象 - ⭐ 多参数必须用 @Param 指定名字，否则 XML 里只能用 arg0/param1，易错

    3.1 Entity¶

    @Data
public class User {
    private Long id;
    private String username;
    private String email;
    private LocalDateTime createTime;
}

    3.2 Mapper 接口¶

    @Mapper
public interface UserMapper {

    User findById(Long id);

    List<User> findAll();

    int insert(User user);

    int update(User user);

    int delete(Long id);
}

    返回值常用 int（受影响行数）；接口本身不需要实现类，MyBatis 用动态代理生成实现（见第 8 节）。

    3.3 Mapper XML¶

    <!-- resources/mapper/UserMapper.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" 
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.example.mapper.UserMapper">

    <resultMap id="BaseResultMap" type="User">
        <id column="id" property="id"/>
        <result column="username" property="username"/>
        <result column="email" property="email"/>
        <result column="create_time" property="createTime"/>
    </resultMap>

    <select id="findById" resultMap="BaseResultMap" parameterType="Long">
        SELECT * FROM users WHERE id = #{id}
    </select>

    <select id="findAll" resultMap="BaseResultMap">
        SELECT * FROM users ORDER BY create_time DESC
    </select>

    <insert id="insert" parameterType="User" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO users (username, email, create_time)
        VALUES (#{username}, #{email}, #{createTime})
    </insert>

    <update id="update" parameterType="User">
        UPDATE users
        SET username = #{username}, email = #{email}
        WHERE id = #{id}
    </update>

    <delete id="delete" parameterType="Long">
        DELETE FROM users WHERE id = #{id}
    </delete>
</mapper>

    useGeneratedKeys="true" keyProperty="id"：插入后把数据库自增主键回填到入参对象的 id 字段。

    3.4 多参数传递：@Param ⭐¶

    // 多个参数必须用 @Param 指定名字（否则 XML 里只能用 arg0/param1，易错）
User findByNameAndEmail(@Param("username") String username,
                        @Param("email") String email);

    <select id="findByNameAndEmail" resultMap="BaseResultMap">
    SELECT * FROM users
    WHERE username = #{username} AND email = #{email}
</select>

    单个参数可以不写 @Param（MyBatis 3.5+ 编译时保留参数名也行，但显式写更稳）。

    3.5 Service 层¶

    @Service
public class UserService {

    @Autowired
    private UserMapper userMapper;

    public User findById(Long id) {
        return userMapper.findById(id);
    }

    public void save(User user) {
        if (user.getId() == null) {
            user.setCreateTime(LocalDateTime.now());
            userMapper.insert(user);
        } else {
            userMapper.update(user);
        }
    }
}

    4. #{} 与 ${} 的区别 ⭐⭐⭐⭐¶

    MyBatis 第一面试题：

    #{} ${}
    处理方式 预编译占位符（替换为 ?，JDBC PreparedStatement 传参） 字符串直接拼接进 SQL
    SQL 注入 ✅ 安全 ❌ 有注入风险
    用途 传值（99% 的场景） 传 SQL 结构：表名、列名、排序字段 
    <!-- #{}：编译后是 SELECT * FROM users WHERE id = ?  参数走 PreparedStatement -->
<select id="findById">
    SELECT * FROM users WHERE id = #{id}
</select>

<!-- ${}：直接拼接。仅用于动态表名/列名/排序，且必须自己做白名单校验！ -->
<select id="findByOrder">
    SELECT * FROM users ORDER BY ${orderColumn} ${orderDir}
</select>

    // ⚠️ ${} 的入参绝不能来自用户原始输入，先白名单校验
Set<String> ALLOWED = Set.of("id", "username", "create_time");
if (!ALLOWED.contains(orderColumn)) throw new IllegalArgumentException("非法排序列");

    记忆：#{} 是参数，${} 是拼接。能用 #{} 就用 #{}。LIKE 模糊查询也用 #{}：LIKE CONCAT('%', #{name}, '%')，而不是 '%'${name}'%'。

    5. 注解开发¶

    知识点： - 简单 SQL 可省略 XML：@Select/@Insert/@Update/@Delete 直接写在接口方法上 - 主键回填用 @Options(useGeneratedKeys = true, keyProperty = "id")；列名 ≠ 属性名用 @Results 映射 - ⭐ 选型规则：注解适合一眼看完的简单单表 CRUD，复杂 SQL/动态 SQL/多表映射用 XML - ⚠️ 同一 Mapper 里注解与 XML 可混用，但同一方法不能同时定义两种方式

    简单 SQL 可以不写 XML，直接用注解：

    @Mapper
public interface UserMapper {

    @Select("SELECT * FROM users WHERE id = #{id}")
    User findById(Long id);

    @Insert("INSERT INTO users(username, email) VALUES(#{username}, #{email})")
    @Options(useGeneratedKeys = true, keyProperty = "id")  // 主键回填
    int insert(User user);

    @Update("UPDATE users SET username = #{username} WHERE id = #{id}")
    int update(User user);

    @Delete("DELETE FROM users WHERE id = #{id}")
    int delete(Long id);

    // 结果映射（列名 ≠ 属性名时）
    @Results({
        @Result(column = "create_time", property = "createTime"),
        @Result(column = "id", property = "id", id = true)
    })
    @Select("SELECT * FROM users")
    List<User> findAll();
}
    方式 适用
    注解 简单单表 CRUD，一眼能看完的 SQL
    XML 复杂 SQL、动态 SQL、多表映射（可维护性更好）

    实际项目常见混用：简单查询用注解，复杂 SQL 用 XML。同一个 Mapper 里两者可以共存，但同一方法不能同时定义。

    6. 动态 SQL¶

    知识点： - if + where：where 标签自动加 WHERE 并去掉开头多余的 AND/OR，替代丑陋的 WHERE 1=1 - choose/when/otherwise 相当于 if / else if / else，只走一个分支；set 标签动态更新非空字段并自动处理末尾逗号 - foreach 做批量查询/插入：collection（List 用 list 或 @Param 名）、item、open/close/separator - ⭐ bind 创建变量让模糊查询用 #{}（避免 ${}）；sql + include 实现 SQL 片段复用

    6.1 if 与 where 标签¶

    <select id="findByCondition" resultMap="BaseResultMap">
    SELECT * FROM users
    <where>  <!-- where 标签自动加 WHERE，并去掉开头多余的 AND/OR -->
        <if test="username != null and username != ''">
            AND username = #{username}
        </if>
        <if test="email != null and email != ''">
            AND email = #{email}
        </if>
        <if test="minAge != null">
            AND age >= #{minAge}
        </if>
    </where>
</select>

    用 <where> 代替 WHERE 1=1：更优雅，条件全空时不会生成 WHERE。

    6.2 choose/when/otherwise¶

    <select id="findByType" resultMap="BaseResultMap">
    SELECT * FROM users
    <where>
        <choose>  <!-- 相当于 if / else if / else，只走一个分支 -->
            <when test="type == 'admin'">
                AND role = 'admin'
            </when>
            <when test="type == 'user'">
                AND role = 'user'
            </when>
            <otherwise>
                AND status = 1
            </otherwise>
        </choose>
    </where>
</select>

    6.3 foreach 标签¶

    <!-- 批量查询 -->
<select id="findByIds" resultMap="BaseResultMap">
    SELECT * FROM users
    WHERE id IN
    <foreach collection="ids" item="id" open="(" separator="," close=")">
        #{id}
    </foreach>
</select>

<!-- 批量插入 -->
<insert id="batchInsert">
    INSERT INTO users (username, email) VALUES
    <foreach collection="list" item="user" separator=",">
        (#{user.username}, #{user.email})
    </foreach>
</insert>
    属性 含义
    collection 集合参数名（List 用 list 或 @Param 名，数组用 array）
    item 循环变量名
    open/close/separator 前后缀与分隔符

    批量插入条数过大时建议分批（如每 1000 条一次），避免 SQL 过长超过 MySQL 的 max_allowed_packet。

    6.4 set/trim/bind¶

    <!-- set：动态更新非空字段，自动处理末尾逗号 -->
<update id="updateSelective">
    UPDATE users
    <set>
        <if test="username != null">username = #{username},</if>
        <if test="email != null">email = #{email},</if>
    </set>
    WHERE id = #{id}
</update>

<!-- trim：where/set 的通用版，自定义前后缀剔除规则 -->
<trim prefix="WHERE" prefixOverrides="AND |OR "> ... </trim>

<!-- bind：在 SQL 里创建变量（模糊查询避免 ${}） -->
<select id="findLike" resultMap="BaseResultMap">
    <bind name="pattern" value="'%' + username + '%'"/>
    SELECT * FROM users WHERE username LIKE #{pattern}
</select>

    6.5 sql 片段复用¶

    <sql id="Base_Column_List">id, username, email, create_time</sql>

<select id="findAll" resultMap="BaseResultMap">
    SELECT <include refid="Base_Column_List"/> FROM users
</select>

    7. 高级映射¶

    知识点： - 一对一用 association（配 javaType），一对多用 collection（配 ofType），配合 JOIN 嵌套结果映射 - ⭐ <id> 必须正确配置：MyBatis 靠它判断是否同一对象来合并一对多的多行结果 - 懒加载：嵌套查询配 fetchType="lazy"，返回的是代理对象，访问关联属性才执行第二条 SQL - ⚠️ N+1 问题：查 100 个用户触发 1 + 100 条 SQL，列表场景慎用懒加载嵌套查询

    7.1 一对一映射（association）¶

    public class Order {
    private Long id;
    private String orderNo;
    private User user;  // 关联用户
}

    <resultMap id="OrderWithUserMap" type="Order">
    <id column="order_id" property="id"/>
    <result column="order_no" property="orderNo"/>
    <association property="user" javaType="User">
        <id column="user_id" property="id"/>
        <result column="username" property="username"/>
        <result column="email" property="email"/>
    </association>
</resultMap>

<select id="findOrderWithUser" resultMap="OrderWithUserMap">
    SELECT 
        o.id as order_id, o.order_no,
        u.id as user_id, u.username, u.email
    FROM orders o
    LEFT JOIN users u ON o.user_id = u.id
    WHERE o.id = #{id}
</select>

    7.2 一对多映射（collection）¶

    public class User {
    private Long id;
    private String username;
    private List<Order> orders;  // 多个订单
}

    <resultMap id="UserWithOrdersMap" type="User">
    <id column="user_id" property="id"/>
    <result column="username" property="username"/>
    <collection property="orders" ofType="Order">
        <id column="order_id" property="id"/>
        <result column="order_no" property="orderNo"/>
    </collection>
</resultMap>

<select id="findUserWithOrders" resultMap="UserWithOrdersMap">
    SELECT 
        u.id as user_id, u.username,
        o.id as order_id, o.order_no
    FROM users u
    LEFT JOIN orders o ON u.id = o.user_id
    WHERE u.id = #{id}
</select>

    ⭐ <id> 一定要正确配置：MyBatis 靠它判断"是不是同一个对象"来合并一对多的多行结果。id 配错会导致结果合并异常。

    7.3 懒加载（延迟加载）⭐⭐⭐¶

    关联查询两种方式：

    <!-- 方式 1：嵌套结果（JOIN 一次查出来，上面 7.1/7.2 的写法） -->

<!-- 方式 2：嵌套查询 + 懒加载：先查主表，访问关联属性时才发起第二条 SQL -->
<resultMap id="UserLazyOrdersMap" type="User">
    <id column="id" property="id"/>
    <result column="username" property="username"/>
    <!-- fetchType=lazy：访问 user.getOrders() 时才执行 selectOrdersByUserId -->
    <collection property="orders" ofType="Order"
                column="id"
                select="selectOrdersByUserId"
                fetchType="lazy"/>
</resultMap>

<select id="selectOrdersByUserId" resultType="Order">
    SELECT * FROM orders WHERE user_id = #{userId}
</select>

    # 全局开关（association/collection 未指定 fetchType 时生效）
mybatis:
  configuration:
    lazy-loading-enabled: true      # 开启懒加载
    aggressive-lazy-loading: false  # false=按需加载单个属性（默认）

    懒加载的原理：返回的对象是 CGLIB/Javassist 代理对象，访问关联属性时触发拦截器去执行第二条 SQL。

    嵌套结果（JOIN） 嵌套查询（懒加载）
    SQL 条数 1 条 N+1 条（列表场景）
    数据量大时 笛卡尔积冗余列 可能触发 N+1 问题
    适用 明确需要关联数据 关联数据可能用不到

    N+1 问题：查 100 个用户，每个用户又各发 1 条查订单的 SQL → 1 + 100 条。列表场景慎用懒加载嵌套查询。

    8. 执行原理 ⭐⭐⭐¶

    知识点： - Mapper 接口无实现类：MapperScan 扫描后注册 MapperFactoryBean，生成 JDK 动态代理（MapperProxy）注入 Spring 容器 - ⭐ 寻址规则：namespace = 接口全限定名、SQL id = 方法名，调用时用"全限定名 + 方法名"找到 MappedStatement - 查询链路：SqlSession → Executor（Simple/Reuse/Batch）→ StatementHandler → ParameterHandler 设参 → ResultSetHandler 结果映射 - 插件（拦截器）正是在这条链路的四大对象上切入的

    8.1 为什么 Mapper 接口不用写实现类？¶

    启动时：
MapperScan 扫描 @Mapper 接口
  → 为每个接口注册 MapperFactoryBean
  → 生成 JDK 动态代理对象（MapperProxy）注入到 Spring 容器

调用时：
userMapper.findById(1L)
  → MapperProxy.invoke()
  → 根据 "接口全限定名 + 方法名" 找到对应的 MappedStatement（XML 里的 SQL 配置）
  → 交给 SqlSession 执行：预编译 SQL → 设参 → 执行 → 结果映射

    namespace 与接口全限定名一致、SQL id 与方法名一致，就是靠这个对应关系找到 SQL 的。

    8.2 一次查询的完整链路¶

    SqlSession（会话，非线程安全，Spring 下由模板管理）
  → Executor（执行器：Simple/Reuse/Batch，决定是否复用 PreparedStatement）
    → StatementHandler（处理 JDBC Statement）
      → ParameterHandler（#{} 参数设置）
      → ResultSetHandler（结果集 → Java 对象映射）

    插件（拦截器）可以在这四个对象的多个方法上切入——见下节。

    9. 插件机制（拦截器）⭐⭐⭐¶

    知识点： - 拦截器可拦截四大对象（Executor、StatementHandler、ParameterHandler、ResultSetHandler）的方法调用 - 底层是 JDK 动态代理层层包装（责任链）；分页、SQL 监控、加密、读写分离插件都基于此 - ⭐ 自定义插件三要素：@Intercepts + @Signature 声明拦截目标/方法/签名，intercept 里调 invocation.proceed() 执行原方法 - Plugin.wrap(target, this) 只包装目标类型，其他类型直接放行

    9.1 原理¶

    MyBatis 允许用拦截器拦截四大对象（Executor、StatementHandler、ParameterHandler、ResultSetHandler）的方法调用，底层是 JDK 动态代理层层包装（责任链）。分页插件、SQL 性能监控、数据加密、读写分离都是这么实现的。

    9.2 手写一个 SQL 耗时统计插件¶

    @Intercepts({
    @Signature(type = StatementHandler.class,  // 拦截哪个对象
               method = "query",                // 哪个方法
               args = {Statement.class, ResultHandler.class})  // 方法签名
})
@Component
public class SqlCostInterceptor implements Interceptor {

    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = invocation.proceed();  // 执行原方法
        long cost = System.currentTimeMillis() - start;
        if (cost > 500) {
            System.out.println("慢 SQL 警告：耗时 " + cost + "ms");
        }
        return result;
    }

    @Override
    public Object plugin(Object target) {
        return Plugin.wrap(target, this);  // 只包装目标类型，其他直接放行
    }
}

    9.3 分页插件原理（PageHelper）¶

    PageHelper.startPage(pageNum, pageSize);  // 把分页参数存入 ThreadLocal
userMapper.findAll();
// 插件拦截 Executor.query：
// 1. 从 ThreadLocal 取出分页参数
// 2. 先执行 SELECT COUNT(*) 查总数
// 3. 改写原 SQL 加上 LIMIT offset, size 再执行
// 4. 清除 ThreadLocal

    注意：startPage 之后必须紧跟 MyBatis 查询语句，中间不能插入其他查询，否则分页参数会"串"到别的 SQL 上。

    10. 缓存机制¶

    知识点： - 一级缓存：SqlSession 级别、默认开启；失效条件——不同 SqlSession、中间执行了增删改、手动 clearCache、查询条件不同 - 二级缓存：Mapper（namespace）级别，需 XML 配 <cache> + cache-enabled=true，eviction 默认 LRU - ⚠️ 二级缓存粒度是 namespace：任何更新清空整个缓存，多表 JOIN 场景容易脏数据，多实例部署也不一致 - ⭐ 实践结论：一级缓存保持默认；二级缓存大多数场景不开，业务缓存交给 Redis

    10.1 一级缓存（SqlSession 级别）¶

    • 默认开启，无法关闭（MyBatis 3.3+ 可配置 SESSION/STATEMENT 作用域）
    • 同一个 SqlSession 内，相同查询直接返回缓存
    // 同一 SqlSession 中，第二次查询从缓存获取
User user1 = userMapper.findById(1L);  // 查数据库
User user2 = userMapper.findById(1L);  // 命中一级缓存

    一级缓存失效的情况： 1. SqlSession 不同（Spring 中每次请求通常是不同 SqlSession） 2. 两次查询之间执行了 insert/update/delete（会清空缓存） 3. 手动调用了 sqlSession.clearCache() 4. 查询条件不同（SQL + 参数 + rowBounds 组成缓存 key）

    ⭐ 经典坑：同一个事务（同一个 SqlSession）里先查询、再更新、再查询——第二次查询不会命中缓存，因为 update 已清空。一级缓存在分布式场景下无法共享，别指望它做业务缓存。

    10.2 二级缓存（Mapper 级别）¶

    跨 SqlSession 共享，以 namespace（Mapper）为单位：

    <!-- Mapper XML 开启 -->
<mapper namespace="com.example.mapper.UserMapper">
    <cache eviction="LRU" flushInterval="60000" size="512" readOnly="true"/>
</mapper>

    # application.yml 全局开关
mybatis:
  configuration:
    cache-enabled: true
    属性 说明
    eviction 淘汰策略：LRU（默认）/FIFO/SOFT/WEAK
    flushInterval 刷新间隔（毫秒）
    size 最多缓存对象数
    readOnly true=返回同一对象引用（快但不安全）；false=返回拷贝（实体需实现 Serializable）

    二级缓存的坑（面试常问为什么不用）： 1. 粒度是 namespace：UserMapper 的任何更新会清空整个 namespace 缓存，多表 JOIN 时数据容易脏 2. 表关联更新无法感知：A 表缓存了 JOIN B 表的结果，B 表更新不会清 A 的缓存 3. 多实例部署下各节点缓存不一致

    实践结论：一级缓存保持默认；二级缓存大多数场景不开，业务缓存交给 Redis。

    11. 分页插件 PageHelper¶

    知识点： - 依赖 pagehelper-spring-boot-starter（SpringBoot 3 用 2.x 版本） - 用法：PageHelper.startPage(pageNum, pageSize) 后紧跟查询，实际执行 SELECT COUNT(*) + LIMIT 改写，结果用 PageInfo 封装（total/pages/list） - ⚠️ startPage 只对紧接着的第一条查询生效：参数存 ThreadLocal，中间插入别的查询会把分页"串"到那条 SQL 上

    11.1 依赖¶

    <dependency>
    <groupId>com.github.pagehelper</groupId>
    <artifactId>pagehelper-spring-boot-starter</artifactId>
    <version>1.4.6</version>  <!-- SpringBoot 3 用 2.x 版本 -->
</dependency>

    11.2 使用¶

    public PageInfo<User> findByPage(int pageNum, int pageSize) {
    PageHelper.startPage(pageNum, pageSize);   // 只对紧接着的第一条查询生效
    List<User> list = userMapper.findAll();    // 实际执行：SELECT COUNT + SELECT ... LIMIT
    return new PageInfo<>(list);               // PageInfo 封装 total/pages/pageNum 等
}

    // Controller 返回示例
PageInfo<User> page = userService.findByPage(1, 10);
page.getTotal();   // 总记录数
page.getPages();   // 总页数
page.getList();    // 当前页数据

    12. 常见面试题¶

    Q1：#{} 和 ${} 的区别？

    {} 预编译占位符防注入；${} 字符串拼接，只用于动态表名/列名/排序且要白名单校验。见第 4 节。¶

    Q2：Mapper 接口为什么不需要实现类？ MyBatis 启动时为接口生成 JDK 动态代理（MapperProxy），按"接口全限定名 + 方法名"匹配 XML 中的 MappedStatement 执行 SQL。见第 8 节。

    Q3：MyBatis 的一级缓存和二级缓存？ 一级：SqlSession 级别，默认开启，update 操作会清空；二级：namespace 级别，需显式开启，因粒度粗、多表关联易脏数据，生产中很少开，业务缓存用 Redis。见第 10 节。

    Q4：MyBatis 的懒加载原理和 N+1 问题？ association/collection 设置 fetchType=lazy 时返回代理对象，访问属性才发起关联查询。列表场景会产生 1+N 条 SQL，应改用 JOIN 一次查出或按需加载。见 7.3 节。

    Q5：MyBatis 插件的原理？ 拦截器基于 JDK 动态代理，拦截四大对象（Executor/StatementHandler/ParameterHandler/ResultSetHandler）的方法，责任链式包装。分页、监控、加密都靠它实现。见第 9 节。

    Q6：PageHelper 的原理？ startPage 把分页参数存入 ThreadLocal，插件拦截查询后先执行 COUNT 再改写 SQL 加 LIMIT。注意 startPage 后必须紧跟查询。

    Q7：MyBatis 如何做分页/批量插入？ 分页用 PageHelper 或手写 LIMIT；批量插入用 foreach 拼多值 INSERT 或 ExecutorType.BATCH。

    13. 练习题¶

    1. 基础 CRUD：为 Product（id、name、price、category）编写 Entity、Mapper 接口和 Mapper XML：findById、findAll、insert（回填自增主键）、deleteById。
    2. 动态 SQL：findByCondition 支持按名称模糊、分类、最低价格可选过滤，要求使用 <where> + <if>。
    3. 批量查询：findByIds 使用 <foreach> 实现 IN 查询。
    4. 注解开发：把练习 1 的 CRUD 改为纯注解实现（@Select/@Insert/@Options）。
    5. 懒加载：为 User→Orders 一对多配置 fetchType="lazy"，写测试验证"访问 getOrders() 时才打印第二条 SQL"。
    6. 思考题：为什么 ${} 有注入风险？LIKE 模糊查询应该怎么写才安全？

    // ========== 练习 1：Entity + Mapper 接口 ==========
@Data
public class Product {
    private Long id;
    private String name;
    private BigDecimal price;
    private String category;
}

@Mapper
public interface ProductMapper {
    Product findById(Long id);
    List<Product> findAll();
    int insert(Product product);
    int deleteById(Long id);

    // 练习 2：动态条件查询
    List<Product> findByCondition(@Param("name") String name,
                                  @Param("category") String category,
                                  @Param("minPrice") BigDecimal minPrice);

    // 练习 3：批量查询
    List<Product> findByIds(@Param("ids") List<Long> ids);
}

    <!-- ========== Mapper XML：resources/mapper/ProductMapper.xml ========== -->
<mapper namespace="com.example.mapper.ProductMapper">

    <resultMap id="BaseResultMap" type="Product">
        <id column="id" property="id"/>
        <result column="name" property="name"/>
        <result column="price" property="price"/>
        <result column="category" property="category"/>
    </resultMap>

    <!-- 按主键查询 -->
    <select id="findById" resultMap="BaseResultMap" parameterType="Long">
        SELECT * FROM products WHERE id = #{id}
    </select>

    <!-- 查询全部 -->
    <select id="findAll" resultMap="BaseResultMap">
        SELECT * FROM products ORDER BY id DESC
    </select>

    <!-- 新增：useGeneratedKeys 把自增主键回填到 product.id -->
    <insert id="insert" parameterType="Product"
            useGeneratedKeys="true" keyProperty="id">
        INSERT INTO products (name, price, category)
        VALUES (#{name}, #{price}, #{category})
    </insert>

    <!-- 按主键删除 -->
    <delete id="deleteById" parameterType="Long">
        DELETE FROM products WHERE id = #{id}
    </delete>

    <!-- 练习 2：动态 SQL，<where> 自动去掉多余的 AND -->
    <select id="findByCondition" resultMap="BaseResultMap">
        SELECT * FROM products
        <where>
            <if test="name != null and name != ''">
                AND name LIKE CONCAT('%', #{name}, '%')
            </if>
            <if test="category != null and category != ''">
                AND category = #{category}
            </if>
            <if test="minPrice != null">
                AND price &gt;= #{minPrice}
            </if>
        </where>
    </select>

    <!-- 练习 3：foreach 批量查询 -->
    <select id="findByIds" resultMap="BaseResultMap">
        SELECT * FROM products WHERE id IN
        <foreach collection="ids" item="id" open="(" separator="," close=")">
            #{id}
        </foreach>
    </select>
</mapper>

@Mapper
public interface ProductAnnoMapper {

    @Select("SELECT * FROM products WHERE id = #{id}")

    @Select("SELECT * FROM products ORDER BY id DESC")
    List<Product> findAll();

    @Insert("INSERT INTO products(name, price, category) VALUES(#{name}, #{price}, #{category})")
    @Options(useGeneratedKeys = true, keyProperty = "id")

    @Delete("DELETE FROM products WHERE id = #{id}")

    14. 本章小结¶

    核心知识点¶

    ✅ 基本使用：Entity、Mapper、XML、@Param 多参数
    ✅ #{} vs ${}：预编译 vs 拼接（安全第一问）
    ✅ 注解开发：@Select/@Insert/@Options，简单 SQL 免 XML
    ✅ 动态 SQL：if、where、choose、foreach、set、bind、sql 片段
    ✅ 高级映射：association/collection、<id> 合并机制、懒加载与 N+1
    ✅ 执行原理：MapperProxy 动态代理、namespace+方法名定位 SQL
    ✅ 插件机制：拦截器 + JDK 动态代理，PageHelper 原理
    ✅ 缓存：一级（SqlSession，默认开）、二级（namespace，慎用）

    最佳实践¶

    1. 能用 #{} 绝不 ${}；动态排序列走白名单
    2. 开启驼峰转换：map-underscore-to-camel-case
    3. 多参数必加 @Param
    4. 列表场景慎用懒加载（N+1），优先 JOIN 一次查出
    5. 二级缓存默认不开，业务缓存交给 Redis
    6. startPage 后紧跟查询，批量插入注意分批
    7. resultMap 的 <id> 配准，一对多合并依赖它
