    03_SpringBoot¶

    1. SpringBoot 概述¶

    知识点： - ⭐ SpringBoot = Spring + 自动配置 + 起步依赖 + 内嵌服务器，"约定优于配置" - 解决痛点：Spring 配置繁琐、依赖版本冲突、部署要外部容器 - SpringBoot 不是新框架，是 Spring 的脚手架（底层还是 Spring）

    1.1 什么是 SpringBoot¶

    SpringBoot 是 Spring 家族用于快速构建生产级应用的框架。它不是新框架，而是站在 Spring 肩膀上，用"约定优于配置"的理念让 Spring 应用开箱即用。

    核心特性：

    • ✅ 自动配置：根据 classpath 中的 jar 自动装配 Bean，几乎零配置启动
    • ✅ 起步依赖（Starter）：一个坐标搞定一组功能的全部依赖与版本兼容
    • ✅ 内嵌容器：内置 Tomcat/Jetty，打成 jar 直接 java -jar 运行，无需部署 WAR
    • ✅ 生产就绪：Actuator 提供健康检查、指标监控

    1.2 SpringBoot 解决了什么痛点¶

    传统 Spring 的痛点 SpringBoot 的对策
    手写大量 XML / Java Config 自动配置，约定优于配置
    手动挑依赖、对齐版本（易冲突） Starter + 父工程统一管版本
    部署 WAR 到外部 Tomcat 内嵌容器，jar 即应用
    每个项目重复配置数据源/MVC starter 即插即用
    没有统一监控/健康检查 Actuator 端点

    1.3 SpringBoot 与 Spring 的关系¶

    ⭐ SpringBoot 不是 Spring 的替代品，而是 Spring 的"脚手架"：SpringBoot（自动配置 + Starter + 内嵌容器）套在 Spring MVC / Spring Data 等功能框架之外，底层仍是 Spring Framework 的 IoC/AOP 容器。你写的 @Service、@Autowired、@RestController 依然是 Spring 的东西，SpringBoot 只是帮你省去了装配过程。

    1.4 版本演进 ⭐¶

    SpringBoot Spring Framework JDK 要求 关键变化
    2.x（如 2.7.x） Spring 5.x JDK 8+ 最后一个使用 javax.* 的版本线
    3.x（如 3.2/3.3） Spring 6.x JDK 17+ 迁移 Jakarta EE 9+：包名 javax.* → jakarta.*

    ⚠️ 最重要的版本事实：

    1. SpringBoot 3.x 强制 JDK 17
    2. Jakarta EE 迁移：Java EE 移交 Eclipse 基金会后改名 Jakarta EE，javax.servlet.*、javax.persistence.* 全部改为 jakarta.*。老项目升级 3.x 时这是最大的编译错误来源：
    import javax.servlet.http.HttpServletRequest;    // 2.x 写法
import jakarta.servlet.http.HttpServletRequest;  // 3.x 写法
    1. SpringBoot 3.x 还原生支持 GraalVM Native Image 与可观测性（Micrometer Tracing）

    2. 快速开始¶

    知识点： - 创建项目：Spring Initializr（start.spring.io 或 IDEA 集成） - ⭐ @SpringBootApplication 三合一：@Configuration + @EnableAutoConfiguration + @ComponentScan - 内嵌 Tomcat，main 方法直接启动，无需 war 部署

    2.1 创建项目：Spring Initializr¶

    网页版 https://start.spring.io/（勾选依赖 → Generate → 导入 IDE）、IDEA 内置向导（New Project → Spring Initializr），或命令行：

    # curl 调 Initializr API 生成 Maven + Web 项目
curl https://start.spring.io/starter.zip \
  -d dependencies=web -d type=maven-project -d javaVersion=17 \
  -o demo.zip && unzip demo.zip && cd demo

    2.2 项目结构¶

    demo/
├── pom.xml                          # 依赖版本由 parent 统一管理
├── src/main/java/com/example/demo/
│   ├── DemoApplication.java         # ⭐ 启动类（必须放在根包）
│   └── controller/ service/ entity/ # 各层业务代码
├── src/main/resources/
│   ├── application.yml              # ⭐ 主配置文件
│   ├── static/  templates/          # 静态资源 / 模板
└── src/test/java/                   # 测试代码

    ⚠️ 启动类必须放在所有业务类的父包（如 com.example.demo），因为 @ComponentScan 默认扫描启动类所在包及其子包。

    2.3 pom.xml 核心结构¶

    <!-- 继承父工程：统一管理几百个依赖的版本号 -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.3.0</version>
    <relativePath/>
</parent>

<dependencies>
    <!-- Web starter：内嵌 Tomcat + Spring MVC + Jackson 一把梭 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <!-- 测试 starter：JUnit5 + Mockito + MockMvc + AssertJ -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
<!-- 另需 spring-boot-maven-plugin 打包插件：把普通 jar 变成可执行 fat jar -->

    2.4 启动类与 @SpringBootApplication 拆解 ⭐¶

    @SpringBootApplication          // 组合注解 = 三个注解的合体
public class DemoApplication {
    public static void main(String[] args) {
        // 创建并启动 Spring 容器（web 应用同时启动内嵌 Tomcat）
        SpringApplication.run(DemoApplication.class, args);
    }
}

    @SpringBootApplication 逐个拆解：

    @SpringBootConfiguration   // ① 本质是 @Configuration：标记当前类是配置类
@EnableAutoConfiguration   // ② ⭐ 开启自动配置（第 3 章详解原理）
@ComponentScan             // ③ 组件扫描：扫当前包及子包的 @Component 系注解
public @interface SpringBootApplication { ... }
    组成注解 作用 等价理解
    @SpringBootConfiguration 声明配置类，可写 @Bean 方法 @Configuration 的马甲
    @EnableAutoConfiguration 触发自动配置机制 加载所有自动配置类
    @ComponentScan 扫描 @Component/@Service/@Controller 默认扫启动类所在包

    运行 main 方法，看到 Tomcat started on port 8080 即启动成功。

    3. 自动配置原理 ⭐⭐⭐⭐¶

    知识点： - ⭐ 面试必考链路：@EnableAutoConfiguration → @Import(AutoConfigurationImportSelector) → 读 META-INF/spring/...AutoConfiguration.imports → 加载配置类 - 配置类内部用 @Conditional 系列注解按需生效（有依赖才配置） - 答题骨架：注解拆解 → imports 文件 → 条件装配

    这是 SpringBoot 的灵魂，也是面试必考题。核心问题：为什么引入一个 starter，对应的 Bean 就自动有了？

    3.1 全景流程图¶

    启动类 @SpringBootApplication
        │ 内含
        ▼
@EnableAutoConfiguration
        │ @Import 导入
        ▼
AutoConfigurationImportSelector（选择器）
        │ 读取 classpath 上所有 jar 中的清单文件：
        │   2.7+：META-INF/spring/
        │         org.springframework.boot.autoconfigure.AutoConfiguration.imports
        │   ≤2.6：META-INF/spring.factories
        ▼
收集 ~140 个候选自动配置类（WebMvc、DataSource、Redis ...）
        │ 逐个评估 @Conditional 条件（类存在？Bean 已定义？配置开了？）
        ▼
只有条件全部满足的配置类才生效，向容器注册 Bean ✅

    3.2 逐步拆解¶

    第一步：@EnableAutoConfiguration 通过 @Import(AutoConfigurationImportSelector.class) 导入"选择器"。

    第二步：选择器扫描 classpath 上所有 jar 里的自动配置清单，汇总成候选列表。清单文件位置随版本变化：

    SpringBoot 版本 自动配置清单文件
    ≤ 2.6 META-INF/spring.factories（EnableAutoConfiguration=... 键）
    2.7 ~ 2.x 新增 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports（一行一个类名）；spring.factories 仍兼容但已废弃
    ≥ 3.0 移除 spring.factories 对自动配置的支持，只认 .imports 文件 
    # spring-boot-autoconfigure jar 中 .imports 文件节选（每行一个配置类）
org.springframework.boot.autoconfigure.web.servlet.WebMvcAutoConfiguration
org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration

    第三步：@Conditional 条件过滤（详见第 4 章）。候选 ≠ 生效，条件满足才装配。

    第四步：以 WebMvcAutoConfiguration 为例看条件如何生效：

    @AutoConfiguration
// 条件 1：必须是 Servlet 型 Web 应用，且 classpath 有 DispatcherServlet
@ConditionalOnWebApplication(type = Type.SERVLET)
@ConditionalOnClass({ Servlet.class, DispatcherServlet.class })
// 条件 2：用户没有自定义 WebMvcConfigurationSupport 才生效
//（这就是"你完全接管 MVC 配置后自动配置让位"的原因）
@ConditionalOnMissingBean(WebMvcConfigurationSupport.class)
public class WebMvcAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean   // 你没配视图解析器，我才配
    public InternalResourceViewResolver defaultViewResolver() { ... }
    // 还注册了静态资源处理器、消息转换器、欢迎页等一大票默认 Bean
}

    💡 这就是"你定义了自己的 Bean，自动配置就闭嘴"：自动配置 Bean 几乎都带 @ConditionalOnMissingBean，用户配置永远优先。

    💡 调试技巧：application.yml 里设 debug: true，启动日志会打印 CONDITIONS EVALUATION REPORT，列出每个自动配置类生效（Positive matches）或不生效（Negative matches）的具体原因，排查装配问题的神器。

    4. @Conditional 家族¶

    知识点： - ⭐ @Conditional 是条件装配的总开关：条件满足才注册 Bean - 常用派生：@ConditionalOnClass（类路径有某类）、@ConditionalOnMissingBean（容器没有才建）、@ConditionalOnProperty（配置项） - 写自定义 starter 时靠它实现"引了依赖就自动配置"

    自动配置的"开关"全部来自 Spring 4 引入的 @Conditional 条件装配。

    4.1 常用条件注解表¶

    注解 满足条件 典型场景
    @ConditionalOnClass classpath 存在指定类 有 Jackson 才配 JSON 转换器
    @ConditionalOnMissingClass classpath 不存在指定类 —
    @ConditionalOnBean 容器中已有指定 Bean 依赖其他 Bean 先注册
    @ConditionalOnMissingBean 容器中没有指定 Bean ⭐ 用户没配我才配（兜底）
    @ConditionalOnProperty 配置项满足指定值 功能开关 xxx.enabled=true
    @ConditionalOnWebApplication 当前是 Web 应用 MVC、Servlet 相关配置
    @ConditionalOnExpression SpEL 表达式为 true 复杂条件组合

    4.2 实战：手写一个 hello-spring-boot-starter ⭐¶

    理解 starter 最好的方式是自己写一个。目标：引入后自动注册 HelloService，支持配置前缀和开关。

    ① 功能类 + 配置属性类：

    public class HelloService {
    private final String prefix;   // 问候前缀，来自配置
    public HelloService(String prefix) { this.prefix = prefix; }
    public String sayHello(String name) { return prefix + ", " + name + "!"; }
}

@ConfigurationProperties(prefix = "hello")   // 绑定 hello.* 配置
public class HelloProperties {
    private String prefix = "Hello";   // 默认值：用户不配置时兜底
    // getter / setter 省略
}

    ② 自动配置类（核心）：

    @AutoConfiguration   // 2.7+ 推荐；旧版本用 @Configuration
// 仅当 hello.enabled 不为 false 时装配（matchIfMissing：不配置默认开启）
@ConditionalOnProperty(prefix = "hello", name = "enabled",
        havingValue = "true", matchIfMissing = true)
@EnableConfigurationProperties(HelloProperties.class)   // 激活属性绑定
public class HelloAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean   // 用户自己定义了 HelloService 就让位
    public HelloService helloService(HelloProperties props) {
        return new HelloService(props.getPrefix());
    }
}

    ③ 注册到清单文件：

    # SpringBoot 2.7+ / 3.x：resources/META-INF/spring/
#   org.springframework.boot.autoconfigure.AutoConfiguration.imports
com.example.hello.HelloAutoConfiguration

# SpringBoot ≤ 2.6 老写法：META-INF/spring.factories
# org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
#   com.example.hello.HelloAutoConfiguration

    ④ 使用方：引入 starter 依赖后，在使用工程里直接 @Autowired HelloService 注入即用（可选配置 hello.prefix 覆盖前缀、hello.enabled: false 整体关闭）。

    ✅ starter 的本质 = 依赖聚合 + 自动配置类 + 清单文件注册。官方推荐拆两个模块（starter 空壳管依赖 + autoconfigure 写逻辑），简单场景合并为一个也可以。

    5. 配置体系¶

    知识点： - ⭐ 配置文件 application.properties / application.yml（yml 注意冒号后空格、缩进空格） - 读配置两方式：@Value（单个值）、@ConfigurationProperties（前缀绑定到对象，推荐，支持松散绑定） - ⭐ 优先级：命令行参数 > 系统环境变量 > application-{profile}.yml > application.yml

    5.1 application.properties vs application.yml¶

    # application.properties —— 扁平键值对
server.port=8080
spring.datasource.url=jdbc:mysql://localhost:3306/test

    # application.yml —— 层级结构（冒号后必须有空格，缩进用空格）
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/test
    对比项 properties yml
    可读性 一般（前缀重复） ⭐ 层级清晰
    语法风险 低 缩进错误难排查
    多文档 不支持 --- 分隔多段
    推荐度 简单场景 ⭐ 生产首选

    5.2 读取配置的两种方式¶

    方式一：@Value（读单个值）

    @Value("${server.port}")            // 读配置
private int port;
@Value("${app.name:default-app}")   // 冒号后是默认值
private String appName;

    方式二：@ConfigurationProperties（类型安全的整组绑定）⭐

    // 把 mail.* 前缀的配置整体映射为对象
@ConfigurationProperties(prefix = "mail")
public class MailProperties {
    private String host;
    private int port = 25;               // 可设默认值
    private Credentials credentials;     // 嵌套对象同理，字段 + getter/setter 即可
    // getter / setter 省略（setter 绑定必须提供 setter）

    public static class Credentials {
        private String username;
        private String password;
    }
}

// 启用绑定：在任意 @Configuration 类上声明（推荐，不侵入 POJO）
@Configuration
@EnableConfigurationProperties(MailProperties.class)
public class MailConfig { }

    对应配置：mail.host、mail.port、mail.credentials.username、mail.credentials.password。

    构造器绑定（不可变配置类）：字段声明为 final，只提供带参构造器和 getter。⚠️ 版本差异：2.x 需在类上显式标注 @ConstructorBinding；3.0+ 只有一个带参构造器时自动使用构造器绑定，注解可省略（多个构造器时仍需标注指明）。完整示例见第 14 章练习 1。

    对比 @Value @ConfigurationProperties
    粒度 单个属性 一组属性
    类型安全 弱 ⭐ 强
    松散绑定 ❌ ✅
    JSR-303 校验 ❌ ✅（加 @Validated）
    嵌套对象/List/Map 麻烦 ✅

    5.3 松散绑定（Relaxed Binding）¶

    @ConfigurationProperties 支持多种写法映射到同一字段：user-name（⭐ 短横线，yml 推荐）、userName（驼峰）、user_name（下划线）、USERNAME（环境变量常用）都能绑定到 userName。

    5.4 配置优先级 ⭐¶

    同一个配置项出现在多处时，从高到低（高的覆盖低的）：

    1. 命令行参数            --server.port=9090          ← 最高
2. Java 系统属性          -Dserver.port=9090
3. OS 环境变量            SERVER_PORT=9090
4. application-{profile}.yml（jar 包外）
5. application-{profile}.yml（jar 包内）
6. application.yml（jar 包外，如 ./config/）
7. application.yml（jar 包内 classpath）              ← 最低

    外部配置位置（jar 外，前覆盖后）：./config/ → ./config/*/ → ./ → classpath:/config/ → classpath:/

    💡 典型用法：jar 里带默认配置，运维在 ./config/application.yml 覆盖，发布时用命令行参数做最终调整——三层都不需要重新打包。

    6. 多环境 Profile¶

    知识点： - ⭐ Profile 按环境隔离配置：application-dev/test/prod.yml - 激活方式（优先级从高到低）：命令行 --spring.profiles.active > 环境变量 > 配置文件 - @Profile 注解：让 Bean 只在特定环境注册

    6.1 Profile 文件命名¶

    约定：application-{profile}.yml，与公共配置 application.yml 并存：

    # application-dev.yml（开发环境）
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/dev_db
logging:
  level:
    root: DEBUG              # 开发环境日志放开

# application-prod.yml（生产环境）
server:
  port: 80
spring:
  datasource:
    url: jdbc:mysql://prod-server:3306/prod_db
logging:
  level:
    root: WARN               # 生产只留警告以上

    yml 也支持单文件多文档（--- 分隔，每段用 spring.config.activate.on-profile 声明归属），但独立文件更推荐。

    6.2 激活方式（优先级从高到低）¶

    java -jar app.jar --spring.profiles.active=prod   # 1. 命令行（部署最常用）
export SPRING_PROFILES_ACTIVE=prod                # 2. 环境变量
# 3. 配置文件 application.yml：spring.profiles.active: dev

    6.3 @Profile：按环境注册 Bean¶

    public interface PaymentService { void pay(); }

@Service
@Profile("dev")      // 仅 dev 环境注册：模拟支付
public class MockPaymentService implements PaymentService { ... }

@Service
@Profile("prod")     // 仅 prod 环境注册：走真实支付网关
public class RealPaymentService implements PaymentService { ... }

    ⚠️ 没有 @Profile 注解的 Bean 在所有环境都注册。

    7. 日志¶

    知识点： - ⭐ SpringBoot 默认 SLF4J + Logback，代码用 @Slf4j/log.info 即可 - 级别：TRACE < DEBUG < INFO < WARN < ERROR，配置 logging.level.xxx=debug - 生产建议：按天滚动归档 + 异步 appender + 分环境级别

    7.1 默认方案：SLF4J + Logback¶

    spring-boot-starter 已内置日志门面 SLF4J + 实现 Logback，直接用：

    @Service
public class OrderService {
    // 固定写法：类级别的 logger（Lombok 用户可用 @Slf4j 代替）
    private static final Logger log = LoggerFactory.getLogger(OrderService.class);

    public void createOrder() {
        log.info("订单创建成功, orderId={}", 1001);      // 占位符写法 ✅
        log.error("订单创建失败", new RuntimeException()); // 带异常栈
    }
}

    7.2 日志级别与文件配置¶

    级别从低到高：TRACE < DEBUG < INFO < WARN < ERROR，配置某级别后只输出该级别及以上。

    logging:
  level:
    root: INFO                     # 全局级别
    com.example: DEBUG             # 自己的包放开 DEBUG
    org.springframework.web: WARN  # 压制框架噪音
  file:
    name: logs/app.log             # 输出到文件（不配则只打控制台）
  logback:
    rollingpolicy:
      max-file-size: 10MB          # 单文件最大 10MB 自动滚动
      max-history: 30              # 保留 30 天

    7.3 切换到 Log4j2¶

    要用 Log4j2 需排除默认日志 starter 再引入：

    <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <!-- 排除默认 Logback 实现 -->
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-logging</artifactId>
        </exclusion>
    </exclusions>
</dependency>

<!-- 引入 Log4j2，并在 classpath 放 log4j2-spring.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-log4j2</artifactId>
</dependency>

    ⚠️ 所有 starter 都要排除干净 spring-boot-starter-logging，否则日志实现冲突。

    Spring MVC 的完整用法（注解、参数绑定、拦截器、异常处理）见 02_Spring MVC，本节只讲 SpringBoot 为 Web 开发自动做了什么。

    8.1 starter-web 带来了什么¶

    spring-boot-starter-web
├── spring-boot-starter-json      → Jackson（JSON 序列化）
├── spring-boot-starter-tomcat    → ⭐ 内嵌 Tomcat 容器

    main 方法一跑，Tomcat 随之启动——应用即服务器。想换 Jetty？排除 Tomcat starter、引入 Jetty starter 即可，自动配置会适配。

    server:

  servlet:

    8.3 默认错误处理机制¶

    SpringBoot 注册了 BasicErrorController，未捕获异常最终转发到 /error：

    浏览器请求 → 异常抛出 → 转发 /error
                          ├── HTML 客户端 → Whitelabel 错误页
                          └── JSON 客户端 → {"status":500,"error":...}

    定制方式（按侵入程度从轻到重）：① @RestControllerAdvice 全局异常处理（最常用，见 Spring MVC 章）；② 自定义 resources/templates/error/404.html 等状态码页面；③ 实现 ErrorController 完全接管。

    9. 测试 ⭐⭐⭐¶

    spring-boot-starter-test 自带 JUnit 5、Mockito、AssertJ、MockMvc。SpringBoot 提供分层测试切片，只加载需要的上下文，又快又稳。

    9.1 @SpringBootTest：完整集成测试¶

    加载完整 Spring 容器，适合端到端验证：

    @SpringBootTest
class DemoApplicationTests {
    @Autowired
    private HelloService helloService;   // 容器启动、Bean 注入正常即可断言

    @Test
    void contextLoads() {
        assertEquals("Hello, Boot!", helloService.sayHello("Boot"));
    }
}

    配合 @SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT) 可启动真实随机端口，注入 TestRestTemplate 直接发 HTTP 请求做集成测试。

    9.2 @WebMvcTest + MockMvc：控制器层测试 ⭐¶

    只加载 Web 层（Controller + 过滤器），Service 用 Mock 替代，无需启动 Tomcat。被测控制器 UserController 提供 GET /api/users/{id}，内部调用 userService.findById(id)，找不到时抛 404：

    @WebMvcTest(UserController.class)      // 只装配 UserController 相关切片
class UserControllerTest {
    @Autowired
    private MockMvc mockMvc;           // 模拟 HTTP 请求，无需真实端口

    @MockitoBean                       // Mock 掉 Service（Boot 3.4+；旧版用 @MockBean）
    private UserService userService;

    @Test
    void shouldReturnUser() throws Exception {
        when(userService.findById(1L))          // given：打桩
            .thenReturn(Optional.of(new User(1L, "张三")));

        mockMvc.perform(get("/api/users/1"))     // when：模拟 GET
            .andExpect(status().isOk())          // then：状态码 200
            .andExpect(jsonPath("$.name").value("张三"));  // JSON 断言
    }

    @Test
    void shouldReturn404WhenNotFound() throws Exception {
        when(userService.findById(99L)).thenReturn(Optional.empty());
        mockMvc.perform(get("/api/users/99"))
            .andExpect(status().isNotFound());   // 404
    }
}

    9.3 @DataJpaTest：持久层测试¶

    只加载 JPA 相关 Bean（Repository + 内嵌数据库），默认每个测试后回滚事务：

    @DataJpaTest
class UserRepositoryTest {
    @Autowired
    private UserRepository userRepository;
    @Autowired
    private TestEntityManager em;   // 便捷插入测试数据

    @Test
    void findByEmailShouldWork() {
        em.persistAndFlush(new User("a@example.com"));
        assertTrue(userRepository.findByEmail("a@example.com").isPresent());
    }
}

    9.4 测试注解速查表¶

    注解 加载范围 用途

    @WebMvcTest Web 切片 Controller + MockMvc
    @DataJpaTest JPA 切片 Repository 测试

    10. Actuator 监控¶

    知识点： - Actuator 暴露应用运行指标端点：/actuator/health（健康检查）、/metrics、/info - ⚠️ 生产只暴露必要端点（management.endpoints.web.exposure.include=health,info），防止信息泄露 - 常配合 Prometheus + Grafana 做监控大盘

    10.1 引入与暴露端点¶

    <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>

    management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics   # 按需暴露（生产谨慎用 "*"）
  endpoint:
    health:
      show-details: always             # 展示健康检查明细

    10.2 常用端点表¶

    端点 说明 典型用途
    /actuator/health ⭐ 健康检查（UP/DOWN） K8s 存活/就绪探针
    /actuator/info 应用信息（版本、构建时间） 运维展示
    /actuator/metrics 指标（内存、HTTP、JVM） 对接 Prometheus/Grafana
    /actuator/env 全部环境变量与配置 排查配置问题
    /actuator/beans 容器中所有 Bean 排查装配问题
    /actuator/loggers 查看/动态修改日志级别 线上临时开 DEBUG
    /actuator/mappings 所有 URL 映射 查看接口清单
    /actuator/threaddump 线程快照 排查死锁 
    curl http://localhost:8080/actuator/health
# {"status":"UP","components":{"db":{"status":"UP"},"diskSpace":{"status":"UP"}}}

    10.3 自定义健康指示器 ⭐¶

    只要向容器注册 HealthIndicator Bean，/health 端点自动纳入：

    @Component   // Bean 名 customHealth → 端点中显示为 "customHealth"
public class CustomHealthIndicator implements HealthIndicator {
    @Override
    public Health health() {
        boolean ok = checkExternalService();   // 你的检查逻辑
        if (ok) {
            return Health.up().withDetail("service", "外部服务正常").build();
        }
        // 任一指示器 DOWN，整体状态即 DOWN
        return Health.down().withDetail("service", "外部服务不可达").build();
    }
    private boolean checkExternalService() { return true; }
}

    11. DevTools 热部署¶

    知识点： - spring-boot-devtools：修改代码/资源后秒级自动重启（双类加载器机制） - ⚠️ 只用于开发环境，生产打包时自动排除

    开发期修改代码/资源后自动重启（秒级），无需手动停止再启动：

    <dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>   <!-- 不传递给依赖方 -->
</dependency>

    原理简述：DevTools 用两个类加载器——基础类加载器加载第三方 jar（不变），重启类加载器加载业务类（常变），代码变更时只重建后者，所以快。

    ⚠️ 它是"自动重启"不是真正的热替换；仅用于开发环境（打包时自动剔除）；IDEA 需开启自动编译（Build → Compiler → Build project automatically）。

    12. 打包部署 ⭐⭐¶

    知识点： - ⭐ mvn package 打出可执行 fat jar（内嵌 Tomcat + 全部依赖），java -jar 直接跑 - 原理：spring-boot-maven-plugin 重打包，MANIFEST 指定 Main-Class 为 JarLauncher - 部署三板斧：jar + systemd/Docker + 启动参数（-Xmx、--spring.profiles.active）

    12.1 打包与运行¶

    # 打包（生成可执行 fat jar，含所有依赖 + 内嵌 Tomcat）
mvn clean package -DskipTests

# 运行（生产常用参数）
java -Xms256m -Xmx512m -jar demo.jar \
     --spring.profiles.active=prod --server.port=8080

    12.2 可执行 jar 原理¶

    demo.jar
├── META-INF/MANIFEST.MF
│     Main-Class: org.springframework.boot.loader.JarLauncher  ← JVM 入口
│     Start-Class: com.example.demo.DemoApplication            ← 你的启动类
├── BOOT-INF/classes/     ← 你的业务代码
└── BOOT-INF/lib/         ← 所有依赖 jar（嵌套 jar）
    • Main-Class 指向 SpringBoot 的 JarLauncher：它用自定义类加载器读取"jar 中嵌套的 jar"
    • Launcher 加载完依赖后，再反射调用 Start-Class（你的启动类）的 main
    • 这一切由 spring-boot-maven-plugin 的 repackage 目标在打包时完成

    12.3 systemd 部署（Linux 服务器）¶

    # /etc/systemd/system/demo.service
[Unit]
Description=Demo SpringBoot App

[Service]

journalctl -u demo -f          # 跟踪日志

    13. 面试题¶

    Q1：SpringBoot 和 Spring 的区别？

    Spring 是基础框架（IoC/AOP/MVC），配置繁琐；SpringBoot 建立在 Spring 之上，通过自动配置、Starter、内嵌容器实现开箱即用。它不替代 Spring，写业务用的仍是 Spring 的注解和 API。

    Q2：说说 SpringBoot 自动配置原理？

    @SpringBootApplication 含 @EnableAutoConfiguration，通过 @Import(AutoConfigurationImportSelector) 读取 classpath 上所有 jar 的自动配置清单（2.7+ 为 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports，旧版为 spring.factories）得到候选配置类，再用 @Conditional 系列注解逐条过滤，条件满足才注册 Bean；用户自定义 Bean 因 @ConditionalOnMissingBean 始终优先。

    Q3：什么是 Starter？

    一组依赖的聚合 + 对应的自动配置。引入一个 starter 坐标即可获得该功能的全部兼容依赖和默认 Bean。典型结构：starter 模块（只有 pom）+ autoconfigure 模块（属性类 + 自动配置类 + 清单文件）。

    Q4：内嵌 Tomcat 是怎么工作的？

    starter-web 引入 starter-tomcat，自动配置检测到 Servlet 环境后创建 Tomcat 并注册 DispatcherServlet，SpringApplication.run() 刷新容器时启动它。换容器只需排除 Tomcat starter、引入 Jetty/Undertow starter。

    Q5：SpringBoot 3 有哪些重要变化？

    ① 基线 JDK 17；② 迁移 Jakarta EE 9+，javax.* → jakarta.*（升级最大工作量）；③ 基于 Spring 6；④ 原生支持 GraalVM Native Image；⑤ 自动配置清单只认 .imports 文件（3.0 移除 spring.factories 支持）。

    Q6：如何自定义一个 Starter？

    四步：① 功能类 + @ConfigurationProperties 属性类；② @AutoConfiguration 配置类，用 @ConditionalOnProperty/@ConditionalOnMissingBean 控制装配；③ 在 .imports 清单注册；④ starter 模块聚合依赖。见第 4 章。

    14. 练习题¶

    1. 配置绑定：为以下配置编写 @ConfigurationProperties 类 OssProperties（前缀 oss），要求嵌套类 Credentials 用构造器绑定（不可变），并在 Controller 中注入使用。
    oss:
  endpoint: oss-cn-hangzhou.aliyuncs.com
  bucket: my-bucket
  credentials:
    access-key: AK123
    secret-key: SK456

    1. MockMvc 测试：已有 BookController 提供 GET /api/books/{id}，依赖 BookService.findById(Long) 返回 Optional<Book>（Book 含 id、title 字段）。用 @WebMvcTest + MockMvc 写两个测试：① 找到书返回 200 且 JSON 含 title；② 找不到返回 404。

    2. 自定义健康指示器：实现 DiskUsageHealthIndicator，磁盘使用率超过 90% 时返回 DOWN 并附带使用率详情，否则 UP。

    参考答案¶

    // ========== 练习 1：OssProperties 配置绑定 ==========
@ConfigurationProperties(prefix = "oss")
public class OssProperties {
    private String endpoint;
    private String bucket;
    private Credentials credentials;      // 嵌套对象
    // getter / setter 省略（setter 绑定需要 setter）

    /** 嵌套类用构造器绑定：final 字段 + 构造器，对象不可变 */
    public static class Credentials {
        private final String accessKey;   // access-key 自动松散绑定
        private final String secretKey;

        // SpringBoot 3.x 单构造器自动走构造器绑定，无需 @ConstructorBinding
        public Credentials(String accessKey, String secretKey) {
            this.accessKey = accessKey;
            this.secretKey = secretKey;
        }
        public String getAccessKey() { return accessKey; }
        public String getSecretKey() { return secretKey; }
    }
}

// 激活绑定：@Configuration + @EnableConfigurationProperties(OssProperties.class)
// 使用：Controller 中 @Autowired OssProperties，
//       ossProperties.getBucket() + "@" + ossProperties.getEndpoint()

    // ========== 练习 2：BookController 的 MockMvc 测试 ==========

    // ========== 练习 3：自定义健康指示器 ==========
@Component   // 注册后 /actuator/health 自动出现 diskUsage 项
public class DiskUsageHealthIndicator implements HealthIndicator {
    @Override
    public Health health() {
        File root = new File("/");                      // 检查根分区
        long total = root.getTotalSpace();
        long free = root.getFreeSpace();
        int percent = (int) ((total - free) * 100 / total);   // 使用率

        if (percent > 90) {
            return Health.down()
                .withDetail("diskUsage", percent + "%")
                .withDetail("freeGB", free / 1024 / 1024 / 1024)
                .build();
        }
        return Health.up().withDetail("diskUsage", percent + "%").build();
    }
}

    15. 本章小结¶

    核心知识点¶

    ✅ 自动配置：@EnableAutoConfiguration → 清单文件 → @Conditional 过滤
    ✅ Starter：依赖聚合 + 自动配置，会写自定义 starter
    ✅ 配置体系：yml、@ConfigurationProperties、松散绑定、优先级
    ✅ Profile：多环境隔离，application-{profile}.yml
    ✅ 测试切片：@SpringBootTest / @WebMvcTest + MockMvc / @DataJpaTest
    ✅ 生产就绪：Actuator 端点、健康指示器、jar 部署、Docker

    最佳实践¶

    1. 构造器注入 + final 字段：依赖清晰、便于测试
    2. 配置用 @ConfigurationProperties 而非散落的 @Value
    3. 环境差异交给 Profile 与外部配置，不要把密码写死在 jar 里
    4. Controller 测试用 @WebMvcTest，比全容器测试快一个量级
    5. Actuator 只暴露必要端点，生产环境配合 Security 保护
    6. 升级到 SpringBoot 3 前先全局替换 javax → jakarta，确认 JDK 17
