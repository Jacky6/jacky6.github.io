    02_Spring MVC¶

    1. Spring MVC 概述¶

    知识点： - ⭐ Spring MVC = Spring 的 Web 层框架，基于请求-响应模型 - 核心思想：前端控制器 DispatcherServlet 统一接收请求并分发给 Controller - 前后端分离时代主要做 JSON API（@RestController）

    1.1 MVC 思想¶

    MVC（Model-View-Controller）分三层：

    层 职责 Web 中的代表
    Model 数据与逻辑 JavaBean/DTO
    View 展示 JSP、Thymeleaf
    Controller 接收请求、调度 Servlet、控制器

    好处：✅ 职责清晰、✅ 便于测试、✅ 前后端并行。

    1.2 Spring MVC 定位¶

    Spring MVC 是 Spring Web 模块的表现层框架，基于 Servlet 规范，是 Java Web 事实标准。演进：Servlet/JSP → Struts2 → Spring MVC → SpringBoot（当下主流）。

    优势：✅ 注解驱动配置少；✅ Controller 是 Spring Bean，享受 IOC/AOP；✅ 九大组件可插拔；✅ 可服务端渲染也可纯返 JSON。

    💡 SpringBoot 引入 spring-boot-starter-web 即集成 Spring MVC 与内嵌 Tomcat。

    2. 核心架构¶

    知识点： - ⭐ 请求流程必背：请求 → DispatcherServlet → HandlerMapping 找处理器 → HandlerAdapter 执行 Controller → 返回结果 - DispatcherServlet 是前端控制器（单入口），九大组件中 HandlerMapping/HandlerAdapter/ViewResolver 最核心 - ⭐ 面试答流程按"找谁处理、怎么调、怎么返回"三段说

    2.1 DispatcherServlet：前端控制器¶

    DispatcherServlet 是所有请求的总调度（前端控制器模式），自己不处理业务：⭐ 默认映射 /，拦截所有请求（静态资源可配置放行）；⭐ 通常只有一个。

    2.2 请求处理流程（最重要！）¶

    请求①► DispatcherServlet②► HandlerMapping（③ 按 URL 找 Handler）
  ④► HandlerAdapter⑤► Controller（⑥ 执行业务）
  ⑦► @ResponseBody？ ├ 是（前后端分离主流）：HttpMessageConverter 序列化 JSON
                    └ 否（服务端渲染）：ViewResolver ⑧ 视图名→View ⑨ 渲染→响应

    逐步说明： 1. 请求到达 DispatcherServlet，HandlerMapping 按 URL 匹配到 @RequestMapping 方法 2. HandlerAdapter 适配调用该方法（参数绑定/校验）；Controller 执行业务返回结果 3. ⭐ 前后端分离：加 @ResponseBody 后经 HttpMessageConverter（Jackson）直接转 JSON，不经 ViewResolver 4. ⭐ 服务端渲染：返回视图名，由 ViewResolver 解析模板渲染响应

    2.3 九大组件（记核心的）¶

    组件 作用 重要性
    HandlerMapping ⭐ URL → Handler 查找 必会
    HandlerAdapter ⭐ 调用 Handler 方法 必会
    ViewResolver ⭐ 视图名 → 视图对象 必会
    HandlerExceptionResolver ⭐ 异常解析（@ExceptionHandler 底层） 必会
    HandlerInterceptor ⭐ / MultipartResolver ⭐ 拦截器（第 7 节）/ 文件上传（第 9 节） 必会/常用
    Locale / Theme / FlashMap 三 Resolver 国际化/主题/重定向传参 了解

    ⚠️ 九大组件都是 Bean，可配置替换（可插拔设计）。

    3. Controller 与请求映射¶

    知识点： - ⭐ @Controller 返回视图，@RestController = @Controller + @ResponseBody（返回 JSON） - 映射注解：@RequestMapping（通用）、@GetMapping/@PostMapping/@PutMapping/@DeleteMapping - 类级 + 方法级路径拼接：@RequestMapping("/api") + @GetMapping("/users") = /api/users

    3.1 @Controller vs @RestController¶

    // @Controller：返回值默认当"视图名"，走 ViewResolver
@Controller
public class PageController {
    @GetMapping("/home")
    public String home() { return "index"; } // 渲染 index.html
}

// @RestController（最常用）= @Controller + @ResponseBody
@RestController
@RequestMapping("/api/users")
public class UserController {
    @GetMapping
    public List<User> list() { return userService.findAll(); } // → JSON 列表
}

    3.2 请求映射注解¶

    注解 说明
    @RequestMapping 通用，可指定任意方法
    @GetMapping/@PostMapping/@PutMapping/@DeleteMapping 查询/新增/修改/删除 
    @RestController
@RequestMapping("/api/orders")      // 类级别统一前缀
public class OrderController {
    @GetMapping("/{id}")            // 路径变量 {id}，RESTful 风格
    public Order get(@PathVariable Long id) { return orderService.findById(id); }
}

    RESTful 建议：✅ URL 名词复数；✅ HTTP 方法表达动作；✅ 层级嵌套 /api/users/1/orders；路径支持 Ant 通配 ?/*/**。

    4. 参数绑定详解¶

    知识点： - ⭐ @RequestParam：URL 查询参数/表单字段；@PathVariable：路径占位符 /users/{id} - ⭐ @RequestBody：JSON 请求体 → 对象（POST 提交 JSON 必用）；POJO 参数默认绑定表单字段 - ⚠️ 表单参数用 @RequestParam 或 POJO，JSON 才用 @RequestBody——用错是 400/415 常见原因

    4.1 常用注解一览¶

    注解 数据来源 典型场景
    @PathVariable URL 路径占位符 资源定位 /users/1
    @RequestParam 查询串/表单字段 过滤分页 /users?page=1
    @RequestBody 请求体（JSON） 新增/修改对象
    @ModelAttribute 表单字段 → 对象 传统表单提交
    @RequestHeader 请求头 取 Token
    @CookieValue Cookie 会话 Cookie

    4.2 逐个示例¶

    @RestController
@RequestMapping("/api")
public class ParamController {
    // ① 路径变量（自动类型转换）　② 查询串（required=false 可不传、defaultValue 默认值）
    @GetMapping("/users/{id}")
    public User byPath(@PathVariable("id") Long id) { return userService.findById(id); }
    @GetMapping("/users")
    public List<User> byQuery(@RequestParam(required = false) String keyword,
            @RequestParam(defaultValue = "1") int page) { return userService.search(keyword, page); }
    // ③ 请求体 JSON → 对象　④ 表单字段自动绑定到对象
    @PostMapping("/users")
    public User create(@RequestBody User user) { return userService.save(user); }
    @PostMapping("/register")
    public String register(@ModelAttribute User user) { return "注册成功：" + user.getUsername(); }
    // ⑤ 请求头　⑥ Cookie
    @GetMapping("/profile")
    public String profile(@RequestHeader("Authorization") String token) { return "token：" + token; }
    @GetMapping("/cart")
    public String cart(@CookieValue(value = "session_id", defaultValue = "") String sid) { return "sid=" + sid; }
}

    4.3 @RequestBody vs 表单参数（重点！）¶

    对比项 @RequestBody @RequestParam / 表单
    数据来源 请求体原文 查询串/表单字段
    Content-Type application/json x-www-form-urlencoded
    解析方式 HttpMessageConverter（Jackson） request.getParameter()
    接对象 ✅ 整体映射为一个对象 参数散列绑定
    GET 可用 ❌ 无请求体 ✅

    ⚠️ 常见坑：前端发 form-urlencoded，后端写 @RequestBody → 415 解析失败。Content-Type 必须匹配。

    5. 响应处理¶

    知识点： - @ResponseBody：返回值序列化为 JSON（消息转换器 Jackson） - ⭐ ResponseEntity：可控制状态码 + 响应头 + 响应体，REST API 规范响应用它 - 统一响应体 Result（code/message/data）是国内团队惯例

    5.1 @ResponseBody 与 ResponseEntity¶

    @ResponseBody：返回值直接写入响应体交给 HttpMessageConverter 转 JSON；加在类上即 @RestController。需自定义状态码/响应头用 ResponseEntity<T>：

    @PostMapping
public ResponseEntity<User> create(@RequestBody User user) {
    User saved = userService.save(user);
    return ResponseEntity.status(HttpStatus.CREATED)               // 201
            .header("Location", "/api/users/" + saved.getId()).body(saved);
}

@GetMapping("/{id}")
public ResponseEntity<User> get(@PathVariable Long id) {
    return userService.findById(id)
            .map(ResponseEntity::ok)                    // 200 + body
            .orElse(ResponseEntity.notFound().build()); // 404
}

    5.2 统一响应体 Result¶

    public class Result<T> {
    private int code;       // 业务码：200 成功
    private String message; // 提示
    private T data;         // 数据
    private Result(int code, String message, T data) { this.code = code; this.message = message; this.data = data; }
    public static <T> Result<T> ok(T data) { return new Result<>(200, "成功", data); }
    public static <T> Result<T> ok() { return ok(null); }
    public static <T> Result<T> error(int code, String msg) { return new Result<>(code, msg, null); }
    // getter/setter 省略
}

// 使用：返回 { "code":200, "message":"成功", "data":{...} }
@GetMapping("/{id}")
public Result<User> get(@PathVariable Long id) { return Result.ok(userService.findById(id)); }

    6. 参数校验¶

    永远不要相信前端传来的数据。标准方案：JSR-303/Bean Validation（引入 spring-boot-starter-validation）。

    6.1 常用注解¶

    注解 作用
    @NotNull / @NotEmpty 不能为 null / 集合字符串非空
    @NotBlank ⭐ 字符串非空（去空格后），用户名/密码
    @Size(min,max) 长度范围
    @Min / @Max 数值上下限
    @Email / @Pattern(regexp) 邮箱 / 正则匹配
    @Past / @Future 过去/将来时间

    6.2 @Valid 触发校验¶

    public class UserDTO {
    @NotBlank(message = "用户名不能为空") @Size(min = 2, max = 20, message = "用户名长度 2~20") private String username;
    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确") private String phone; // getter/setter 省略
}

// @Valid 触发校验，失败抛 MethodArgumentNotValidException
@PostMapping("/register")
public Result<User> register(@Valid @RequestBody UserDTO dto) {
    return Result.ok(userService.register(dto));
}

    6.3 分组校验¶

    新增/修改规则不同时用分组（接口仅作标记）：

    public interface Insert {}   // 分组标记接口
public interface Update {}

public class UserDTO {
    @Null(groups = Insert.class, message = "新增时 ID 必须为空")
    @NotNull(groups = Update.class, message = "修改时 ID 不能为空")
    private Long id; // 使用：@Validated(Insert.class) @RequestBody UserDTO dto
}

    ⚠️ @Valid vs @Validated（高频）：@Valid 是 JSR-303 标准注解，支持嵌套对象校验；@Validated 是 Spring 扩展，支持分组校验。分组用 @Validated、嵌套用 @Valid。

    6.4 自定义校验器¶

    // ① 注解（@Constraint 指定校验器）
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = GenderValidator.class)
public @interface Gender {
    String message() default "性别只能是 0 或 1";
    Class<?>[] groups() default {}; Class<? extends Payload>[] payload() default {};
}

// ② 校验逻辑（null 交给 @NotNull）
public class GenderValidator implements ConstraintValidator<Gender, Integer> {
    public boolean isValid(Integer v, ConstraintValidatorContext c) { return v == null || v == 0 || v == 1; }
}
// ③ 使用：@Gender private Integer gender;

    7. 拦截器¶

    知识点： - ⭐ HandlerInterceptor 三方法：preHandle（前，false 拦截）、postHandle（后）、afterCompletion（完成后，清理资源） - 执行顺序：多个拦截器 preHandle 正序、postHandle/afterCompletion 倒序（栈式） - ⚠️ 拦截器 vs 过滤器：拦截器是 Spring 层（能拿 Handler），Filter 是 Servlet 层（更早、更通用）

    7.1 HandlerInterceptor 三方法¶

    public interface HandlerInterceptor {
    // ① Controller 执行前：返回 false 中断请求
    boolean preHandle(HttpServletRequest req, HttpServletResponse resp, Object handler);
    // ② Controller 执行后、渲染前：可改 ModelAndView
    void postHandle(HttpServletRequest req, HttpServletResponse resp, Object handler, ModelAndView mv);
    // ③ 请求完成后：清理资源、记录耗时
    void afterCompletion(HttpServletRequest req, HttpServletResponse resp, Object handler, Exception ex);
}

    // 实战：登录拦截器 + 注册
@Component
public class LoginInterceptor implements HandlerInterceptor {
    public boolean preHandle(HttpServletRequest req, HttpServletResponse resp, Object handler) {
        if (req.getRequestURI().startsWith("/api/login")) return true; // 白名单放行
        String token = req.getHeader("Authorization");
        if (token != null && tokenService.verify(token)) return true;
        resp.setStatus(401); // 未登录中断
        return false;
    }
}

@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Autowired private LoginInterceptor loginInterceptor;
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/api/**")          // 拦截
                .excludePathPatterns("/api/login");  // 排除
    }
}

    7.2 执行顺序（重点！）¶

    单个拦截器：preHandle → Controller → postHandle → 视图渲染 → afterCompletion（preHandle 返回 false 则直接响应，后续不执行）。

    多个拦截器（A 先注册、B 后注册）——栈式/洋葱模型：

    A.preHandle ─► B.preHandle ─► Controller ─► B.postHandle ─► A.postHandle ─► 渲染 ─► B.afterCompletion ─► A.afterCompletion

    preHandle 按注册顺序，postHandle/afterCompletion 反序。

    ⚠️ 若 A.preHandle 返回 false：B.preHandle、Controller、postHandle 都不执行，只执行已通过拦截器的 afterCompletion。

    7.3 拦截器 vs 过滤器¶

    对比项 Filter 过滤器 Interceptor 拦截器
    规范/时机 Servlet 规范，DispatcherServlet 之前 Spring MVC，DispatcherServlet 之内
    范围 所有请求（含静态资源） 只拦截到 Controller 的请求
    Spring Bean/Handler 信息 ❌ / ❌ ✅ / ✅
    用途 编码、跨域、敏感词 登录、权限、日志

    8. 跨域 CORS¶

    知识点： - ⭐ 跨域是浏览器同源策略限制（协议/域名/端口任一不同），服务端本身不受限 - 解决：CORS 响应头（Access-Control-Allow-Origin 等），Spring 用 @CrossOrigin 或全局配置 - ⚠️ 网关（Nginx/Gateway）已加 CORS 头时，后端别再加，重复会报错

    浏览器同源策略：协议/域名/端口任一不同即跨域，前后端分离必然遇到，后端用 CORS 响应头放行。

    // 方式一：@CrossOrigin（局部，加在类或方法上）
@CrossOrigin(origins = "http://localhost:5173", maxAge = 3600)
@RestController
public class UserController { ... }

// 方式二：全局配置（推荐）
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOriginPatterns("*")                 // 生产收紧白名单！
                .allowedMethods("GET", "POST", "PUT", "DELETE")
                .allowCredentials(true).maxAge(3600);
    }
}

    ⚠️ 生产环境不要把源设为 * 且同时允许 Cookie，应配置明确的前端域名白名单。

    9. 文件上传与下载¶

    知识点： - ⭐ 上传：表单 enctype="multipart/form-data"，Controller 用 MultipartFile 接收 - 下载：响应头 Content-Disposition: attachment + 文件流写出 - ⚠️ 上传必须校验类型/大小、重命名存储，防恶意文件

    9.1 上传（MultipartFile）¶

    @PostMapping("/upload")
public Result<String> upload(@RequestParam("file") MultipartFile file) throws IOException {
    if (file.isEmpty()) return Result.error(400, "文件不能为空");  // ① 判空
    String name = file.getOriginalFilename();
    String ext = name.substring(name.lastIndexOf('.'));
    if (!List.of(".jpg", ".png", ".pdf").contains(ext.toLowerCase()))
        return Result.error(400, "仅支持 jpg/png/pdf");           // ② 类型白名单
    String saveName = UUID.randomUUID() + ext;                    // ③ 重命名防覆盖
    File dest = new File("/data/upload/" + saveName);
    dest.getParentFile().mkdirs();
    file.transferTo(dest);                                        // ④ 保存
    return Result.ok(saveName);
}

    spring.servlet.multipart:
  max-file-size: 10MB      # 单文件上限
  max-request-size: 50MB   # 请求总上限

    9.2 下载¶

    @GetMapping("/download/{name}")
public ResponseEntity<Resource> download(@PathVariable String name) throws IOException {
    File file = new File("/data/upload/" + name);
    if (!file.exists()) return ResponseEntity.notFound().build();
    // Content-Disposition 触发下载，中文文件名需 URL 编码
    return ResponseEntity.ok().contentType(MediaType.APPLICATION_OCTET_STREAM)
            .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=" + URLEncoder.encode(name, "UTF-8"))
            .body(new FileSystemResource(file));
}

    💡 底层由 MultipartResolver 解析 multipart 请求体，SpringBoot 已自动配置。

    10. 异常处理¶

    知识点： - ⭐ 全局异常处理 = @RestControllerAdvice + @ExceptionHandler（按异常类型捕获） - 三层结构：业务异常（自定义 BusinessException）、参数校验异常、兜底 Exception - ⚠️ 兜底捕获必须记日志，否则异常被吞无法排查

    局部：Controller 内 @ExceptionHandler 只处理本类异常。全局（推荐）：

    @RestControllerAdvice // = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {
    // 业务异常
    @ExceptionHandler(BizException.class)
    public Result<Void> handleBiz(BizException ex) { return Result.error(ex.getCode(), ex.getMessage()); }
    // 参数校验失败（@Valid 抛出）→ 400
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException ex) {
        return Result.error(400, ex.getBindingResult().getFieldErrors().get(0).getDefaultMessage());
    }
    // 兜底：不向前端暴露堆栈
    @ExceptionHandler(Exception.class)
    public Result<Void> handleOther(Exception ex) { return Result.error(500, "服务器内部错误"); }
}

    💡 回顾 01_Spring 基础：本质是 AOP 思想的应用，底层是 HandlerExceptionResolver；多个 @ExceptionHandler 按"异常类型最精确"优先匹配。

    11. 高频面试题¶

    Q1：Spring MVC 的请求处理流程？

    请求到 DispatcherServlet → HandlerMapping 按 URL 找 Handler → HandlerAdapter 适配调用（参数解析/校验）→ Controller 执行业务 → 带 @ResponseBody 则由 HttpMessageConverter 转 JSON 响应，否则 ViewResolver 解析视图渲染；拦截器三方法穿插执行。

    Q2：拦截器和过滤器的区别？

    Filter 属 Servlet 规范，作用于所有请求，在 DispatcherServlet 之前；Interceptor 属 Spring MVC，只拦截到 Controller 的请求，是 Bean 可注入、能拿 Handler 信息。登录权限用拦截器，编码/限流用过滤器。

    Q3：@RequestParam 和 @PathVariable 的区别？

    @PathVariable 从路径占位符取值（/users/{id}→/users/1），RESTful 定位资源；@RequestParam 从查询串/表单取值（/users?id=1），适合可选过滤。均支持类型转换与默认值。

    Q4：@Controller 和 @RestController 的区别？

    @RestController = @Controller + @ResponseBody。前者返回值默认当视图名交 ViewResolver 渲染；后者直接经 HttpMessageConverter 转 JSON 写入响应体。

    Q5：@RequestBody 的原理？

    读取请求体，按 Content-Type（如 application/json）选 HttpMessageConverter（默认 Jackson）反序列化为对象，响应时反向序列化；Content-Type 不对报 415。

    12. 练习题¶

    1. RESTful + 参数绑定：实现"图书管理"增删改查（/api/books），列表支持 ?keyword=&page=&size=（可选有默认值）。
    2. 校验：BookDTO（书名非空 2~50、价格>0、ISBN 13 位数字），@Valid 校验 + 全局异常处理转 Result。
    3. 拦截器：写 LogInterceptor，preHandle 记开始时间，afterCompletion 打印"方法名+耗时"，注册到 /api/**。
    4. 思考：@Valid 校验失败为何捕获 MethodArgumentNotValidException 而非 ConstraintViolationException？

@RequestMapping("/api/books")
public class BookController {

    public Result<List<Book>> list(@RequestParam(required = false) String keyword,
            @RequestParam(defaultValue = "1") int page, @RequestParam(defaultValue = "10") int size) {
        return Result.ok(bookService.search(keyword, page, size)); }
    @GetMapping("/{id}") // 详情
    public Result<Book> get(@PathVariable Long id) { return Result.ok(bookService.findById(id)); }
    @PostMapping // 新增
    public Result<Book> create(@Valid @RequestBody BookDTO dto) { return Result.ok(bookService.save(dto)); }
    @PutMapping("/{id}") // 修改
    public Result<Book> update(@PathVariable Long id, @Valid @RequestBody BookDTO dto) { return Result.ok(bookService.update(id, dto)); }
    @DeleteMapping("/{id}") // 删除
    public Result<Void> delete(@PathVariable Long id) { bookService.delete(id); return Result.ok(); }
}

// 练习 3：LogInterceptor
@Component
public class LogInterceptor implements HandlerInterceptor {
    public boolean preHandle(HttpServletRequest req, HttpServletResponse resp, Object h) {
        req.setAttribute("start", System.currentTimeMillis()); return true;
    }
    public void afterCompletion(HttpServletRequest req, HttpServletResponse resp, Object h, Exception ex) {
        System.out.println(((HandlerMethod) h).getMethod().getName() + " 耗时："
                + (System.currentTimeMillis() - (Long) req.getAttribute("start")) + " ms");
    }
}

    13. 本章小结¶

    核心知识点¶

    ✅ 架构：DispatcherServlet + HandlerMapping/HandlerAdapter/ViewResolver
    ✅ 映射/绑定：@RestController、六大参数注解、@RequestBody 与 Content-Type
    ✅ 响应/校验：ResponseEntity、Result、@Valid/@Validated、分组、自定义校验器
    ✅ 拦截器/跨域/文件/异常：三方法顺序、CORS、MultipartFile、@RestControllerAdvice

    最佳实践¶

    1. 前后端分离一律 @RestController + Result，永远做参数校验
    2. 登录/权限放拦截器，编码等底层放过滤器
    3. CORS 生产收紧白名单；上传必判空、类型白名单、UUID 重命名
