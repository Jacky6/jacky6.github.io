    12_NIO 与网络编程¶

    1. IO 模型演进¶

    知识点： - 三种 IO 模型：BIO（JDK 1.0，同步阻塞）、NIO（JDK 1.4，同步非阻塞 + 多路复用）、AIO（JDK 1.7，异步回调，Linux 支持有限）⭐ - BIO 瓶颈：accept/read 全阻塞，一个连接占一个线程，连接数一多内存和调度撑不住（C10K 问题） - NIO 解法：Selector IO 多路复用，一个线程监听成百上千个连接，有事件才处理（Linux 底层是 epoll）

    1.1 BIO / NIO / AIO¶

    模型 全称 JDK 特点
    BIO Blocking IO 1.0 同步阻塞，一个连接一个线程
    NIO Non-blocking IO（New IO） 1.4 同步非阻塞 + IO 多路复用，一个线程管多个连接
    AIO（NIO.2） Asynchronous IO 1.7 异步非阻塞，OS 完成后回调（Linux 支持有限，用得少）

    1.2 BIO 的瓶颈¶

    BIO 服务端模型：
客户端1 ──→ accept() 阻塞等待 ──→ new Thread(处理连接1)
客户端2 ──→                      ──→ new Thread(处理连接2)
...
    • accept()、read()、write() 全部阻塞：线程干等数据
    • 一个连接占一个线程：1 万连接就要 1 万线程（C10K 问题），内存和调度都撑不住
    • 线程池能缓解（伪异步 IO），但连接数一多，任务排队，响应变慢

    1.3 NIO 的解法：多路复用¶

    NIO 服务端模型：
所有连接的 Channel ──注册──→ Selector（一个）
                              ↓ 单线程轮询
                        哪个连接有事件（可读/可写/新连接）就处理哪个

    一个线程通过 Selector 监听成百上千个连接，有事件才处理——这就是 IO 多路复用（Linux 底层是 epoll）。

    2. NIO 三大核心：Channel、Buffer、Selector¶

    知识点： - 三件套：Channel 双向数据传输管道、Buffer 读写中转容器、Selector 多路复用监听事件 ⭐ - 与 BIO 流的区别：Channel 双向、数据必须经过 Buffer、可配置非阻塞 - ⭐ Buffer 四指针 capacity/limit/position/mark；写→读必须 flip()，clear() 只复位指针不清数据 - FileChannel：Buffer 中转读写，transferTo 走 sendfile 零拷贝（数据不进 JVM 堆） - ⚠️ FileChannel 只能阻塞模式；allocateDirect 分配堆外直接内存可减少一次拷贝

    2.1 核心概念¶

    概念 作用 类比
    Channel（通道） 双向的数据传输管道 流，但可读可写、可非阻塞
    Buffer（缓冲区） 数据读写的中转容器 数组 + 读写位置指针
    Selector（选择器） 多路复用器，监听多个 Channel 的事件 前台接待

    与 BIO 流的区别： - 流是单向的（InputStream 或 OutputStream），Channel 是双向的 - 流直接读写字节，Channel 的数据必须经过 Buffer - Channel 可以配置为非阻塞模式

    2.2 主要 Channel 实现¶

    Channel 用途
    FileChannel 文件读写（只能阻塞模式）
    SocketChannel TCP 客户端连接
    ServerSocketChannel TCP 服务端监听
    DatagramChannel UDP

    2.3 Buffer 结构 ⭐¶

    Buffer 本质是数组，外加四个指针：

    capacity：总容量（固定）
limit：    当前可读写到的边界
position： 下一个读/写的位置
mark：     标记位（reset 可回到这里）

0 <= mark <= position <= limit <= capacity

    写模式 → 读模式必须 flip（最高频考点）：

    ByteBuffer buf = ByteBuffer.allocate(1024);  // 堆内存 Buffer

// === 写入阶段 ===
buf.put((byte) 1);
buf.put((byte) 2);
buf.put((byte) 3);
// 此时：position=3, limit=1024

// === 切换到读模式 ===
buf.flip();   // limit=3（刚才写到哪），position=0（从头读）

// === 读取阶段 ===
while (buf.hasRemaining()) {
    System.out.println(buf.get());  // 1, 2, 3
}

// === 读完清理 ===
buf.clear();    // position=0, limit=capacity（数据还在，只是指针复位，可再写入覆盖）
// buf.compact(); // 另一种：保留未读数据到头部，position 指向未读数据之后
    方法 作用
    allocate(n) 分配堆内 Buffer
    allocateDirect(n) 堆外（直接）内存，减少一次内核态→用户态拷贝，IO 更快
    put/get 写/读
    flip() 写模式 → 读模式
    clear() 复位指针准备重新写（不清数据）
    compact() 保留未读数据，腾出写空间
    rewind() position 归零重读（limit 不变）

    2.4 FileChannel 文件读写¶

    // 文件复制（NIO 版）
try (FileChannel in = FileChannel.open(Path.of("src.txt"), StandardOpenOption.READ);
     FileChannel out = FileChannel.open(Path.of("dst.txt"),
             StandardOpenOption.CREATE, StandardOpenOption.WRITE)) {

    // 方式 1：Buffer 中转
    ByteBuffer buf = ByteBuffer.allocate(8192);
    while (in.read(buf) != -1) {
        buf.flip();
        while (buf.hasRemaining()) {
            out.write(buf);
        }
        buf.clear();
    }

    // 方式 2：零拷贝直传（推荐，数据不经过用户态 Buffer）
    // in.transferTo(0, in.size(), out);
}

    transferTo / transferFrom 底层走操作系统的 sendfile，零拷贝：数据不进入 JVM 堆，直接从内核缓冲区到目标。Kafka、RocketMQ 传输大文件都用这个思想。

    3. Selector 多路复用 ⭐⭐⭐¶

    知识点： - 四种事件：OP_ACCEPT（ServerSocketChannel 新连接）、OP_CONNECT、OP_READ、OP_WRITE - 事件循环：selector.select() 阻塞等就绪事件 → 遍历 selectedKeys() 分发处理 ⭐ - ⚠️ 处理完的 SelectionKey 必须 remove，否则下次循环重复处理 - 读到 -1 表示对端关闭：close 连接并 key.cancel() - 生产几乎不手写 NIO 服务端——用 Netty（封装 Reactor 线程模型、编解码、粘包处理）

    3.1 事件类型¶

    SelectionKey.OP_ACCEPT    // ServerSocketChannel：有新连接
SelectionKey.OP_CONNECT   // SocketChannel：连接建立完成
SelectionKey.OP_READ      // 可读
SelectionKey.OP_WRITE     // 可写

    3.2 非阻塞 TCP 服务端（单线程处理多连接）¶

    import java.net.InetSocketAddress;
import java.nio.ByteBuffer;
import java.nio.channels.*;
import java.util.Iterator;

public class NioServer {
    public static void main(String[] args) throws Exception {
        // 1. 打开 ServerSocketChannel 并设为非阻塞
        ServerSocketChannel serverChannel = ServerSocketChannel.open();
        serverChannel.configureBlocking(false);
        serverChannel.bind(new InetSocketAddress(8080));

        // 2. 注册到 Selector，关注 ACCEPT 事件
        Selector selector = Selector.open();
        serverChannel.register(selector, SelectionKey.OP_ACCEPT);
        System.out.println("NIO 服务启动，端口 8080");

        // 3. 事件循环（单线程管理所有连接）
        ByteBuffer buffer = ByteBuffer.allocate(1024);
        while (true) {
            // select() 阻塞直到至少一个 Channel 有就绪事件（返回就绪数量）
            if (selector.select() == 0) continue;

            Iterator<SelectionKey> it = selector.selectedKeys().iterator();
            while (it.hasNext()) {
                SelectionKey key = it.next();
                it.remove();  // ⭐ 必须移除，否则下次循环重复处理

                if (key.isAcceptable()) {
                    // 新连接：接收并注册读事件
                    SocketChannel client = serverChannel.accept();
                    client.configureBlocking(false);
                    client.register(selector, SelectionKey.OP_READ);
                    System.out.println("新连接: " + client.getRemoteAddress());

                } else if (key.isReadable()) {
                    // 读数据
                    SocketChannel client = (SocketChannel) key.channel();
                    buffer.clear();
                    int len = client.read(buffer);
                    if (len == -1) {
                        client.close();          // 对端关闭
                        key.cancel();
                        continue;
                    }
                    buffer.flip();
                    String msg = new String(buffer.array(), 0, len);
                    System.out.println("收到: " + msg);

                    // 回写
                    ByteBuffer resp = ByteBuffer.wrap(("echo: " + msg).getBytes());
                    while (resp.hasRemaining()) {
                        client.write(resp);
                    }
                }
            }
        }
    }
}

    BIO vs NIO 服务端对比：

    BIO NIO
    线程模型 一连接一线程 一线程多连接（Selector）
    阻塞 accept/read 全阻塞 非阻塞，select 统一等待
    适用 连接数少且固定 连接数多、短请求（聊天、推送）
    编程复杂度 简单 复杂（事件循环、半包粘包要自己处理）

    生产中几乎不手写 NIO 服务端——用 Netty（NIO 框架，封装了 Reactor 线程模型、编解码器、粘包处理）。这里手写是为了理解原理。

    4. Socket 网络编程（BIO 版）¶

    知识点： - TCP 编程：服务端 ServerSocket.accept() 阻塞等待连接，客户端 new Socket(host, port) 发起连接 ⭐ - 经典 BIO 服务端模型：accept 后 new Thread 处理每个连接；基于字节流的 IO 读写 - UDP：DatagramSocket + DatagramPacket 收发包，无连接、不可靠但快 ⭐ - ⚠️ PrintWriter 包装输出流要传 true 开启自动 flush，否则数据可能滞留缓冲区 - 选型：TCP 可靠（HTTP、数据库）；UDP 快（直播、游戏、DNS）

    4.1 TCP 客户端/服务端¶

    // === 服务端（每连接一线程的简单 BIO 模型）===
try (ServerSocket server = new ServerSocket(9000)) {
    System.out.println("等待连接...");
    while (true) {
        Socket socket = server.accept();  // 阻塞等待客户端
        new Thread(() -> handle(socket)).start();
    }
}

static void handle(Socket socket) {
    try (socket;  // Java 9+ 可以这样写（effectively final）
         BufferedReader in = new BufferedReader(
             new InputStreamReader(socket.getInputStream()));
         PrintWriter out = new PrintWriter(socket.getOutputStream(), true)) {

        String line;
        while ((line = in.readLine()) != null) {
            System.out.println("客户端说: " + line);
            out.println("echo: " + line);  // true 表示自动 flush
        }
    } catch (IOException e) {
        e.printStackTrace();
    }
}

// === 客户端 ===
try (Socket socket = new Socket("localhost", 9000);
     PrintWriter out = new PrintWriter(socket.getOutputStream(), true);
     BufferedReader in = new BufferedReader(
         new InputStreamReader(socket.getInputStream()));
     BufferedReader console = new BufferedReader(new InputStreamReader(System.in))) {

    String input;
    while ((input = console.readLine()) != null) {
        out.println(input);                 // 发送
        System.out.println("服务端: " + in.readLine());  // 接收
    }
}

    4.2 UDP（DatagramSocket）¶

    // 发送端
try (DatagramSocket ds = new DatagramSocket()) {
    byte[] data = "你好 UDP".getBytes();
    DatagramPacket packet = new DatagramPacket(data, data.length,
        InetAddress.getByName("localhost"), 9001);
    ds.send(packet);
}

// 接收端
try (DatagramSocket ds = new DatagramSocket(9001)) {
    byte[] buf = new byte[1024];
    DatagramPacket packet = new DatagramPacket(buf, buf.length);
    ds.receive(packet);  // 阻塞等待
    System.out.println(new String(packet.getData(), 0, packet.getLength()));
}

    TCP vs UDP：

    TCP UDP
    连接 面向连接（三次握手） 无连接
    可靠性 可靠（确认、重传、排序） 不可靠，可能丢包乱序
    速度 较慢 快
    场景 HTTP、文件传输、数据库 视频直播、游戏、DNS

    5. AIO（NIO.2 异步 IO，了解）¶

    知识点： - AIO 是异步非阻塞：IO 由 OS 完成，完成后回调 CompletionHandler 的 completed()，线程全程不阻塞 - ⚠️ Linux 底层仍是 epoll 模拟的异步（非真正异步），性能优势不明显，生产很少使用；Windows IOCP 下才是真异步

    AsynchronousServerSocketChannel server =
    AsynchronousServerSocketChannel.open().bind(new InetSocketAddress(8081));

// Future 风格
server.accept(null, new CompletionHandler<AsynchronousSocketChannel, Void>() {
    @Override
    public void completed(AsynchronousSocketChannel client, Void att) {
        server.accept(null, this);  // 继续接受下一个连接
        // 异步读：read 完成后回调，线程全程不阻塞
        ByteBuffer buf = ByteBuffer.allocate(1024);
        client.read(buf, buf, new CompletionHandler<Integer, ByteBuffer>() {
            @Override
            public void completed(Integer n, ByteBuffer b) {
                // 处理数据
            }
            @Override
            public void failed(Throwable exc, ByteBuffer b) {}
        });
    }
    @Override
    public void failed(Throwable exc, Void att) {}
});

    AIO 在 Linux 底层仍是 epoll 模拟的异步（非真正 io_uring 级别的异步），性能优势不明显，实际生产很少使用；Windows IOCP 下是真异步。Netty 曾经支持 AIO，后来也移除了。

    6. 零拷贝与 mmap（进阶）¶

    知识点： - mmap（MappedByteBuffer）：把文件映射到内存，像操作数组一样随机读写，适合大文件 ⭐ - 常见零拷贝手段（面试高频，常结合 Kafka 问）：transferTo 走 sendfile 系统调用；mmap 减少一次拷贝 - 传统 read+write 要 4 次拷贝（磁盘→内核→用户→Socket 缓冲→网卡），sendfile 减到 2~3 次 - ⚠️ 内存映射后没有公开的 unmap API，文件句柄释放时机不可控

    // 内存映射文件：把文件映射到内存，像操作数组一样操作文件
try (FileChannel ch = FileChannel.open(Path.of("big.dat"),
        StandardOpenOption.READ, StandardOpenOption.WRITE)) {
    MappedByteBuffer mapped = ch.map(FileChannel.MapMode.READ_WRITE, 0, ch.size());
    mapped.put(0, (byte) 0xFF);  // 直接修改"文件内容"
    // 适合大文件随机读写；注意映射后文件句柄释放时机（unmap 没有公开 API）
}

    常见零拷贝手段（面试高频，结合 Kafka 问）： 1. FileChannel.transferTo → sendfile 系统调用 2. mmap（MappedByteBuffer）→ 减少一次拷贝 3. 传统 read+write：磁盘→内核缓冲→用户缓冲→Socket 缓冲→网卡（4 次拷贝），sendfile 减到 2~3 次

    7. 常见面试题¶

    Q1：BIO、NIO、AIO 的区别？ BIO 同步阻塞，一连接一线程；NIO 同步非阻塞 + Selector 多路复用，一线程多连接；AIO 异步非阻塞，OS 完成 IO 后回调。生产主流是 NIO（Netty）。

    Q2：NIO 的三大核心？ Channel（双向通道）、Buffer（数据容器，注意 flip/clear 指针切换）、Selector（多路复用，监听多个 Channel 的事件）。

    Q3：Buffer 的 flip 做了什么？ 把 limit 设为当前 position（写到的位置），position 归零——从写模式切到读模式。不 flip 就读不到刚写的数据。

    Q4：select/poll/epoll 了解吗？（Linux 视角） 都是 IO 多路复用系统调用。select/poll 每次调用都要把 fd 集合从用户态拷到内核态、线性扫描，fd 上限低（select 1024）；epoll 用红黑树管理 fd、就绪链表通知，O(1) 获取就绪事件，支持大量连接。Java NIO 在 Linux 上底层就是 epoll。

    Q5：什么是零拷贝？ 数据不经过用户态缓冲区，直接在内核中从文件到 Socket（sendfile），减少拷贝次数和上下文切换。Kafka 消费消息、RocketMQ 刷盘都用。

    Q6：为什么实际开发用 Netty 而不是原生 NIO？ 原生 NIO 要自己处理：半包粘包、Selector 空轮询 bug、断线重连、线程模型、编解码。Netty 全部封装好且久经考验（Dubbo、RocketMQ、Elasticsearch 底层都用它）。

buf.put("hello".getBytes());   // 步骤 1
buf.flip();                    // 步骤 2
buf.get();                     // 步骤 3（读 1 个字节）

    练习 3（文件复制）：分别用 Buffer 中转和 transferTo 复制一个 100MB 文件，计时对比。

    练习 4（NIO 服务端）：编译运行第 3 节的 NioServer，用两个 telnet/nc 客户端同时连接并发消息，验证单线程处理多连接。

    参考答案¶

    import java.net.InetSocketAddress;
import java.nio.ByteBuffer;
import java.nio.channels.*;
import java.nio.file.*;
import java.util.*;

public class NioExercises {

    public static void main(String[] args) throws Exception {
        // 练习 1 答案：
        ByteBuffer buf = ByteBuffer.allocate(16);
        buf.put("hello".getBytes());
        System.out.println("步骤1: position=5, limit=16");
        buf.flip();
        System.out.println("步骤2: position=0, limit=5");
        buf.get();
        System.out.println("步骤3: position=1, limit=5（读走 1 字节）");
        buf.clear();
        System.out.println("步骤4: position=0, limit=16（数据还在，指针复位）");

        // 练习 3：两种方式复制计时
        Path src = Path.of("/tmp/big-src.dat");
        if (!Files.exists(src)) {  // 先生成 100MB 测试文件
            byte[] chunk = new byte[1024 * 1024];
            try (var out = Files.newOutputStream(src)) {
                for (int i = 0; i < 100; i++) out.write(chunk);
            }
        }
        copyWithBuffer(src, Path.of("/tmp/big-dst1.dat"));
        copyWithTransferTo(src, Path.of("/tmp/big-dst2.dat"));
    }

    // 练习 2 思路：
    // 服务端维护 Set<Socket> clients（或用 NIO Selector）；
    // 每连接线程读到消息后，遍历 clients 逐个 writer.println(msg) 转发，
    // 注意同步 clients 集合（CopyOnWriteArraySet）和剔除已断开的连接。

    // 练习 3：Buffer 中转
    static void copyWithBuffer(Path src, Path dst) throws Exception {
        long start = System.currentTimeMillis();
        try (FileChannel in = FileChannel.open(src, StandardOpenOption.READ);
             FileChannel out = FileChannel.open(dst,
                 StandardOpenOption.CREATE, StandardOpenOption.WRITE)) {
            ByteBuffer buf = ByteBuffer.allocate(64 * 1024);
            while (in.read(buf) != -1) {
                buf.flip();
                while (buf.hasRemaining()) out.write(buf);
                buf.clear();
            }
        }
        System.out.println("Buffer 方式: " + (System.currentTimeMillis() - start) + "ms");
    }

    // 练习 3：transferTo 零拷贝
    static void copyWithTransferTo(Path src, Path dst) throws Exception {
        long start = System.currentTimeMillis();
        try (FileChannel in = FileChannel.open(src, StandardOpenOption.READ);
             FileChannel out = FileChannel.open(dst,
                 StandardOpenOption.CREATE, StandardOpenOption.WRITE)) {
            long size = in.size();
            long transferred = 0;
            while (transferred < size) {  // 大文件可能一次传不完，循环
                transferred += in.transferTo(transferred, size - transferred, out);
            }
        }
        System.out.println("transferTo 方式: " + (System.currentTimeMillis() - start) + "ms");
        // 通常明显更快（少一次用户态拷贝）
    }

    // 练习 4：直接运行第 3 节 NioServer 的 main，
    // 另开终端：nc localhost 8080（或 telnet），输入文字看 echo 回复
}

    9. 本章小结¶

    核心知识点¶

    ✅ IO 模型：BIO（一连接一线程）→ NIO（Selector 多路复用）→ AIO（回调，少用）
    ✅ NIO 三件套：Channel（双向）、Buffer（flip/clear 指针管理）、Selector（事件监听）
    ✅ FileChannel：Buffer 读写、transferTo 零拷贝、mmap 内存映射
    ✅ 网络编程：TCP（ServerSocket/Socket）、UDP（DatagramSocket）、TCP vs UDP 选型
    ✅ 生产实践：原生 NIO 复杂（粘包、空轮询 bug），实际用 Netty

    最佳实践¶

    1. Buffer 写完读之前别忘了 flip
    2. Selector 循环中 selectedKeys 处理完必须 remove
    3. 文件大段拷贝优先 transferTo
    4. TCP 服务端生产场景直接上 Netty
    5. 理解 epoll 思想有助于看懂 Redis、Nginx 的高并发模型
