    11_JDBC¶

    1. JDBC 概述¶

    知识点：

    • ⭐ JDBC = Java 访问关系数据库的标准 API（java.sql 包），面向接口编程，换库只换驱动
    • 核心接口：Connection（连接）、PreparedStatement（预编译 SQL）、ResultSet（结果集）
    • JDBC 4.0+ 驱动 SPI 自动注册，无需 Class.forName

    1.1 什么是 JDBC¶

    JDBC（Java Database Connectivity）是 Java 访问关系型数据库的标准 API（java.sql 包）。它定义了一套接口，各数据库厂商提供实现（驱动 jar），Java 代码面向接口编程，换数据库只需换驱动和连接串。

    应用程序代码
    ↓ 调用
JDBC API（java.sql 接口：Connection、Statement、ResultSet...）
    ↓ SPI 加载
数据库驱动（MySQL Driver / PostgreSQL Driver / ...）
    ↓ 协议
数据库（MySQL / PostgreSQL / Oracle ...）

    1.2 核心接口¶

    接口 作用
    DriverManager 管理驱动，获取连接（老式写法）
    DataSource 获取连接的现代方式（连接池都用它）
    Connection 数据库连接（会话），管理事务
    Statement 执行静态 SQL（易 SQL 注入，少用）
    PreparedStatement 预编译 SQL，防注入 + 复用执行计划 ⭐
    CallableStatement 调用数据库存储过程
    ResultSet 查询结果集（游标逐行读取）

    2. 快速开始¶

    知识点：

    • Maven 坐标添加数据库驱动；JDBC 4.0 起驱动经 SPI 自动注册，无需再写 Class.forName ⭐
    • 获取连接：DriverManager.getConnection(url, user, password)，配合 try-with-resources 自动关闭资源
    • ⚠️ MySQL 8 连接串需明确 serverTimezone 参数
    • 核心三件套：Connection（连接与事务）、PreparedStatement（执行 SQL）、ResultSet（查询结果）

    2.1 添加驱动依赖（Maven）¶

    <!-- MySQL 8.x 驱动 -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>8.3.0</version>
</dependency>

    JDBC 4.0（Java 6）之后驱动通过 SPI 自动注册，不再需要手写 Class.forName("com.mysql.cj.jdbc.Driver")。

    2.2 第一个 JDBC 程序¶

    import java.sql.*;

public class JdbcDemo {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8";
        String user = "root";
        String password = "123456";

        // try-with-resources 自动关闭（Connection/Statement/ResultSet 都实现了 AutoCloseable）
        try (Connection conn = DriverManager.getConnection(url, user, password);
             PreparedStatement ps = conn.prepareStatement("SELECT id, name FROM users WHERE id > ?")) {

            ps.setInt(1, 10);  // 设置第 1 个占位符

            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {  // 游标下移，直到没有下一行
                    int id = rs.getInt("id");
                    String name = rs.getString("name");
                    System.out.println(id + " - " + name);
                }
            }

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    连接串要点（MySQL）：

    • jdbc:mysql://host:port/dbname，MySQL 默认端口 3306
    • serverTimezone：MySQL 8 驱动要求明确时区
    • useSSL=false：本地开发关闭 SSL 警告
    • rewriteBatchedStatements=true：批量插入性能优化

    3. CRUD 操作¶

    知识点：

    • 增删改用 executeUpdate()，返回受影响行数；查询用 executeQuery()，返回 ResultSet
    • ResultSet 是游标：while (rs.next()) 逐行推进，按列名（推荐）或列序号（从 1 开始）取值
    • 取回自增主键：prepareStatement 时传 RETURN_GENERATED_KEYS，再调 getGeneratedKeys()
    • 批量：addBatch() 攒批 + executeBatch() 分批提交；⚠️ MySQL 要加 rewriteBatchedStatements=true 才真正合并 ⭐

    3.1 增删改（executeUpdate）¶

    // INSERT
String sql = "INSERT INTO users(name, age) VALUES(?, ?)";
try (PreparedStatement ps = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
    ps.setString(1, "张三");
    ps.setInt(2, 25);

    int rows = ps.executeUpdate();  // 返回受影响行数
    System.out.println("插入 " + rows + " 行");

    // 取回自增主键
    try (ResultSet keys = ps.getGeneratedKeys()) {
        if (keys.next()) {
            long id = keys.getLong(1);
            System.out.println("新记录 ID: " + id);
        }
    }
}

// UPDATE / DELETE 同理：executeUpdate 返回受影响行数

    3.2 查询（executeQuery）¶

    String sql = "SELECT id, name, age FROM users WHERE age >= ?";
try (PreparedStatement ps = conn.prepareStatement(sql)) {
    ps.setInt(1, 18);
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            User u = new User();
            u.setId(rs.getLong("id"));
            u.setName(rs.getString("name"));
            u.setAge(rs.getInt("age"));
            // rs.getObject("create_time", LocalDateTime.class)  // JDBC 4.2 支持 java.time
        }
    }
}

    ResultSet 取值方法：getInt/getLong/getString/getBigDecimal/getDate/getTimestamp/getBoolean/getObject，都支持按列名（推荐）或列序号（从 1 开始）取值。

    3.3 批量操作¶

    String sql = "INSERT INTO logs(msg) VALUES(?)";
try (PreparedStatement ps = conn.prepareStatement(sql)) {
    for (int i = 0; i < 10000; i++) {
        ps.setString(1, "msg-" + i);
        ps.addBatch();
        if (i % 1000 == 999) {
            ps.executeBatch();  // 每 1000 条提交一批，避免内存爆掉
            ps.clearBatch();
        }
    }
    ps.executeBatch();
}
// MySQL 连接串加 rewriteBatchedStatements=true 才能真正合并成多值插入

    4. SQL 注入与 PreparedStatement ⭐⭐⭐¶

    知识点：

    • SQL 注入：字符串拼接让用户输入改变 SQL 结构（恒真条件导致全表数据泄露）
    • ⭐ PreparedStatement 预编译 + 参数化是根本防御：SQL 模板先编译，参数只作为"值"传输
    • 附带好处：相同 SQL 模板可复用执行计划，性能更好
    • ⚠️ ? 占位符不能替代表名/列名/ORDER BY 字段，动态排序列要用白名单校验

    4.1 注入是怎么发生的¶

    // ❌ Statement 拼接 SQL：危险！
String name = request.getParameter("name");  // 假设用户输入 ' OR '1'='1
String sql = "SELECT * FROM users WHERE name = '" + name + "'";
// 拼出来：SELECT * FROM users WHERE name = '' OR '1'='1'
// 恒真条件 → 全表数据泄露
Statement st = conn.createStatement();
ResultSet rs = st.executeQuery(sql);

    4.2 PreparedStatement 为什么安全¶

    // ✅ 占位符参数化：SQL 结构先发给数据库编译，参数只作为"值"传输
PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE name = ?");
ps.setString(1, name);  // 无论输入什么，都只是字符串值，不可能改变 SQL 结构

    原理：

    1. 预编译：SQL 模板先发送到数据库编译出执行计划，? 的位置已固定
    2. 参数化：参数以数据形式传输，不参与 SQL 解析，注入内容失去语法意义
    3. 附带好处：相同 SQL 模板可复用执行计划，性能更好

    注意：? 不能替代表名、列名、ORDER BY 字段（这些是 SQL 结构不是值），动态排序列要用白名单校验。

    5. 事务管理¶

    知识点：

    • 事务流程：setAutoCommit(false) 开启 → 执行多条 SQL → 成功 commit / 失败 rollback
    • ⭐ 四种隔离级别：READ_UNCOMMITTED → READ_COMMITTED（Oracle 默认）→ REPEATABLE_READ（MySQL InnoDB 默认）→ SERIALIZABLE，隔离性递增、并发性递减
    • ⚠️ 连接池场景归还连接前要恢复 autoCommit 为 true
    • Savepoint 保存点支持只回滚事务的一部分

    5.1 基本用法¶

    Connection conn = dataSource.getConnection();
try {
    conn.setAutoCommit(false);  // ⭐ 关闭自动提交，开启事务

    // 转账：A 扣钱 + B 加钱，要么都成功要么都失败
    try (PreparedStatement ps1 = conn.prepareStatement("UPDATE account SET balance = balance - ? WHERE user_id = ?")) {
        ps1.setBigDecimal(1, new BigDecimal("100"));
        ps1.setString(2, "A");
        ps1.executeUpdate();
    }
    try (PreparedStatement ps2 = conn.prepareStatement("UPDATE account SET balance = balance + ? WHERE user_id = ?")) {
        ps2.setBigDecimal(1, new BigDecimal("100"));
        ps2.setString(2, "B");
        ps2.executeUpdate();
    }

    conn.commit();  // 全部成功才提交
} catch (SQLException e) {
    conn.rollback();  // 任何失败全部回滚
    throw e;
} finally {
    conn.setAutoCommit(true);  // 归还连接前恢复默认（连接池场景重要）
    conn.close();
}

    5.2 事务隔离级别¶

    级别 脏读 不可重复读 幻读 说明
    READ_UNCOMMITTED ✅可能 ✅可能 ✅可能 几乎不用
    READ_COMMITTED ❌ ✅可能 ✅可能 Oracle 默认
    REPEATABLE_READ ❌ ❌ ✅可能 MySQL InnoDB 默认
    SERIALIZABLE ❌ ❌ ❌ 完全串行，性能最差 
    conn.setTransactionIsolation(Connection.TRANSACTION_REPEATABLE_READ);

    三个"读问题"：脏读=读到别人未提交的数据；不可重复读=同一事务内两次读同一行结果不同（被别人 UPDATE 了）；幻读=同一事务内两次范围查询行数不同（被别人 INSERT 了）。MySQL InnoDB 的 RR 级别通过 MVCC + 间隙锁基本解决了幻读。

    5.3 Savepoint（保存点）¶

    Savepoint sp = conn.setSavepoint("STEP1");
try {
    // 一些操作
} catch (SQLException e) {
    conn.rollback(sp);  // 只回滚到保存点，而不是整个事务
}

    6. 连接池 ⭐⭐⭐⭐¶

    知识点：

    • 连接创建销毁昂贵（TCP 握手 + 认证）且数据库连接数有限 → 连接池预创建并复用连接 ⭐
    • 借还模型：getConnection() 借（毫秒级），close() 在池化实现下是归还而非真关闭
    • 关键参数：maximumPoolSize、minimumIdle、connectionTimeout、maxLifetime（要小于数据库超时）
    • 选型：HikariCP 性能最强、SpringBoot 默认；Druid 功能全（监控、SQL 防火墙）、国内常用

    6.1 为什么需要连接池¶

    数据库连接的创建（TCP 握手 + 认证 + 会话初始化）耗时几十到几百毫秒，频繁创建销毁是巨大浪费，且数据库连接数有限（MySQL 默认 max_connections=151）。连接池预先创建并复用连接：

    应用借连接：dataSource.getConnection()（从池中取，毫秒级）
应用还连接：conn.close()（池化实现下不是真关闭，而是归还池中）

    6.2 HikariCP（SpringBoot 默认）¶

    <dependency>
    <groupId>com.zaxxer</groupId>
    <artifactId>HikariCP</artifactId>
    <version>5.1.0</version>
</dependency>

    import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;

HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/demo");
config.setUsername("root");
config.setPassword("123456");
config.setMaximumPoolSize(10);      // 最大连接数（默认 10）
config.setMinimumIdle(5);           // 最小空闲连接
config.setConnectionTimeout(30_000); // 借连接超时（默认 30 秒）
config.setMaxLifetime(1_800_000);   // 连接最大存活时间（默认 30 分钟，要小于数据库的超时）

try (HikariDataSource ds = new HikariDataSource(config)) {
    try (Connection conn = ds.getConnection()) {  // 毫秒级获取
        // 使用 conn ...
    }  // close() 实际是归还连接
}

    连接池 特点

    Druid 功能全（监控、SQL 防火墙），国内流行
    DBCP2 Apache 出品，老牌
    C3P0 已过时，了解即可

    7. 连接池原理与常见问题 ⭐¶

    知识点：

    • 工作流程：初始化建 minIdle 个连接 → 借出时校验有效性，无空闲且达 maxSize 则等待超时 → 归还时重置状态（回滚未提交事务、恢复 autoCommit）
    • ⚠️ 连接泄漏：借出后忘 close 或异常路径漏还 → try-with-resources + HikariCP leakDetectionThreshold 检测
    • 连接数不是越大越好；HikariCP 官方公式 connections = core_count * 2 + effective_spindle_count，10~20 往往够用
    • maxLifetime 必须小于数据库 wait_timeout，否则应用会拿到已被数据库关闭的"死连接"

    7.1 连接池工作流程¶

    初始化：创建 minIdle 个连接放入空闲队列
借：getConnection()
   ├─ 有空闲连接 → 校验有效性 → 返回（标记为使用中）
   ├─ 无空闲且未达 maxSize → 新建连接返回
   └─ 无空闲且已达 maxSize → 等待 connectionTimeout，超时报错
还：close()
   └─ 校验/重置状态（回滚未提交事务、恢复 autoCommit）→ 放回空闲队列
后台维护：检测空闲超时、最大存活时间、泄漏检测

    7.2 高频问题¶

    连接泄漏：借出后没 close（忘写或异常路径漏了），连接被耗尽。

    • 对策：try-with-resources；开启 HikariCP 的 leakDetectionThreshold（如 60 秒未归还打堆栈日志）

    连接数设置多大？

    • 不是越大越好：连接多 → 数据库上下文切换开销大、锁竞争加剧
    • HikariCP 官方公式：connections = (core_count * 2) + effective_spindle_count（磁盘数，SSD 按 1 算）
    • 10~20 往往能支撑惊人的吞吐量，先压测再调

    maxLifetime 为什么要小于数据库超时？

    • MySQL 的 wait_timeout 默认 8 小时会单方面关闭空闲连接；连接池若不先于它回收，应用拿到的就是已被数据库关闭的"死连接"。HikariCP 默认 30 分钟，安全。

    8. JDBC 的封装演进¶

    知识点：

    • 原生 JDBC 繁琐 → Spring JdbcTemplate（轻封装）→ MyBatis（半自动 ORM）→ JPA（全自动）
    • ⭐ 国内主流：MyBatis（SQL 可控）；实际开发不再裸写 JDBC

    手写 JDBC 太繁琐（获取连接、设参数、手动映射、关资源），实际开发都用封装：

    原生 JDBC（本章）
  ↓ 轻量封装
Spring JdbcTemplate（SQL 还是自己写，免去资源管理）
  ↓ ORM
MyBatis（SQL 与代码分离，半自动映射）→ 见《MyBatis》章
JPA/Hibernate（全自动 ORM，面向对象不写 SQL）

    JdbcTemplate 示例对比：

    // 原生 JDBC：20 行起步
// JdbcTemplate：
List<User> users = jdbcTemplate.query(
    "SELECT id, name, age FROM users WHERE age >= ?",
    new Object[]{18},
    (rs, rowNum) -> new User(rs.getLong("id"), rs.getString("name"), rs.getInt("age"))
);

    9. 常见面试题¶

    Q1：Statement、PreparedStatement、CallableStatement 的区别？ Statement 执行静态 SQL（字符串拼接，有注入风险）；PreparedStatement 预编译 + 参数化，防注入、可复用执行计划，最常用；CallableStatement 调用存储过程。

    Q2：SQL 注入的原理和防御？ 拼接字符串让用户输入改变了 SQL 结构。防御：参数化查询（PreparedStatement）是根本手段；辅助：最小权限账号、输入校验、ORM 框架。

    Q3：为什么用连接池？ 连接创建销毁昂贵、数据库连接数有限。池化复用 + 借还模型，毫秒级获取连接。主流 HikariCP（默认）、Druid。

    Q4：JDBC 的事务怎么控制？ setAutoCommit(false) 开启 → 执行多条 SQL → commit/rollback。注意恢复 autoCommit、连接归还。隔离级别用 setTransactionIsolation 设置。

    Q5：ResultSet 是什么？为什么不能存起来慢慢用？ 它是游标，底层依赖数据库连接和网络流逐行拉取；连接关闭后失效。要缓存数据就映射成 List 对象。

    Q6：JDBC 4.0 之后还需要 Class.forName 加载驱动吗？ 不需要。驱动 jar 的 META-INF/services/java.sql.Driver 通过 SPI（ServiceLoader）自动注册到 DriverManager。

    10. 练习题¶

    练习 1（查询）：连接本地 MySQL（或用 H2 内存库），建 users 表（id/name/age），插入 3 条数据后用 PreparedStatement 查询 age > 18 的记录并打印。

    练习 2（注入演示）：写一个用 Statement 拼接的登录查询 SELECT * FROM users WHERE name='xx' AND password='yy'，构造输入让条件恒真；再改成 PreparedStatement 验证注入失效。

    练习 3（事务）：实现转账方法 transfer(from, to, amount)，中间故意抛异常，验证回滚后余额不变。

    练习 4（连接池）：用 HikariCP 改造练习 1，maximumPoolSize 设为 2，循环借还 10 次打印每次获取连接耗时。

    参考答案¶

    import com.zaxxer.hikari.*;
import java.sql.*;

public class JdbcExercises {

    // H2 内存库依赖（无本地 MySQL 也能跑）：
    // <dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId><version>2.2.224</version></dependency>
    static final String URL = "jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1";

    public static void main(String[] args) throws Exception {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl(URL);
        config.setMaximumPoolSize(2);
        try (HikariDataSource ds = new HikariDataSource(config)) {
            initTable(ds);
            queryUsers(ds);          // 练习 1
            loginDemo(ds);           // 练习 2
            transferDemo(ds);        // 练习 3
            poolDemo(ds);            // 练习 4
        }
    }

    static void initTable(HikariDataSource ds) throws SQLException {
        try (Connection conn = ds.getConnection(); Statement st = conn.createStatement()) {
            st.execute("CREATE TABLE IF NOT EXISTS users(id BIGINT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(50), age INT, password VARCHAR(50))");
            st.execute("INSERT INTO users(name, age, password) VALUES ('Alice', 20, 'p1'), ('Bob', 17, 'p2'), ('Carol', 25, 'p3')");
        }
    }

    // 练习 1：参数化查询
    static void queryUsers(HikariDataSource ds) throws SQLException {
        String sql = "SELECT id, name, age FROM users WHERE age > ?";
        try (Connection conn = ds.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setInt(1, 18);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    System.out.println(rs.getLong("id") + " " + rs.getString("name") + " " + rs.getInt("age"));
                }
            }
        }
    }

    // 练习 2：注入对比
    static void loginDemo(HikariDataSource ds) throws SQLException {
        String evil = "' OR '1'='1";  // 攻击输入
        try (Connection conn = ds.getConnection()) {
            // ❌ Statement 拼接：恒真，返回所有用户
            try (Statement st = conn.createStatement();
                 ResultSet rs = st.executeQuery("SELECT * FROM users WHERE name='" + evil + "' AND password='x'")) {
                int count = 0;
                while (rs.next()) count++;
                System.out.println("Statement 注入后查到 " + count + " 条（泄露！）");
            }
            // ✅ PreparedStatement：输入只是普通字符串，查不到任何结果
            try (PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE name=? AND password=?")) {
                ps.setString(1, evil);
                ps.setString(2, "x");
                try (ResultSet rs = ps.executeQuery()) {
                    System.out.println("PreparedStatement 查到 " + (rs.next() ? "有" : "无") + "结果（安全）");
                }
            }
        }
    }

    // 练习 3：事务回滚
    static void transferDemo(HikariDataSource ds) throws SQLException {
        try (Connection conn = ds.getConnection()) {
            conn.setAutoCommit(false);
            try (PreparedStatement ps = conn.prepareStatement("UPDATE users SET age = age + ? WHERE name = ?")) {
                ps.setInt(1, 1);
                ps.setString(2, "Alice");
                ps.executeUpdate();
                // 模拟第二步出错
                throw new SQLException("模拟故障");
            } catch (SQLException e) {
                conn.rollback();  // Alice 的年龄恢复原样
                System.out.println("事务已回滚：" + e.getMessage());
            }
        }
    }

    // 练习 4：连接池借还
    static void poolDemo(HikariDataSource ds) throws SQLException {
        for (int i = 0; i < 10; i++) {
            long start = System.nanoTime();
            try (Connection conn = ds.getConnection()) {
                long cost = (System.nanoTime() - start) / 1000;
                System.out.println("第" + i + "次获取连接耗时 " + cost + "μs");  // 微秒级
            }
        }
    }
}

    11. 本章小结¶

    核心知识点¶

    ✅ 核心接口：Connection / PreparedStatement / ResultSet 三件套
    ✅ CRUD：executeUpdate（增删改）、executeQuery（查询）、批量
    ✅ 防注入：PreparedStatement 预编译 + 参数化（必会）
    ✅ 事务：autoCommit/commit/rollback、四种隔离级别、savepoint
    ✅ 连接池：借还模型、HikariCP 参数（maxPoolSize 默认 10）、泄漏检测
    ✅ 演进：JDBC → JdbcTemplate → MyBatis/JPA

    最佳实践¶

    1. 永远用 PreparedStatement，不用字符串拼接 SQL
    2. 永远用 try-with-resources 管理连接和结果集
    3. 生产环境必须用连接池，别裸 DriverManager
    4. 金额字段用 BigDecimal，不用 float/double
    5. 连接归还前确保事务已提交或回滚
    6. 结果集及时映射成对象，不要持有跨连接使用
