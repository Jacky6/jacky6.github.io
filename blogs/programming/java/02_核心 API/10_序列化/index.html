    10_序列化¶

    1. 概述¶

    知识点： - 序列化 = 对象 → 字节流（便于存储/网络传输）；反序列化是还原 - ⚠️ Java 原生序列化安全性差，跨系统通信优先 JSON

    1.1 什么是序列化¶

    序列化（Serialization）：把内存中的对象转换成字节序列。 反序列化（Deserialization）：把字节序列还原成对象。

    🏠 生活类比：搬家时房子没法直接搬，于是把家具打包成箱子（序列化），卡车运走，到新房再还原（反序列化）。箱子就是字节序列——能上卡车（网络）、能进仓库（磁盘）。

    Java 对象 --序列化--> 字节序列 --存/传--> 文件 / 网络 / 缓存
Java 对象 <--反序列化-- 字节序列 <--读回-- 文件 / 网络 / 缓存

    1.2 为什么需要¶

    场景 说明
    ✅ 持久化 对象写入文件/数据库，重启后恢复（如游戏存档）
    ✅ 网络传输 跨 JVM 传对象：RMI、RPC、消息队列
    ✅ 缓存 Redis 中存放 Java 对象
    ✅ 深拷贝 "序列化再反序列化"复制整个对象图

    ⚠️ 只有实例字段被序列化；方法、static 字段、class 定义不在字节序列里。

    2. 核心用法¶

    知识点： - 实现 Serializable 标记接口才能序列化；ObjectOutputStream/ObjectInputStream 读写 - ⭐ serialVersionUID 版本控制：不一致抛 InvalidClassException，所有可序列化类显式声明 - transient 字段不参与序列化；static 字段本来就不属于对象

    2.1 Serializable 标记接口¶

    // Serializable 是标记接口：没有任何方法，只是声明"我允许被序列化"
public class User implements Serializable {
    private static final long serialVersionUID = 1L; // 版本号，见 2.3
    private String name;
    private int age;
}
    • ✅ 序列化逻辑由 ObjectOutputStream 完成，接口只做声明
    • ❌ 没实现就写入 → NotSerializableException
    • ⚠️ 对象引用的其他对象也必须可序列化（String、集合、数组都可以）

    2.2 完整示例：写文件与读文件¶

    写出（序列化） 读入（反序列化）
    ObjectOutputStream.writeObject(obj) ObjectInputStream.readObject() 返回 Object，需强转 
    import java.io.*;

class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int age;
    private transient String password; // 不参与序列化，见 2.4

    User(String name, int age, String password) {
        this.name = name; this.age = age; this.password = password;
    }
    @Override
    public String toString() { return name + "/" + age + "/" + password; }
}

public class SerializationDemo {
    public static void main(String[] args) throws Exception {
        // ① 序列化：对象 -> 字节流 -> 文件
        try (ObjectOutputStream oos = new ObjectOutputStream(
                new FileOutputStream("user.ser"))) {
            oos.writeObject(new User("Alice", 25, "pwd123"));
        }
        // ② 反序列化：文件 -> 字节流 -> 对象
        try (ObjectInputStream ois = new ObjectInputStream(
                new FileInputStream("user.ser"))) {
            User u = (User) ois.readObject();
            System.out.println(u); // Alice/25/null（transient 字段为默认值）
        }
    }
}

    ⭐ 要点：类必须在 classpath 中，否则 ClassNotFoundException；文件开头魔数是 ¬í。

    2.3 serialVersionUID：版本号¶

    序列化时写入流，反序列化时比较流中的 UID 与当前类的 UID：

    流中 UID == 当前类 UID ?
  ├── 相等 ✅ 允许反序列化
  └── 不等 ❌ InvalidClassException: local class incompatible

    不写会怎样：JVM 按类结构（类名、接口、字段、方法签名等做 SHA-1 取 8 字节）自动计算默认值，对类结构极其敏感——加一个字段 UID 就可能变，旧数据全部读不了。

    最佳实践： - ✅ 显式声明：private static final long serialVersionUID = 1L; - ✅ 不兼容修改（如删字段）时手动递增为 2L - ⚠️ 枚举固定为 0L，自己声明的会被忽略

    兼容修改 ✅（不改 UID 也能读旧数据） 不兼容修改 ❌
    增加字段（取默认值） 删除字段
    增删 writeObject/readObject 修改基本类型字段的类型
    修改字段访问修饰符 非 static 改 static、非 transient 改 transient

    2.4 transient 关键字¶

    transient 修饰的字段不写入字节流，反序列化后为默认值（null / 0 / false）。

    什么时候用： - 🔒 敏感信息：密码、密钥 - 🚫 字段类型不可序列化：Thread、Socket、数据库连接 - ♻️ 可重建的缓存字段，反序列化后重新计算

    ⚠️ static 字段属于类、本来就不序列化，再加 transient 是多余的（见 Q4）。

    2.5 自定义序列化：writeObject / readObject¶

    类中定义这两个私有方法，序列化框架会自动调用（底层通过反射查找，见 02_反射）：

    class Player implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;

    // 签名必须完全一致
    private void writeObject(ObjectOutputStream out) throws IOException {
        out.defaultWriteObject();                // 先做默认序列化
        out.writeUTF("校验尾:" + name.length()); // 再追加自定义数据
    }
    private void readObject(ObjectInputStream in)
            throws IOException, ClassNotFoundException {
        in.defaultReadObject();                  // 先做默认反序列化
        String tail = in.readUTF();              // 读取顺序必须与写出一致！
        if (!tail.startsWith("校验尾:"))
            throw new InvalidObjectException("数据被篡改");
    }
}

    serialPersistentFields（进阶）：声明 private static final ObjectStreamField[] 字段可自定义"哪些字段参与序列化"，突破字段必须是类当前字段的限制；声明后 writeObject/readObject 里要用 putFields()/getFields() 读写，不能再调 defaultWriteObject/defaultReadObject。日常少用，了解即可。

    2.6 writeReplace / readResolve¶

    方法 时机 作用
    writeReplace() 序列化前 返回替身对象去序列化
    readResolve() 反序列化后、返回前 返回值替换刚创建的对象 
    // readResolve：防止单例被序列化破坏
public class Singleton implements Serializable {
    private static final long serialVersionUID = 1L;
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() { return INSTANCE; }

    private Object readResolve() { return INSTANCE; } // 返回值替换新建实例
}

    ❌ 没有 readResolve：每次反序列化都新建实例，s1 == s2 为 false，单例被破坏。 ✅ 更简单的方案：枚举单例——只序列化常量名，反序列化按名找回原常量，天然免疫。

    2.7 Externalizable¶

    继承 Serializable，但要求类自己实现两个方法，JVM 不做任何默认读写：

    class Point implements Externalizable {
    private int x, y;
    public Point() {} // ⚠️ 必须 public 无参构造：先 new 再 readExternal
    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeInt(x); out.writeInt(y); // 写什么完全自己定
    }
    public void readExternal(ObjectInput in) throws IOException {
        x = in.readInt(); y = in.readInt(); // 顺序必须与写的一致
    }
}
    对比项 Serializable ⭐ Externalizable
    接口方法 无（标记接口） writeExternal + readExternal
    默认行为 自动读写非 transient 实例字段 全靠手写
    无参构造器 不需要 必须 public
    版本兼容 serialVersionUID 控制 自己负责
    使用频率 高（日常首选） 低（极致性能/特殊格式）

    2.8 用序列化实现深拷贝¶

    序列化写入整个对象图，读回来就是结构相同的副本——最简单的深拷贝（对比浅拷贝 clone 见 11_Object 类详解）：

    @SuppressWarnings("unchecked")
public static <T extends Serializable> T deepCopy(T obj) throws Exception {
    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    try (ObjectOutputStream oos = new ObjectOutputStream(bos)) {
        oos.writeObject(obj);                 // 写入内存字节数组
    }
    try (ObjectInputStream ois = new ObjectInputStream(
            new ByteArrayInputStream(bos.toByteArray()))) {
        return (T) ois.readObject();          // 还原出全新副本
    }
}
// Author a2 = deepCopy(a1); a2.books.add("彷徨");
// → a1.books 不受影响 ✅，a1 != a2

    ⚠️ 缺点：性能差（IO + 反射），且对象图中所有类必须可序列化。高性能场景手写拷贝构造器。

    3. 底层原理¶

    知识点： - 序列化流包含类元信息 + 字段值，按对象图递归写入 - ⚠️ 单例要加 readResolve 防止反序列化创建新实例（枚举单例免疫）

    3.1 序列化流程¶

    oos.writeObject(root)
  ① 检查 Serializable（否则 NotSerializableException）
  ② 写流头：魔数 0xACED + 版本 0x0005
  ③ 写类元信息：类名、serialVersionUID、字段描述
  ④ 递归遍历对象图，逐个写出引用的子对象
  ⑤ 有 writeObject() → 调用它；否则默认写非 static 非 transient 字段

    3.2 句柄表：循环引用安全¶

    内部维护句柄表：对象第一次写入分配句柄编号，之后只写句柄引用：

    A ──> B ──> A（循环引用）
  写 A：完整数据，登记 handle#1
  写 B：完整数据，登记 handle#2
  B 内再遇 A：只写 "引用 handle#1"，不重复写

    ⭐ 保证：① 循环引用不会无限递归；② 同一对象只存一份，反序列化后 == 仍成立。

    3.3 反序列化不调用构造器¶

    对 Serializable 类，JVM 直接重建字段值，不执行任何构造器；但会调用第一个不可序列化父类的无参构造器初始化父类部分（没有可访问的无参构造器则抛 InvalidClassException）。这也解释了 Externalizable 为何强制 public 无参构造：先 new 空对象再填数据。

    4. 替代方案：JSON¶

    原生序列化是二进制、绑定 Java 类型。现代开发跨系统交换几乎都用 JSON：

    对比项 Java 序列化 JSON
    格式 二进制 文本，人类可读 ✅
    跨语言 ❌ 只能 Java ✅ 任何语言
    结构耦合 强（UID 不匹配即失败） 弱（容忍多/少字段）
    安全性 反序列化漏洞多 ❌ 解析数据不执行代码 ✅ 
    // Jackson（Spring 默认）：writeValueAsString 对象->JSON，readValue JSON->对象
// Gson（轻量/Android）：toJson / fromJson，默认跳过 transient 字段
ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(user);
User u2 = mapper.readValue(json, User.class);

    ⭐ 选型：跨服务/缓存/配置 → JSON；只有纯 Java 内部、需保存完整对象图时才考虑原生序列化。

    5. 安全警告 ⚠️¶

    readObject() 会按流中元信息实例化任意 Serializable 类并执行其 readObject。攻击者构造恶意字节流，可利用 classpath 中第三方库的类链式触发危险代码（gadget chain），最终执行 Runtime.exec() 等。

    • 🔧 ysoserial：知名反序列化利用工具，一键生成各类 gadget 链 payload
    • 🛡️ 防御：
    • ✅ 不要反序列化不可信数据（最重要）
    • ✅ JDK 9+ 用 ObjectInputFilter（JEP 290）做类白名单
    • ✅ 优先 JSON，从根上消除风险

    6. 常见面试题¶

    Q1：为什么 String 可以被序列化？ String 实现了 Serializable 并声明了 serialVersionUID；内部状态只是一个不可变的 char[]/byte[]（Java 9+），全是纯数据，不依赖线程、平台或运行时资源。推广：状态能完全用数据表达、在另一个 JVM 恢复仍有意义的类才适合序列化。

    Q2：serialVersionUID 不写会怎样？ 运行时按类结构自动计算默认值，对类结构高度敏感——加个字段 UID 就可能变，反序列化旧数据抛 InvalidClassException: local class incompatible。显式声明固定 UID，兼容修改后仍可读取旧数据。

    Q3：单例如何防止序列化破坏？ ① 定义 readResolve() 返回已有实例，JVM 用它替换新建对象；② 用枚举单例——只序列化常量名，按名找回原常量，天然安全。注意 readResolve 无法阻止过程中对象的创建，只是替换最终返回值。

    Q4：transient 修饰 static 字段会怎样？ 什么都不会发生。static 字段属于类而非实例，本来就不参与序列化，transient 是冗余的；反序列化后 static 字段保持当前 JVM 中的值。

    Q5：反序列化会调用构造器吗？ Serializable 类不调用自身构造器，但会调用第一个不可序列化父类的无参构造器；Externalizable 会调用 public 无参构造器创建空对象，再 readExternal 填充。

    7. 练习题¶

    练习 1（基础）：Student(name, age, password) 实现序列化，password 用 transient，写出读回后验证为 null。

    参考答案 
    class Student implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name; private int age;
    private transient String password;
    // 构造器、toString 略
}
// oos.writeObject(new Student("Bob", 20, "secret"));
// (Student) ois.readObject() → Bob/20/null ✅

    练习 2（进阶）：饿汉单例 Config implements Serializable，先不写 readResolve，序列化再反序列化用 == 验证单例被破坏；加上 readResolve 再验证。

    参考答案 
    Config c1 = Config.getInstance();
ByteArrayOutputStream bos = new ByteArrayOutputStream();
new ObjectOutputStream(bos).writeObject(c1);
Config c2 = (Config) new ObjectInputStream(
        new ByteArrayInputStream(bos.toByteArray())).readObject();
System.out.println(c1 == c2); // 有 readResolve：true ✅ 否则 false ❌

    练习 3（挑战）：用 2.8 的 deepCopy 深拷贝含 List 的对象，修改副本验证原件不变；若被引用的类不实现 Serializable 会怎样？

    参考答案 抛出 `NotSerializableException`——深拷贝要求对象图中每个类都可序列化。修复：实现 Serializable，或把该字段标记 transient。

    8. 本章小结¶

    核心知识点： - ✅ 序列化 = 对象 → 字节序列；反序列化反之 - ✅ 类实现标记接口 Serializable；用 writeObject/readObject 读写 - ✅ serialVersionUID 务必显式声明；不写则自动计算，类一改就抛 InvalidClassException - ✅ transient 字段不参与序列化；static 本来就不参与 - ✅ writeObject/readObject 自定义读写；writeReplace/readResolve 替换对象（单例保护） - ✅ Externalizable 完全自主，但强制 public 无参构造器 - ✅ 反序列化不调用构造器；第一个不可序列化父类的无参构造器会被调用 - ✅ 句柄表保证循环引用安全、重复引用只写一份 - ✅ 现代开发优先 JSON；原生序列化警惕反序列化漏洞

    最佳实践： 1. 所有可序列化类显式声明 serialVersionUID = 1L 2. 敏感字段一律 transient 3. 单例加 readResolve，或用枚举单例 4. 不反序列化不可信数据；必要时用 ObjectInputFilter 白名单 5. 跨系统通信优先 JSON 6. 深拷贝优先手写拷贝构造器，序列化深拷贝仅作便捷方案
