    11_JSON¶

    1. JSON 概述¶

    知识点：

    • ⭐ JSON = 轻量文本数据交换格式，跨语言、人类可读，现代开发的事实标准
    • ⭐ Java 三大 JSON 库：Jackson（Spring 默认，功能最全）、Gson（轻量）、Fastjson2（国产高性能）
    • ⚠️ Fastjson 1.x 有严重反序列化漏洞史，新项目一律用 Fastjson2 或 Jackson

    1.1 什么是 JSON¶

    JSON（JavaScript Object Notation）是轻量级的文本数据交换格式。虽然名字里有 JavaScript，但它独立于任何语言——几乎所有语言都有 JSON 解析库。

    🏠 生活类比：Java 原生序列化像"只有中国人能看懂的中文包裹"，JSON 像"联合国通用英文包裹"——任何国家（语言）收到都能打开。

    两种基本结构：
对象：{"name": "张三", "age": 25, "vip": true}
数组：[1, 2, 3] 或 [{"id": 1}, {"id": 2}]

六种数据类型：
string（"abc"）  number（42 / 3.14）  boolean（true/false）
null             object（{...}）      array（[...]）

    ⚠️ JSON 语法易错点： - 键必须用双引号（{name: "张三"} 不合法） - 字符串必须双引号（单引号不合法） - 没有注释、最后一个元素不能有尾逗号

    1.2 JSON vs Java 原生序列化¶

    对比项 Java 原生序列化 JSON
    格式 二进制 文本，人类可读 ✅
    跨语言 ❌ 仅 Java ✅ 任何语言
    结构耦合 强（serialVersionUID 不匹配即失败） 弱（容忍多/少字段）
    安全性 反序列化漏洞多 ❌ 解析数据不执行代码 ✅
    体积 大（含类元信息） 小

    1.3 三大 JSON 库对比 ⭐¶

    对比项 Jackson Gson Fastjson2
    维护方 FasterXML 社区 Google 阿里巴巴
    Spring 集成 ✅ 默认（MVC/Boot） 需手动换 需手动换
    功能 最全（注解/树模型/流式） 中等 丰富
    性能 高 中 ✅ 高
    安全记录 良好 ✅ 良好 ⚠️ 1.x 漏洞史
    适用 服务端首选 Android/轻量场景 高性能需求

    ⭐ 结论：服务端用 Jackson（Spring 默认、生态最全），学透 Jackson 即可覆盖 90% 场景。

    2. Jackson 快速开始 ⭐¶

    知识点： - ⭐ ObjectMapper 是 Jackson 的核心门面类，线程安全，全局一个实例即可 - 序列化：writeValueAsString（对象→JSON）；反序列化：readValue（JSON→对象）

    2.1 依赖与基础示例¶

    <!-- pom.xml -->
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.17.0</version>
</dependency>

    import com.fasterxml.jackson.databind.ObjectMapper;

public class JacksonDemo {
    public static void main(String[] args) throws Exception {
        ObjectMapper mapper = new ObjectMapper();   // 线程安全，复用！

        // ① 对象 → JSON 字符串
        User user = new User(1L, "张三", 25);
        String json = mapper.writeValueAsString(user);
        System.out.println(json);   // {"id":1,"name":"张三","age":25}

        // ② JSON 字符串 → 对象
        User parsed = mapper.readValue(json, User.class);
        System.out.println(parsed.getName());   // 张三

        // ③ 对象 ↔ 文件
        mapper.writeValue(new java.io.File("user.json"), user);
        User fromFile = mapper.readValue(new java.io.File("user.json"), User.class);
    }
}

class User {
    private Long id;
    private String name;
    private int age;
    public User() {}   // ⚠️ Jackson 需要无参构造器（或用其他方案，见 5.3）
    public User(Long id, String name, int age) { this.id = id; this.name = name; this.age = age; }
    // getter/setter 省略——Jackson 默认通过 getter 序列化、setter 反序列化
}

    2.2 ObjectMapper 线程安全 ⭐¶

    ObjectMapper 是线程安全的（配置完成后只读），生产环境：

✅ 正确：单例 / Spring 中注入现成的 Bean
    private static final ObjectMapper MAPPER = new ObjectMapper();

❌ 错误：每次调用 new 一个（配置缓存全浪费，性能差）

    3. Jackson 常用注解 ⭐⭐⭐¶

    知识点： - ⭐ 五大高频注解：@JsonProperty（改名）、@JsonIgnore（忽略）、@JsonFormat（日期格式）、@JsonInclude（空值策略）、@JsonAlias（反序列化别名） - 注解加在字段或 getter 上均可

    3.1 注解速查与示例¶

    import com.fasterxml.jackson.annotation.*;
import java.time.LocalDateTime;

public class Order {
    @JsonProperty("order_no")        // ① 序列化名改为 order_no（下划线风格对接外部系统）
    private String orderNo;

    @JsonIgnore                       // ② 序列化/反序列化都忽略（敏感字段）
    private String internalToken;

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")   // ③ 日期格式化
    private LocalDateTime createTime;

    @JsonInclude(JsonInclude.Include.NON_NULL)     // ④ 为 null 时不输出该字段
    private String remark;

    @JsonAlias({"tel", "mobile"})    // ⑤ 反序列化时额外接受 tel/mobile 作为别名
    private String phone;

    // getter/setter 省略
}

    3.2 序列化效果演示¶

    Order order = new Order();
order.setOrderNo("ORD-001");
order.setInternalToken("secret");      // 被忽略
order.setCreateTime(LocalDateTime.now());
order.setRemark(null);                  // NON_NULL → 不输出
order.setPhone("13800000000");

// 输出：
// {"order_no":"ORD-001","createTime":"2026-08-26 10:30:00","phone":"13800000000"}

    3.3 类级别注解¶

    // 全局策略：整个类所有 null 字段都不输出
@JsonInclude(JsonInclude.Include.NON_NULL)
public class ApiResponse { ... }

// 忽略 JSON 中多出来的未知字段（见 5.1 配置方式的注解版）
@JsonIgnoreProperties(ignoreUnknown = true)
public class ExternalDto { ... }

// 只序列化指定字段（白名单）
@JsonAutoDetect(fieldVisibility = JsonAutoDetect.Visibility.ANY)
public class Config { ... }

    4. 复杂类型处理 ⭐⭐⭐¶

    知识点： - ⭐ 泛型容器必须用 TypeReference（类型擦除导致 List\<User> 反序列化成 List\<LinkedHashMap>） - Map、嵌套对象、数组都有对应写法

    4.1 泛型与 TypeReference（必考）⭐¶

    ObjectMapper mapper = new ObjectMapper();
List<User> users = List.of(new User(1L, "张三", 25), new User(2L, "李四", 30));

// 序列化没问题
String json = mapper.writeValueAsString(users);   // [{...},{...}]

// ❌ 反序列化陷阱：不能直接传 List.class
// List<User> wrong = mapper.readValue(json, List.class);
//   → 元素实际是 LinkedHashMap，取出来强转 User 报 ClassCastException

// ✅ 正确：TypeReference 保留完整泛型信息
List<User> right = mapper.readValue(json, new TypeReference<List<User>>() {});
System.out.println(right.get(0).getName());   // 张三 ✅

// Map 同理
Map<String, User> map = mapper.readValue(mapJson, new TypeReference<Map<String, User>>() {});

    原理：Java 泛型在运行时被擦除，List.class 不知道元素是 User；TypeReference 用匿名子类技巧"冻结"泛型信息到字节码。

    4.2 Map 与嵌套结构¶

    // Map ↔ JSON 天然对应
Map<String, Object> map = new HashMap<>();
map.put("name", "张三");
map.put("scores", List.of(90, 85, 92));      // 嵌套数组
map.put("address", Map.of("city", "杭州"));  // 嵌套对象

String json = mapper.writeValueAsString(map);
// {"name":"张三","scores":[90,85,92],"address":{"city":"杭州"}}

// 反序列化回 Map
Map<String, Object> back = mapper.readValue(json, new TypeReference<Map<String, Object>>() {});

    5. Jackson 高级配置 ⭐⭐⭐⭐¶

    知识点： - ⭐ FAIL_ON_UNKNOWN_PROPERTIES：遇到未知字段是否报错（对接外部接口必关） - ⭐ LocalDateTime 需要 jackson-datatype-jsr310 模块，且 date-format 对它无效 - ⭐ Long 精度丢失：前端 JS 只能安全表示 2^53，超长 ID 序列化为字符串

    5.1 常用全局配置¶

    ObjectMapper mapper = new ObjectMapper();

// ① 遇到 JSON 中多余的未知字段不报错（默认会抛异常）⭐ 对接外部 API 必开
mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);

// ② 空对象不报错（没有任何属性的对象默认序列化报错）
mapper.configure(SerializationFeature.FAIL_ON_EMPTY_BEANS, false);

// ③ 日期全局格式（⚠️ 只对 java.util.Date 生效，LocalDateTime 见 5.2）
mapper.setDateFormat(new SimpleDateFormat("yyyy-MM-dd HH:mm:ss"));

// ④ 全局 null 策略（等价于类上 @JsonInclude(NON_NULL)）
mapper.setSerializationInclusion(JsonInclude.Include.NON_NULL);

    5.2 Java 8 日期时间（高频坑）⭐¶

    <!-- 处理 LocalDateTime 等 Java 8 时间类型的模块 -->
<dependency>
    <groupId>com.fasterxml.jackson.datatype</groupId>
    <artifactId>jackson-datatype-jsr310</artifactId>
    <version>2.17.0</version>
</dependency>

    ObjectMapper mapper = new ObjectMapper();
mapper.registerModule(new JavaTimeModule());   // ⭐ 注册 Java 8 时间模块

// ⚠️ 默认输出时间戳数组 [2026,8,26,10,30]，禁用它：
mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);

// 配合字段上的 @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss") 得到可读格式

    ⚠️ 经典坑：SpringBoot 里 spring.jackson.date-format 对 LocalDateTime 无效（它只作用于 Date）。LocalDateTime 要用 @JsonFormat 注解或自定义 JavaTimeModule 的 serializer。

    5.3 Long 精度丢失（前后端分离必知）⭐¶

    问题根源：
JavaScript 的 Number 只能精确表示 2^53 - 1（9007199254740991）
雪花算法生成的 Long ID（19 位）传给前端 → 末几位变成 0！

解决方案：后端把长整型序列化为字符串

// 方案 1：字段级注解
public class Order {
    @JsonSerialize(using = ToStringSerializer.class)
    private Long id;   // 前端拿到 "1234567890123456789"（字符串）
}

// 方案 2：全局配置（所有 Long 都转字符串，注意影响范围）
SimpleModule module = new SimpleModule();
module.addSerializer(Long.class, ToStringSerializer.instance);
module.addSerializer(Long.TYPE, ToStringSerializer.instance);
mapper.registerModule(module);

    5.4 不可变对象与 record（JDK 17）¶

    // record 天生适配 Jackson 2.12+（通过规范构造器反序列化，无需无参构造）
public record UserVO(Long id, String name) {}

ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(new UserVO(1L, "张三"));
UserVO vo = mapper.readValue(json, UserVO.class);   // ✅ 直接可用

    💡 普通类没有无参构造器会报错，解法：加无参构造 / 构造器加 @JsonCreator + 参数加 @JsonProperty / 用 record。

    6. 树模型 JsonNode：处理动态 JSON ⭐⭐¶

    知识点： - 结构未知/多变的 JSON（如第三方回调）用树模型，不需要定义 POJO - path() 取不到返回 MissingNode（不抛异常），get() 返回 null

    ObjectMapper mapper = new ObjectMapper();
String json = """
    {"user": {"name": "张三", "tags": ["VIP", "活跃"]}, "code": 200}
    """;

JsonNode root = mapper.readTree(json);

// 逐层读取
String name = root.path("user").path("name").asText();      // 张三
int code = root.path("code").asInt();                        // 200
String firstTag = root.path("user").path("tags").get(0).asText();  // VIP

// path vs get：path 取不到返回 MissingNode（链式安全），get 返回 null
String missing = root.path("a").path("b").asText("默认值");   // 不抛异常

// 树模型也能转对象
User user = mapper.treeToValue(root.path("user"), User.class);

    7. Gson 与 Fastjson2 速览¶

    知识点： - 看懂别人的代码库常见写法即可，新项目优先 Jackson - Fastjson 1.x 漏洞多，见到 com.alibaba.fastjson（无 2）要警惕

    7.1 Gson（Google 出品）¶

    <dependency>
    <groupId>com.google.code.gson</groupId>
    <artifactId>Gson</artifactId>
    <version>2.11.0</version>
</dependency>

    Gson gson = new GsonBuilder()
        .setDateFormat("yyyy-MM-dd HH:mm:ss")
        .create();

String json = gson.toJson(user);                    // 对象 → JSON
User u = gson.fromJson(json, User.class);           // JSON → 对象
List<User> list = gson.fromJson(json,               // 泛型用 TypeToken
        new TypeToken<List<User>>() {}.getType());

    7.2 Fastjson2（阿里，注意是 2）¶

    <dependency>
    <groupId>com.alibaba.fastjson2</groupId>
    <artifactId>fastjson2</artifactId>
    <version>2.0.51</version>
</dependency>

    String json = JSON.toJSONString(user);              // 对象 → JSON
User u = JSON.parseObject(json, User.class);        // JSON → 对象
List<User> list = JSON.parseArray(json, User.class);

    7.3 三库 API 对照¶

    操作            Jackson                  Gson                Fastjson2
─────────────────────────────────────────────────────────────────────
序列化          writeValueAsString()     toJson()            toJSONString()
反序列化        readValue()              fromJson()          parseObject()
泛型反序列化    TypeReference            TypeToken           parseObject(json, Type)
忽略字段        @JsonIgnore              @Expose(反向)        @JSONField(serialize=false)

    ⚠️ 安全提示：Fastjson 1.x 的 autoType 反序列化漏洞（远程代码执行）历史上多次爆发，维护方已推荐迁移 Fastjson2。面试提到 Fastjson 时主动说清这段历史是加分项。

    8. JSON 安全 ⚠️¶

    知识点： - JSON 解析本身安全（数据≠代码），风险在"多态反序列化"特性 - 防御：不开启默认多态类型、外部数据不反序列化成任意类型

    风险场景：开启了 Jackson 多态（@JsonTypeInfo / enableDefaultTyping）
后，攻击者在 JSON 里指定恶意类名，反序列化时触发该类的危险逻辑。

防御三原则：
① 不用 enableDefaultTyping（已废弃的 API）
② @JsonTypeInfo 必须配 @JsonSubTypes 白名单（只允许已知子类）
③ 外部输入反序列化为明确的 DTO，不要用 Object/Map 兜底后再强转

    9. 高频面试题 ⭐¶

    Q1：Java 中 JSON 库怎么选？

    服务端首选 Jackson（Spring 默认、功能最全、社区活跃）；Android/轻量场景用 Gson；高性能需求且团队熟悉可用 Fastjson2。坚决不用 Fastjson 1.x（反序列化漏洞史）。

    Q2：ObjectMapper 是线程安全的吗？

    是。配置完成后内部状态只读，生产环境应该全局单例复用。每次 new 会丢失配置缓存，性能差。

    Q3：为什么 List\<User> 反序列化要用 TypeReference？

    Java 泛型运行时擦除，List.class 丢失元素类型，Jackson 只能把元素解析成 LinkedHashMap。TypeReference 通过匿名子类在字节码中保留完整泛型信息。

    Q4：前后端分离中 Long 型 ID 为什么可能失真？怎么解决？

    JavaScript Number 只能精确表示 2^53 内的整数，雪花算法的 19 位 Long ID 超出。解决：后端用 @JsonSerialize(using = ToStringSerializer.class) 把长整型序列化为字符串。

    Q5：SpringBoot 里 LocalDateTime 序列化格式怎么控制？

    先注册 JavaTimeModule（Boot 已自动注册）并禁用 WRITE_DATES_AS_TIMESTAMPS；spring.jackson.date-format 只对 Date 生效，LocalDateTime 要用字段上的 @JsonFormat(pattern = "...") 或自定义 serializer。

    Q6：Jackson 遇到未知字段报错怎么办？

    mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false) 全局关闭，或类上加 @JsonIgnoreProperties(ignoreUnknown = true)。对接外部 API 必配——对方加字段不能导致我方崩。

    10. 练习题¶

    1. 基础读写：定义 Book（id、title、price、publishDate），用 Jackson 实现对象→JSON→对象的往返，验证字段一致。

    2. 注解应用：给 Book 加需求：① JSON 中 title 显示为 book_name；② 增加一个 internalCode 字段不出现在 JSON；③ publishDate（LocalDateTime）输出 yyyy年MM月dd日 格式。

    3. 泛型陷阱：把 List<Book> 序列化后，分别用 readValue(json, List.class) 和 TypeReference 反序列化，用 instanceof 验证两种方式的元素类型差异。

    4. 树模型：解析下面这段 JSON，取出第二个作者的姓名和书籍总数：

    {"data": {"authors": [{"name": "鲁迅", "books": 3}, {"name": "老舍", "books": 5}]}}

    参考答案¶

    // ========== 练习 1：基础读写 ==========
public class Book {
    private Long id;
    private String title;
    private BigDecimal price;
    private LocalDateTime publishDate;
    public Book() {}
    public Book(Long id, String title, BigDecimal price, LocalDateTime publishDate) {
        this.id = id; this.title = title; this.price = price; this.publishDate = publishDate;
    }
    // getter/setter 省略
}

ObjectMapper mapper = new ObjectMapper();
mapper.registerModule(new JavaTimeModule());
mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);

Book book = new Book(1L, "呐喊", new BigDecimal("39.5"), LocalDateTime.now());
String json = mapper.writeValueAsString(book);          // 对象 → JSON
Book parsed = mapper.readValue(json, Book.class);       // JSON → 对象
System.out.println(parsed.getTitle());                  // 呐喊 ✅

// ========== 练习 2：注解应用 ==========
public class Book {
    private Long id;

    @JsonProperty("book_name")                          // ① 改名
    private String title;

    @JsonIgnore                                         // ② 不出现在 JSON
    private String internalCode;

    @JsonFormat(pattern = "yyyy年MM月dd日")              // ③ 日期格式
    private LocalDateTime publishDate;
    // 其余省略
}

// ========== 练习 3：泛型陷阱验证 ==========
String json = mapper.writeValueAsString(List.of(book));

List<?> wrong = mapper.readValue(json, List.class);
System.out.println(wrong.get(0) instanceof Book);               // false
System.out.println(wrong.get(0) instanceof java.util.Map);      // true ← LinkedHashMap！

List<Book> right = mapper.readValue(json, new TypeReference<List<Book>>() {});
System.out.println(right.get(0) instanceof Book);               // true ✅

// ========== 练习 4：树模型 ==========
String json = """
    {"data": {"authors": [{"name": "鲁迅", "books": 3}, {"name": "老舍", "books": 5}]}}
    """;
JsonNode root = mapper.readTree(json);
JsonNode authors = root.path("data").path("authors");
String secondName = authors.get(1).path("name").asText();       // 老舍
int totalBooks = 0;
for (JsonNode a : authors) {
    totalBooks += a.path("books").asInt();                      // 3 + 5
}
System.out.println(secondName + "，共 " + totalBooks + " 本");   // 老舍，共 8 本

    11. 本章小结¶

    主题 核心要点
    选型 服务端用 Jackson；Gson 轻量；Fastjson2 高性能；禁用 Fastjson 1.x
    ObjectMapper 线程安全，全局单例；writeValueAsString / readValue
    注解 @JsonProperty 改名、@JsonIgnore 忽略、@JsonFormat 日期、@JsonInclude 空值、@JsonAlias 别名
    泛型 必须 TypeReference，否则元素变 LinkedHashMap
    日期 LocalDateTime 需 JavaTimeModule；date-format 对它无效
    Long 精度 前端 JS 上限 2^53，长 ID 用 ToStringSerializer 转字符串
    树模型 结构未知用 readTree + path()，链式取值不抛异常
    安全 不开默认多态，@JsonTypeInfo 配白名单

    最佳实践： 1. ObjectMapper 全局单例，配置集中在一处 2. 对接外部 JSON 一律关 FAIL_ON_UNKNOWN_PROPERTIES 3. 前后端分离项目全局处理 Long → String 4. 外部输入反序列化为明确 DTO，不用 Object 兜底
