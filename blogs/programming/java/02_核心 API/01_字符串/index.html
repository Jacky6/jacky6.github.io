    1. String 类¶

    知识点：

    • String 是不可变字符序列，所有"修改"操作都返回新对象，原对象不变
    • ⭐ 字面量字符串共享常量池中的同一对象；new 出来的在堆上另建对象
    • ⚠️ new String("Hello") 创建 1 个或 2 个对象（取决于常量池是否已有）
    • ⭐ == 比较引用，equals 比较内容；字符串比较内容永远用 equals

    1.1 String 概述¶

    String 是 Java 中最常用的类，用于表示不可变的字符序列。

    ⭐ String 为什么设计成不可变？（必考）

    1. 安全：字符串大量用于类加载、网络连接、文件路径。若可变，传进来的参数中途被改，系统就被攻破了

    2. 字符串常量池的前提：只有不可变才能放心共享——多处引用同一个 "Hello" 对象，谁也不怕谁改

    3. 哈希缓存：String 的 hashCode 算一次就缓存起来（常用作 HashMap 的 key），可变的话哈希就失效了

    4. 天然线程安全：不可变对象无需同步

    实现方式：内部字符数组用 final 修饰且 private，所有"修改"操作（replace/substring/toUpperCase）都返回新对象，原对象不变。

    与 C++ 对比：C++ 的 std::string 是可变的；Java 把"不可变字符串 + 可变 StringBuilder"分成两个类。

    特点：

    • ✅ 不可变性：创建后不能修改
    • ✅ 线程安全：不可变所以线程安全
    • ✅ 字符串常量池：节省内存
    • ✅ 基于 char 数组（Java 8）或 byte 数组（Java 9+）
    String str1 = "Hello";
String str2 = "Hello";
String str3 = new String("Hello");

System.out.println(str1 == str2);      // true（同一对象）
System.out.println(str1 == str3);      // false（不同对象）
System.out.println(str1.equals(str3)); // true（内容相同）

    ⚠️ new String("Hello") 创建了几个对象？（经典考题）

    答案：1 个或 2 个。

    • 字面量 "Hello"：若常量池中没有，先在常量池创建 1 个
    • new：在堆中必然创建 1 个新对象
    • 所以：常量池已有 → 1 个（堆里的）；常量池没有 → 2 个（池里 + 堆里）

    补充说明：

    • 常量池在哪？ JDK 6 在永久代（PermGen），JDK 7+ 移到了堆中（一个叫 StringTable 的哈希表，存的是 String 对象的引用）。

    • 为什么不能复用？ new 是语言契约，保证产生一个独立对象。若偷偷返回池里的引用，== 的行为就不可预测了。想复用就显式调 intern()。

    • 常量池没有时，为什么要先往池里放一个？ 字面量 "Hello" 写在源码里，编译期就记录在 class 文件的常量池中。运行到 ldc 字节码时 JVM 必须解析它——查 StringTable，没有就创建一个放进去，这是字面量入池的固定流程，跟后面有没有 new 无关。new 拿到这个池里的引用作为构造参数，再在堆上拷贝出一个独立对象。两步各自独立，所以是 2 个。

    ⚠️ == 与 equals 的分工（贯穿整个 Java 学习）：

    • ==：比较引用（是否同一对象）；基本类型比较值
    • equals()：Object 默认也是比引用，但 String 等类重写为比内容
    • 字符串比较内容永远用 equals()，== 只在需要判断"是不是同一个对象"时用

    ⚠️ 字符串拼接的底层（JDK 8 vs 9+）：

    String s = "a" + "b" + "c";
// 编译期优化：常量直接拼成 "abc"，不产生中间对象（等价于写 "abc"）

String x = "a";
String s2 = x + "b";
// 含变量：JDK 8 编译成 StringBuilder.append 链；
// JDK 9+ 用 invokedynamic（StringConcatFactory），原理类似但更高效
// 注意：循环里拼接每轮都新建 StringBuilder，务必手动复用（见 2.1）

    1.2 字符串创建¶

    // 方式 1：字面量（推荐）。ldc 指令查 StringTable，有就复用，没有就创建并入池 → 0 或 1 个对象
String str1 = "Hello";

// 方式 2：new 关键字。先 ldc 解析 "Hello"（入池），再 new 在堆上拷贝一个 → 1 或 2 个对象
String str2 = new String("Hello");

// 方式 3：字符数组。不涉及字面量，直接在堆上 new 一个，拷贝 char[] → 恰好 1 个对象
char[] chars = {'H', 'e', 'l', 'l', 'o'};
String str3 = new String(chars);

// 方式 4：字节数组。同理，用 byte[] 构造，按默认字符集解码 → 恰好 1 个对象
byte[] bytes = {72, 101, 108, 108, 111};
String str4 = new String(bytes);

    四种方式的本质区别：

    方式 是否入常量池 对象个数 说明
    字面量 "Hello" ✅ 自动入池 0~1 池里有就复用，没有就创建并入池
    new String("Hello") ✅（字面量部分） 1~2 字面量先入池，new 再在堆上拷贝一个
    new String(char[]) ❌ 恰好 1 无字面量，纯堆对象
    new String(byte[]) ❌ 恰好 1 无字面量，按字符集解码后建堆对象

    • 方式 3、4 不经过常量池，因为构造参数是数组而非字面量，ldc 不会触发

    • 方式 4 的 byte[] 构造会使用平台默认字符集解码，生产环境应指定字符集：new String(bytes, StandardCharsets.UTF_8)

    1.3 常用方法¶

    String str = "Hello, World!";

// 获取长度
int len = str.length();  // 13

// 获取字符
char c = str.charAt(0);  // 'H'

// 子字符串
String sub1 = str.substring(7);     // "World!"
String sub2 = str.substring(0, 5);  // "Hello"

// 查找
int index = str.indexOf("World");   // 7
int last = str.lastIndexOf("o");    // 8

// 判断
boolean b1 = str.startsWith("Hello");  // true
boolean b2 = str.endsWith("!");        // true
boolean b3 = str.contains("World");    // true
boolean b4 = str.isEmpty();            // false

// 比较
boolean eq1 = str.equals("Hello, World!");  // true
boolean eq2 = str.equalsIgnoreCase("hello, world!");  // true
int cmp = str.compareTo("Hello, World!");  // 0

// 替换
String replaced = str.replace("World", "Java");  // "Hello, Java!"

// 分割
String[] parts = str.split(", ");  // ["Hello", "World!"]

// 转大小写
String upper = str.toUpperCase();  // "HELLO, WORLD!"
String lower = str.toLowerCase();  // "hello, world!"

// 去空格
String trimmed = "  Hello  ".trim();  // "Hello"

// 转数组
char[] chars = str.toCharArray();
byte[] bytes = str.getBytes();

    JDK 11+ 新增方法（现代项目常用）：

    // isBlank()：判断空白字符串（空串或纯空格），区别于 isEmpty() 只判断长度为 0
"  ".isBlank();   // true
"  ".isEmpty();   // false（长度不为 0）

// strip()：去除 Unicode 空白，比 trim() 更全面（trim 只去 ≤ U+0020 的空白）
"\u3000Hello\u3000".strip();   // "Hello"（去全角空格 U+3000）
"\u3000Hello\u3000".trim();    // "\u3000Hello\u3000"（trim 不认识全角空格）

// repeat(n)：重复 n 次，替代循环拼接
"ab".repeat(3);   // "ababab"

// lines()：按行分割返回 Stream<String>
"a\nb\nc".lines().toList();   // ["a", "b", "c"]

// String.join()（JDK 8+ 静态方法）：便捷拼接，底层走 StringJoiner
String.join(", ", "Java", "Python", "Go");   // "Java, Python, Go"

    常用方法底层实现与复杂度

    方法 底层实现 时间复杂度 备注
    length() 直接返回内部数组长度（属性值） $O(1)$ JDK 9+ 有 coder 字段，但仍是 $O(1)$
    charAt(i) 直接从数组取 value[i] $O(1)$ 越界抛 StringIndexOutOfBoundsException
    substring(b,e) JDK 7u6+ 拷贝出新数组+新 String $O(n)$ JDK 7 早期共享数组（内存泄漏），后改为拷贝
    indexOf(str) 朴素模式匹配（暴力扫描） $O(n \cdot m)$ $n$=主串长，$m$=子串长；未用 KMP
    lastIndexOf(str) 从尾部往回扫 $O(n \cdot m)$ 同上，方向相反
    startsWith(pre) 从头逐字符比较 $O(k)$ $k$=前缀长度
    endsWith(suf) 从尾部对齐逐字符比较 $O(k)$ $k$=后缀长度
    contains(str) 内部调用 indexOf(str) >= 0 $O(n \cdot m)$ 本质就是 indexOf
    isEmpty() 判断 value.length == 0 $O(1)$
    equals(obj) 先比引用→比长度→逐字符比较 $O(n)$ 长度不同直接返回 false（快速失败）
    equalsIgnoreCase() 先比长度，逐字符大写化后比较 $O(n)$ 比 equals 多一次大小写转换
    compareTo(other) 逐字符相减，遇到不等就返回差值 $O(n)$ 字典序比较
    replace(old,new) 遍历找所有匹配→拷贝拼接新数组 $O(n \cdot m)$ 返回新 String，原对象不变
    split(regex) 正则引擎编译+匹配+逐段截取 $O(n)$~$O(n^2)$ 取决于正则复杂度；高频调用建议预编译 Pattern
    toUpperCase() 遍历逐字符转换→新数组+新 String $O(n)$ 某些 Unicode 字符一对多映射会变长
    toLowerCase() 同上 $O(n)$
    trim() 找首尾空白边界→substring 拷贝 $O(n)$ 只去 $\le$ U+0020 的空白；strip()（JDK 11+）覆盖 Unicode 空白
    toCharArray() Arrays.copyOf 拷贝出新 char[] $O(n)$ ⚠️ 返回的是副本，修改不影响原 String
    getBytes() 按默认字符集编码→新 byte[] $O(n)$ ⚠️ 默认字符集依赖平台，生产环境应指定 UTF-8

    关键结论： - 所有"修改"类方法（substring/replace/toUpperCase/trim）都返回新对象，原 String 不变——这是不可变性的直接体现 - indexOf/contains 用的是朴素暴力匹配，没有 KMP 优化；超长文本搜索考虑用 Pattern 预编译或第三方库 - split 内部走正则引擎，每次调用都重新编译正则；循环中频繁 split 应改用预编译的 Pattern.split

    ⚠️ equals vs contentEquals 的区别（容易踩坑）：

    方法 参数类型 说明
    equals(Object) 仅 String 先比引用→比长度→逐字符比较；参数非 String 直接返回 false
    contentEquals(CharSequence) 任意 CharSequence 可与 StringBuilder/StringBuffer 比较内容 
    StringBuilder sb = new StringBuilder("Hello");
String str = "Hello";

str.equals(sb);              // false！参数不是 String 类型
str.contentEquals(sb);       // true，可以和 StringBuilder 比内容

    结论：需要和 StringBuilder/StringBuffer 比较内容时用 contentEquals，String 之间用 equals。

    CharSequence 接口——三者的共同祖先：

    String、StringBuilder、StringBuffer 都实现了 CharSequence 接口（字符序列的抽象）。这是三者同源的体现：

    • CharSequence 定义了 charAt(i)、length()、subSequence()、toString() 等方法
    • 任何接受 CharSequence 参数的方法都能同时接受 String / StringBuilder / StringBuffer
    • contentEquals(CharSequence) 正是利用这个接口实现跨类型内容比较

    2. StringBuilder 和 StringBuffer¶

    知识点：

    • 循环中用 + 拼接会创建大量临时对象，可变字符串类专为高效拼接而生
    • StringBuilder 可变、非线程安全、性能高；StringBuffer 方法加 synchronized，线程安全但性能略低
    • 常用方法：append/insert/delete/replace/reverse，默认容量 16
    • ⚠️ 大量拼接场景务必用 StringBuilder/StringBuffer 代替 String 的 +

    2.1 为什么需要可变字符串¶

    为什么 + 会创建临时对象？

    String 不可变，+ 无法原地修改，只能"造一个新的"。以 str += i 为例：

    // JDK 8 编译器把 str += i 翻译成：
str = new StringBuilder().append(str).append(i).toString();
//       ↑ 每轮 new 一个 StringBuilder        ↑ toString 再 new 一个 String

    每轮循环产生 2 个临时对象（StringBuilder + String），N 轮 = $2N$ 个。StringBuilder 内部还要扩容拷贝，代价更大。

    JDK 9+ 改用 invokedynamic（StringConcatFactory），不再显式 new StringBuilder，但每轮仍产生 1 个新 String——不可变性决定了"拼接 = 新对象"这个事实无法改变。

    而手动复用一个 StringBuilder，N 轮只产生 1 个 StringBuilder + 1 个 最终 String。

    // ❌ 低效：每次 + 都创建新对象
String str = "";
for (int i = 0; i < 1000; i++) {
    str += i;  // 每轮 new StringBuilder + new String → 2 个临时对象
}

// ✅ 高效：只使用一个对象
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(i);  // 原地写入，不产生临时对象
}
String result = sb.toString();  // 最后只 new 1 个 String

    2.2 StringBuilder¶

    特点：

    • ✅ 可变字符序列
    • ✅ 非线程安全
    • ✅ 性能高（单线程推荐）

    实现本质：内部维护一个非 final 的 char[]（JDK 9+ 为 byte[]），与 String 的 final 数组形成对比。append/insert/delete 直接操作这个数组，返回 this（原地修改，不造新对象）。容量不够时按 旧容量 × 2 + 2 扩容（Arrays.copyOf 拷贝到新数组）。最终 toString() 才 new 一个 String 作为不可变的"最终产物"。

    StringBuilder sb = new StringBuilder();

// 追加
sb.append("Hello");
sb.append(", ");
sb.append("World");
sb.append("!");

// 插入
sb.insert(5, " Java");  // "Hello Java, World!"

// 删除
sb.delete(5, 10);  // "Hello, World!"

// 替换
sb.replace(7, 12, "Java");  // "Hello, Java!"

// 反转
sb.reverse();  // "!avaJ ,olleH"

// 长度
int len = sb.length();  // 12

// 容量
int cap = sb.capacity();  // 初始默认 16，超出后自动扩容（此时已扩容）

// 转字符串
String str = sb.toString();

    2.3 StringBuffer¶

    特点：

    • ✅ 可变字符序列
    • ✅ 线程安全（方法有 synchronized）
    • ❌ 性能略低

    实现本质：与 StringBuilder 完全同源——都继承自 AbstractStringBuilder，内部结构、扩容策略一模一样。唯一区别：每个 public 方法都加了 synchronized，保证同一时刻只有一个线程能操作内部数组。代价是获取/释放锁的开销，单线程下白白浪费性能。现代代码中多线程拼字符串的场景极少，JDK 5 之后基本被 StringBuilder 取代。

    StringBuffer sb = new StringBuffer();
sb.append("Hello");
sb.append(" World");

// 方法同 StringBuilder
String str = sb.toString();

    2.4 三者对比¶

    特性 String StringBuilder StringBuffer
    可变性 不可变 可变 可变
    线程安全 ✅ ❌ ✅
    性能 低 高 中
    使用场景 少量操作 单线程多操作 多线程多操作

    3. 字符串常量池¶

    知识点：

    • 字面量字符串共享常量池中的同一对象；new String 在堆中另建对象
    • intern() 返回常量池中对应对象的引用
    • ⚠️ 常量拼接编译期折叠成常量；含变量的运行期拼接会创建新对象

    3.1 常量池原理¶

    字符串常量池（StringTable）是什么？

    • 本质：JVM 内部维护的一个哈希表（C++ 实现），存储 String 对象的引用——相同内容的字符串只存一份，大家共享
    • 对象在哪？ String 对象本身始终在堆上（JDK 6 字面量对象在永久代，JDK 7+ 全部在堆）。StringTable 只存引用，不存对象本体
    • 位置变迁：JDK 6 StringTable 在永久代（PermGen），JDK 7+ 移到堆中（避免 PermGen OOM）
    • 工作流程：ldc 字节码执行时查表 → 命中就返回已有引用，未命中就在堆上创建 String 对象，把引用存入表中

    三种入池方式：

    方式 是否入池 说明
    字面量 "Hello" ✅ 自动 编译期记录在 class 常量池，运行期 ldc 自动入池
    new String("Hello") ⚠️ 部分 字面量入池，但 new 的堆对象不入池
    intern() ✅ 手动 查池→有就返回引用，没有则（JDK 7+）存入当前堆对象引用并返回

    容量与调优：

    • StringTable 桶数固定（默认 60013），可用 -XX:StringTableSize 调整

    • 桶数固定 + 字符串多 → 链表变长 → 查找从 $O(1)$ 退化为 $O(n)$

    • 大量 intern() 会导致 GC 停顿增加、查询变慢

    • 调优：-XX:StringTableSize=200000 扩大桶数

    • 验证：-XX:+PrintStringTableStatistics 退出时打印桶数、条目数、冲突链长度

    String str1 = "Hello";
String str2 = "Hello";
String str3 = new String("Hello");

// str1 和 str2 指向常量池中的同一对象
// str3 在堆中创建新对象

System.out.println(str1 == str2);      // true
System.out.println(str1 == str3);      // false
System.out.println(str1.equals(str3)); // true

// intern()：查常量池，有就返回池中引用，没有就放入再返回
String str4 = str3.intern();  // str3 是堆对象，intern 后 str4 指向池中 "Hello"
System.out.println(str1 == str4);      // true（str4 复用了池中 str1 的引用）

    3.2 常量池优化¶

    日常编码中的常量池最佳实践：

    • 优先用字面量：自动入池复用，无需额外开销
    • 避免无意义的 new：new String("Hello") 白白在堆上多造一个对象，池里还多一份引用
    • 常量拼接编译期就折叠："Hello" + "World" 在编译阶段直接合并为 "HelloWorld"，运行时无拼接开销
    • 含变量的拼接运行期才执行：a + b 变量值不确定，编译期无法折叠，运行时走 StringBuilder / invokedynamic
    // ✅ 推荐：使用字面量
String str1 = "Hello";

// ❌ 不推荐：无意义地 new
String str2 = new String("Hello");

// 字符串拼接
String a = "Hello";
String b = "World";

// 编译期优化（常量拼接）
String c = "Hello" + "World";  // 等效于 "HelloWorld"

// 运行期拼接（创建新对象）
String d = a + b;  // 使用 StringBuilder

    4. 字符串格式化¶

    知识点：

    • String.format() 按占位符格式化并返回字符串；printf 格式化输出到控制台
    • 常用占位符：%s 字符串、%d 整数、%f 浮点、%.2f 保留 2 位小数、%05d 补零、%tY-%tm-%td 日期

    4.1 String.format()¶

    String.format() 的本质：

    • 底层：委托给 java.util.Formatter，按 printf 风格的格式字符串替换占位符，返回拼接好的新 String

    • %s / %d / %f：分别匹配字符串、整数、浮点数，参数类型不符会抛 IllegalFormatConversionException

    • %.2f：.2 表示精度（小数点后 2 位），%05d 中 0 表示补零、5 表示最小宽度

    • %<tm：< 标志表示复用上一个参数，避免为同一天传多次 new Date()

    • 线程安全：Formatter 不是线程安全的，但 String.format() 每次调用都新建 Formatter，用完即弃，无并发问题

    • 性能注意：频繁调用有一定开销（正则解析格式串 + 创建 Formatter），高频场景可考虑预拼接

    // 格式化字符串
String str1 = String.format("Hello, %s!", "World");
// "Hello, World!"

// 数字格式化
String str2 = String.format("Price: %.2f", 19.99);
// "Price: 19.99"

// 整数格式化
String str3 = String.format("Count: %05d", 42);
// "Count: 00042"

// 日期格式化（< 标志表示复用上一个参数，即同一个 Date 对象）
String str4 = String.format("Date: %tY-%<tm-%<td", new Date());
// "Date: 2026-09-17"

    4.2 printf¶

    System.out.printf("Name: %s, Age: %d%n", "Alice", 25);
System.out.printf("Price: $%.2f%n", 19.99);

    5. 经典算法题¶

    5.1 反转字符串¶

    思路：双指针法——toCharArray 转数组后，左右指针向中间靠拢，边走边交换。时间 $O(n)$，空间 $O(n)$（char 数组副本）。也可直接用 StringBuilder.reverse()，底层实现一样。

    public String reverseString(String s) {
    char[] chars = s.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        char temp = chars[left];
        chars[left] = chars[right];
        chars[right] = temp;
        left++;
        right--;
    }
    return new String(chars);
}

// 使用 StringBuilder
public String reverseString2(String s) {
    return new StringBuilder(s).reverse().toString();
}

    5.2 验证回文串¶

    思路：先转小写 + 正则去掉非字母数字，再用双指针从两端向中间比较。[^a-z0-9] 匹配所有非小写字母和数字，replaceAll 替换为空串。

    public boolean isPalindrome(String s) {
    s = s.toLowerCase().replaceAll("[^a-z0-9]", "");
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s.charAt(left) != s.charAt(right)) {
            return false;
        }
        left++;
        right--;
    }
    return true;
}

    5.3 字符串转整数¶

    思路（LeetCode 第 8 题）：先 trim 去空格 → 判断正负号 → 逐字符累加 result = result * 10 + digit → 用 long 防溢出，超 int 范围则截断为 MAX_VALUE / MIN_VALUE。

    ⚠️ 简化版说明：本实现是 LeetCode 8 的简化版，仅处理了空格、正负号和数字部分。遇到首字符非数字/非符号时直接返回 0（符合题意），未处理前导零、小数点等边界情况。完整题解需额外处理前导空格（含 tab）、正负号后非数字立即返回 0 等细节。

    public int myAtoi(String s) {
    s = s.trim();
    if (s.isEmpty()) return 0;

    int sign = 1, index = 0;
    if (s.charAt(0) == '-') {
        sign = -1;
        index++;
    } else if (s.charAt(0) == '+') {
        index++;
    }

    long result = 0;
    while (index < s.length() && Character.isDigit(s.charAt(index))) {
        result = result * 10 + (s.charAt(index) - '0');
        if (result * sign > Integer.MAX_VALUE) return Integer.MAX_VALUE;
        if (result * sign < Integer.MIN_VALUE) return Integer.MIN_VALUE;
        index++;
    }

    return (int)(result * sign);
}

    5.4 最长公共前缀¶

    思路：以第一个字符串为初始前缀，逐个与后续字符串比较——若 indexOf(prefix) != 0（不是前缀），就缩短前缀末尾一位再比，直到匹配或前缀为空。

    public String longestCommonPrefix(String[] strs) {
    if (strs == null || strs.length == 0) return "";

    String prefix = strs[0];
    for (int i = 1; i < strs.length; i++) {
        while (strs[i].indexOf(prefix) != 0) {
            prefix = prefix.substring(0, prefix.length() - 1);
            if (prefix.isEmpty()) return "";
        }
    }
    return prefix;
}

    import java.util.LinkedHashMap;
import java.util.Map;

// 练习 1
public static String countChars(String str) {
    // LinkedHashMap 保持字符首次出现的顺序
    Map<Character, Integer> map = new LinkedHashMap<>();
    for (char c : str.toCharArray()) {
        // getOrDefault：键不存在时返回默认值 0
        map.put(c, map.getOrDefault(c, 0) + 1);
    }
    StringBuilder sb = new StringBuilder();
    for (Map.Entry<Character, Integer> e : map.entrySet()) {
        sb.append(e.getKey()).append("=").append(e.getValue()).append(" ");
    }
    return sb.toString().trim();
}
// countChars("hello") → "h=1 e=1 l=2 o=1"

public static String join(String[] words) {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < words.length; i++) {
        sb.append(words[i]);        // 追加单词
        if (i < words.length - 1) {
            sb.append(",");         // 除最后一个外追加分隔符
        }
    }
    return sb.toString();
}

    7. 高频面试题¶

    Q1：String 为什么设计成不可变？

    ① 字符串常量池的前提——内容可变会导致共享同一引用的变量互相污染；② 安全——网络连接的 host、类加载的类名都是 String，不可变才不会被中途篡改；③ 天然线程安全；④ hashCode 可缓存（String 常用作 HashMap 的 key）。代价：拼接产生新对象。

    Q2：String s = new String("abc") 创建了几个对象？

    最多两个：字面量 "abc" 在常量池中（若不存在则创建），new 在堆中再建一个。若常量池已有 "abc" 则只创建堆中这一个。

    Q3：String、StringBuilder、StringBuffer 怎么选？

    String 不可变，少量拼接/常量用；StringBuilder 可变、非线程安全、最快，单线程大量拼接用（循环里必须用它）；StringBuffer 可变、方法加 synchronized 线程安全，仅多线程共享拼接时需要（现代代码很少用）。

    Q4：字符串拼接的底层原理？

    JDK 8：编译器把 a + b 转成 StringBuilder 的 append 链；但循环内的 += 每轮都新建 StringBuilder + String，性能差。JDK 9+：改用 invokedynamic + StringConcatFactory 优化。最佳实践：循环拼接显式用一个 StringBuilder。

    Q5：字符串驻留（intern）是什么？

    常量池保证相同内容的字符串只存一份。字面量自动入池；new String(...) 创建的堆对象可以调用 intern() 返回池中同内容的引用（池中没有则放入）。JDK 7+ 常量池移到堆中。

    8. 本章小结¶

    核心知识点¶

    ✅ String：不可变、常用方法、常量池
    ✅ StringBuilder：可变、非线程安全、高性能
    ✅ StringBuffer：可变、线程安全
    ✅ 字符串格式化：format、printf

    最佳实践¶

    1. 少量操作用 String：代码简洁
    2. 单线程多操作用 StringBuilder：性能最优
    3. 多线程多操作用 StringBuffer：线程安全
    4. 字符串比较用 equals：不用 ==
    5. 注意空指针：先判断 null 和 empty
