    1. 集合框架概述¶

    知识点： - 集合是存储和操作一组对象的容器：大小动态、只能存对象、功能丰富 - 两大体系：Collection（List 有序可重复 / Set 不可重复 / Queue 队列）+ Map（键值对，不属于 Collection） - ⭐ ArrayList/LinkedList、HashSet/LinkedHashSet/TreeSet、HashMap/TreeMap/ConcurrentHashMap 是最常用实现

    1.1 什么是集合¶

    集合（Collection）是用于存储和操作一组对象的容器。

    数组 vs 集合：

    特性 数组 集合
    大小 固定 动态
    类型 基本类型/对象 只能存储对象
    功能 基础 丰富（增删改查）

    1.2 集合体系结构¶

    Collection（接口）
├── List（接口）- 有序、可重复
│   ├── ArrayList - 动态数组，随机访问快
│   ├── LinkedList - 双向链表（同时实现 Deque）
│   ├── Vector - 线程安全（已过时，改用 CopyOnWriteArrayList）
│   └── CopyOnWriteArrayList - 写时复制，读多写少场景
├── Set（接口）- 不可重复
│   ├── HashSet - 基于 HashMap，无序
│   ├── LinkedHashSet - 保持插入顺序
│   └── TreeSet - 红黑树，有序
└── Queue（接口）- 队列
    ├── PriorityQueue - 二叉堆，优先级出队
    ├── ArrayDeque（Deque 接口）- 双端队列
    └── BlockingQueue 家族 - 阻塞队列（并发篇详解）

Map（接口）- 键值对，不属于 Collection
├── HashMap - 数组 + 链表/红黑树，无序
├── LinkedHashMap - 保持插入顺序/访问顺序（可做 LRU）
├── TreeMap - 红黑树，按键有序
├── Hashtable - 线程安全（已过时）
└── ConcurrentHashMap - 高性能线程安全 ⭐

    2. List 接口¶

    知识点： - List 有序、可重复；ArrayList 基于动态数组，随机访问 O(1)，中间增删 O(n) - LinkedList 双向链表，头尾操作 O(1)，按索引访问 O(n)；同时实现 Deque 可当栈/队列 - ⭐ ArrayList 懒初始化：第一次 add 才分配容量 10，每次扩容 1.5 倍并拷贝数组 - ⚠️ "LinkedList 插入删除一定更快"是误区：按索引定位也是 O(n)

    2.1 ArrayList¶

    特点： - ✅ 基于动态数组 - ✅ 随机访问快 O(1)（实现了 RandomAccess 接口） - ❌ 中间插入删除慢 O(n)（需要移动元素） - ❌ 非线程安全

    import java.util.ArrayList;
import java.util.List;

public class ArrayListDemo {
    public static void main(String[] args) {
        // 创建
        List<String> list = new ArrayList<>();

        // 添加
        list.add("Java");
        list.add("Python");
        list.add(1, "C++");  // 指定位置插入

        // 获取
        String item = list.get(0);  // "Java"

        // 修改
        list.set(0, "Go");

        // 删除
        list.remove(0);
        list.remove("Python");

        // 遍历
        for (String s : list) {
            System.out.println(s);
        }

        // 判断
        boolean contains = list.contains("Go");
        boolean isEmpty = list.isEmpty();
    }
}

    扩容机制 ⭐：

    // JDK 8+ ArrayList 扩容核心逻辑（简化）
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;
    // 新容量 = 旧容量 + 旧容量右移 1 位 = 旧容量的 1.5 倍
    int newCapacity = oldCapacity + (oldCapacity >> 1);
    if (newCapacity - minCapacity < 0)
        newCapacity = minCapacity;
    elementData = Arrays.copyOf(elementData, newCapacity);
}

    要点： - 懒初始化：new ArrayList<>() 时底层数组是空的，第一次 add 才分配长度 10 的数组（DEFAULT_CAPACITY = 10） - 每次扩容为原来的 1.5 倍，并伴随数组拷贝（Arrays.copyOf） - 优化：能预估元素数量时指定初始容量 new ArrayList<>(1000)，避免反复扩容拷贝

    2.2 LinkedList¶

    特点： - ✅ 基于双向链表 - ✅ 头尾插入删除 O(1) - ❌ 随机访问慢 O(n)（要从头或尾遍历到目标位置） - ✅ 同时实现了 Deque 接口，可当栈、队列、双端队列用

    import java.util.LinkedList;

LinkedList<String> list = new LinkedList<>();

// 添加
list.add("A");
list.addFirst("First");
list.addLast("Last");

// 作为栈使用
list.push("Stack");
String pop = list.pop();

// 作为队列使用
list.offer("Queue");
String poll = list.poll();

    注意："LinkedList 插入删除一定比 ArrayList 快"是常见误区。只有在已经持有节点引用（如用迭代器遍历时删除）或头尾操作时才是 O(1)；按索引定位再删除，LinkedList 要先走链表找到位置，反而更慢。

    2.3 ArrayList vs LinkedList¶

    场景 推荐 原因
    随机访问多 ArrayList get(i) O(1)，CPU 缓存友好
    头尾增删（栈/队列） ArrayDeque 比 LinkedList 更快更省内存
    遍历中删除 两者皆可 用迭代器 remove，都是 O(1) 摊销
    按索引频繁中间插入 ArrayList LinkedList 定位就是 O(n)

    实践中绝大多数场景 ArrayList 是更优默认选择；LinkedList 的常见用途已被 ArrayDeque 取代。

    2.4 线程安全的 List¶

    // 方式 1：Collections 包装（所有方法加锁，性能一般）
List<String> syncList = Collections.synchronizedList(new ArrayList<>());

// 方式 2：CopyOnWriteArrayList（写时复制，读完全无锁）⭐
// 写操作时复制新数组，适合读多写少（如监听器列表、配置缓存）
List<String> cow = new CopyOnWriteArrayList<>();

    Vector 是 JDK 1.0 遗留类，每个方法都加 synchronized，已不推荐使用。

    3. Set 接口¶

    知识点： - Set 不可重复；HashSet 无序（基于 HashMap），LinkedHashSet 保持插入顺序，TreeSet 红黑树有序 - ⚠️ 去重原理：先比 hashCode()，哈希相同再比 equals()；自定义对象必须同时重写两者 - TreeSet 要求元素可比较（Comparable 或 Comparator），否则抛 ClassCastException

    3.1 HashSet¶

    特点： - ✅ 基于 HashMap 实现（元素存在 HashMap 的 key 上，value 是固定占位对象） - ✅ 无序、不可重复 - ✅ 允许一个 null

    import java.util.HashSet;
import java.util.Set;

Set<String> set = new HashSet<>();

// 添加
set.add("Java");      // true
set.add("Python");    // true
set.add("Java");      // false（重复）

// 遍历（无序）
for (String s : set) {
    System.out.println(s);
}

    去重原理：先比 hashCode()，哈希相同再比 equals()。因此自定义对象放入 Set 必须同时重写 equals 和 hashCode（详见 Object 类详解）。

    3.2 LinkedHashSet¶

    特点：HashSet 基础上维护了一条双向链表，保持插入顺序。

    Set<String> set = new LinkedHashSet<>();
set.add("C");
set.add("A");
set.add("B");
// 遍历顺序：C, A, B

    3.3 TreeSet¶

    特点：红黑树实现，元素有序（自然排序或 Comparator 排序），增删查均 O(log n)。

    TreeSet<Integer> set = new TreeSet<>();
set.add(3);
set.add(1);
set.add(2);
// 遍历顺序：1, 2, 3（升序）

// 范围查询（NavigableSet 能力）
set.subSet(1, 3);   // [1, 2)
set.headSet(2);     // 小于 2
set.tailSet(2);     // 大于等于 2
set.floor(2);       // 小于等于 2 的最大值
set.ceiling(2);     // 大于等于 2 的最小值

    元素必须可比较（实现 Comparable 或构造时传入 Comparator），否则抛 ClassCastException。

    4. Map 接口 ⭐⭐⭐¶

    知识点： - Map 存键值对，键不可重复；HashMap 允许一个 null 键、多个 null 值，非线程安全、无序 - ⭐ HashMap 底层：数组 + 链表/红黑树；默认容量 16、负载因子 0.75；链表≥8 且数组≥64 树化 - ⭐ JDK 7 头插法并发扩容成环，JDK 8 改尾插法解决成环，但依然不是线程安全的 - LinkedHashMap 维护双向链表（插入序/访问序，可做 LRU）；TreeMap 红黑树按键有序 - ⭐ ConcurrentHashMap：JDK 7 分段锁 → JDK 8 CAS + 桶头节点锁，不允许 null 键值

    4.1 HashMap 基本使用¶

    特点： - ✅ 基于哈希表 - ✅ 键不可重复，值可重复 - ✅ 允许一个 null 键、多个 null 值 - ❌ 非线程安全 - ❌ 无序

    import java.util.HashMap;
import java.util.Map;

public class HashMapDemo {
    public static void main(String[] args) {
        // 创建
        Map<String, Integer> map = new HashMap<>();

        // 添加
        map.put("Java", 1);
        map.put("Python", 2);

        // 获取
        Integer value = map.get("Java");  // 1
        Integer missing = map.get("Go");  // null

        // 获取或默认
        Integer result = map.getOrDefault("Go", 0);

        // 删除
        map.remove("Java");

        // 遍历
        // 方式 1：keySet（不推荐，多一次查表）
        for (String key : map.keySet()) {
            System.out.println(key + " = " + map.get(key));
        }

        // 方式 2：entrySet（推荐）
        for (Map.Entry<String, Integer> entry : map.entrySet()) {
            System.out.println(entry.getKey() + " = " + entry.getValue());
        }

        // 方式 3：forEach
        map.forEach((k, v) -> System.out.println(k + " = " + v));
    }
}

    4.2 HashMap 底层结构 ⭐⭐⭐⭐¶

    整体结构：

    JDK 7：数组 + 链表
JDK 8：数组 + 链表 + 红黑树

table[]（Node 数组，每个位置叫一个"桶" bucket）
┌────┬────┬────┬────┬────┐
│ 0  │ 1  │ 2  │ 3  │ 4  │ ...
└────┴─┬──┴────┴─┬──┴────┘
       │         │
      Node      Node
       │         │
      Node      Node（链表长度 > 8 且数组长度 ≥ 64 时转红黑树）
       │
      Node

    关键常量（源码）：

    常量 值 含义
    DEFAULT_INITIAL_CAPACITY 16 数组默认初始容量
    DEFAULT_LOAD_FACTOR 0.75f 默认负载因子
    TREEIFY_THRESHOLD 8 链表树化阈值
    UNTREEIFY_THRESHOLD 6 红黑树退化回链表阈值
    MIN_TREEIFY_CAPACITY 64 树化要求的最小数组容量

    哈希扰动与定位：

    // 1. 扰动函数：高 16 位参与运算，减少碰撞
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

// 2. 定位桶：容量 n 是 2 的幂，(n-1) & hash 等价于 hash % n 但更快
index = (n - 1) & hash;

    put() 完整流程（面试必背）：

    1. table 为空？ → 先初始化（resize）
2. 计算 hash，定位桶下标 i = (n-1) & hash
3. table[i] 为空？ → 直接放入新节点，跳到 6
4. 桶不为空：
   a. 头节点 key 相同（hash 相等且 equals）→ 覆盖 value
   b. 是红黑树节点 → 按树的方式插入
   c. 是链表 → 尾插法遍历链表：
      - 找到 key 相同的节点 → 覆盖 value
      - 走到尾部 → 插入新节点；若插入后链表长度 ≥ 8 → 树化（见下）
5. 树化判断：链表节点数已达 8 个还要再插入时触发
   - 数组长度 < 64 → 不树化，改为扩容（resize）
   - 数组长度 ≥ 64 → 链表转红黑树
6. ++size > threshold（容量 × 负载因子）→ 扩容为 2 倍

    扩容机制（resize）：

    • 新容量 = 旧容量 × 2（保持 2 的幂），新阈值 = 新容量 × 0.75
    • JDK 8 扩容时不再重新计算哈希：每个节点要么留在原位 i，要么移动到 i + oldCap，只需判断 (e.hash & oldCap) == 0（新增的那一位是 0 还是 1）
    // JDK 8 扩容时链表拆分（高低位两条链，保持原有顺序）
if ((e.hash & oldCap) == 0)  → 留在原下标
else                         → 移动到 原下标 + oldCap
    • JDK 7 的坑：头插法 + 并发扩容会导致链表成环（死循环）；JDK 8 改为尾插法解决了成环问题，但 HashMap 依然不是线程安全的（并发 put 会丢数据、size 不准）

    三个经典追问：

    Q1：为什么容量必须是 2 的幂？ - (n-1) & hash 可以替代取模运算，位运算更快 - 2 的幂保证 n-1 的二进制全是 1，哈希值能均匀分布到每个桶 - 扩容时元素位置只取决于新增的一个比特位，迁移成本最低

    Q2：为什么负载因子是 0.75？ - 时间和空间的折中：1.0 碰撞太多（查找慢），0.5 太浪费空间 - 0.75 时桶中节点数符合泊松分布，单个桶达到 8 个节点的概率约千万分之六

    Q3：为什么树化阈值是 8、退化阈值是 6？ - 理想哈希下桶内节点数服从 λ=0.5 的泊松分布，长度达到 8 的概率约 0.00000006，树化只是极端碰撞下的兜底 - 退化阈值 6 比树化阈值 8 小，留了缓冲带，避免节点数在 7、8 之间震荡时频繁树化/退化 - 红黑树节点占用空间约是链表节点的 2 倍，节点少时链表反而划算

    4.3 LinkedHashMap¶

    特点：HashMap 基础上维护一条双向链表，支持两种顺序：

    // 1. 插入顺序（默认）
Map<String, Integer> map = new LinkedHashMap<>();
map.put("C", 3);
map.put("A", 1);
map.put("B", 2);
// 遍历顺序：C, A, B

// 2. 访问顺序（accessOrder = true）：最近访问的排最后 → 天然适合做 LRU 缓存
Map<String, Integer> lru = new LinkedHashMap<>(16, 0.75f, true);
lru.put("a", 1);
lru.put("b", 2);
lru.get("a");          // 访问 a，a 被移到链表尾部
// 遍历顺序：b, a

    用 LinkedHashMap 实现 LRU 缓存：

    class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCache(int capacity) {
        // accessOrder=true：按访问顺序维护链表
        super(capacity, 0.75f, true);
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        // 超出容量时自动移除最久未访问的（链表头部）
        return size() > capacity;
    }
}

    4.4 TreeMap¶

    特点：红黑树实现，按键排序，增删查 O(log n)，支持范围查询（NavigableMap）。

    Map<String, Integer> map = new TreeMap<>();
map.put("C", 3);
map.put("A", 1);
map.put("B", 2);
// 遍历顺序：A, B, C（自然排序）

// 范围操作
map.subMap("A", "C");     // [A, C)
map.headMap("B");         // 键小于 B
map.tailMap("B");         // 键大于等于 B
map.firstKey();           // A
map.lastKey();            // C

    4.5 HashMap vs Hashtable vs ConcurrentHashMap¶

    特性 HashMap Hashtable ConcurrentHashMap
    线程安全 ❌ ✅（全表锁） ✅（桶级锁）
    null 键/值 允许 不允许 不允许
    锁粒度 无锁 整个 Map 单个桶头节点
    性能 高 低 高
    迭代器 fail-fast fail-fast 弱一致（不抛异常）
    推荐 单线程 已过时 多线程 ⭐

    Collections.synchronizedMap() 也是全表锁，性能接近 Hashtable，且复合操作（如 get 后 put）仍需自己加锁。

    4.6 ConcurrentHashMap 底层 ⭐⭐⭐⭐¶

    JDK 7：分段锁（Segment）

    ConcurrentHashMap
├── Segment[0]（ReentrantLock）→ 小 HashTable
├── Segment[1]（ReentrantLock）→ 小 HashTable
├── ...
└── Segment[15]              （默认 16 段，并发度 16）

    不同 Segment 可以并发写；同一个 Segment 内仍互斥。

    JDK 8：抛弃 Segment，CAS + synchronized

    table[]（Node 数组，与 HashMap 结构一致：数组 + 链表/红黑树）
put 流程：
1. 计算 hash 定位桶
2. 桶为空 → CAS 写入（无锁）
3. 桶不为空 → synchronized 锁住桶的头节点，再遍历链表/红黑树插入
4. 链表长度 ≥ 8 且数组 ≥ 64 → 树化
5. size 统计：baseCount + CounterCell 数组分散热点（类似 LongAdder）

    要点： - 锁粒度从"段"细化到"桶头节点"，并发度 = 桶数量 - get 不加锁：Node 的 val 和 next 都是 volatile，保证可见性 - 不允许 null 键值：并发场景下 get(k) == null 无法区分"没有这个键"还是"值就是 null"（单线程的 HashMap 可以 containsKey 二次确认，并发下做不到） - 迭代器弱一致：遍历时不抛 ConcurrentModificationException，但不保证看到遍历开始后的修改 - size() 是估算值（并发计数），putIfAbsent、compute、merge 等原子方法优先使用

    ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

// 线程安全的"读后写"，用原子方法而不是先 get 再 put
map.putIfAbsent("k", 1);
map.compute("k", (key, v) -> v == null ? 1 : v + 1);
map.merge("k", 1, Integer::sum);   // 计数惯用法

    5. Queue 家族¶

    知识点： - PriorityQueue 是数组实现的二叉最小堆，按优先级出队，入队/出队 O(log n) - ArrayDeque 循环数组双端队列，可当栈/队列，比 LinkedList 更快更省内存，不允许 null - BlockingQueue 的 put/take 在满/空时阻塞，是生产者-消费者模型首选

    5.1 PriorityQueue（优先级队列）¶

    • 底层是数组实现的二叉最小堆，出队顺序按优先级（自然排序或 Comparator），不是先进先出
    • 入队/出队 O(log n)，非线程安全
    PriorityQueue<Integer> pq = new PriorityQueue<>();  // 最小堆
pq.offer(5);
pq.offer(1);
pq.offer(3);
System.out.println(pq.poll());  // 1（最小的先出）
System.out.println(pq.poll());  // 3

// 最大堆：反转比较器
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());

// Top-K 问题：维护大小为 K 的最小堆

    5.2 ArrayDeque（双端队列）¶

    • 循环数组实现，可当栈也可当队列，比 LinkedList 更快更省内存（无节点对象开销）
    • 不允许 null 元素
    Deque<String> stack = new ArrayDeque<>();
stack.push("A");          // 当栈用
stack.pop();

Deque<String> queue = new ArrayDeque<>();
queue.offer("B");         // 当队列用
queue.poll();

    5.3 BlockingQueue（阻塞队列，了解）¶

    实现 特点
    ArrayBlockingQueue 数组有界队列，创建时必须指定容量
    LinkedBlockingQueue 链表队列，默认容量 Integer.MAX_VALUE（慎用）
    SynchronousQueue 不存储元素，直接交接（CachedThreadPool 用它）
    PriorityBlockingQueue 优先级 + 阻塞
    DelayQueue 延迟队列（定时任务、缓存过期）

    put/take 在满/空时阻塞线程，是生产者-消费者模型的首选。详见 多线程基础 和 并发工具类详解。

    6. Comparator 与排序 ⭐⭐⭐¶

    知识点： - Comparable 是类内部实现的自然排序（compareTo）；Comparator 是外部定义的定制排序（compare），不侵入类 - ⭐ Comparator 支持链式组合：comparing/comparingInt + reversed/thenComparing - ⚠️ compareTo 结果应与 equals 一致，否则 TreeSet/TreeMap 行为"看起来不对" - List.sort 用 TimSort（稳定）；Arrays.sort(int[]) 用双轴快排（基本类型无稳定性问题）

    6.1 Comparable vs Comparator¶

    Comparable Comparator
    位置 类内部实现 外部独立定义
    方法 compareTo(T o) compare(o1, o2)
    语义 自然排序（类的默认规则） 定制排序（可多个）
    侵入性 要改类 不改类 
    // Comparable：类自己定义"自然顺序"
class Student implements Comparable<Student> {
    String name;
    int age;

    @Override
    public int compareTo(Student other) {
        return Integer.compare(this.age, other.age);  // 按年龄升序
    }
}

// Comparator：外部定制，想怎么排就怎么排
Comparator<Student> byName = Comparator.comparing(s -> s.name);
Comparator<Student> byAgeDesc = Comparator.comparingInt((Student s) -> s.age).reversed();
// 组合：先按年龄，年龄相同按姓名
Comparator<Student> combined = Comparator.comparingInt((Student s) -> s.age)
                                         .thenComparing(s -> s.name);

list.sort(combined);
Collections.sort(list, byName);   // 等价写法

    约定：compareTo 的结果应与 equals 一致（a.compareTo(b) == 0 时 a.equals(b) 应为 true），否则 TreeSet/TreeMap 的行为会"看起来不对"。

    6.2 排序算法与稳定性¶

    • Collections.sort / List.sort：对象数组用 TimSort（归并+插入，稳定，O(n log n)）
    • Arrays.sort(int[])：基本类型用双轴快速排序（不稳定，但基本类型无稳定性问题）
    • 稳定性：相等的元素排序后相对位置不变。需要"多字段排序保持前一次顺序"时必须用稳定排序

    7. fail-fast 与 fail-safe ⭐⭐⭐¶

    知识点： - ⭐ fail-fast：迭代器检查 modCount，遍历中被结构性修改就抛 ConcurrentModificationException - ⚠️ foreach 中直接删除会触发 fail-fast；正确做法是 iterator.remove() 或 removeIf() - fail-safe：ConcurrentHashMap 迭代器弱一致、CopyOnWriteArrayList 基于快照，遍历中修改不抛异常

    7.1 fail-fast（快速失败）¶

    ArrayList、HashMap 等集合内部维护 modCount（结构性修改次数）。迭代器创建时记住 expectedModCount，每次 next() 都检查，不一致就抛 ConcurrentModificationException。

    List<String> list = new ArrayList<>(List.of("A", "B", "C"));

// ❌ 错误：foreach 中直接删除 → 抛 ConcurrentModificationException
for (String s : list) {
    if ("B".equals(s)) {
        list.remove(s);
    }
}

// ✅ 正确 1：用迭代器的 remove（会同步更新 expectedModCount）
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if ("B".equals(it.next())) {
        it.remove();
    }
}

// ✅ 正确 2：Java 8+ removeIf
list.removeIf("B"::equals);

    fail-fast 是尽力而为的检测（modCount 没有 volatile 修饰），不能用来保证线程安全，只能尽早暴露 bug。

    7.2 fail-safe（安全失败）¶

    • ConcurrentHashMap：迭代器弱一致，遍历的是创建时的状态，不抛异常，也不保证看到后续修改
    • CopyOnWriteArrayList：迭代器基于创建时的数组快照，遍历期间修改完全不影响迭代器

    8. 不可变集合与工厂方法（Java 9+）¶

    知识点： - List.of/Set.of/Map.of 创建不可变集合，不允许 null，修改抛 UnsupportedOperationException - Collections.unmodifiableList 是只读视图：原集合变了它也跟着变 - List.copyOf 创建不可变副本，适合对外部传入集合做防御性拷贝

    // Java 9+ 集合工厂：简洁 + 不可变 + 不允许 null
List<String> list = List.of("A", "B", "C");
Set<String> set = Set.of("A", "B");
Map<String, Integer> map = Map.of("A", 1, "B", 2);
Map<String, Integer> map2 = Map.ofEntries(
    Map.entry("A", 1),
    Map.entry("B", 2)
);

list.add("D");           // ❌ UnsupportedOperationException
// list 中放入 null   // ❌ NullPointerException

// 传统包装方式（视图，原集合变了它也跟着变）
List<String> unmodifiable = Collections.unmodifiableList(new ArrayList<>(list));

// 防御性拷贝：把外部传入的集合变成自己可控的副本
List<String> defensive = List.copyOf(externalList);
    方式 可变性 null 说明
    List.of 不可变 ❌ Java 9+，推荐
    Collections.unmodifiableList 视图（原集合变则跟着变） ✅ 只读包装
    List.copyOf 不可变副本 ❌ 防御性拷贝

    9. Java 8+ 集合新特性¶

    知识点： - Java 8 为集合带来两类新特性：Stream API 链式处理 + Map 接口的计算方法 - Stream：filter/map/collect 链式调用完成过滤、映射、收集，不修改原集合 - computeIfAbsent 键不存在才计算并放入（懒初始化）；computeIfPresent 键存在才更新 - ⭐ merge(key, 1, Integer::sum) 是计数/合并的万能写法：不存在则 put，存在则 value = old + 1

    9.1 Stream API¶

    List<String> list = Arrays.asList("Java", "Python", "C++");

// 过滤 + 映射 + 收集
List<String> result = list.stream()
    .filter(s -> s.length() > 3)
    .map(String::toUpperCase)
    .collect(Collectors.toList());
// 输出：[JAVA, PYTHON]

    完整用法见 Stream API。

    9.2 Map 新方法¶

    Map<String, Integer> map = new HashMap<>();

// computeIfAbsent：键不存在才计算并放入（懒初始化）
map.computeIfAbsent("Java", k -> 0);

// computeIfPresent：键存在才更新
map.computeIfPresent("Java", (k, v) -> v + 1);

// merge：计数/合并的万能写法
map.merge("Java", 1, Integer::sum);
// 等价于：不存在则 put("Java", 1)，存在则 value = old + 1

    10. 常见面试题¶

    Q1：HashMap 的 put 流程？ → 见 4.2 节六步流程。

    Q2：HashMap 为什么线程不安全？JDK 7 和 8 各有什么问题？ JDK 7 头插法并发扩容会链表成环（死循环）；JDK 8 尾插法解决了成环，但并发 put 仍可能覆盖丢数据、size 不准。线程安全请用 ConcurrentHashMap。

    Q3：HashMap 和 Hashtable 的区别？ → 见 4.5 节对比表。

    Q4：ConcurrentHashMap 如何保证线程安全？ JDK 7 分段锁（Segment，默认 16 段）；JDK 8 改为 CAS（空桶插入）+ synchronized（锁桶头节点），锁粒度更细；get 无锁（volatile 保证可见性）。

    Q5：HashMap 的 key 需要满足什么条件？ 正确重写 equals 和 hashCode（equals 相等 → hashCode 必须相等）；最好用不可变对象（如 String、Integer）做 key，否则放入后修改 key 会导致再也取不出来。

    Q6：如何遍历 Map？哪种最快？ entrySet 遍历（一次拿到 key 和 value）优于 keySet + get（多一次哈希查找）；Java 8+ 可用 forEach。

    Q7：什么是 fail-fast？ 迭代器检查 modCount，遍历中被结构性修改就抛 ConcurrentModificationException。正确删除用 iterator.remove() 或 removeIf()。

    11.1 两数之和¶

    public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();

    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (map.containsKey(complement)) {
            return new int[]{map.get(complement), i};
        }
        map.put(nums[i], i);
    }

    return new int[]{};
}

    11.2 有效的字母异位词¶

    public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;

    Map<Character, Integer> map = new HashMap<>();

    for (char c : s.toCharArray()) {
        map.put(c, map.getOrDefault(c, 0) + 1);
    }

    for (char c : t.toCharArray()) {
        map.put(c, map.getOrDefault(c, 0) - 1);
        if (map.get(c) < 0) return false;
    }

    return true;
}

    11.3 数组中的第 K 大元素（PriorityQueue）¶

    public int findKthLargest(int[] nums, int k) {
    // 维护大小为 k 的最小堆，堆顶就是第 k 大
    PriorityQueue<Integer> heap = new PriorityQueue<>(k);
    for (int num : nums) {
        if (heap.size() < k) {
            heap.offer(num);
        } else if (num > heap.peek()) {
            heap.poll();
            heap.offer(num);
        }
    }
    return heap.peek();
}

    import java.util.*;

// 练习 1
public static Map<String, Integer> wordCount(String text) {
    Map<String, Integer> map = new HashMap<>();
    String[] words = text.split(" ");  // 按空格分词
    for (String word : words) {
        if (word.isEmpty()) {
            continue;  // 跳过多余空格产生的空串
        }
        // merge：键不存在则放 1，存在则用 (旧值, 1) -> 旧值 + 1 更新
        map.merge(word, 1, Integer::sum);
    }
    return map;
}
// wordCount("java is fun java is great") → {java=2, is=2, fun=1, great=1}

// 练习 2
public static List<Integer> dedup(List<Integer> list) {
    // LinkedHashSet：既去重，又保持插入顺序
    Set<Integer> set = new LinkedHashSet<>(list);
    return new ArrayList<>(set);  // 再转回 List
}
// dedup(Arrays.asList(3, 1, 2, 1, 3)) → [3, 1, 2]
// 不需要保持顺序可用 HashSet；需要排序可用 TreeSet

// 练习 3 答案：
// (1) [A, C, B] —— add(1, "C") 在索引 1 处插入，B 被挤到索引 2
// (2) 1 —— Map 的键不可重复，第二次 put 覆盖了旧值
// (3) 2 —— 覆盖后 "Java" 对应的值是 2

// 练习 4：LinkedHashMap accessOrder + removeEldestEntry
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    LRUCache(int capacity) {
        super(capacity, 0.75f, true);  // true = 按访问顺序
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;  // 超容量自动淘汰链表头（最久未访问）
    }
}
// get/put 都会把节点移到链表尾部，链表头始终是最久未访问的元素

    核心知识点¶

    ✅ List：ArrayList（随机访问、1.5 倍扩容）、LinkedList（双向链表）、CopyOnWriteArrayList（读多写少）
