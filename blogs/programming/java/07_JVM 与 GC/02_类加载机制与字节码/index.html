    02_类加载机制与字节码¶

    本章深挖类加载细节与字节码：类怎么被装进内存？.class 里到底是什么？多态在字节码层如何实现？ 这是动态代理、SPI、Spring 的底层原理，也是面试最高频考点。Java 不像 C++ 编译期链接所有符号，而是运行时按需加载类——这是本章一切机制的根源。

    1. 类加载全过程详解¶

    知识点： - ⭐ 五个阶段：加载 → 验证 → 准备 → 解析 → 初始化（中间三步合称链接） - ⭐ 初始化触发时机（主动引用）是面试必考点 - 准备阶段只赋零值，static final 常量例外

    .class 字节流 → ①加载(读字节流) → ②链接(验证→准备→解析) → ③初始化(执行 <clinit>)

    1.1 五阶段速查表 ⭐¶

    阶段 做什么 关键点
    ① 加载 按全限定名读取字节流，在方法区生成 Class 对象 字节流可来自 jar、网络、动态生成（代理类）
    ② 验证 校验文件格式、元数据、字节码、符号引用 防恶意字节码；-noverify 已被废弃
    ③ 准备 为静态变量分配内存并赋零值 static final 常量直接赋值（ConstantValue）
    ④ 解析 符号引用 → 直接引用 可延迟到运行期（支持动态绑定）
    ⑤ 初始化 执行 <clinit>()：静态赋值 + 静态块 JVM 加锁保证线程安全、只执行一次

    ⚠️ <clinit>() 是源码中静态变量赋值与静态块的按序拼接；没有任何静态成员时可以没有它。这正是静态懒汉单例天然线程安全的原因。

    1.2 准备 vs 初始化：代码验证¶

    public class PrepareDemo {
    public static int a = 7;          // 准备阶段后 a=0，初始化阶段后 a=7
    public static final int B = 7;    // 准备阶段后 B=7（ConstantValue 属性）

    public static void main(String[] args) {
        System.out.println(a + ", " + B); // 输出 7, 7（main 前初始化已完成）
    }
}

    1.3 初始化的触发时机（主动引用）⭐¶

    只有 6 种主动引用触发初始化，其余都是被动引用：

    主动引用 例子
    new / 读写静态字段 / 调用静态方法 new Obj()、Obj.x、Obj.foo()
    反射调用 Class.forName("X")
    初始化子类前先初始化父类 new Child() 触发 Parent.<clinit>
    main 方法所在的主类 启动类最先初始化
    MethodHandle 调用 REF_invokeStatic 句柄对应的静态方法
    含 default 方法的接口被实现 实现类初始化 → 接口初始化

    被动引用经典三连（面试陷阱）：

    public class LoadDemo {
    static class Parent {
        static int value = 10;
        static { System.out.println("Parent 初始化"); }
    }
    static class Child extends Parent {
        static { System.out.println("Child 初始化"); }
    }

    public static void main(String[] args) {
        // ① 通过子类读父类静态字段：只初始化 Parent，Child 不初始化
        System.out.println(Child.value);
        // ② 数组定义不触发元素类的初始化
        Child[] arr = new Child[5];
    }
}
// 输出：
// Parent 初始化
// 10

    🧠 C++ 类比：相当于 C++11 的 magic statics——推迟到首次主动使用，且保证线程安全的一次性执行。

    ✅ 用 java -verbose:class LoadDemo 可观察每个类的加载时机。

    2. 双亲委派模型深挖¶

    知识点： - ⭐ 加载请求先逐级向上委派，父加载器搞不定才自己加载 - JDK 9+ 三层：Bootstrap / Platform / Application（Extension 已更名） - ⭐ 打破场景：SPI（线程上下文类加载器）、Tomcat、OSGi、热部署

    2.1 结构与 loadClass 逻辑¶

       Bootstrap ClassLoader    java.lang.* 核心类（JVM 内置，C++ 实现）
        ▲ 委派向上 / 失败回退
   Platform ClassLoader     JDK 平台模块（JDK 9+，原 Extension）
        ▲
   Application ClassLoader  classpath（你的业务代码）
        ▲
   自定义 ClassLoader        findClass() 是打破委派的入口

    ClassLoader.loadClass() 核心逻辑：先 findLoadedClass() 查缓存 → 没加载就委派父加载器 → 父抛 ClassNotFoundException 才轮到自己 findClass()。

    ✅ 为什么需要双亲委派： 1. 安全：你自己写的 java.lang.String ❌ 永远不会被加载（Bootstrap 先加载了正版） 2. 唯一：同一个类只被加载一次，避免重复加载与类型混乱

    🐍 Python 类比：像 sys.modules 缓存 + import 委派的组合，保证同名模块只导入一次；Java 把它上升为安全架构。

    2.2 打破双亲委派的场景 ⭐¶

    场景 为什么要打破 手段
    SPI（JDBC/JNDI） 接口由 Bootstrap 加载，实现在第三方 jar 线程上下文类加载器 TCCL
    Tomcat 多 webapp 需隔离，且优先加载应用自身类 WebAppClassLoader 子优先
    OSGi 模块化热部署，bundle 间网状依赖 每 Bundle 一个加载器，委派成网
    热部署/热替换 同名类要加载出"新版本" 新建自定义加载器替换旧的

    SPI 与线程上下文类加载器（TCCL）：java.sql.Driver 接口由 Bootstrap 加载，但 MySQL 驱动实现在 classpath 上——父加载器无法"向下"加载！解法：DriverManager 通过 Thread.currentThread().getContextClassLoader()（默认 AppClassLoader）配合 ServiceLoader.load()，借"子加载器"完成反向加载：

    // ServiceLoader.load() 的本质（JDK 源码简化）：
// ClassLoader cl = Thread.currentThread().getContextClassLoader(); // 默认 AppClassLoader
// return new ServiceLoader<>(cl, service);  // 父接口 + 子实现，打破双亲委派

    Tomcat：每个 webapp 有独立 WebAppClassLoader，先自己加载应用类（child-first）再向上委派；不同应用可用同名不同版本的类且互不干扰，是多应用隔离部署的基石。

    3. 字节码文件结构¶

    知识点： - ⭐ class 文件 = 魔数 + 版本号 + 常量池 + 访问标志 + 字段表 + 方法表 + 属性表 - ⭐ 会用 javap -v 读懂真实输出，面试能逐行解释

    3.1 整体结构图¶

    u4 magic(0xCAFEBABE) → u2 版本号(major 61=JDK17) → 常量池(类的"通讯录")
→ 访问标志 + this/super/interfaces → 字段表 → 方法表(含字节码) → 属性表(Code 等)
    major 版本 对应 JDK major 版本 对应 JDK
    52 8 61 17
    55 11 65 21

    4. 方法调用指令与多态¶

    知识点： - ⭐ 五条调用指令对应五类调用目标 - ⭐ 静态分派（重载，编译期定）vs 动态分派（重写，运行期查 vtable） - lambda 用 invokedynamic，调用目标在运行期才生成

    4.1 五种指令对比 ⭐¶

    指令 调用目标 分派方式 典型例子
    invokestatic 静态方法 编译期 Math.max(a,b)
    invokespecial 构造器 / private / super 编译期 super.toString()
    invokevirtual 类实例方法 运行期动态 obj.toString()
    invokeinterface 接口方法 运行期动态 list.add(x)
    invokedynamic 动态调用点 由引导方法决定 lambda、字符串拼接 
    public class InvokeDemo {
    interface Greeter { String greet(String n); }
    static void staticM() {}
    void virtualM() {}
    private void specialM() {}

    public static void main(String[] args) {
        staticM();                          // invokestatic
        InvokeDemo d = new InvokeDemo();    // <init> → invokespecial
        d.virtualM();                       // invokevirtual
        d.specialM();                       // private → invokespecial
        Greeter g = n -> "hi " + n;         // lambda → invokedynamic
        System.out.println(g.greet("Java"));// invokeinterface
    }
}

    4.2 多态如何实现：动态分派¶

    重载是静态分派（编译器看声明类型），重写是动态分派（JVM 看实际类型）：

    invokevirtual obj.show() → 堆中对象头 → Klass 类元数据 → vtable 按槽位索引
                                        找到实际类型（Dog）的重写版本 → 执行

    public class DispatchDemo {
    static class Animal { void show() { System.out.println("Animal"); } }
    static class Dog extends Animal {
        @Override void show() { System.out.println("Dog"); }
    }

    public static void main(String[] args) {
        Animal a = new Dog();
        a.show();   // 字节码写死调 Animal.show，运行期 vtable 找到 Dog.show
    }               // 输出 Dog
}

    🧠 C++ 类比：与 vtable 思路完全一致，invokevirtual 就是"虚指针查虚表"的 Java 版；invokeinterface 因一个接口可有任意多个实现，额外需要 itable。

    ⚠️ JIT 优化：对只有一个实现类的 invokevirtual，HotSpot 会做去虚化（内联为直接调用）——所以 Java 多态的开销常常是零。

    5. 动态代理的字节码原理¶

    知识点： - ⭐ JDK Proxy：运行时生成实现接口的 $ProxyN，用 invokevirtual 调 InvocationHandler.invoke - ⭐ CGLIB：生成目标类的子类，MethodInterceptor + FastClass 索引调用

    5.1 JDK Proxy 生成的字节码长什么样¶

    import java.lang.reflect.Proxy;

interface Greeting { String sayHello(String name); }

public class JdkProxyDemo {
    public static void main(String[] args) {
        // 加 -Djdk.proxy.ProxyGenerator.saveGeneratedFiles=true 可把 $Proxy0.class 落盘观察
        Greeting proxy = (Greeting) Proxy.newProxyInstance(
            Greeting.class.getClassLoader(),
            new Class<?>[]{Greeting.class},
            (p, method, a) -> "Hello, " + a[0] + " via " + method.getName());
        System.out.println(proxy.sayHello("World"));
        System.out.println(proxy.getClass().getName()); // jdk.proxy1.$Proxy0
    }
}

    生成的 $Proxy0 extends Proxy implements Greeting，每个接口方法都归结为同一模式——invokevirtual 调用 handler.invoke：

    public final String sayHello(String);
  Code:
     1: getfield      #16   // Field Proxy.h:InvocationHandler
     5: getstatic     #18   // Field m3:Method（静态块缓存的 sayHello）
     9: anewarray     #20   // 把参数装进 Object[]
    16: invokevirtual #22   // InvocationHandler.invoke(Object,Method,Object[])
    22: areturn             // 结果强转 String 后返回

    ✅ 结论：JDK 代理本质是接口委托 + 反射调用；Method 对象在静态块里一次缓存，避免每次查找。

    5.2 CGLIB 的子类字节码¶

    CGLIB（基于 ASM）生成 Target$$EnhancerByCGLIB$$xxx extends Target，重写所有非 final 方法并转发给 MethodInterceptor.intercept；配套的 FastClass 用索引直接调用替代反射：

    public final void doSomething() {
    MethodInterceptor mi = this.CGLIB$CALLBACK_0;
    if (mi != null) mi.intercept(this, CGLIB$doSomething$0$Method, ...);
    else CGLIB$doSomething$0();   // 等价 super.doSomething()
}
    对比 JDK 动态代理 CGLIB
    生成方式 $ProxyN 实现接口 子类继承目标类
    调用方式 Method.invoke 反射 FastClass 索引直调（更快）
    限制 必须有接口 不能代理 final 类/方法
    典型应用 Spring AOP（有接口的 bean） Spring AOP（无接口）、Mockito

    ⚠️ 两者都在运行期生成新类、占用元空间——这正是 01 章说"动态类多的服务容易 Metaspace OOM"的原因。

    6. 高频面试题¶

    Q1：Class.forName() 与 ClassLoader.loadClass() 的区别？ 答：Class.forName(name) 默认 initialize=true，会触发 <clinit>；loadClass() 只到加载+链接。JDBC 用前者因为驱动注册依赖静态块；Spring 加载 bean 类常用后者避免初始化副作用。

    Q2：为什么 static final 常量引用不触发初始化？ 答：编译期常量被 javac 解析后直接写入调用方的常量池（ConstantValue），运行期与定义类再无依赖，属于被动引用。

    Q3：SPI 为什么必须打破双亲委派？ 答：SPI 接口（如 java.sql.Driver）由 Bootstrap 加载，实现在 classpath 第三方 jar 里——父加载器无法反向加载子路径，于是借 TCCL 让"子加载器"加载实现，本质是接口与实现由不同层级加载器加载。

    Q4：Tomcat 的类加载体系是怎样的？ 答：每个 webapp 有独立 WebAppClassLoader，子优先先加载应用自身类再向上委派到 Common 加载器；不同应用同名类互相隔离，支撑多版本共存与热部署。

    Q5：JDK 代理和 CGLIB 的字节码级区别？ 答：JDK 生成接口实现类，核心是 invokevirtual 调 InvocationHandler.invoke（反射）；CGLIB 生成子类，重写方法转发给 MethodInterceptor，靠 FastClass 索引调用避开反射、更快，但不能代理 final 类/方法。

    Q6：lambda 用哪条指令？为什么不生成匿名内部类？ 答：invokedynamic。首次执行到 lambda 时引导方法（LambdaMetafactory）才动态生成函数式接口实现类；编译期不产生内部类，后续可自由优化（单例复用、内联）。

    7. 练习题¶

    1. 写代码验证"static final 编译期常量是被动引用"：访问 Util 类的常量不应打印其静态块日志。

    2. 手写自定义 ClassLoader：重写 findClass() 从磁盘读字节并 defineClass；用两个加载器实例加载同名类，验证 c1 == c2 为 false。

    3. 编译 InvokeDemo 后用 javap -c 找出：构造器、private 方法、接口方法、lambda 分别对应哪条 invoke 指令？

    参考答案¶

    // 练习 1：常量编译期被解析，Util 不会初始化（没有 "Util 初始化" 输出）
public class ConstRef {
    static class Util {
        static final String TIP = "我是常量"; // ConstantValue，编译期解析
        static { System.out.println("Util 初始化"); }
    }
    public static void main(String[] args) {
        System.out.println(Util.TIP); // 只输出"我是常量"
    }
}

    // 练习 2：类的唯一性 = 全限定名 + 加载器。两个加载器 → 两个"不同"的类
import java.nio.file.*;

public class MyLoader extends ClassLoader {
    private final Path dir;
    public MyLoader(Path dir) { this.dir = dir; }

    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        try {
            byte[] bytes = Files.readAllBytes(dir.resolve(name + ".class"));
            return defineClass(name, bytes, 0, bytes.length); // 核心 API
        } catch (Exception e) { throw new ClassNotFoundException(name, e); }
    }

    public static void main(String[] args) throws Exception {
        Path dir = Path.of("/tmp/classes");
        Class<?> c1 = new MyLoader(dir).loadClass("Demo");
        Class<?> c2 = new MyLoader(dir).loadClass("Demo");
        System.out.println(c1 == c2); // false：加载器是类身份的一部分
    }
}

    # 练习 3：javap -c InvokeDemo（节选结论）
   invokespecial   // "<init>":()V              ← 构造器
   invokespecial   // specialM:()V              ← private 方法
   invokeinterface // Greeter.greet             ← 接口方法
   invokedynamic   // makeConcatWithConstants   ← "hi " + n（JDK 9+ 字符串拼接）
   # lambda 表达式本身的生成也是 invokedynamic（LambdaMetafactory）

    8. 本章小结¶

    主题 核心要点
    加载过程 加载→验证→准备→解析→初始化；准备赋零值，初始化执行 <clinit>
    触发时机 仅 6 种主动引用触发初始化；数组、父类字段引用、编译期常量都是被动
    双亲委派 先向上委派，防核心类被篡改；TCCL/Tomcat/OSGi 按需打破
    类文件 CAFEBABE + 常量池 + 字段表 + 方法表；major 61 = JDK 17
    调用指令 static/special 编译期定；virtual/interface 查 vtable 动态分派；invokedynamic 运行期生成
    动态代理 JDK 代理接口走反射，CGLIB 继承子类走 FastClass
