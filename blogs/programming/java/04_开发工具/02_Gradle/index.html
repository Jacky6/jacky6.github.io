    02_Gradle¶

    1. Gradle 概述¶

    知识点： - Gradle = 新一代构建工具，Groovy/Kotlin DSL 配置，Android 官方构建工具 - ⭐ 对比 Maven：增量构建更快、DSL 比 XML 灵活、依赖配置更丰富 - Spring 生态两者都常用；老项目 Maven 多，新项目 Gradle 增多

    1.1 什么是 Gradle¶

    Gradle 是一款开源的自动化构建工具，使用 Groovy 或 Kotlin DSL 编写构建脚本，兼具 Maven 的依赖管理能力和 Ant 的灵活性。它是 Android 官方构建工具，也是 Spring Boot 官方推荐的构建工具之一。

    核心功能： - ✅ 构建自动化：编译、测试、打包、发布 - ✅ 依赖管理：兼容 Maven/Ivy 仓库，支持传递依赖解析 - ✅ 增量构建：只重新执行输入发生变化的任务 - ✅ 构建缓存：跨构建复用任务结果，甚至跨机器共享 - ✅ 灵活扩展：插件机制 + 可编程脚本，几乎无所不能

    1.2 Gradle vs Maven¶

    特性 Maven Gradle
    配置语言 XML（声明式） Groovy / Kotlin DSL（可编程）
    构建性能 每次全量构建，较慢 ⭐ 增量编译 + 构建缓存，快 2~10 倍
    灵活性 固定生命周期，扩展靠插件 高，脚本即代码，可自定义任务
    依赖范围 compile/provided/runtime/test implementation/api/compileOnly/runtimeOnly 等
    Android 生态 不支持 ✅ 官方指定构建工具
    学习曲线 平缓 较陡
    适用场景 传统企业项目 新项目、Android、微服务

    💡 如何选择：维护老项目跟着团队走；新项目、Android 项目优先选 Gradle。

    2. 安装¶

    知识点： - ⭐ 推荐 SDKMAN 或 Homebrew 安装，方便多版本切换 - Gradle Wrapper（gradlew）：项目自带指定版本的 Gradle，团队环境统一

    2.1 安装方式¶

    # ✅ 方式一：SDKMAN（推荐，跨平台，便于多版本管理；先安装 SDKMAN：sdkman.io）
sdk install gradle 8.7

# ✅ 方式二：Homebrew（macOS / Linux）
brew install gradle

# ✅ 方式三：手动安装
# 下载 gradle.org/install 的 binary 压缩包，解压到 /opt/gradle，配置环境变量：
export GRADLE_HOME=/opt/gradle/gradle-8.7
export PATH=$PATH:$GRADLE_HOME/bin

# 验证安装
gradle -v

    ⚠️ 实际开发中通常不需要全局安装 Gradle，使用项目自带的 Wrapper 即可（见下文）。

    2.2 Gradle Wrapper（gradlew）¶

    每个 Gradle 项目都会自带 Wrapper 文件：根目录的 gradlew（Linux/macOS）、gradlew.bat（Windows）启动脚本，以及 gradle/wrapper/ 下的 gradle-wrapper.jar（下载器）和 gradle-wrapper.properties（指定 Gradle 版本）。

    gradlew 的作用：首次执行时自动下载 gradle-wrapper.properties 中指定的 Gradle 版本，然后用该版本执行构建。

    为什么项目要自带 Wrapper？ - ✅ 环境一致：所有开发者和 CI 使用相同 Gradle 版本，避免"我机器上能构建"的问题 - ✅ 零安装易升级：克隆即用；./gradlew wrapper --gradle-version 8.7 一条命令升级并提交到 Git

    ./gradlew build        # Linux/macOS 用 ./gradlew；Windows 用 gradlew.bat

    3. 核心概念¶

    知识点： - ⭐ 三概念：Project（项目）、Task（任务，构建的基本单元）、Plugin（插件，提供任务和约定） - 任务之间可以声明依赖关系，Gradle 构建 DAG 按序执行

    3.1 Project / Task / Plugin¶

    概念 说明 类比 Maven
    Project 一次构建的载体，对应一个 build.gradle 一个 pom.xml
    Task 构建的最小执行单元（编译、测试、打 jar…） 生命周期阶段
    Plugin 向 Project 注册一组约定任务和扩展 Maven 插件 
    ./gradlew tasks              # 查看所有任务
./gradlew build --dry-run    # 预演任务执行顺序（不真正执行）

    3.2 任务依赖图¶

    ./gradlew build 会依次触发 compileJava → classes → jar → test → build。与 Maven 固定生命周期不同，这张任务依赖图（DAG）由插件声明、可被脚本修改，这就是 Gradle 灵活的根源。

    4. Groovy DSL 配置详解¶

    知识点： - build.gradle 核心结构：plugins（插件）→ dependencies（依赖）→ 自定义任务 - ⭐ java 插件提供 compileJava/test/jar 等标准任务

    4.1 初始化项目¶

    mkdir hello-gradle && cd hello-gradle
gradle init            # 按提示选择：application → Java → Groovy DSL

    生成的项目结构与 Maven 一致（src/main/java、src/test/java），核心文件是 build.gradle：

    4.2 build.gradle 结构¶

    // 1️⃣ plugins 块：声明插件（必须在最前面）
plugins {
    id 'java'            // 编译、测试、打包
    id 'application'     // 提供 run 任务
}

// 2️⃣ 基本信息与 JDK
group = 'com.example'
version = '1.0.0'
java { toolchain { languageVersion = JavaLanguageVersion.of(17) } }

// 3️⃣ 仓库：去哪里下载依赖
repositories { mavenCentral() }

// 4️⃣ 依赖
dependencies {
    implementation 'com.google.guava:guava:33.0.0-jre'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.1'
}

// 5️⃣ 任务配置
application { mainClass = 'com.example.Main' }   // run 任务的入口类
tasks.named('test') { useJUnitPlatform() }       // 启用 JUnit 5

    4.3 常用任务命令¶

    ./gradlew build        # 编译 + 测试 + 打包（最常用）
./gradlew run          # 运行 application 插件的主类
./gradlew test         # 运行测试
./gradlew clean        # 删除 build/ 输出目录
./gradlew dependencies # 打印完整依赖树（排查冲突必备）

# 常用参数
./gradlew build -x test          # 排除测试（等价 Maven -DskipTests）
./gradlew build --scan           # 构建性能分析

    5. Kotlin DSL¶

    Gradle 官方推荐使用 Kotlin DSL（文件名 build.gradle.kts），IntelliJ IDEA 对它的自动补全和类型检查远好于 Groovy。

    5.1 语法对比¶

    // Groovy DSL（build.gradle）
plugins { id 'java' }
dependencies { implementation 'com.google.guava:guava:33.0.0-jre' }

    // Kotlin DSL（build.gradle.kts）
plugins { java }   // 内置插件可直接写名字
dependencies { implementation("com.google.guava:guava:33.0.0-jre") }

    5.2 主要差异¶

    差异点 Groovy DSL Kotlin DSL
    字符串 单引号 '...' 双引号 "..."
    方法调用 可省略括号 必须带括号
    赋值 mainClass = '...' mainClass.set(...) 或属性赋值
    IDE 支持 一般 ⭐ 编译期检查 + 完整补全

    ⚠️ 同一个项目只能二选一，不能混用。Spring Initializr 生成项目时可以选择。

    6. 依赖管理¶

    知识点： - ⭐ 依赖配置（scope）：implementation（编译私有）、api（传递给消费者）、compileOnly、runtimeOnly、testImplementation - 版本目录 libs.versions.toml：集中管理依赖版本（Gradle 7+） - 国内配置阿里云镜像加速

    6.1 依赖范围（配置）¶

    配置 编译 运行 测试 传递给使用者 说明
    implementation ✅ ✅ ✅ ❌ ⭐ 默认首选，隔离性好
    api ✅ ✅ ✅ ✅ 仅用于库模块的公开 API 依赖
    compileOnly ✅ ❌ ❌ ❌ 编译期需要、运行时容器提供（如 Lombok、servlet-api）
    runtimeOnly ❌ ✅ ✅ ✅ 运行期才需要（如 MySQL 驱动）
    testImplementation ❌ ❌ ✅ ❌ 仅测试（如 JUnit）

    💡 implementation vs api：implementation 不向下游传递，隔离性好、构建更快；api 会把依赖暴露给使用者。能用 implementation 就不要用 api。

    6.2 仓库配置与阿里云镜像¶

    repositories {
    // 国内开发强烈建议放第一位，下载速度提升 10 倍
    maven { url 'https://maven.aliyun.com/repository/public' }
    mavenCentral()
}

    💡 想让所有项目生效，可把同样的 repositories 配置写入用户级初始化脚本 ~/.gradle/init.gradle 的 allprojects 块中。

    6.3 版本目录（libs.versions.toml）¶

    多模块项目中版本号散落各处难以维护，Gradle 7+ 提供版本目录统一管理，文件位于 gradle/libs.versions.toml：

    [versions]
guava = "33.0.0-jre"
junit = "5.10.1"

[libraries]
guava = { module = "com.google.guava:guava", version.ref = "guava" }
junit-jupiter = { module = "org.junit.jupiter:junit-jupiter", version.ref = "junit" }

    在 build.gradle 中通过 libs 前缀引用：

    dependencies {
    implementation libs.guava
    testImplementation libs.junit.jupiter
}

    6.4 与 Maven 互操作¶

    • ✅ Gradle 直接使用 Maven 仓库（Maven Central、私服 Nexus/Artifactory），无需迁移制品
    • ✅ 读取依赖的 pom.xml 解析传递依赖和排除规则
    • ✅ 发布到 Maven 仓库：应用 maven-publish 插件
    • ⚠️ 老项目迁移可用 gradle init 读取 pom.xml 自动生成 build.gradle
    • ⚠️ 依赖冲突时用 exclude 排除传递依赖：
    implementation('org.springframework:spring-core:6.1.5') {
    exclude group: 'commons-logging'
}

    7. 实战：Spring Boot 项目¶

    知识点： - Spring Boot Gradle 插件提供 bootRun/bootJar 任务 - bootJar 打出可执行 fat jar，等价于 Maven 的 spring-boot:repackage

    完整的 build.gradle（Groovy DSL，Spring Boot 3.2 + Java 17）：

    plugins {
    id 'java'
    id 'org.springframework.boot' version '3.2.4'
    id 'io.spring.dependency-management' version '1.1.4'
}

group = 'com.example'
version = '1.0.0'
java { toolchain { languageVersion = JavaLanguageVersion.of(17) } }

repositories {
    maven { url 'https://maven.aliyun.com/repository/public' }
    mavenCentral()
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    runtimeOnly 'com.mysql:mysql-connector-j'   // 版本由 BOM 管理，无需写
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

    ./gradlew bootRun      # 启动 Spring Boot 应用
./gradlew build        # 打包出可执行 fat jar：build/libs/demo-1.0.0.jar

    💡 io.spring.dependency-management 插件等价于 Maven 中导入 spring-boot-dependencies BOM，所以 starter 依赖不用写版本号。

    8. 常见面试题¶

    Q1：implementation 和 api 的区别？

    api 声明的依赖会传递给依赖当前模块的项目，出现在它们的编译类路径上；implementation 的依赖仅本模块可见，不向外暴露。好处是：① 模块内部实现变更不会导致下游重新编译，构建更快；② 依赖边界清晰。结论：默认 implementation，只有写在公开 API 签名里的依赖才用 api。

    Q2：为什么项目要自带 Gradle Wrapper？

    Wrapper（gradlew）锁定了项目使用的 Gradle 版本。任何人克隆项目后无需预装 Gradle，首次运行自动下载指定版本，保证所有开发者和 CI 环境的构建行为完全一致，也便于通过一条命令统一升级版本。

    Q3：Gradle 比 Maven 快在哪？

    • 增量构建：任务声明了输入/输出，未变化的任务直接跳过（UP-TO-DATE）
    • 构建缓存：任务结果按输入哈希缓存，可跨机器从远程缓存拉取
    • 并发执行：无依赖关系的任务并行、多模块并行编译
    • 避免重复工作：Maven 每次 mvn clean install 全量重来，Gradle 只算增量

    9. 练习题¶

    练习 1：使用 Gradle 初始化一个可运行的 Java 控制台项目，执行构建并运行。

    练习 2：为项目添加 Guava 依赖，使用其 Lists.newArrayList() 创建列表并打印，验证依赖生效。

    📝 参考答案（点击展开） **练习 1**： 
    mkdir demo && cd demo
gradle init --type java-application
# 按提示选择：Groovy DSL / Java 17

./gradlew build     # 编译 + 测试 + 打包
./gradlew run       # 输出 Hello, World!
    **练习 2**：在 `build.gradle` 添加 `implementation 'com.google.guava:guava:33.0.0-jre'`，修改 `App.java`： 
    import com.google.common.collect.Lists;

public class App {
    public static void main(String[] args) {
        System.out.println(Lists.newArrayList("Java", "Gradle"));  // [Java, Gradle]
    }
}
    运行 `./gradlew run` 输出列表即成功；`./gradlew dependencies` 可查看传递依赖。

    10. 本章小结¶

    核心知识点¶

    ✅ 核心概念：Project / Task / Plugin，构建即任务依赖图
    ✅ Wrapper：gradlew 锁定版本，保证团队环境一致
    ✅ 配置文件：plugins、repositories、dependencies 三大块
    ✅ 依赖范围：implementation（默认）、api、compileOnly、runtimeOnly
    ✅ Kotlin DSL：类型安全，IDE 支持更好，官方推荐
    ✅ 版本目录：libs.versions.toml 统一管理版本
    ✅ 性能优势：增量构建 + 构建缓存 + 并行执行

    最佳实践¶

    1. ⭐ 始终使用 Wrapper，并提交到 Git
    2. 依赖默认用 implementation，最小化 api
    3. 国内开发配置阿里云镜像加速
    4. 用 ./gradlew dependencies 排查依赖冲突
    5. 大型项目开启构建缓存：org.gradle.caching=true（gradle.properties）
