    01_Maven¶

    1. Maven 概述¶

    知识点：

    • Maven = 项目构建 + 依赖管理工具（Apache 出品）
    • ⭐ 两大核心：依赖管理（中央仓库 + POM 声明）和构建生命周期（clean/compile/test/package 标准化）
    • 对比 Gradle：Maven 用 XML 配置、约定严格；Gradle 用 Groovy/Kotlin DSL、更灵活

    1.1 什么是 Maven¶

    Maven 是 Apache 开发的 Java 项目构建和管理工具。

    核心功能：

    • ✅ 项目构建：编译、测试、打包、部署
    • ✅ 依赖管理：自动下载和管理 jar 包
    • ✅ 统一结构：标准的项目目录结构
    • ✅ 插件系统：丰富的插件扩展功能

    1.2 Maven vs Gradle¶

    特性 Maven Gradle
    配置语言 XML Groovy/Kotlin
    构建速度 较慢 较快（增量构建）
    学习曲线 平缓 较陡
    灵活性 一般 高
    推荐使用 传统项目 新项目

    2. 安装和配置¶

    知识点：

    • 安装：Windows 解压并配置 MAVEN_HOME 与 Path；macOS 用 brew install maven；Linux 用包管理器，装完 mvn -version 验证
    • settings.xml（安装目录/conf/）两个关键配置：localRepository 本地仓库路径、mirrors 镜像（如阿里云）加速下载 ⭐

    2.1 安装 Maven¶

    Windows¶

    1. 下载：Maven 官网
    2. 解压到：C:\Program Files\Apache\maven
    3. 配置环境变量： 
      MAVEN_HOME = C:\Program Files\Apache\maven
Path = %MAVEN_HOME%\bin
    4. 验证： 
      mvn -version

    macOS¶

    # 使用 Homebrew
brew install maven

# 验证
mvn -version

    Linux¶

    # Ubuntu/Debian
sudo apt install maven

# 验证
mvn -version

    2.2 配置 settings.xml¶

    <!-- Maven 安装目录/conf/settings.xml -->
<settings>
    <!-- 本地仓库路径 -->
    <localRepository>D:\maven-repo</localRepository>

    <!-- 镜像配置（加速下载） -->
    <mirrors>
        <mirror>
            <id>aliyun</id>
            <name>Aliyun Maven</name>
            <url>https://maven.aliyun.com/repository/public</url>
            <mirrorOf>central</mirrorOf>
        </mirror>
    </mirrors>
</settings>

    3. 项目结构¶

    知识点：

    • 约定优于配置：src/main/java 源码、src/main/resources 资源、src/test/java 测试代码、target/ 构建输出 ⭐
    • pom.xml 是项目核心配置文件，位于项目根目录
    • 创建项目：命令行 mvn archetype:generate（指定 groupId/artifactId/原型），或 IDE 直接新建 Maven 项目

    3.1 标准目录结构¶

    my-project/
├── pom.xml              # 项目配置文件
├── src/
│   ├── main/
│   │   ├── java/        # Java 源代码
│   │   ├── resources/   # 资源文件
│   │   └── webapp/      # Web 应用（可选）
│   └── test/
│       ├── java/        # 测试代码
│       └── resources/   # 测试资源
├── target/              # 构建输出目录
└── .mvn/                # Maven 配置（可选）

    3.2 创建 Maven 项目¶

    # 命令行创建
mvn archetype:generate \
  -DgroupId=com.example \
  -DartifactId=my-project \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DinteractiveMode=false

# 或使用 IDE
# IntelliJ IDEA: File → New → Project → Maven

    4. POM 文件详解¶

    知识点：

    • pom.xml 核心组成：坐标（groupId/artifactId/version，必须）、properties（属性，如 JDK 版本与编码）、dependencies（依赖）、build/plugins（构建插件）⭐
    • ⭐ 坐标唯一定位一个构件：groupId 组织标识 + artifactId 项目名称 + version 版本号
    • packaging 打包方式：jar（默认）/ war（Web）/ pom（聚合与父工程）

    4.1 基本结构¶

    <project>
    <!-- 坐标（必须） -->
    <groupId>com.example</groupId>
    <artifactId>my-project</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <!-- 项目信息 -->
    <name>My Project</name>
    <description>项目描述</description>
    <url>https://github.com/example/my-project</url>

    <!-- 属性 -->
    <properties>
        <maven.compiler.source>11</maven.compiler.source>
        <maven.compiler.target>11</maven.compiler.target>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <!-- 依赖 -->
    <dependencies>
        <dependency>
            <groupId>org.springframework</groupId>
            <artifactId>spring-core</artifactId>
            <version>5.3.0</version>
        </dependency>
    </dependencies>

    <!-- 构建配置 -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.8.1</version>
            </plugin>
        </plugins>
    </build>
</project>

    4.2 坐标说明¶

    <groupId>com.example</groupId>    <!-- 组织/公司标识 -->
<artifactId>my-project</artifactId> <!-- 项目名称 -->
<version>1.0.0</version>          <!-- 版本号 -->
<packaging>jar</packaging>        <!-- 打包方式：jar/war/pom -->

    5. 依赖管理¶

    知识点：

    • 依赖声明四要素：groupId + artifactId + version + scope
    • ⭐ 四种作用域：compile（默认全程有效）、provided（容器提供，如 servlet-api）、runtime（运行时才需要，如 JDBC 驱动）、test（仅测试，如 JUnit）
    • 常用命令：mvn clean/compile/test/package/install，-DskipTests 跳过测试，dependency:tree 查看依赖树 ⭐

    5.1 依赖配置¶

    <dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>5.3.0</version>
    <scope>compile</scope>
</dependency>

    5.2 依赖作用域¶

    scope 编译 测试 运行 说明
    compile ✅ ✅ ✅ 默认，全程有效
    provided ✅ ✅ ❌ 容器提供（如 servlet-api）
    runtime ❌ ✅ ✅ 运行时有效（如 JDBC 驱动）
    test ❌ ✅ ❌ 仅测试有效（如 JUnit）

    5.3 常用命令¶

    # 清理
mvn clean

# 编译
mvn compile

# 测试
mvn test

# 打包
mvn package

# 安装到本地仓库
mvn install

# 跳过测试
mvn package -DskipTests

# 查看依赖树
mvn dependency:tree

    6. 常用插件¶

    知识点：

    • Maven 功能靠插件扩展：编译插件 maven-compiler-plugin 用 source/target 指定 JDK 版本 ⭐
    • 打包插件 maven-jar-plugin 可在 manifest 中指定 mainClass，使 jar 可执行

    6.1 编译插件¶

    <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.8.1</version>
    <configuration>
        <source>11</source>
        <target>11</target>
    </configuration>
</plugin>

    6.2 打包插件¶

    <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-jar-plugin</artifactId>
    <version>3.2.0</version>
    <configuration>
        <archive>
            <manifest>
                <mainClass>com.example.Main</mainClass>
            </manifest>
        </archive>
    </configuration>
</plugin>

    7. 多模块项目¶

    知识点：

    • 父 POM：packaging 为 pom，用 <modules> 声明子模块列表
    • 子模块：用 <parent> 继承父 POM 的坐标与配置，自身只需声明 artifactId ⭐

    7.1 父 POM¶

    <project>
    <groupId>com.example</groupId>
    <artifactId>parent</artifactId>
    <version>1.0.0</version>
    <packaging>pom</packaging>

    <modules>
        <module>module-a</module>
        <module>module-b</module>
    </modules>
</project>

    7.2 子模块¶

    <project>
    <parent>
        <groupId>com.example</groupId>
        <artifactId>parent</artifactId>
        <version>1.0.0</version>
    </parent>

    <artifactId>module-a</artifactId>
</project>

    8. 最佳实践¶

    知识点：

    • 版本管理：把版本号抽成 <properties> 变量（如 ${spring.version}），一处修改处处生效 ⭐
    • BOM（Bill of Materials）：在 dependencyManagement 中 import 官方 BOM（如 spring-boot-dependencies），依赖无需再写 version ⭐

    8.1 版本管理¶

    <properties>
    <spring.version>5.3.0</spring.version>
</properties>

<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>${spring.version}</version>
</dependency>

    8.2 使用 BOM¶

    <dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>2.5.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

    9. 构建生命周期 ⭐⭐¶

    知识点：

    • ⭐ 三套生命周期：clean（清理）、default（构建核心）、site（文档）
    • ⭐ default 关键阶段按序执行：validate→compile→test→package→install→deploy
    • 执行某阶段会先执行它之前的所有阶段（mvn package 会先 compile 和 test）

    9.1 生命周期是什么¶

    Maven 有三套生命周期，最常用的是 default（构建） 生命周期。执行某个阶段时，它之前的所有阶段都会依次执行。

    clean 生命周期：pre-clean → clean → post-clean

default 生命周期（核心阶段，按顺序执行）：
validate → compile → test → package → verify → install → deploy
   校验       编译     测试    打包      检查    装到本地仓库  发布到远程

site 生命周期：生成项目文档站点

    理解这一点后，很多疑惑就解开了：

    mvn install    # 会自动先执行 compile、test、package
mvn test       # 会自动先执行 compile
mvn package    # 会自动先执行 compile、test

    9.2 常用命令速查¶

    mvn clean package        # 清理 + 打包（最常用）
mvn clean install        # 打包并安装到本地仓库（多模块开发常用）
mvn clean package -DskipTests    # 跳过测试执行
mvn clean package -Dmaven.test.skip=true  # 跳过测试编译和执行
mvn dependency:tree      # 查看依赖树（排查冲突）
mvn dependency:analyze   # 分析依赖（未使用/未声明的）
mvn versions:display-dependency-updates  # 检查依赖新版本

    10. 传递依赖与冲突解决 ⭐⭐⭐¶

    知识点：

    • ⭐ 传递依赖：引入 A 会自动引入 A 依赖的 B（减少手动声明）
    • ⭐ 冲突解决两原则：最短路径优先、先声明者优先
    • 排查工具：mvn dependency:tree 看依赖树， 排除冲突依赖

    10.1 传递依赖¶

    依赖会"传染"：你依赖 A，A 依赖 B，那么 B 也会自动加入你的项目。

    你的项目
└── spring-webmvc
    ├── spring-core
    ├── spring-beans
    └── spring-context
        └── spring-aop   ← 传递进来的

    10.2 依赖冲突¶

    同一个依赖被不同路径引入不同版本时，Maven 按两条规则仲裁：

    规则 说明
    最短路径优先 路径层级浅的版本胜出
    先声明优先 路径一样长时，pom 中先声明的胜出 
    项目
├── A → C(1.0)    ← 路径长度 2，先声明 → C 用 1.0 ✅
└── B → C(2.0)

    10.3 排查与解决¶

    # 1. 找出冲突
mvn dependency:tree -Dincludes=com.example:lib-c

    <!-- 2. 用 exclusion 排除不想要的版本 -->
<dependency>
    <groupId>com.example</groupId>
    <artifactId>lib-a</artifactId>
    <version>1.0</version>
    <exclusions>
        <exclusion>
            <groupId>com.example</groupId>
            <artifactId>lib-c</artifactId>
        </exclusion>
    </exclusions>
</dependency>

<!-- 3. 或在 dependencyManagement 中统一锁定版本（推荐） -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.example</groupId>
            <artifactId>lib-c</artifactId>
            <version>2.0</version>
        </dependency>
    </dependencies>
</dependencyManagement>

    dependencyManagement 只声明版本，不引入依赖；子模块/dependencies 引用时自动采用锁定版本。这是大型项目统一依赖版本的标准做法。

    11. 练习题¶

    1. 从零创建：用 mvn archetype:generate 创建一个项目，编译打包，观察 target 目录。
    2. 依赖管理：给项目添加 JUnit 5 依赖（scope 为 test），写一个测试并用 mvn test 运行。
    3. 依赖树：对任意项目执行 mvn dependency:tree，找出一条传递依赖链并解释。

    参考答案¶

  -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false
cd demo

    <!-- 练习 2：pom.xml 添加 -->

    <groupId>org.junit.jupiter</groupId>

</dependency>

    12. 高频面试题¶

    Q1：Maven 的三大生命周期？

    ① clean：清理 target；② default：核心构建（validate → compile → test → package → verify → install → deploy）；③ site：生成项目站点。生命周期由有序的 phase 组成，执行某个 phase 会先执行它之前的所有 phase。mvn clean package = clean 生命周期 + default 到 package。

    Q2：依赖冲突怎么解决？

    调解原则：① 最短路径优先（依赖树中路径短的胜出）；② 路径相同则先声明优先。排查：mvn dependency:tree -Dincludes=冲突包 查看依赖来源；解决：<exclusions> 排除 + 在 POM 直接声明想要的版本（顶层声明路径最短必然胜出）。

    Q3：依赖 scope 有哪些？

    compile（默认：编译+测试+运行）；provided（编译测试有效，运行由容器提供，如 servlet-api、lombok）；runtime（编译不需要运行需要，如 MySQL 驱动）；test（仅测试，如 JUnit）；system（本地 jar，少用）。面试口诀：provided 容器给，runtime 编译不用。

    Q4：mvn install 和 mvn deploy 的区别？

    install：产物装进本地仓库（~/.m2），只供本机其他项目使用；deploy：上传到远程仓库（Nexus/Artifactory/GitHub Packages），供团队共享。开发中多模块联调用 install，发布给团队用 deploy。

    Q5：dependencyManagement 和 dependencies 的区别？

    dependencyManagement 只声明版本号不引入依赖（子模块引用时可省略版本，统一管控）；dependencies 真正引入。Spring Boot 的父 POM 就是靠 dependencyManagement + BOM 统一几百个依赖的版本。

    Q6：SNAPSHOT 版本和 RELEASE 版本？

    SNAPSHOT 是开发中的不稳定版本，每次构建可能变化（Maven 会检查远程更新）；RELEASE（无 -SNAPSHOT 后缀）是不可变的正式版本。生产依赖必须用 RELEASE。
