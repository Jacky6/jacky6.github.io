    03_观察者模式¶

    1. 观察者模式概述¶

    知识点：

    • 观察者模式：一对多依赖，一个对象状态变化时自动通知所有依赖者
    • 别名：发布-订阅模式；角色：被观察者（Subject）+ 观察者（Observer）
    • ⭐ 应用：事件系统、消息队列、Spring 事件、GUI 监听器

    1.1 什么是观察者模式¶

    观察者模式（Observer Pattern）定义对象间的一对多依赖关系，当一个对象状态改变时，所有依赖它的对象都收到通知并自动更新。

    别名：发布 - 订阅模式（Publish-Subscribe）

    应用场景：

    • ✅ 事件处理系统
    • ✅ 消息队列
    • ✅ MVC 架构
    • ✅ 响应式编程

    1.2 角色¶

    角色 说明
    Subject（主题） 被观察者，维护观察者列表
    Observer（观察者） 接收通知并更新
    ConcreteSubject 具体主题
    ConcreteObserver 具体观察者

    2. 实现方式¶

    知识点：

    • 自定义实现：Subject 维护观察者列表，状态变化时遍历通知
    • Java 内置 Observable/Observer 已废弃（Java 9），了解即可

    2.1 自定义实现¶

    // 观察者接口
public interface Observer {
    void update(String message);
}

// 主题接口
public interface Subject {
    void attach(Observer observer);
    void detach(Observer observer);
    void notifyObservers(String message);
}

// 具体主题
public class NewsAgency implements Subject {
    private List<Observer> observers = new ArrayList<>();

    @Override
    public void attach(Observer observer) {
        observers.add(observer);
    }

    @Override
    public void detach(Observer observer) {
        observers.remove(observer);
    }

    @Override
    public void notifyObservers(String message) {
        for (Observer observer : observers) {
            observer.update(message);
        }
    }

    public void addNews(String news) {
        System.out.println("发布新闻：" + news);
        notifyObservers(news);
    }
}

// 具体观察者
public class NewsChannel implements Observer {
    private String name;

    public NewsChannel(String name) {
        this.name = name;
    }

    @Override
    public void update(String message) {
        System.out.println(name + " 收到通知：" + message);
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        NewsAgency agency = new NewsAgency();

        NewsChannel cctv = new NewsChannel("CCTV");
        NewsChannel bbc = new NewsChannel("BBC");

        agency.attach(cctv);
        agency.attach(bbc);

        agency.addNews("Java 17 发布");
        // 输出：
        // 发布新闻：Java 17 发布
        // CCTV 收到通知：Java 17 发布
        // BBC 收到通知：Java 17 发布
    }
}

    2.2 Java 内置实现¶

    import java.util.Observable;
import java.util.Observer;

// 被观察者
public class NewsAgency extends Observable {
    public void addNews(String news) {
        setChanged();  // 标记状态改变
        notifyObservers(news);
    }
}

// 观察者
public class NewsChannel implements Observer {
    private String name;

    @Override
    public void update(Observable o, Object arg) {
        System.out.println(name + " 收到：" + arg);
    }
}

// 注意：Java 9 已废弃 Observable，推荐使用第三方库

    3. Spring 事件机制¶

    知识点：

    • ⭐ Spring 事件是观察者模式的标准落地：ApplicationEvent + @EventListener
    • 默认同步执行，加 @Async 变异步；用于业务解耦（下单后送积分）

    3.1 定义事件¶

    // 事件类
public class UserRegisteredEvent extends ApplicationEvent {
    private final User user;

    public UserRegisteredEvent(Object source, User user) {
        super(source);
        this.user = user;
    }

    public User getUser() {
        return user;
    }
}

    3.2 发布事件¶

    @Service
public class UserService {

    @Autowired
    private ApplicationEventPublisher eventPublisher;

    public void register(User user) {
        // 保存用户
        // ...

        // 发布事件
        eventPublisher.publishEvent(new UserRegisteredEvent(this, user));
    }
}

    3.3 监听事件¶

    // 方式 1：实现 ApplicationListener
@Component
public class EmailListener implements ApplicationListener<UserRegisteredEvent> {
    @Override
    public void onApplicationEvent(UserRegisteredEvent event) {
        User user = event.getUser();
        System.out.println("发送欢迎邮件给：" + user.getEmail());
    }
}

// 方式 2：@EventListener
@Component
public class SmsListener {

    @EventListener
    public void handleUserRegistered(UserRegisteredEvent event) {
        User user = event.getUser();
        System.out.println("发送短信给：" + user.getPhone());
    }

    // 异步监听
    @Async
    @EventListener
    public void handleAsync(UserRegisteredEvent event) {
        // 异步处理
    }
}

    4.1 订单状态变更¶

    // 事件
public class OrderStatusChangedEvent extends ApplicationEvent {
    private final Long orderId;
    private final OrderStatus oldStatus;
    private final OrderStatus newStatus;

    public OrderStatusChangedEvent(Object source, Long orderId, 
                                    OrderStatus oldStatus, OrderStatus newStatus) {
        super(source);
        this.orderId = orderId;
        this.oldStatus = oldStatus;
        this.newStatus = newStatus;
    }

    // getter
}

// Service 发布事件
@Service
public class OrderService {
    @Autowired
    private ApplicationEventPublisher eventPublisher;

    public void updateStatus(Long orderId, OrderStatus newStatus) {
        Order order = getOrder(orderId);
        OrderStatus oldStatus = order.getStatus();

        order.setStatus(newStatus);
        orderRepository.save(order);

        eventPublisher.publishEvent(
            new OrderStatusChangedEvent(this, orderId, oldStatus, newStatus)
        );
    }
}

// 监听器 1：发送通知
@Component
public class OrderNotificationListener {
    @EventListener
    public void onOrderStatusChanged(OrderStatusChangedEvent event) {
        if (event.getNewStatus() == OrderStatus.SHIPPED) {
            System.out.println("订单已发货，发送通知");
        }
    }
}

// 监听器 2：更新库存
@Component
public class InventoryListener {

    4.2 消息队列¶

    // 主题
public class MessageQueue implements Subject {
    private List<Observer> subscribers = new ArrayList<>();
    private Queue<String> messages = new LinkedList<>();

    @Override
    public void attach(Observer observer) {
        subscribers.add(observer);
    }

    @Override
    public void detach(Observer observer) {
        subscribers.remove(observer);
    }

    @Override
    public void notifyObservers(String message) {
        for (Observer observer : subscribers) {
            observer.update(message);
        }
    }

    public void publish(String message) {
        messages.offer(message);
        notifyObservers(message);
    }
}

// 订阅者
public class Subscriber implements Observer {
    private String name;

    public Subscriber(String name) {
        this.name = name;
    }

    @Override
    public void update(String message) {
        System.out.println(name + " 收到消息：" + message);
    }
}

    5. 优缺点¶

    知识点：

    • 优点：观察者和被观察者解耦、支持广播通信
    • 缺点：观察者多时通知开销大、可能循环依赖、异步下顺序不保证

    5.1 优点¶

    • ✅ 解耦：主题和观察者松散耦合
    • ✅ 开闭原则：新增观察者无需修改主题
    • ✅ 灵活：支持广播通知
    • ✅ 符合依赖倒置：依赖抽象而非具体

    5.2 缺点¶

    • ❌ 循环依赖：可能导致无限循环
    • ❌ 性能问题：观察者多时通知耗时
    • ❌ 变化不明：不知道具体哪个观察者响应

    6. 练习题¶

    1. 气象站监控：实现 WeatherStation（主题，维护温度/湿度）和 Observer 接口，两个观察者 CurrentConditionsDisplay（显示当前温湿度）和 StatisticsDisplay（统计历史最高/最低温度）；调用 setMeasurements() 后所有观察者自动更新。
    2. 取消订阅：支持 detach() 退订，验证退订后不再收到通知。

    参考答案¶

    import java.util.ArrayList;
import java.util.List;

// 观察者接口
public interface Observer {
    void update(double temperature, double humidity);
}

// 主题接口
public interface Subject {
    void attach(Observer observer);   // 订阅
    void detach(Observer observer);   // 取消订阅
    void notifyObservers();           // 通知所有观察者
}

// 具体主题：气象站
public class WeatherStation implements Subject {
    private final List<Observer> observers = new ArrayList<>();
    private double temperature;
    private double humidity;

    @Override
    public void attach(Observer observer) {
        observers.add(observer);
    }

    @Override
    public void detach(Observer observer) {
        observers.remove(observer);
    }

    @Override
    public void notifyObservers() {
        for (Observer observer : observers) {
            observer.update(temperature, humidity);
        }
    }

    // 气象数据更新 → 自动通知所有观察者
    public void setMeasurements(double temperature, double humidity) {
        this.temperature = temperature;
        this.humidity = humidity;
        System.out.println("\n气象站数据更新：温度 " + temperature + "℃，湿度 " + humidity + "%");
        notifyObservers();
    }
}

// 具体观察者 1：当前状况面板
public class CurrentConditionsDisplay implements Observer {
    @Override
    public void update(double temperature, double humidity) {
        System.out.println("[当前状况] 温度：" + temperature + "℃，湿度：" + humidity + "%");
    }
}

// 具体观察者 2：统计面板（记录历史最高/最低温度）
public class StatisticsDisplay implements Observer {
    private double maxTemp = Double.MIN_VALUE;
    private double minTemp = Double.MAX_VALUE;

    @Override
    public void update(double temperature, double humidity) {
        maxTemp = Math.max(maxTemp, temperature);
        minTemp = Math.min(minTemp, temperature);
        System.out.printf("[统计] 历史最高：%.1f℃，历史最低：%.1f℃%n", maxTemp, minTemp);
    }
}

// ========== 验证 ==========
public class Main {
    public static void main(String[] args) {
        WeatherStation station = new WeatherStation();

        CurrentConditionsDisplay current = new CurrentConditionsDisplay();
        StatisticsDisplay statistics = new StatisticsDisplay();

        // 练习 1：两个观察者订阅
        station.attach(current);
        station.attach(statistics);

        station.setMeasurements(25.0, 60);   // 两个面板都更新
        station.setMeasurements(30.5, 55);

        // 练习 2：取消订阅后不再收到通知
        station.detach(statistics);
        station.setMeasurements(18.0, 70);   // 只有当前状况面板更新
    }
}

    7. 高频面试题¶

    Q1：观察者模式和发布-订阅模式的区别？

    观察者：观察者直接注册到被观察者上，耦合度稍高；发布-订阅：中间多一个事件通道（Broker/EventBus），发布者不知道订阅者是谁，完全解耦。JDK 的 Observer/EventListener 是观察者，消息队列（Kafka/RocketMQ）是发布-订阅。

    Q2：Spring 事件机制是怎么实现的？

    ApplicationEventPublisher.publishEvent() 发布，@EventListener/ApplicationListener 监听，底层由 ApplicationEventMulticaster 维护"事件类型 → 监听器"的映射并逐个回调。默认同步执行（可 @Async 异步），还有 @TransactionalEventListener 支持事务提交后才触发。

    Q3：观察者模式解决什么问题？有什么典型场景？

    一个对象状态变化时，自动通知所有依赖它的对象，且无需硬编码通知逻辑——一对多的松耦合通信。典型：GUI 事件、消息推送、下单后发短信/加积分/扣库存、Spring 事件、MQ。

    Q4：观察者模式的缺点？

    ① 通知顺序不可控；② 同步通知时一个观察者卡住会拖累整条链（要异步或限超时）；③ 观察者过多时发布开销大；④ 调试困难（调用关系隐式）。

    Q5：Java 里除了 Spring，还有哪些观察者模式的例子？

    ① JDK 早期的 java.util.Observer（已废弃）；② java.beans.PropertyChangeListener（属性变更监听）；③ java.awt 的事件监听体系；④ 响应式流（Reactor/RxJava）本质也是观察者思想的延伸。

    8. 本章小结¶

    核心知识点¶

    ✅ 观察者模式结构：Subject、Observer
    ✅ 自定义实现：接口定义、通知机制
    ✅ Spring 事件：ApplicationEvent、@EventListener
    ✅ 实战应用：订单状态、消息队列

    最佳实践¶

    1. 使用 Spring 事件机制：企业级应用首选
    2. 异步处理：@Async 避免阻塞
    3. 注意循环依赖：避免观察者触发主题
    4. 合理拆分事件：不同业务用不同事件
    5. 考虑性能：观察者多时使用消息队列
