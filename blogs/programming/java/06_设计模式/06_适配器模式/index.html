    06_适配器模式¶

    1. 适配器模式概述¶

    知识点： - 适配器模式：把一个类的接口转换成客户端期望的另一个接口 - 别名：包装器；生活类比：电源转接头 - ⭐ 典型场景：接入第三方 SDK、老接口改造、统一多个相似接口

    1.1 什么是适配器模式¶

    适配器模式（Adapter Pattern）将一个类的接口转换成客户希望的另一个接口，使原本不兼容的类可以一起工作。

    别名：包装器模式（Wrapper Pattern）

    适用场景： - ✅ 使用现有类，但接口不符合需求 - ✅ 需要复用现有类 - ✅ 统一多个类的接口

    1.2 生活中的例子¶

    电源适配器：
- 220V 交流电 → 5V 直流电
- 让手机可以使用墙上的电源

USB 转接头：
- USB-A → USB-C
- 让旧设备可以使用新接口

    2. 实现方式¶

    知识点： - 类适配器：继承被适配类（Java 单继承限制少用） - ⭐ 对象适配器：组合被适配对象（推荐，更灵活）

    2.1 类适配器（继承）¶

    // 目标接口
public interface Target {
    void request();
}

// 需要适配的类
public class Adaptee {
    public void specificRequest() {
        System.out.println("特殊请求");
    }
}

// 适配器（继承）
public class Adapter extends Adaptee implements Target {
    @Override
    public void request() {
        // 调用 Adaptee 的方法
        specificRequest();
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        Target target = new Adapter();
        target.request();
    }
}

    2.2 对象适配器（组合，推荐）¶

    // 目标接口
public interface Target {
    void request();
}

// 需要适配的类
public class Adaptee {
    public void specificRequest() {
        System.out.println("特殊请求");
    }
}

// 适配器（组合）
public class Adapter implements Target {
    private Adaptee adaptee;

    public Adapter(Adaptee adaptee) {
        this.adaptee = adaptee;
    }

    @Override
    public void request() {
        adaptee.specificRequest();
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        Adaptee adaptee = new Adaptee();
        Target target = new Adapter(adaptee);
        target.request();
    }
}

    2.3 接口适配器¶

    // 接口有 4 个方法
public interface Target {
    void method1();
    void method2();
    void method3();
    void method4();
}

// 抽象适配器（提供空实现）
public abstract class AbstractAdapter implements Target {
    public void method1() {}
    public void method2() {}
    public void method3() {}
    public void method4() {}
}

// 具体适配器（只重写需要的方法）
public class ConcreteAdapter extends AbstractAdapter {
    @Override
    public void method1() {
        System.out.println("实现 method1");
    }

    @Override
    public void method2() {
        System.out.println("实现 method2");
    }
    // method3 和 method4 使用默认空实现
}

    3. 实战示例¶

    3.1 支付接口适配¶

    // 旧支付接口
public interface OldPayment {
    void payOld(double amount);
}

// 新支付接口
public interface NewPayment {
    void pay(BigDecimal amount, String currency);
}

// 旧的实现
public class AlipayOld implements OldPayment {
    @Override
    public void payOld(double amount) {
        System.out.println("支付宝支付：" + amount);
    }
}

// 适配器
public class PaymentAdapter implements NewPayment {
    private OldPayment oldPayment;

    public PaymentAdapter(OldPayment oldPayment) {
        this.oldPayment = oldPayment;
    }

    @Override
    public void pay(BigDecimal amount, String currency) {
        // 转换参数
        double amountDouble = amount.doubleValue();

        // 调用旧接口
        oldPayment.payOld(amountDouble);
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        OldPayment old = new AlipayOld();
        NewPayment adapter = new PaymentAdapter(old);

        adapter.pay(new BigDecimal("100.00"), "CNY");
    }
}

    3.2 日志系统适配¶

    // 第三方日志库
public class ThirdPartyLogger {
    public void info(String message) {
        System.out.println("[INFO] " + message);
    }

    public void error(String message) {
        System.out.println("[ERROR] " + message);
    }

    public void debug(String message) {
        System.out.println("[DEBUG] " + message);
    }
}

// 我们的日志接口
public interface Logger {
    void info(String message);
    void error(String message);
    void debug(String message);
    void warn(String message);
}

// 适配器
public class LoggerAdapter implements Logger {
    private ThirdPartyLogger thirdPartyLogger;

    public LoggerAdapter(ThirdPartyLogger logger) {
        this.thirdPartyLogger = logger;
    }

    @Override
    public void info(String message) {
        thirdPartyLogger.info(message);
    }

    @Override
    public void error(String message) {
        thirdPartyLogger.error(message);
    }

    @Override
    public void debug(String message) {
        thirdPartyLogger.debug(message);
    }

    @Override
    public void warn(String message) {
        // 第三方没有 warn，用 info 代替
        thirdPartyLogger.info("[WARN] " + message);
    }
}

    3.3 数据源适配¶

    // 旧的数据源接口
public interface OldDataSource {
    String getString(String key);
    int getInt(String key);
}

// 新的数据源接口
public interface NewDataSource {
    <T> T get(String key, Class<T> type);
    void set(String key, Object value);
}

// 旧的实现
public class PropertiesDataSource implements OldDataSource {
    private Properties props = new Properties();

    @Override
    public String getString(String key) {
        return props.getProperty(key);
    }

    @Override
    public int getInt(String key) {
        return Integer.parseInt(props.getProperty(key));
    }
}

// 适配器
public class DataSourceAdapter implements NewDataSource {
    private OldDataSource oldDataSource;

    public DataSourceAdapter(OldDataSource dataSource) {
        this.oldDataSource = dataSource;
    }

    @Override
    @SuppressWarnings("unchecked")
    public <T> T get(String key, Class<T> type) {
        if (type == String.class) {
            return (T) oldDataSource.getString(key);
        } else if (type == Integer.class) {
            return (T) Integer.valueOf(oldDataSource.getInt(key));
        }
        throw new IllegalArgumentException("Unsupported type: " + type);
    }

    @Override
    public void set(String key, Object value) {
        // 旧数据源不支持 set，抛出异常或忽略
        throw new UnsupportedOperationException("Set not supported");
    }
}

    4. 适配器 vs 代理 vs 装饰器¶

    知识点： - ⭐ 结构都是'包一层'，区别在意图：适配器改接口、代理控访问、装饰器加功能 - 适配器：接口不兼容；装饰器：接口不变增强功能；代理：接口不变控制访问

    模式 目的 实现
    适配器 接口转换 改变接口
    代理 控制访问 接口不变
    装饰器 增强功能 接口不变

    5. 优缺点¶

    知识点： - 优点：复用现有类、解耦客户端和被适配者 - 缺点：过度使用会让系统结构复杂（层层包装）

    5.1 优点¶

    • ✅ 复用现有代码：无需修改原有类
    • ✅ 解决接口不兼容：让不兼容的类一起工作
    • ✅ 提高灵活性：可以随时替换适配器
    • ✅ 符合开闭原则：新增适配器无需修改原有代码

    5.2 缺点¶

    • ❌ 增加复杂度：引入额外的类
    • ❌ 过度使用：系统设计混乱

    6. 练习题¶

    1. 对象适配器：第三方传感器 FahrenheitSensor 只提供 readFahrenheit()，而系统依赖 TemperatureSensor 接口（readCelsius()）。编写 SensorAdapter 完成转换（公式：C = (F − 32) × 5/9）。
    2. 接口适配器：MediaPlayerListener 声明 5 个事件方法（onPlay/onPause/onStop/onError/onComplete）；编写抽象类 MediaPlayerAdapter 提供空实现，SimpleListener 继承它只重写 onPlay() 和 onError()。

    参考答案¶

    // ========== 练习 1：对象适配器适配温度传感器 ==========

// 目标接口：系统要求的接口
public interface TemperatureSensor {
    double readCelsius();   // 读取摄氏温度
}

// 被适配者：第三方传感器，只提供华氏度
public class FahrenheitSensor {
    public double readFahrenheit() {
        return 77.0;  // 模拟读取：77℉
    }
}

// 对象适配器：组合被适配者 + 实现目标接口
public class SensorAdapter implements TemperatureSensor {
    private final FahrenheitSensor sensor;

    public SensorAdapter(FahrenheitSensor sensor) {
        this.sensor = sensor;
    }

    @Override
    public double readCelsius() {
        // 华氏度 → 摄氏度：C = (F - 32) × 5/9
        double f = sensor.readFahrenheit();
        return (f - 32) * 5.0 / 9.0;
    }
}

// ========== 练习 2：接口适配器 ==========

// 接口有 5 个事件方法
public interface MediaPlayerListener {
    void onPlay();
    void onPause();
    void onStop();
    void onError(String message);
    void onComplete();
}

// 抽象适配器：提供空实现
public abstract class MediaPlayerAdapter implements MediaPlayerListener {
    @Override
    public void onPlay() {}

    @Override
    public void onPause() {}

    @Override
    public void onStop() {}

    @Override
    public void onError(String message) {}

    @Override
    public void onComplete() {}
}

// 只关注 onPlay 和 onError，无需实现其他 3 个方法
public class SimpleListener extends MediaPlayerAdapter {
    @Override
    public void onPlay() {
        System.out.println("开始播放");
    }

    @Override
    public void onError(String message) {
        System.out.println("播放出错：" + message);
    }
}

// ========== 验证 ==========
public class Main {
    public static void main(String[] args) {
        // 练习 1：第三方传感器通过适配器接入系统
        TemperatureSensor sensor = new SensorAdapter(new FahrenheitSensor());
        System.out.printf("摄氏温度：%.1f℃%n", sensor.readCelsius());  // 25.0℃

        // 练习 2：接口适配器，只重写需要的方法
        MediaPlayerListener listener = new SimpleListener();
        listener.onPlay();             // 开始播放
        listener.onPause();            // 空实现，无输出
        listener.onError("文件损坏");  // 播放出错：文件损坏
    }
}

    7. 本章小结¶

    核心知识点¶

    ✅ 类适配器：继承实现
    ✅ 对象适配器：组合实现（推荐）
    ✅ 接口适配器：抽象类提供空实现
    ✅ 实战应用：支付、日志、数据源

    最佳实践¶

    1. 优先使用对象适配器：更灵活
    2. 明确适配目的：接口转换
    3. 文档化适配器：说明适配原因
    4. 避免过度使用：不要为了模式而模式
