    08_抽象类与接口¶

    本章知识点清单¶

    1. 抽象类¶

    1.1 知识点¶

    知识点 1：什么是抽象类

    抽象类（Abstract Class）是用 abstract 修饰的类。它是"不完整的类"——可能包含没有实现的方法（抽象方法），因此不能直接创建对象，只能作为父类被继承。

    设计动机：当多个类有共同的特征和行为，但某些行为"每个类做法不同"时，把共同部分抽到父类，不同的部分声明为抽象方法，交给子类实现。

    知识点 2：抽象类可以有哪些成员（全部清单）

    成员 是否允许 说明
    普通字段（实例/静态） ✅ 和普通类一样
    构造方法 ✅ 供子类 super() 调用，不是用来 new 的
    具体方法 ✅ 子类直接继承复用
    抽象方法 ✅ 子类必须实现
    静态方法 ✅ 可以通过类名调用
    final 方法 ⚠️ 语法允许，但"抽象类 + final 方法"在语义上矛盾（见易错点）

    知识点 3：抽象方法的规则 ⭐⭐⭐

    1. 用 abstract 修饰，只有声明，没有方法体（连 {} 都没有）：public abstract void speak();
    2. 子类必须重写父类的所有抽象方法，否则子类也必须声明为 abstract
    3. 抽象方法不能是 private——private 方法子类看不到，无法重写，逻辑矛盾
    4. 抽象方法不能是 static——静态方法属于类，不参与重写
    5. 抽象方法不能是 final——final 禁止重写，与"必须被重写"矛盾

    ⚠️ 易错点汇总：

    // ❌ 1. 实例化抽象类
Animal a = new Animal();  // 编译错误：Animal is abstract; cannot be instantiated

// ❌ 2. 抽象方法带方法体
public abstract void speak() {}  // 编译错误：abstract 方法不能有 body

// ❌ 3. private/final/static 抽象方法
private abstract void m1();   // 编译错误
final abstract void m2();     // 编译错误
static abstract void m3();    // 编译错误

// ❌ 4. 子类没实现全部抽象方法又不声明 abstract
class Dog extends Animal { }  // 若 Animal 有未实现的抽象方法 → 编译错误
                              // 除非：abstract class Dog extends Animal

    1.2 示例¶

    // 抽象类
public abstract class Animal {
    // 普通字段
    protected String name;

    // 构造方法（供子类 super 调用）
    public Animal(String name) {
        this.name = name;
    }

    // 抽象方法（没有方法体）：不同动物叫声不同，交给子类实现
    public abstract void speak();

    // 具体方法：所有动物睡觉方式相同，父类直接实现
    public void sleep() {
        System.out.println(name + " 在睡觉");
    }
}

// 子类实现抽象方法
public class Dog extends Animal {
    public Dog(String name) {
        super(name);  // 调用父类构造方法
    }

    @Override
    public void speak() {
        System.out.println(name + " 汪汪汪");
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        // Animal a = new Animal("动物");  // ❌ 不能实例化抽象类

        // ✅ 多态：父类引用指向子类对象
        Animal dog = new Dog("旺财");
        dog.speak();  // 旺财 汪汪汪（运行期执行子类实现）
        dog.sleep();  // 旺财 在睡觉（继承的父类方法）
    }
}

    2. 接口¶

    2.1 知识点¶

    知识点 4：什么是接口

    接口（Interface）是比抽象类更彻底的抽象——它定义一组行为规范（"能做什么"），完全不关心"谁来做、怎么做"。实现类必须提供所有方法的具体实现。

    与 C++ 对比：C++ 没有接口关键字，惯用"纯虚类"（所有方法都是纯虚函数 = 0 的抽象类）模拟接口。Java 的 interface 是语言原生支持，且天然支持多实现。

    知识点 5：接口的成员构成（按 Java 版本演进）⭐⭐⭐

    版本 允许的成员
    Java 7 及以前 常量（public static final）+ 抽象方法（public abstract）
    Java 8 ➕ 默认方法（default）+ 静态方法（static）
    Java 9 ➕ 私有方法（private）——供默认方法复用逻辑

    接口不能有的成员： - ❌ 构造方法（接口不是类，不能被实例化） - ❌ 实例字段（字段只能是常量） - ❌ 实例代码块

    知识点 6：接口的修饰规则 ⭐⭐

    1. 接口中方法默认就是 public abstract，字段默认就是 public static final——写不写都一样
    2. 实现类实现接口方法时，必须用 public（不能缩小访问权限；默认就是 public，不写就是包私有 → 编译错误）
    3. 接口可以 extends 多个接口（多继承），弥补类的单继承限制
    4. 实现类必须实现接口中所有抽象方法，否则声明为抽象类

    知识点 7：标记接口（了解）

    没有任何方法的接口叫标记接口（Marker Interface），作用只是"打标签"，让 JVM/框架识别。JDK 典型例子： - Serializable：标记"这个类可以被序列化"（见序列化章节） - Cloneable：标记"允许 clone" - RandomAccess：标记"支持快速随机访问"（ArrayList 实现，LinkedList 不实现）

    2.2 示例¶

    // 接口定义（包含 Java 7/8/9 全部成员形态）
public interface Flyable {
    // 常量（隐式 public static final）
    int MAX_HEIGHT = 1000;

    // 抽象方法（隐式 public abstract）
    void fly();

    // Java 8+ 默认方法：实现类可以直接用，也可以重写
    default void land() {
        System.out.println("降落");
    }

    // Java 8+ 静态方法：只能通过接口名调用
    static void showInfo() {
        System.out.println("这是 Flyable 接口");
    }

    // Java 9+ 私有方法：给默认方法复用的内部逻辑
    private void helper() {
        // ...
    }
}

// 实现接口
public class Bird implements Flyable {
    @Override
    public void fly() {            // ⚠️ 必须 public，写成默认权限会编译错误
        System.out.println("鸟儿飞翔");
    }

    @Override
    public void land() {           // 默认方法也可以重写
        System.out.println("鸟儿降落");
    }
}

// 使用
Bird bird = new Bird();
bird.fly();            // 鸟儿飞翔
bird.land();           // 鸟儿降落
Flyable.showInfo();    // 静态方法用接口名调用
// Flyable f = new Flyable();  // ❌ 接口不能实例化

    知识点 6 示例：多实现

    public interface Swimmable {
    void swim();
}

public interface Flyable {
    void fly();
}

// 一个类实现多个接口（Java 弥补单继承的方式）
public class Duck implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("鸭子飞翔");
    }

    @Override
    public void swim() {
        System.out.println("鸭子游泳");
    }
}

    ⭐ 为什么 Java 类只能单继承、接口可以多实现？ 类继承会带来字段和具体实现，多继承时两个父类有同名成员就冲突（"菱形继承"问题，C++ 至今要用虚继承解决）。接口在 Java 7 时代只有方法签名没有实现，多实现只是"承诺多个契约"，不会有实现冲突——所以安全。Java 8 的默认方法引入了实现，因此才有冲突解决规则（见第 5 节）。

    3. 抽象类 vs 接口 ⭐⭐⭐⭐¶

    3.1 知识点：语法层面差异¶

    特性 抽象类 接口
    关键字 abstract class interface
    实例化 ❌ 不能 ❌ 不能
    继承/实现 单继承（extends 一个） 多实现（implements 多个）
    构造方法 ✅ 可以有 ❌ 不能有
    字段 任意（实例/静态、任意修饰符） 只能是 public static final 常量
    方法 任意（抽象 + 具体 + 静态 + final） 抽象 + 默认 + 静态 + 私有（Java 9+）
    访问修饰符 任意 方法隐式 public

    3.2 知识点：设计层面差异（面试核心）⭐⭐⭐⭐¶

    is-a vs can-do（是什么 vs 能做什么）：

    • 抽象类表达 is-a（"是一种"）：Dog 是一种 Animal。抽象类是对事物本质的抽象，子类与父类是同类事物，共享状态和实现
    • 接口表达 can-do（"能做什么"）：Dog 能 Flyable？不，Bird 能 Flyable。接口是对行为能力的抽象，不相关的类也可以实现同一接口（Bird 和 Airplane 都能飞，但本质完全不同）

    选择指南：

    何时使用抽象类：
- 多个类有共同的【状态和行为实现】需要复用（代码复用）
- 类之间有明确的 is-a 层次关系
- 需要非 public 成员、需要实例字段

何时使用接口：
- 定义【行为规范】，不关心实现者是谁
- 不相关的类需要相同的能力（如 Bird 和 Airplane 都 Flyable）
- 需要多实现（一个类同时具备多种能力）
- 对外 API 设计（接口稳定，实现可替换）

    实践口诀：用接口定义类型（面向接口编程），用抽象类复用代码。Java 集合框架是典范：List 是接口（定义规范），AbstractList 是抽象类（复用公共实现），ArrayList/LinkedList 是具体类。

    3.3 示例：接口 + 抽象类组合¶

    // 接口定义行为
public interface Payment {
    void pay(BigDecimal amount);
}

// 抽象类提供通用实现（模板方法模式）
public abstract class AbstractPayment implements Payment {
    protected String merchantId;

    public AbstractPayment(String merchantId) {
        this.merchantId = merchantId;
    }

    // 模板方法：定义支付的固定流程，final 防止子类破坏流程
    @Override
    public final void pay(BigDecimal amount) {
        validate(amount);
        doPay(amount);
        log(amount);
    }

    // 抽象方法：具体支付方式由子类实现
    protected abstract void doPay(BigDecimal amount);

    protected void validate(BigDecimal amount) {
        if (amount.compareTo(BigDecimal.ZERO) <= 0) {
            throw new IllegalArgumentException("金额必须大于 0");
        }
    }

    protected void log(BigDecimal amount) {
        System.out.println("支付记录：" + amount);
    }
}

// 具体实现：只关心"怎么付"
public class Alipay extends AbstractPayment {
    public Alipay(String merchantId) {
        super(merchantId);
    }

    @Override
    protected void doPay(BigDecimal amount) {
        System.out.println("支付宝支付：" + amount);
    }
}

    4. 函数式接口 ⭐⭐⭐¶

    4.1 知识点¶

    1. 定义：只有一个抽象方法的接口（默认方法、静态方法、私有方法不计入）
    2. 用途：可以用 Lambda 表达式直接赋值实现（详见 Lambda 表达式）
    3. @FunctionalInterface 注解：让编译器检查"是否真的只有一个抽象方法"，加错会编译报错（只是检查，不加注解只要是单抽象方法也是函数式接口）

    4.2 示例：内置四大函数式接口¶

    接口 抽象方法 语义 记忆
    Consumer<T> void accept(T t) 有参无返回（消费） 吃进去
    Supplier<T> T get() 无参有返回（供给） 吐出来
    Function<T,R> R apply(T t) 有参有返回（转换） 加工
    Predicate<T> boolean test(T t) 有参返回 boolean（判断） 判断 
    import java.util.function.*;

// Consumer - 消费型
Consumer<String> printer = s -> System.out.println(s);
printer.accept("Hello");

// Supplier - 供给型
Supplier<Double> random = () -> Math.random();
Double num = random.get();

// Function - 函数型（String → Integer）
Function<String, Integer> parser = Integer::parseInt;
Integer result = parser.apply("123");

// Predicate - 断言型
Predicate<String> isEmpty = String::isEmpty;
boolean blank = isEmpty.test("");

// 派生：UnaryOperator<T>（Function 的特例，入参出参同类型）
UnaryOperator<Integer> square = x -> x * x;
// BinaryOperator<T>（两个同类型入参）
BinaryOperator<Integer> add = (a, b) -> a + b;

    4.3 示例：自定义函数式接口¶

    @FunctionalInterface  // 编译器检查：必须只有一个抽象方法
public interface Converter<T, R> {
    R convert(T source);
}

// Lambda 实现
Converter<String, Integer> converter = Integer::parseInt;
Integer result = converter.convert("123");

    5. 接口继承与默认方法冲突 ⭐⭐⭐¶

    5.1 知识点¶

    1. 接口可以多继承接口：interface C extends A, B（类只能单继承类）
    2. 默认方法冲突解决三规则（按优先级）：
    3. 规则 1 类优先（Class wins）：父类的具体方法 > 任何接口的默认方法
    4. 规则 2 子接口优先：有继承关系的接口，子接口的默认方法覆盖父接口的
    5. 规则 3 无关接口必须重写：两个无关接口有同名默认方法，实现类必须重写，可用 接口名.super.方法() 指定调用哪个
    6. 为什么引入默认方法：Java 8 给 Collection 加 stream()/forEach()，若定义为抽象方法，所有已有实现类全部编译失败。默认方法让接口能演进而不破坏旧代码

    5.2 示例¶

    // 接口多继承
public interface A { void methodA(); }
public interface B { void methodB(); }
public interface C extends A, B {   // ✅ 接口可以多继承
    void methodC();
}
// 实现类需要实现 A、B、C 的全部抽象方法

// ── 冲突规则 3：无关接口同名默认方法 ──
public interface X {
    default void show() { System.out.println("X"); }
}
public interface Y {
    default void show() { System.out.println("Y"); }
}
public class Z implements X, Y {
    @Override
    public void show() {   // ❗ 必须重写，否则编译错误
        X.super.show();    // 可以显式指定调用 X 的版本
        // 或自己实现
    }
}

// ── 冲突规则 1：类优先 ──
public class Parent {
    public void show() { System.out.println("父类"); }
}
public interface M {
    default void show() { System.out.println("接口M"); }
}
public class Child extends Parent implements M {
    // 不用重写！父类具体方法优先于接口默认方法
}
new Child().show();  // 输出：父类

    6. 面向接口编程 ⭐⭐⭐⭐¶

    6.1 知识点¶

    面向接口编程：编写代码时依赖接口类型，而不是具体实现类。这是 Java 最重要的设计原则之一，也是 Spring 依赖注入（DI）的思想根基。

    三个好处： 1. 解耦：调用方只认识接口，换实现不用改调用代码 2. 可替换：同一个接口可以有多个实现（ArrayList/LinkedList 都是 List） 3. 可测试：测试时传入 mock 实现，不依赖真实数据库/网络

    // ❌ 面向实现：写死了 ArrayList，想换 LinkedList 要改代码
ArrayList<String> list = new ArrayList<>();

// ✅ 面向接口：声明类型用接口，实现可以随时换
List<String> list = new ArrayList<>();   // 想换就改右边：new LinkedList<>()

// Spring 里的真实场景：
// UserService 依赖 UserDao 接口，Spring 注入具体实现（或 Mock）
// public class UserService {
//     @Autowired
//     private UserDao userDao;  // 面向接口，不关心是 MySQL 实现还是 Mock
// }

    详细应用见 Spring 基础 的 IOC 章节。

    7. 实战示例¶

    7.1 模板方法模式（抽象类应用）¶

    // 抽象类定义模板
public abstract class DataProcessor {

    // 模板方法（final 防止重写）：固定流程
    public final void process(String file) {
        loadData(file);
        validate();
        transform();
        save();
    }

    // 抽象方法：每个步骤由子类实现
    protected abstract void loadData(String file);
    protected abstract void validate();
    protected abstract void transform();
    protected abstract void save();
}

// CSV 处理器
public class CsvProcessor extends DataProcessor {
    @Override
    protected void loadData(String file) {
        System.out.println("加载 CSV：" + file);
    }

    @Override
    protected void validate() {
        System.out.println("验证 CSV 格式");
    }

    @Override
    protected void transform() {
        System.out.println("转换 CSV 数据");
    }

    @Override
    protected void save() {
        System.out.println("保存到数据库");
    }
}
// JsonProcessor 同理——流程相同，各步骤实现不同

    7.2 策略模式（接口应用）¶

    // 策略接口
public interface SortStrategy {
    <T extends Comparable<T>> void sort(List<T> list);
}

// 具体策略
public class QuickSortStrategy implements SortStrategy {
    @Override
    public <T extends Comparable<T>> void sort(List<T> list) {
        System.out.println("快速排序");
        // 实现...
    }
}

public class MergeSortStrategy implements SortStrategy {
    @Override
    public <T extends Comparable<T>> void sort(List<T> list) {
        System.out.println("归并排序");
        // 实现...
    }
}

// 上下文：面向接口编程，策略可运行时切换
public class Sorter {
    private SortStrategy strategy;

    public void setStrategy(SortStrategy strategy) {
        this.strategy = strategy;
    }

    public <T extends Comparable<T>> void sort(List<T> list) {
        strategy.sort(list);
    }
}

    8. 常见面试题¶

    Q1：抽象类和接口的区别？ 语法层面：抽象类可以有构造方法、实例字段、各种方法，类只能单继承；接口只能有常量和抽象方法（Java 8+ 加默认/静态方法），可以多实现。设计层面：抽象类是 is-a（代码复用），接口是 can-do（行为规范）。

    Q2：抽象类能有构造方法吗？有什么用？ 能。虽然抽象类不能 new，但构造方法供子类的 super() 调用，用于初始化继承自父类的字段。

    Q3：接口为什么不能有构造方法？ 接口不是类，不能被实例化，构造方法没有意义。接口的初始化逻辑在 Java 8 后通过静态方法或默认方法表达。

    Q4：一个类能实现多个接口，为什么不能继承多个类？ 多类继承会有菱形继承问题（两个父类同名成员冲突、构造顺序混乱）。接口（Java 7 前）只有方法签名没有实现，多实现只是承诺契约，没有冲突；Java 8 默认方法引入实现后，用"类优先、子接口优先、必须重写"三规则解决冲突。

    Q5：什么是函数式接口？ 只有一个抽象方法的接口，可以用 Lambda 表达式实现。JDK 内置四大：Consumer、Supplier、Function、Predicate。

    Q6：默认方法是为了解决什么问题？ 接口演进问题。Java 8 给 Collection 加 stream()/forEach() 时，默认方法让旧实现类不用修改代码就能获得新方法。

    // 练习 1
public abstract class Shape {
    // 抽象方法：子类必须实现
    public abstract double area();

    // 普通方法：子类直接继承复用
    public void describe() {
        System.out.println("面积 = " + area());
    }
}

public class Circle extends Shape {
    private double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;  // 圆面积公式
    }
}

public class Rectangle extends Shape {
    private double width, height;

    public Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public double area() {
        return width * height;  // 矩形面积公式
    }
}

// 使用（多态）：
// Shape s = new Circle(2);
// s.describe();  // 面积 = 12.566...（运行期调用子类的 area()）

// 练习 2
public interface Swimmable {
    void swim();
}

public interface Flyable {
    void fly();

    default void land() {  // Java 8+ 默认方法，实现类可以不重写
        System.out.println("降落");
    }
}

public class Duck implements Swimmable, Flyable {  // 多实现
    @Override
    public void swim() {
        System.out.println("鸭子游泳");
    }

    @Override
    public void fly() {
        System.out.println("鸭子飞");
    }
}

    10. 本章小结¶

    核心知识点¶

    ✅ 抽象类：abstract 修饰，不能实例化，可以有构造方法/字段/具体方法，单继承
    ✅ 抽象方法：无方法体、子类必须实现，不能 private/static/final
    ✅ 接口：行为规范，常量+抽象方法（Java 8+ 默认/静态方法，Java 9+ 私有方法），多实现
    ✅ 抽象类 vs 接口：is-a 用抽象类，can-do 用接口；接口定类型，抽象类复用代码
    ✅ 函数式接口：单抽象方法，Lambda 的基础，四大内置接口
    ✅ 默认方法冲突：类优先、子接口优先、无关接口必须重写
    ✅ 面向接口编程：依赖接口不依赖实现，Spring DI 的根基

    最佳实践¶

    1. 优先使用接口：定义行为规范，面向接口编程
    2. 抽象类用于复用：有共同状态和实现时提取到抽象类
    3. 组合优于继承：接口 + 抽象类组合（如 AbstractList 模式）
    4. 函数式接口用 Lambda：代码更简洁
