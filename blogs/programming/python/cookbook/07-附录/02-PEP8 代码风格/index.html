    1. 简介¶

    本文档给出了 Python 标准库的代码规范。风格指南会随时间演进——当语言本身发生变化时，旧的规范会被淘汰。

    许多项目有自己的编码风格指南。如果与本文档冲突，项目特定指南优先。

    2. 核心原则¶

    知识点： - 代码被阅读的次数远多于被编写的次数——可读性是最高目标 - 一致性层级：模块/函数内 > 项目内 > 与 PEP 8 一致；项目特定指南优先 - ⚠️ 绝不要为了遵守 PEP 8 而破坏向后兼容

    "A Foolish Consistency is the Hobgoblin of Little Minds" —— 愚蠢的一致性是渺小灵魂的魔鬼

    • 代码被阅读的次数远多于被编写的次数
    • 风格指南的核心目标是可读性和一致性
    • 一致性层级：模块/函数内 > 项目内 > 与 PEP 8 一致
    • 知道何时该打破规则：
    • 遵循规范反而降低可读性时
    • 与周围代码保持一致（历史原因）时
    • 需要兼容旧版 Python 时
    • 绝不要为了遵守 PEP 8 而破坏向后兼容！

    3. 代码布局¶

    3.1 缩进¶

    • 每级缩进使用 4 个空格
    • 续行使用垂直对齐或悬挂缩进

    知识点： - 每级缩进 4 空格；续行用垂直对齐或悬挂缩进；禁止混合 Tab 和空格 - 行长与空行：代码 79 字符、注释 72 字符；顶层定义间 2 空行、类内方法间 1 空行；优先括号隐式续行 - 导入每行一个，顺序标准库→第三方→本地，组间空行；避免通配符导入 - ⭐ 面试重点：二元操作符换行推荐放在操作符之前（Knuth 风格）

    # ✅ 垂直对齐
foo = long_function_name(var_one, var_two,
                         var_three, var_four)

# ✅ 悬挂缩进（首行无参数）
foo = long_function_name(
    var_one, var_two,
    var_three, var_four
)

# ✅ 额外 4 空格区分参数与函数体
def long_function_name(
        var_one, var_two, var_three,
        var_four):
    print(var_one)

# ❌ 首行有参数且未垂直对齐
foo = long_function_name(var_one, var_two,
    var_three, var_four)

    多行条件语句的缩进处理：

    # 方案一：不额外缩进
if (this_is_one_thing and
    that_is_another_thing):
    do_something()

# 方案二：加注释区分（支持语法高亮的编辑器）
if (this_is_one_thing and
    that_is_another_thing):
    # Both conditions true → frobnicate
    do_something()

# 方案三：操作符前置 + 额外缩进
if (this_is_one_thing
        and that_is_another_thing):
    do_something()

    多行结构的闭合括号可对齐全行最后一个非空字符，或对齐到起始字符：

    # 对齐到最后一个元素
my_list = [
    1, 2, 3,
    4, 5, 6,
]

# 对齐到起始符
my_list = [
    1, 2, 3,
    4, 5, 6,
]

    3.2 Tab 还是空格？¶

    • 空格是首选缩进方式
    • Tab 仅用于与已有 Tab 缩进的代码保持一致
    • Python 禁止混合使用 Tab 和空格

    3.3 最大行长度¶

    内容 限制
    代码行 79 字符
    注释 / 文档字符串 72 字符
    团队一致同意时（代码） 可放宽至 99 字符
    • 优先使用括号隐式续行，而非反斜杠 \
    • 标准库保守采用 79 字符限制
    # ✅ 推荐：括号续行
result = (
    long_expression_1
    + long_expression_2
    - long_expression_3
)

# ✅ 反斜杠仅在不适用括号时使用
with open('/path/to/file') as f1, \
     open('/path/to/output', 'w') as f2:
    f2.write(f1.read())

    3.4 二元操作符换行位置¶

    新代码推荐：换行在操作符之前（Knuth 风格，数学排版惯例）

    # ✅ 推荐：操作符在前，易于匹配操作数
income = (gross_wages
          + taxable_interest
          + (dividends - qualified_dividends)
          - ira_deduction
          - student_loan_interest)

# ❌ 旧风格：操作符在后，容易分散
income = (gross_wages +
          taxable_interest +
          (dividends - qualified_dividends) -
          ira_deduction -
          student_loan_interest)

    两种风格都允许，局部保持一致即可。

    3.5 空行¶

    场景 空行数
    顶层函数/类定义之间 2 行
    类内方法定义之间 1 行
    函数内逻辑分段 酌情使用（少量）
    一组单行函数之间 可省略

    3.6 源文件编码¶

    • 核心 Python 发行版始终使用 UTF-8，不需编码声明
    • 标准库标识符必须使用 ASCII
    • 非 ASCII 字符尽量少用，仅用于人名、地名

    3.7 导入语句¶

    # ✅ 每个导入一行
import os
import sys

# ✅ 同一模块可导入多个名称
from subprocess import Popen, PIPE

# ❌ 一行导入多个模块
import sys, os

    导入顺序（各组之间空一行）：

    1. 标准库
    2. 第三方库
    3. 本地应用/库
    import os
import sys

import requests
import numpy as np

from mypackage import my_module
    • 推荐绝对导入，复杂包布局时可用显式相对导入
    • 避免通配符导入 (from module import *)
    # ✅ 绝对导入（推荐）
import mypkg.sibling
from mypkg import sibling

# ✅ 显式相对导入（复杂布局时可接受）
from . import sibling
from .sibling import example

    3.8 模块级双下划线名称¶

    __all__, __author__, __version__ 等应放在模块文档字符串之后、导入语句之前（__future__ 导入除外）：

    """This is the example module."""

from __future__ import barry_as_FLUFL

__all__ = ['a', 'b', 'c']
__version__ = '0.1'
__author__ = 'Cardinal Biggles'

import os
import sys

    4. 字符串引号¶

    • 单引号和双引号等价，选一种保持一致
    • 字符串内含引号时，用另一种引号避免转义
    • 三引号始终使用双引号（与 PEP 257 文档字符串规范一致）

    知识点： - 单引号与双引号等价，项目内选一种保持一致 - 内含引号时用另一种引号避免转义；三引号始终用双引号

    # 单/双引号等价——保持一致即可
name = 'Alice'
greeting = "Hello"

# 内含引号时用另一种
text = "It's a beautiful day"
quote = 'He said "Hello"'

# 三引号始终用双引号
def func():
    """This is a docstring."""
    pass

    5. 表达式与语句中的空格¶

    5.1 避免多余空格¶

    知识点： - 括号/方括号/花括号内侧不加空格；逗号后加 1 空格；避免行尾空格 - 二元操作符两侧各 1 空格；函数调用与索引括号前不加空格 - ⚠️ 默认值 imag=0.0 的 = 两侧不加空格，带注解时 sep: AnyStr = None 要加 - 切片冒号两侧空格相等；不推荐多条语句同行

    # ✅ 括号内侧不加空格
spam(ham[1], {eggs: 2})
# ❌
spam( ham[ 1 ], { eggs: 2 } )

# ✅ 尾逗号后紧跟闭括号
foo = (0,)
# ❌
foo = (0, )

# ✅ 逗号/分号/冒号前不加空格
if x == 4: print(x, y); x, y = y, x
# ❌
if x == 4 : print(x , y) ; x , y = y , x

# ✅ 切片中的冒号两侧空格相等
ham[1:9], ham[1:9:3], ham[:9:3], ham[1::3]
ham[lower + offset : upper + offset]

# ✅ 函数调用括号前不加空格
spam(1)
# ❌
spam (1)

# ✅ 索引括号前不加空格
dct['key'] = lst[index]
# ❌
dct ['key'] = lst [index]

# ✅ 赋值对齐不加多余空格
x = 1
y = 2
long_variable = 3
# ❌
x             = 1
y             = 2
long_variable = 3

    5.2 其他建议¶

    • 避免行尾空格（不可见、易混淆）
    • 二元操作符两侧各一个空格：=, +=, ==, <, >, !=, <=, >=, in, not in, is, is not, and, or, not
    • 不同优先级操作符混用时，可在低优先级操作符周围加空格（自行判断，但每侧不超过一个空格）
    # ✅
i = i + 1
submitted += 1
x = x*2 - 1
hypot2 = x*x + y*y
c = (a+b) * (a-b)

# ❌
i=i+1
submitted +=1
x = x * 2 - 1

    5.3 函数注解¶

    # ✅ 冒号后加空格，箭头两侧加空格
def munge(input: AnyStr): ...
def munge() -> PosInt: ...

# ❌
def munge(input:AnyStr): ...
def munge()->PosInt: ...

    5.4 关键字参数与默认值¶

    # ✅ 无注解默认值：= 两侧不加空格
def complex(real, imag=0.0):
    return magic(r=real, i=imag)

# ✅ 带注解默认值：= 两侧加空格
def munge(sep: AnyStr = None): ...
def munge(input: AnyStr, sep: AnyStr = None, limit=1000): ...

# ❌
def complex(real, imag = 0.0):
    return magic(r = real, i = imag)

# ❌
def munge(input: AnyStr=None): ...

    5.5 复合语句¶

    • 一般不推荐将多条语句写在同一行
    # ✅
if foo == 'blah':
    do_blah_thing()
do_one()
do_two()
do_three()

# ❌
if foo == 'blah': do_blah_thing()
do_one(); do_two(); do_three()

    6. 尾随逗号¶

    • 单元素元组必须加尾随逗号，建议加括号

    知识点： - 单元素元组必须加尾随逗号：('setup.cfg',)，建议加括号 - 多行列表加尾随逗号有利于版本控制 diff，闭合符另起一行

    # ✅
FILES = ('setup.cfg',)

# ❌
FILES = 'setup.cfg',
    • 多行列表中，尾随逗号有助于版本控制的 diff
    # ✅ 每项一行，尾随逗号，闭合符另起一行
FILES = [
    'setup.cfg',
    'tox.ini',
]

# ❌ 尾随逗号与闭合符同行
FILES = ['setup.cfg', 'tox.ini',]

    7. 命名约定¶

    知识点： - 函数/变量小写下划线、类 CapWords、常量全大写下划线、异常 CapWords + Error 后缀 - ⭐ 面试重点：_前缀内部使用、双前缀触发名称修饰、__both 魔术方法勿自创 - 避免 l/O/I 单字符变量名；实例方法首参 self，类方法首参 cls - Python 没有真正的私有属性，不加下划线即表示公共

    7.1 常见命名风格一览¶

    风格 示例
    小写单字母 b
    大写单字母 B
    全小写 lowercase
    小写下划线 lower_case_with_underscores
    全大写 UPPERCASE
    大写下划线 UPPER_CASE_WITH_UNDERSCORES
    大驼峰 (CapWords) CapitalizedWords, HTTPServerError
    小驼峰 (mixedCase) mixedCase

    缩写词在大驼峰中全部大写：HTTPServerError > HttpServerError

    7.2 下划线特殊含义¶

    形式 含义
    _single_leading 弱"内部使用"标记，from M import * 不导入
    single_trailing_ 避免与关键字冲突（如 class_）
    __double_leading 类属性名称修饰（name mangling）
    __double_both__ "魔术"对象，如 __init__，不要自创

    7.3 避免的名称¶

    • 不用 l（小写 L）、O（大写 O）、I（大写 I）作为单字符变量名
    • tempted 用 l 时改用 L

    7.4 各类名称约定¶

    类型 约定 示例
    包/模块 全小写，简短，下划线不推荐（包） mypackage, my_module
    类 CapWords MyClass, HTTPClient
    类型变量 CapWords，简短 T, AnyStr, VT_co
    异常 CapWords + Error 后缀 ValueError, ConnectionError
    函数/变量 小写 + 下划线 my_function, user_name
    方法/实例变量 同函数 get_value, _internal_state
    常量 全大写 + 下划线 MAX_OVERFLOW, PI
    C 扩展的 Python 封装模块 前导下划线 _socket

    7.5 函数与方法参数¶

    • 实例方法第一个参数：self
    • 类方法第一个参数：cls
    • 参数名与关键字冲突时，加尾部下划线：class_ 优于 clss

    7.6 继承设计¶

    可见性 命名 说明
    公共 无前导下划线 外部客户端可使用
    非公共 _single_leading 不保证兼容性
    子类不应使用 __double_leading 触发名称修饰，避免冲突

    Python 中没有真正的"私有"属性。不加下划线即表示公共。

    8. 公共与内部接口¶

    • 只有公共接口保证向后兼容
    • 使用 __all__ 明确声明公共 API
    • 内部接口用单下划线前缀
    • 导入的名称始终视为实现细节，其他模块不应依赖

    知识点： - 只有公共接口保证向后兼容，用 all 明确声明公共 API - 内部接口用单下划线前缀；导入的名称视为实现细节

    __all__ = ['PublicClass', 'public_function']

class PublicClass:
    pass

class _InternalHelper:
    """内部辅助类"""
    pass

    9. 编程建议¶

    9.1 跨实现兼容¶

    • 不依赖 CPython 的特定优化（如 a += b 字符串拼接）
    • 性能敏感处使用 ''.join() 进行字符串拼接

    9.2 单例比较¶

    • 与 None 比较始终用 is / is not

    知识点： - 与 None 比较始终用 is / is not；性能敏感处用 ''.join() 拼接字符串 - 用 def 定义函数，不把 lambda 赋值给变量；富比较可用 functools.total_ordering() - 异常从 Exception 派生而非 BaseException，用 raise X from Y 保留 traceback - 资源用 with 管理；return 保持一致，不返回值处显式 return None

    # ✅
if foo is not None:

# ❌
if not foo is None:

    9.3 富比较操作¶

    实现排序时应实现全部 6 个操作，或使用 functools.total_ordering()：

    from functools import total_ordering

@total_ordering
class MyClass:
    def __eq__(self, other): ...
    def __lt__(self, other): ...
    # 其他由装饰器自动生成

    9.4 lambda 绑定¶

    • 始终用 def 而非赋值 lambda
    # ✅
def f(x):
    return 2 * x

# ❌
f = lambda x: 2 * x

    9.5 异常¶

    • 从 Exception 派生，而非 BaseException
    • 使用 raise X from Y 保留原始 traceback
    • 捕获异常时指定具体类型，避免裸 except:
    # ✅
try:
    value = collection[key]
except KeyError:
    return key_not_found(key)
else:
    return handle_value(value)

# ❌ try 块过大，掩盖了 handle_value 中的 KeyError
try:
    return handle_value(collection[key])
except KeyError:
    return key_not_found(key)

    9.6 资源管理¶

    • 使用 with 语句确保资源清理
    • Context manager 应通过单独方法调用，使其意图明确
    # ✅
with conn.begin_transaction():
    do_stuff_in_transaction(conn)

# ❌ 意图不明确
with conn:
    do_stuff_in_transaction(conn)

    9.7 return 一致性¶

    • 同一函数中，要么所有 return 都返回表达式，要么都不返回
    • 不返回值的地方显式写 return None
    # ✅
def foo(x):
    if x >= 0:
        return math.sqrt(x)
    else:
        return None

    10. 类型注解¶

    10.1 函数注解¶

    • 遵循 PEP 484 语法
    • 标准库保守使用，新项目/大规模重构时鼓励使用

    10.2 变量注解 (PEP 526)¶

    知识点： - 函数注解遵循 PEP 484，变量注解遵循 PEP 526 - ⚠️ 变量注解：冒号后 1 空格（code: int），带默认值时 = 两侧各 1 空格（label: str = ''）

    # ✅ 冒号后一个空格，等号两侧各一个空格
code: int

class Point:
    coords: Tuple[int, int]
    label: str = ''

# ❌
code:int          # 冒号后无空格
code : int        # 冒号前有空格
result: int=0     # 等号周围无空格

    11. 速查表¶

    命名速查¶

    知识点： - 命名速查：模块/包小写、类 CapWords、异常加 Error、常量全大写 - 空格速查：二元操作符两侧 1 空格、关键字参数 = 不加空格、箭头 -> 两侧加空格 - ⭐ 面试前过一遍速查表，覆盖最高频的风格考点

    模块/包     → lowercase / lower_case
类          → CapWords
异常        → CapWords + Error
函数/变量    → lowercase_with_underscores
常量        → UPPERCASE_WITH_UNDERSCORES
方法/属性   → lowercase_with_underscores
非公共       → _leading_underscore
子类禁用     → __double_leading
关键字冲突   → trailing_underscore_

    空格速查（附示例）¶

    二元操作符          → 两侧各 1 空格    # x = a + b
赋值(关键字参数)      → = 两侧不加空格   # func(x=1)
赋值(带注解默认值)    → = 两侧加空格     # func(x: int = 1)
冒号(注解)           → 后加 1 空格      # x: int
箭头(→)             → 两侧各 1 空格    # -> str
函数调用括号前        → 不加空格         # func(1)
索引括号前           → 不加空格         # lst[0]
切片冒号             → 两侧相等空格     # ham[lower : upper]

    # 1. 二元操作符两侧各 1 空格 ✅
result = a + b
count += 1
if x == 10:
    pass

# 2. 关键字参数默认值：= 两侧不加空格 ✅
def connect(host, port=8080, timeout=30):
    pass
connect('localhost', port=9000)
# ❌ connect('localhost', port = 9000)

# 3. 带注解的默认值：= 两侧加空格 ✅
def greet(name: str = 'World') -> str:
    pass
# ❌ def greet(name: str=None): ...

# 4. 变量注解冒号后加 1 空格 ✅
count: int
message: str = 'hello'
# ❌ code:int  /  code : int

# 5. 函数箭头两侧各 1 空格 ✅
def parse(data: bytes) -> dict:
    pass
# ❌ def parse(data) ->dict:

# 6. 函数调用括号前不加空格 ✅
calculate(10, 20)
# ❌ calculate (10, 20)

# 7. 索引/字典括号前不加空格 ✅
elements[0]
config['key']
# ❌ elements [0]  /  config ['key']

# 8. 切片冒号两侧相等空格 ✅
items[1:4]                       # 简单切片：紧凑写法
data[offset : offset + length]   # 含运算时：两侧加空格提高可读性
text[start : end]                # 变量切片：两侧空格可选，保持一致即可
text[start + 1 : end - 1]

    # ===== 额外常见场景 =====

# 括号/方括号/花括号内侧不加空格
dct = {'key': 1}
lst = [1, 2, 3]
# ❌ dct = { 'key': 1 }  /  lst = [ 1, 2, 3 ]

# 逗号后加 1 空格
tup = (1, 2, 3)
# ❌ tup = (1,2,3)

# 尾逗号后紧跟闭括号，不加空格
tup = (0,)
# ❌ tup = (0, )

# = 用于赋值时两侧加空格，对齐时不补多余空格
count = 1
name = 'Alice'
long_value = 42
# ❌ count      = 1  （用空格对齐 = 号不推荐）

    核心知识点¶

    ✅ 核心原则：可读性优先，项目特定指南优先于 PEP 8 ✅ 代码布局：4 空格缩进、79 字符行宽、顶层定义间 2 空行、导入分三组 ✅ 命名约定：函数/变量小写下划线、类 CapWords、常量全大写、异常以 Error 结尾 ✅ 下划线语义：_前缀内部使用、双前缀名称修饰、__both 魔术方法勿自创 ✅ 空格规则：二元操作符两侧各 1 空格，括号内侧不加，默认值 = 不加空格（带注解时加） ✅ 编程建议：与 None 用 is 比较、def 代替赋值 lambda、异常继承 Exception
