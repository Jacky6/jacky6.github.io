    🐛 调试方法¶

    1. print 调试¶

    最简单直接的调试方式：

    知识点：

    • print 调试最简单直接；logging 模块提供 debug/info/warning/error/critical 五级日志
    • pdb.set_trace() 或 Python 3.7+ 的 breakpoint() 设置断点进入交互调试
    • ⭐ 面试重点：记住 pdb 核心命令——n 下一行、s 进入函数、c 继续、p 打印变量、q 退出
    • 正式项目用 logging 代替散落的 print，可按级别过滤
    def calculate_total(items):
    print(f"DEBUG: items = {items}")

    total = 0
    for item in items:
        print(f"DEBUG: processing {item}")
        total += item

    print(f"DEBUG: total = {total}")
    return total

# 使用
calculate_total([1, 2, 3, 4, 5])

    2. 使用 logging 模块¶

    import logging

# 配置日志
logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s - %(levelname)s - %(message)s'
)

def process_data(data):
    logging.debug(f"开始处理数据：{data}")

    if not data:
        logging.warning("数据为空")
        return None

    result = sum(data)
    logging.info(f"处理完成，结果：{result}")

    return result

# 日志级别
logging.debug("调试信息")    # 详细信息
logging.info("一般信息")     # 确认运行正常
logging.warning("警告信息")  # 潜在问题
logging.error("错误信息")    # 错误发生
logging.critical("严重错误") # 严重问题

    日志输出到文件¶

    生产环境通常把日志落盘，方便事后排查：

    import logging

# filename 参数让日志写入文件（同时不再打印到控制台）
logging.basicConfig(
    filename="app.log",
    level=logging.DEBUG,
    format="%(asctime)s - %(levelname)s - %(message)s"
)

logging.info("这条日志写入 app.log")

# 需要同时输出到控制台和文件时，用 Handler 组合
logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)
logger.addHandler(logging.FileHandler("app.log"))      # file output
logger.addHandler(logging.StreamHandler())             # console output

    3. 使用 pdb 调试器¶

    import pdb

def buggy_function(x, y):
    result = x + y
    pdb.set_trace()  # 设置断点
    result = result * 2
    return result

# 运行后会进入交互调试模式

    pdb 常用命令¶

    n (next)      - 执行下一行
s (step)      - 进入函数内部
c (continue)  - 继续执行到下一个断点
l (list)      - 显示当前代码
p (print)     - 打印变量值
q (quit)      - 退出调试器
h (help)      - 显示帮助

    4. 使用 breakpoint() (Python 3.7+)¶

    知识点：

    • breakpoint() 等价于 pdb.set_trace()，但可通过环境变量 PYTHONBREAKPOINT 控制
    • PYTHONBREAKPOINT=0 时所有 breakpoint() 调用被跳过——部署时不必删断点代码
    • ⚠️ 调试完记得处理断点：要么删除，要么靠 PYTHONBREAKPOINT=0 全局关闭
    def process(items):
    total = 0
    for item in items:
        total += item
        breakpoint()  # 自动进入调试器
    return total

# 生产环境直接禁用，无需改代码：
# $ PYTHONBREAKPOINT=0 python app.py

    📜 读懂 Traceback¶

    知识点：

    • Traceback 从上往下是调用栈（最外层 → 最内层），最后一行是异常类型和信息——先看最后一行
    • ⭐ 面试重点：能根据 traceback 指出出错的文件、行号和调用路径
    • 在 except 块中可用 traceback.print_exc() 打印当前异常的完整调用栈（常用于日志）
    def divide(a, b):
    return a / b

def process():
    return divide(10, 0)

process()
# Traceback (most recent call last):
#   File "app.py", line 6, in <module>   <- 最外层：程序入口
#     process()
#   File "app.py", line 4, in process    <- 中间层：调用链
#     return divide(10, 0)
#   File "app.py", line 2, in divide     <- 最内层：真正出错的位置
#     return a / b
# ZeroDivisionError: division by zero    <- 最后一行：异常类型 + 信息

    在 except 中记录完整调用栈（比只记 str(e) 信息多得多）：

    import traceback

try:
    int("abc")
except ValueError:
    traceback.print_exc()  # 打印完整调用栈到 stderr，也可 logging.exception() 记录

    🧟 事后调试（Post-mortem Debugging）¶

    知识点：

    • 程序已经崩溃了才想调试？两种手段保留现场：python -i 和 pdb.post_mortem()
    • python -i script.py：脚本崩溃后不退出，进入交互环境，可检查变量
    • pdb.post_mortem()：在 except 块中对刚发生的异常"验尸"，停在出错那一行
    • ⭐ 面试重点：print + 事后调试是生产环境无法复现问题时的救命稻草
    # python -i：崩溃后进入交互模式，检查现场变量
$ python -i app.py
>>> # 脚本崩溃后停在这里，可以 print(变量) 检查

    import pdb

try:
    result = 1 / 0
except ZeroDivisionError:
    pdb.post_mortem()  # 进入调试器，停在 1 / 0 那一行，可 p 检查变量

    🔍 常见错误排查¶

    1. NameError¶

    知识点：

    • NameError：变量未定义先使用；TypeError：类型不匹配（如 "5" + 3）
    • IndexError：索引越界；KeyError：字典缺键，用 dict.get(key, 默认值) 规避
    • ⚠️ AttributeError 常因方法名拼写错误（如 appnd）；字符串不可变，需生成新字符串
    # ❌ 错误
print(x)  # NameError: name 'x' is not defined

# ✅ 解决
x = 10
print(x)

    2. TypeError¶

    # ❌ 错误
result = "5" + 3  # TypeError

# ✅ 解决
result = int("5") + 3
# 或
result = "5" + str(3)

    3. IndexError¶

    # ❌ 错误
items = [1, 2, 3]
print(items[5])  # IndexError

# ✅ 解决
if len(items) > 5:
    print(items[5])
else:
    print("索引超出范围")

    4. KeyError¶

    # ❌ 错误
data = {"a": 1}
print(data["b"])  # KeyError

# ✅ 解决
print(data.get("b", "默认值"))
# 或
if "b" in data:
    print(data["b"])

    5. AttributeError¶

    # ❌ 错误
text = "hello"
text.appnd("x")  # AttributeError (拼写错误)

# ✅ 解决
text = "hello"
# 字符串不可变，需要创建新字符串
text = text + "x"

    🛠️ 调试工具¶

    1. VS Code 调试¶

    知识点：

    • VS Code 配置 .vscode/launch.json 即可断点调试；PyCharm 点行号设断点右键 Debug
    • timeit.timeit(语句, number=N) 测量代码片段执行时间
    • cProfile + pstats：按 cumulative 排序打印最耗时的前 N 个函数
    // .vscode/launch.json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Python: Current File",
            "type": "python",
            "request": "launch",
            "program": "${file}",
            "console": "integratedTerminal"
        }
    ]
}

    2. PyCharm 调试¶

    • 点击行号旁边设置断点
    • 右键选择 Debug
    • 使用调试工具栏

    3. 使用 timeit 性能分析¶

    import timeit

# 测试代码执行时间
time = timeit.timeit(
    "sum(range(1000))",
    number=10000
)
print(f"执行时间：{time:.4f}秒")

    4. 使用 cProfile 性能分析¶

    import cProfile
import pstats

def slow_function():
    total = 0
    for i in range(1000000):
        total += i
    return total

# 性能分析
profiler = cProfile.Profile()
profiler.enable()
slow_function()
profiler.disable()

# 打印统计
stats = pstats.Stats(profiler)
stats.sort_stats('cumulative')
stats.print_stats(10)

    📝 调试最佳实践¶

    ✅ 推荐¶

    知识点：

    • ✅ 有意义的变量名、docstring、assert 验证假设、logging 记录关键信息
    • ⚠️ 避免：过多 print、except: pass 静默吞异常、过长函数难以定位问题
    # 1. 使用有意义的变量名
def calculate_user_total(user_id, items):  # 清晰
    pass

def calc(uid, i):  # 不清晰
    pass

# 2. 添加文档字符串
def process_data(data):
    """处理数据并返回结果"""
    pass

# 3. 使用断言验证假设
def divide(a, b):
    assert b != 0, "除数不能为零"
    return a / b

# 4. 记录关键信息
import logging

def process(order):
    logging.info(f"处理订单：{order.id}")
    # ...

    ❌ 避免¶

    # 1. 过度使用 print
def func():
    print("1")
    print("2")
    print("3")
    # ... 太多调试输出

# 2. 忽略异常
try:
    risky_operation()
except:
    pass  # 静默失败

# 3. 过长的函数
def long_function():
    # 100 行代码...
    # 难以调试
    pass

    🎯 调试检查清单¶

    • 变量是否正确初始化？
    • 函数参数类型是否正确？
    • 循环边界是否正确？
    • 条件判断是否完整？
    • 异常是否被正确处理？
    • 返回值是否符合预期？
    • 是否有副作用影响其他代码？

    本章小结¶

    核心知识点¶

    ✅ 调试方法：print 快速定位 → logging 分级记录（可落盘）→ pdb/breakpoint() 交互断点（PYTHONBREAKPOINT=0 可全局关闭） ✅ pdb 核心命令：n 下一行、s 进入函数、c 继续、l 看代码、p 打印变量、q 退出 ✅ 读懂 Traceback：先看最后一行（异常类型 + 信息），调用栈从上往下由外到内，定位出错行 ✅ 事后调试：python -i 保留崩溃现场，pdb.post_mortem() 对异常"验尸" ✅ 常见错误：NameError 未定义、TypeError 类型错、IndexError 越界、KeyError 缺键（dict.get 规避）、AttributeError 多因拼写错 ✅ 性能分析：timeit 测片段耗时，cProfile + pstats 找热点函数；不静默吞异常

    调试是编程的重要技能，多练习会越来越好！
