    14_算法选择指南（Algorithm Selection）¶

    本章知识点清单¶

    # 知识点 一句话结论 重要度
    1 三步定位法 数据规模定复杂度上限 → 关键词定算法套路 → 求解目标定代码框架 ⭐⭐⭐⭐
    2 规模反推复杂度 n 的范围直接排除大部分算法，是读题后的第一道过滤器 ⭐⭐⭐⭐
    3 关键词信号表 题面特征词（连续/有序/所有方案/Top K…）直接映射候选算法 ⭐⭐⭐⭐
    4 求解目标分类 求所有方案→回溯；求最优值→DP/贪心；求满足条件的区间→滑动窗口；存在性/计数→哈希/搜索 ⭐⭐⭐⭐
    5 连续 vs 不连续 连续子数组/子串优先滑动窗口、前缀和；不连续（子序列/子集）想 DP、回溯 ⭐⭐⭐⭐
    6 数据结构信号 有序→二分；动态最值→堆；配对/下一个更大→栈；依赖关系→拓扑排序 ⭐⭐⭐
    7 组合套路 前缀和+哈希、二分答案+贪心、排序+双指针、单调栈等固定搭配 ⭐⭐⭐⭐
    8 前提验证 单调性、无后效性、贪心交换论证——套模板前必须验证，否则硬套必错 ⭐⭐⭐⭐
    9 30 秒判断流程 看规模 → 看连续性 → 看目标 → 看结构提示 → 验证前提 ⭐⭐⭐⭐
    10 一题多解对比 同一题面下不同约束（如含负数）会把答案从滑动窗口切换到前缀和+哈希 ⭐⭐⭐⭐
    11 求方案 ≠ 必须回溯 方案总数只有多项式级时直接枚举更优；回溯仅当 n ≤ 20 且方案数指数级 ⭐⭐⭐⭐

    1. 三步定位法总览¶

    1.1 知识点¶

    前面 13 章分别讲"每个算法怎么写"，本章解决另一个更卡人的问题：拿到一道新题，怎么在 30 秒内确定用哪个算法？ 核心是三步定位法：

    第一步：看数据规模 → 锁定复杂度上限（排除法，砍掉 80% 候选）
第二步：看关键词   → 特征词直接映射候选算法（信号表）
第三步：看求解目标 → 确定代码框架（枚举/最优化/区间/判定）
    • 第一步是硬约束：$n \le 10^5$ 时 $O(n^2)$ 必超时，再喜欢暴力也得换思路
    • 第二步是软提示：关键词给出候选，但可能"骗人"（见 3.3 易错点）
    • 第三步定骨架：求方案数和求最值的代码结构完全不同
    • 最后还有一道保险：套模板前验证算法前提（单调性/无后效性），这是最容易翻车的一步

    本章所有表格都建议当"字典"用：做题卡壳时回来查，而不是死记硬背。

    1.2 为什么需要方法论¶

    每个算法单独学都懂，一到新题就懵，原因是缺少从"题面"到"算法"的映射。这个映射无法靠灵感，只能靠刻意总结的对照表 + 验证习惯。本章的表格就是这份对照表，第 6 节的 30 秒流程是把对照表变成肌肉记忆的路径。

    2. 第一步：看数据规模，锁定复杂度上限¶

    2.1 知识点¶

    题目给的 $n$ 的范围不是装饰品，它是最强的选型约束。竞赛/面试题的数据范围通常是精心设计的——恰好卡掉低一档的复杂度。经验公式：1 秒内大约执行 $10^8$ 次基本操作，据此反推：

    $n$ 的范围 可接受复杂度 典型算法
    $n \le 20$ $O(2^n)$、$O(n!)$ 回溯、状压 DP、暴力枚举子集/排列
    $n \le 100$ $O(n^3)$ Floyd、区间 DP
    $n \le 3000$ $O(n^2)$ 常规二维 DP、双指针暴力、朴素匹配
    $n \le 10^5$ $O(n \log n)$ 排序、堆、二分、分治、线段树
    $n \le 10^6$ $O(n)$ 滑动窗口、双指针、哈希、单调栈、前缀和
    $n > 10^6$ $O(\log n)$ / $O(1)$ 每次查询 二分答案、数学公式、预处理+O(1)查询

    💡 读题第一件事：找到 "1 <= nums.length <= ..."，把复杂度上限写在草稿纸上，再开始想算法。看到 $n \le 10^5$ 还想写 $O(n^2)$ 嵌套循环，基本必超时。

    2.2 反向用法：从复杂度猜算法¶

    这张表还能反过来用——当你想到一个 $O(n \log n)$ 的做法但题目 $n \le 3000$ 时，说明存在更简单的 $O(n^2)$ 做法（通常是二维 DP），不必死磕优化。数据范围既是下限（不能更慢），也暗示了出题人预期的解法档次。

    2.3 ⚠️ 易错点：经验法则的边界¶

    1. 常数因子：O(n) 但常数极大（如哈希冲突严重）可能不如 O(n log n) 的排序
2. 多次查询：单次 O(n) 但查询 q 次 → 总 O(nq)，需要预处理（前缀和/ST 表）
3. n 很小（≤ 20）时不要过度优化：O(2^n) 回溯 + 剪枝往往就是标答
4. 字符串题注意字符集大小 k：计数类做法可能是 O(nk)

    最常见的失误是忽略查询次数 q：LeetCode 303 区间和查询，每次现算 O(n)、q 次查询总 O(nq)，数据一大就超时——这正是前缀和存在的意义（预处理 O(n)，每次查询 O(1)）。

    3. 第二步：关键词 → 算法信号表¶

    3.1 知识点¶

    题面中的特征词是出题人留下的"路标"。下面这张表覆盖 90% 的高频信号，左列是题面特征，右列是第一反应：

    题目关键词/特征 首选算法 对应章节
    连续子数组/子串 的最值 滑动窗口、前缀和 13 章
    所有组合/排列/子集 回溯 12 章
    "最多/最少/最长/最短" + 选择有后效性 动态规划 10 章
    每步可证明的局部最优（区间调度类） 贪心 11 章
    有序/旋转数组/"最小的满足…" 二分查找、二分答案 9 章
    括号匹配、下一个更大元素、柱状图 栈（单调栈） 3 章
    Top K、第 K 大、数据流中位数 堆（对顶堆） 6 章
    层序、最少步数、最短转化路径 BFS 4/7 章
    所有路径、连通性、环检测 DFS、并查集 7 章
    依赖关系、执行顺序 拓扑排序 7 章
    两数之和、去重、频次统计 哈希表 5 章
    链表中点、倒数第 K 个、判环 快慢指针 2 章
    区间求和/单点修改 前缀和、树状数组、线段树 1 章
    前缀匹配、字符串集合查找 Trie 6 章
    无序但答案与"排序后相邻"有关 排序后扫描 8 章
    生成括号、N 皇后、数独 回溯 + 剪枝 12 章

    3.2 信号叠加：多个关键词同时出现¶

    真实题目往往叠加多个信号，此时组合套路（第 5 节）比单一算法更常见。判断优先级：约束性强的信号优先。例如"有序数组 + 两数之和"→ 双指针（利用有序）；"无序数组 + 两数之和"→ 哈希表。"连续 + 最短 + 满足条件"→ 滑动窗口；"不连续 + 最长 + 满足条件"→ DP。

    3.3 ⚠️ 易错点：关键词会"骗人"¶

    ❌ 看到"最长"就想到 DP？
   LC 3 无重复字符的最长子串 → "子串"（连续）→ 滑动窗口 O(n)
   LC 300 最长递增子序列     → "子序列"（不连续）→ DP O(n²)/贪心+二分 O(n log n)

❌ 看到"中位数/第 K 大"就排序？
   静态数据一次查询 → 排序 O(n log n) 就够
   数据流/动态数据   → 堆 O(log n) 维护

❌ 看到"路径"就 DFS 暴力？
   求所有路径 → DFS
   求最短路径 → 无权图 BFS；带权图 Dijkstra

    破解方法：关键词只给候选，最终确认要过第三步（求解目标）和前提验证（第 7 节）。尤其注意"子串/子数组"（连续）和"子序列/子集"（不连续）这对词，它们是滑动窗口与 DP 的分水岭。

    4. 第三步：按求解目标定框架¶

    4.1 知识点¶

    同样的数据、同样的约束，要求的东西不同，算法框架就完全不同。把求解目标分成四类，每类对应固定骨架：

    求解目标 问题形态 算法框架
    所有方案 "返回所有组合/排列/分割方案" 回溯（决策树 DFS + 撤销）
    最优值 "最大/最小/最长/最短是多少" DP（有后效性）或贪心（可证明局部最优）
    满足条件的区间 "和 ≥ target 的最短子数组" 滑动窗口（连续）/ 前缀和+哈希（含负数）
    存在性/计数 "是否存在…/有多少个…" 哈希表、DFS/BFS/并查集、数学

    4.2 决策流程图¶

    读题
 │
 ├─ 数据规模 n？──────────────→ 锁定复杂度上限（第 2 节）
 │
 ├─ 要求什么？
 │   │
 │   ├─ 所有方案（枚举）──────→ 回溯/DFS（n ≤ 20 量级）

 │   │     ├─ 子问题重叠 + 无后效性 ──→ 动态规划

 │   │     └─ 答案空间单调 ──────────→ 二分答案 + 贪心验证
 │   │

    4.3 ⚠️ 易错点："求方案"和"求值"混用框架¶

    求方案数（如 LC 62 不同路径）用 DP 计数没问题；但求具体方案（如 LC 51 N 皇后的棋盘摆法）必须回溯枚举——DP 只留数值不留路径。反过来，求方案数时用回溯会超时（方案数本身是指数级），必须 DP。一句话：要列举就回溯，要计数/最值就 DP——但注意规模前提：方案总数只有多项式级时（如三数之和的 O(n²)），直接枚举比回溯更优，见 6.3 节。

    5. 高频组合套路¶

    5.1 知识点¶

    中等以上的题很少考单一算法，而是固定搭配。这些组合值得整块记住，见到题面直接调用：

    组合套路 题面特征 代表题
    前缀和 + 哈希表 连续子数组和为 K 的个数（含负数） LC 560
    二分答案 + 贪心验证 "最小的最大值/最大的最小值" LC 875、410
    单调栈 下一个更大元素、柱状图最大矩形 LC 739、84
    排序 + 双指针 三数之和类、两数之和 II LC 15、167
    堆 + 贪心 任务调度、合并 K 个链表 LC 621、23
    拓扑排序 + DP 依赖关系上的最长/最短路径 LC 210、课程表 III
    排序 + 贪心 无重叠区间、会议室 LC 435
    前缀和 + 单调队列 含负数的"和 ≥ target 最短子数组" LC 862
    DFS + 记忆化 网格路径计数、字符串搜索状态 LC 329
    快慢指针 + 反转链表 链表中点、回文链表 LC 876、234

    5.2 为什么组合是常态¶

    单一数据结构往往只解决"一半"：前缀和把区间和变 O(1)，但"找和为 K"还需要哈希表定位；二分把"求最优"变"判可行"，但判定本身要贪心实现。识别组合的技巧：把题目拆成两个子问题，分别问"每个子问题用什么基础工具"，再拼起来。

    6. 30 秒实战判断流程¶

    6.1 知识点¶

    把前三步串成固定顺序，每道题读完后按序自问：

    1. n 多大？        → 复杂度上限是多少，排除哪些做法
2. 连续还是不连续？ → 连续优先滑动窗口/前缀和；不连续想 DP/回溯
3. 求方案还是求值？ → 方案用回溯；值用 DP/贪心/二分
4. 数据结构提示？   → 有序→二分；动态最值→堆；配对→栈；依赖→拓扑
5. 前提成立吗？     → 单调性/无后效性/贪心证明，不成立就换下一候选

    6.2 完整示例一：一对"孪生题"走流程¶

    用两道题面几乎相同、约束不同的题演示流程的威力——这正是第 5 步（前提验证）存在的意义：

    题 A（LC 209 长度最小的子数组）：正整数数组，求和 ≥ target 的最短连续子数组。

    1. n ≤ 10^5          → 需要 O(n) 或 O(n log n)
2. "连续子数组"       → 滑动窗口候选
3. 求最短（值）       → 可变窗口，最短题在 while 内更新
4. 无特殊结构提示
5. 前提验证：全是正数 → 窗口扩张和只增、收缩和只减 → 单调性成立 ✅
→ 结论：滑动窗口 O(n)

    def minSubArrayLen(target, nums):
    left = total = 0
    ans = float('inf')
    for right, x in enumerate(nums):
        total += x                    # 扩张
        while total >= target:        # 满足条件就收缩，找更短
            ans = min(ans, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if ans == float('inf') else ans

    题 B（LC 560 和为 K 的子数组）：数组可含负数，数和恰好等于 k 的连续子数组个数。

    1. n ≤ 2×10^4        → O(n²) 勉强能过，但存在 O(n) 标答
2. "连续子数组"       → 想滑动窗口？
3. 求计数（恰好等于）  → 滑动窗口只会处理 "≥" 型单调条件
4. 无特殊结构提示
5. 前提验证：含负数 → 窗口扩张时和可能变小，"该扩张还是收缩"失去依据
   → 单调性不成立 ❌ 滑动窗口出局
→ 换候选：前缀和 + 哈希（prefix[j] - prefix[i] == k ⇔ 子数组 (i, j] 和为 k）

    from collections import defaultdict

def subarraySum(nums, k):
    count = defaultdict(int)
    count[0] = 1                      # 预置 0:1，处理"前缀本身等于 k"
    prefix = ans = 0
    for x in nums:
        prefix += x
        ans += count[prefix - k]      # 之前有多少个前缀和 = prefix - k
        count[prefix] += 1
    return ans

    孪生题的启示：题面只差"正数 vs 可负"，算法却从滑动窗口换成前缀和+哈希。如果跳过第 5 步直接套模板，题 B 必错。这就是"会写算法"和"会选算法"的差距。

    6.3 完整示例二：三数之和（LC 15）——每一步都先指向"错误答案"¶

    这道题的有趣之处在于：五步流程中前几步的直觉答案会被后面的步骤逐一否掉，完美展示排除法的完整链路：

    题面：数组中找出所有和为 0 的三元组，答案不含重复组合。

    1. n ≤ 3000          → O(n²) 可接受（9×10⁶），O(n³) 危险（2.7×10¹⁰）
2. "组合"，不要求连续  → 排除滑动窗口 ❌
3. 求所有方案        → 第一反应是回溯 ❌
                      但回溯适合 n ≤ 20，这里 C(3000,3) ≈ 4.5×10⁹ 必超时
                      → 转化视角：去重后的三元组总数只有 O(n²) 级，可以高效枚举
4. 拆子问题："固定一个数后找两数之和 = -nums[i]"
                      → 有序数组上的两数之和 → 双指针 ✅
5. 前提验证：排序后 sum < 0 则 left++、sum > 0 则 right--，方向确定
                      → 单调性成立 ✅
→ 结论：排序 + 固定一个数 + 双指针，O(n²)

    排除过程（这才是方法论的价值）：

    候选 被谁否掉 原因
    暴力三重循环 O(n³) 第 1 步（规模） $n \le 3000$ 时 $2.7 \times 10^{10}$ 超时
    滑动窗口 第 2 步（连续性） 组合不要求连续，窗口无从收缩
    回溯 第 3 步（规模 × 目标） 求方案确实指向回溯，但 $n$ 超出指数级算法的适用范围
    哈希表（查 a+b=-c） 第 4 步（结构） 可行 O(n²)，但去重逻辑繁琐，不如双指针天然有序 
    def threeSum(nums):
    nums.sort()                          # O(n log n)，双指针与去重都依赖有序
    n, ans = len(nums), []
    for i in range(n - 2):
        if nums[i] > 0:                  # 剪枝：最小数 > 0，三数之和不可能为 0
            break
        if i > 0 and nums[i] == nums[i - 1]:   # 去重①：跳过重复的第一个数
            continue
        left, right = i + 1, n - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s < 0:
                left += 1
            elif s > 0:
                right -= 1
            else:
                ans.append([nums[i], nums[left], nums[right]])
                while left < right and nums[left] == nums[left + 1]:   # 去重②
                    left += 1
                while left < right and nums[right] == nums[right - 1]: # 去重③
                    right -= 1
                left += 1
                right -= 1
    return ans

    三数之和的启示：这是"求方案 ≠ 必须回溯"的最佳例证——方案总数本身只有 $O(n^2)$ 个时，直接枚举比决策树搜索更高效。4.3 节的口诀"要列举就回溯"要加上规模前提。另外，算法选对只是及格线，三处去重才是面试翻车点：① 第一个数和前一个比（和 i+1 比会漏掉 [-1, -1, 2] 这种解）；② 命中后跳过相同的 nums[left]/nums[right]（否则 [-2, 0, 0, 2, 2] 输出重复的 [-2, 0, 2]）；③ 去重后仍要 left += 1; right -= 1，停在原地会死循环。

    7. ⚠️ 易错点：套模板前必须验证的四个前提¶

    本章反复强调的最后一道保险。每个"套路"都有成立前提，前提不成立时模板不仅慢，而且错：

    算法 必须验证的前提 前提破坏时换什么 反例题
    滑动窗口 窗口性质单调（扩张/收缩方向确定） 前缀和+哈希（LC 560）、前缀和+单调队列（LC 862） 含负数的区间和
    贪心 局部最优 ⇒ 全局最优（交换论证） 动态规划 LC 322 零钱兑换（面额 1/3/4 凑 6：贪心 4+1+1=3 枚，DP 3+3=2 枚）
    二分答案 check 函数单调（值越大越容易/难满足） DP、暴力 答案空间不单调的判定
    DP 无后效性 + 最优子结构 状态设计改造（增加维度）或贪心/回溯 有后效性的网格问题需把"方向"纳入状态
    二分查找 搜索空间有序或可减半 先排序（O(n log n)）或哈希 无序数组直接二分

    记忆口诀："窗口看单调，贪心要证明，二分看空间，DP 看后效"。验证只需要 10 秒钟，但能省下 30 分钟的调试。

    8. 本章小结¶

    核心知识点¶

    ✅ 三步定位法：数据规模定复杂度 → 关键词定套路 → 求解目标定框架 ✅ 规模反推复杂度：$n \le 10^5$ 想 $O(n \log n)$，$n \le 10^6$ 想 $O(n)$，$n \le 20$ 才允许指数级 ✅ 关键词信号表：连续→滑动窗口；所有方案→回溯；有序→二分；Top K→堆；依赖→拓扑排序 ✅ 求解目标四分类：所有方案→回溯；最优值→DP/贪心；满足条件区间→滑动窗口；存在性/计数→哈希/搜索 ✅ 分水岭词汇："子串/子数组"（连续）vs "子序列/子集"（不连续） ✅ 组合套路是常态：前缀和+哈希、二分答案+贪心、排序+双指针、单调栈、堆+贪心 ✅ 求方案 ≠ 必须回溯：方案总数只有多项式级时直接枚举更优（三数之和），回溯仅当 n ≤ 20 且方案数指数级 ✅ 前提验证是保险：窗口看单调、贪心要证明、二分看空间、DP 看后效

    最佳实践¶

    1. 读题先看 n：把复杂度上限写在草稿上，再开始想算法，避免在必超时的方向上浪费时间
    2. 圈出关键词：特别圈"连续/不连续""方案/数值""存在/计数"这三对分水岭词
    3. 候选按序验证：信号表给出 2-3 个候选时，用前提验证逐个排除，而不是凭感觉挑
    4. 卡壳时查表：本章表格是字典不是课文，做题卡住回来对表，比空想有效
    5. 做完做总结：每道题写一行"题面特征 → 所用算法 → 为什么不是另一个"，积累自己的信号表
