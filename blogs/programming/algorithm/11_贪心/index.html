    1. 贪心思想与适用条件¶

    1.1 知识点¶

    贪心算法（Greedy）指在每一步选择中都采取当前状态下最优的选择，并且一旦做出选择就不后悔（不回溯），希望由局部最优解推出全局最优解。理解贪心记住三点： - 局部最优：每一步只看眼前，选当前最好的，不做全局枚举 - 不回溯：选择一旦做出就不可撤销，这是贪心与 DP、回溯的本质区别，也是它快的原因 - 必须可证：贪心不是万能钥匙。只有问题满足 贪心选择性质（局部最优能导致全局最优）和 最优子结构（大问题的最优解包含子问题的最优解）时才能用，且策略的正确性需要证明

    贪心的核心难点从来不是写代码，而是判断"什么时候能用贪心"。拿不准时的流程：先尝试证明贪心策略（交换论证/归纳法）；证不出来，就换 DP；实在没把握，写一个暴力解对拍验证贪心的输出。

    1.2 贪心 vs 动态规划¶

    贪心 vs 动态规划

贪心：
  每一步选当前最优，一条路走到底
  快，但不一定能得到最优解

动态规划：
  考虑所有可能，选全局最优
  慢，但一定能得到最优解
    特性 贪心 动态规划
    选择方式 当前最优 全局最优
    回溯 不回溯 考虑所有可能
    效率 O(n log n) 或 O(n) O(n²) 或 O(n³)
    正确性 需证明 必然正确
    适用 特殊问题 一般最优化问题

    1.3 ⚠️ 易错点：贪心不适用的反例（背包问题 / 硬币找零）¶

    贪心最容易翻车的地方，是把"看起来局部最优"直接当成"全局最优"。两个经典反例要刻在脑子里：

    # 反例 1：0/1 背包（物品不可拆分）
# 背包容量 50，物品：A(重10, 值60)、B(重20, 值100)、C(重30, 值120)
# 贪心按"性价比"排序：A(6.0) > B(5.0) > C(4.0)
#   先拿 A（余量 40），再拿 B（余量 20），C 装不下 → 总价值 160
# 但最优解是 B + C：重量 20 + 30 = 50 刚好装满，总价值 220
# ❌ 贪心得不到最优解，0/1 背包必须用 DP
# （注意：如果物品可拆分，"分数背包"按性价比贪心反而是最优的——
#   差别就在"能不能切开补满剩余容量"）

# 反例 2：硬币找零（特定面额）
# 面额 [1, 5, 11]，凑出金额 15，要求硬币数最少
# 贪心每次选最大面额：11 + 1 + 1 + 1 + 1 → 5 枚
# 最优解：5 + 5 + 5 → 3 枚
# ❌ 贪心不是最优；面额为 [1, 5, 10, 25] 这类特殊体系时贪心才成立

    结论：遇到最优化问题，先问"局部最优的选择会不会堵死后面的路"。答案不确定就写暴力解对拍，或直接上 DP。

    2. 基础贪心：排序 + 线性扫描¶

    2.1 知识点¶

    最基础的贪心题几乎都是同一个套路：先排序，再线性扫描。排序的作用是把"当前最优选择"显式化——排好序后，每一步该选谁、该跳过谁变得一目了然，一次遍历即可完成。典型代表是分配饼干（LC 455）：排序后"用最小的饼干满足胃口最小的孩子"就是局部最优，因为它不浪费大饼干。

    还有一类约束来自两个方向的问题（如分发糖果 LC 135：既要比左边高、又要比右边高），一次扫描只能照顾一个方向，标准解法是左右各扫一遍，同一位置取两次结果的 max。

    2.2 分配饼干（LeetCode 455）¶

    def findContentChildren(g: List[int], s: List[int]) -> int:
    """
    LeetCode 455：分配饼干

    g: 孩子的胃口值
    s: 饼干尺寸
    每个孩子最多一块饼干，饼干尺寸 >= 胃口才能满足

    贪心策略：
    1. 用小饼干满足小胃口（不浪费）
    2. 排序后双指针
    """
    g.sort()  # 孩子胃口
    s.sort()  # 饼干尺寸

    child = cookie = 0

    while child < len(g) and cookie < len(s):
        if s[cookie] >= g[child]:
            # 这块饼干能满足这个孩子
            child += 1
        # 无论是否满足，饼干都用掉了
        cookie += 1

    return child


# 示例
g = [1, 2, 3]
s = [1, 1]
print(findContentChildren(g, s))  # 1

g = [1, 2]
s = [1, 2, 3]
print(findContentChildren(g, s))  # 2

    复杂度：排序 O(m log m + n log n)，双指针扫描 O(m + n)；空间 O(log m + log n)（排序栈）。

    2.3 分发糖果（LeetCode 135）¶

    def candy(ratings: List[int]) -> int:
    """
    LeetCode 135：分发糖果

    规则：
    1. 每个孩子至少 1 颗糖果
    2. 相邻孩子中，评分高的必须获得更多糖果

    贪心策略：
    1. 从左到右：右边评分高 → 糖果多
    2. 从右到左：左边评分高 → 糖果多
    3. 取两次遍历的最大值
    """
    n = len(ratings)
    candies = [1] * n

    # 从左到右
    for i in range(1, n):
        if ratings[i] > ratings[i - 1]:
            candies[i] = candies[i - 1] + 1

    # 从右到左
    for i in range(n - 2, -1, -1):
        if ratings[i] > ratings[i + 1]:
            candies[i] = max(candies[i], candies[i + 1] + 1)

    return sum(candies)


# 示例
ratings = [1, 0, 2]
print(candy(ratings))  # 5 ([2, 1, 2])

ratings = [1, 2, 2]
print(candy(ratings))  # 4 ([1, 2, 1])

    复杂度：两次遍历 O(n)；空间 O(n)。

    2.4 ⚠️ 易错点：分发糖果只扫一遍¶

    ratings = [1, 3, 4, 3, 2]

# ❌ 只从左到右扫一遍：得到 [1, 2, 3, 1, 1]
# 位置 3 评分 3 > 位置 4 评分 2，但位置 3 只有 1 颗糖，违反规则

# ✅ 左右各扫一遍，同一位置取两次结果的 max：
# 左→右：[1, 2, 3, 1, 1]   （只保证"右边评分更高"这一侧的约束）
# 右→左：[1, 1, 3, 2, 1]   （只保证"左边评分更高"这一侧的约束）
# 合并：  [1, 2, 3, 2, 1] → 共 9 颗，两个方向的约束同时满足

    单向扫描天然只能看到一侧的邻居，双向约束必须拆成两次单向扫描分别处理，这是分发糖果题的通用思路。

    3. 区间问题¶

    3.1 知识点¶

    区间贪心是贪心章的高频考点，成败在于排序维度选哪一个： - 求最多能保留多少个互不重叠区间（无重叠区间 LC 435、活动选择）：按右端点（结束时间）排序，优先保留结束早的——结束越早，给后面留的空间越大，这是可以严格证明的贪心策略 - 合并所有重叠区间（合并区间 LC 56）：按左端点（开始时间）排序，保证"可能重叠的区间一定相邻"，一次遍历即可合并

    记忆口诀："选最多看右端点，做合并看左端点"。两个方向的排序维度不可互换，选错维度贪心直接失效（见 3.4 反例）。

    3.2 无重叠区间（LeetCode 435）¶

    def eraseOverlapIntervals(intervals: List[List[int]]) -> int:
    """
    LeetCode 435：无重叠区间

    求需要移除的最小区间数

    贪心策略：
    1. 按结束时间排序
    2. 优先保留结束早的区间（给后面留更多空间）
    """
    if not intervals:
        return 0

    # 按结束时间排序
    intervals.sort(key=lambda x: x[1])

    count = 1  # 保留的区间数
    end = intervals[0][1]

    for i in range(1, len(intervals)):
        if intervals[i][0] >= end:
            # 不重叠，可以保留
            count += 1
            end = intervals[i][1]

    return len(intervals) - count


# 示例
intervals = [[1, 2], [2, 3], [3, 4], [1, 3]]
print(eraseOverlapIntervals(intervals))  # 1（移除 [1,3]）

    思路：最少移除数 = 总数 − 最多能保留的不重叠区间数。按右端点排序后贪心选取，O(n log n)。

    3.3 合并区间（LeetCode 56）¶

    def merge(intervals: List[List[int]]) -> List[List[int]]:
    """
    LeetCode 56：合并区间

    贪心策略：
    1. 按开始时间排序
    2. 遍历合并重叠区间
    """
    if not intervals:
        return []

    # 按开始时间排序
    intervals.sort(key=lambda x: x[0])

    merged = [intervals[0]]

    for interval in intervals[1:]:
        last = merged[-1]

        if interval[0] <= last[1]:
            # 重叠，合并
            last[1] = max(last[1], interval[1])
        else:
            # 不重叠，添加新区间
            merged.append(interval)

    return merged


# 示例
intervals = [[1, 3], [2, 6], [8, 10], [15, 18]]
print(merge(intervals))  # [[1, 6], [8, 10], [15, 18]]

    复杂度：排序 O(n log n)，合并 O(n)。

    3.4 ⚠️ 易错点：区间排序维度选错（左端点 vs 右端点）¶

    intervals = [[1, 10], [2, 3], [4, 5]]

# ❌ 求"最多保留几个不重叠区间"时按左端点排序：
# 先选了 [1,10]，后面两个区间全被它挡住 → 只能保留 1 个
# ✅ 按右端点排序：先选 [2,3]，再选 [4,5] → 保留 2 个（最优）
# 原因：左端点小不代表"占的地方少"，[1,10] 左端点最小却最挡路；
#       右端点小才真正意味着"早点结束、给后面腾地方"

# ❌ 反过来，合并区间若按右端点排序，"重叠的区间一定相邻"不再成立，
# 一次遍历会漏合并。合并必须按左端点排序。

    结论：排序维度不是随便选的——"选最多"按右端点，"做合并"按左端点，写代码前先想清楚目标是哪一个。

    3.5 ⚠️ 易错点：合并区间时右端点忘记取 max¶

    intervals = [[1, 5], [2, 4], [6, 8]]

# ❌ 合并时直接赋值 last[1] = interval[1]：
# [1,5] 与 [2,4] 合并后右端点变成 4，区间反而缩小了
# （[2,4] 被完全包含在 [1,5] 里，直接赋值丢掉了已覆盖的范围）
last[1] = interval[1]          # ❌

# ✅ 右端点取 max，防止被包含的区间让范围倒退
last[1] = max(last[1], interval[1])   # ✅

    4. 跳跃游戏：维护最远可达边界¶

    4.1 知识点¶

    跳跃游戏系列（LC 55 / LC 45）的贪心不落点在"每一步跳哪"，而在于只维护一个量：当前能到达的最远位置。因为只要位置 i 可达，i 之前的所有位置也都可达，所以不需要枚举每种跳法，线性扫描时不断更新 max_reach = max(max_reach, i + nums[i]) 即可： - LC 55（能否到达终点）：扫描中若 i > max_reach 说明当前位置不可达，直接失败；max_reach 触到终点即成功 - LC 45（最少跳几次）：把"一次跳跃能覆盖的范围"当作一层边界，在当前这跳的边界内贪心地看下一跳能延伸多远，走到边界就不得不跳一次

    这类题的本质是贪心地推迟决策：不到边界不跳，每跳都把可达范围扩到最大。

    4.2 跳跃游戏（LeetCode 55）¶

    def canJump(nums: List[int]) -> bool:
    """
    LeetCode 55：跳跃游戏

    每个位置表示能跳跃的最大长度
    判断能否到达最后一个位置

    贪心策略：
    维护能到达的最远位置
    """
    max_reach = 0

    for i, jump in enumerate(nums):
        if i > max_reach:
            # 当前位置不可达
            return False

        max_reach = max(max_reach, i + jump)

        if max_reach >= len(nums) - 1:
            return True

    return max_reach >= len(nums) - 1


# 示例
nums = [2, 3, 1, 1, 4]
print(canJump(nums))  # True

nums = [3, 2, 1, 0, 4]
print(canJump(nums))  # False

    复杂度：O(n) 时间，O(1) 空间。

    4.3 跳跃游戏 II（LeetCode 45）¶

    def jump(nums: List[int]) -> int:
    """
    LeetCode 45：跳跃游戏 II

    求到达最后位置的最少跳跃次数

    贪心策略：
    在可达范围内选择能跳最远的位置
    """
    if len(nums) <= 1:
        return 0

    jumps = 0
    current_end = 0
    farthest = 0

    for i in range(len(nums) - 1):
        farthest = max(farthest, i + nums[i])

        if i == current_end:
            # 必须跳跃了
            jumps += 1
            current_end = farthest

            if current_end >= len(nums) - 1:
                break

    return jumps


# 示例
nums = [2, 3, 1, 1, 4]
print(jump(nums))  # 2 (0→1→4)

    复杂度：O(n) 时间，O(1) 空间。

    注意循环写的是 range(len(nums) - 1)——不遍历最后一个位置：终点是"到达"而不是"起跳"的地方，如果把最后一格也遍历到，会多算一次跳跃。

    5. 贪心 + 堆：Top K 与霍夫曼¶

    5.1 知识点¶

    堆（优先队列）是贪心的加速器：当"当前最优"是动态变化的（每加入一个元素，"第 k 大"的门槛都会变），就需要堆在 O(log k) 时间内维护这个最优值。

    • Top K 模式：求最大的 k 个元素，维护一个大小为 k 的小顶堆，堆顶就是"第 k 大"的门槛，比门槛高的元素才替换进来。整体 O(n log k)，优于全排序的 O(n log n)，且适合数据流场景
    • 霍夫曼编码：贪心 + 堆的教科书应用——每次从堆中取出频率最小的两个节点合并成新节点再放回，局部最优（让频率最小的编码最长）导致全局最优（总编码长度最短）

    下面两道题都是"小顶堆守门"模式：堆里始终只保留候选的 k 个元素，堆顶负责淘汰不够格的。

    5.2 数据流中的第 K 大元素（LeetCode 703）¶

    import heapq

class KthLargest:
    """
    LeetCode 703：数据流中的第 K 大元素

    贪心 + 堆
    维护大小为 k 的最小堆
    """

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.heap = nums[:k]
        heapq.heapify(self.heap)

        for num in nums[k:]:
            self.add(num)

    def add(self, val: int) -> int:
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, val)
        elif val > self.heap[0]:
            heapq.heapreplace(self.heap, val)

        return self.heap[0]

    复杂度：add 单次 O(log k)；堆只存 k 个元素，空间 O(k)。

    5.3 前 K 个高频元素（LeetCode 347）¶

    from collections import Counter
import heapq

def topKFrequent(nums: List[int], k: int) -> List[int]:
    """
    LeetCode 347：前 K 个高频元素

    贪心 + 堆
    """
    counter = Counter(nums)

    # 维护大小为 k 的最小堆
    heap = []
    for num, freq in counter.items():
        if len(heap) < k:
            heapq.heappush(heap, (freq, num))
        elif freq > heap[0][0]:
            heapq.heapreplace(heap, (freq, num))

    return [num for freq, num in heap]


# 示例
nums = [1, 1, 1, 2, 2, 3]
k = 2
print(topKFrequent(nums, k))  # [1, 2]

    复杂度：统计 O(n)，堆操作 O(m log k)（m 为不同元素个数）。

    5.4 ⚠️ 易错点：Top K 该用大顶堆还是小顶堆¶

    import heapq

nums = [3, 1, 5, 2, 4]
k = 2  # 求最大的 2 个元素

# ❌ 误区 1：求"最大的 k 个"就用大顶堆
# 大顶堆堆顶是最大值，无法在 O(1) 内找到"目前入选者里最小的那个"，
# 新元素来了不知道该淘汰谁，守不住门

# ❌ 误区 2：全部入堆、不限制堆大小（Python 的 heapq 只有小顶堆）
heap = []
for num in nums:
    heapq.heappush(heap, num)   # 堆长到 n，最后再挑最大的 k 个 = 变相全排序 O(n log n)

# ✅ 大小为 k 的小顶堆：堆顶是"第 k 大"的门槛，比门槛高才替换进来
heap = []
for num in nums:
    if len(heap) < k:
        heapq.heappush(heap, num)
    elif num > heap[0]:
        heapq.heapreplace(heap, num)  # 单次 O(log k)，总体 O(n log k)
# heap 中即最大的 k 个元素

    口诀：求最大的 k 个 → 小顶堆（淘汰小的）；求最小的 k 个 → 大顶堆（淘汰大的）。

    6. 经典贪心题¶

    6.1 知识点¶

    这一节收录四道面试高频题，各自代表一种贪心形态： - 盛最多水的容器（LC 11）：双指针贪心——每步移动短板，因为移动长板被证明不可能更优，等于一步步排除不可能成为答案的组合 - 加油站（LC 134）：全局可行性（总油量 ≥ 总消耗）+ 局部重置（油量变负就换起点），两条贪心结论拼出 O(n) 解 - 单调递增的数字（LC 738）：数字位上的贪心——找到第一个下降位，前一位减 1、后面全变 9，倒序扫描处理连续借位 - 摆动序列（LC 376）：只保留峰值和谷值，相等不算摆动，up/down 两个状态交替上升

    6.2 盛最多水的容器（LeetCode 11）¶

    def maxArea(height: List[int]) -> int:
    """
    LeetCode 11：盛最多水的容器

    贪心 + 双指针
    从两端向中间移动，每次移动较短的板
    """
    left, right = 0, len(height) - 1
    max_area = 0

    while left < right:
        # 计算当前面积
        h = min(height[left], height[right])
        w = right - left
        area = h * w
        max_area = max(max_area, area)

        # 移动较短的板
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1

    return max_area


# 示例
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
print(maxArea(height))  # 49

    复杂度：O(n) 时间，O(1) 空间。

    6.3 ⚠️ 易错点：盛水容器该移动长板还是短板¶

    # 面积 = min(h[left], h[right]) * (right - left)

# ❌ 移动较长的板：
# 宽度一定减 1，而高度受限于短板不可能变大 → 面积必然不增，
# 这一步纯属浪费，还会错过以短板为边界的所有更优组合

# ✅ 移动较短的板：宽度虽减 1，但短板换成了可能更高的板，面积才有机会变大
if height[left] < height[right]:
    left += 1    # ✅ 移动短板
else:
    right -= 1   # ✅ 移动短板（两板相等时移哪边都行）

    这正是双指针 O(n) 正确性的来源：每次移动都排除了一整批不可能更优的组合（长板与所有更内侧位置的配对），而不是盲目缩小搜索范围。

    6.4 加油站（LeetCode 134）¶

    def canCompleteCircuit(gas: List[int], cost: List[int]) -> int:
    """
    LeetCode 134：加油站

    判断能否绕环路行驶一周

    贪心策略：
    1. 如果总油量 < 总消耗，肯定不行
    2. 从某个起点开始，如果到不了下一站，说明起点到当前点之间的任何点都不行
    """
    if sum(gas) < sum(cost):
        return -1

    start = 0
    tank = 0

    for i in range(len(gas)):
        tank += gas[i] - cost[i]

        if tank < 0:
            # 从 start 到 i 都不可行
            start = i + 1
            tank = 0

    return start


# 示例
gas = [1, 2, 3, 4, 5]
cost = [3, 4, 5, 1, 2]
print(canCompleteCircuit(gas, cost))  # 3

    复杂度：O(n) 时间，O(1) 空间。关键贪心结论：若从 start 出发到 i 时油量首次变负，则 [start, i] 中任意一点当起点都会在 i 处变负，所以起点直接跳到 i + 1。

    6.5 单调递增的数字（LeetCode 738）¶

    def monotoneIncreasingDigits(n: int) -> int:
    """
    LeetCode 738：单调递增的数字

    找到小于等于 n 的最大单调递增数字

    贪心策略：
    从左到右找到第一个下降的位置，将该位减 1，后面全变为 9
    """
    s = list(str(n))
    n_len = len(s)

    # 找到第一个下降的位置
    marker = n_len
    for i in range(n_len - 1, 0, -1):
        if s[i] < s[i - 1]:
            marker = i
            s[i - 1] = str(int(s[i - 1]) - 1)

    # marker 之后全变为 9
    for i in range(marker, n_len):
        s[i] = '9'

    return int(''.join(s))


# 示例
n = 332
print(monotoneIncreasingDigits(n))  # 299

    为什么倒序扫描：如 332，个位 2 < 3 先把十位减 1 得 322，接着 2 < 3 还要把百位减 1 得 222，最后 marker 之后全置 9 得 299。从右往左扫可以一次性处理连续借位。

    6.6 摆动序列（LeetCode 376）¶

    def wiggleMaxLength(nums: List[int]) -> int:
    """
    LeetCode 376：摆动序列

    求最长摆动子序列的长度

    贪心策略：
    只统计峰值（局部最大/最小）
    """
    if len(nums) < 2:
        return len(nums)

    up = down = 1

    for i in range(1, len(nums)):
        if nums[i] > nums[i - 1]:
            up = down + 1
        elif nums[i] < nums[i - 1]:
            down = up + 1

    return max(up, down)


# 示例
nums = [1, 7, 4, 9, 2, 5]
print(wiggleMaxLength(nums))  # 6 ([1, 7, 4, 9, 2, 5])

    贪心直觉：单调坡上只保留坡底和坡顶，中间的点留着不会让摆动次数变多。注意 nums[i] == nums[i-1] 时两个状态都不更新——相等不构成摆动。

    7. 贪心证明技巧¶

    7.1 知识点¶

    面试中被追问"为什么你的贪心策略是对的"时，要能给出论证。常用三板斧： - 交换论证：假设存在比贪心解更优的解，通过逐步"交换/替换"把它改造成贪心解且不损失目标值，导出矛盾 - 归纳法：证明做出第一次贪心选择后，剩余子问题仍保持相同结构与最优子结构 - 暴力对拍：写暴力解在小数据上验证贪心结果，找反例最快

    判断流程（拿不准能不能用贪心时照此执行）：

    如何判断能否用贪心？

1. 尝试证明贪心策略的正确性
2. 如果无法证明，可能需要 DP
3. 可以写暴力解验证贪心结果

    7.2 交换论证¶

    思想：假设存在更优解，通过交换操作导出矛盾。

    示例：活动选择问题

问题：选择最多的互不重叠的活动

贪心策略：按结束时间排序，优先选结束早的

证明：
1. 假设贪心解不是最优，存在更优解 O
2. 设贪心解为 G，第一个不同的活动为 a_i 和 o_i
3. 由于贪心选结束最早的，所以 a_i.end <= o_i.end
4. 用 a_i 替换 o_i，仍然可行且活动数不变
5. 逐步替换，可将 O 转换为 G
6. 因此 G 也是最优解

    这也回答了 3.4 的排序维度问题：活动选择/无重叠区间必须按结束时间排序，"结束早"正是交换论证中能被安全替换的性质来源。

    7.3 归纳法¶

    思想：证明贪心选择后，剩余子问题仍保持最优结构。

    即证两件事：① 第一步贪心选择一定包含在某个最优解中；② 做出该选择后，剩下的问题与原问题同构且最优子结构不变。对第一步归纳，即可推出整个贪心过程最优。

    9. 本章小结¶

    核心知识点¶

    ✅ 贪心思想：每步选局部最优且不回退，期望推出全局最优
    ✅ 适用前提：贪心选择性质 + 最优子结构，正确性必须证明
    ✅ 反例警钟：0/1 背包、特定面额硬币找零，贪心得不到最优，须用 DP
    ✅ 排序 + 贪心：最基础模式，分配饼干、分发糖果（双向扫描取 max）
    ✅ 区间问题：求最多不重叠按右端点排，合并区间按左端点排；合并时右端点取 max
    ✅ 跳跃游戏：维护最远可达边界，O(n) 一遍扫完
    ✅ 贪心 + 堆：Top K 用大小为 k 的小顶堆守门；霍夫曼每次合并最小两项
    ✅ 双指针贪心：盛水容器移动短板，每步排除一批不可能更优的组合
    ✅ 贪心证明：交换论证、归纳法、暴力对拍

    最佳实践¶

    1. 先证明再写码：动手前用交换论证或归纳法过一遍贪心策略，证不出来就换 DP
    2. 区间题先定排序维度："选最多看右端点，做合并看左端点"，写反即错
    3. Top K 选对堆：求最大的 k 个用小顶堆、求最小的 k 个用大顶堆，并严格限制堆大小为 k
    4. 双向约束拆两遍：一个方向管不住的约束（如分发糖果），左右各扫一遍再合并
    5. 拿不准就对拍：写暴力解在小规模数据上验证贪心输出，反例一找一个准

    贪心常见模式¶

    模式 代表题
    排序后贪心 分配饼干、无重叠区间
    双指针贪心 盛水容器、两数之和
    堆贪心 Top K、霍夫曼编码
    区间贪心 合并区间、跳跃游戏
