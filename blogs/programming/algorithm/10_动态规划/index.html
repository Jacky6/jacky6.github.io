    10_动态规划（Dynamic Programming）¶

    本章知识点清单¶

    # 知识点 一句话结论 重要度
    1 DP 核心思想 大事化小 + 记住算过的结果，每个子问题只算一次 ⭐⭐⭐⭐
    2 DP 五步骤 状态定义 → 转移方程 → 初始化 → 遍历顺序 → 举例推导，套模板不靠灵感 ⭐⭐⭐⭐⭐
    3 三大适用条件 最优子结构 + 重叠子问题 + 无后效性，缺一就不是 DP 的菜 ⭐⭐⭐
    4 基础线性 DP 爬楼梯/斐波那契/打家劫舍，一维递推 + 滚动变量空间优化 ⭐⭐⭐⭐
    5 路径 DP 最小路径和/不同路径，第一行第一列单独初始化是高频坑 ⭐⭐⭐
    6 0-1 背包 每件物品选或不选，一维优化必须倒序遍历容量 ⭐⭐⭐⭐⭐

    11 区间 DP 按区间长度从小到大枚举，戳气球用"最后一个处理"的逆向思维 ⭐⭐⭐

    1. 动态规划概述¶

    1.1 知识点¶

    动态规划（Dynamic Programming，DP）是一种将复杂问题分解为更小子问题的优化方法。它与分治的区别在于：DP 的子问题会重复出现，所以把算过的结果存起来，下次遇到直接查表，避免重复计算。理解 DP 记住三个关键词： - 分治思想：大问题 → 小问题，小问题的答案拼出大问题的答案 - 记忆化：保存已计算的结果，用空间换时间，把指数级暴力降为多项式级 - 状态转移：从小问题推导大问题，用一个递推式（转移方程）描述这种推导关系

    DP 有两种实现方向：自顶向下的记忆化搜索（递归 + 缓存）和自底向上的递推（循环填表），两者写出的递推式完全相同，面试中通常先讲清递推式再任选其一实现。

    与贪心对比：贪心每一步只挑局部最优、不回头；DP 会枚举每个子问题的所有可能再取最优。贪心是 DP 的特例（转移方程退化成只取一个分支）。与分治对比：分治的子问题互不重叠（如归并排序），DP 的子问题大量重叠——这正是需要"记忆"的原因。

    1.2 适用场景¶

    能用 DP 的问题必须同时满足三个条件，这也是面试"这题为什么能用 DP"的标准答案：

    ✅ 最优子结构：大问题的最优解包含子问题的最优解（能从子问题的最优解推出大问题的最优解）
    ✅ 重叠子问题：子问题会被重复计算（否则直接分治即可，不需要记忆）
    ✅ 无后效性：未来与过去无关，只与现在有关——当前状态一旦确定，之后的推导只依赖当前状态，与"怎么走到这个状态"的路径无关

    三条件是快速判定"能不能 DP"的清单：三条都满足才动手。如果最优子结构不成立（子问题互相冲突），通常要换贪心或搜索；如果无后效性不成立，需要重新设计状态（把缺失的信息塞进状态定义里）。

    1.3 递归 vs 记忆化 vs 动态规划¶

    动态规划 vs 递归 vs 分治

递归：自顶向下，可能有重复计算
    f(5)
   /    \
 f(4)   f(3)
 /  \   /  \
f(3) f(2) ...  ← f(3) 重复计算！

动态规划：自底向上或记忆化，无重复
    f(5)
      ↑
    f(4)
      ↑
    f(3) ← 只计算一次
      ↑
    f(2)

    以斐波那契为例，朴素递归的时间复杂度是 O(2ⁿ)；加记忆化（每个 f(i) 只算一次）或改自底向上递推后降为 O(n)——这就是 DP 的价值。

    1.4 ⚠️ 易错点：不是所有"递推"都是 DP，也不是所有问题都能 DP¶

    ❌ 常见误区一：以为写了 dp[i] = ... 就是动态规划。如果状态之间没有最优子结构（比如子问题的解不能合并出大问题的最优解），那只是普通递推，DP 的最优性保证并不成立。

    ❌ 常见误区二：子问题不重叠也硬上 DP。比如归并排序的左右两半互不相干，直接分治递归即可，加 dp 表纯属浪费内存。

    ✅ 判定口诀：能拆（最优子结构）+ 重复算（重叠子问题）+ 不回头（无后效性），三条齐了才用 DP。

    2. DP 解题五步骤 ⭐⭐⭐（本章灵魂）¶

    2.1 知识点¶

    所有 DP 题都可以套同一套五步流程，这是本章最重要的方法论——DP 题做不出来，99% 是五步中的某一步没做对，而不是缺灵感：

    步骤 1：定义状态（dp 数组的含义）
步骤 2：确定状态转移方程
步骤 3：初始化边界条件
步骤 4：确定遍历顺序
步骤 5：举例推导 dp 数组
    • 步骤 1 是一切的根基：dp[i] 或 dp[i][j] 到底表示什么？下标含义、值的含义、最终答案是哪个 dp 值，必须用一句完整的话写下来
    • 步骤 2 是 DP 的灵魂：从"最后一步决策"出发，把大问题拆成若干已解决的子问题
    • 步骤 3 最容易被轻视：初始值不是凭直觉写的，而是从定义反推出来的（见 2.4 易错点）
    • 步骤 4 的原则只有一条：算 dp[i] 时，它所依赖的状态必须已经算好；背包类问题中遍历顺序还会改变答案的组合/排列语义（见第 4 节）
    • 步骤 5 是免费的调试器：手推一个小样例的 dp 表，写代码前先验证转移方程和初始化

    做题时把五步写在注释里再动手，比盯着屏幕空想快得多。

    2.2 示例：爬楼梯（五步骤完整走一遍）¶

    # 问题：每次可以爬 1 或 2 阶，爬到 n 阶有多少种方法？

# 步骤 1：定义状态
# dp[i] = 爬到第 i 阶的方法数

# 步骤 2：状态转移方程
# dp[i] = dp[i-1] + dp[i-2]
# 最后一步可以是爬 1 阶或 2 阶

# 步骤 3：初始化
# dp[0] = 1（地面）
# dp[1] = 1（1 阶）

# 步骤 4：遍历顺序
# 从前往后

# 步骤 5：推导
# dp[0]=1, dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5...

def climbStairs(n: int) -> int:
    if n <= 1:
        return 1

    dp = [0] * (n + 1)
    dp[0] = 1
    dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]


# 空间优化（只需要前两个状态）
def climbStairs_optimized(n: int) -> int:
    if n <= 1:
        return 1

    prev2, prev1 = 1, 1
    for i in range(2, n + 1):
        curr = prev1 + prev2
        prev2 = prev1
        prev1 = curr

    return prev1

    注意优化版的前提：转移方程只依赖前两个状态，所以可以用两个变量滚动代替整个数组，空间从 O(n) 降到 O(1)。依赖前 k 个状态的递推都可以这样压缩（打家劫舍、斐波那契同理）；依赖整行/整列的（如路径 DP）则压缩成一行滚动数组。

    2.3 ⚠️ 易错点：状态定义不清，转移方程必错¶

    这是 DP 第一大坑：没把 dp[i] 的含义写清楚就急着写转移，结果状态含义在推导中途被悄悄换掉，或者答案取错了位置。

    ❌ 反例：做"最长递增子序列"时把 dp[i] 定义成"前 i 个元素中的 LIS 长度"，写转移时又按"以 nums[i] 结尾"来推——两套含义混用，方程怎么写都不对。

    ✅ 正确姿势：动笔先写一句话定义，包含三要素——下标含义、值的含义、答案在哪个位置：

    # ❌ 模糊定义："dp[i] 是第 i 个位置的最优解"
#    —— 什么最优解？含不含 nums[i]？答案是不是 dp[-1]？全都没说

# ✅ 明确定义（以 LIS 为例）：
# dp[i] = 以 nums[i] 【结尾】的 LIS 长度
#   - 必须选 nums[i]（"结尾"二字的约束）
#   - 答案是 max(dp)，而不是 dp[-1]（LIS 不一定以最后一个元素结尾）

    经验法则：转移方程推不动时，回头重新定义状态，而不是硬凑方程。"以 i 结尾 / 前 i 个 / 区间 [i, j]"这三种定义方式覆盖绝大多数题目，定义选错了后面全错。

    2.4 ⚠️ 易错点：初始化错误——递推起点写错，满盘皆错¶

    DP 第二大坑。初始值不是凭直觉填的，而是从 dp 定义反推出来的：把边界下标代入定义，它应该等于什么？

    坑一：边界值凭直觉写

    # 爬楼梯，❌ 想当然把起点初始化为 0
dp[0] = 0   # "第 0 阶不存在，所以是 0"——错！
dp[1] = 1
# 后果：dp[2] = dp[1] + dp[0] = 1，而正确答案是 2，之后全错

# ✅ 从定义反推：dp[0] = "爬到第 0 阶（地面）的方法数"
#    站在地面不动就是 1 种方法（什么都不做也是一种方案）
dp[0] = 1
dp[1] = 1

    坑二："空方案"类初始值漏设

    # 零钱兑换：dp[j] = 凑成金额 j 的最少硬币数
# ❌ 忘记初始化 dp[0]，默认全是 0，min 转移永远取不到 +1 的分支
dp = [0] * (amount + 1)

# ✅ 凑成金额 0 需要 0 枚硬币（"一枚都不选"是合法方案），这是递推起点
INF = float('inf')
dp = [INF] * (amount + 1)
dp[0] = 0

    坑三：打家劫舍的 dp[1] 初始化

    # 打家劫舍：dp[1] 表示"只考虑前两家"的最大金额
# ❌ 写成 dp[1] = nums[1]：如果第一家金额更大就错了，且没考虑 len(nums) == 1 时越界
dp[1] = nums[1]

# ✅ 前两家只能偷一家，取较大者；同时必须先处理数组长度不足 2 的边界
dp[1] = max(nums[0], nums[1])

    自查方法：写完初始化后，把边界下标代入 dp 定义，问自己"这个值按定义应该等于几"；再手动推两三个状态，看是否和预期一致。

    3. 基础 DP 问题¶

    3.1 知识点¶

    线性 DP 是最简单的 DP 形态：状态沿一个方向递推，dp[i] 只依赖前面少数几个状态。掌握三个基本型： - 递推求和型（斐波那契、爬楼梯）：dp[i] = f(dp[i-1], dp[i-2])，可滚动变量压缩到 O(1) - 二维路径型（最小路径和、不同路径）：dp[i][j] 依赖左边和上边，第一行第一列要单独初始化，可压缩成一行滚动数组 - 选或不选型（打家劫舍）：每个元素面临"选/不选"的二选一决策，dp[i] = max(dp[i-1], dp[i-2] + nums[i])

    这三类是所有复杂 DP 的地基，面试中 DP 手写题大多从这里出题。

    3.2 斐波那契数列¶

    def fib(n: int) -> int:
    """
    LeetCode 509：斐波那契数列

    F(0) = 0, F(1) = 1
    F(n) = F(n-1) + F(n-2)
    """
    if n <= 1:
        return n

    dp = [0] * (n + 1)
    dp[0] = 0
    dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]


# 空间优化版
def fib_optimized(n: int) -> int:
    if n <= 1:
        return n

    prev2, prev1 = 0, 1
    for _ in range(2, n + 1):
        curr = prev1 + prev2
        prev2 = prev1
        prev1 = curr

    return prev1

    3.3 最小路径和¶

    def minPathSum(grid: List[List[int]]) -> int:
    """
    LeetCode 64：最小路径和

    从左上到右下，每次只能向下或向右
    求路径上数字和的最小值
    """
    m, n = len(grid), len(grid[0])

    # dp[i][j] = 到达 (i,j) 的最小路径和
    dp = [[0] * n for _ in range(m)]

    # 初始化
    dp[0][0] = grid[0][0]

    # 第一行（只能从左边来）
    for j in range(1, n):
        dp[0][j] = dp[0][j - 1] + grid[0][j]

    # 第一列（只能从上面来）
    for i in range(1, m):
        dp[i][0] = dp[i - 1][0] + grid[i][0]

    # 填充其余位置
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + grid[i][j]

    return dp[m - 1][n - 1]


# 空间优化（只需要一行）
def minPathSum_optimized(grid: List[List[int]]) -> int:
    m, n = len(grid), len(grid[0])
    dp = [0] * n

    dp[0] = grid[0][0]
    for j in range(1, n):
        dp[j] = dp[j - 1] + grid[0][j]

    for i in range(1, m):
        dp[0] += grid[i][0]
        for j in range(1, n):
            dp[j] = min(dp[j], dp[j - 1]) + grid[i][j]

    return dp[n - 1]

    3.4 不同路径¶

    def uniquePaths(m: int, n: int) -> int:
    """
    LeetCode 62：不同路径

    从左上到右下，每次只能向下或向右
    求有多少种不同路径
    """
    # dp[i][j] = 到达 (i,j) 的路径数
    dp = [[1] * n for _ in range(m)]

    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i - 1][j] + dp[i][j - 1]

    return dp[m - 1][n - 1]


# 空间优化
def uniquePaths_optimized(m: int, n: int) -> int:
    dp = [1] * n

    for _ in range(1, m):
        for j in range(1, n):
            dp[j] += dp[j - 1]

    return dp[n - 1]

    3.5 ⚠️ 易错点：二维 DP 的第一行第一列没单独初始化¶

    路径类二维 DP 的高频坑：dp[i][j] = dp[i-1][j] + dp[i][j-1] 这个转移方程只在 i>0 且 j>0 时成立。第一行只能从左边来、第一列只能从上面来，必须单独填。

    # ❌ 直接用通式填全表：dp[0][j] 会引用 dp[-1][j]
#    Python 里 dp[-1] 是最后一行，不报错但答案全错（最隐蔽的一类 bug）
for i in range(m):
    for j in range(1, n):
        dp[i][j] = dp[i - 1][j] + dp[i][j - 1]   # i=0 时 dp[-1][j] 越界回绕

# ✅ 先单独初始化第一行、第一列，再从 (1,1) 开始填
for j in range(1, n):
    dp[0][j] = dp[0][j - 1] + grid[0][j]   # 第一行：只能从左边来
for i in range(1, m):
    dp[i][0] = dp[i - 1][0] + grid[i][0]   # 第一列：只能从上面来
for i in range(1, m):
    for j in range(1, n):
        dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + grid[i][j]

    为什么"不同路径"看起来没这个问题？因为它把整个 dp 表直接初始化为 1（[[1] * n for _ in range(m)]），第一行第一列恰好就该是 1——这是把初始化藏进了建表里，不是不需要初始化。换成带障碍物的版本（LeetCode 63），第一行第一列遇到障碍后全得置 0，就又必须显式处理了。

    4. 背包问题 ⭐⭐⭐¶

    4.1 知识点¶

    背包问题是 DP 里最经典的一族模型：给一组物品（各有重量/价值）和一个容量有限的背包，求在不超过容量前提下的最优选择方案。面试中几乎所有"从集合里选元素凑目标"的题都能归约成背包： - 0-1 背包：每件物品最多选 1 次（选或不选） - 完全背包：每件物品可以选无限次 - 多重背包：每件物品最多选 k 次

    三种背包共用同一个二维状态定义：dp[i][j] = 前 i 个物品、容量为 j 时的最优值。区别全在转移方式上；压缩成一维数组后，区别进一步浓缩为遍历容量的方向——这是本章最需要记牢的结论（见 4.6 易错点）。

    4.2 0-1 背包¶

    def knapsack_01(weights: List[int], values: List[int], capacity: int) -> int:
    """
    0-1 背包问题

    n 个物品，每个重量 weight[i]，价值 value[i]
    背包容量 capacity，求最大价值
    每个物品只能选 0 次或 1 次

    dp[i][j] = 前 i 个物品，容量为 j 时的最大价值
    """
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(capacity + 1):
            # 不选第 i 个物品
            dp[i][j] = dp[i - 1][j]

            # 选第 i 个物品（如果容量够）
            if j >= weights[i - 1]:
                dp[i][j] = max(dp[i][j], 
                              dp[i - 1][j - weights[i - 1]] + values[i - 1])

    return dp[n][capacity]


# 空间优化（一维数组，倒序遍历）
def knapsack_01_optimized(weights: List[int], values: List[int], capacity: int) -> int:
    n = len(weights)
    dp = [0] * (capacity + 1)

    for i in range(n):
        # 倒序遍历（避免重复使用同一物品）
        for j in range(capacity, weights[i] - 1, -1):
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])

    return dp[capacity]


# 示例
weights = [2, 3, 4, 5]
values = [3, 4, 5, 6]
capacity = 8
print(knapsack_01(weights, values, capacity))  # 10

    0-1 背包关键点：
- 倒序遍历容量：保证每个物品只用一次
- 状态转移：dp[j] = max(dp[j], dp[j-w] + v)

    为什么一维版本必须倒序？二维版里 dp[i][j] 依赖的是上一行 dp[i-1][...]；压成一维后，dp[j - weights[i]] 必须还是"没考虑过物品 i"时的旧值。倒序遍历容量，算 dp[j] 时比它小的 dp[j-w] 还没被本轮更新，正好是上一轮的值；如果正序，dp[j-w] 已经在本轮被更新过（可能已经装过物品 i），同一件物品就被重复装了。

    4.3 完全背包¶

    def knapsack_complete(weights: List[int], values: List[int], capacity: int) -> int:
    """
    完全背包问题

    每个物品可以选无限次

    关键：正序遍历容量（允许重复使用）
    """
    n = len(weights)
    dp = [0] * (capacity + 1)

    for i in range(n):
        # 正序遍历（可以重复使用）
        for j in range(weights[i], capacity + 1):
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])

    return dp[capacity]


# 示例（零钱兑换问题）
def coinChange(coins: List[int], amount: int) -> int:
    """
    LeetCode 322：零钱兑换

    完全背包应用
    求凑成金额的最少硬币数
    """
    INF = float('inf')
    dp = [INF] * (amount + 1)
    dp[0] = 0

    for coin in coins:
        for j in range(coin, amount + 1):
            dp[j] = min(dp[j], dp[j - coin] + 1)

    return dp[amount] if dp[amount] != INF else -1


# 示例
coins = [1, 2, 5]
amount = 11
print(coinChange(coins, amount))  # 3 (5+5+1)

    完全背包与 0-1 背包的代码只差遍历方向：正序遍历容量时，算 dp[j] 用到的 dp[j - weights[i]] 是本轮刚更新过的值——它可能已经装过物品 i，恰好实现"无限次取用"。零钱兑换是完全背包的求方案数/最值变体：状态含义换成"最少硬币数"，max 换成 min，初始化 dp[0]=0、其余为无穷大。

    4.4 多重背包¶

    多重背包：第 i 件物品最多选 counts[i] 次，是 0-1 与完全背包的折中形态。面试出现频率低于前两者，但"限定每种元素使用次数"的应用题（如限定字符个数拼字符串）本质都是它。

    朴素解法：在 0-1 背包的转移上多套一层"选几个"的枚举 k（0 ≤ k ≤ counts[i] 且 k·w ≤ j）。时间复杂度 O(n · capacity · maxCount)。工程上常用二进制拆分把"选 k 次"拆成 O(log k) 个 0-1 背包物品，把复杂度降为 O(n · capacity · log maxCount)。

    def knapsack_multiple(weights: List[int], values: List[int],
                      counts: List[int], capacity: int) -> int:
    """
    多重背包问题

    第 i 件物品最多选 counts[i] 次

    dp[j] = 容量为 j 时的最大价值
    转移时枚举第 i 件物品选 k 个（0 <= k <= counts[i] 且 k*w <= j）
    """
    n = len(weights)
    dp = [0] * (capacity + 1)

    for i in range(n):
        # 一维优化必须倒序（同 0-1 背包，保证物品 i 的状态基于上一轮）
        for j in range(capacity, weights[i] - 1, -1):
            # 枚举选 k 个物品 i
            for k in range(1, counts[i] + 1):
                if k * weights[i] > j:
                    break
                dp[j] = max(dp[j], dp[j - k * weights[i]] + k * values[i])

    return dp[capacity]


# 二进制拆分优化：把 counts[i] 件物品拆成 1, 2, 4, ..., 余数 组"新物品"，
# 转化为 0-1 背包。例如 counts=13 拆成 1,2,4,6 四件，任意 0~13 的数量都能拼出
def knapsack_multiple_binary(weights: List[int], values: List[int],
                             counts: List[int], capacity: int) -> int:
    # 第一步：二进制拆分
    new_w, new_v = [], []
    for w, v, c in zip(weights, values, counts):
        k = 1
        while c > 0:
            take = min(k, c)
            new_w.append(w * take)
            new_v.append(v * take)
            c -= take
            k *= 2

    # 第二步：对拆出来的物品做 0-1 背包
    dp = [0] * (capacity + 1)
    for w, v in zip(new_w, new_v):
        for j in range(capacity, w - 1, -1):
            dp[j] = max(dp[j], dp[j - w] + v)

    return dp[capacity]

    4.5 遍历顺序：组合数 vs 排列数¶

    def combinationSum4(nums: List[int], target: int) -> int:
    """
    LeetCode 377：组合总和 IV

    求排列数（考虑顺序）

    关键：外层遍历容量，内层遍历物品
    """
    dp = [0] * (target + 1)
    dp[0] = 1

    # 外层容量，内层物品 → 排列数
    for j in range(1, target + 1):
        for num in nums:
            if j >= num:
                dp[j] += dp[j - num]

    return dp[target]


# 对比：求组合数（不考虑顺序）
# 外层物品，内层容量 → 组合数

    为什么循环顺序会改变答案的语义？以 nums=[1,2]、target=3 为例： - 外层物品、内层容量：物品 1 处理完才处理物品 2，方案里物品出现的"种类顺序"被固定为 [1,2]，(1,2) 和 (2,1) 只算一次 → 组合数 = 2（{1,1,1}、{1,2}） - 外层容量、内层物品：每个容量 j 都重新考虑所有物品作为"最后一步"，(1,2) 和 (2,1) 被当成不同的最后一步分别计数 → 排列数 = 3（1+1+1、1+2、2+1）

    记忆口诀：先物后容是组合，先容后物是排列。这个规则对求方案数（+）和最值（max/min）都成立，但最值问题两种顺序结果相同，只有计数问题会暴露差异。

    4.6 ⚠️ 易错点：背包遍历顺序写反，0-1 变完全、组合变排列¶

    背包问题的三大顺序坑，每一个都会让答案"看起来能跑但就是错的"：

    坑一：0-1 背包一维版正序遍历容量 → 物品被重复使用

    # ❌ 0-1 背包用正序：dp[j-w] 是本轮已更新值，同一物品被反复装
for j in range(weights[i], capacity + 1):
    dp[j] = max(dp[j], dp[j - weights[i]] + values[i])
# 实际效果：退化成了完全背包，每件物品无限用

# ✅ 倒序遍历，保证 dp[j-w] 还是"没考虑物品 i"的上一轮状态
for j in range(capacity, weights[i] - 1, -1):
    dp[j] = max(dp[j], dp[j - weights[i]] + values[i])

    坑二：完全背包倒序遍历 → 每件物品只能用一次

    # ❌ 完全背包用倒序：等价于 0-1 背包，"无限次"失效
for j in range(capacity, weights[i] - 1, -1):
    dp[j] = max(dp[j], dp[j - weights[i]] + values[i])

# ✅ 正序遍历，让 dp[j-w] 引用本轮更新值，实现重复取用
for j in range(weights[i], capacity + 1):
    dp[j] = max(dp[j], dp[j - weights[i]] + values[i])

    坑三：求排列数却用了"先物品后容量"→ 少算顺序

    # LeetCode 377 组合总和 IV 求的是排列数
# ❌ 外层物品：nums=[1,2], target=3 时只会算出组合数 2
for num in nums:
    for j in range(num, target + 1):
        dp[j] += dp[j - num]

# ✅ 外层容量、内层物品：(1,2) 与 (2,1) 各算一次，答案为 3
for j in range(1, target + 1):
    for num in nums:
        if j >= num:
            dp[j] += dp[j - num]

    三种背包一维写法的速记表：

    背包类型 容量遍历方向 内外层（计数时）
    0-1 背包 倒序 外层物品
    完全背包 正序 组合：外层物品；排列：外层容量
    多重背包 倒序 + 内层枚举个数 外层物品

    5. 子序列问题 ⭐⭐⭐¶

    5.1 知识点¶

    子序列问题（可以不连续，但保持相对顺序）是线性 DP 的另一大类。两个高频状态定义技巧： - "以 i 结尾"型（LIS）：dp[i] 表示必须选 nums[i] 时的最优解。好处是转移有明确锚点；代价是答案要取 max(dp) 而不是 dp[-1] - "前 i 个"型 / 双串型（LCS、编辑距离）：dp[i][j] 表示 text1 前 i 个字符和 text2 前 j 个字符的答案，下标天然对齐空串边界（i=0 或 j=0 表示空串），初始化最不容易出错

    区间型的回文子序列则是"区间 [i, j]"定义，遍历方向与常规相反（从下往上填表），见 5.4。

    5.2 最长递增子序列（LIS）¶

    def lengthOfLIS(nums: List[int]) -> int:
    """
    LeetCode 300：最长递增子序列

    dp[i] = 以 nums[i] 结尾的最长递增子序列长度
    """
    if not nums:
        return 0

    n = len(nums)
    dp = [1] * n

    for i in range(1, n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)

    return max(dp)


# 贪心 + 二分优化 O(n log n)
def lengthOfLIS_optimized(nums: List[int]) -> int:
    tails = []

    for num in nums:
        # 二分查找第一个 >= num 的位置
        left, right = 0, len(tails)
        while left < right:
            mid = (left + right) // 2
            if tails[mid] < num:
                left = mid + 1
            else:
                right = mid

        if left == len(tails):
            tails.append(num)
        else:
            tails[left] = num

    return len(tails)


# 示例
nums = [10, 9, 2, 5, 3, 7, 101, 18]
print(lengthOfLIS(nums))  # 4 ([2, 3, 7, 18])

    复杂度：DP 解法 O(n²)；贪心 + 二分解法 O(n log n)——tails[k] 维护"长度为 k+1 的递增子序列的最小结尾"，结尾越小越有利于后续扩展，这是贪心成立的原因。面试先写 O(n²) 保证正确，再主动提出二分优化加分。

    5.3 最长公共子序列（LCS）¶

    def longestCommonSubsequence(text1: str, text2: str) -> int:
    """
    LeetCode 1143：最长公共子序列

    dp[i][j] = text1[:i] 和 text2[:j] 的 LCS 长度
    """
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[m][n]


# 示例
text1 = "abcde"
text2 = "ace"
print(longestCommonSubsequence(text1, text2))  # 3 ("ace")

    LCS 的转移逻辑：两个末尾字符相等就一起选上（答案 +1，问题缩小到都去掉末尾）；不相等就分别舍弃其中一个，取较优者。第 0 行第 0 列全是 0，对应"空串与任何串的 LCS 为 0"——这正是"前 i 个"定义让初始化变简单的地方。

    5.4 最长回文子序列¶

    def longestPalindromeSubseq(s: str) -> int:
    """
    LeetCode 516：最长回文子序列

    dp[i][j] = s[i:j+1] 的最长回文子序列长度
    """
    n = len(s)
    dp = [[0] * n for _ in range(n)]

    # 单个字符都是回文
    for i in range(n):
        dp[i][i] = 1

    # 从下往上，从左往右
    for i in range(n - 2, -1, -1):
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])

    return dp[0][n - 1]


# 示例
s = "bbbab"
print(longestPalindromeSubseq(s))  # 4 ("bbbb")

    注意本题的遍历方向：dp[i][j] 依赖 dp[i+1][j-1]、dp[i+1][j]、dp[i][j-1]，即依赖下一行和本行左边，所以 i 必须从下往上（倒序）遍历——遍历顺序永远由状态依赖关系决定，这是五步骤中步骤 4 的直接体现。

    5.5 ⚠️ 易错点：LIS 答案取 max(dp) 而不是 dp[-1]¶

    "以 i 结尾"型状态的通病：最终答案不一定在最后一个位置。

    nums = [1, 3, 6, 7, 9, 4, 10, 5, 6]
# dp = [1, 2, 3, 4, 5, 3, 6, 4, 5]
# LIS 长度是 6（子序列 1,3,6,7,9,10），以 10 结尾

return dp[-1]    # ❌ 返回 5：以最后一个元素 6 结尾的 LIS 长度
return max(dp)   # ✅ 返回 6：遍历所有结尾位置取最大

    同类陷阱：最长公共子序列用"前 i 个"定义时答案是 dp[m][n]（右下角）；而回文子序列用"区间 [i,j]"定义时答案是 dp[0][n-1]（左上角）——答案的位置由状态定义决定，写代码前先想清楚。

    6. 区间 DP ⭐¶

    6.1 知识点¶

    区间 DP：状态定义在一个区间 [i, j] 上，通过枚举区间内的分割点 k 把大区间拆成两个小区间：dp[i][j] = 枚举k { dp[i][k] ⊕ dp[k+1][j] + 合并代价 }。

    两个固定套路： - 按区间长度从小到大枚举（外层 length，内层起点 i）：保证算大区间时所有子区间都已算好 - 时间复杂度 O(n³)：n² 个状态 × 每个状态枚举 O(n) 个分割点，n 通常 ≤ 500

    戳气球是区间 DP 的经典变形：正向思考"先戳哪个"会导致区间互相污染，逆向思考"最后戳哪个"，区间之间就独立了——遇到区间合并类问题想不通时，试试逆向定义"最后一个操作"。

    6.2 矩阵链乘法¶

    def matrixChainOrder(p: List[int]) -> int:
    """
    矩阵链乘法

    p = [30, 35, 15, 5, 10, 20, 25]
    表示矩阵：A1(30×35), A2(35×15), A3(15×5), A4(5×10), A5(10×20), A6(20×25)

    求最小标量乘法次数
    """
    n = len(p) - 1
    dp = [[0] * n for _ in range(n)]

    # length = 链长度
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = float('inf')

            for k in range(i, j):
                cost = dp[i][k] + dp[k + 1][j] + p[i] * p[k + 1] * p[j + 1]
                dp[i][j] = min(dp[i][j], cost)

    return dp[0][n - 1]

    dp[i][j] = 计算矩阵链 Ai..Aj 的最小乘法次数；枚举分割点 k 表示"最后一次乘法发生在 (Ai..Ak) × (Ak+1..Aj)"，合并代价为 p[i]·p[k+1]·p[j+1]（两个结果矩阵相乘的标量次数）。

    6.3 戳气球¶

    def maxCoins(nums: List[int]) -> int:
    """
    LeetCode 312：戳气球

    区间 DP
    """
    # 添加边界
    nums = [1] + nums + [1]
    n = len(nums)
    dp = [[0] * n for _ in range(n)]

    # 区间长度
    for length in range(2, n):
        for left in range(n - length):
            right = left + length

            # 枚举最后戳破的气球
            for k in range(left + 1, right):
                coins = nums[left] * nums[k] * nums[right]
                coins += dp[left][k] + dp[k][right]
                dp[left][right] = max(dp[left][right], coins)

    return dp[0][n - 1]

    关键设计：两端补虚拟气球 1，dp[left][right] 表示开区间 (left, right) 内所有气球戳完的最大收益；枚举 k 为"该区间内最后一个戳破的气球"，此时它的左右邻居恰好是边界气球 nums[left] 和 nums[right]，左右两个子区间互不干扰。

    7. 经典算法题¶

    7.1 打家劫舍¶

    def rob(nums: List[int]) -> int:
    """
    LeetCode 198：打家劫舍

    不能偷相邻的房屋，求最大金额
    """
    if not nums:
        return 0
    if len(nums) == 1:
        return nums[0]

    dp = [0] * len(nums)
    dp[0] = nums[0]
    dp[1] = max(nums[0], nums[1])

    for i in range(2, len(nums)):
        dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])

    return dp[-1]


# 空间优化
def rob_optimized(nums: List[int]) -> int:
    prev2, prev1 = 0, 0

    for num in nums:
        curr = max(prev1, prev2 + num)
        prev2 = prev1
        prev1 = curr

    return prev1

    "选或不选"决策的典范：dp[i-1] 是不偷第 i 家（维持前 i-1 家的最优），dp[i-2] + nums[i] 是偷第 i 家（则第 i-1 家必须跳过）。变体：环形房屋（LeetCode 213）拆成"偷第一家不偷最后一家"和"偷最后一家不偷第一家"两次线性求解；树形房屋（LeetCode 337）换成树形 DP。

    7.2 编辑距离¶

    def minDistance(word1: str, word2: str) -> int:
    """
    LeetCode 72：编辑距离

    可以将一个单词转换为另一个单词的操作：
    - 插入一个字符
    - 删除一个字符
    - 替换一个字符

    求最少操作数
    """
    m, n = len(word1), len(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    # 初始化
    for i in range(m + 1):
        dp[i][0] = i
    for j in range(n + 1):
        dp[0][j] = j

    # 状态转移
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if word1[i - 1] == word2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = min(
                    dp[i - 1][j] + 1,      # 删除
                    dp[i][j - 1] + 1,      # 插入
                    dp[i - 1][j - 1] + 1   # 替换
                )

    return dp[m][n]

    双串 DP 的巅峰题：dp[i][j] = word1 前 i 个字符变成 word2 前 j 个字符的最少操作数。三种操作对应三个转移方向——删除（i 减 1）、插入（j 减 1，等价于对 word1 删）、替换（i、j 各减 1）。初始化 dp[i][0]=i、dp[0][j]=j 表示"空串变 i 个字符需要 i 次插入"。它是拼写检查、git diff 的核心算法，面试必背。

    8. 本章小结¶

    核心知识点¶

    ✅ DP 核心思想：分治 + 记忆化 + 状态转移，子问题只算一次
    ✅ DP 五步骤：状态定义 → 转移方程 → 初始化 → 遍历顺序 → 举例推导
    ✅ 三大适用条件：最优子结构、重叠子问题、无后效性
    ✅ 基础线性 DP：爬楼梯、斐波那契、打家劫舍、路径问题
    ✅ 背包问题：0-1 背包（倒序）、完全背包（正序）、多重背包（枚举/二进制拆分）
    ✅ 遍历顺序语义：先物后容是组合，先容后物是排列
    ✅ 子序列 DP：LIS、LCS、最长回文子序列
    ✅ 区间 DP：按长度枚举 + 分割点，戳气球逆向思维
    ✅ 空间优化：滚动变量（O(1)）、滚动数组（一行）

    最佳实践¶

    1. 永远先写状态定义：一句话讲清"下标含义、值的含义、答案在哪"，定义不清就不要动手写转移方程
    2. 初始化从定义反推，不凭直觉：把边界下标代入定义验证；写代码前先手推一个小样例的 dp 表
    3. 遍历顺序看依赖关系：依赖谁，谁就必须先算；背包一维写法记住"0-1 倒序、完全正序；组合先物品、排列先容量"
    4. 空间优化放在最后做：先写出正确的二维/完整版本，确认依赖范围（前一行/前两格）后再压缩
    5. 遇到区间互相污染想逆向："最后一步操作"是戳气球类问题的破题钥匙

    DP 类型总结¶

    类型 特征 代表题
    线性 DP 一维/二维数组 爬楼梯、LIS
    背包 DP 容量限制 0-1 背包、零钱兑换
    区间 DP 枚举分割点 戳气球、矩阵链乘
    状压 DP 状态压缩 旅行商问题
    数位 DP 数字计数 第 k 个数
