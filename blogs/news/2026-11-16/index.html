    4.1【补遗】Termination Lag：Coding Agent 早已解出却迟迟不停¶

    • 提交：2026-11-11 | arXiv:2611.14960
    • 跨 5 个模型 × 2 个 agent 框架 × 3 个 SWE-bench 数据集刻画「终止滞后」：38~82% 的成功运行在首次代码编辑时就已得到正确补丁，但之后仍消耗中位数 35~60% 的步数用于验证与探索，且 1~8% 会把正确补丁改错。
    • 关注：直接量化 coding agent 的「过度运行」成本与自我破坏风险，对停止条件与成本优化有实操指导意义。

    4.2【补遗】生产排障实证：瓶颈在「访问权」而非推理¶

    • 提交：2026-11-12 | arXiv:2611.17304
    • 对 Claude Code 诊断 8 起生产数据库事故的实地观察：凡根因涉及运行时并发的事故，agent 都先给错误结论再撤回；瓶颈普遍在「生产状态访问权」（锁视图、完整死锁报告、只读执行）而非推理能力；提出「取证层」（安全查询 API + 死锁记录仪 + 生产重放沙箱）作为解法。
    • 关注：生产级 agent 失败归因从「推理不足」转向「访问不足」——工具/权限设计的启发性实证。
