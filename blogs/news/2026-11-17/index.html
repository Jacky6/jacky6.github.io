    • 日期：2026-11-16 | 来源：openai-agents-python Releases
    • 新增 Python 工具调用审批（可记住审批决定）、支持接入应用自有模型客户端（Responses/Chat Completions、LiteLLM、AnyLLM）、Session 内接入 Realtime 语音（WebSocket/WebRTC/SIP）、checkpoint 恢复保留 request/token 预算、Linux ARM64 wheel。
    • 关注：0.24 重构线最实质的一次更新——审批、模型中立、语音三大能力同发。

    1.2 LangChain 双文系统化「目标驱动 Agent」方法论¶

    • 日期：2026-11-16 | 来源：From tasks to goals · We rebuilt LangSmith around the agent
    • Harrison Chase《From tasks to goals》：从「派任务」转向「定目标」对架构的六点影响（agent 自选任务、工具调用不可预知、后台提问 inbox、反馈机制、触发器/停止规则、记忆复利）。LangSmith 重构为「以 agent 为核心对象」的平台：每个 agent 有全局唯一 record（ID/Owner/Type），打通 build/run/improve/govern 全生命周期，编码 agent 类型可接 GitHub 追踪 PR 与 token 成本，支持治理任何 OTLP 上报的第三方 agent。
    • 关注：agent 资产化治理成为平台竞争新焦点。

    4. 学术前沿¶

    「Mon, 16 Nov 2026」批次已上架（cs.AI 164 条 + cs.MA 10 条全量扫描）；入选 8 篇均为 2026-11-13 提交，逐篇核实 abs 页。

    4.1 多智能体「更强」叙事的系统性证伪¶

    • 提交：2026-11-13 | arXiv:2611.17610
    • 对 9 项实证研究、516 个多智能体配置做元分析：相对单次贪心的「优势」多源于样本数/算力混淆；与样本数或预算匹配的基线相比，多智能体系统平均准确率反而低 0.042，74% 可比对比中不超过基线；正收益需证据分区、外部验证或跨模型错误多样性。
    • 关注：争议性与引用潜力俱佳——多 agent 的收益必须扣掉算力账再谈（附 PACE 审稿清单与核算 CLI）。

    4.2 Soteria：形式化验证 + 运行时强制的安全 Agent（NeurIPS'26 Oral）¶

    • 提交：2026-11-13 | arXiv:2611.17880
    • 执行前对 agent 生成的结构化计划做形式化验证，执行中以已验证计划做运行时强制、不安全动作被阻断后提供恢复引导；任务成功率达最强基线 1.7 倍且零策略违规（作者含 Sharad Malik、Aarti Gupta）。

    4.3 ModHarness-RL：harness 成为可学习、随训练进化的程序¶

    • 提交：2026-11-13 | arXiv:2611.18533
    • 把 agentic RL 中固定的手写 harness 重写为可学习程序：交互记录为类型化 State 块，Compression 程序组装上下文、Steering 程序纠偏；候选程序从近期轨迹提出、执行验证后回放历史轨迹。1.5B~8B 模型多数设置超过固定 harness 基线。
    • 关注：harness 自动优化主线（HarnessFlow→DeCAF→Agency→MULTILOOP）进入「随训练进化」阶段。

    4.4 WebArena-Pro：头部 coding agent 直接对位的多模态 Web 基准¶

    • 提交：2026-11-13 | arXiv:2611.17955（NeurIPS 2026 E&D）
    • 300 任务、20 个自托管应用、首纳音视频观测；最强成绩 Codex+GPT 6.1 Sol 与 Claude Code+Opus 5.5 均 62.3%，OpenCode+Kimi 3.1 Pro 60.7%；最强通用配置（Gemini 3.1 Pro omni）仅 30.3%——coding harness 与通用配置的差距被量化。

    4.5 Aligning AI Teams：责任扩散是多智能体对齐失效主因¶

    • 提交：2026-11-13 | arXiv:2611.17820（含 Jascha Sohl-Dickstein）
    • 单智能体对齐训练迁移不到团队：互评、群聊协调等自然干预不可靠；「责任扩散」是主因；设置专职 safety lead agent + 协调者发布安全规范文档可恢复单体对齐水平——与 Trilemma、Helpful Agent Problem 同属多智能体安全实证线。

    4.6 CarryOn：学习型长程上下文管理¶

    • 提交：2026-11-13 | arXiv:2611.17808
    • 轻量上下文管理器：紧凑执行状态 + 可追溯源头的细粒度证据，学习型选择器替代总结/剪枝，上下文管理本身零额外 LLM 调用；AppWorld/OfficeBench/Tau2-Telecom 宏平均成功率 75.7%（+6.7pt），并提出成本敏感指标 NCS（每次成功成本）。

    4.7 Vision-as-a-Tool：把 MLLM 变成可调用视觉工具（Furu Wei 团队）¶

    • 提交：2026-11-13 | arXiv:2611.17797
    • VaaT 范式：纯文本 agent 可完全外包视觉推理，多模态 agent 可按需增强原生感知；落地为 VHarness（5 个原子动作），Image-to-HTML/SVG/3D 持续提升——与 thinking-with-images 路线形成对照。

    4.8 机制可解释性进入 Agent 失效分析：Web 元素幻觉案例¶

    • 提交：2026-11-13 | arXiv:2611.18514（Mor Geva、Ziyu Yao 等）
    • 对 Qwen2.5-7B web agent 的「元素幻觉」做机制分析：最后 prompt token 上的线性探针可在生成开始前预测幻觉（0.80 AUC），沿探针方向 steering 修正 85% 幻觉但误伤 7% 有效动作；探针对 prompt 格式高度敏感——对「可解释性解释 agent」的可行边界给出冷静结论。

    候补：When Should LLM Agents Forget?（记忆过滤误删关键事实的风险）；Do Verifier Judgments Survive Abstraction?（验证器可靠性）；TradeGauntlet（自主交易 agent 合规控制）。
