08_主从复制

复制原理、配置、读写分离、GTID、故障处理

1. 复制概述

1.1 什么是主从复制？

主从复制是 MySQL 将主库的数据变更同步到一个或多个从库的机制。

主从复制架构：
┌─────────────┐
│   Master    │  ← 处理写操作
│ 192.168.1.10│
│   :3306     │
└──────┬──────┘
       │ Binlog
       │
       ├──────────────┐
       ▼              ▼
┌─────────────┐ ┌─────────────┐
│   Slave1    │ │   Slave2    │  ← 处理读操作
│192.168.1.11 │ │192.168.1.12 │
│   :3306     │ │   :3306     │
└─────────────┘ └─────────────┘

1.2 复制用途

用途 说明
读写分离 主库写，从库读，分散负载
数据备份 从库作为热备
数据分析 在从库上进行分析，不影响主库
故障恢复 主库故障时切换从库
地理分布 异地部署，就近访问

1.3 复制原理

复制过程：
1. Master 将数据变更写入 Binlog
2. Slave 的 I/O 线程读取 Master 的 Binlog
3. Slave 将 Binlog 写入 Relay Log
4. Slave 的 SQL 线程读取 Relay Log
5. SQL 线程重放 SQL，更新数据

┌─────────────┐     Binlog     ┌─────────────┐
│   Master    │ ─────────────▶ │  Slave I/O  │
│             │                │   线程      │
└─────────────┘                └──────┬──────┘
                                      │
                                      │ Relay Log
                                      ▼
                               ┌─────────────┐
                               │  Slave SQL  │
                               │   线程      │
                               └──────┬──────┘
                                      │
                                      ▼
                               ┌─────────────┐
                               │ Slave Data  │
                               └─────────────┘

2. 配置主从复制

2.1 主库配置

# /etc/my.cnf - Master

[mysqld]
# 服务器 ID（必须唯一）
server-id = 1

# 开启 Binlog
log_bin = mysql-bin

# Binlog 格式（推荐 ROW）
binlog_format = ROW

# Binlog 过期时间
expire_logs_days = 7

# 最大 Binlog 大小
max_binlog_size = 100M

# 同步方式（1=最安全）
sync_binlog = 1

# 复制用户权限
# 需要 REPLICATION SLAVE 权限

2.2 创建复制用户

-- 在主库创建复制用户
CREATE USER 'repl'@'%' IDENTIFIED BY 'StrongPassword123!';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;

-- 查看主库状态
SHOW MASTER STATUS;
-- +------------------+----------+--------------+------------------+
-- | File             | Position | Binlog_Do_DB | Binlog_Ignore_DB |
-- +------------------+----------+--------------+------------------+
-- | mysql-bin.000001 |      154 |              |                  |
-- +------------------+----------+--------------+------------------+

2.3 从库配置

# /etc/my.cnf - Slave

[mysqld]
# 服务器 ID（必须唯一）
server-id = 2

# 开启 Relay Log
relay_log = mysql-relay-bin

# 只读（防止误写）
read_only = 1

# 超级用户也可写（用于特殊操作）
super_read_only = 1

# 跳过某些错误（谨慎使用）
# slave_skip_errors = 1062

2.4 配置复制

-- 在从库执行
CHANGE MASTER TO
    MASTER_HOST='192.168.1.10',
    MASTER_PORT=3306,
    MASTER_USER='repl',
    MASTER_PASSWORD='StrongPassword123!',
    MASTER_LOG_FILE='mysql-bin.000001',
    MASTER_LOG_POS=154;

-- 启动复制
START SLAVE;

-- 查看复制状态
SHOW SLAVE STATUS\G
-- *************************** 1. row ***************************
--              Slave_IO_State: Waiting for master to send event
--                 Master_Host: 192.168.1.10
--                 Master_User: repl
--                   Slave_IO_Running: Yes
--                  Slave_SQL_Running: Yes
--              Seconds_Behind_Master: 0

2.5 初始化从库数据

# 方式 1：mysqldump
# 主库备份
mysqldump -u root -p --all-databases --master-data=2 > backup.sql

# 从库恢复
mysql -u root -p < backup.sql

# 方式 2：物理备份（XtraBackup）
# 主库备份
xtrabackup --backup --target-dir=/backup/mysql

# 从库恢复
xtrabackup --copy-back --target-dir=/backup/mysql

3. 复制模式

3.1 异步复制（默认）

Master          Slave
  │               │
  │─ 写事务 ─────▶│
  │               │
  │─ 提交 ───────▶│
  │               │
  │ ◀─ 确认 ──────│
  │               │
  │               │─ 异步读取 Binlog
  │               │─ 异步应用

特点： - 主库不等待从库确认 - 性能最好 - 可能丢失数据（主库故障时）

3.2 半同步复制

# 主库配置
[mysqld]
plugin_load_add = 'semisync_master.so'
rpl_semi_sync_master_enabled = 1
rpl_semi_sync_master_timeout = 1000  # 1 秒超时

# 从库配置
[mysqld]
plugin_load_add = 'semisync_slave.so'
rpl_semi_sync_slave_enabled = 1

-- 查看半同步状态
SHOW STATUS LIKE 'Rpl_semi_sync%';

特点： - 至少一个从库确认后才返回 - 平衡性能和安全性 - 超时后降级为异步

3.3 全同步复制（MGR）

MySQL Group Replication (MGR)：
- 多主模式
- 自动故障转移
- 数据强一致
- 性能开销较大

4. GTID 复制

4.1 什么是 GTID？

GTID（Global Transaction Identifier）是全局事务标识符。

GTID 格式：
source_id:transaction_id
例如：abc12345-1234-1234-1234-123456789012:1-5

source_id: 服务器 UUID
transaction_id: 事务序号

4.2 GTID 优势

传统复制 GTID 复制
需要指定 binlog 文件+位置 只需指定 GTID
主从切换复杂 主从切换简单
容易出错 自动定位位置

4.3 配置 GTID

# 主库和从库都需要配置
[mysqld]
gtid_mode = ON
enforce_gtid_consistency = ON
log_slave_updates = ON

-- 配置 GTID 复制
CHANGE MASTER TO
    MASTER_HOST='192.168.1.10',
    MASTER_USER='repl',
    MASTER_PASSWORD='password',
    MASTER_AUTO_POSITION = 1;  -- 自动定位 GTID

START SLAVE;

5. 读写分离

5.1 应用层实现

# Python 示例
import mysql.connector
from mysql.connector import pooling

# 主库连接池（写）
master_pool = pooling.MySQLConnectionPool(
    pool_name="master",
    pool_size=5,
    host="192.168.1.10",
    user="app",
    password="password",
    database="shop"
)

# 从库连接池（读）
slave_pool = pooling.MySQLConnectionPool(
    pool_name="slave",
    pool_size=10,
    host="192.168.1.11",
    user="app",
    password="password",
    database="shop"
)

def get_master_conn():
    return master_pool.get_connection()

def get_slave_conn():
    return slave_pool.get_connection()

# 写操作使用主库
def create_user(username, email):
    conn = get_master_conn()
    cursor = conn.cursor()
    cursor.execute(
        "INSERT INTO users (username, email) VALUES (%s, %s)",
        (username, email)
    )
    conn.commit()
    cursor.close()
    conn.close()

# 读操作使用从库
def get_user(user_id):
    conn = get_slave_conn()
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
    result = cursor.fetchone()
    cursor.close()
    conn.close()
    return result

5.2 中间件实现

中间件 特点
MySQL Router Oracle 官方，轻量级
ProxySQL 功能强大，支持路由、缓存
MaxScale MariaDB 出品，功能丰富
Atlas 360 开源，已停止维护

5.3 复制延迟问题

问题：主库写入后，从库未及时同步

解决方案：
1. 关键业务读主库
2. 等待从库同步（sleep）
3. 使用 GTID 等待
4. 使用半同步复制

# 等待从库同步
def wait_for_slave_gtid(gtid):
    conn = get_slave_conn()
    cursor = conn.cursor()
    cursor.execute(
        "SELECT WAIT_UNTIL_SQL_THREAD_AFTER_GTIDS(%s, 10)",
        (gtid,)
    )
    cursor.close()
    conn.close()

6. 故障处理

6.1 复制错误

-- 查看错误
SHOW SLAVE STATUS\G
-- Last_Error: Duplicate entry '1' for key 'PRIMARY'

-- 跳过错误（谨慎使用）
STOP SLAVE;
SET GLOBAL sql_slave_skip_counter = 1;
START SLAVE;

-- 或指定 GTID 跳过
STOP SLAVE;
SET GLOBAL gtid_next = 'xxx:123';
BEGIN; COMMIT;
SET GLOBAL gtid_next = 'AUTOMATIC';
START SLAVE;

6.2 主从同步中断

-- 检查网络
PING master_host

-- 检查复制用户权限
SHOW GRANTS FOR 'repl'@'%';

-- 检查 binlog 是否存在
SHOW BINARY LOGS;

-- 重新配置复制
STOP SLAVE;
RESET SLAVE;
CHANGE MASTER TO ...;
START SLAVE;

6.3 主从数据不一致

# 使用 pt-table-checksum 检查
pt-table-checksum --host=master --user=check

# 使用 pt-table-sync 修复
pt-table-sync --sync-to-master --host=slave --user=sync

6.4 主库故障切换

-- 1. 选择新的主库（延迟最小的从库）
SHOW SLAVE STATUS\G

-- 2. 停止复制
STOP SLAVE;
RESET SLAVE ALL;

-- 3. 提升为主库
RESET MASTER;

-- 4. 修改其他从库配置
CHANGE MASTER TO MASTER_HOST='new_master' ...;
START SLAVE;

-- 启动复制

RESET SLAVE ALL;
