07_存储引擎

InnoDB、MyISAM、Memory 等存储引擎详解

1. 存储引擎概述

1.1 什么是存储引擎？

存储引擎是 MySQL 中负责数据存储和提取的组件，MySQL 采用插件式架构，支持多种存储引擎。

MySQL 架构：
┌─────────────────────────────────────┐
│           SQL 层（Server）            │
│   解析器 | 优化器 | 执行器 | 缓存    │
└─────────────────────────────────────┘
                    │
┌─────────────────────────────────────┐
│          存储引擎层（Engine）          │
│  ┌───────┐ ┌───────┐ ┌───────┐      │
│  │InnoDB │ │MyISAM │ │Memory │ ...  │
│  └───────┘ └───────┘ └───────┘      │
└─────────────────────────────────────┘

1.2 查看存储引擎

-- 查看所有存储引擎
SHOW ENGINES;

-- 查看默认存储引擎
SELECT @@default_storage_engine;

-- 查看表使用的存储引擎
SHOW TABLE STATUS LIKE 'table_name';

-- 或
SELECT table_name, engine 
FROM information_schema.tables 
WHERE table_schema = 'database_name';

1.3 设置存储引擎

-- 设置全局默认存储引擎
SET GLOBAL default_storage_engine = InnoDB;

-- 创建表时指定
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50)
) ENGINE=InnoDB;

-- 修改表存储引擎
ALTER TABLE users ENGINE=MyISAM;

2. InnoDB 引擎

2.1 特点

特性 说明
事务支持 ✅ 支持 ACID 事务
行级锁 ✅ 支持行级锁，高并发
外键 ✅ 支持外键约束
聚簇索引 ✅ 数据按主键存储
MVCC ✅ 支持多版本并发控制
崩溃恢复 ✅ 支持自动崩溃恢复
全文索引 ✅ 5.6+ 支持
适用场景 OLTP、高并发读写

2.2 物理存储结构

InnoDB 文件：
- ibdata1: 系统表空间（数据字典、undo log 等）
- ib_logfile0, ib_logfile1: redo log
- .ibd: 表空间文件（每表一个，innodb_file_per_table=1）

表空间结构：
┌─────────────────────────────────────┐
│            表空间（.ibd）             │
│  ┌─────┬─────┬─────┬─────┬─────┐    │
│  │Page │Page │Page │Page │Page │    │
│  │  1  │  2  │  3  │ ... │  N  │    │
│  └─────┴─────┴─────┴─────┴─────┘    │
│  Page 大小：默认 16KB                 │
└─────────────────────────────────────┘

2.3 关键配置

[mysqld]
# 存储引擎
default-storage-engine = InnoDB

# 缓冲池大小（重要！设置为物理内存的 50-80%）
innodb_buffer_pool_size = 4G

# 缓冲池实例数
innodb_buffer_pool_instances = 8

# 日志文件大小
innodb_log_file_size = 256M

# 日志文件数量
innodb_log_files_in_group = 2

# 刷新方式（1=最安全，0=最快）
innodb_flush_log_at_trx_commit = 1

# 每表一个表空间
innodb_file_per_table = 1

# 页大小
innodb_page_size = 16K

# 线程并发数
innodb_thread_concurrency = 0

# IO 能力（根据磁盘性能设置）
innodb_io_capacity = 200
innodb_io_capacity_max = 400

2.4 InnoDB 日志

redo log（重做日志）:
- 物理日志，记录"在某个数据页上做了什么修改"
- 循环写入，空间固定
- 崩溃恢复使用
- 保证持久性

undo log（回滚日志）:
- 逻辑日志，记录"相反的 SQL"
- 事务回滚和 MVCC 使用
- 保证原子性

3. MyISAM 引擎

3.1 特点

特性 说明
事务支持 ❌ 不支持
锁粒度 表锁
外键 ❌ 不支持
崩溃恢复 ❌ 不支持
全文索引 ✅ 支持
COUNT(*) ✅ 内部维护，快速
适用场景 读多写少、日志记录

3.2 物理存储结构

MyISAM 文件：
- .frm: 表结构定义
- .MYD: 数据文件（MYData）
- .MYI: 索引文件（MYIndex）

3.3 配置选项

[mysqld]
# 键缓存大小
key_buffer_size = 256M

# 并发插入
concurrent_insert = 2

# 延迟键写入
delay_key_write = 1

3.4 MyISAM vs InnoDB

特性 InnoDB MyISAM
事务 ✅ ❌
锁粒度 行锁 表锁
外键 ✅ ❌
崩溃恢复 ✅ ❌
COUNT(*) 全表扫描 内部维护
全文索引 ✅ (5.6+) ✅
存储空间 较大 较小
写入性能 高并发好 低并发好
读取性能 好 略好

4. Memory 引擎

4.1 特点

特性 说明
存储介质 内存
事务支持 ❌
锁粒度 表锁
索引类型 哈希（默认）或 B+Tree
适用场景 临时表、缓存表、会话数据

4.2 使用示例

-- 创建 Memory 表
CREATE TABLE temp_data (
    id INT,
    value VARCHAR(100),
    INDEX USING HASH (id)
) ENGINE=Memory;

-- 使用场景：临时数据、会话存储、缓存
CREATE TABLE user_sessions (
    session_id VARCHAR(64) PRIMARY KEY,
    user_id INT,
    data TEXT,
    expires_at TIMESTAMP,
    INDEX USING HASH (session_id)
) ENGINE=Memory;

4.3 注意事项

  • 表重启后数据丢失
  • 表大小受 memmax_heap_table_size 限制
  • 不支持 BLOB/TEXT 类型

5. 其他存储引擎

5.1 Archive

-- 归档引擎，只支持 INSERT 和 SELECT
CREATE TABLE logs_archive (
    id INT AUTO_INCREMENT,
    log_data TEXT,
    created_at TIMESTAMP
) ENGINE=Archive;

-- 特点：
-- - 高压缩比
-- - 只支持 INSERT 和 SELECT
-- - 不支持 UPDATE、DELETE、索引
-- - 适合日志归档

5.2 CSV

-- CSV 引擎，数据存储为 CSV 文件
CREATE TABLE csv_data (
    id INT,
    name VARCHAR(100)
) ENGINE=CSV;

-- 特点：
-- - 数据存储为 CSV 格式
-- - 可与外部程序交换数据
-- - 不支持索引

5.3 Blackhole

-- 黑洞引擎，接收但不存储数据
CREATE TABLE blackhole_table (
    id INT,
    data VARCHAR(100)
) ENGINE=Blackhole;

-- 特点：
-- - 写入的数据被丢弃
-- - 用于复制中继或审计
-- - SELECT 总是返回空

5.4 Federated

-- 联合引擎，访问远程 MySQL 表
CREATE TABLE federated_table (
    id INT,
    name VARCHAR(100)
) ENGINE=Federated
CONNECTION='mysql://user:pass@remote_host:3306/db/table';

-- 特点：
-- - 访问远程表
-- - 性能较差
-- - 已废弃，不推荐使用

6. 引擎选择指南

6.1 选择建议

场景 推荐引擎 理由
OLTP 应用 InnoDB 事务、行锁、高并发
读多写少 MyISAM 快速 COUNT、读取
临时数据 Memory 内存存储、快速
日志归档 Archive 高压缩、只追加
数据交换 CSV CSV 格式、易导入导出

6.2 迁移引擎

-- 方式 1：ALTER TABLE
ALTER TABLE table_name ENGINE=InnoDB;

-- 方式 2：创建新表 + 数据迁移
CREATE TABLE new_table LIKE old_table;
ALTER TABLE new_table ENGINE=InnoDB;
INSERT INTO new_table SELECT * FROM old_table;
RENAME TABLE old_table TO backup_table, new_table TO old_table;

-- 方式 3：mysqldump + 导入
mysqldump -u root -p database table_name > table.sql
# 编辑 SQL 文件，修改 ENGINE
mysql -u root -p database < table.sql

7. 引擎监控

7.1 InnoDB 状态

-- 查看 InnoDB 状态
SHOW ENGINE INNODB STATUS;

-- 查看缓冲池使用
SELECT 
    pool_id,
    SUM(data_read) AS data_read,
    SUM(data_written) AS data_written,
    SUM(pages_read) AS pages_read,
    SUM(pages_written) AS pages_written
FROM information_schema.innodb_buffer_pool_stats
GROUP BY pool_id;

-- 查看表空间
SELECT 
    table_name,
    engine,
    data_length,
    index_length,
    data_free
FROM information_schema.tables
WHERE engine = 'InnoDB';

7.2 性能指标

-- 查看 InnoDB 指标
SHOW STATUS LIKE 'Innodb_%';

-- 关键指标
-- Innodb_buffer_pool_read_requests: 逻辑读请求
-- Innodb_buffer_pool_reads: 物理读次数
-- Innodb_buffer_pool_wait_free: 等待空闲页次数
-- Innodb_row_lock_time: 行锁等待时间
-- Innodb_row_lock_waits: 行锁等待次数
