05_索引

索引原理、B+Tree、索引优化、执行计划分析

1. 索引概述

1.1 什么是索引？

索引是帮助数据库高效获取数据的数据结构，类似于书籍的目录。

无索引：全表扫描（O(N)）
┌─────────────────────────────────┐
│ row1 │ row2 │ row3 │ ... │ rowN │
└─────────────────────────────────┘
        ↑ 需要遍历所有行

有索引：索引查找（O(logN)）
┌─────────────────────────────────┐
│  索引   │  指向  │
│  key1  │ → row5 │
│  key2  │ → row10│
│  key3  │ → row15│
└─────────────────────────────────┘
        ↑ 直接定位到数据行

1.2 索引优缺点

优点 缺点
加快查询速度 占用额外存储空间
加速排序和分组 降低写入性能（INSERT/UPDATE/DELETE）
加速表连接 需要维护索引结构
保证唯一性 优化器可能选错索引

1.3 何时使用索引？

适合创建索引的场景： - 主键、外键 - WHERE 子句中的列 - JOIN 连接条件 - ORDER BY、GROUP BY 的列 - 高选择性列（不同值多）

不适合创建索引的场景： - 表记录太少 - 低选择性列（如性别） - 频繁更新的列 - TEXT、BLOB 类型 - 很少在查询中使用的列

2. 索引数据结构

2.1 B+Tree 索引

B+Tree 结构（3 层）：
         ┌─────────┐
         │  50     │  ← 根节点（索引）
         └────┬────┘
              │
       ┌──────┴──────┐
       ▼             ▼
┌──────────┐   ┌──────────┐
│ 10  30   │   │ 70  90   │  ← 内部节点（索引）
└────┬─────┘   └────┬─────┘
     │              │
  ┌──┴──┐       ┌──┴──┐
  ▼     ▼       ▼     ▼
┌────┐ ┌────┐ ┌────┐ ┌────┐
│1-9 │ │10- │ │50- │ │70- │  ← 叶子节点（数据）
│    │ │49  │ │69  │ │100 │
└────┘ └────┘ └────┘ └────┘
     │              │
     └──────────────┘  ← 叶子节点链表（范围查询）

B+Tree 特点： - 非叶子节点只存索引，不存数据 - 所有数据都在叶子节点 - 叶子节点用链表连接（范围查询快） - 树高度低（3-4 层可存千万级数据）

2.2 哈希索引

哈希索引：
key → hash(key) → 数据位置

"张三" → hash("张三") = 12345 → row 100
"李四" → hash("李四") = 67890 → row 200

哈希索引特点： - 等值查询快（O(1)） - 不支持范围查询 - 不支持排序 - 不支持模糊查询 - Memory 引擎默认使用

3. 索引类型

3.1 普通索引（INDEX）

-- 创建时添加
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    INDEX idx_username (username)
);

-- 事后添加
CREATE INDEX idx_username ON users(username);

-- 删除索引
DROP INDEX idx_username ON users;
ALTER TABLE users DROP INDEX idx_username;

3.2 唯一索引（UNIQUE）

-- 创建时添加
CREATE TABLE users (
    id INT PRIMARY KEY,
    email VARCHAR(100),
    UNIQUE INDEX uk_email (email)
);

-- 事后添加
CREATE UNIQUE INDEX uk_email ON users(email);

-- 与普通索引区别：不允许重复值

3.3 主键索引（PRIMARY KEY）

-- 主键自动创建索引
CREATE TABLE users (
    id INT PRIMARY KEY,  -- 主键索引
    username VARCHAR(50)
);

-- 主键特点：
-- 1. 唯一且非 NULL
-- 2. 一张表只能有一个主键
-- 3. InnoDB 的主键是聚簇索引

3.4 复合索引（联合索引）

-- 多列索引
CREATE INDEX idx_name_age ON users(username, age);

-- 最左前缀原则
SELECT * FROM users WHERE username = 'zhangsan';        -- ✅ 使用索引
SELECT * FROM users WHERE username = 'zhangsan' AND age = 25;  -- ✅ 使用索引
SELECT * FROM users WHERE age = 25;                     -- ❌ 不使用索引

-- 创建复合索引
CREATE INDEX idx_status_created ON orders(status, created_at);

-- 查询
SELECT * FROM orders WHERE status = 1 AND created_at > '2024-01-01';  -- ✅
SELECT * FROM orders WHERE status = 1;                    -- ✅
SELECT * FROM orders WHERE created_at > '2024-01-01';     -- ❌

3.5 全文索引（FULLTEXT）

-- 创建全文索引（仅 MyISAM 和 InnoDB 5.6+）
CREATE FULLTEXT INDEX ft_content ON articles(content);

-- 全文搜索
SELECT * FROM articles 
WHERE MATCH(content) AGAINST('MySQL 教程' IN NATURAL LANGUAGE MODE);

-- 布尔模式
SELECT * FROM articles 
WHERE MATCH(content) AGAINST('+MySQL -Oracle' IN BOOLEAN MODE);

3.6 空间索引（SPATIAL）

-- 创建空间索引
CREATE TABLE locations (
    id INT PRIMARY KEY,
    location POINT NOT NULL,
    SPATIAL INDEX idx_location (location)
);

4. 聚簇索引与二级索引

4.1 聚簇索引（Clustered Index）

InnoDB 聚簇索引：
叶子节点存储完整行数据

主键索引（聚簇索引）：
┌─────────────────────────────────┐
│  id=1  │  (1, '张三', 25, ...) │  ← 数据就在索引中
│  id=2  │  (2, '李四', 30, ...) │
│  id=3  │  (3, '王五', 28, ...) │
└─────────────────────────────────┘

特点： - InnoDB 使用聚簇索引 - 数据按主键顺序存储 - 一张表只有一个聚簇索引 - 主键查询最快

4.2 二级索引（Secondary Index）

二级索引（非聚簇索引）：
叶子节点存储主键值

username 索引（二级索引）：
┌─────────────────────┐
│ 'zhangsan' │ → 1    │  ← 指向主键
│ 'lisi'     │ → 2    │
│ 'wangwu'   │ → 3    │
└─────────────────────┘

查询过程：
1. 在二级索引找到 'zhangsan' → 主键 id=1
2. 回表：在聚簇索引找到 id=1 → 获取完整数据

4.3 覆盖索引

-- 查询只需要索引列，无需回表
SELECT id, username FROM users WHERE username = 'zhangsan';
-- ✅ 覆盖索引：username 索引包含 id 和 username

-- 需要回表
SELECT id, username, email FROM users WHERE username = 'zhangsan';
-- ❌ 需要回表获取 email

5. 索引管理

5.1 查看索引

-- 查看表的所有索引
SHOW INDEX FROM users;

-- 查看索引详情
SELECT 
    index_name,
    column_name,
    seq_in_index,
    non_unique,
    index_type
FROM information_schema.statistics
WHERE table_name = 'users';

5.2 分析索引使用

-- 查看索引使用情况
SHOW STATUS LIKE 'Handler_read%';

-- Handler_read_first: 索引第一个值读取次数
-- Handler_read_key: 通过索引读取行数
-- Handler_read_next: 按顺序读取下一行次数
-- Handler_read_rnd: 随机读取行数（高表示索引不佳）
-- Handler_read_rnd_next: 全表扫描读取行数

5.3 索引维护

-- 分析表（更新索引统计信息）
ANALYZE TABLE users;

-- 检查表
CHECK TABLE users;

-- 优化表（重建索引，回收空间）
OPTIMIZE TABLE users;

-- 重建索引（5.6+）
ALTER TABLE users ENGINE=InnoDB;

6. 索引优化原则

6.1 最左前缀原则

-- 复合索引 (a, b, c)
SELECT * FROM t WHERE a = 1 AND b = 2 AND c = 3;  -- ✅ 完全使用
SELECT * FROM t WHERE a = 1 AND b = 2;            -- ✅ 使用前两列
SELECT * FROM t WHERE a = 1;                       -- ✅ 使用第一列
SELECT * FROM t WHERE b = 2 AND c = 3;            -- ❌ 不使用索引
SELECT * FROM t WHERE a = 1 AND c = 3;            -- ⚠️ 只使用 a

6.2 避免索引失效

-- ❌ 对索引列使用函数
SELECT * FROM users WHERE YEAR(created_at) = 2024;
-- ✅ 改为
SELECT * FROM users WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01';

-- ❌ 对索引列进行运算
SELECT * FROM products WHERE price * 2 > 200;
-- ✅ 改为
SELECT * FROM products WHERE price > 100;

-- ❌ 隐式类型转换
SELECT * FROM users WHERE phone = 13800138000;  -- phone 是字符串
-- ✅ 改为
SELECT * FROM users WHERE phone = '13800138000';

-- ❌ LIKE 以通配符开头
SELECT * FROM users WHERE username LIKE '%san';
-- ✅ LIKE 不以通配符开头
SELECT * FROM users WHERE username LIKE 'zhang%';

-- ❌ OR 条件中有没有索引的列
SELECT * FROM users WHERE username = 'zhangsan' OR email = 'zhang@example.com';
-- 如果只有 username 有索引，则索引失效

-- ❌ IS NULL / IS NOT NULL 可能导致索引失效（取决于数据分布）

6.3 索引列选择性

-- 选择性 = 不同值数量 / 总行数
-- 选择性越高，索引效果越好

-- 查看列的选择性
SELECT 
    COUNT(DISTINCT username) / COUNT(*) AS username_selectivity,
    COUNT(DISTINCT gender) / COUNT(*) AS gender_selectivity
FROM users;

-- gender 选择性低（只有 2-3 个值），不适合建索引
-- username 选择性高，适合建索引

6.4 索引覆盖

-- 创建覆盖索引
CREATE INDEX idx_status_user ON orders(status, user_id, created_at);

-- 查询使用覆盖索引
SELECT status, user_id, created_at 
FROM orders 
WHERE status = 1 AND user_id = 100;
-- ✅ 无需回表

6.5 前缀索引

-- 长字符串创建前缀索引
CREATE INDEX idx_email_prefix ON users(email(10));
-- 只索引 email 前 10 个字符

-- 检查前缀选择性
SELECT 
    COUNT(DISTINCT email) / COUNT(*) AS full_selectivity,
    COUNT(DISTINCT LEFT(email, 10)) / COUNT(*) AS prefix_selectivity
FROM users;

7. 执行计划分析（EXPLAIN）

7.1 EXPLAIN 基本用法

EXPLAIN SELECT * FROM users WHERE username = 'zhangsan';

7.2 EXPLAIN 输出字段

字段 说明
id 查询序号，越大优先级越高
select_type 查询类型（SIMPLE/PRIMARY/SUBQUERY 等）
table 显示的表
type 访问类型（性能从好到差）
possible_keys 可能使用的索引
key 实际使用的索引
key_len 使用索引的长度
ref 显示哪个字段或常数与索引比较
rows 需要扫描的行数
Extra 额外信息

7.3 type 访问类型（重要）

性能从好到差：

system > const > eq_ref > ref > range > index > ALL

- system: 表只有一行（系统表）
- const: 主键或唯一索引等值查询
- eq_ref: 主键或唯一索引关联查询
- ref: 非唯一索引查询
- range: 索引范围扫描
- index: 全索引扫描
- ALL: 全表扫描（最差）

-- const 示例
EXPLAIN SELECT * FROM users WHERE id = 1;
-- type: const

-- ref 示例
EXPLAIN SELECT * FROM users WHERE username = 'zhangsan';
-- type: ref

-- range 示例
EXPLAIN SELECT * FROM products WHERE price > 100;
-- type: range

-- ALL 示例
EXPLAIN SELECT * FROM users WHERE email LIKE '%@example.com';
-- type: ALL（全表扫描）

7.4 Extra 常见值

值 说明
Using index 使用覆盖索引（好）
Using where 使用 WHERE 过滤
Using temporary 使用临时表（需要优化）
Using filesort 使用文件排序（需要优化）
Using join buffer 使用连接缓冲
Impossible WHERE WHERE 条件不可能成立 
-- Using index（好）
EXPLAIN SELECT id, username FROM users WHERE username = 'zhangsan';
-- Extra: Using index

-- Using temporary（需要优化）
EXPLAIN SELECT status, COUNT(*) FROM users GROUP BY status;
-- Extra: Using temporary

-- Using filesort（需要优化）
EXPLAIN SELECT * FROM users ORDER BY created_at;
-- Extra: Using filesort

8. 索引优化实战

8.1 慢查询优化

-- 1. 找到慢查询
SELECT * FROM orders WHERE user_id = 100 ORDER BY created_at DESC LIMIT 10;

-- 2. 分析执行计划
EXPLAIN SELECT * FROM orders WHERE user_id = 100 ORDER BY created_at DESC LIMIT 10;

-- 3. 创建优化索引
CREATE INDEX idx_user_created ON orders(user_id, created_at DESC);

-- 4. 验证优化
EXPLAIN SELECT * FROM orders WHERE user_id = 100 ORDER BY created_at DESC LIMIT 10;
-- type: ref, Extra: Using index condition

8.2 分页优化

-- 慢的分页（深分页）
SELECT * FROM products ORDER BY id LIMIT 100000, 10;

-- 优化 1：使用覆盖索引 + 回表
SELECT p.* FROM products p
INNER JOIN (
    SELECT id FROM products ORDER BY id LIMIT 100000, 10
) AS tmp ON p.id = tmp.id;

-- 优化 2：记录上次 ID
SELECT * FROM products WHERE id > 100000 ORDER BY id LIMIT 10;

8.3 COUNT 优化

-- 慢的 COUNT
SELECT COUNT(*) FROM users WHERE status = 1;

-- 优化 1：使用覆盖索引
CREATE INDEX idx_status ON users(status);

-- 优化 2：使用近似值
SELECT TABLE_ROWS FROM information_schema.tables 
WHERE table_name = 'users';

-- 优化 3：维护计数表
CREATE TABLE user_stats (
    status TINYINT PRIMARY KEY,
    count INT DEFAULT 0
);
-- 每次 INSERT/DELETE 时更新计数
