06. LangGraph 基础

LangChain Agents 基于 LangGraph 构建。了解 LangGraph 有助于深入理解 Agent 的工作原理。

什么是 LangGraph？

LangGraph 是一个低级别的 Agent 编排框架，用于构建有状态的、多角色的应用程序。

LangChain vs LangGraph

┌─────────────────────────────────────────────────────────┐
│              LangChain vs LangGraph                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  LangChain（高层）                                       │
│  ─────────────                                          │
│  ✅ 预构建的 Agent 架构                                   │
│  ✅ 简单易用（10 行代码）                                 │
│  ✅ 适合快速开发                                         │
│  ❌ 定制性有限                                           │
│                                                         │
│  LangGraph（底层）                                       │
│  ─────────────                                          │
│  ✅ 完全定制的工作流                                     │
│  ✅ 细粒度控制                                           │
│  ✅ 适合复杂场景                                         │
│  ❌ 学习曲线陡峭                                         │
│                                                         │
│  关系：LangChain Agents 基于 LangGraph 构建              │
│  建议：先用 LangChain，需要深度定制时再用 LangGraph       │
│                                                         │
└─────────────────────────────────────────────────────────┘

核心概念

StateGraph（状态图）

StateGraph = 状态 + 节点 + 边

状态（State）：在节点之间传递的数据
节点（Nodes）：执行具体任务的函数
边（Edges）：定义节点之间的执行顺序

示例：
┌─────────┐     ┌─────────┐     ┌─────────┐
│  Node A │ ──→ │  Node B │ ──→ │  Node C │
└─────────┘     └─────────┘     └─────────┘
     ↑                                  │
     └──────────────────────────────────┘

状态流转：
初始状态 → Node A → 更新状态 → Node B → 更新状态 → Node C

基础示例

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# 1. 定义状态
class State(TypedDict):
    value: int

# 2. 定义节点函数
def add_one(state: State) -> State:
    return {"value": state["value"] + 1}

# 3. 创建图
graph = StateGraph(State)

# 4. 添加节点
graph.add_node("add_one", add_one)

# 5. 添加边
graph.add_edge(START, "add_one")
graph.add_edge("add_one", END)

# 6. 编译
app = graph.compile()

# 7. 运行
result = app.invoke({"value": 0})
print(result)  # {'value': 1}

LangGraph 如何支撑 LangChain

Agent 的状态图

LangChain Agent 的底层结构：

┌─────────────────────────────────────────────────────────┐
│              Agent StateGraph                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  状态（State）：                                         │
│  {                                                      │
│    "messages": [...],  # 对话历史                       │
│    "tools": [...],     # 可用工具                       │
│  }                                                      │
│                                                         │
│  节点（Nodes）：                                         │
│  - agent_node: LLM 思考和决策                            │
│  - tool_node: 执行工具调用                               │
│                                                         │
│  边（Edges）：                                           │
│  START → agent_node                                     │
│  agent_node → [工具调用？]                              │
│    ├─ 是 → tool_node → agent_node（循环）              │
│    └─ 否 → END                                          │
│                                                         │
└─────────────────────────────────────────────────────────┘

简化的 Agent 实现

from typing import TypedDict, List
from langchain_core.messages import BaseMessage
from langgraph.graph import StateGraph, START, END

# 1. 定义状态
class AgentState(TypedDict):
    messages: List[BaseMessage]

# 2. Agent 节点（LLM 思考）
def agent_node(state: AgentState):
    # 调用 LLM
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# 3. 工具节点
def tool_node(state: AgentState):
    # 执行工具调用
    last_message = state["messages"][-1]
    tool_result = execute_tool(last_message.tool_calls)
    return {"messages": [tool_result]}

# 4. 路由函数
def should_continue(state: AgentState):
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"  # 有工具调用，去 tool_node
    return END  # 否则结束

# 5. 构建图
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tool_node)

graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", should_continue)
graph.add_edge("tools", "agent")  # 工具执行后回到 agent

# 6. 编译
app = graph.compile()

# 7. 运行
result = app.invoke({
    "messages": [{"role": "user", "content": "北京天气"}]
})

高级特性

检查点（Checkpointing）

from langgraph.checkpoint.memory import MemorySaver

# 创建检查点保存器
memory = MemorySaver()

# 编译时启用检查点
app = graph.compile(checkpointer=memory)

# 使用配置（thread_id 区分不同会话）
config = {"configurable": {"thread_id": "conversation-1"}}

# 第一次运行
result = app.invoke({"messages": [...]}, config)

# 中断后可以从检查点恢复
result = app.invoke(None, config)  # 继续执行

中断和恢复

from langgraph.graph import StateGraph, START, END

# 在特定节点前中断
app = graph.compile(
    checkpointer=memory,
    interrupt_before=["human_review"]  # 在 human_review 节点前中断
)

# 运行到中断点
result = app.invoke({"messages": [...]}, config)

# 检查状态
snapshot = app.get_state(config)
print(f"下一个节点：{snapshot.next}")  # ['human_review']

# 人工审核后继续
app.update_state(config, {"approved": True})
result = app.invoke(None, config)

流式输出

# 流式处理每个节点
for node, values in app.stream({"messages": [...]}):
    print(f"节点：{node}")
    print(f"输出：{values}")

# 流式完整状态
for state in app.stream(input, stream_mode="values"):
    print(f"当前状态：{state}")

子图（Subgraphs）

# 创建子图
subgraph = StateGraph(SubState)
subgraph.add_node("sub_node", sub_function)
# ... 添加更多节点和边
compiled_subgraph = subgraph.compile()

# 在主图中使用子图
main_graph = StateGraph(MainState)
main_graph.add_node("subgraph", compiled_subgraph)
# ...

何时使用 LangGraph？

适合 LangChain（高层）

✅ 快速构建标准 Agent
✅ 简单的工具调用
✅ 对话式应用
✅ 原型开发
✅ 不需要复杂工作流

适合 LangGraph（底层）

✅ 复杂的工作流编排
✅ 多 Agent 协作
✅ 需要精细控制状态
✅ 自定义执行逻辑
✅ 复杂的人机交互
✅ 确定性 + Agent 混合流程

从 LangChain 迁移到 LangGraph

何时考虑迁移？

如果你需要：
- 完全自定义的 Agent 架构
- 复杂的状态管理
- 多 Agent 协作
- 特殊的执行流程
- 精细的流式控制

→ 考虑使用 LangGraph

最佳实践

✅ 推荐

# 1. 先用 LangChain，需要时再迁移到 LangGraph
agent = create_agent(...)  # 先快速原型

# 2. 明确定义状态
class State(TypedDict):
    messages: List[BaseMessage]
    metadata: Dict

# 3. 保持节点函数单一职责
def agent_node(state): ...  # 只负责 LLM 调用
def tool_node(state): ...   # 只负责工具执行

# 4. 使用检查点持久化
app = graph.compile(checkpointer=MemorySaver())

# 5. 添加错误处理
def safe_node(state):
    try:
        return do_something()
    except Exception as e:
        return {"error": str(e)}

❌ 避免

# 1. 过度工程化
# 能用 LangChain 解决就不要用 LangGraph

# 2. 状态过于复杂
class State(TypedDict):
    field1: ...
    field2: ...
    # ... 50 个字段 ❌

# 3. 节点函数过于复杂
def mega_node(state):
    # 做 10 件事 ❌
    # 应该拆分为多个节点

# 4. 忽略检查点
app = graph.compile()  # ❌ 没有持久化

# 5. 循环没有退出条件
graph.add_edge("A", "B")
graph.add_edge("B", "A")  # ❌ 无限循环
