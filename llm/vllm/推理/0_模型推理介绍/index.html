大模型推理（Large Language Model Inference）是指将训练好的大语言模型用于实际生成文本的过程。这个过程不是“一键输出”，而是由多个关键阶段协同完成的，每个阶段都有其特定任务和性能特征。

🧩 大模型推理的三大核心阶段

大模型推理主要分为三个阶段：

阶段 名称 关键作用
1️⃣ Prefill（预填充） 处理用户输入 prompt，构建上下文和 KV Cache
2️⃣ Decoding / Generation（解码/生成） 自回归地逐个生成输出 token（推流的核心）
3️⃣ Post-processing（后处理） 清理输出、截断、格式化、返回结果

下面我们详细展开。

1️⃣ Prefill 阶段：理解你的问题

✅ 做了什么？

  • 输入用户的 prompt（如：“请写一首关于春天的诗”）
  • 将 prompt 分词（tokenize）为 token 序列
  • 通过 Transformer 的所有层进行前向传播
  • 计算并缓存每个 token 的 Key 和 Value 向量（KV Cache）

🔍 特点：

  • 并行计算：所有 prompt tokens 可以同时处理，GPU 利用率高
  • 耗时与 prompt 长度成正比：输入越长，prefill 时间越久
  • 不产生输出文本，但为后续生成打基础

📈 性能指标：

  • TTFT（Time to First Token）：从请求开始到第一个输出 token 的时间，受 prefill 影响最大

💡 优化手段：FlashAttention、PagedAttention、模型量化等

2️⃣ Decoding / Generation 阶段：一个字一个字地“写答案”

这是最核心的生成阶段，也是我们看到“文字一个个蹦出来”的原因。

✅ 做了什么？

  • 每次生成一个 token（自回归）
  • 使用 KV Cache 避免重复计算历史信息
  • 重复以下步骤直到结束：
  • 输入当前上下文（prompt + 已生成内容）
  • 模型预测下一个 token 的概率分布
  • 采样（如 greedy、top-p 等）选择 token
  • 返回该 token（如果是流式）
  • 更新 KV Cache
  • 继续下一轮

🔁 示例流程：

输入: "你好"
→ 生成: "，"
→ 生成: "今"
→ 生成: "天"
→ ...

🔍 特点：

  • 串行为主：每次只能生成一个 token，无法完全并行
  • 延迟累积：输出越长，总时间越久
  • 支持流式输出（Streaming）：每生成一个 token 就推送给客户端

📈 性能指标：

  • TPOT（Time Per Output Token）：每个输出 token 的平均耗时
  • 吞吐量（Tokens/sec）：衡量 GPU 解码效率

💡 优化手段：连续批处理（Continuous Batching）、推测解码（Speculative Decoding）

3️⃣ Post-processing 阶段：整理输出，准备返回

当生成结束（遇到 EOS 标记或达到最大长度），进入后处理阶段。

✅ 做了什么？

  • 去除特殊标记（如 </s>）
  • 截断多余内容（如重复、乱码）
  • 统计信息收集（生成长度、耗时、token 数等）
  • 构造最终响应 JSON 或 SSE 流
  • 释放 KV Cache 和显存资源

📝 输出示例（OpenAI API 兼容格式）：

{
  "id": "cmpl-123",
  "object": "text_completion",
  "model": "qwen3-vl-2b",
  "choices": [
    {
      "text": "春天来了，花儿开了...",
      "finish_reason": "length"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 50,
    "total_tokens": 60
  }
}

🔄 整体流程图

[用户请求]
     ↓
  Prefill 阶段  ← 处理 prompt，生成 KV Cache
     ↓
Decoding 阶段  ← 自回归生成 token（可流式推送）
     ↓
Post-processing ← 清理输出，构造响应
     ↓
[返回客户端]

🚀 推理引擎如何提升效率？（以 vLLM 为例）

你之前使用的 vLLM 正是通过以下技术优化这三个阶段：

技术 作用
PagedAttention 将 KV Cache 分页管理，显存利用率提升 3-5 倍
Continuous Batching 动态合并多个请求的 decoding 阶段，提高 GPU 利用率
Chunked Prefill 支持超长 prompt 分块处理，边 prefill 边 streaming
GPU Memory Utilization 控制 防止 OOM，合理分配显存

⚙️ 例如你命令中的参数： bash --gpu-memory-utilization=0.85 --tensor-parallel-size 1 --max-model-len 2000 都是在配置推理阶段的资源使用策略。

📊 不同场景下的瓶颈分析

场景 主要瓶颈
短 prompt + 长输出（如写作） Decoding 阶段（TPOT 高）
超长文档输入（如摘要） Prefill 阶段（TTFT 高）
高并发聊天服务 显存 + KV Cache 管理
实时语音交互 首字延迟（TTFT）必须低

✅ 总结：三大阶段对比表

阶段 并行性 耗时因素 优化重点 是否流式
Prefill ✅ 高（并行） prompt 长度 FlashAttention, KV Cache ❌
Decoding ❌ 低（串行） 输出长度 连续批处理, 推测解码 ✅ 支持流式
Post-process ✅ 快速 固定开销 格式化、统计、释放资源 -

💬 类比理解

你可以把大模型推理想象成一位作家写作：

  1. Prefill → 作家认真读完你给的题目和背景材料（花时间理解）
  2. Decoding → 作家一个字一个字写下答案（边想边写）
  3. Post-processing → 检查错别字、排版、提交稿件

如果你正在部署模型（如 Qwen、Llama 等），了解这些阶段有助于你： - 调优参数（如 max_model_len、gpu_memory_utilization） - 选择合适的推理框架（vLLM vs TGI vs llama.cpp） - 优化用户体验（降低首字延迟、支持流式）
