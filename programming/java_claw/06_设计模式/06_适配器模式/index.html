06_适配器模式

1. 适配器模式概述

1.1 什么是适配器模式

适配器模式（Adapter Pattern）将一个类的接口转换成客户希望的另一个接口，使原本不兼容的类可以一起工作。

别名：包装器模式（Wrapper Pattern）

适用场景： - ✅ 使用现有类，但接口不符合需求 - ✅ 需要复用现有类 - ✅ 统一多个类的接口

1.2 生活中的例子

电源适配器：
- 220V 交流电 → 5V 直流电
- 让手机可以使用墙上的电源

USB 转接头：
- USB-A → USB-C
- 让旧设备可以使用新接口

2. 实现方式

2.1 类适配器（继承）

// 目标接口
public interface Target {
    void request();
}

// 需要适配的类
public class Adaptee {
    public void specificRequest() {
        System.out.println("特殊请求");
    }
}

// 适配器（继承）
public class Adapter extends Adaptee implements Target {
    @Override
    public void request() {
        // 调用 Adaptee 的方法
        specificRequest();
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        Target target = new Adapter();
        target.request();
    }
}

2.2 对象适配器（组合，推荐）

// 目标接口
public interface Target {
    void request();
}

// 需要适配的类
public class Adaptee {
    public void specificRequest() {
        System.out.println("特殊请求");
    }
}

// 适配器（组合）
public class Adapter implements Target {
    private Adaptee adaptee;

    public Adapter(Adaptee adaptee) {
        this.adaptee = adaptee;
    }

    @Override
    public void request() {
        adaptee.specificRequest();
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        Adaptee adaptee = new Adaptee();
        Target target = new Adapter(adaptee);
        target.request();
    }
}

2.3 接口适配器

// 接口有 4 个方法
public interface Target {
    void method1();
    void method2();
    void method3();
    void method4();
}

// 抽象适配器（提供空实现）
public abstract class AbstractAdapter implements Target {
    public void method1() {}
    public void method2() {}
    public void method3() {}
    public void method4() {}
}

// 具体适配器（只重写需要的方法）
public class ConcreteAdapter extends AbstractAdapter {
    @Override
    public void method1() {
        System.out.println("实现 method1");
    }

    @Override
    public void method2() {
        System.out.println("实现 method2");
    }
    // method3 和 method4 使用默认空实现
}

3. 实战示例

3.1 支付接口适配

// 旧支付接口
public interface OldPayment {
    void payOld(double amount);
}

// 新支付接口
public interface NewPayment {
    void pay(BigDecimal amount, String currency);
}

// 旧的实现
public class AlipayOld implements OldPayment {
    @Override
    public void payOld(double amount) {
        System.out.println("支付宝支付：" + amount);
    }
}

// 适配器
public class PaymentAdapter implements NewPayment {
    private OldPayment oldPayment;

    public PaymentAdapter(OldPayment oldPayment) {
        this.oldPayment = oldPayment;
    }

    @Override
    public void pay(BigDecimal amount, String currency) {
        // 转换参数
        double amountDouble = amount.doubleValue();

        // 调用旧接口
        oldPayment.payOld(amountDouble);
    }
}

// 使用
public class Main {
    public static void main(String[] args) {
        OldPayment old = new AlipayOld();
        NewPayment adapter = new PaymentAdapter(old);

        adapter.pay(new BigDecimal("100.00"), "CNY");
    }
}

3.2 日志系统适配

// 第三方日志库
public class ThirdPartyLogger {
    public void info(String message) {
        System.out.println("[INFO] " + message);
    }

    public void error(String message) {
        System.out.println("[ERROR] " + message);
    }

    public void debug(String message) {
        System.out.println("[DEBUG] " + message);
    }
}

// 我们的日志接口
public interface Logger {
    void info(String message);
    void error(String message);
    void debug(String message);
    void warn(String message);
}

// 适配器
public class LoggerAdapter implements Logger {
    private ThirdPartyLogger thirdPartyLogger;

    public LoggerAdapter(ThirdPartyLogger logger) {
        this.thirdPartyLogger = logger;
    }

    @Override
    public void info(String message) {
        thirdPartyLogger.info(message);
    }

    @Override
    public void error(String message) {
        thirdPartyLogger.error(message);
    }

    @Override
    public void debug(String message) {
        thirdPartyLogger.debug(message);
    }

    @Override
    public void warn(String message) {
        // 第三方没有 warn，用 info 代替
        thirdPartyLogger.info("[WARN] " + message);
    }
}

3.3 数据源适配

// 旧的数据源接口
public interface OldDataSource {
    String getString(String key);
    int getInt(String key);
}

// 新的数据源接口
public interface NewDataSource {
    <T> T get(String key, Class<T> type);
    void set(String key, Object value);
}

// 旧的实现
public class PropertiesDataSource implements OldDataSource {
    private Properties props = new Properties();

    @Override
    public String getString(String key) {
        return props.getProperty(key);
    }

    @Override
    public int getInt(String key) {
        return Integer.parseInt(props.getProperty(key));
    }
}

// 适配器
public class DataSourceAdapter implements NewDataSource {
    private OldDataSource oldDataSource;

    public DataSourceAdapter(OldDataSource dataSource) {
        this.oldDataSource = dataSource;
    }

    @Override
    @SuppressWarnings("unchecked")
    public <T> T get(String key, Class<T> type) {
        if (type == String.class) {
            return (T) oldDataSource.getString(key);
        } else if (type == Integer.class) {
            return (T) Integer.valueOf(oldDataSource.getInt(key));
        }
        throw new IllegalArgumentException("Unsupported type: " + type);
    }

    @Override
    public void set(String key, Object value) {
        // 旧数据源不支持 set，抛出异常或忽略
        throw new UnsupportedOperationException("Set not supported");
    }
}

4. 适配器 vs 代理 vs 装饰器

模式 目的 实现
适配器 接口转换 改变接口
代理 控制访问 接口不变
装饰器 增强功能 接口不变

5. 优缺点

5.1 优点

  • ✅ 复用现有代码：无需修改原有类
  • ✅ 解决接口不兼容：让不兼容的类一起工作
  • ✅ 提高灵活性：可以随时替换适配器
  • ✅ 符合开闭原则：新增适配器无需修改原有代码

5.2 缺点

  • ❌ 增加复杂度：引入额外的类
  • ❌ 过度使用：系统设计混乱

6. 本章小结

核心知识点

✅ 类适配器：继承实现
✅ 对象适配器：组合实现（推荐）
✅ 接口适配器：抽象类提供空实现
✅ 实战应用：支付、日志、数据源

最佳实践

  1. 优先使用对象适配器：更灵活
  2. 明确适配目的：接口转换
  3. 文档化适配器：说明适配原因
  4. 避免过度使用：不要为了模式而模式
