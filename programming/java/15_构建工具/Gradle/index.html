Gradle 是一个 基于 Groovy 或 Kotlin DSL 的开源构建自动化工具，以其灵活性、可扩展性和强大的依赖管理能力，在 Java、Android、Kotlin、Groovy、Scala 等项目中广泛使用。

一、Gradle 简介

1.1 什么是 Gradle？

Gradle 是一个现代的构建工具，结合了 Ant 的灵活性和 Maven 的依赖管理功能，并引入了更灵活的构建脚本语法（Groovy 或 Kotlin）。它支持多种语言和平台：

  • Java / Kotlin / Scala / Groovy / Android
  • C/C++（从版本 4.0 开始）
  • Web 应用（如 JavaScript）

1.2 Gradle 核心特性

特性 描述
声明式依赖管理 支持远程仓库（Maven、Ivy）、传递依赖、依赖排除等。
增量构建（Incremental Build） 只构建发生变化的部分，提高效率。
多项目构建 支持模块化项目结构，主项目和子项目之间可以共享配置。
自定义任务与插件系统 用户可以编写自定义任务或使用官方/第三方插件扩展功能。
支持多种语言和框架 不仅限于 Java，还支持 Android、Python、C++ 等。
运行速度快 并行任务执行、缓存机制提升性能。

二、Gradle 安装与环境准备

2.1 安装方式

方式一：使用 SDKMAN（推荐）

sdk install gradle 8.3

方式二：手动安装

  1. 下载地址：https://gradle.org/releases/
  2. 解压并配置环境变量 GRADLE_HOME 和 PATH

方式三：使用 gradle wrapper（最常用）

在项目根目录下，gradlew 命令会自动下载对应版本的 Gradle。

./gradlew -v

三、Gradle 构建文件结构

典型的 Gradle 项目包含以下核心文件：

文件名 作用说明
build.gradle 模块级构建脚本，定义插件、依赖、任务等。
settings.gradle 配置项目名称、包含哪些模块（适用于多模块项目）。
gradle.properties 定义全局属性，如 JVM 参数、Gradle 属性等。
gradle/wrapper/gradle-wrapper.properties Gradle Wrapper 的配置文件，指定 Gradle 版本。

四、Gradle 构建脚本基础

4.1 build.gradle 示例（Java 项目）

plugins {
    id 'java'
}

version '1.0-SNAPSHOT'

repositories {
    mavenCentral()
}

dependencies {
    implementation 'com.google.guava:guava:31.1-jre'
    testImplementation 'junit:junit:4.13.2'
}

4.2 settings.gradle 示例

rootProject.name = 'my-project'
include 'app', 'lib'

五、Gradle 常用命令

命令 说明
gradle tasks 查看所有可用任务
gradle build 构建整个项目
gradle clean 清理输出目录 (build/)
gradle run 运行应用程序（需配置 application 插件）
gradle dependencies 查看依赖树
gradle -q help --task <task-name> 查看某个任务详情

使用 wrapper 时加前缀 ./gradlew。

六、Gradle 插件

Gradle 插件用于扩展构建行为，常见插件包括：

插件 ID 功能

七、依赖管理（Dependency Management）

7.1 依赖类型

类型 说明
implementation 编译和运行时依赖（不暴露给上游模块）
api 同类于 implementation，但对旧版兼容
compileOnly 编译期依赖（不打包进最终 jar）
runtimeOnly 运行时依赖（编译时不参与）
testImplementation 测试代码依赖

7.2 添加依赖示例

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web:2.7.0'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.8.1'
}

十、Gradle vs Maven 对比

对比项 Gradle Maven
脚本语言 Groovy / Kotlin DSL XML
性能 更快，支持增量构建 较慢
扩展性 强，支持自定义插件 通过插件机制扩展
学习曲线 稍陡峭 相对平缓
社区生态 Android 官方推荐，社区活跃 Java 生态广泛使用
依赖管理 更灵活，支持多种方式 基于 POM 的依赖管理

十一、Gradle Wrapper

Gradle Wrapper 确保项目使用特定版本的 Gradle，无需全局安装。

生成 Wrapper

# 在项目根目录执行
gradle wrapper --gradle-version 8.5

# 或使用 gradle-wrapper 插件
./gradlew wrapper --gradle-version 8.5

项目结构

my-project/
├── gradle/
│   └── wrapper/
│       ├── gradle-wrapper.jar
│       └── gradle-wrapper.properties
├── gradlew          # Unix/Mac 脚本
├── gradlew.bat      # Windows 脚本
├── build.gradle
└── src/

使用 Wrapper

# Unix/Mac
./gradlew build

# Windows
gradlew.bat build

# 提交到版本控制
git add gradle/ gradlew gradlew.bat

gradle-wrapper.properties

distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
distributionUrl=https\://services.gradle.org/distributions/gradle-8.5-bin.zip
networkTimeout=10000
validateDistributionUrl=true
zipStoreBase=GRADLE_USER_HOME
zipStorePath=wrapper/dists

十二、Gradle 性能优化

启用构建缓存

# gradle.properties
org.gradle.caching=true
org.gradle.parallel=true
org.gradle.daemon=true
org.gradle.configureondemand=true

命令行优化

# 并行执行
./gradlew build --parallel

# 启用构建缓存
./gradlew build --build-cache

# 配置缓存（Gradle 6.6+）
./gradlew build --configuration-cache

# 持续构建（开发时自动重新构建）
./gradlew build --continuous

# 扫描构建性能
./gradlew build --scan

JVM 配置

# gradle.properties
org.gradle.jvmargs=-Xmx2g -XX:MaxMetaspaceSize=512m -XX:+HeapDumpOnOutOfMemoryError

依赖缓存

# 查看依赖缓存
./gradlew dependencies --refresh-dependencies

# 清理依赖缓存
rm -rf ~/.gradle/caches/modules-2

十三、版本目录（Version Catalogs）

Gradle 7.0+ 推荐的依赖版本管理方式。

配置版本目录

# gradle/libs.versions.toml
[versions]
spring-boot = "3.2.0"
junit = "5.10.1"
lombok = "1.18.30"

[libraries]
spring-boot-starter-web = { module = "org.springframework.boot:spring-boot-starter-web", version.ref = "spring-boot" }
spring-boot-starter-test = { module = "org.springframework.boot:spring-boot-starter-test", version.ref = "spring-boot" }
junit-jupiter = { module = "org.junit.jupiter:junit-jupiter", version.ref = "junit" }
lombok = { module = "org.projectlombok:lombok", version.ref = "lombok" }

[bundles]
spring-boot = ["spring-boot-starter-web", "spring-boot-starter-test"]

使用版本目录

// build.gradle
plugins {
    id 'java'
}

dependencies {
    implementation libs.spring.boot.starter.web
    testImplementation libs.spring.boot.starter.test
    testImplementation libs.junit.jupiter
    compileOnly libs.lombok
    annotationProcessor libs.lombok
}

// build.gradle.kts
dependencies {
    implementation(libs.spring.boot.starter.web)
    testImplementation(libs.spring.boot.starter.test)
    testImplementation(libs.junit.jupiter)
    compileOnly(libs.lombok)
    annotationProcessor(libs.lombok)
}

十五、Kotlin DSL

Gradle 支持使用 Kotlin 编写构建脚本，提供更好的 IDE 支持。

build.gradle.kts 示例

plugins {
    java
    application
}

group = "com.example"
version = "1.0.0"

repositories {
    mavenCentral()
}

dependencies {
    implementation("com.google.guava:guava:32.1.3-jre")
    testImplementation("org.junit.jupiter:junit-jupiter:5.10.1")
}

application {
    mainClass.set("com.example.Main")
}

tasks.test {
    useJUnitPlatform()
}

tasks.jar {
    manifest {
        attributes["Main-Class"] = "com.example.Main"
    }
}

Groovy vs Kotlin DSL 对比

特性 Groovy DSL Kotlin DSL
语法 动态、简洁 静态类型、安全
IDE 支持 基础 优秀（自动补全、导航）
学习曲线 平缓（对 Groovy 熟悉者） 稍陡峭（需要 Kotlin 基础）
编译速度 快 稍慢
推荐场景 快速原型、简单项目 大型项目、团队协作

十六、多项目构建进阶

共享配置

// settings.gradle
rootProject.name = 'my-project'
include 'common', 'service-a', 'service-b'

// build.gradle (root)
subprojects {
    apply plugin: 'java'

    repositories {
        mavenCentral()
    }

    java {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }

    dependencies {
        testImplementation 'org.junit.jupiter:junit-jupiter:5.10.1'
    }
}

// service-a/build.gradle
dependencies {
    implementation project(':common')
}

// service-b/build.gradle
dependencies {
    implementation project(':common')
    implementation project(':service-a')
}

条件性配置

subprojects {
    if (project.name.startsWith('service-')) {
        apply plugin: 'org.springframework.boot'
    }

    if (project.name == 'common') {
        // 公共模块特殊配置
    }
}

十七、发布构件

发布到本地

plugins {
    id 'maven-publish'
}

publishing {
    publications {
        mavenJava(MavenPublication) {
            from components.java
            groupId = 'com.example'
            artifactId = 'my-library'
            version = '1.0.0'

            pom {
                name = 'My Library'
                description = 'A useful library'
                url = 'https://github.com/example/my-library'
            }
        }
    }

    repositories {
        mavenLocal()
    }
}

// 发布到本地
// ./gradlew publishToMavenLocal

发布到远程仓库

publishing {
    repositories {
        maven {
            name = 'nexus'
            url = 'https://nexus.example.com/repository/maven-releases/'
            credentials {
                username = findProperty('nexusUsername') ?: ''
                password = findProperty('nexusPassword') ?: ''
            }
        }
    }
}

// 发布到远程
// ./gradlew publish

发布到 Maven Central

plugins {
    id 'maven-publish'
    id 'signing'
}

publishing {
    publications {
        mavenJava(MavenPublication) {
            from components.java

            // 源码和 Javadoc
            artifact javaDocJar
            artifact sourcesJar

            pom {
                name = 'My Library'
                description = 'A useful library'
                url = 'https://github.com/example/my-library'

                licenses {
                    license {
                        name = 'MIT License'
                        url = 'https://opensource.org/licenses/MIT'
                    }
                }

                developers {
                    developer {
                        id = 'developer'
                        name = 'Developer Name'
                        email = 'developer@example.com'
                    }
                }

                scm {
                    connection = 'scm:git:git://github.com/example/my-library.git'
                    developerConnection = 'scm:git:ssh://github.com/example/my-library.git'
                    url = 'https://github.com/example/my-library'
                }
            }
        }
    }

    repositories {
        maven {
            name = 'ossrh'
            url = 'https://s01.oss.sonatype.org/service/local/staging/deploy/maven2/'
            credentials {
                username = findProperty('ossrhUsername') ?: ''
                password = findProperty('ossrhPassword') ?: ''
            }
        }
    }
}

signing {
    sign publishing.publications.mavenJava
}

// 构建源码和 Javadoc
tasks.register('sourcesJar', Jar) {
    archiveClassifier = 'sources'
    from sourceSets.main.allSource
}

tasks.register('javaDocJar', Jar) {
    archiveClassifier = 'javadoc'
    from javadoc
}

// 发布
// ./gradlew publish

十八、常见问题排查

依赖冲突

# 查看依赖树
./gradlew dependencies

# 查看特定配置的依赖
./gradlew dependencies --configuration runtimeClasspath

# 查看特定模块的依赖
./gradlew :service-a:dependencies

解决冲突：

dependencies {
    implementation('com.example:lib-a:1.0') {
        exclude group: 'com.example', module: 'conflicting-lib'
    }

    // 强制使用特定版本
    implementation 'com.example:conflicting-lib:2.0'
}

构建缓慢

# 启用并行和缓存
./gradlew build --parallel --build-cache

# 查看构建扫描（性能分析）
./gradlew build --scan

# 清理缓存
rm -rf ~/.gradle/caches

内存不足

# gradle.properties
org.gradle.jvmargs=-Xmx4g -XX:MaxMetaspaceSize=1g

网络问题

# gradle.properties
# 配置代理
systemProp.http.proxyHost=proxy.example.com
systemProp.http.proxyPort=8080
systemProp.https.proxyHost=proxy.example.com
systemProp.https.proxyPort=8080

十九、最佳实践总结

✅ 推荐做法

1. 使用 Gradle Wrapper 统一团队 Gradle 版本
2. 使用版本目录（Version Catalogs）管理依赖
3. 启用构建缓存和并行执行
4. 使用 Kotlin DSL 获得更好的 IDE 支持
5. 配置 JaCoCo 测试覆盖率
6. 使用 Checkstyle 等代码质量插件
7. 分离配置和代码
8. 定期更新 Gradle 和插件版本
9. 使用私有仓库管理内部构件
10. 使用 --scan 分析构建性能

❌ 避免做法

1. 硬编码版本号（使用版本目录）
2. 使用动态版本（LATEST/RELEASE）
3. 忽略依赖冲突警告
4. 在生产环境使用 SNAPSHOT 依赖
5. 提交 build/ 目录到版本控制
6. 在构建脚本中执行网络请求
7. 过度使用 project.dependencies（使用配置缓存）
8. 忽略 Gradle 版本更新
