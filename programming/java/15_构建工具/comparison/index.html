    Maven vs Gradle - 对比与选择指南¶

    📊 快速对比¶

    对比项 Maven Gradle 胜出
    配置文件 XML (pom.xml) Groovy/Kotlin DSL ⚖️ 平手
    学习曲线 平缓 稍陡峭 🏆 Maven
    构建速度 标准 更快（增量构建） 🏆 Gradle
    灵活性 约定优于配置 高度灵活 🏆 Gradle
    依赖管理 优秀 优秀 ⚖️ 平手
    多模块支持 支持 支持（更灵活） 🏆 Gradle
    Android 支持 有限 官方推荐 🏆 Gradle
    社区生态 成熟稳定 活跃增长 ⚖️ 平手
    企业采用率 高 增长中 🏆 Maven
    IDE 支持 优秀 优秀 ⚖️ 平手

    📋 详细对比¶

    1. 配置文件语法¶

    Maven (XML)： 

    <project>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
            <version>3.2.0</version>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.11.0</version>
                <configuration>
                    <source>17</source>
                    <target>17</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>

    Gradle (Groovy)： 

    dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web:3.2.0'
}

tasks.compileJava {
    sourceCompatibility = '17'
    targetCompatibility = '17'
}

    Gradle (Kotlin)： 

    dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web:3.2.0")
}

tasks.compileJava {
    sourceCompatibility = "17"
    targetCompatibility = "17"
}

    对比： - Maven XML 冗长但结构清晰 - Gradle 简洁但需要学习 DSL - Kotlin DSL 提供类型安全和更好的 IDE 支持

    2. 构建速度¶

    测试场景：中等规模 Java 项目（50+ 模块）

    操作 Maven Gradle 提升
    首次构建 5:30 4:00 27%
    增量构建 2:15 0:45 67%
    清理后构建 5:30 4:15 23%

    Gradle 快的原因： - 增量构建（只编译变化的文件） - 构建缓存（复用其他项目的构建结果） - 并行执行（同时执行独立任务） - 守护进程（保持 JVM 运行）

    3. 依赖管理¶

    Maven： 

    <!-- 依赖管理 -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>3.2.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<!-- 使用依赖 -->
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>

    Gradle (版本目录)： 

    # gradle/libs.versions.toml
[versions]
spring-boot = "3.2.0"

[libraries]
spring-boot-starter-web = { module = "org.springframework.boot:spring-boot-starter-web", version.ref = "spring-boot" }


    // build.gradle
dependencies {
    implementation libs.spring.boot.starter.web
}

    对比： - 两者都支持传递依赖 - 两者都支持 BOM/版本目录 - Gradle 的依赖配置更灵活（implementation/api/compileOnly）

    4. 多模块项目¶

    Maven： 

    <!-- 父 POM -->
<project>
    <packaging>pom</packaging>
    <modules>
        <module>common</module>
        <module>service-a</module>
        <module>service-b</module>
    </modules>
</project>

    Gradle： 

    // settings.gradle
rootProject.name = 'my-project'
include 'common', 'service-a', 'service-b'

// build.gradle (root)
subprojects {
    apply plugin: 'java'

    repositories {
        mavenCentral()
    }

    dependencies {
        testImplementation 'org.junit.jupiter:junit-jupiter:5.10.1'
    }
}

    对比： - Maven 结构清晰，配置分散 - Gradle 配置集中，更灵活 - Gradle 支持条件性配置

    5. 插件系统¶

    Maven 插件： 

    <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-shade-plugin</artifactId>
    <version>3.5.0</version>
    <executions>
        <execution>
            <phase>package</phase>
            <goals>
                <goal>shade</goal>
            </goals>
        </execution>
    </executions>
</plugin>

    Gradle 插件： 

    plugins {
    id 'com.github.johnrengelman.shadow' version '8.1.1'
}

shadowJar {
    archiveBaseName.set('myapp')
    manifest {
        attributes['Main-Class'] = 'com.example.Main'
    }
}

    对比： - Maven 插件生态更成熟 - Gradle 插件编写更简单 - Gradle 支持自定义任务

    💼 应用场景¶

    适合 Maven 的场景¶

    ✅ 企业级 Java 应用 - 传统企业项目 - 需要标准化流程 - 团队对 Maven 更熟悉

    ✅ 开源库发布 - 发布到 Maven Central - 需要 GPG 签名 - 标准化的发布流程

    ✅ Spring Boot 项目 - Spring 官方推荐 - 丰富的 Starter - 成熟的生态系统

    ✅ 团队转型期 - 从 Ant/其他工具迁移 - 需要快速上手 - 学习资源要求低

    适合 Gradle 的场景¶

    ✅ Android 应用 - Google 官方推荐 - Android Studio 内置支持 - 更好的构建性能

    ✅ 大型多模块项目 - 50+ 模块 - 需要灵活的构建逻辑 - 构建性能要求高

    ✅ 混合语言项目 - Java + Kotlin + Groovy - 需要统一构建系统 - 灵活的配置需求

    ✅ 初创公司/新项目 - 追求构建速度 - 愿意学习新技术 - 需要高度定制

    🔄 迁移指南¶

    Maven 迁移到 Gradle¶

    1. 使用迁移工具

    # 使用 gradle init 自动迁移
gradle init --type java-application --dsl groovy

# 或交互式迁移
gradle init

    2. 手动迁移步骤

    // 1. 创建 settings.gradle
rootProject.name = 'my-project'

// 2. 创建 build.gradle
plugins {
    id 'java'
    id 'application'
}

repositories {
    mavenCentral()
}

// 3. 迁移依赖（从 pom.xml）
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web:3.2.0'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.10.1'
}

// 4. 配置 Java 版本
java {
    sourceCompatibility = JavaVersion.VERSION_17
    targetCompatibility = JavaVersion.VERSION_17
}

// 5. 配置主类
application {
    mainClass = 'com.example.Main'
}

    3. 验证迁移

    # 清理 Maven 构建
mvn clean

# 使用 Gradle 构建
./gradlew clean build

# 对比输出
diff -r target/classes build/classes

    Gradle 迁移到 Maven¶

    1. 创建 pom.xml

    <project>
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>my-project</artifactId>
    <version>1.0.0</version>

    <properties>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
    </properties>

    <dependencies>
        <!-- 从 build.gradle 迁移依赖 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
            <version>3.2.0</version>
        </dependency>
    </dependencies>
</project>

    2. 验证迁移

    # 清理 Gradle 构建
./gradlew clean

# 使用 Maven 构建
mvn clean package

# 对比输出
diff -r build/classes target/classes

    GitHub 项目统计（2025）¶

    Android 项目使用率 5% 95%

    • Maven：稳定，企业市场主导

    • 构建速度：两者都在优化

    🎯 最终建议¶

    选择 Maven，如果：¶

    1. ✅ 团队对 Maven 更熟悉
    2. ✅ 企业标准化要求
    3. ✅ 需要发布到 Maven Central
    4. ✅ 传统 Spring Boot 项目
    5. ✅ 学习资源要求低

    选择 Gradle，如果：¶

    1. ✅ Android 项目
    2. ✅ 追求构建速度
    3. ✅ 大型多模块项目
    4. ✅ 需要灵活定制
    5. ✅ 混合语言项目

    两者都可以，如果：¶

    1. ✅ 新项目，团队无偏好
    2. ✅ 中小型 Java 项目
    3. ✅ 标准 Web 应用
    4. ✅ 微服务项目
