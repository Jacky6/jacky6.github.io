🛠️ 核心概念对比

项目结构

Maven：

my-project/
├── pom.xml
├── src/
│   ├── main/
│   │   ├── java/
│   │   └── resources/
│   └── test/
│       ├── java/
│       └── resources/
└── target/

Gradle：

my-project/
├── build.gradle
├── settings.gradle
├── src/
│   ├── main/
│   │   ├── java/
│   │   └── resources/
│   └── test/
│       ├── java/
│       └── resources/
└── build/

依赖声明

Maven：

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
        <version>3.2.0</version>
    </dependency>
</dependencies>

Gradle (Groovy)：

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web:3.2.0'
}

Gradle (Kotlin)：

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web:3.2.0")
}

功能 Maven Gradle

📊 依赖管理

依赖作用域对比

Maven Scope Gradle Configuration 说明
compile (默认) implementation 编译和运行时
test testImplementation 测试时使用
runtime runtimeOnly 运行时需要
provided compileOnly 编译时需要，运行时由容器提供

依赖冲突解决

Maven：

<dependencies>
    <dependency>
        <groupId>com.example</groupId>
        <artifactId>lib-a</artifactId>
        <version>1.0</version>
        <exclusions>
            <exclusion>
                <groupId>com.example</groupId>
                <artifactId>conflicting-lib</artifactId>
            </exclusion>
        </exclusions>
    </dependency>
</dependencies>

Gradle：

dependencies {
    implementation('com.example:lib-a:1.0') {
        exclude group: 'com.example', module: 'conflicting-lib'
    }
}

🏗️ 多模块项目

Maven 多模块

<!-- 父 POM -->
<project>
    <packaging>pom</packaging>
    <modules>
        <module>module-a</module>
        <module>module-b</module>
    </modules>
</project>

Gradle 多模块

// settings.gradle
include 'module-a', 'module-b'

// build.gradle (root)
subprojects {
    apply plugin: 'java'
    // 公共配置
}

🚀 性能优化

Maven 优化

# 并行构建
mvn -T 4 clean install

# 离线模式（使用本地缓存）
mvn -o clean install

# 跳过测试和检查
mvn -DskipTests -Dmaven.javadoc.skip=true clean install

Gradle 优化

# 启用守护进程（默认启用）
gradle --daemon build

# 并行执行
gradle --parallel build

# 配置缓存
gradle --configuration-cache build

# 构建缓存
gradle --build-cache build

📝 最佳实践

✅ 推荐做法

1. 使用构建工具包装器（Maven Wrapper / Gradle Wrapper）
2. 统一团队构建工具版本
3. 使用依赖版本管理（BOM / version catalogs）
4. 分离配置和代码
5. 启用构建缓存
6. 定期更新依赖版本
7. 使用私有仓库（Nexus / Artifactory）

❌ 避免做法

1. 硬编码版本号（使用属性或版本目录）
2. 忽略依赖冲突
3. 在生产环境使用 SNAPSHOT 版本
4. 提交 build/target 目录到版本控制
5. 过度使用动态版本（LATEST/RELEASE）
