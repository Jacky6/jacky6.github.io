自动装箱机制和自动拆箱

自动装箱：指的是基本数据类型自动转换成对应的包装类。例如，将int转换为Integer。

自动拆箱：指的是包装类自动转换成对应的基本数据类型。例如，将Integer转换为int。

基本数据类型与包装类的对应关系：

基本数据类型 包装类
byte Byte
short Short
int Integer
long Long
float Float
double Double
char Boolean 
// 自动装箱：将 int 转为 Integer
Integer num = 10; // 实际上等效于 Integer num = Integer.valueOf(10);

// 自动拆箱：将 Integer 转为 int
int n = num; // 实际等效于 int n = num.intValue();

抽象类和接口

抽象类是对一种事物的抽象，即对类抽象，继承抽象类的子类和抽象类本身是一种 `is-a` 的关系。 而接口是对行为的抽象。抽象类是对整个类整体进行抽象，包括属性、行为，但是接口却是对类局部（行为）进行抽象。 ref：https://javabetter.cn/oo/abstract-vs-interface.html#_03%E3%80%81%E4%B8%A4%E8%80%85%E5%B7%AE%E5%88%AB 抽象类像是c++

one sentences

  1. 基本类型局部变量为初始化，然后进行其他操作，编译器会进行报错处理。类基本类型字段默认会被强制初始化（一般值为 0 ，非基本类型的对象引用会被初始化为 NULL），所以不会报错。
  2. static关键字不能用于局部变量，而仅适用于字段（成员变量）。如果一个字段是static的基本类型，并且没有初始化，那它就会获得基本类型的标准初始值。如果它是一个对象引用，则默认初始值为null。

构建工具

介绍：

Maven (mvn) 和 Gradle (gradlew) 是两种常用的 Java 项目构建工具，它们各自有独特的特性和用法。

Maven

  • 项目模型: 以项目对象模型（POM）为核心，通过 pom.xml 文件配置项目，包括依赖、插件、生命周期等。
  • 生命周期: Pre-defined 生命周期阶段（如 clean, validate, compile, test, package, verify, install, deploy）。
  • 依赖管理: 使用中央仓库（Maven Central）和本地缓存，支持依赖的传递性管理。
  • 插件: 项目构建的各种功能几乎全部通过插件提供，配置相对繁琐但功能强大。
  • 优点: 稳定，广泛使用，社区和文档资源丰富。
  • 缺点: XML 配置较复杂，不够灵活。

Gradle

  • 项目模型: 采用基于 Groovy 或 Kotlin 的 DSL 脚本进行配置。
  • 任务系统: 以任务为中心，灵活定义和管理构建任务，支持增量构建和缓存。
  • 依赖管理: 支持 Maven 和 Ivy 仓库，依赖声明简洁。
  • 插件: 拥有丰富的内置插件及自定义插件，插件管理灵活。
  • 优点: 配置灵活，额外特性如增量构建提升构建速度，易于集成和扩展。
  • 缺点: 学习曲线可能较 Maven 高，尤其对于不熟悉 Groovy 或 Kotlin 的开发者。

mvn 和 gradlew

  • mvn: 通常用于执行 Maven 命令，如构建项目（mvn clean install）、运行测试（mvn test）等。
  • gradlew: 是 Gradle Wrapper 的命令行启动脚本，保证无论开发者本地是否安装了 Gradle，都能够使用项目指定的 Gradle 版本进行构建。它自动下载 Gradle 二进制文件并执行。

使用场景

选择工具时通常考虑项目规模、团队熟悉度以及功能要求：

  • Maven 更适合传统、稳定的大型项目，尤其是团队成员经验丰富时。
  • Gradle 则适合需要快速迭代、配置精细控制的项目，尤其是现代 DevOps 和 CI/CD 集成中。

在新的项目中选择合适的工具可以提高开发效率和构建速度。
